# Kamimusuhi R0 — Learned Memory Gate

Can an agent with finite memory learn *what is worth remembering*? Episodes
mix future-relevant items, distractors and noise; the agent must choose
IGNORE / STORE / RECALL / ANSWER each step under a 4-slot memory capacity.

Isolated from M/H/S/T/J systems. Standalone under `experiments/r0/`.

## Task

- 128-step episodes. Events: `ITEM` (key,value), `NOISE` (random payload),
  `QUERY key`, `NULL`. `ITEM` keys come from 16 symbols; a hidden subset of
  4 "queryable" keys is always queried 16–64 steps later (RELEVANT), all
  others are never queried (DISTRACTOR). Class labels are never observed —
  selectivity must be learned from which keys ever get queried.
- Memory: 4 slots, fixed-length payload. `STORE` writes the current event
  (FIFO eviction, same-key refresh). `RECALL` snapshots slot payloads into
  the observation plus two derived readout features — a per-slot key-match
  bit and the matched slot's value one-hot — both all-zero until a RECALL
  fills the buffer. Stored *values* are only readable through the recall
  buffer, so ANSWER without RECALL is blind; the derived features exist
  because the experiment is about gating, not readout mechanics, and the
  heuristic baselines get a perfect key-match reader for the same reason.
- `QUERY` stays active for 4 steps; the env demands an answer at the
  deadline (forced-answer) so every query produces a correct/wrong signal.

## Run

Uses the repo `.venv` (torch 2.x, numpy, pyyaml, pytest, matplotlib).

```bash
# smoke (seconds): wiring check, not a quality signal
python -m pytest experiments/r0/tests
python -m experiments.r0.train --config experiments/r0/configs/smoke.yaml \
    --model gru64 --seed 0 --run-id smoke

# full matrix: 3 models x 3 seeds, then clean+causal+OOD eval grid
python -m experiments.r0.sweep --config experiments/r0/configs/default.yaml \
    --models mlp gru64 gru128 --seeds 0 1 2

# single run / eval
python -m experiments.r0.train --config experiments/r0/configs/default.yaml \
    --model gru64 --seed 0 --run-id gru64_s0
python -m experiments.r0.evaluate --checkpoint artifacts/runs/gru64_s0/best.pt \
    --episodes 256 [--causal erase|shuffle|permute|noise] \
    [--ood delay96|delay128|highnoise|slots2]
python -m experiments.r0.evaluate --baseline fifo --episodes 256
```

Budget controls honored without code edits: `R0_TIME_BUDGET` (seconds),
`R0_MAX_ITERS`, `R0_NUM_ENVS`.

## Training protocol

Per iteration: `num_envs=64` complete episodes (all envs share T=128, so
recurrent hidden state legitimately restarts from zero; PPO re-runs stored
observation sequences). The first `imitation_iters=60` updates are
DAGGER-style behavioral cloning: the student rolls out its own policy, each
step is labeled by an oracle gate evaluated on the *student's* env state,
and 50% of envs execute the teacher's action so trajectories visit healthy
memory states. Act CE is class-balanced; answer CE is labeled only where
the student's recall buffer actually contains the queried key. The
remaining updates are plain PPO on task reward only. Provenance is
disclosed because "learned gate" claims rest on the *final* policy, which
PPO continues to shape under capacity pressure.

Reward: correct +1.0, wrong -0.3, any resolved answer +0.2, expire -0.25,
recall-hit shaping +0.2 (first RECALL that retrieves the queried key),
STORE -0.01, RECALL -0.02. Validation for best.pt uses held-out seed
700001; all reported numbers use eval corpus seed 900001+.

## Baselines

`random` (p=0.25 store), `fifo`, `lru`, `reservoir`, `oracle` (upper bound:
stores only to-be-queried items). Heuristics share a perfect key-match
reader so they isolate *storage policy* quality; learned agents must learn
both gating and readout.

## Metrics

`accuracy`, `important_retention` (queried key in memory at query time),
`store_precision` (useful/total stores), `memory_efficiency`
(useful/occupied slots at query), action counts.

## Causal tests / OOD

R-C1 `shuffle` (swap memory with a donor episode at query), R-C2 `erase`,
R-C3 `permute` (slot order), R-C4 `noise` (noise_rate 0.9 + 24 distractors).
OOD: `delay96`, `delay128` (longer episodes), `highnoise`, `slots2`.
