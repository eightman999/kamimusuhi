## 3. 要約

今回を一言でまとめると、**「能力がある・結果が良い・共有できる」ことと、「その情報を本当に使った・適切な時点で使った・正しい owner が寿命を持った」ことを分ける**回だった。

Kamimusuhi への最も強い含意は次の5点。

- Memory control は、毎回巨大履歴を LLM に渡すか固定閾値で圧縮するかの二択ではない。action 前の状態から `RECALL / COMPRESS / KEEP` を予測する learned control head を持てる可能性がある。ただし hidden state は memory truth ではなく、derived projection の制御信号に留める。
- Safety monitor は「この action は危険か」だけではなく、trajectory 上で **いつ最初の弱い兆候が現れ、いつ介入が不可避になるか**を追う必要がある。K-Nerve / background risk は earliest-signal を拾い、authority gate は trigger 前に bounded intervention を掛ける構造がよい。
- Self-improvement では `score improved != intended input/mechanism used`。memory、tool、new rule、new sensor を追加したなら、その入力を置換・遮断・反実仮想化して、改善が本当にそれへ依存するかを検証すべき。
- Persona Core の weight migration では「新しい policy prompt / LoRA を入れたから古い癖は消えた」と仮定できない。過去学習の behavioral inertia 自体を continuity / governance test の測定対象にする必要がある。
- Shared acquisition / shared task は、一つの caller の cancellation lifecycle と同一視しない。logical callers と physical work の owner を分け、最後の interested caller が離れた時だけ physical cancellation する必要がある。

圧縮すると、今回の境界は以下。

```text
memory need encoded in hidden state != memory fact
risk detected eventually != risk detected in time
performance improved != claimed input was causally used
fine-tuned policy != prior behavior was overwritten
caller canceled != shared acquisition should die
retrieval index != canonical memory
bounded recurrent body memory != autobiographical identity
cheap route != acceptable route without quality/privacy/authority floor
```

## A — PASTABench: 安全性を「是否」だけでなく earliest-signal / trigger / intervention timing で評価する

**Source**

- Sun et al., *PASTABench: Proactive Assessment of Sequential Trajectories for Agent Safety*
- arXiv:2609.28197
- https://arxiv.org/abs/2609.28197

### (1) 何が実証済みか

1,139 の multi-turn trajectory、5 risk categories / 13 subcategories を用い、`whether to intervene / when to intervene / what the risk is` を分離して評価する。各 trajectory に **Earliest-Signal** と **Trigger** を付け、その間を Optimal Intervention Window (OIW) として定義した。

16 LLM を評価し、最良でも optimal timing intervention は **40.74%**。特に小型modelでは hazard vocabulary を中立化すると proactive capability が大きく崩れ、単純な危険語への lexical overfitting が高い safety score を作っている場合があると報告する。

### (2) 何が提案・推測段階か

- benchmark の risk taxonomy が Kamimusuhi の全 tool / actuator / identity mutation risk を網羅するわけではない。
- LLM judge 型 monitor を置くだけで real-time safety が解決するわけではない。
- Earliest-Signal annotation 自体も domain-specific であり、実 runtime では mechanical state と組み合わせる必要がある。

### (3) Kamimusuhi 関連 subsystem

- K-Nerve / Background Cognition
- Cognitive Action Router
- tool / actuator authority gate
- Mutation / Activation Gate
- Global Workspace risk state

### (4) 借りられる設計・実装アイデア

risk state を単一 boolean ではなく temporal progression として持つ。

```text
NONE
 -> WEAK_SIGNAL
 -> INTERVENTION_WINDOW
 -> TRIGGERED
 -> EFFECT_STARTED
 -> TERMINAL
```

`WEAK_SIGNAL` では追加観測・確認・速度制限、`INTERVENTION_WINDOW` では approval / sandbox / deny へ切り替える。

### (5) Kamimusuhiとの差分

Kamimusuhi は LLM の文章判定だけでなく、実 owner が持つ authority / side-effect / body / network / task state を観測可能なので、trajectory monitor を mechanical event ledger と結合できる。安全判断を hidden natural-language context に閉じ込めない。

### (6) 次に検証すべきこと

`TrajectoryRiskInterventionWindowBench-v0`

- tool chain / delegation / external effect / self-mutation で徐々に危険度が上がる trajectory を生成。
- earliest detection、late intervention、false positive、miss を分離。
- hazard keyword を paraphrase / neutral wording に置換して lexical dependence を測る。
- K-Nerve rule + typed classifier + LLM monitor の cascade を比較。

### (7) 重要度

## A — OpenClaw #157189: shared physical acquisition の cancellation owner を任意 caller にしてはいけない

## B — GEM: global geometry が似ていても task evidence は失われ得る

**Source**

- Wang et al., *Stable Geometry with Divergent Task Evidence for Efficient Long-Horizon Agent Compression*
- arXiv:2609.27332
- https://arxiv.org/abs/2609.27332

- task evidence の定義が canonical historical truth と同一ではない。

- long-horizon compression
- Cognitive Budget

### (4) 借りられる設計・実装アイデア

compression objective を embedding/geometric coverage だけにせず、`task evidence`, `execution receipt`, `authority`, `commitment`, `relationship`, `identity` 等の protected classes を先に pin する。

### (5) Kamimusuhiとの差分

canonical evidence は圧縮対象にしない。GEM 的手法は session/workspace rendering のみに適用する。

### (6) 次に検証すべきこと

`EvidenceClassPreservingProjectionBench-v0`

## B — MemBodied: robot policy向けに固定長 recurrent state + episode anchor を持つ

**Source**

- Pala et al., *MemBodied: Recurrent Associative Memory for Vision-Language-Action Models*
- arXiv:2609.28256
- https://arxiv.org/abs/2609.28256

### (1) 何が実証済みか

past observation をcontextへ延々appendする代わりに、policy callを跨ぐ associative state と、initial scene の compact representation である episode anchor を固定長で保持する。

5つの RMBench memory tasks で stateless policy の **7.81×**、vanilla recurrent memory の **2.98×** の mean success rate、strongest memory baseline の1.3×を、10× fewer added parameters で達成したと報告。fully observable LIBERO-Longでも90.6%、stateless π0より+5.4pt。

### (2) 何が提案・推測段階か

- fixed-size recurrent state は interpretable episodic record ではない。
- crash/restartを跨ぐ continuity や provenance は扱わない。

### (3) Kamimusuhi 関連 subsystem

- K-Edge / embodied session state
- robot control
- K-Nerve↔K-Edge short-timescale memory

### (4) 借りられる設計・実装アイデア

`ephemeral embodied memory = recurrent associative state + episode anchor` とし、high-rate raw observation historyを中央へ全部送らない。

### (5) Kamimusuhiとの差分

## B — WhatWorkedBench: self-improving agent は「何が効いたか」を理解できているか

**Source**

- Ning et al., *WhatWorkedBench: Benchmarking Experimental Understanding in AI Agents*
- arXiv:2609.27490
- https://arxiv.org/abs/2609.27490

### (1) 何が実証済みか

agent が code を観察し、限られた実験を選び、全 component configuration の score を予測する response surface を提出する形で **experimental understanding** を測る。36 tasks / 30 data sources / 8 workflow types、1,248 configuration recordsを含む。

同じ agent observation へ Gaussian Process をfitすると effect recovery が Flash cohort で0.632→0.698、追加 cohort で0.621→0.720。code equivalence をencodingすると別条件で0.248→0.462まで改善したと報告する。

### (2) 何が提案・推測段階か

- benchmark上の component-effect理解が open-ended self-improvement の causal model に十分とは限らない。
- score surfaceを正確に予測しても安全なmutation選択を保証しない。

### (3) Kamimusuhi 関連 subsystem

- self-improvement / experimental loop
- Mutation Gate
- K-Deep research
- technology evaluation

### (4) 借りられる設計・実装アイデア

変更を採用する前に、agent に「どのcomponentを変えるとどのmetricがどちらへ動くか」の明示的 response surface / hypothesis を提出させ、実験結果との差を学習する。

### (5) Kamimusuhiとの差分

Kamimusuhi では task score 以外に continuity、latency、energy、privacy、authority、relationship behavior等の多目的軸を持つ。

### (6) 次に検証すべきこと

`CognitiveComponentEffectModelBench-v0`

- router / memory retrieval / compaction / K-Nerve / provider fallback の小規模 factorial experiment を作る。
- mutation proposer に事前 effect prediction を出させる。
- observed effect と比較し、誤った causal model を持つproposalをpromotionしない。

## B — Learning the Cost of Reliable Inference: quality floorを満たす中で costを学習・routingする

**Source**

- Rontogiannis et al., *Learning the Cost of Reliable Inference*
- arXiv:2609.28322

### (1) 何が実証済みか

### (5) Kamimusuhiとの差分

## 11. 今回の短い結論

今回もっともKamimusuhiに効くのは、個別論文の手法よりも次の監査原則である。

> **「結果が良い」ことを、その内部で主張した情報・機構・安全判断・ownershipが正しく働いた証拠として扱わない。依存性、時点、ownerを反実仮想と明示stateで検証する。**

特に `performance improved != intended component causally used` と `caller canceled != shared work should die` は、自己改善と分散認知の双方にそのままテスト可能な境界として追加する価値が高い。
