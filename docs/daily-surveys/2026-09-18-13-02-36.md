## 3.1 A+ — Cognitive Serializability: reasoning中に読んだdata/evidence/policy/authorityをcommit時まで一体として扱う

**Primary:** Jun He, Deying Yu, *When AI Agents Commit: Cognitive Serializability Across Data, Evidence, Policy, and Authority*, arXiv:2609.20261.  
https://arxiv.org/abs/2609.20261

注: 2026-09-18 recent listingで再浮上したが、arXiv v1自体は **2026-07-28 submitted**。したがって「今日投稿された研究」ではなく、今回のfresh batch探索で拾った重要backfillとして扱う。

### (1) 何が実証済みか

論文は、agentがmutationを導く際に参照するDB read、retrieved evidence、policy、belief、delegated authorityがreasoning中に変化し得ることを問題化する。prototypeは注入したanomalyを全て防ぎ、mean commit overhead **3.22 ms**を報告している。

### (2) 何が提案・推測段階か

`Cognitive Serializability`が一般的なagent runtimeすべてで必要十分ということは未証明。外部service reservationやstochastic derivationを含む完全一般化は契約footprintの完全性に依存する。

### (3) Kamimusuhi関係先

- Continuity Kernel
- Mutation / Activation Gate
- canonical self / relationship mutation
- tool side-effect admission
- delegated authority
- evidence freshness / policy epoch

### (4) 借りられる設計・実装アイデア

proposalが参照した依存を単一digestではなくtyped vectorとして保持する。

```text
DerivationReceipt
  data_revision[]
  evidence_revision[]
  policy_epoch
  authority_epoch / grant_id
  belief_revision[]
  external_reservation[]
  derivation_artifact_digest
```

commit直前にcurrent vectorと照合し、strict serializableか、effect-compatible再認証か、quarantine/recomputeかを決める。

### (5) Kamimusuhiとの差分

既存 `MutationReadAuthorityCoherenceBench` は「検証したsnapshotとmutation basisを同一にする」が主眼。今回の論文は **複数domainのderivation dependencyを同時にbindする**ところまで一般化している。Kamimusuhiではself/relationship/evidence/authorityを別domainとしているため相性が良い。

### (6) 次に検証すべきこと

**`DerivationDependencyCommitBench-v0`**

- dataは変わらないがpolicyだけ変わる
- evidenceは同じだがsource revocationが起きる
- delegated grantがreasoning途中で失効する
- relationship factが訂正される
- external reservationが失われる

をreasoning→commit間に注入し、stale proposalが0件commitされるか測る。

### (7) 重要度

**A+** — 既存continuity/mutation invariantsを横断的に統合する形式化として強い。

## 3.2 A — Harness valueはcomponentとmodel/budgetの相互作用で決まる

**Primary:** Zhang et al., *How Do Agent Harnesses Create Value? Planning Information and Release Control in Stateful LLM Agents*, arXiv:2609.20474.  
https://arxiv.org/abs/2609.20474

### (1) 実証済み

265 matched cellsで、task-specific Fixed planはword-count matchedなSham planよりoracle-verified successを **+7.17 percentage points**改善。read-only terminal verifierはRetailのoracle-invalid episodeの **61%**をrejectした一方、correct episodeの **17%**もwithholdした。追加costはepisodeあたり1 cent未満と報告。

### (2) 提案・推測

Retail/Airline系の結果を全tool agentへ一般化はできない。liability functionの設定でcomponent価値が変わる。

### (3) 関係先

- Cognitive Action Router
- K-Core / K-Deep escalation
- Cognitive Budget
- terminal verifier / release gate

### (4) 借りる

planner・executor・terminal verifierを「全部載せ」せず、task complexity / false-pass liability / model能力 / budgetごとに選ぶ。

### (5) 差分

Kamimusuhiはidentity continuityを含むため、単なるsuccess/costだけでなく **false canonical mutation / false external effect**の損失を別に置く必要がある。

### (6) 次

**`HarnessComponentEconomicsBench-v0`**: direct / planner-only / verifier-only / planner+verifierをK-Core taskで比較し、success、false-pass、latency、tokens、energy、external-effect liabilityを測る。

### (7) 重要度

**A**

## 3.3 A — SkillAA: failure attributionから局所skill repairへ

**Primary:** Shang et al., *SkillAA: Attribution-Guided Skill-Graph Updating with Targeted Validation and Rollback*, arXiv:2609.20455.  
https://arxiv.org/abs/2609.20455

### (1) 実証済み

skill applicability / execution / compositionをgraph化し、success/failure差からrepair対象objectを特定、local structureだけ更新し、Local Gate + Big Gateでcommit前検証する。gpt-5.6-sol設定でSearchQA **81.5%**、LiveMath **66.7%**、DocVQA **91.2%**を報告。

### (2) 提案・推測

長期運用でgraphが肥大化・循環・競合した時の安定性、security-sensitive skill、multi-user procedural memoryでの安全性は未確認。

### (3) 関係先

- procedural memory
- tool skill evolution
- sleep/consolidation
- self-improvement candidate generation

### (4) 借りる

failureをskill全体の再生成へ直結せず、`applicability / execution / composition` のどこが壊れたかをattributionして局所proposalを作る。

### (5) 差分

Kamimusuhiではprocedural skillはidentity/self stateと別domain。SkillAA型のupdate権限をPersona Coreやcanonical autobiographyへ横流ししてはいけない。

### (6) 次

**`SkillGraphScopedMutationBench-v0`**: 1 skill node故障を注入し、全体rewrite vs attributed local editでregression radius、validation cost、rollback成功率を比較。

### (7) 重要度

**A**

## 3.4 A — SafeHarness: safety constraintを「知っている」だけではPhysical AIは安全にならない

**Primary:** Xu et al., *Coding Agents with an Obstacle-Aware Harness for Safe Robot Manipulation*, arXiv:2609.20822.  
https://arxiv.org/abs/2609.20822

### (1) 実証済み

agentはpromptで障害物への接触禁止を与えられ、trace内でも障害物をreasonしているのに、多くのcaseで衝突した。著者はroute planningとcontact executionにconstraint-aware harnessを追加し、task success **71.9%**、collision avoidance **87.5%**を報告。same agent without harness比でそれぞれ2.3× / 1.5×としている。

### (2) 提案・推測

特定のmanipulation settingから一般的なPhysical AI safetyへの一般化は未証明。bounding-box route表現も複雑なdynamic sceneでは不足し得る。

### (3) 関係先

- K-Nerve / K-Edge
- MOVI / robotics
- physical action gate
- deliberative plannerとreflex safety layerの境界

### (4) 借りる

自然言語policyだけでなく、constraintをroute/contactの**実行表現そのもの**へ落とす。計画後のverify、infeasible時replan、contact-point gateを分離する。

### (5) 差分

Kamimusuhiは「安全constraintを理解した」というself-reportをauthorityにしない。低latency deterministic/geometric guardをplannerの外側にも残すべき。

### (6) 次

**`PhysicalConstraintPriorityBench-v0`**: 同じtaskで prompt-only / planner constraint / geometric guard / both を比較し、collision、goal success、replan率、latencyを測る。

### (7) 重要度

**A**

## 3.5 A — LLM multi-agent consensusはhuman deliberationのproxyにならない

**Primary:** Tengfei Shao, *Language-model groups overstate consensus when replaying human deliberation on a reasoning task*, arXiv:2609.20543.  
https://arxiv.org/abs/2609.20543

### (1) 実証済み

100 held-out human Wason groupsをmatched LLM groupsでreplay。human consensus estimateは定義により **24.0–57.0%**、約1/5のhumanは投稿しなかった一方agentはほぼ常に投稿。submit-based / participation-matched分析でもagent-human consensus gapは約 **34–44 percentage points**。reasoning-mode群はほぼ全員一致しても多くが誤答し、simulated consensusはcollective accuracyを追わなかった。

### (2) 提案・推測

Wason taskから一般社会的議論へ直接一般化はできない。ただし「agent同士が一致した」ことをhuman-likenessやtruthの証拠に使う危険は明確。

### (3) 関係先

- Theory of Mind / social cognition
- multi-model adjudication
- external-agent consultation
- Global Workspace consensus aggregation

### (4) 借りる

`agreement rate`、`participation rate`、`accuracy/evidence quality`、`independence`を別metricにする。abstentionやsilenceを欠損ではなく社会的状態として残す。

### (5) 差分

Kamimusuhiは最終的に1個体として統合判断する。複数specialistを人格の「多数決」にせず、evidence/provenanceを統合する方が設計思想に合う。

### (6) 次

**`ConsensusCalibrationBench-v0`**: 3–7 specialist agentsで、majority vote / confidence vote / evidence-weighted / independent verifierを比較。合意率と正答率が乖離するadversarial framingを入れる。

### (7) 重要度

**A**

## 3.6 A — Workspace Models: train-time VLM supervisionをdeployment-time軽量latent memoryへ蒸留

**Primary:** Dashora et al., *Workspace Models: Lightweight Robotic Memory via Saliency-Driven Supervision*, arXiv:2609.20820, CoRL 2026.  
https://arxiv.org/abs/2609.20820

### (1) 実証済み

full history conditioningがspurious correlationを増やす問題に対し、VLMをtrain-timeだけ使ってtask-relevant current/historical informationを選び、軽量な`workspace token`へdistill。simulationとhardwareで、deployment時のVLM-in-loopなしにmemory-intensive taskを解き、policy performance改善も報告。

### (2) 提案・推測

latent tokenが何を忘れているかの監査性、out-of-distribution event、long-term autobiographical fidelityへの適用は未証明。

### (3) 関係先

- K-Edge / K-Nerve
- robot working memory
- Global Workspace
- sensory history compression

### (4) 借りる

高価なsemantic teacherをoffline/train-timeに使い、runtimeにはsmall latent carrierだけ置くfast/slow設計。

### (5) 差分

Kamimusuhiのcanonical episodic memoryはlatent tokenに置換しない。workspace tokenは **ephemeral/rebuildable control state** として扱い、必要ならraw evidenceへ戻れる構造にする。

### (6) 次

**`WorkspaceTokenReplayBench-v0`**: raw history / caption-summary / learned latent / latent+raw fallbackを、robot state transition accuracy・latency・failure recoveryで比較。

### (7) 重要度

## 3.9 B+ — 長期personalizationの効果と単なる反復接触を分離

**Primary:** Akbulut et al., *Tailored to you: longitudinal effects of personalising language models*, arXiv:2609.20077.  
https://arxiv.org/abs/2609.20077

### (1) 実証済み

992 participantsが5日間daily advice-seeking。non-personalized baseline、memory-based personalization、survey-based personalizationを比較。いくつかの変化はpersonalizationではなくrepeated exposureが主因だった。一方memory-based群はself-disclosure増加・creepiness低下、survey-based群は共有情報へのregret増加を報告。

### (2) 提案・推測

5日間なのでmonth/year scaleのrelationship dynamicsは未解明。advice task以外への一般化も要注意。

### (3) 関係先

- relationship memory
- personalization
- privacy / consent
- HCI / companion continuity

### (4) 借りる

personalization評価では`memory enabled vs disabled`だけでなく、**repeated exposure control**を必ず置く。memory由来とintake-profile由来も分離する。

### (5) 差分

Kamimusuhiは長期関係を重視するため、短期satisfactionより self-disclosure / regret / perceived creepiness / correction burden / autonomy を長期metricにする必要がある。

### (6) 次

`PersonalizationChannelLongitudinalStudy-v0`: baseline / episodic-memory / explicit-profile / hybridを4週間比較し、utilityとprivacy心理を同時測定。

### (7) 重要度

**B+**

## 3.10 B+ — Self-Replicating NCA: phenotype/genotypeを別metricで追うopen-ended substrate

**Primary:** Jain et al., *Self-Replicating Neural Cellular Automata: Quantifying Emergent Phenotypic and Genotypic Diversity in an OpenEnded Substrate*, arXiv:2609.19902.  
https://arxiv.org/abs/2609.19902

### (1) 実証済み

各pixelがtiny neural networkを持ち、neighbor clone + weight mutationによるself-replicationだけで存続。1680 small runs + 24 long runs（1000 generations, 200×200）のうち **20/24 long configurations**でpersistent/self-maintaining。phenotype-genotype diversity tradeoffを報告し、full-genome hashはsparse random-weight probeが見逃すlineage structureを可視化した。

### (2) 提案・推測

### (4) 借りる

behavior/phenotypeだけでなくsubstrate/genotype lineage metricを並走させ、片方のdiversityだけで「多様な個体が進化した」と判断しない。

### (5) 差分

Kamimusuhiのidentityはgenotype/model weightsだけではない。canonical autobiographical lineageとbehavioral phenotypeの双方を別に追う点が決定的に異なる。

### (6) 次

### (7) 重要度

**B+**

**Primary:** Fan et al., *An Empirical Study of Harness Design for Coding Agents*, arXiv:2609.20804.  
https://arxiv.org/abs/2609.20804

176 matched settings、4 models、SWE-Bench Verified + Terminal-Bench 2.1でplanning / action space / context managementを分離評価。主な報告:

- context budgetが小さいほどcontext managementの価値が増える
-利益の多くはcontext-overflow prevention由来
- rule-based elision → LLM summarizationの順が高効率
- recoverable elided contentを追加してもmodelがほぼ使わずaccuracy gainなし
- planningはweak modelではaccuracy scaffold、strong modelではaccuracyをほぼ変えずcost saverへ役割が変化
- bash-capable modelではbash-only interfaceが低costで有効

これは `Cognitive Budget` と `RouterCapabilityCoEvolution` を補強する。**同じharness topologyを全modelに固定しない**ことが実装上の重要差分。独立P0にはせず、`HarnessComponentEconomicsBench-v0`の評価matrixへ統合する。

# 11. 今回の圧縮結論

今回いちばん強い設計更新候補は次の5つ。

```text
1. reasoningで参照したdata/evidence/policy/authorityを、commit時に同じdependency setとして再認証する
2. harnessを「多いほど良い」とせず、model能力・budget・false-pass liabilityでcomponentを選ぶ
3. failureからskill全体を書き換えず、attributionした局所graphだけをrepairする
4. physical safety constraintはpromptで理解させるだけでなく、route/contact executionの表現へ落とす
5. multi-agent consensusをtruthやhuman deliberationのproxyとして扱わない
```

Kamimusuhi向けに言い換えると、**「考えている間に前提が変わっていないこと」「追加した認知機構が本当にその個体・予算で役立っていること」「失敗の責任範囲より広く自己改変しないこと」「理解した規則を実行境界で機械的に守ること」「賛成者の数と独立した証拠の数を分けること」**が今回の核心。
