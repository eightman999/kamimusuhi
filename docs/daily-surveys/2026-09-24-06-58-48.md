## 3. 要約

今回の中心テーマは、**「一度できた・一度決めた・一度宣言した」を、そのまま継続的に正しい state と見なさないこと**だった。

- early intent hypothesis は、後から evidence が来ても自然に撤回されるとは限らない。曖昧さを `tentative` のまま保持し、後の clarification が invalidation を発生させる必要がある。
- procedural skill を deterministic にすると再現性とコストは改善するが、routing boundary が間違えば**同じ失敗を完全に再現する**。skill の本体より eligibility/abstention が重要になる。
- task completion metadata に path が残っていても、そのファイルが durable attachment へコピーされたとは限らない。`declared output != preserved output` を completion receipt で区別すべき。
- low-latency recurrent organ は「大きい state を持てば安全」ではなく、行動再現に必要な最小情報量を測り、ephemeral control state を canonical memory から切り離せる。
- browser/tool organ は parent process や `/json/version` が生きていても、critical child が死んでいれば利用不能である。health は capability end-to-end で証明する必要がある。
- relational rupture は明示的な一文だけでなく、複数 turn の implicit context を統合しないと検出・repair が浅くなる。
- online self-improvement は algorithm 自体を state-dependent に変えられるが、それは bounded cognitive body の変更として lineage / rollback を持たせるべきで、identity mutation と混ぜない。
- tactile reflex は learned policy への teacher として有用でも、distribution shift 下の runtime robustness が policy に完全移植されるとは限らない。反射器官を早期に削除しない。

共通原則を圧縮すると、`clarification != state correction`、`habit consistency != habit validity`、`artifact declared != artifact preserved`、`process alive != capability ready`、`learned imitation != reflex robustness internalized` を分離する回だった。

# 4. 重要発見

## A — Clarification Is Not Correction: 初期 intent collapse が後続 clarification を無効化する

**Source**

- Lin et al., *Clarification Is Not Correction: LLMs Fail to Let Go*
- arXiv:2609.25337
- https://arxiv.org/abs/2609.25337

### (1) 何が実証済みか

Gemini-2.5-Pro / Flash を用いた writing・planning・coding の controlled dialogue で、**最終的に含まれる task-relevant information が同じでも、情報の提示順序で結果が変わる**ことを数千 trial で示している。

著者らは、曖昧な初期 turn で hidden task state が一つの解釈へ早期 collapse し、その後の clarification が「以前の仮説を無効化する correction」ではなく「既存 state への追加 context」として扱われる failure を `early posterior collapse` と整理している。特に coding では、早期 assumption が interface や control flow のような構造化 artifact に埋め込まれやすい。

また、通常の summary / memory strategy は安定した解決にならず、CoT は reasoning trace 上の明示的誤 commit を減らしても final task success を改善しない場合があると報告する。

### (2) 何が提案・推測段階か

- `tentative hypothesis`を保持し、高 impact の曖昧さでは質問し、後続 evidence が以前の解釈を否定したら state を rebuild する設計は論文の提案。
- これが長期 relationship memory / autobiographical state でも同じ機構で十分かは未実証。
- posterior という語は機能的記述であり、LLM 内部に明示 Bayesian state が存在する証拠ではない。

### (3) Kamimusuhi 関連 subsystem

- Global Workspace / task state
- Common Ground / user-intent model
- Persona Core の uncertainty handling
- tool plan / code artifact lifecycle
- derived context / session memory

### (4) 借りられる設計・実装アイデア

`intent hypothesis` を scalar な一つの state に潰さず、少なくとも次を明示する。

```text
hypothesis_id
status = tentative | supported | contradicted | retired
supporting_evidence_ids
contradicting_evidence_ids
derived_artifact_ids
clarification_required
```

新しい user evidence が hypothesis を否定した場合、単に context を追記せず、その hypothesis から派生した tool plan / code / summary / action proposal を stale 化し、必要なら rebuild する。

### (5) Kamimusuhiとの差分

Kamimusuhi はすでに canonical evidence と derived state、freshness を分けるが、**session-level intent interpretation の invalidation graph**は仕様上まだ十分に具体化されていない。これは historical truth の上書き防止とは別に、現在の task model を撤回可能にする問題。

### (6) 次に検証すべきこと

`AmbiguityPreservingTaskStateBench-v0`

- 最終情報が同一で順序だけ異なる dialogue pair を作る。
- `single committed state` と `tentative hypothesis set` を比較する。
- 後続 clarification で derived plan/artifact が確実に stale / rebuild されるか。
- coding / tool execution の高 impact action 前だけ clarification threshold を上げる。
- canonical user utterance は変更せず、interpretation だけ retire できること。

### (7) 重要度

**A**

理由: persistent agent の memory 容量ではなく**解釈 state の撤回可能性**を問題にしており、Kamimusuhi の canonical/derived 分離を interactive cognition へ拡張できる。

## A — Making Agents More Consistent: deterministic habit は domain boundary を間違えると「悪い失敗を完璧に再現」する

**Source**

- Weber & Taneja, *Making Agents More Consistent: Skills Should Form Habits for Repeat Tasks*
- arXiv:2609.25299
- https://arxiv.org/abs/2609.25299

### (1) 何が実証済みか

42 tasks を3回ずつ実行した評価では、model により **38–74% の task で回答が一致しない**。生成内容の 95.3–97.2% が既知 plan の再導出に使われていたと報告する。

execution history から deterministic skill candidate を作り、candidate が自分の適用 input region を宣言し、4段階 gate を通過した場合だけ reasoning path を置換する `habit formation` を導入。text-to-SQL では habit variant が repeated 456 dispatches すべてで再現し、置換対象 arm に対して non-inferior、token を14–56%削減し、7–53 reuse で正味 positive になった。

ただし guard は natural paraphrase の2.6%、**boundary 近傍入力の26%を誤って habit に通した**。しかも13 failure中11は trace-conformance gate では検出不能だった。論文が明示する通り、deterministic error は deterministic success と同じように完全再現される。

### (2) 何が提案・推測段階か

- 他 domain でも同じ break-even reuse 数や guard 誤差になるとは限らない。
- execution trace similarity が安全な適用範囲を一般に定義できるわけではなく、実際に boundary failure が残っている。
- long-horizon procedural identity や personality habit への適用は論文の範囲外。

### (3) Kamimusuhi 関連 subsystem

- procedural memory / skill library
- K-Nerve / K-Edge fast path
- Cognitive Action Router
- Cognitive Budget
- self-improvement / Mutation Gate

### (4) 借りられる設計・実装アイデア

reasoning trace から skill を作る場合、skill 本体と**適用領域 classifier / abstention**を別 artifact として扱う。

```text
skill_version
claimed_input_region
positive_examples
boundary_examples
known_failures
route_confidence
fallback_route
reference_trace_ids
```

特に「一度 skill 化したから今後全部 deterministic path」ではなく、境界付近は高価な reasoning へ戻す。

### (5) Kamimusuhiとの差分

Kamimusuhi は procedural evolution / trajectory shortcut / skill admission を既に収載しているが、本研究は **skill correctness より dispatch boundary が principal failure point になり得る**ことを定量化した点が差分。`determinism == reliability` とみなしてはいけない。

### (6) 次に検証すべきこと

`HabitDomainBoundaryBench-v0`

- exact repeat / natural paraphrase / near-boundary / explicit OOD を分ける。
- habit route と reasoning route の accuracy / variance / latency / token / energy を測る。
- trace-conformanceだけ、semantic guard併用、hard rule併用を比較する。
- boundary confidence が低いと必ず reasoning へ戻れること。
- bad habit をactivation後に発見した際、version単位でfence / rollbackできること。

### (7) 重要度

**A**

理由: K-Nerve/K-Edge の「速い決定器」や procedural memory を実装する際、**fast path の中身ではなく入口の境界が安全性を決める**という具体的実証。

## A — Hermes #120647: completion が artifact を宣言しても durable preservation は成立していない

**Source**

- NousResearch/hermes-agent issue #120647, *kanban_complete artifacts declared outside the task workspace are silently never attached*
- https://github.com/NousResearch/hermes-agent/issues/120647

### (1) 何が実証済みか

Hermes の `kanban_complete(artifacts=[...])` で、task-managed scratch workspace 内の artifact は attachment directory へ staging される一方、**workspace 外の path は silently skip**され、attachment rowもwarningも作られない。しかし completion event / run metadata には元 path がそのまま残るため、表面的には deliverable が保存されたように見える。

reporter は in-workspace control と out-of-workspace case を比較し、後者では `complete_task` が `True` を返し、attachment directory は作られず、list は空、metadata は元 path のままになることを再現している。実運用例では、その未保存ファイルが約1分後にcleanupで削除され、recover不能になった。

### (2) 何が提案・推測段階か

- out-of-tree artifact を loud-fail / warn / copy-any-existing のどれにするかは maintainer 未決定。
- Kamimusuhi が Hermes の kanban artifact contract を採用する必要はない。

### (3) Kamimusuhi 関連 subsystem

- K-Deep / delegated task result
- durable result obligation
- canonical evidence / execution receipt
- task completion / publication boundary
- result delivery and artifact custody

### (4) 借りられる設計・実装アイデア

completion receipt は「agent が path を宣言した」ではなく**durable store owner が preservation を確認した**ことを条件にする。

```text
artifact_declared
  -> source resolved
  -> copied / adopted by durable owner
  -> digest + size recorded
  -> retrievable from owner namespace
  -> completion receipt may reference it
```

失敗時は `preserved=false` を明示し、successful completion と混ぜない。

### (5) Kamimusuhiとの差分

Kamimusuhi は thought / execution / delivery を分離しているが、**結果 artifact の custody transfer**を別状態として明示する余地がある。直前回の `ActivationArtifactClosureBench` は cognitive body の deployment completeness であり、こちらは delegated work output の durable custody / completion truthfulness なので別問題。

### (6) 次に検証すべきこと

`DeclaredArtifactPreservationClosureBench-v0`

- managed workspace内 / outside workspace / symlink / remote mount / ephemeral tmp を網羅する。
- completion success 前に durable owner から digest/readback を取る。
- cleanup と completion を競合させる crash-window test。
- metadata の path が declaration なのか preserved locator なのか型で分ける。
- result delivery後にも artifact が owner namespace から取得可能か確認する。

### (7) 重要度

**A**

理由: K-Deepや外部agentへ長時間仕事を委譲する設計で、`finished` と `deliverable survived` を分離しないと成果物を失ったまま成功を記録する。

## A — Minimal Recurrent Behavioral Memory: K-Nerve の recurrent state を「最小必要情報量」で設計できる

**Source**

- *Minimal Recurrent Behavioral Memory for Imitation under Partial Observability*
- arXiv:2609.25757
- https://arxiv.org/abs/2609.25757

### (1) 何が実証済みか

partial observability 下で expert behavior を再現するために必要な recurrent memory の**最小情報量**を定式化し、compatibility relation が transitive な場合の exact minimum と、一般 case の entropy minimization を与える。さらに sole-carrier measurement により、behavioral sufficiency と excess code rate、observation / alternate memory path の混入を分ける。

manipulation task では hidden mode が最大512あっても learned code rate が理論上の0-bit / 2-bit requirement付近へ収束し、waiting中の instantaneous demand が0でも、anticipatory memory が 2→1→0 bit と減る構造を報告する。

学習面では event-agnostic future-behavior supervision が40 seed中36で sufficient memory を得て、longest-horizon pixel setting は成功 seed が0/8→6/8、closed-loop success は0.08→0.57へ改善したと報告されている。

### (2) 何が提案・推測段階か

- Kamimusuhi の wake / interrupt / salience routing に必要なbit量は未測定。
- この minimal behavioral memory は durable autobiographical memory や identity continuity を扱わない。
- 理論 minimum へ近いことが robustness / safety の最適を意味するわけではない。

### (3) Kamimusuhi 関連 subsystem

- K-Nerve
- K-Edge recurrent control
- sensory event routing
- low-latency / low-power cognition
- ephemeral working state

### (4) 借りられる設計・実装アイデア

K-Nerve の recurrent state を GRU hidden size や neuron count のような substrate metric だけで決めず、**行動等価性を保つために必要な information state**として測る。

特に canonical memory を参照しなくても良い reflex taskでは、stateを最小の ephemeral carrier に限定する。

### (5) Kamimusuhiとの差分

Kamimusuhi の K0-E2 では strict-memory / delay task を使って recurrent memory を評価しているが、本研究は「何bit必要か」「他の経路が情報を運んでいないか」を切り分けるformal measurementを与える。これはK-Nerveの比較を architecture-size から task-sufficiencyへ移せる。

### (6) 次に検証すべきこと

`MinimalReflexStateSufficiencyBench-v0`

- wake / ignore / interrupt / backchannel / route-selection のPOMDPを作る。
- taskごとの理論/empirical minimum state を測る。
- observation leak / timestamp / cache等のalternate carrierを遮断する。
- memory sizeを減らし、behavioral sufficiencyとlatency/energyを同時測定する。
- ephemeral stateがcanonical self/relationship mutation authorityを持たないことを確認する。

### (7) 重要度

**A**

理由: K-Nerveの「小さく速い状態機械」を神経模倣でなく、**必要な行動情報量**から設計する具体的評価軸になる。

## B — Online Automated Algorithm Design: algorithm 本体を state-dependent に変える online cognitive-body evolution

- arXiv:2609.25325
- https://arxiv.org/abs/2609.25325

`OnDesign` は target optimization の途中状態ごとにLLM agentsが新しい executable algorithm behaviorを合成し、その実行 feedback を次段の designへ戻す。algorithm designとtarget optimizationをofflineに分離せず、**algorithm自体をstate-dependent decision variable**として扱う。

Bayesian optimization、evolutionary continuous optimization、mixed-variable optimizationの3 scenario、6 benchmark suites + 1 engineering problemで conventional optimizer / offline LLM-AAD より overall performance が高いと報告する。

### (2) 何が提案・推測段階か

- persistent personal agentの長期self-improvementへそのまま一般化できない。
- generated algorithmの安全性、identity continuity、long-run regressionは本論文の中心ではない。

### (3) Kamimusuhi 関連 subsystem

- self-improvement
- Mutation / Activation Gate
- K-Deep
- procedural algorithm library

### (4) 借りられる設計・実装アイデア

bounded task optimizerを一つの固定toolとみなさず、runtime evidenceから**新しいalgorithm artifactをproposalする organ**として扱う。ただし各versionはlineage / input regime / evaluation receiptを持たせる。

### (5) Kamimusuhiとの差分

Kamimusuhiでは cognitive-body/procedural algorithm の更新と identity/persona mutationを分ける必要がある。OnDesignのonline algorithm rewriteは前者としてのみ借りる。

## B — tactile reflex teacher: policy が模倣できても runtime reflex の disturbance robustness は移植されない

**Source**

- Feng et al., *What is the Better Curriculum: Controller-Shaped Grasping Behavior for Contact Force-Sensitive Manipulation*
- arXiv:2609.25887
- https://arxiv.org/abs/2609.25887

### (1) 何が実証済みか

25 Hz tactile reflex controllerをdata-collection teacherに使い、tactile-free policyへcontroller-shaped demonstrationを学習させる。ACTではnominal plastic-cup taskで**95% stable grasps**となり、screened manual demonstrationより改善した。

一方 randomized external disturbance では、reflex-dataで学習した `π0.5` policyをpolicy-onlyで使うと45% failureが残り、deployment-time reflex arbiter併用では全graspを保持した。つまり nominal behavior を模倣しても、reflexの disturbance rejection が完全にweightsへ移植されたわけではない。

### (2) 何が提案・推測段階か

- 触覚反射とKamimusuhi K-Nerveの一般routing/reflexが同じ学習力学を持つとは限らない。
- unseen paper cupは exploratory trendであり一般化の強い証拠ではない。

### (3) Kamimusuhi 関連 subsystem

- K-Nerve / K-Edge
- embodied learning
- reflex arbitration
- sensor-actuator loop

### (4) 借りられる設計・実装アイデア

reflexを「最終的に学習policyへ蒸留して消すteacher」だけでなく、**distribution shift時に残す independent runtime guardian**として評価する。

### (5) Kamimusuhiとの差分

KamimusuhiのK-Nerveはidentity authorityを持たない低latency器官。学習policyがnominal taskで反射を模倣できても、retire条件は nominal imitationではなく disturbance coverage で決めるべき。

### (6) 次に検証すべきこと

`ReflexTeacherRetentionBench-v0`

- reflex-assisted demonstration → learned fast policyを作る。
- nominal / latency jitter / sensor noise / actuator disturbance / OODで、policy-only vs policy+reflexを比較する。
- reflex retirementはworst-case disturbance non-inferiorityを満たした場合だけ許す。

### (7) 重要度

**B**

## C — A theory of plasticity: 「変わった量」ではなく「変われる余地」を測る概念整理

**Source**

- *A theory of plasticity: capacity for change as inverse configurational constraint*
- arXiv:2609.25312
- https://arxiv.org/abs/2609.25312

### (1) 何が実証済みか

論文はplasticityを観測されたchange量ではなく、固定accessibility criterionの下で取り得るconfiguration repertoire、すなわち**prospective capacity for change**として定義する理論枠組みを提示する。constraintが低いほどaccessible repertoireが広がるという整理を行う。

### (2) 何が提案・推測段階か

Kamimusuhiのself-improvementに直接使えるoperational metricやagent benchmarkは未実証で、現段階ではconceptual transferに留まる。

### (3) Kamimusuhi 関連 subsystem

- self-improvement governance
- Persona/Core plasticity
- Mutation policy
- developmental/open-ended learning

### (4) 借りられる設計・実装アイデア

`actual drift` と `capacity to change` を別指標にする。たとえばmutation proposal space、activation constraints、reversible regionをplasticity budgetとして記録する発想。

### (5) Kamimusuhiとの差分

Kamimusuhiは変更をlineage/activation gateで管理する実装系で、本論文は一般理論。normative specへ入れる段階ではない。

### (6) 次に検証すべきこと

`PlasticityCapacityVsObservedChangeBench-v0` をwatch候補とし、同じactual change量でも mutation option set / rollback possibility が異なる2 systemを区別できるか検討する。

### (7) 重要度

**C**

理由: 概念的には有用だが、現時点でKamimusuhi固有の実証・実装根拠は弱い。

## 11. 今回の圧縮結論

**Kamimusuhiは、stateやartifactを「存在する/完了した」のbooleanで扱うより、何がまだtentativeで、何が無効化され、どこまでdurable ownerへ引き渡され、どの入力領域でだけ再利用可能かを持つべきである。**

今回の新規 evidence を一行ずつにすると、

```text
clarification received       != prior interpretation invalidated
habit is deterministic       != habit is valid for this input
artifact path was declared   != artifact is durably preserved
parent service is alive      != requested capability is operational
policy copied reflex behavior != disturbance robustness was internalized
observed behavioral change   != capacity for future change
```

となる。
