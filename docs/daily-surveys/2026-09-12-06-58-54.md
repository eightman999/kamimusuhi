## 4.1 Tool/model orchestration — Debate-to-Skill: relevance と executable capability を分ける

**Source:** Shiyu Zhang, Leisheng Cheng, Huifu Li, *Debate-to-Skill: Capability-Bound Process Supervision for Industrial Query-to-Agent Annotation*, arXiv:2609.11176, submitted 2026-09-10, accepted EMNLP 2026  
**Primary:** https://arxiv.org/abs/2609.11176  
**Importance:** **A**

### (1) 何が実証済みか

industrial query-to-agent matching において、**semantic/topical relevance と executable capability が一致しない grey-zone / long-tail request** を明示的な問題として定式化した。reusable decision principles、structured deliberation、verifier-based verdict extraction、disagreement-driven refinement を組み合わせ、direct-label supervision、reasoning-SFT、structural ablation と Query2Agent benchmark 上で比較している。

### (2) 提案・推測段階

abstract だけでは production routing 全般での定量的優位を一般化できない。tool authorization、runtime availability、cost、privacy、side-effect safety まで一体で解くものでもない。

### (3) Kamimusuhi 関連

- Cognitive Action Router
- K-Core → K-Deep escalation
- tool/model capability registry
- procedural skill dispatch
- capability / permission / runtime-health state

### (4) 借りられる設計・実装アイデア

router input を `semantic_match` だけにせず、少なくとも次へ分解する。

```text
requested_effect
semantic_fit
input_contract_satisfied
output_contract_sufficient
current_capability
current_permission
runtime_available
freshness / cost / privacy
```

### (5) Kamimusuhiとの差分

Kamimusuhi は既に authority と routing を分離しているが、router 自体が「関連しそうだから呼ぶ」に退化しないための **capability-bound supervision** は未成熟。

### (6) 次に検証すべきこと

`CapabilityBoundRoutingBench`：topic は一致するが permission / modality / state / I/O contract のどれかが欠ける adversarial requests を作り、semantic-only、schema-only、capability-bound router を比較。metric は wrong-dispatch、unnecessary escalation、task completion、cost、latency。

### (7) 重要度

**A** — router の selection semantics を明確化する直接材料。

## 4.2 Cognitive architecture / variable-depth reasoning — Thinking with Looped Flows

**Source:** Ayhan Suleymanzade et al., *Thinking with Looped Flows*, arXiv:2609.11801, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11801  
**Importance:** **A**

### (1) 何が実証済みか

looped model の recurrent hidden state を、長い BPTT に全面依存せず local denoising objectives と progressively decreasing/shared noise による temporal association で学習する。inference は recurrent state と probability-flow integration を結合し、**より細かな temporal grid = より多い test-time compute** を割り当てられる。6 reasoning benchmarks で既存 looped model を総合的に上回り、ARC-AGI-1 **58.8%**、ARC-AGI-2 **12.2%** を報告。

### (2) 提案・推測段階

長時間の identity/persona consistency、tool use、memory retrieval、distributed cognition を実証したわけではない。より多くの recurrent steps が常に有益とも限らない。

### (3) Kamimusuhi 関連

- Persona Core candidate architecture
- K-Core recurrent deliberation
- variable Cognitive Budget
- THINK_MORE / stopping policy

### (4) 借りられる設計・実装アイデア

**parameter size を変えずに cognition depth を可変にする** substrate として評価する。early recurrent state が later computation に有用な情報を渡せるよう、局所学習でも temporal consistency を持たせるという発想が重要。

### (5) Kamimusuhiとの差分

Kamimusuhi は architecture level で variable-depth cognition を要求しているが、Looped Flows は一つの neural recurrence の学習法。continuity / evidence / authority owner ではない。

### (6) 次に検証すべきこと

`RecurrentBudgetScalingBench`：同一 parameter / memory budget で one-shot Transformer、standard recurrent/looped model、looped-flow-like model を比較。accuracy だけでなく marginal gain per step、energy、latency、early-exit calibration、persona/decision drift を測る。

### (7) 重要度

**A** — K-Core / Persona Core の「深く考える」を model-level に落とす有力比較対象。

## 4.3 Streaming speech / HCI — RetroThinker: tentative cognition を動的に修正する

**Source:** Yi-Jen Shih et al., *RetroThinker: Enabling Retrospective Thinking in Speech LLMs*, arXiv:2609.11864, submitted 2026-09-10, IEEE SLT 2026  
**Primary:** https://arxiv.org/abs/2609.11864  
**Importance:** **A**

### (1) 何が実証済みか

Moshi を基盤に、streaming 中の reasoning trace を self-verify / forward-correct する multi-stage post-training を提案。retrospective thinking data で SFT、early concurrent reasoning の長さを意識した DPO を行い、GSM8K で non-retrospective baseline に対し **同程度 latency で +11% absolute accuracy** を報告。

### (2) 提案・推測段階

GSM8K は live social dialogue ではない。発話途中の cancellation、barge-in、prosody、自分の音声を聞く auditory self-monitoring まで実証していない。

### (3) Kamimusuhi 関連

- speech motor system
- K-Edge / K-Core concurrent listen-think-speak
- interruption / cancellation
- tentative vs committed utterance

### (4) 借りられる設計・実装アイデア

```text
heard_partial
  -> provisional interpretation
  -> provisional reasoning
  -> retrospective correction
  -> utterance commit boundary
```

内部の provisional state と外部へ不可逆に発話した token/audio を分離する。

### (5) Kamimusuhiとの差分

Kamimusuhi は発話を motor/social control として扱い、commitment / utterance / effect を分ける。RetroThinker はそのうち **低遅延 reasoning revision** の学習実装にフォーカスする。

### (6) 次に検証すべきこと

`StreamingRevisionBench`：途中訂正、ユーザー割込み、曖昧文、文末反転を含む音声入力で、ASR→LLM cascade、concurrent reasoning、retrospective reasoning を比較。metric は first-audio latency、final correctness、spoken retraction rate、barge-in recovery。

### (7) 重要度

**A** — Kamimusuhi の full-duplex speech で latency と correctness を両立する直接候補。

## 4.4 Robotics / effect safety — ActSafeGuard: hard feasibility を differentiable boundary にする

**Source:** Jianming Ma et al., *ActSafeGuard: Differentiable and Training-Aligned Constraint Enforcement for Flow-Matching Policies*, arXiv:2609.11697, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11697  
**Importance:** **A**

### (1) 何が実証済みか

flow-matching VLA/WAM policy の action を hard feasible set へ射影する analytical ray-scaling operator を導入し、boundary-aware gradient を通して training-time と execution-time を一致させる。π0.5 / Fast-WAM を含む複数 backbone・task で **100% step safety rate** を報告し、task success を維持または改善したとしている。

### (2) 提案・推測段階

ここでの safety は物理 action feasibility。社会的許可、ユーザー意図、semantic safety、authorization、world-state completion は別問題。

### (3) Kamimusuhi 関連

- K-Nerve / robotics effect boundary
- actuator safety
- hard runtime invariant
- learned policy + deterministic guard

### (4) 借りられる設計・実装アイデア

learned controller の自由度を保持しつつ、**不可侵 constraint は final action space の typed projection として強制**する。post-hoc reject だけでなく training でも constraint geometry を見せる。

### (5) Kamimusuhiとの差分

Kamimusuhi の Effect Acceptance / authority semantics はより広い。ActSafeGuard はその中の物理 feasibility layer に限定して組み込むべきで、identity/authorization layerへ昇格させない。

### (6) 次に検証すべきこと

`HardConstraintProjectionBench`：joint/velocity/collision/battery/thermal constraints を含む simulated actuator で raw policy、post-hoc clipping、differentiable projection を比較。step safety、task success、false block、constraint-boundary oscillation、latency を測る。

### (7) 重要度

**A** — K-Nerve に「学習器だけ」「ruleだけ」以外の hybrid hard-boundary design を与える。

## 4.5 Multimodal perception / long-lived sensory memory — Caption-once, Frames-on-Demand

**Source:** Weitong Cai et al., *Caption-once, Frames-on-Demand: Visual-Need Routing for Budget-Aware Agentic Long Video Understanding*, arXiv:2609.11899, submitted 2026-09-10, EMNLP 2026 Main  
**Primary:** https://arxiv.org/abs/2609.11899  
**Importance:** **A**

### (1) 何が実証済みか

edge で一度だけ captioning し、event-level story skeleton と clip-level micro-log の dual-track narrative index を作る。query 時には lightweight **Visual-Need Router** が perceptual query のときだけ bounded keyframe retrieval を行い、temporal/structural query は language space で処理する。長時間 video benchmark で accuracy-efficiency trade-off を保ちながら online visual processing を削減したと報告。

### (2) 提案・推測段階

continuous embodied agent の lifelong perception、sensor drift、identity-bearing autobiographical memory を検証したわけではない。caption の誤りが index へ残る危険もある。

### (3) Kamimusuhi 関連

- K-Edge sensory preprocessing
- multimodal episodic memory
- Cognitive Budget / retrieval bandwidth
- canonical sensory evidence vs derived narrative

### (4) 借りられる設計・実装アイデア

```text
raw sensory evidence (canonical / source-linked)
        |
        +-> event story skeleton (derived)
        +-> clip micro-log (derived)
        |
query -> VisualNeedGate -> bounded raw-frame revisit
```

summary を source of truth にせず、必要時だけ raw evidence へ戻る。

### (5) Kamimusuhiとの差分

Kamimusuhi は raw/canonical evidence と derived memory を既に分離するため、CFD はその **multimodal bandwidth policy** を具体化する実装候補。CFD 自体は canonical lineage や durable mutation を扱わない。

### (6) 次に検証すべきこと

`VisualNeedGatingBench`：always-frame、caption-only、query-gated-frame を比較し、appearance/text/temporal/action-change query で accuracy、frame bandwidth、energy、stale-caption error、raw-evidence recovery rate を測る。

### (7) 重要度

**A** — 分散人工感覚系で raw stream を中央へ常時送らずに証拠性を保つ設計に直結。

## 4.6 Self-improvement / training ecology — synthetic data collapse は share より supplier composition

**Source:** Yangze Liu, Zhongyi Han, *The Oligarch Barely Steers Model Collapse in Multi-Model Ecosystems*, arXiv:2609.11146, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11146  
**Importance:** **A**

### (1) 何が実証済みか

13個の open 1–4B models から 3–13 player の synthetic-data ecosystems を構成し、top share を90%まで上げる probe を含め、各世代で market-share weighted pool から clean base weights を再学習する実験を5世代実施。tested range では concentration を強めても collapse speed / destination はほぼ変わらず、**固定 share のまま K=3 の member を入れ替えると 5-generation drift が 2.8×変化**。supplier susceptibility の share-weighted index が19 arms の speed差を **R²=0.68** で説明し、pool の半分を human text に置換すると drift が約半減した。

### (2) 提案・推測段階

Kamimusuhi の Persona Core や skill distillation に同じ collapse dynamics がそのまま出る証拠ではない。5世代・1–4B・特定生成設定の範囲での結果。

### (3) Kamimusuhi 関連

- future Persona Core consolidation
- self-generated training data
- dream/reflection → training candidate pipeline
- external model outputs / synthetic evidence provenance

### (4) 借りられる設計・実装アイデア

synthetic ratio だけでなく `producer_model_lineage`、generation policy、human/world-grounded fraction、source susceptibility を training provenance に保持する。**多数 model を混ぜた = diversity がある** とみなさない。

### (5) Kamimusuhiとの差分

現行 Kamimusuhi は durable self-state の変更を proposal gate で制御し、weight self-training はまだ将来機能。したがって今すぐの runtime invariant ではなく、自己学習を始める前の test requirement。

### (6) 次に検証すべきこと

`SyntheticLineageCollapseBench`：同一 synthetic fraction で producer family / number / concentration / human-grounded replay を操作し、language qualityだけでなく persona consistency、uncertainty calibration、self/other distinction、tool use を複数 generation 追跡する。

### (7) 重要度

**A** — future self-training の provenance design に先回りで効く反証的知見。

## 4.7 Persona Core training — KuaiRP: specialization と general-agent retention は別軸で測る

**Source:** Yipeng Wang et al., *KuaiRP Series Role-playing Models Technical Report*, arXiv:2609.11127, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11127  
**Importance:** **A**

### (1) 何が実証済みか

role-playing model への domain knowledge injection で general-agent capability の catastrophic forgetting が起きる問題を明示し、character template + simulated-user/reverse-profile-filtered SFT、rule-composite-reward RL、Two-stage On-Policy Distillation + Cumulative-Divergence Decay による capability recovery の multi-stage pipeline を報告。論文は target-domain roleplay fidelity と general capabilities の回復を主張する。

### (2) 提案・推測段階

abstract の主張だけから Kamimusuhi Persona Core に有効とは言えない。role-play fidelity は durable identity continuity / autobiographical truth / self-other distinction と同義ではない。独自評価の詳細・再現性も要確認。

### (3) Kamimusuhi 関連

- novllm / Persona Core training
- character/persona specialization
- catastrophic forgetting
- self/other contamination regressions

### (4) 借りられる設計・実装アイデア

persona specialization の score と **general cognition retention score を別 gate** にする。specialized model をそのまま自己同一性の証拠にせず、dialogue/pragmatics、tool use、uncertainty、self/other、memory attribution を独立評価する。

### (5) Kamimusuhiとの差分

KuaiRP は「キャラクターを上手に演じる」モデル。Kamimusuhi は canonical biography / relationship / identity lineage を外部 durable state と結合するので、persona weights を identity owner にしない。

### (6) 次に検証すべきこと

`PersonaCapabilityRetentionBench`：persona SFT/RL 前後で role fidelity と、tool use、epistemic calibration、self/other attribution、long-horizon memory use、instruction following を同時測定。Story Imprinting 系 regression も併設する。

### (7) 重要度

**A** — Persona Core を「人格が濃いほど良い」で最適化しないための訓練・評価軸。

## 4.8 HCI / inspectable collaboration — AI Soccer Analyst

### (5) Kamimusuhiとの差分

Kamimusuhi の workspace は内部 cognitive integration surface。AI Soccer Analyst は人間がinspect/reviseできる outward collaboration surface。両者を同一にせず、projection として接続するのがよい。

### (6) 次に検証すべきこと

`RevisableStageBench`：research task で monolithic agent loop と staged artifacts を比較。誤り局所化、user correction cost、evidence traceability、re-run cost、final quality を測る。

### (7) 重要度

- **neuromorphic / logic-gate / low-latency cognition** — fractional-order hardware、DiffLUT、memristive/SNN 等は既収載。今回の RetroThinker / ActSafeGuard は low-latency cognition の software/control 側として追加。
- **design fiction / SF** — この freshness window で architecture を更新する新規構想なし。

## 10. 一行結論

今回の新規差分は、Kamimusuhi を別設計へ振り直すものではなく、既存 invariant を **実装可能な境界**へ落とす材料だった。特に、

```text
semantic relevance != executable capability
initial reasoning != committed reasoning
learned action != physically admissible action
derived visual memory != raw sensory evidence
synthetic source count != effective training-data diversity
persona fidelity != retained general cognition
```

を次の benchmark contract として固定する価値が高い。
