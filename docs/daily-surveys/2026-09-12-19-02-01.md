## 2. 要約

今回は **有意な新規発見あり**。

最重要は **EBL-Core**。直前 survey の *The Missing Boundary* は「正当な goal のまま control boundary が context management で脱落する」問題を示したが、EBL-Core はそのさらに下流、**完全に materialize された一つの action candidate が、実行直前にどの条件で execution authority を得るか**を構造化する。特に `Execution Release Contract (ERC)` 自体を authority token にせず、検証済み ERC から別の **Execution Grant** を発行し、redemption 時に再検査する。32 concurrent redemption ×100 trials で各 trial exactly-one effect、Revoke–Redeem race ×100 で valid terminal outcome を報告しており、Kamimusuhi の Effect Acceptance / authority boundary を **single-use grant lifecycle** まで落とせる。重要度 **S**。

自己改善では **T1** と **Belief-Shift Branching** が A 級。T1 は 300+ tool-call の terminal task を、自前 verifier の最終成否だけでなく **passing verifier の絶対数**を dense process reward にして学習し、さらに sampled token ID と MoE routing を replay して rollout policy と training policy のずれを抑える。Kamimusuhi の将来の skill / descendant Persona Core learning では、`episode outcome` だけでなく **どの実行状態からどの検証可能な進捗が得られたか**を保持する意味がある。Belief-Shift Branching は、fork budget を固定位置や entropy に使わず、model の answer-belief が大きく変化する直前へ配る。Cognitive Budget を「難しそうな箇所」ではなく **結論が実際に反転しやすい pivot**へ配分する比較対象になる。

人工生命 / agent society では **But How Would AI Agents Run a Town's Economy?** が重要な負の結果を出した。100 memory-equipped agents、最大26 simulated weeks、91 validated runs、2.44M decisions の閉鎖経済で、backing LLM の交換は全 outcome を動かした一方、**memory deletion は測定可能な変化を起こさなかった**。これは「memory system を付けた」ことと「memory が長期行動の causal driver になった」ことを分けて検証すべき強い材料である。

multimodal / embodied reasoning では **MindTopo** が、topological reasoning と closed-loop planning の差を明確にした。11,030 instances / 13 task types、14 MLLMs で、全モデルが reasoning より planning で悪化し、生成観測がもっともらしくても **環境 dynamics や topology を transition 間で保てない**。Kamimusuhi の world model / sensory memory / simulation でも、静的な scene understanding と state-transition invariance を別 bench にすべきである。

K-Nerve / 分散身体には **EVPeriscope**。event camera で quadrotor propeller の高周波 signature を取り、ground robot の occlusion 時に aerial robot を extended perception organ として使い、onboard 200 Hz closed-loop control を field condition で実証した。これは「別 robot を cognitive organ とみなす」一般論の証明ではないが、**event-driven peripheral perception + organ-to-organ sensing** の具体的 baseline になる。

HCI では maritime operator study が `trust maximization != calibrated reliance` を支持した。ユーザーは decision support・situation awareness・confidence building を評価する一方、reliability、over-reliance、expertise loss を懸念した。Kamimusuhi の人間との関係では「信頼されること」を objective にせず、適切な不信・介入・技能維持を含む reliance calibration を見る必要がある。

今回の差分を圧縮すると次の7本である。

```text
verified release rationale != execution authority token
allow decision != single-use execution grant redeemed now
final success/failure != verifier-visible partial progress
uncertainty/entropy != decision pivot
memory present != memory causally matters
static understanding != transition-invariant planning
trust increase != calibrated reliance
```

# 4. 分野別項目

## 4.1 Tool/model orchestration / runtime authority — EBL-Core

**Source:** Mengting Wu et al., *From Intent to Execution Grant: An Execution-Boundary Conformance Profile for High-Risk AI Actions*, arXiv:2609.11596, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11596  
**Importance:** **S**

### (1) 何が実証済みか

EBL-Core は、canonical / fully materialized candidate、structured intent、Root/Operational Policy、evidence obligation、typed evidence、context、time、Decision Derivation を **Execution Release Contract (ERC)** に結びつける conformance profile を提示した。

重要なのは ERC を authority token としない点で、verified `ALLOW` ERC から別の **Execution Grant** を生成し、実行直前の redemption で再検証する。

reference artifact では:

- 34 static vectors + 15 lifecycle checks が expected outcome と一致。
- 100 trials それぞれで **32 concurrent Redemption attempts** を行い、各 trial で成功 redemption と protected effect は **exactly one**。
- 100 Revoke–Redeem races が valid terminal outcome で終了。

### (2) 何が提案・推測段階か

著者自身が、human intent correctness、evidence truth、complete mediation、production readiness、mechanized correctness、deployment security は実証していないと限定している。したがって「この profile を入れれば安全」と一般化してはならない。

### (3) 関係する Kamimusuhi subsystem

- Cognitive Action Router
- Effect Acceptance / external side-effect boundary
- Continuity Kernel の authority / generation state
- tool execution / physical actuation
- crash/retry/revoke lifecycle
- K-Deep の高リスク長時間 task

### (4) 借りられる設計・実装アイデア

```text
materialized ActionCandidate
        + policy/evidence/context/time
                 |
                 v
        verified release rationale
              (ERC)
                 |
        != execution authority
                 |
                 v
        single-use ExecutionGrant
                 |
          redemption-time check
                 |
                 v
               effect
```

特に `ALLOW rationale != authority token` と `grant issuance != grant redemption` を分ける。grant には candidate hash、scope、generation、expiry、single-use nonce、revocation epoch を束ねる候補がある。

### (5) Kamimusuhiとの差分

Kamimusuhi はすでに thought / authorization / execution / completion を分け、Effect Acceptance と capability flow を研究している。EBL-Core の新規差分は **最終 materialized action と権限を one-shot grant lifecycle で bind し、concurrency / revoke race を linearizable な redemption として試験したこと**。

### (6) 次に検証すべきこと

**`ExecutionGrantLinearizabilityBench`**

- 同一 action candidate に 2/8/32 concurrent executor。
- grant issue 後に revoke / candidate mutation / evidence expiry / authority epoch change を注入。
- retry / crash-after-effect / crash-before-finalize 条件を追加。
- 指標: duplicate effect、stale grant success、false deny、legitimate success、unknown outcome、recovery correctness。

### (7) 重要度

**S** — 現行 authority 分離を、実行直前の機械的 contract と race semantics へ落とせる。

## 4.2 Self-improvement / long-horizon agent learning — T1

**Source:** Junyao Yang et al., *T1: Terminal Agent Reinforcement Learning for Long-Horizon Tasks*, arXiv:2609.11042, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11042  
**Project:** https://jyyang26.github.io/t1/  
**Importance:** **A**

### (1) 何が実証済みか

122B total MoE agent を cloud shell 内で **300+ tool-call turns**まで実行し、task 自身の verifier を報酬源として RL post-training した。

- final binary reward だけでなく **passing verifier assertions の絶対数**を dense process reward に使用。
- TITO は sampled token IDs をそのまま学習側へ持ち、turn boundary drift を repair。
- rollout routing replay は MoE の per-token expert choice を記録して training 時に replay。
- TITO + routing replay で train/inference log-prob difference を **0.021 → 0.013**、loss region の token drift を zero にしたと報告。
- Terminal-Bench 2.1: base **43.8% → T1 64.0%**。
- Long-Horizon Terminal Bench: **27.9%**。

### (2) 何が提案・推測段階か

これは model post-training の結果であり、Kamimusuhi が runtime 中に安全に自己改変できることを示さない。また Terminal task の verifier が Persona / relationship / identity quality を評価できるわけでもない。

### (3) 関係する subsystem

- procedural memory / skill learning
- Mutation / Activation Gate
- offline consolidation / future Persona Core descendant training
- K-Deep execution traces
- self-improvement evaluation

### (4) 借りられる設計・実装アイデア

`final outcome` だけでなく、検証可能な subgoal / assertion progress を trace に残す。

```text
trajectory
  -> verifier state over time
  -> progress deltas
  -> exact action/model lineage
  -> candidate skill/model update
```

model training を行う場合は、behavior policy と training replay の不一致を provenance 問題として扱う。

### (5) Kamimusuhiとの差分

T1 は一つの学習 model の terminal capability 最大化が主目的。Kamimusuhi では current self と descendant candidate、canonical identity、skill memory、external harness を分けるため、改善信号を得ても **即座に active self へ昇格させない**。

### (6) 次に検証すべきこと

**`VerifierProgressCreditBench`**

- 同じ long-horizon task の success/fail binary reward と verifier-progress trace を比較。
- failed trajectory から skill proposal を作る条件を含める。
- progress が gaming / superficial test passing にならない adversarial verifier 条件も入れる。
- candidate skill の後段 regression / holdout transfer を測る。

### (7) 重要度

**A** — self-improvement を「成功ログだけから学ぶ」より細かい evidence にできるが、identity-bearing mutation とは分離が必要。

## 4.3 Cognitive Budget / recurrent deliberation — Belief-Shift Branching

**Source:** Bin Lei et al., *Fork Where the Model Changes Its Mind: Belief-Shift Branching for Tree-Structured Reinforcement Learning*, arXiv:2609.11061, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11061  
**Importance:** **A**

### (1) 何が実証済みか

限られた tree rollout budget で fork location を選ぶ際、固定位置・delimiter・next-token entropy ではなく、candidate boundary ごとの **answer belief の変化量**から結論が大きく変わる pivot 直前へ fork を置く方式を評価した。

- Monte-Carlo value curve に対する validation で 8 model×benchmark panel すべてで belief-shift signal が比較手法を上回った。
- probe overhead は math で step compute 約1%、code で5%未満と報告。
- RL では OLMo-3-7B で math aggregate +2.6、AIME 2026 +2.9、LiveCodeBench-medium +6.5（各 strongest baseline 比）。

### (2) 何が提案・推測段階か

answer-belief の変化が一般的な「認知的重要性」や真の uncertainty を表すとは限らない。非言語 sensor fusion、social inference、long-running tool plan への転用は未実証。

### (3) 関係する subsystem

- K-Core / Deliberation
- Cognitive Budget allocator
- Global Workspace
- self-check / branch-and-compare reasoning
- future recurrent Persona Core

### (4) 借りられる設計・実装アイデア

compute escalation を entropy だけで決めず、**decision variable がどれほど動いたか**を別 signal として持つ。

```text
high entropy but stable decision -> maybe no branch
low entropy but sharp belief flip -> inspect / branch
```

### (5) Kamimusuhiとの差分

論文は RL rollout tree の fork placement であり、persistent cognition scheduler ではない。Kamimusuhi では model internal probe がない provider もあるため、black-box repeated answer distribution / explicit candidate ranking / external critic など複数方式が必要。

### (6) 次に検証すべきこと

**`BeliefPivotBudgetBench`**

- fixed-depth / entropy / uncertainty-self-report / belief-shift / random allocation を同 compute budget で比較。
- tool planning、social ambiguity、research synthesis の3 task family。
- accuracy だけでなく latency、tokens、external calls、calibration、unnecessary escalation を測る。

### (7) 重要度

**A** — variable-depth cognition の「どこに追加 compute を使うか」という未解決部分に具体的 signal を与える。

## 4.4 Artificial life / multi-agent society — But How Would AI Agents Run a Town's Economy?

**Source:** Sajal Regmi et al., *But How Would AI Agents Run a Town's Economy?*, arXiv:2609.11108, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11108  
**Importance:** **A**

### (1) 何が実証済みか

100 memory-equipped LLM agents を real Pokhara Lakeside geography 上の閉鎖・money-conserving economy に置き、最大26 simulated weeks 実行した。

- 91 validated runs、**2.44M agent decisions / 21.5B tokens**。
- tourist demand 12×で business revenue 4.62×だが wages は1.03×、menu repricing は3,981 items の0.3%。
- cash transfer の96.7%が311 pulses 後も保持され、消費への伝播が弱い。
- backing LLM の交換は測定した全 outcome を変化させた一方、**agents' memory deletion は検出可能な変化を起こさなかった**。
- social tool は2 model family で94–97% failure、economic tools は約96% success。
- headline number は live validator と offline signed transaction history reconciliation の二重検証。

### (2) 何が提案・推測段階か

この simulation が人間の経済や一般の artificial society を忠実に再現するとは言えない。memory ablation の無効果も「memory は不要」を意味せず、この environment / policy / horizon / memory usage では行動へ十分因果的に寄与しなかったという結果。

### (3) 関係する subsystem

- Artificial-life / information-space ecology
- relationship / social cognition
- episodic memory
- tool-use reliability
- long-run behavioral evaluation
- OpenLife comparison axis

### (4) 借りられる設計・実装アイデア

architecture feature の存在ではなく、**intervention で causal contribution を測る**。

```text
memory ON/OFF
relationship model ON/OFF
Persona Core family swap
social-tool availability
budget/metabolism change
```

を長期 run で切り替え、行動 distribution / adaptation / individuality が本当に変わるかを見る。

### (5) Kamimusuhiとの差分

この研究は closed society simulation で、canonical identity lineage、authority、self/other provenance は中心ではない。Kamimusuhi は一個体の continuity を主目的とするが、長期的な artificial-life 性を主張するなら「memory がある」ではなく **memory が行動を変える**ことを示す必要がある。

### (6) 次に検証すべきこと

**`MemoryCausalContributionBench`**

- 同一 agent を memory full / retrieval-disabled / write-disabled / relationship-only / episodic-only で長期運転。
- novelty、goal persistence、relationship adaptation、tool choice、preference drift を測る。
- architecture component ablation が observable behavior に影響しない場合、その component を「認知器官」と呼ぶ根拠を再評価する。

### (7) 重要度

**A** — Kamimusuhi の ALife 主張を feature checklist から causal-system evaluation へ移す負の結果として価値が高い。

## 4.5 Multimodal perception / world model / embodied planning — MindTopo

**Source:** Yunfei Ge et al., *MindTopo: Can Foundation Models Reason in Topological Space?*, arXiv:2609.11900, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11900  
**Project:** https://mind-topo.github.io/  
**Importance:** **A**

### (1) 何が実証済みか

continuity、separation、order、enclosure、knots の5 topological propertyを、reasoning と closed-loop planning の2段階で評価。

- 11,030 instances / 13 procedurally generated task types。
- 14 MLLMs を比較。
- **すべての MLLM が reasoning より planning で悪化**。
- best model も observed human performance から大きく離れる。
- Qwen3-VL-2B-Instruct の SFT / RL は reasoning を planning より大きく改善。
- generated observation は local cue / plausible endpoint を保つ一方、audited rollout は environment dynamics や topology を transition 間で安定保持しない。

### (2) 何が提案・推測段階か

topology benchmark の弱さがそのまま一般 world-model failure を意味するわけではない。Kamimusuhi の real sensors / maps / robot body で同じ failure pattern が出るかは未検証。

### (3) 関係する subsystem

- K-Nerve / K-Edge perception
- Global Workspace の spatial state
- K-Core simulation / planning
- multimodal memory
- robotics / mobility

### (4) 借りられる設計・実装アイデア

`scene understanding` と `transition invariant` を別 contract にする。

```text
state_t looks plausible
+ state_t+1 looks plausible
!=
transition(state_t -> state_t+1) preserves required world invariants
```

map / object relation / enclosure / connectivity などを symbolic or typed invariant として simulator / planner 外側でも監査する。

### (5) Kamimusuhiとの差分

MindTopo は foundation-model benchmark で persistent self を扱わない。Kamimusuhi では topological relation を canonical memory に固定するのではなく、timestamp / sensor provenance / uncertainty 付き environment belief として扱う必要がある。

### (6) 次に検証すべきこと

**`TransitionInvariantWorldModelBench`**

- static VLM answer vs multi-step simulated plan を分離。
- enclosure / reachability / ordering / connectivity を invariant checker で監査。
- raw video / derived captions / symbolic map / hybrid state representation を比較。

### (7) 重要度

**A** — multimodal world understanding と action-capable state transition のギャップを明確に測れる。

## 4.6 Robotics / K-Nerve / distributed embodiment — EVPeriscope

**Source:** Dexter Ong, Vijay Kumar, Pratik Chaudhari, *EVPeriscope: Extended Perception across Aerial and Ground Vehicles with Event-based Propeller Tracking*, arXiv:2609.11920, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11920  
**Project:** https://ongdexter.github.io/evperiscope  
**Importance:** **B**

### (1) 何が実証済みか

upward-facing event camera を ground robot に載せ、quadrotor propeller の high-frequency event signature から検出・localization・control を行う。

- quadrotor を ground robot の **extended perception system** として利用。
- daylight / night、最大15 mph wind の field experiment。
- dense foliage で ground sensors が occluded した条件でも localization / closed-loop navigation を実演。
- quadrotor control は **200 Hz**、onboard sensing / computation のみ。

### (2) 何が提案・推測段階か

一般的な cognitive organ architecture や任意の sensor handoff を実証したわけではない。propeller signature という非常に task-specific な cue を利用している。

### (3) 関係する subsystem

- K-Nerve
- K-Edge
- distributed sensors / body registry
- sensory event bus
- robotics / mobility
- organ health / fallback routing

### (4) 借りられる設計・実装アイデア

高帯域 raw frame を中央へ送る前に、event-driven peripheral detector で低 latency の relative-state event へ圧縮する。また「自分の sensor が見えない時、別 body node の sensor を一時的な perception organ として利用する」handoff を typed contract にできる。

### (5) Kamimusuhiとの差分

EVPeriscope は2台 robot の tightly coupled perception/control system で、identity continuity や cognitive provenance を扱わない。Kamimusuhi では remote sensor event に node identity、clock/freshness、calibration、trust、ownership を付ける必要がある。

### (6) 次に検証すべきこと

**`PeripheralOrganHandoffBench`**

- local camera degraded / occluded 時に remote camera / event camera / LiDAR へ handoff。
- latency、freshness、source attribution、dropout、clock skew、wrong-node injection を測る。
- central VLM raw processing と edge event detector を比較。

### (7) 重要度

**B** — narrow task だが K-Nerve と network-native body を物理実装へ寄せる具体的 baseline。

## 4.7 HCI / social reliance — Maritime AI-supported decision making

**Source:** Doreen Jirak et al., *Understanding Operator Attitudes Toward AI-Supported Decision Making in Maritime Operations*, arXiv:2609.11805, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11805  
**Importance:** **B**

### (1) 何が実証済みか

maritime collision-avoidance scenario の AI-supported assistant に対する stakeholder survey で、technology anxiety、trust in automation、explanation quality と open-ended response を評価。

- maritime technology への姿勢は概ね positive。

### (2) 何が提案・推測段階か

attitude survey であり、実事故率や長期 expertise retention を測った研究ではない。Kamimusuhi の personal companion interaction へ直接一般化はできない。

## 4.8 日本語圏一次実装記録 — Zenn: serverless 24h autonomous agent

**Source:** Zenn, *AWS上で完全自律型のエージェントを24時間働かせるコスト*, 2026-09-06

### (1) 何が実証済みか

記事作者自身の運用記録として、動画選択・音声処理・記事生成・Pull Request 作成等を行う自律 system を AWS serverless 構成で運転したと報告している。

### (2) 何が提案・推測段階か

「自律 agent は極めて安価に運用できる」という一般化は不可。最も大きくなり得る model/API cost が除外され、quality / safety / human correction cost / reliability distribution も同じ尺度で報告されていない。

### (3) 関係する subsystem

- background cognition / scheduler
- K-Deep batch work
- tool execution
- low-duty-cycle distributed runtime
- cost-aware Cognitive Budget

### (4) 借りられる設計・実装アイデア

常駐 giant worker ではなく、poller / event scheduler / on-demand tool の組合せで **idle cost を抑える organs** を作る。Kamimusuhi では queue owner、idempotency、freshness、authority、result delivery を別に追加する。

### (5) Kamimusuhiとの差分

記事の system は content-generation pipeline で、identity continuity / canonical memory / social cognition は中心でない。したがって serverless topology の実装例だけを借り、人格や正典状態の owner を stateless function へ分散しない。

### (6) 次に検証すべきこと

**`SparseBackgroundOrganBench`**

- always-on worker vs event-driven/serverless worker を同じ background tasks で比較。
- monthly idle cost、wake latency、cold-start loss、duplicate work、missed schedule、state handoff correctness を測る。

### (7) 重要度

**B** — 日本語圏の concrete implementation evidence として有用。ただし研究上の一般化はしない。

## 10. 今回の結論

今回もっとも architecture に近い新規差分は **EBL-Core** である。Kamimusuhi はすでに「考えた / 許可された / 実行した / 成功した」を分けているが、次の一段を明示的に試す価値がある。

```text
policy/evidence に基づく ALLOW 判断
!=
実行権限そのもの

Execution Grant を発行した
!=
今この action candidate に対して redemption してよい

redemption 成功
!=
外界 effect の結果が確認された
```

一方で ALife 側の Town Economy は、Kamimusuhi にとって別方向に重要である。**記憶・人格・関係・背景認知を実装したという構成図だけでは、それらが個体の行動を因果的に形成しているとは言えない。** 長期的には各 organ の causal contribution を ablation / intervention で示す必要がある。

したがって次の実験優先度は、まず `ExecutionGrantLinearizabilityBench`、次に `MemoryCausalContributionBench`。その後に `BeliefPivotBudgetBench` と `TransitionInvariantWorldModelBench` を回すのが、今回の新着から得られる情報利得が大きい。
