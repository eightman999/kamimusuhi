## 重要発見

### A — TwinCheck

Source: https://arxiv.org/abs/2609.26911

1. **実証済み:** evidence条件を満たした時だけnegative twinを作り、structural checkと順序反転pairwise verificationを通して置換する。159 BFCL V4 exact-replay pairsでGPT-5.6 Solのtask success 45.3%→58.5%、95% CI +8.2〜+18.8 points、観測されたsuccess→failure regressionは0。
2. **提案段階:** BFCLから一般のself-repairへの外挿とverifier common-mode failureは未解決。
3. **関係subsystem:** Cognitive Action Router、K-Deep repair、Mutation/Activation Gate。
4. **借りる案:** failure hypothesis → evidence → candidate twin → structural check → comparative verification → replace/abstain。
5. **差分:** durable mutationだけでなく単一tool actionのrepairにもcounterfactual admission gateを適用できる。
6. **次に検証:** `CounterfactualActionReplacementBench-v0`。
7. **重要度:** **A**

### A — ChronoFuse / Availability-time Perception

Source: https://arxiv.org/abs/2609.26919

1. **実証済み:** event detectorをoutput availability timeで評価すると性能が低下する問題を示し、ChronoFuseはfuture observationなしでavailability時点を予測。+0.17M params / +0.84ms overhead、1Mpxでlatency lossの71%、FREDで90.8%を回復、EV-Flying 20.95 sAP vs 2.25。
2. **提案段階:** 他modalitiesへの一般化は未検証。predictionはcanonical observationではなくderived estimateとして扱うべき。
3. **関係subsystem:** K-Nerve、multimodal perception、embodied K-Edge、Event Bus freshness。
4. **借りる案:** observed_at / computed_at / available_at / prediction horizon / uncertaintyをsensory eventへ持たせる。
5. **差分:** staleなら捨てるだけでなくknown latencyぶん未来を補償する。
6. **次に検証:** `AvailabilityTimePerceptionBench-v0`。
7. **重要度:** **A**

### A — Semantic Progress Witness

Source: https://github.com/openclaw/openclaw/issues/157491

1. **実証済み:** 内容が変わらないprogress更新でもrevision metadataが変わることでloop protectionが「変化あり」と扱う再現例が報告された。stable receipt controlとの比較でも差が出た。
2. **提案段階:** revision自体はaudit/freshnessには必要なので消すべきではない。
3. **関係subsystem:** agent loop、background cognition、retry、Cognitive Budget、homeostasis。
4. **借りる案:** ToolReceiptをaudit metadataとsemantic outcomeへ分離し、no-progress判定はsemantic projectionを見る。
5. **差分:** provenance-rich receiptを重視するKamimusuhiほど、receipt churnをprogress witnessにしないことが重要。
6. **次に検証:** `SemanticProgressWitnessBench-v0`。
7. **重要度:** **A**

### A — Effective Resource Budget

Source: https://github.com/openclaw/openclaw/issues/157575

1. **実証済み:** child workerのresource limit表示と、parent runtime設定を含めた実効heap ceilingが大きくずれる再現例が報告された。
2. **提案段階:** larger effective ceilingが直ちにfailureを意味するわけではない。
3. **関係subsystem:** Computational Embodiment、Cognitive Budget、K-Edge/Core/Deep worker、resource regulator。
4. **借りる案:** requested / inherited / effective / observed peak / enforcement ownerをResourceBudgetReceiptへ分離。
5. **差分:** budgetを「設定値」ではなく実効enforcement stateとして扱う。
6. **次に検証:** `HierarchicalResourceBudgetEffectivenessBench-v0`。
7. **重要度:** **A**

### B — Evaluation Traffic Memory Isolation

Source: https://github.com/NousResearch/hermes-agent/issues/121935

1. **実証済み:** real profileへeval suiteを流した環境で、test interaction由来の長期memoryが実ユーザーmemoryへ混入し、後の会話へ再利用された事例が報告された。
2. **提案段階:** eval時にreadも止めるか、writeだけshadow化するかは評価目的次第。
3. **関係subsystem:** episodic / relationship memory、evaluation harness、dream / simulation、canonical evidence admission。
4. **借りる案:** production / eval / simulation / replay / synthetic-userをoriginで分け、eval write-backをshadow namespaceへ送る。
5. **差分:** evaluation interactionをautobiographical experienceへ自動昇格させない。
6. **次に検証:** `EvaluationMemoryContaminationBench-v0`。
7. **重要度:** **B**

### B — Reasoning Trace Causal Use

Source: https://arxiv.org/abs/2609.27038

1. **実証済み:** Qwen3-4Bのself-generated reasoning stepsは76.9%±2.8%がcausally load-bearing。behavioral testは88.2%で11.4 points過大評価。Qwen3-1.7Bはoverall 54.8%。
2. **提案段階:** synthetic lookupから自然agent reasoningへの一般化は未検証。
3. **関係subsystem:** reflection、self-model、metacognition、self-improvement credit assignment。
4. **借りる案:** self-reportをcausal provenanceへ直昇格せず、可能ならintervention / ablation / replayで確認。
5. **差分:** reflection/evidence分離を定量negative evidenceで補強。
6. **次に検証:** `ReasoningTraceCausalUseBench-v0`。
7. **重要度:** **B**

### B — Cross-Modal Evidence Order

Source: https://arxiv.org/abs/2609.26986

1. **実証済み:** instruction/evidence contentを固定し、conflicting textとimage/speechの位置だけ交換するとjudgmentが系統的に変化した。
2. **提案段階:** conflictのないinputや全modelへの一般化は未確定。
3. **関係subsystem:** Global Workspace、multimodal fusion、evidence/belief update。
4. **借りる案:** source arrival orderとauthorityを分離し、conflict時はcanonical ordering / permutation / structured fusionを比較。
5. **差分:** 非同期Event Busではnetwork jitterがevidence orderを変えるためtransport order leakが実運用上重要。
6. **次に検証:** `CrossModalEvidenceOrderInvarianceBench-v0`。
7. **重要度:** **B**

### B — Intent-Conditioned Turn Timing / TACT

Source: https://arxiv.org/abs/2609.27372

1. **実証済み:** 9,728 episodes / 73.2h / 5 dyadic corpora。intent-conditioned timing scoreを導入し、11 systemsでbest 0.47 vs human 0.86、human judgmentとのSpearman 0.81 vs binary 0.46。
2. **提案段階:** 日本語会話へのtransferは未検証。
3. **関係subsystem:** full-duplex speech、K-Nerve backchannel、social cognition、Relationship Memory。
4. **借りる案:** silence/overlapを即failureにせずintentとspeaker historyでtimingを評価。
5. **差分:** latencyとsocial appropriatenessを別metricにする。
6. **次に検証:** `IntentConditionedTurnTimingBench-v0`。
7. **重要度:** **B**

### B — Recall Supersession and Rank Hygiene

Source: https://github.com/NousResearch/hermes-agent/issues/121900

1. **実証済み:** superseded run-logや大きなevent summaryが現在のpreference情報より上位にretrievalされる事例が報告された。
2. **提案段階:** curated preferenceを常にraw evidenceより高rankにすべきとは限らない。
3. **関係subsystem:** Relationship Memory、derived retrieval index、supersession、workspace projection。
4. **借りる案:** authority domain / supersession status / evidence class / source_idをretrieval candidateへ持たせる。
5. **差分:** canonical truth authorityとretrieval salienceは別物。
6. **次に検証:** `SupersessionAwareRecallRankingBench-v0`。
7. **重要度:** **B**
