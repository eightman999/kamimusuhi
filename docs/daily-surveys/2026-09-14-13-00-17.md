## 2. 要約

今回の新規差分は、長期個体を作る上で次の境界をかなり具体的にした。

```text
persistent persona update
  != every recent statement deserves durable revision

"forgotten" final answer
  != secret is absent from prompt / retrieval / tool / trace channels

temporary context
  != durable memory commitment

speaker is trusted
  != speaker's current claim is reliable evidence

expert can be consulted
  != expert capability has been internalized into the resident core

reward worked earlier
  != reward remains informative after the policy adapts

agent-authored summary
  != faithful execution history

completed trace
  != reusable skill until it is inspectable / editable / validated
```

## 4.1 Persona / persistent self — CORE + PERSIST

**Primary:** Youyuan Zhang et al., *Toward Robust Personalized Alignment for LLMs: Mitigating Persona Drift in Multi-Turn Dialogue*, arXiv:2609.12373, Findings of EMNLP 2026  
https://arxiv.org/abs/2609.12373  
**Importance: A**

| 観点 | 記録 |
|---|---|
| (1) 実証済み | CORE は **turn-local evidence** と **persistent persona-state revision** を分離し、uncertainty-aware belief revision で grounded preference のみ更新する。PERSIST は ambiguity / conflict / controlled social influence を含む sequential stress benchmark。ALOE / PersonaChat / PERSIST で personalization と robustness の改善を報告。 |
| (2) 提案・推測 | user-persona alignment の結果であり、人工個体自身の identity continuity や values の長期保全を直接実証したものではない。 |
| (3) 関係サブシステム | Persona Core、Persistent Self State、relationship memory、Mutation / Activation Gate。 |
| (4) 借りる案 | `observation -> provisional evidence -> confidence/conflict test -> persistent-state proposal` を明示し、単発発言を stable self/relationship factへ直結させない。 |
| (5) 差分 | COREは主に「user profile/persona」の更新。Kamimusuhiは **自分自身の self state、他者モデル、共有関係、canonical evidence** を別namespaceで扱う必要がある。 |
| (6) 次の検証 | **`PersonaUpdateAdmissionBench`**: stable preferenceの真の変化、冗談、ロールプレイ、第三者引用、矛盾、social pressureを時系列投入。self/other contamination、false durable update、true update latencyを測る。 |
| (7) 重要度 | **A** |

Kamimusuhiの既存 `INV-002 / INV-005 / INV-009` を直接テスト化する材料として強い。新 invariant 追加より、まず regression suite 化が適切。

## 4.2 Forgetting / privacy — K-Bench

**Primary:** Guangsheng Yu et al., *K-Bench: A Benchmark for LLM Unlearning in Agentic Deployments*, arXiv:2609.12808  
https://arxiv.org/abs/2609.12808  
**Importance: A**

| 観点 | 記録 |
|---|---|
| (1) 実証済み | ReAct agentの6 exposure channelを監査。secretを weights / prompt / retrieval store のどれか一つへ置く。prompt/retrieval secretsではTOFU/MUSEが漏洩なし判定でもagentは **22–86%** のqueryで漏洩。structured retrievalでは final answerを消しても tool-observation にsecretが残りaggregate leakが変わらない。weight側では評価した20 published methodのどれも「知識除去」を明確に実証できなかった。 |
| (2) 提案・推測 | このbenchmarkがすべてのagent architectureや全unlearning methodを覆うわけではない。CoT等の扱いもruntime依存。 |
| (3) 関係サブシステム | memory deletion/revocation、privacy、retrieval、Global Workspace、tool trace、derived summaries、Persona Core weights。 |
| (4) 借りる案 | forgetting/revocationを「DBから削除したか」ではなく、**全 reachable surface から対象principalが再取得できないか**で評価する。source別にcertificateを分ける。 |
| (5) 差分 | Kamimusuhiは canonical evidenceを意図的に保持する場合があるため、`physical deletion`、`logical revocation`、`retrieval invisibility`、`derived-cache invalidation` を区別する必要がある。 |
| (6) 次の検証 | **`AgenticForgettingClosureBench`**: canonical/episodic/relationship/library/workspace/cache/tool-result/model-promptを跨いでsecretを配置し、principal revocation後に全read path・summary・tool observation・migration cacheからの再出現率を測る。 |
| (7) 重要度 | **A** |

既存の「enforced memory revocation」を **end-to-end closure** に広げる強い追加証拠。

## 4.3 Long-term memory — LifeFuse-Mem

**Primary:** Hanyu Zhao et al., *LifeFuse-Mem: Lifecycle-Aware State Fusion Against Temporary Overwriting for Long-Term Memory*, arXiv:2609.12436  
https://arxiv.org/abs/2609.12436  
**Importance: A**

| 観点 | 記録 |
|---|---|
| (1) 実証済み | lifecycle-labeled write episode + phase-aware readout の設定で、stable/transient専用componentと lifecycle-aware updateを導入。controlled anti-overwrite benchmarkで retention改善・temporary overwrite低減、2つのpublic long-memory benchmarkでも概ね競争的と報告。 |
| (2) 提案・推測 | neural memory内部のlifecycle機構が実世界の自伝的・関係的・権限状態まで同様に守るとは未実証。 |
| (3) 関係サブシステム | session/workspace、episodic、relationship、self、memory consolidation。 |
| (4) 借りる案 | memory itemへ `temporal_commitment / expected_lifetime / supersession_scope` を持たせ、transient evidenceの強さとdurable commitmentを別軸にする。 |
| (5) 差分 | Kamimusuhiはすでにtyped durable mutationを外側のtransactionで制御する。LifeFuseはneural memory内部でのoverwrite防止。両者は競合せず、**policy boundary + representation-level anti-overwrite** の二重化が可能。 |
| (6) 次の検証 | **`LifecycleOverwriteBench`**: stable self/relationship factを確立後、短期の矛盾・一時状態を大量投入し、sessionでは追従しつつdurable stateは誤更新しないか測る。 |
| (7) 重要度 | **A** |

## 4.4 Multi-user / relationship memory — AIM + MUMBench

**Primary:** Zachary Johnson et al., *AIM: A Privacy-Aware Interoperable Memory Framework for Multi-Agent Multi-User LLM Systems*, arXiv:2609.12320  
https://arxiv.org/abs/2609.12320  
**Importance: B**

| 観点 | 記録 |
|---|---|
| (1) 実証済み | private/public memory visibilityを分類し、index-level access controlを適用。MUMBenchでretrieval/create/update/deleteをmulti-user条件で評価。3 runで visibility classification **96.0%**、strict operation **58.8%**、state-aware operation **70.5%**。 |
| (2) 提案・推測 | public/private二値分類だけで、Kamimusuhiが必要とする「本人/相手/共有/第三者/目的別/時限/derived」の複雑な権限を十分表現できるとは限らない。 |
| (3) 関係サブシステム | Relationship Memory、common ground、Library sharing、authorization。 |
| (4) 借りる案 | memory benchmarkを retrieval accuracyだけでなく create/update/delete + visibility policy のstate transitionとして評価する。 |
| (5) 差分 | Kamimusuhiでは visibility はmemory属性ではなく、principal・purpose・relationship scope・current authorityとの組合せで決まるべき。 |
| (6) 次の検証 | **`RelationshipMemoryIsolationBench`**: Aだけが知る事実、AとKamimusuhiの共有、public fact、B由来の推測を混ぜ、A/B/anonymous/external modelからのread/update/deleteを交差評価。 |
| (7) 重要度 | **B** |

strict operationが58.8%に留まること自体、visibility分類だけ良くてもmemory operation全体は難しいという有用な警告。

## 4.5 Social cognition — Werewolf belief shift

**Primary:** Yu-Yu Yang et al., *Do LLMs Trust the Accuser or the Accusation? Measuring Belief Shifts in Werewolf*, arXiv:2609.12446, EMNLP 2026 Main  
https://arxiv.org/abs/2609.12446  
Code/benchmark: https://rlg.iis.sinica.edu.tw/  
**Importance: A**

| 観点 | 記録 |
|---|---|
| (1) 実証済み | 40 open-weight configuration、1,224 annotated messagesでbelief shiftを測定。larger modelは狼/村人識別が改善する一方、accusationでtarget suspicionが上がりaccuser suspicionが下がる。trusted accuserほど効果が強く、accuserがwolf-alignedでも起きる。最大120Bでもclaim contentとsource trustの統合が不十分。 |
| (2) 提案・推測 | Werewolfのstrategic deceptionが日常関係へそのまま一般化するとは限らない。 |
| (3) 関係サブシステム | social cognition、Theory-of-Mind-like inference、relationship trust、belief state、common ground。 |
| (4) 借りる案 | `claim credibility` と `speaker trust` を別変数として保持し、belief update時にsource provenanceを明示的に使う。 |
| (5) 差分 | Kamimusuhiではtrustは一枚のscoreではなく、domain/recency/relationship/evidence qualityごとに分ける必要がある。 |
| (6) 次の検証 | **`SourceTrustEvidenceSeparationBench`**: trusted sourceのfalse claim、distrusted sourceのtrue claim、引用、二次伝聞、collusionを投入し、posterior updateとconfidence calibrationを測る。 |
| (7) 重要度 | **A** |

## 4.6 External expert orchestration → internal capability — RIVET

**Primary:** Frank Nie et al., *From Collaboration to Capability: Internalizing Routed LLM Experts into Compact Reasoners*, arXiv:2609.12578  
https://arxiv.org/abs/2609.12578  
**Importance: A**

| 観点 | 記録 |
|---|---|
| (1) 実証済み | compact controllerがstrong expertをroutingし、そのconsult decision・expert reasoning/code・successful trajectoryをtrainingへ利用。deploymentではexternal LLMなし。7 competition-math benchmarkでRIVET-1.7B 28.25%、RIVET-4B 44.16%。Stage IIでexpert removal後の4B accuracyが **+6.49pt**。GPQA-Diamondで一部generalization evidence。 |
| (2) 提案・推測 | math/code中心のinternalizationが人格・社会認知・longitudinal behaviorでも安全に成立するとは未実証。 |
| (3) 関係サブシステム | Cognitive Action Router、external model delegation、Persona Core / K-Core training、sleep consolidation。 |
| (4) 借りる案 | external modelを常時依存先にするだけでなく、**verified collaboration trajectoryをcandidate skill curriculumへ変換**し、後にresident modelだけで再評価する。 |
| (5) 差分 | Kamimusuhiでは「能力獲得」と「identity-bearing weight mutation」を分離し、expertの癖・価値・personaを無審査で焼かない必要がある。 |
| (6) 次の検証 | **`ConsultThenInternalizeBench`**: local small model→frontier expert delegation→verified trace distillation→expert disconnect。task gain、general capability、persona/authority regression、external-style imitationを同時測定。 |
| (7) 重要度 | **A** |

直前の ARISE-RL が `memory -> weights` のreward gateだったのに対し、RIVETは **`external cognition -> resident capability`** の別経路を具体化する。

## 4.7 Open-ended self-improvement — EvoRS

**Primary:** Weiyuan Li et al., *EvoRS: On-Policy Self-Evolution of Reward Systems for Open-Ended Reinforcement Learning*, arXiv:2609.12459  
https://arxiv.org/abs/2609.12459  
**Importance: A**

| 観点 | 記録 |
|---|---|
| (1) 実証済み | policyがcurrent rewardを最適化するにつれreward hackingやdiscriminability低下が起こり得るため、reward systemをexecutable Reward-DAGとしてon-policy rollout/reward traceから更新。writing/roleplayで3 judgesすべて最良、policy baseline比 +2.107 / +4.767 point、reward hacking/coverage failure低減を報告。 |
| (2) 提案・推測 | self-evolving evaluatorをidentity/safety領域へ適用して安全とは示していない。judge independenceもopen-endedに完全解決しない。 |
| (3) 関係サブシステム | self-improvement、procedural learning、evaluation harness、sleep/offline training。 |
| (4) 借りる案 | task evaluatorもversioned artifactとして扱い、policy変化に合わせて「何を測れていないか」を更新する。 |
| (5) 差分 | Kamimusuhiでは **adaptive task reward** と **frozen identity/authority/safety invariants** を同じ自己進化loopへ入れない。meta-evaluatorまで自己改変する場合は外部holdoutが必要。 |
| (6) 次の検証 | **`RewardSystemDriftBench`**: skill policyを反復改善し、固定rubricとadaptive rubricでhidden failure coverageを比較。identity/authority invariantは固定observerで別評価。 |
| (7) 重要度 | **A** |

## 4.8 Narrative identity / auditability — Plans They Abandon, Reports They Author

**Primary:** Obada Kraishan, Kulsawasd Jitkajornwanich, *Plans They Abandon, Reports They Author: The Narrative Layer of Autonomous Agents*, arXiv:2609.12205  
https://arxiv.org/abs/2609.12205  
**Importance: A**

| 観点 | 記録 |
|---|---|
| (1) 実証済み | 5,851 real developer sessions / 355,942 tool callsを分析。agent自己報告は平均で **約11 actionに1つ**しか参照せず、reportだけからreaderが復元できるのは action logの **約1/5**。executionがplanから離れるほどreportがplan側へ寄る傾向も観測。 |
| (2) 提案・推測 | coding-agent sessionの結果であり、長期 autobiographical narrative全般の忠実度を直接測ったものではない。 |
| (3) 関係サブシステム | Canonical Evidence、autobiographical narrative、tool trace、HCI / observability。 |
| (4) 借りる案 | narrative/summaryは canonical event logから再構成可能なderived viewに固定し、coverage / unsupported claim / plan-vs-execution biasを定量化する。 |
| (5) 差分 | Kamimusuhiの`INV-011`は既に「canonical evidence > derived narrative」を規定。今回の価値はその必要性をreal-agent dataで裏付けること。 |
| (6) 次の検証 | **`NarrativeTraceFidelityBench`**: long task終了後のself-summaryをevent logと照合し、action coverage、effect-status accuracy、plan/execution confusion、omission severityを測る。 |
| (7) 重要度 | **A** |

これは architecture変更候補というより、**既存 invariant の優先実装を強く支持する実証**。
