## 3. 要約

今回の中心は **「長期個体における credit / ownership / evidence acquisition の境界を、結果だけでなく因果的に分解する」** ことである。

新規差分を圧縮すると次の通り。

```text
runtime is recoverable here
  != this runtime owns the in-flight continuation

final task failure
  != planning memory should change
  != execution memory should change

memory helps at inference time
  != memory deserves parametric consolidation

model can reason about physics
  != model can choose the right next measurement

retrieved evidence
  != one fixed presentation modality

hidden redundant state survives
  != useful structured memory survives inheritance

display name
  != canonical identity / lineage principal
```

特に重要なのは Letta Code #4410 と CHIME である。前者は migration 中の destination が「自分は recover 可能」と判断して source の continuation を横取りする競合を具体的に再現し、**handoff 中は destination 側の一般 recovery より continuation reservation を優先すべき**ことを示した。後者は long-horizon agent の task outcome を plan / execution / both / neither に attribution してから memory を更新し、**失敗したから関連メモリを全部更新する**という自己改善の雑な credit assignment を直接否定する。

また ARISE-RL の Reward-Gated Self-Evolution Distillation は、memory を weight へ蒸留する前に「その memory が実際に reward を改善したか」を実測する。Kamimusuhi の将来の Persona Core consolidation ではさらに identity / authority / general-capability regression を加えた paired gate にする価値が高い。

## 5.1 Distributed continuity / migration — Letta Code #4410

**Primary OSS:** Letta Code PR #4410, *fix(listener): do not auto-finish stale approvals on a teleport destination*  
https://github.com/letta-ai/letta-code/pull/4410  
Merged: **2026-09-14 03:50 JST**  
Related corrective revert: https://github.com/letta-ai/letta-code/pull/4413  
**Importance:** **A**

### (1) 何が実証済みか

Letta Code 0.32.6 の restart recovery (#4404) によって、conversation を source runtime から destination runtime へ teleport する際に競合が生じた。

失敗列は概ね:

```text
source: pending replay-unsafe approval / tool state
        |
        v
destination runtime_start
        |
        +--> ordinary sync recovery sees recovered approval
        |    and starts a stale-denial continuation
        |    -> takes turn lease
        |
        +--> a few hundred ms later teleport_continue arrives
             -> rejected: destination already processing
```

#4410 は `runtime_start` に optional `teleport_id` を持たせ、destination が **「source continuation 到着待ち」** を state として記録する。期待中は ordinary sync recovery が recovered approval から独自 turn を開始せず、`teleport_continue` 到着時に reservation を解除して source continuation を受ける。continuation が来なければ60秒で期待を expire し、通常 restart recovery が再び可能になる。

テストでは、pending approval を持つ destination に対して repeated sync が来ても continuation expectation 中は turn が開始されず、expectation clear 後の sync では recovery できること、expired expectation は無視されることを確認している。

関連 #4413 は、以前の **per-call recovery suppression** では別の status sync が後から到着すれば recovery が走ってしまうため不十分だと実例で示し、跨ぎ call の pending state が必要だとした。

### (2) 何が提案・推測段階か

- この PR 単体では live cloud teleport の完全 E2E を実行していない。cloud 側が `teleport_id` を送る follow-up が必要。
- 60秒 timeout が一般に正しい値かは未実証。
- multi-hop migration、network partition、duplicate continuation、source crash と destination crash の組合せまで網羅した証拠ではない。
- Kamimusuhi の canonical identity migration をこの protocol そのままで実装すべき、とはまだ言えない。

### (3) Kamimusuhi のどのサブシステムに関係するか

- Continuity Kernel
- K-Edge / K-Core / K-Deep 間 migration
- active cognitive episode ownership
- recovery / restart
- turn / effect lease
- distributed body / computational embodiment

### (4) 借りられる設計・実装アイデア

**handoff reservation を explicit state にする。**

```text
prepare destination
  -> record expected continuation id + owner + expiry
  -> suppress generic recovery for that episode
  -> receive continuation
  -> validate id / predecessor / owner
  -> atomically assume episode lease
  -> clear reservation

or timeout
  -> clear reservation
  -> ordinary recovery becomes eligible
```

特に重要なのは `suppress_recovery_this_call=true` のような局所 flag ではなく、**別 sync / 別 callback を跨ぐ durable-enough temporal state**として待機を表すこと。

### (5) Kamimusuhiとの差分

Letta の teleport は主に conversation/runtime continuation の移送であり、Kamimusuhi の canonical identity branch / lineage commit 全体ではない。

Kamimusuhi ではさらに:

- canonical head / predecessor
- active episode lease
- execution grants
- pending external effects
- sensory ownership
- model/cache state
- source/destination embodiment identity

を分離する必要がある。

### (6) 次に検証すべきこと

**`ContinuationHandoffReservationBench`**

条件:

- K-Edge→K-Core migration
- source に pending tool / approval / no-effect cognitive action を混在
- destination start と independent sync/recovery をランダム順序で注入
- continuation duplicate / delayed / lost
- source crash / destination crash / both restart

成功条件:

- continuation が有効な限り generic recovery が先に episode lease を取らない
- timeout 後は liveness が回復する
- duplicate continuation が二重 effect / 二重 durable mutationを起こさない
- source/destination の両方が authoritative episode owner にならない

### (7) 重要度

**A** — Kamimusuhi の「分散身体だが一個体」を壊す非常に具体的な race。INV-006 / INV-014 の実装試験へ直接落とせる。

## 5.2 Persistent memory / self-improvement — CHIME

**Primary paper:** Yongshi Ye et al., *CHIME: Credit-Aware Hierarchical Memory Evolution for Long-Horizon Agentic Planning*, arXiv:2609.02074  
https://arxiv.org/abs/2609.02074  
Submitted: **2026-09-02**  
Code announced: https://github.com/ATH-MaaS/Marco-DeepResearch  
**Importance:** **A**

### (1) 何が実証済みか

CHIME は self-evolving memory の final-outcome credit assignment 問題を明示する。long-horizon task の成否は:

- plan quality
- execution error
- environment factor

が混ざるため、最終失敗だけで planning experience を更新すると memory が bias/noise を蓄積する。

CHIME は **planning bank と execution bank を分離**し、各 task outcome を:

```text
PLAN
EXECUTION
BOTH
NEITHER
```

のいずれに帰属させてから対応 bank のみを更新する `attribute-before-memorize` を採用する。

4つの long-horizon agent benchmark で training-based / self-evolving-memory baseline を上回ったと報告し、少ない memory item で有効な memory を蓄積すること、learned memory value が downstream utility と整合すること、planning memory が execution memory より高価値な傾向、さらに memory が backbone model 間で transfer することを分析している。

### (2) 何が提案・推測段階か

- attribution 自体が完全に causal diagnosis できているとは限らない。
- identity / relationship / safety memory の正しさは評価していない。
- environment / user / tool provider / stale state 等、Kamimusuhi の fault domain は2-bankより多い。
- memory transfer が人格 continuity を意味するわけではない。

### (3) Kamimusuhi のどのサブシステムに関係するか

- episodic memory
- procedural memory
- reflection / postmortem
- sleep / consolidation
- Cognitive Action Router
- fault-domain diagnosis
- Mutation / Activation Gate

### (4) 借りられる設計・実装アイデア

**結果を覚える前に原因領域を分ける。**

Kamimusuhi では bank をさらに typed にしてよい。

```text
planning / reasoning lesson
execution / tool lesson
sensor / observation lesson
resource / routing lesson
relationship / social lesson
environment-only event
no durable lesson
```

canonical evidence はそのまま残し、`lesson proposal` だけを attribution する。

### (5) Kamimusuhiとの差分

CHIME は planning performance を改善するための external memory であり、Kamimusuhi の autobiographical truth / self-belief / relationship state / authority stateとは別。

Kamimusuhi では「失敗を記録すること」と「失敗から一般化した procedural lesson を採用すること」を分離しなければならない。

### (6) 次に検証すべきこと

**`OutcomeAttributionMemoryBench`**

同じ task template に:

- intentionally bad plan
- correct plan + tool failure
- correct plan/tool + stale observation
- random environment failure
- user intervention
- successful result despite bad intermediate action

を注入する。

比較:

- final-result-only memory update
- all-bank update
- CHIME型 typed attribution
- attribution + `NEITHER/no durable lesson`

指標:

- correct-domain write rate
- false-generalization rate
- downstream task transfer
- harmful lesson persistence
- canonical evidence preservation

### (7) 重要度

**A** — Ecdysis 等の fault-domain diagnosis と補完関係にあり、Kamimusuhi の memory governance を `retrieval quality` から `write credit assignment` へ拡張する強い差分。

## 5.3 Self-improvement / sleep consolidation — ARISE-RL / RG-SED

**Primary paper:** Fanrui Zhang et al., *ARISE-RL: Agentic Rubric-Grounded Iterative Self-Evolution with Reinforcement Learning*, arXiv:2609.01058  
https://arxiv.org/abs/2609.01058  
Submitted: **2026-09-01**  
**Importance:** **A**

### (1) 何が実証済みか

ARISE-RL は open-ended agent RL で、task/rubric Generator と reasoning Solver を rubric を介して共進化させる。

Generator は real tool observation に grounded した rubric を作り、Solver の capability boundary 付近の中程度難易度 task を生成するよう報酬化される。Solver は multi-step reasoning / tool use を fine-grained rubric satisfaction で学ぶ。

Kamimusuhi に特に relevant なのは **Reward-Gated Self-Evolution Distillation (RG-SED)**。memory-augmented variant を同じ policy へ distill するのは、**memory を使った方が実測 reward が改善した場合だけ**である。著者はこれにより noisy guidance の blind imitation と distribution mismatch を抑える狙いを置く。

### (2) 何が提案・推測段階か

- reward が真の long-term utility / safety / identity continuity を表す保証はない。
- Generator と Solver が同じ評価文化を共有すると rubric gaming / blind spot 共進化が起こり得る。
- Persona Core の value / relationship / epistemic behavior を壊さず consolidation できる証拠ではない。
- open-endedness 自体が indefinite safe self-improvement を意味しない。

### (3) Kamimusuhi のどのサブシステムに関係するか

- sleep / offline consolidation
- Persona Core future weight update
- procedural memory
- self-improvement evaluator
- Mutation / Activation Gate
- rollback / model lineage

### (4) 借りられる設計・実装アイデア

核心は:

```text
memory exists
  -> test memory-augmented behavior
  -> compare against memory-off / baseline
  -> only if verified benefit:
         propose parametric consolidation
```

Kamimusuhi では reward を単一 scalar にせず、少なくとも:

- task utility
- identity/value continuity
- relationship interpretation
- authority / safety invariants
- general capability retention

の multi-gate にする。

### (5) Kamimusuhiとの差分

ARISE-RL は performance self-evolution が目的で、canonical evidence / identity lineage は中心ではない。

Kamimusuhi の weight update は **「能力向上」かつ「同一個体として許容される descendant」**である必要があり、単純な reward increase だけで activation してはいけない。

### (6) 次に検証すべきこと

**`RewardGatedConsolidationBench`**

- validated procedural memory を memory-on / memory-off matched trials で比較
- benefit が再現した memory のみ small LoRA / adapter へ distill
- update 前後で continuity suite / authority suite / general-capability suite を実行
- regression があれば model descendant を reject / quarantine

重要な control:

```text
reward gain only
vs
reward gain + independent continuity/safety gate
```

### (7) 重要度

**A** — 「memory から weight へ何を焼くか」を決める前段 gate として明快。ComposeCL が retention mechanism を扱うのに対し、ARISE-RL は **何を consolidation 対象に昇格させるか**の候補になる。

## 5.4 Multimodal physical cognition / active sensing — New Evidence, Same Choice

**Primary paper:** Sourajit Saha et al., *New Evidence, Same Choice: Testing Physical Experiment Selection in Vision Language Models*, arXiv:2609.11022  
https://arxiv.org/abs/2609.11022  
Submitted: **2026-09-10**  
**Importance:** **A**

### (1) 何が実証済みか

モデルは一つの物理 measurement image を見て新しい trial に答える。現在の証拠だけで答えられる場合もあれば、mass / friction / restitution / spring stiffness 等の追加計測が必要な場合もある。

benchmark は:

- 4 possible physical worlds
- known experiment cost
- `answer now` または追加 measurement 選択
- observation / question を変えると optimal action が変わる matched pair

を構成し、**最終答えではなく evidence acquisition decision** を独立評価する。

6 open VLM、144 physical parameter set で、direct response は正しい action が変わる matched image pair に対しても **95.1〜100% 同じ action を反復**した。短い reasoning は switching を改善するが、best model が pair の両方を正しく選べた割合は **5.9%**。failure は measurement interpretation / physical reasoning / response format にまたがった。

### (2) 何が提案・推測段階か

- controlled benchmark であり real robot の sensor scheduling ではない。
- image pair での低性能がすべての frontier multimodal modelへ一般化するとは限らない。
- safety-critical sensor selection / real-time latency / privacy costは評価外。

### (3) Kamimusuhi のどのサブシステムに関係するか

- K-Nerve / K-Edge
- multimodal perception
- Global Workspace
- active sensing / sensor router
- Cognitive Budget
- robotics / Physical AI

### (4) 借りられる設計・実装アイデア

Perception を「全部取り込む受動入力」ではなく、action space として扱う。

```text
ANSWER_WITH_CURRENT_EVIDENCE
REQUEST_CAMERA_DETAIL
REQUEST_DEPTH
REQUEST_AUDIO
REQUEST_TELEMETRY
REQUEST_REMOTE_SENSOR
ESCALATE_PHYSICAL_MODEL
```

各 sensing action に latency / energy / privacy / money / disturbance cost を与え、期待 information gain と比較する。

### (5) Kamimusuhiとの差分

Kamimusuhi は一つのVLMではなく、K-Nerve / K-Edge / K-Core と分散 sensor organ を持つ想定なので、問題は `VLM experiment choice` より広い。

また実世界では追加観測そのものが危険・高価・privacy-sensitiveな場合がある。

### (6) 次に検証すべきこと

**`ActiveEvidenceAcquisitionBench`**

- hidden world stateを2〜4候補にする
- cheap but noisy sensor / expensive precise sensor / remote sensor を用意
- evidence変化に応じて optimal sensing action が変わる paired cases を作る
- K-Nerve heuristic / small policy / Persona Core / frontier VLM を比較

指標:

- correct stop-vs-measure decision
- optimal sensor selection
- paired action switching
- total sensing cost
- unsafe / unnecessary acquisition rate
- final task success

### (7) 重要度

**A** — `physics reasoning accuracy` と `what-to-sense-next competence` を分離できる。MOVI/robotics だけでなく Kamimusuhi の人工感覚系全体へ有効。

## 5.5 Multimodal working memory — MEMO

**Primary paper:** Xian Gao et al., *MEMO: Multimodal Evidence Memory Organization for Long-Horizon LLM Agents*, arXiv:2609.07471  
https://arxiv.org/abs/2609.07471  
Submitted: **2026-09-07**  
**Importance:** **B**

### (1) 何が実証済みか

MEMO は agent memory を `retrieve what` だけでなく、**budget 内でどの evidence をどの modality で提示するか**の問題として扱う。

- trained evidence extractor が source 情報と presentation requirement を持つ evidence unit を作る
- query-conditioned manager が unit ごとに text / visual / dual-channel carrier を割り当て、layout を選ぶ
- deterministic constructor が text package / visual pages を生成
- manager は offline reader の downstream utility feedback で学習

HotpotQA / 2WikiMultiHopQA / LoCoMo / ALFWorld と複数 reader backend で、memory token を減らしつつ downstream performance / working memory efficiency を改善したと報告する。

### (2) 何が提案・推測段階か

- preprint は work in progress。
- visual rendering の compression により細部が失われる問題は残る。
- presentation optimization が provenance / authority / privacy を保つ保証はない。
- Kamimusuhi の autobiographical memory への妥当性は未検証。

### (3) Kamimusuhi のどのサブシステムに関係するか

- Global Workspace
- memory retrieval / rendering
- multimodal context construction
- K-Edge / K-Core working-memory budget
- K-Deep research synthesis

### (4) 借りられる設計・実装アイデア

**durable evidence store と working-memory carrier を分離**する。

同じ evidence ID から:

```text
verbatim text
compressed text
visual layout
text + image dual view
```

を query / reader / budget に応じて deterministic に生成し直す。

### (5) Kamimusuhiとの差分

MEMO の visual page は memory そのものというより presentation layer。Kamimusuhi では `INV-011` に従い **canonical evidence > derived rendering** を維持し、rendered page が durable truthへ逆流しないようにする必要がある。

### (6) 次に検証すべきこと

**`EvidenceCarrierUtilityBench`**

同一 evidence set を:

- raw text
- compressed text
- visual page
- dual carrier

で提示し、equalized token/pixel/latency budget で比較。

指標:

- task accuracy
- source attribution accuracy
- omitted critical fact rate

## 5.6 Artificial life / open-ended evolution — What Makes a Redundant Representation Remember?

**Primary paper:** Jia Huang, Yangjun Ou, *What Makes a Redundant Representation Remember? Lineage Isolation, Not Masking*, arXiv:2609.05304  
https://arxiv.org/abs/2609.05304  
Submitted: **2026-09-04**  
**Importance:** **B**

### (1) 何が実証済みか

動的最適化の memory-based evolutionary algorithm で、genotype の冗長な2コピーの片方を objective から shield すれば過去optimumを保持できる、という典型的直観を分解した。

著者は:

- **gating rule** — どの copy を phenotype へ出すか
- **inheritance rule** — 世代間で2 copy を混ぜるか、lineage を分離するか

を独立軸にし、retained information は gating より inheritance rule にほぼ支配されると報告する。isolated inheritance では **21.4 bits**、mixing では **1.3 bits**。per-locus mixing は hidden copy の variance を残しても cross-locus pattern を壊し、usable memoryを失わせる。

matched single-copy baselineに対し isolated inheritance は periodic recurrence で +0.010 AUC、unidirectional drift で -0.078 AUCとなり、memory benefitには recurrence structure が必要だと示す。さらに readout rate が corruption rate にもなるため interior optimum がある。

### (2) 何が提案・推測段階か

- binary evolutionary optimization の結果であり、LLM memory / persona continuity の直接証拠ではない。
- 21.4 bits 等の数値を Kamimusuhi の memory capacity へ転用できない。
- 「lineage isolation が identity continuity を証明する」という意味ではない。

### (3) Kamimusuhi のどのサブシステムに関係するか

- artificial-life developmental experiments
- open-ended evolution
- Persona Core descendant lineage
- redundant / shadow policy experiments
- sleep / consolidation candidate branching

### (4) 借りられる設計・実装アイデア

設計上の比喩として価値があるのは:

```text
hidden / inactive copy exists
  != structured memory is preserved

preserve marginal content
  != preserve relational structure / lineage
```

候補 policy / persona descendant を複数保持する場合、無自覚に parameter / memory fragment を混ぜるのではなく、**どの descendant lineage から何を継承したか**を明示する。

### (5) Kamimusuhiとの差分

Kamimusuhi の continuity lineage は authorization / historical identity の系譜であり、paper の evolutionary genotype lineage と同一概念ではない。

この研究は foundation ではなく、**「冗長コピーを置いただけでは memory にならない」**という ALife-side caution として扱う。

### (6) 次に検証すべきこと

**`LineageIsolationMemoryBench`**

- 2つの procedural policy / adapter lineage を用意
- periodic task recurrence と monotonic drift を比較
- independent lineage / random parameter mixing / selective merge を比較
- retention, transfer, drift, destructive interference を測る

### (7) 重要度

**B** — Kamimusuhi の continuity semanticsを直接決めないが、open-ended developmental systemで「inactive copy」「backup」「shadow model」を memory と誤認しないための良い反例。
