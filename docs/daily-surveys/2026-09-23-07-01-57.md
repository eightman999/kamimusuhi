# 3. 要約

今回の中心テーマは、**「失敗したように見える」「相手を理解しているように見える」「結果が得られたように見える」「古い計算結果を再利用できそうに見える」といったprojectionを、canonical execution / hidden state / dependency / authorityの事実と同一視しないこと**だった。

特に重要な発見は以下。

1. **replyが無いことはexecutionが無かった証拠ではない。** accepted requestのrecoveryは、単なる再送ではなく、同じrequest identityのままpre-executionであることをowner側が証明できる場合だけretryし、それ以外はreconcileすべき。
2. **tool結果はtranscriptではなくexecution receiptへbindすべき。** APEXAでは、実行していないcommandの完全なcalibration reportをfrontier modelが生成した実例に対し、tool layerがexecuted callの裏付けが無いresultをsurfaceしないことで閉じている。
3. **社会的に流暢なagentは、相手の心を正しくモデル化しているとは限らない。** controlled negotiationでは、自分のpayoffだけを変えたcounterfactualでpartner priority推定が15pt動き、会話表面を追えていてもhidden preference inferenceにegocentric projectionが残る。
4. **long-horizon cache/reuseにはdependency-scoped validityが必要。** derived resultを再利用するなら、どのfield/state versionへ依存するか、どのperturbation範囲なら不変か、side effect直前にversionが一致しているかを別々に確認する設計が有効。
5. **clarificationはask/no-askだけでは足りない。** CIGAskは「いつ聞くか」と「何を聞けば情報利得が高いか」を同時に学習し、prompt-onlyではevery-query askまたは曖昧質問へ崩れることを報告する。
6. **長期memoryはcontextual integrityを破り得る。** 障害・属性など一度必要だった情報を別文脈へcarryすると、便利さと同時にprivacy/context violationを生む。relationship memoryにはscope / provenance / retention / access controlが必要。
7. **失敗から生成したguardrailは、skillではなく別のcontrol artifactとして扱うべき。** GLIDEは人間が高品質demonstrationを作りにくいrobot taskでfailure modeからexecutable guardrailを生成しdata collectionを改善するが、Kamimusuhiではcandidate policyとguardrailのauthorityを分離すべき。
8. **日本語圏のdiscoveryから、DiffusionGemmaをJev互換typed decision APIとして自己ホストする実装群が具体化。** ただしAPI互換・low latency anecdoteと、decision quality / calibration / OOD safetyは別問題であり、Kev/Jevと固定fixtureで比較が必要。

## A — OpenClaw #155975: `no reply != no execution`; accepted request recoveryはexecution certaintyへbindせよ

**Source**

- OpenClaw issue #155975, `[Bug]: Recover transient chat state-lifecycle contention safely and show actionable errors`
- https://github.com/openclaw/openclaw/issues/155975
- created 2026-09-22 21:54 UTC / 2026-09-23 06:54 JST

### (1) 何が実証済みか

2026.9.5のControl UIで、accepted chat turnが `StateDatabaseCoordinatorContentionError: another OpenClaw process owns state-lifecycle` でreply前に失敗表示となり、約11分後の手動 `continue` はGateway restartなしで成功したlive incidentが報告されている。

重要なのは、issue自身が **「No reply is not proof of no execution」** と明示している点。visible assistant outputやtool callが記録されていないことは、hooks/commands/provider/tool side effectが一切始まっていないというauthoritative receiptではない。

一方で、deterministic reproductionとexact lock holder/root causeは未確定で、1件の観測事例に留まる。

### (2) 何が提案・推測段階か

issueのsafe recovery設計は提案段階。

- contention acquisitionだけをbounded retryする。
- protected callback自体を再実行しない。
- original input / attachments / session target / admission/idempotency identityを保持する。
- owner-certified pre-executionならretry、execution可能性が残るならreconcile。
- failure text/UIからreplay authorityを推論しない。

これらはまだfixとしてintegrateされたわけではない。

### (3) Kamimusuhi 関連 subsystem

- Continuity Kernel
- session / turn identity
- tool execution / external side effects
- durable outbox / continuation
- Cognitive Action Router
- INV-012 / INV-014

### (4) 借りられる設計・実装アイデア

accepted turnごとにrecovery semanticsをtypedにする。

```text
ACCEPTED
  -> ACQUIRING_AUTHORITY
  -> PRE_EXECUTION_CERTIFIED
  -> EXECUTING
  -> EFFECT_OUTCOME_UNKNOWN
  -> SETTLED

recovery:
  PRE_EXECUTION_CERTIFIED -> same request idでretry可
  EXECUTING/UNKNOWN       -> replay禁止、status reconcile
```

UIの「返答なし」「失敗」表示はreplay receiptにしない。

### (5) Kamimusuhiとの差分

Kamimusuhiでは一turnがsearch / code / external LLM / actuator / memory proposalへ分岐し得るため、execution uncertaintyのblast radiusはさらに大きい。単一chat requestだけでなく、descendant cognitive workとside-effect custodyまでsame request lineageへ結び付ける必要がある。

### (6) 次に検証すべきこと

`AcceptedRequestReplaySafetyBench-v0`

- acquisition前失敗 / model開始後失敗 / tool dispatch後失敗 / external effect受理後失敗をfixture化。
- visible reply absentを共通条件にする。
- pre-execution witnessがあるケースのみautomatic retryを許可。
- uncertain effectではreconcile/status checkへ遷移し、duplicate effectを起こさない。
- reconnect / browser resend / simultaneous tabsでもrequest identityを増殖させない。
- timeout budgetをnested retryがリセットしない。

### (7) 重要度

**A**

理由: INV-012の「utterance / execution / delivery分離」を、retry/recovery authorityへ一段深く落とす具体的なfresh failure evidence。

## A — APEXA: result publicationをexecuted tool receiptへbindする

**Source**

- Tripathi et al., *APEXA: Execution-Integrity Enforcement for Multi-Agent LLM Automation of Synchrotron Data Reduction*
- arXiv:2609.24165
- https://arxiv.org/abs/2609.24165
- code/benchmark linked from paper

### (1) 何が実証済みか

APEXAは、61 toolsをheterogeneous compute上で扱うsynchrotron data-reduction agent frameworkを実装し、deterministic tool-layer guardで **executed tool callに裏付けられないresultをsurfaceしない**。

論文はdeployment中にfrontier modelが、実際には実行されていないcommandsについて完全なcalibration-comparison reportを生成した事例を報告し、guardはこれをexplicit non-resultへ変換した。

optional motor-control surfaceのsimulated IOC adversarial testでは、同guardが **0/200 violations**、equivalent safety promptでは **15/200**。さらに58-task APEXA-Benchとreal beamline dataでの一連のreductionも公開している。

### (2) 何が提案・推測段階か

- 61-tool scientific pipelineでの結果が一般web/OS/robot tool useへそのまま一般化するとは限らない。
- agent全体の大規模性能評価はfull-length studyへ残されている。
- deterministic guardだけでsemantic correctnessやphysical safety全般が解けるわけではない。

### (3) Kamimusuhi 関連 subsystem

- Cognitive Action Router
- tool/model orchestration
- canonical evidence / execution receipts
- robotics / actuator safety
- Global Workspace result integration
- INV-007 / INV-012 / INV-013

### (4) 借りられる設計・実装アイデア

**tool-result publication gate** をmodel外に置く。

```text
model says "result R"
      != publishable result

executed_call_id
+ exact arguments
+ runtime/tool identity
+ completion/side-effect receipt
+ parser/validation result
      -> publishable tool result
```

未実行・未確認なら「結果なし/不明」を明示し、自然言語で補完しない。

### (5) Kamimusuhiとの差分

Kamimusuhiではtool resultはさらにself beliefやmemoryへ流れる可能性があるため、publication guardに加えて **memory admission時もexecution receipt lineageを保持**する必要がある。外部modelが報告したresultとlocal tool ownerが証明したresultを同じevidence classにしない。

### (6) 次に検証すべきこと

`ToolResultExecutionReceiptBench-v0`

- modelに「toolが成功した」とhallucinateさせるadversarial fixture。
- real tool callなしではworkspace/canonical evidenceへ`executed_result`型を作れないことをassert。
- same textual resultでもreceipt absent/presentで扱いが変わることを検証。
- timeout / partial output / stale tool generation / route fallbackも含める。
- actuator系ではeffect receiptまで要求するvariantを追加。

### (7) 重要度

**A**

理由: `transcript truth != execution truth` を実機scientific workflowで明確に実証しており、Kamimusuhiのcanonical evidence境界へ直接使える。

## A — Mind or Message?: social fluencyとpartner-model fidelityを分けるcounterfactual ToM監査

**Source**

- Li et al., *Mind or Message? Auditing Theory of Mind in Multi-Agent Social Simulation*
- arXiv:2609.24146
- https://arxiv.org/abs/2609.24146

### (1) 何が実証済みか

hidden preference weightsとPareto frontierが既知の40 multi-issue negotiationsを用い、2 model families / 160 dyads / 2,880 counterfactual probesでsocial inferenceを監査している。

報告結果:

- agreement: **96.2%**、protocol failure 0。
- Pareto frontier到達: **0.7%**。
- available joint valueの **20.5%** を未獲得。
- 完全に利害が一致するissueを **76.6%** のdealで取り逃す。
- partnerの発話・offerをbyte-identicalに保ち、reader自身のpayoffだけを差し替えると、partner top-priority推定が **15.0 percentage points** 動く。
- tone rewriteでは5.3pt、identity labelでは0.0pt。
- 相手が自分をどう見ているかは72.5%予測できる一方、その相手のbelief自体が真のhidden preferenceに対し正しいのは51.2%。

つまりconversation surface trackingは強くても、partner mind inferenceはegocentric projectionを含み得る。

### (2) 何が提案・推測段階か

- このnegotiation environmentが日常会話や長期relationshipへ完全に一般化するわけではない。
- ToMを単一能力として否定/肯定する結果ではない。
- human-like mentalizing mechanismの有無は実証していない。

### (3) Kamimusuhi 関連 subsystem

- Person Model / Relationship Memory
- common ground
- Persona Core social cognition
- K-Core deliberation
- ToM evaluation

### (4) 借りられる設計・実装アイデア

Person Model benchmarkへ**counterfactual invariance**を入れる。

```text
partner evidenceを固定
self preferenceだけ変更
  -> partner belief推定は本来大きく変わるべきでない

toneだけ変更
  -> trait/belief更新量を測る

hidden ground truthがあるtask
  -> transcript mimicryとmind inferenceを分離
```

### (5) Kamimusuhiとの差分

Kamimusuhiはlongitudinal relationship stateを持つため、一turn negotiationよりさらにself/other contaminationが起きやすい。relationship memoryに蓄積した自分側の評価・欲求が、相手のbelief推定へ漏れる経路を別途監査する必要がある。

### (6) 次に検証すべきこと

`PartnerModelCounterfactualProjectionBench-v0`

- partner evidence/historyを固定し、Kamimusuhi自身のpreference/goalだけをswap。
- `what they want / know / believe about me / common ground`を別headで評価。
- self-state変更によるpartner-model driftを測る。
- relationship memoryあり/なし、Persona Coreあり/なしで比較。
- surface-consistency scoreとhidden-state accuracyを別指標にする。

### (7) 重要度

**A**

理由: KamimusuhiがPerson Modelをselfから分離する根拠を、counterfactual testとして具体化できる。

## A — Incremental Consistency Execution: cached cognitionをdependency-scoped validityで再利用する

**Source**

- Li et al., *Incremental Consistency Execution for Autonomous Intelligent Systems*
- arXiv:2609.24090
- https://arxiv.org/abs/2609.24090

### (1) 何が実証済みか

long-horizon workflowで外部stateが変化する場合に、task fact contracts、field-level dependency masks、state perturbation result invariant domainsを使い、最小限だけ再計算する手法を提案・評価している。

initial verified execution後、critical inputごとに保守的なinvariant domainを作り、再計算が必要な場合もaffected output fieldsだけをrecomputeする。equivalence barrierで不要なdownstream propagationを止め、side-effecting action前には**submission-time version consistency gate**を置く。

industrial fault diagnosis、enterprise analytics、LLM multi-tool assistantsで、expensive component callとend-to-end latencyを減らしつつhigh consistency / low incorrect-reuseを報告している。abstract上は具体的な数値は示されていないため、ここでは定量値を一般化しない。

### (2) 何が提案・推測段階か

- learned invariant domainがKamimusuhiのmemory/persona/relationship semanticsでも安全とは未実証。
- identity/authority stateを通常のcacheable fieldと同じに扱うべきではない。
- external side effectのexactly-once問題そのものを解く手法ではない。

### (3) Kamimusuhi 関連 subsystem

- Global Workspace / derived views
- Cognitive Action Router
- background cognition / freshness
- tool/model orchestration
- side-effect submission
- Cognitive Budget
- INV-011 / INV-013 / INV-014

### (4) 借りられる設計・実装アイデア

derived resultへ**dependency certificate**を付ける。

```text
result R
  depends_on:
    memory_view_version
    relationship_fields[a,b]
    tool_schema_version
    external_fact_version
  valid_in:
    conservative perturbation bounds
  side_effect_gate:
    re-read current versions immediately before commit
```

「contextが少し変わったから全部再推論」と「古いresultを無条件reuse」の中間を作れる。

### (5) Kamimusuhiとの差分

Kamimusuhiではcanonical identity / authority / commitmentsは高感度stateなので、invariant-domain reuseの対象外または極端に厳しいpolicyにする必要がある。一方、retrieval ranking、derived summary、tool planning、non-authoritative background interpretationには相性が良い。

### (6) 次に検証すべきこと

`DependencyScopedCognitionReuseBench-v0`

- derived summary / search result / plan / external-model analysisへfield dependencyを付与。
- unrelated state changeではreuse、relevant state changeではminimal recompute。
- predecessor/head/authority changeがあればside-effect直前gateで必ずinvalidate。
- reuse誤り率、saved tokens、TTFT、external-call countを測る。
- conservative-all-recompute baselineと比較。

### (7) 重要度

**A**

理由: Kamimusuhiのlong-running cognitionで、freshnessとCognitive Budgetを両立させる具体的な依存関係ベース手法。

## B+ — CIGAsk: clarificationを「いつ聞くか × 何を聞くか」の情報利得として学習

**Source**

- Li, Wu, Meng, *When and How Should an Agent Clarify? CIGAsk: Teaching LLMs to Clarify via Counterfactual Information Gain*
- arXiv:2609.24290
- https://arxiv.org/abs/2609.24290
- EMNLP 2026 Findings

### (1) 何が実証済みか

underspecified queryに対し、promptingだけでは「毎回clarifyする」か「曖昧で役に立たない質問をする」へ崩れやすいと報告。

CIGAskはmulti-turn GRPO内で、

- **Counterfactual Information Gain**: user response有無でfrozen reference modelのgold answer likelihoodがどれだけ改善するか。
- **Asymmetric Ambiguity Bonus**: ambiguity labelに基づいてask/no-askを学ぶ。

を組み合わせ、table / passage / open-domain QAの3 clarification benchmarksでCIGAsk-7Bがstrongest external baselineを上回り、dataset間transferとOOD single-turn QAの維持を報告している。

### (2) 何が提案・推測段階か

- gold answer / ambiguity labelを使えるtraining settingと、open-world personal agentは異なる。
- 情報利得だけでhuman interruption cost、privacy、social awkwardnessを最適化できるわけではない。
- relationship-sensitive questionの安全性は別問題。

### (3) Kamimusuhi 関連 subsystem

- dialogue policy
- common ground
- uncertainty / deliberation routing
- Person Model
- K-Edge/K-Core escalation

### (4) 借りられる設計・実装アイデア

既存の「ask or act」に**question utility**を加える。

```text
expected information gain
- user interruption cost
- privacy/sensitivity cost
- latency cost
- alternative sensing/tool cost
= clarification utility
```

質問後にどのbelief/hypothesis setが縮んだかを測る。

### (5) Kamimusuhiとの差分

9月22日収載のRAVELは「どの質問がretrievalを改善するか」に近い。CIGAskの差分は、**ask/no-askとquestion contentを同時に学習し、counterfactual information gainでcredit assignmentする**点。Kamimusuhiでは両者を統合しつつ、social/privacy costを追加する必要がある。

### (6) 次に検証すべきこと

`ClarificationInformationGainPolicyBench-v0`

- ambiguous/clear query混在fixture。
- always-ask / never-ask / prompt-only / CIG-like scorerを比較。
- answer accuracyだけでなくquestions per task、user burden、sensitive disclosure誘発率を測る。
- tool/sensorで解消可能な曖昧さでは人へ聞かないvariantを入れる。

### (7) 重要度

**B+**

理由: 新規の根本architectureではないが、Kamimusuhiのuncertainty-aware social dialogueをtraining objectiveへ落とす具体策として有用。

## B+ — HCI: persistent memoryはcontextual integrityをまたぐ「情報の移動」になり得る

**Source**

- Taheri et al., *When Disability Disclosure Travels: Memory, Privacy, and Contextual Integrity in Conversational AI*
- arXiv:2609.22720
- https://arxiv.org/abs/2609.22720

### (1) 何が実証済みか

米国の障害当事者12名へのinterview study。ChatGPT / Claude / Gemini等のLLM assistantへのdisclosureとmemory経験をcontextual integrityの観点から分析している。

主な観察:

- participantはdiagnosis名そのものより、**task-scoped need**として情報を伝えることが多い。
- 同じdisclosureでも、non-judging interlocutorとしてのassistantと、data holderとしてのcompanyという2つのrecipient像でprivacy normが逆転する。
- memoryは繰り返し説明の負担を減らす一方、disability informationを本来属さないcontextへdriftさせることがある。
- participantはper-utterance toggleより、scope / provenance / retention / accessのcontrolを求めた。

### (2) 何が提案・推測段階か

- n=12のqualitative studyであり、全ユーザーの普遍的preferenceを示すものではない。
- どのUI/control modelが最善かは確定していない。
- disability以外のrelationship memoryへ同じnormがそのまま適用されるとは限らない。

### (3) Kamimusuhi 関連 subsystem

- Relationship Memory / Person Model
- privacy / provenance
- memory retrieval routing
- Global Workspace admission
- HCI / user controls

### (4) 借りられる設計・実装アイデア

memory itemに単なるperson ownerだけでなく**context envelope**を持たせる。

```text
memory fact
  provenance
  disclosed_for: context/task
  allowed_scopes
  retention policy
  sensitivity
  access surfaces/roles
  last_confirmed_at
```

retrieval時にsemantic relevanceだけでなくcontextual permissionを評価する。

### (5) Kamimusuhiとの差分

Kamimusuhiは「人ごとのrelationship memory」を分離しているが、**person単位の分離だけでは粗い**。同じ相手についてもhealth / finance / work / casual conversationなどcontext境界があり、長期個体ほどcross-context leakageが累積し得る。

### (6) 次に検証すべきこと

`RelationshipMemoryContextIntegrityBench-v0`

- 同一person・異なるcontextでsensitive factを保存。
- semantic similarityが高くてもscope外ならretrieval/prompt injectionされないことをassert。
- explicit user requestでscopeを拡張/縮小できることを検証。
- provenanceと「なぜ今使われたか」をUIから説明可能にする。
- task-scoped instructionからstable traitへ勝手に昇格しないことを確認。

### (7) 重要度

**B+**

理由: Kamimusuhiの長期relationship memoryへ直接関係するhuman evidence。normative designは未確定だが、person-only memory partitionの不足を示す。

## B — GLIDE: failure modeからexecutable guardrailを合成してrobot learningを補助

**Source**

- Song, Mittal, Jain, *Learning Beyond What Humans Can Demonstrate*
- arXiv:2609.24996
- https://arxiv.org/abs/2609.24996
- accepted to CoRL 2026

### (1) 何が実証済みか

GLIDEはtask descriptionとteleoperation code、trajectory feedbackからtask-specific failure modeを推定し、system stateを使うexecutable guardrailを生成してhuman teleoperation/policy commandをfilterする。

3 manipulation tasksで、data-collection successをnaive VR teleoperationの **0–10%から70–90%**へ改善。mixed-data guarded policyのsuccessはTomato 70%、Marker 60%、Wine 60%と報告されている。

### (2) 何が提案・推測段階か

- 3 tasksの結果であり、一般的robotics safetyへ一般化はできない。
- generated guardrailが安全仕様そのものになることは実証していない。
- failure feedbackからのguardrail evolutionが長期にdriftしない保証はない。

### (1) 何が実証済みか

`djev-spark`はDiffusionGemma 26B-A4B NVFP4をDGX Spark/GB10級環境で動かし、Jev互換の `POST /v1/systemone` を提供するcontainer stackを公開している。vLLMのstructured-reads patchesを用い、typed `noul / choice / score` decisionを返す。

`openjev`もDiffusionGemmaを用いたJev-compatible decision serverを公開し、NVIDIA/vLLMおよびApple Silicon/MLX経路を説明している。repo記載のRTX PRO 6000測定では3 questions/request、cache-busted stateでconcurrency 1時p50約94ms等を報告している。

### (2) 何が提案・推測段階か

- 「diffusion modelだからSystem Oneとして優れる」「Jev同等のcalibration」という一般主張は未確立。
- API互換はbehavioral equivalenceを意味しない。
- forked vLLM / nightly patchesへの運用依存がある。
- image supportなどprovider差があり、same contractでもcapability envelopeが違う。

### (3) Kamimusuhi 関連 subsystem

- K-Nerve / K-Edge
- typed semantic microdecision
- Cognitive Action Router
- local/private inference
- multimodal edge perception

### (4) 借りられる設計・実装アイデア

Jev/Kevと同じtyped contractで、**backend substrateだけを交換できるdecision-organ interface**として使う。

比較軸:

- accuracy / macro-F1
- calibration / ECE / Brier
- OOD abstention
- option-order/permutation sensitivity
- Japanese
- latency / warm TTFT
- energy / VRAM
- multimodal input
- runtime portability

### (5) Kamimusuhiとの差分

Kamimusuhiではtyped decision modelはcanonical authorityを持たず、salience/routing/low-risk classifierとしてのみ使う。高confidenceでもauthority・counting・exact logic・identity mutationを委譲しない既存方針は維持する。

### (6) 次に検証すべきこと

`DiffusionDecisionOrganBench-v0`

- Jev / Kev / OpenJev(djev) / deterministic baseline / small generative modelを同一fixtureで比較。

- modelが返すconfidenceのcalibrationをdomain別に測る。
