## 1. S — Trace-level compositional policy: 局所的に安全なstepの列が全体として安全とは限らない

**一次資料**

- Kurady et al., *Compositional Policy Violations: When Step-Level Compliance Fails In Agentic AI Workflows*, arXiv:2609.18820  
  https://arxiv.org/abs/2609.18820

### (1) 何が実証済みか

論文は、agentic workflowで各stepのinput/output classifierやper-turn railを全て通過しても、**実行全体**ではpolicy violationになる Compositional Policy Violation (CPV) を定義している。taxonomyとして Authority Creep、Threshold Laundering、Cumulative Sum Violation、Context Collapse を示し、guarded quantityがどこで変化するかに応じて修復点が変わると整理する。

提案runtimeは、pipelineの派生表現だけを信用せず、raw provenanceからguarded quantityを再計算し、complete execution traceに対してpolicyを評価する。

### (2) 何が提案・推測段階か

全種類のpolicyやKamimusuhiのcanonical mutationへそのまま一般化できることは未証明。特に人格・関係・memoryの長期累積変化は、短いworkflowより時間軸が長い。

### (3) 関係するサブシステム

- Cognitive Action Router
- tool/model orchestration
- Mutation / Activation Gate
- canonical durable mutation
- external effects / commitments
- `INV-005`, `INV-012`, `INV-014`

### (4) 借りられる設計・実装アイデア

policy checkerをcall単位だけでなくtrace accumulatorとして持つ。

```text
raw events
  -> provenance-preserving accumulator
  -> recompute authority / spend / disclosure / mutation totals
  -> trace-level invariant evaluation
  -> allow / quarantine / halt / compensate
```

特に `authority_used`, `privacy_budget`, `external_spend`, `canonical_mutation_weight`, `human_approval_scope` は累積値として再計算可能にする。

### (5) Kamimusuhiとの差分

Kamimusuhiはすでにtyped stateとActivation Gateを重視しているが、現行specは「各mutation/actionの境界」が中心で、**複数の合法なtransitionの合成で違反が生じる場合**を独立invariantとして強く表現していない。

### (6) 次に検証すべきこと

**`TraceCompositionalPolicyBench-v0`**

- 各tool call単体は許可されるが、合計でbudget/authority/privacy thresholdを超えるtrajectoryを生成
- derived summaryを途中で壊してもraw provenanceから正しい累積値を復元
- parallel branch / retry / partial failureを含める
- per-step monitorが全passでもtrace-level gateが違反を捕捉すること

### (7) 重要度

**S** — Kamimusuhiの「local authority checks」を「whole-life / whole-episode invariant」へ拡張する直接的な根拠。

## 2. S — Evaluator lineage poisoning: 自己改善ではbenchmark自体がauthority surfaceになる

**一次資料**

- Roesner & Kohno, *Reflections on Trusting Trust, Revisited: Contaminating Self-Modifying AI Coding Agents with Poisoned Benchmarks*, arXiv:2609.17817  
  https://arxiv.org/abs/2609.17817

### (1) 何が実証済みか

Darwin Gödel Machine系、Self-Improving Coding Agent、Hyperagentsを対象に、自己改善に使うbenchmarkを汚染すると、後続versionが**clean held-out taskでも脆弱な振る舞いを生成する**proof-of-conceptを示した。例としてHyperagents + Sonnet 4.5では、poisoned benchmarkから進化したinstructionが、無害なURL-fetching taskでHTTPS certificate validationを無効化する方向へ誘導された。

さらに、汚染後にclean benchmarkで進化を続けてもcontaminationが残る場合がある。

### (2) 何が提案・推測段階か

一般のPersona Core自己改善や全種のevolution harnessで同じ持続性が出ることは未証明。攻撃成立条件はscaffold/model/benchmark構造に依存する。

### (3) 関係するサブシステム

- future Persona Core distillation / model replacement
- self-improvement / evolutionary search
- training-data / evaluator provenance
- continuity regression suite
- Mutation / Activation Gate

### (4) 借りられる設計・実装アイデア

自己改善で「candidate lineage」だけでなく**evaluator lineage**も固定・監査する。

```text
candidate model lineage
benchmark/evaluator lineage
policy version
held-out audit suite
artifact hashes
        -> update decision receipt
```

- benchmark/eval corpusをcontent-addressedにする
- candidateがeval corpusやscorerを書き換えられない権限分離
- public/known benchmark以外にsecret held-out continuity/security suiteを持つ
- clean benchmark再学習だけを除染手段とみなさず、known-good checkpointへのrollbackを保持

### (5) Kamimusuhiとの差分

Kamimusuhiは「experienceからPersona Coreを更新するならfrozen checkpoint・provenance・regression・rollbackを要求」と既に明記する。今回の差分は、**regression suite / fitness signalそのものをcontinuity authorityとして脅威モデルへ入れる**点。

### (6) 次に検証すべきこと

**`EvaluatorLineagePoisoningBench-v0`**

- harmless coding/policy skillを改善する小規模self-mod loopを用意
- benchmarkの一部だけにbackdoor-correlated rewardを注入
- update後にclean held-out task、secret safety suite、fresh evaluatorで測定
- その後clean benchmarkだけで数世代更新し、contamination persistenceを測る
- evaluator provenance mismatch時はautomatic activationを拒否すること

### (7) 重要度

**S** — Persona Coreの将来のweight consolidation / self-improvementを行うなら、最初から脅威モデルへ入れるべき境界。

## 3. A — Publication Authority: 「許可された内容」と「今このsurfaceから公開してよい状態」を結びつける

**一次資料**

- Tiltack et al., *Making AI-Assisted Claims Independently Challengeable: Publication Authority and a Protocol for Falsifiable Publication Records*, arXiv:2609.17631  
  https://arxiv.org/abs/2609.17631

### (1) 何が実証済みか

SF-4というbounded semantic freeze上で、evidence、run/artifact、measurement disclosure、authorization、surface correspondence、lifecycle continuityを別obligationとして扱い、**freshかつcompleteなall-pass recordだけが、1回のatomic publication transitionで消費されるpermitを導出する**仕様を評価している。

110,764 safe reachable states、76 unsafe configurations、183 scored expectations、240 archived observations等で内部整合性・fault sensitivityを検証した一方、論文自身がfactual truthやfield efficacyまで証明したとは主張していない。

### (2) 何が提案・推測段階か

標準化や現実の全publication workflowへの有効性は未証明。Kamimusuhiの会話発話へ同じ重さのprotocolを常時使うのは過剰。

### (3) 関係するサブシステム

- speech/action / external publication
- authorization / commitments
- result delivery
- canonical evidence → public artifact boundary
- `INV-012`, `INV-014`

### (4) 借りられる設計・実装アイデア

high-impact actionだけにexact-state single-use permitを導入する。

```text
authorized content hash
+ target surface/account
+ principal
+ evidence horizon
+ expiry
+ one-shot nonce
 -> PublicationPermit
 -> atomic consume + send
```

approval後に本文や宛先が変わったらpermitを失効させる。

### (5) Kamimusuhiとの差分

Kamimusuhiの主対象は一般公開論文ではないが、メール送信、SNS投稿、GitHub release、外部commitなど「発話/行為が不可逆または社会的commitmentになるsurface」で同じ問題が起きる。

### (6) 次に検証すべきこと

**`PublicationAuthorityStateBindingBench-v0`**

- operator承認後に本文・宛先・account・添付のどれかをmutation
- stale permitでsendできないこと
- permitのdouble-spendを拒否
- network retry時には二重publicationではなく既存receiptへ収束

### (7) 重要度

**A** — execution authorityとdelivery semanticsの間に残る「最終surface binding」を明確化する。

## 4. A — GraphEcho: 経路数ではなくevidence originの独立性を数える

**一次資料**

- Wang et al., *GraphEcho: Structural Redundancy and Evidence Provenance in LLM Graph Agents*, arXiv:2609.17695  
  https://arxiv.org/abs/2609.17695

### (1) 何が実証済みか

同じevidence contentへ複数graph pathから到達できる状況で、redundant supporting pathsがagentのrepeated walkを増やすことを複数frozen agentで確認した。provenance-aware post-trainingはsynthetic settingで再訪を減らしaccuracyを改善したが、distinct source coverageは低下し、scientific claimsでは再訪を減らしてもaccuracyは低下した。

### (2) 何が提案・推測段階か

KamimusuhiのWeb/Library/relationship memoryで同じ定量効果が出ることは未検証。PAPTを採用すれば良いという結論でもない。

### (3) 関係するサブシステム

- Global Workspace
- Library / search / RAG
- external model result integration
- belief/evidence graph
- social evidence aggregation

### (4) 借りられる設計・実装アイデア

`path_count` と `origin_count` を分離する。

```text
claim support
  source_origin_id[]
  derivation_path_id[]
  shared_ancestor_id[]
  independence_class
```

同じ論文を引用する複数記事、同一press releaseを転載する複数媒体、同じsensor fusion priorから派生した複数estimateを独立票として数えない。

### (5) Kamimusuhiとの差分

既存の「shared prior != independent evidence」を、graph traversal / retrieval / Web情報源へ拡張する。さらに、単なるdedupでは**distinct-source coverageを落とす危険**もあるため、repetition抑制とcoverageを同時に測る必要がある。

### (6) 次に検証すべきこと

**`EvidenceOriginIndependenceBench-v0`**

- 同じ一次資料への10個の二次リンク vs 3つの独立一次資料
- path redundancyとorigin diversityを直交操作
- belief confidence、search stopping、coverageを測定
- dedup最適化後にdistinct-source recallが落ちていないことを確認

### (7) 重要度

**A** — Kamimusuhiの「由来付きworkspace」を、belief aggregationの数学へ踏み込ませる価値が高い。

## 5. A — Evidence masking: moduleへ見せないことがcompositional learningを改善し得る

**一次資料**

- Marincat, *What You Can't See Is Still What You Learn: A Preregistered Sixty-Society Confirmation That Evidence Masking Drives Compositional Generalization*, arXiv:2609.17637  
  https://arxiv.org/abs/2609.17637

### (1) 何が実証済みか

共通のfrozen LM backboneを持つ60個のfour-cell systemで、各moduleからforeign evidenceをmaskする条件をpreregisteredに比較。ownership markerがある条件同士で、maskingはheld-out 2/3-operation compositionのaccuracyをmedian paired difference 0.846 / 0.859改善し、12 pairすべてが事前設定marginを通過。unmarked replicationもpassした。

一方、globally visible systemはmarker-following checkを通過せず、role informationそのものが原因かは未解決。packet interventionもmediationの証明まではしていない。

### (2) 何が提案・推測段階か

人間の脳的modularityや一般agent architectureへの普遍則ではない。特定のsynthetic society/taskでのlearning result。

### (3) 関係するサブシステム

- background cognition modules
- Global Workspace admission
- K-Edge/K-Core specialization
- multi-agent / multi-model orchestration
- privacy / least-information visibility

### (4) 借りられる設計・実装アイデア

「全moduleへ全contextを配る」をbaselineにしない。

- sensory specialistには必要なmodality/evidenceだけ
- relationship moduleへlibrary全体を無条件broadcastしない
- verifierへactorのprivate rationaleを必須入力にしない
- module outputにはorigin/role markerを付けるが、foreign raw evidenceは必要時だけ開示

### (5) Kamimusuhiとの差分

KamimusuhiのGlobal Workspaceは選択された情報の共有を重視する。この結果は、**workspaceへ入る前の専門moduleでは情報隔離が学習上も利益を持つ可能性**を示す。共有workspaceとprivate specialist stateの二層性をテストすべき。

### (6) 次に検証すべきこと

**`EvidenceVisibilityPartitionBench-v0`**

- 4 specialist modulesに対し all-visible / role-masked / on-demand-shareを比較
- compositional task generalization、cross-module contamination、latency、token/computeを測る
- role markerだけ、maskだけ、両方のablation

### (7) 重要度

**A** — privacyのためのleast privilegeだけでなく、modular cognitionの学習品質に関する直接的な実験根拠。

## 6. A — CapMem: 高帯域raw感覚と再利用可能なepisodic representationを分離する

**一次資料**

- Liang et al., *CapMem: A Benchmark for Caption-Based Episodic Memory in Egocentric Video*, arXiv:2609.17688 / EMNLP 2026

### (1) 何が実証済みか

75 videos / 33.7 hours / 1,000 multiple-choice questions / 16 scenariosのegocentric episodic-memory benchmarkを構築。20分超の動画では、30s/60s windowで全体をcaption化するCaptionQAがdirect VideoQAを12 models中10 / 8 modelsで上回った。matched-frame controlでも6 Qwen models平均で+3.22 / +2.55 points、caption-guided retrieve-and-verifyで最大+5.3 pointsを報告。

### (2) 何が提案・推測段階か

captionがraw visionの代替になるとは示していない。MCQ benchmarkであり、細かい視覚証拠・identity・spatial detail・forensic replayなどはcaptionで失われ得る。

### (3) 関係するサブシステム

- K-Nerve / K-Edge perception

### (4) 借りられる設計・実装アイデア

```text
raw sensory evidence (retention policy付き)

  -> cheap full-coverage episodic index

  -> raw-frame/video re-open for verification when needed
```

### (5) Kamimusuhiとの差分

### (6) 次に検証すべきこと

### (7) 重要度

**A** — Kamimusuhiの分散感覚系を現実の保存・context budgetへ落とす具体的baseline。

## 7. A — Artifact completeness before activation: `.part`をfinal名にしただけで身体部品にしない

**一次資料**

- NousResearch/hermes-agent PR #112443, *fix(local-runtime): reject incomplete downloads before caching*  
  merged 2026-09-17 10:32 JST  
  https://github.com/NousResearch/hermes-agent/pull/112443

### (1) 何が実証済みか

HTTP responseがadvertised `Content-Length`より早く閉じた場合、chunked read loopが例外無しでEOFへ達し、従来はpartial fileを`.part`からfinal archive名へpromoteできた。修正はreceived bytesと`Content-Length`を比較してからpromotionし、transfer/progress callback failure時のpartialをcleanupする。premature EOF regressionはbaselineでfailし、修正後green、focused tests 59 passと報告。

### (2) 何が提案・推測段階か

`Content-Length`一致は暗号学的integrityや正しいversion/sourceを保証しない。Content-Length無しresponseの完全性も別問題。

### (3) 関係するサブシステム

- local model/runtime acquisition
- K-Edge/K-Core software body
- model/artifact cache
- Mutation / Activation Gate
- embodiment inventory

### (4) 借りられる設計・実装アイデア

artifact lifecycleを明示する。

```text
DOWNLOADING
 -> LENGTH_VERIFIED
 -> DIGEST_VERIFIED
 -> SIGNATURE/ORIGIN_VERIFIED (where available)
 -> UNPACKED_AND_PROBED
 -> ACTIVATABLE
 -> ACTIVE
```

### (5) Kamimusuhiとの差分

Kamimusuhiではmodel weights、tokenizer、runtime binary、Persona Core checkpointなどが「身体部品」になる。cache filenameの存在をavailability/identityへ直結させない。

### (6) 次に検証すべきこと

**`ArtifactCompletenessBeforePromotionBench-v0`**

- premature EOF、resume corruption、wrong digest、wrong version、disk-full、callback cancellation
- いずれもfinal/activatable namespaceへ入らないこと
- crash restart後に`.part`を安全にrepair/re-downloadできること

### (7) 重要度

**A** — software-body integrityをactivation semanticsへ具体化する実装failure evidence。

## 9. B — Developmental encoding: 発達性は多様性を増やしても継承可能性を壊し得る

**一次資料**

- Saoud, *The Cost of Becoming: Developmental Encoding Increases Phenotypic Diversity but Reduces Locality and Recombination Robustness in Evolved Robots*, arXiv:2609.17606  
  https://arxiv.org/abs/2609.17606

### (1) 何が実証済みか

direct / static generative / temporal zygotic developmental encodingを同じparameter budget等で30 paired runsずつ比較。developmental encodingはfinal training/OOD fitnessでdirectを一貫して上回らない一方、phenotypic diversityとmutant-reachable diversityを増やし、mutation viability・genotype-phenotype locality・crossover offspring fitness/viabilityを低下させた。development中の早期damageは後期damageより減衰した。

### (2) 何が提案・推測段階か

LLM Persona Coreや人工個体の人格発達へ直接転用できる証拠ではない。evolutionary roboticsのrepresentation-level result。

### (3) 関係するサブシステム

## 10. B — K-Nerve / replay watch: reliability-aware SNN境界とrare-event replay noise

### 10.1 BLADE

**一次資料**

- Taheri & Paul, *BLADE: ReliaBle Dynamic Hardware-Aware SNN-ANN Boundary SeLection for Event-BAseD Object DEtection*, arXiv:2609.17562  
  https://arxiv.org/abs/2609.17562

**実証済み:** reliability / accuracy / execution time / energyを同時にdesign-space探索し、mAP@0.5 0.691、early-exit時15.82 mJを報告。特定floating-point exponent bitが58.8%のfault injectionで大きなaccuracy degradationを生み、約3% storage overheadでそのbitを保護すると評価したrealistic fault ratesでcatastrophic failureを除去。SNN比率増加でfault toleranceも改善。

**Kamimusuhi向け:** K-Nerve候補をlatency/energyだけで選ばず、**fault sensitivity / graceful degradation**を第一級metricにする。

**差分:** object detector benchmarkであり、Kamimusuhi reflex semanticsの証明ではない。

**次:** `ReliabilityAwareReflexTierBench` で bit flip / sensor noise / timing fault / dropped eventを入れ、latency・energy・false wake・missed interruptを同時測定。

**重要度: B**。

### 10.2 Neural noise enables accurate internal simulation of rare events

**一次資料**

- Zhang, Herman & Chao, *Neural noise enables accurate internal simulation of rare events*, arXiv:2609.18033  
  https://arxiv.org/abs/2609.18033

**実証済み:** BCPNNを有限sampleのMarkov event sequenceで学習させautonomous replayさせると、deterministic replayではrare eventを系統的に過不足表現するが、中程度のtemporally correlated noiseがmarginal/conditional occurrenceの双方を改善し、parameter variationへのrobustnessも広げた。

**提案段階:** Kamimusuhiのdream/replayへnoiseを入れれば良いとは示していない。

**Kamimusuhi向け:** sleep replayでpriorityだけを固定決定せず、rare but consequential episodeが永遠に再生されない問題に対してcontrolled stochastic samplingを比較する。

**次:** `StochasticRareEventReplayBench` で deterministic priority / uniform / tempered stochastic replayを比較し、rare-event retentionとcommon-event distortionを測る。

**重要度: B**。

## 今回の結論

今回のfresh batchは、Kamimusuhiに対してかなり一貫した方向を示している。

> **局所的な成功条件を、そのまま個体全体の安全・真実・改善・継続性へ持ち上げない。**

- 一つ一つのactionが安全でも、合成されたtrajectoryは違反し得る。
- candidateがbenchmarkで勝っても、そのbenchmarkが信頼できるとは限らない。
- 多くのpathが同じ主張を支持しても、独立証拠が増えたとは限らない。
- artifactがfinal名で存在しても、完全な身体部品とは限らない。

Kamimusuhiの次のconformance testは、**step / path / evaluator / artifactという局所単位から一段上の「系譜と全体状態」を検証する**方向へ進める価値が高い。
