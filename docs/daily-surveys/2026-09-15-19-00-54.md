## 要約

今回の重要差分は5本に圧縮できる。

1. **同じ agent / participant でも、thread / episode が違えば cognition context は別 identity key を持つ必要がある。** Hermes Agent #111003 では group member の hidden session key に thread が含まれず、thread B が thread A の backend transcript を読んで応答する実害があった。`agent identity != episode identity != relationship-thread state` を実装レベルで示す強い事例。
2. **provider-native reasoning / message IDs は portable memory ではない。** Hermes #111181 は model switch 後の replay を、endpoint だけでなく issuing model まで bind するよう修正した。Kamimusuhi の「model は交換可能だが self は継続する」を裏返すと、**交換可能な model 固有 artifact は continuity state に混ぜない**必要がある。
3. **外部 memory capture は durability と exactly-once を分けて考える必要がある。** Hermes #111595 は session-end 一括 ingest の silent loss を per-turn capture + pending retry に変えた一方、明示的に at-least-once semantics を採用している。これは derived/search memory には合理的だが、canonical autobiographical evidence では重複排除・event identity が別途必要になる。
4. **共有 credential の refresh は単なる key-value 更新ではなく、single-use effect を含む分散 transaction である。** Hermes #111186 は read → refresh POST → persist 全体を cross-process fence で囲み、peer が既に回した token を再利用しないようにした。
5. **良い最終回答でも procedural contract を守ったとは限らない。** ContractEval は query に対して active な obligation を明示し、skip / wrong branch / ordering / invariant violation を output quality とは別に検査する。Kamimusuhi の Execution Grant / Mutation Gate / continuity protocol を、自然言語 rubric ではなく obligation graph として試験する具体案になる。

今回の設計圧縮:

```text
same agent != same episode/thread
conversation continuity != provider-native replay continuity
memory durability != exactly-once canonical history
shared credential state != concurrency-safe single-use authority
acceptable output != procedurally justified execution
observation != mutation authority
```

### A — Hermes #111595: per-turn memory capture + session-owned pending retry は durability を上げるが、at-least-once は canonical history にはそのまま使えない

**出典**: NousResearch/hermes-agent PR #111595, *fix(supermemory): capture turns via documents API so self-hosted sessions are not dropped*, merged 2026-09-15 15:25 JST  
https://github.com/NousResearch/hermes-agent/pull/111595

1. **何が実証済みか**
   - self-hosted backend では session-end の cloud-only endpoint が404となり、buffer済み conversation 全体が失われる silent-loss bug が存在した。
   - per-turn `documents.add` へ変更し、失敗した turn は owning session id を保持した pending item として次 turn / session end / session switch / shutdown で retry。
   - session switch 後も failed old turn を new session id へ re-home しない。
   - worker / shutdown flush を single-owner lock で serialize。
   - pending buffer は 50 turns / 256 KiB に bounded、persistent failure 時は drop-oldest。
   - live local endpoint で 500 → pending retention → next write retry を確認し、最終関連 suite 76/76 pass。
   - 実装は明示的に **at-least-once**: remote が受理した後 response が失われた場合、retry により重複 append し得る。
2. **何が提案・推測段階か**
   - at-least-once で生じる duplicate が downstream retrieval quality にどの程度影響するかはこのPRでは評価されていない。
   - drop-oldest が long-horizon personal memory に許容されるかは用途依存。
3. **関係する Kamimusuhi subsystem**
   - episodic capture
   - external/derived memory provider
   - canonical evidence ingest
   - session lineage / episode attribution
   - shutdown/recovery path
4. **借りられる設計・実装アイデア**
   - capture を session-end 巨大 transaction に集中させず、turn/event 単位の durable outbox にする。
   - retry item は **origin episode/event id を保持**し、current session へ付け替えない。
   - external provider queue は bounded にし、overflow/drop を observability に出す。
   - canonical sideでは `event_id` / idempotency key / content-addressed receipt を持ち、at-least-once transport から exactly-once logical history を再構成する。
5. **Kamimusuhiとの差分**
   - Hermes Supermemory は optional memory provider。Kamimusuhi の canonical evidence / autobiography は失敗時に drop-oldest してよいデータではない。
   - Kamimusuhi では external vector/search memory を **derived cache** として扱い、canonical event ledger の代替にしない方が安全。
6. **次に検証すべきこと**
   - `MemoryDeliverySemanticsBench`: response-loss、500、session switch、shutdown、duplicate retry を注入し、canonical ledger は重複なし・derived provider はat-least-onceでも再構築可能かを確認。
   - `event_id` dedupe あり/なしで retrieval duplication、autobiographical count、relationship-event aggregationの誤差を比較。
7. **重要度**: **A**

**設計圧縮**: `durable retry != exactly-once autobiographical event`

### A — Hermes #111186: shared OAuth refresh は single-use capability を含むため cross-process fence が必要

   - External Resource Router
   - capability / Execution Grant lifecycle
4. **借りられる設計・実装アイデア**
   - capability refresh/rotationを単なる JSON update ではなく **consume-once effect** としてモデル化。
   - fence取得後に state を再読込し、peer progress を adopt して不要な effect を発火しない。

5. **Kamimusuhiとの差分**
   - Kamimusuhi は複数hostを想定するため、local file lock は単一host baseline にすぎない。将来は lease/fencing token / transactional authority owner が必要になり得る。

7. **重要度**: **A**

## 今回の結論

今回の差分は派手な新architectureというより、**Kamimusuhiの「継続する一個体」を実装する時に、何を同じものとして扱ってはいけないか**を強く具体化するものだった。

特に優先して持ち帰るべき境界は次の3つ。

```text
participant / agent principal
    != active thread / episode identity

canonical cognitive continuity
    != provider/model-native replay artifact continuity

durable memory transport
    != exactly-once autobiographical truth
```

次に実装するなら、情報利得が最も高い順に

`EpisodeScopeCompositeIdentityBench → IssuerBoundRuntimeArtifactBench → MemoryDeliverySemanticsBench`

を推奨する。
