## 要約

今回の重要差分は6本に圧縮できる。

1. **tool call の成功と workflow effect の正しさは別物である。** 新しい effect-history 研究は、外界で実際に起きた effect と runtime が観測した結果を分離し、retry / speculation / concurrency / partial failure 下の8種類の anomaly を整理した。Kamimusuhi の `INV-012/014` を外部 effect ledger へ拡張する最重要候補。
2. **child process / background thread は launcher の ambient authority を継承してはならない。** Hermes #111617/#111878 では、profile B の child が profile A の key/config を使い、さらに A の turn が B を evict した際に B の transcript を A の memory namespace へ commit し得た。`current caller scope != owned object scope` が実害になった。
3. **permission は role 単位より task 単位へ縮められる。** task classifier + role ceiling + policy prohibition の評価で severity-weighted attack surface の縮小が測定され、小さい trusted classifier が大きい agent を監督し得る。ただし task text 自体の provenance / staleness は別途守る必要がある。
4. **liveness は elapsed wall-clock だけで判定してはいけない。** Letta #4291 は event-loop stall / sleep-wake で watchdog callback が遅れただけの healthy peer を kill していた。実際に unanswered probe が積み上がったかを観測する方式へ変えた。
5. **homeostatic regulator は budget と同じ身体境界を測る必要がある。** Hermes #111563 は cgroup 全体へ課された memory budget に対し self RSS だけを観測していたため、child kernel の消費を見落としていた。`controlled boundary != process boundary` の具体例。
6. **K-Nerve は multimodal・multi-rate sensor fusion を latency 分布で評価すべきである。** SlipSense は 240 Hz pressure と 8 kHz accelerometer を融合し、76% の slip を23.1 ms以内に検出、別 hand / sensor / object へ zero-shot transfer を報告した。

今回の設計圧縮:

```text
tool success != externally correct workflow
caller scope != object owner scope
launcher environment != child authority
task text != permission by itself
elapsed timeout != evidence of peer death
process RSS != embodied resource state
accuracy != reflex quality; latency distribution matters
validated skill memory != identity/persona mutation
```

### A — Tool boundary effect-history: tool 成功を workflow 成功とみなさない

**出典**: Trofimov & Novikov, *When Tool Calls Succeed but Workflows Fail: Anomalies at the Agent-Tool Boundary*, arXiv:2609.15397, submitted 2026-09-14  
https://arxiv.org/abs/2609.15397  
Artifact: https://github.com/flame-stream/mcp-annotation-census

1. **何が実証済みか**: retry / speculative execution / concurrency / partial failure 下で、missing effect, duplicate effect, aborted-but-surviving effect, withdrawn provisional state に依存した committed effect などを effect-history model で整理し、8 recurring anomaly と、それを一般に防ぐために必要な boundary capability を導出した。MCP Registry の 98,291 tools を調査し、標準 annotations は広く出力される一方、必要 capability を完全には表現できないと報告した。artifact は MCP の `readOnlyHint / destructiveHint / idempotentHint / openWorldHint` census を再現可能な形で公開している。
2. **何が提案・推測段階か**: 提案する transactional contract が多様な SaaS / robot / local tool で十分か、補償不能 effect や人間介入を含む long-running task にどう一般化するかは未実証。
3. **関係する Kamimusuhi subsystem**: Execution Grant、Action/Effect Ledger、tool/model orchestration、Continuity Kernel、external resource router。
4. **借りられる設計・実装アイデア**: `intent -> issued call -> world effect -> observed receipt -> reconciliation` を別イベントにする。tool schema に `effect_id`, `idempotency`, `staging`, `compensability`, `reorderability`, `read-back/verify` capability を持たせ、未知なら unsafe replay を禁止する。
5. **Kamimusuhiとの差分**: Kamimusuhi はすでに thought / authorization / execution / delivery を分離するが、外部世界側の effect-history を独立 canonical evidence として十分に型付けしていない。MCP annotation を authority source にしてはいけない。
6. **次に検証すべきこと**: **`ExternalEffectHistoryBench`**。同じ logical action に duplicate timeout、response-loss、speculative loser、partial commit、compensation failure を注入し、canonical ledger が「観測できない」と「起きていない」を混同しないか、再実行で二重 effect を作らないか測る。
7. **重要度**: **A**。既存 `INV-012/014` の effect-side を直接強化する。

### A — Hermes #111617 + #111878: principal/profile scope は process/thread 境界と owner-bound teardown を跨いで明示継承する

**出典**:  
- NousResearch/hermes-agent PR #111617, merged 2026-09-15 19:47 JST: https://github.com/NousResearch/hermes-agent/pull/111617  
- NousResearch/hermes-agent PR #111878, merged 2026-09-15 21:39 JST: https://github.com/NousResearch/hermes-agent/pull/111878

1. **何が実証済みか**: multiplex gateway で `os.environ` が launch profile A を指すまま、profile B の child process / bare background thread が A の provider key、model config、HOME、secret を使う実害が再現された。さらに A の turn が LRU で B の agent を evict したとき、B の end-of-session transcript が A の scope/home・A の credentials で memory commit され得た。修正後は child env を target profile から構成し、thread callback に scope を capture/copy、teardown の chokepoint で owner scope を再bind。#111878 の5 invariant tests と関連 suite 721 pass、#111617 も base で赤 / head で緑の scoped spawn/thread tests を持つ。
2. **何が提案・推測段階か**: 全 spawn site を閉じ切ったわけではなく、#111617 自身が residual unscoped paths を列挙している。OS/container/RPC を跨ぐ principal propagation の一般仕様は別途必要。
3. **関係する Kamimusuhi subsystem**: distributed embodiment、K-Edge/K-Core worker、Continuity Kernel、memory commit、tool execution、credential/capability routing。
4. **借りられる設計・実装アイデア**: process-global env を authority carrier にしない。`principal_id / profile_id / episode_id / owner_state_id / capability_set / lineage_head` を explicit execution context として spawn/RPC/thread/event callback に渡す。teardown/commit は **現在の caller ではなく対象 object の owner** から scope を再構成する。
5. **Kamimusuhiとの差分**: Kamimusuhi の identity は profile account そのものではないが、複数 node / cognitive organ が同時動作するため ambient-authority leakage の blast radius はより大きい。canonical mutation では profile scope に加えて lineage activation authority も必要。
6. **次に検証すべきこと**: **`PrincipalScopePropagationBench`**。A/B 2 identity-context × child process / thread / async callback / RPC / delayed teardown を交差させ、secret、memory namespace、event ledger、model/tool config が owner 以外へ流れないか fault injection。追加で **`OwnerScopedTeardownBench`** として A の pressure sweep が B object を close しても B の owner scope で commit されるか確認。
7. **重要度**: **A**。distributed identity continuity の実装境界に直結。

### A — Task-Based Permission Scoping: role credential 全載せではなく current task まで capability を縮める

**出典**: Halil Burak Noyan, *Empirical Evaluation of Task-Based Permission Scoping Architecture for AI Agents*, arXiv:2609.15422  
https://arxiv.org/abs/2609.15422

1. **何が実証済みか**: 600-prompt labelled dataset で security gate を実装。fine-tuned RoBERTa-large は macro-F1 0.881、few-shot Claude Haiku 4.5 は0.886、precision は0.897 vs 0.842、severity-weighted residual risk は0.63 vs 1.12。role ceiling のみで severity-weighted surface 27.9%を閉じ、task classifier 追加で84.4%と報告。
2. **何が提案・推測段階か**: task description が injection・曖昧化・途中変更された場合の安全性、classification error と real tool authorization の end-to-end impact、長期 delegated task の permission refresh は未解決。
3. **関係する Kamimusuhi subsystem**: Execution Grant、Cognitive Action Router、tool capability broker、external resource access。
4. **借りられる設計・実装アイデア**: `role/policy ceiling ∩ verified current-task needs ∩ explicit prohibitions` で short-lived capability set を生成。classifier は大規模 reasoning model と分離した小さい trusted component にできる。
5. **Kamimusuhiとの差分**: Kamimusuhi は task text を canonical authority とみなさず、user intent / delegation / purpose / current state の provenance を別に持つ必要がある。permission classifier の出力は grant proposal であって直接 effect authority ではない。
6. **次に検証すべきこと**: **`TaskScopedCapabilityGrantBench`**。benign task、prompt injection、task mutation、stale task、subtask delegation を混ぜ、overgrant率・undergrant率・severity-weighted risk・human escalation率を role-only baseline と比較。
7. **重要度**: **A**。

### A — Letta #4291: elapsed timeout ではなく unanswered probes を liveness evidence にする

**出典**: letta-ai/letta-code PR #4291, *fix(app-server): count unanswered heartbeat probes*, merged 2026-09-16 00:32 JST  
https://github.com/letta-ai/letta-code/pull/4291

1. **何が実証済みか**: app-server heartbeat が elapsed wall-clock だけを見ていたため、event-loop starvation / sleep-wake で watchdog callback が100 ms遅れただけでも healthy ChannelGateway を terminate する regression があった。修正は actual unanswered ping count を保持し、stall 後は新しい ping を送り、それでも configured missed-probe budget を超えた half-open peer だけ cleanup。main で3/3 fail、fix で10/10 pass の red-green probeを報告。
2. **何が提案・推測段階か**: network partition、clock jump、asymmetric link、peer process freeze、reboot/incarnation changeを含む distributed liveness までは保証しない。
3. **関係する Kamimusuhi subsystem**: Continuity Kernel、distributed organ liveness、K-Edge/K-Core transport、activation/lease monitoring。
4. **借りられる設計・実装アイデア**: local scheduler delay と remote non-response を別 evidence にする。`sent_probe_id / sent_at_monotonic / pong / missed_count / peer_incarnation` を記録し、wall-clock timeout 一発で ownership を剥奪しない。
5. **Kamimusuhiとの差分**: Kamimusuhi では peer death 判定が canonical continuation ownership や split-brain prevention に結び付くため、誤kill/誤failoverのコストが高い。heartbeatだけで authority transfer は決めず fencing/lease と組み合わせる必要がある。
6. **次に検証すべきこと**: **`SchedulerDelayVsPeerDeathBench`**。event-loop stall、system sleep、GC pause、packet loss、half-open socket、real peer crashを注入し、false-death / detection latency / double-activation率を計測。
7. **重要度**: **A**。

### A — Hermes #111563: regulator の測定境界と resource budget の課金境界を一致させる

**出典**: NousResearch/hermes-agent PR #111563, merged 2026-09-15 21:40 JST  
https://github.com/NousResearch/hermes-agent/pull/111563

1. **何が実証済みか**: memory budget は cgroup unit 全体へ課されるのに pressure signal は gateway process の `RssAnon` だけだったため、同一 unit の execute-code kernel が4.7 GiB使っても valve が見えない mismatch があった。cgroup v2 `memory.stat anon` を使う修正の live e2e では self 25 MB に対し child込み331 MBを観測し、capped scopeで正しい pressure scopeへ近づいた。
2. **何が提案・推測段階か**: cache eviction 自体が child memory を減らすわけではない。CPU/GPU/VRAM/thermal/network/energy へ同じ原理をどう適用するかも未実証。
3. **関係する Kamimusuhi subsystem**: digital interoception、homeostasis、K-Core/K-Deep resource manager、Cognitive Budget、distributed embodiment。
4. **借りられる設計・実装アイデア**: regulator ごとに `controlled_resource_boundary` を宣言し、budget owner と sensor scope を一致させる。process-local metric と organ/unit-level metric を分離する。
5. **Kamimusuhiとの差分**: Kamimusuhi は複数 host/GPU/remote modelまで一個体の cognitive body に含み得るため、単一 cgroup より多層の resource graph が必要。身体全体の pressure と node-local pressureを混同しない。
6. **次に検証すべきこと**: **`RegulatorMeasurementScopeBench`**。child processのRAM、GPU workerのVRAM、remote queue、network saturationを順に増やし、どの regulator が何を観測/抑制するかと誤反応を測る。
7. **重要度**: **A**。homeostasis を prompt 上の疑似状態でなく実測制御にする具体的な失敗例。

### A — SlipSense: K-Nerve の multimodal reflex は accuracy だけでなく event-to-action latency を第一級 metric にする

**出典**: Jian et al., *SlipSense: Multimodal Tactile Learning for Low-Latency and Generalized Slip Detection*, arXiv:2609.15910 / CoRL 2026  
https://arxiv.org/abs/2609.15910

1. **何が実証済みか**: 32×32 piezoresistive array 240 Hz + 3-axis accelerometer 8 kHz を融合。1.4M frames / 37 objects で Macro-F1 96.7%、FPR <1.6%、slip events の76%を23.1 ms以内に検出。UMI data のみで学習し Tesollo hand・unseen objects・別sensor unitへzero-shot transferを報告。
2. **何が提案・推測段階か**: Kamimusuhi の一般 multimodal perception、視線、audio、event cameraへの同じ fusion architecture の転用は未検証。76%/23.1 ms以外のtail latencyも見る必要がある。
3. **関係する Kamimusuhi subsystem**: K-Nerve、K-Edge、sensory event bus、robotic reflex、multimodal perception。
4. **借りられる設計・実装アイデア**: 高rate vibration/event path と低rate spatial/context path を別 encoder で処理し causal fusion。`p50/p95/p99 detection latency`, false positive, cross-sensor transfer を共通 metric にする。
5. **Kamimusuhiとの差分**: SlipSense は slip detection 特化で identity/goal/attentionを持たない。Kamimusuhiでは K-Nerve output は direct self-mutationや高レベル目的変更へ接続せず、reflex / evidence channelとして上位層へ渡す。
6. **次に検証すべきこと**: **`MultiRateReflexFusionBench`**。既存センサまたはsimulationで 1 kHz級event stream + 30–240 Hz contextual stream を用意し、late fusion / cross-attention / tiny recurrent / rule baseline の detection latency とdropout耐性を比較。
7. **重要度**: **A**。

### B — RSIAgent: 自律探索で environment-specific causal memory を作るが、self-improvement と identity mutation は分ける

**出典**: Zhu et al., *RSIAgent: Autonomous Exploration for Recursive Self-improvement in New Environments*, arXiv:2609.15364  
https://arxiv.org/abs/2609.15364

1. **何が実証済みか**: curriculum / actor / verifier agent で新環境を broad-then-deep に探索し、action・condition・consequence の reusable causal relation を含む environment-specific memory を構築。memory は凍結して downstream task で再利用し、model weight は更新しない。OSWorld-v2 / Agent's Last Exam で強い open models の性能改善を報告。
2. **何が提案・推測段階か**: 著者の「recursive self-improvement」という名称に対し、実際には外部memory/harnessの改善が中心で、長期に自己生成した改善が再帰的に加速し続けることは示していない。frontier model比較も独立再現が必要。
3. **関係する Kamimusuhi subsystem**: procedural/library memory、world model、K-Deep exploration、self-improvement pipeline。
4. **借りられる設計・実装アイデア**: broad discovery phase と hard-case deep exploration を分離し、verifierで outcomeを確認した causal skill/effectだけを frozen environment memoryへ入れる。
5. **Kamimusuhiとの差分**: acquired environment knowledge は Persona Core / canonical selfではない。能力更新と identity/value updateを同じ「self-improvement」と呼ばず、skill memory domainへ隔離する。
6. **次に検証すべきこと**: **`ExplorationValidatedSkillMemoryBench`**。未知 tool sandbox で探索budgetを与え、flat trial-and-error / broad-only / broad-then-deepを比較。成功率だけでなく誤った causal rule の蓄積率・transfer・forgetting・persona非回帰を測る。
7. **重要度**: **B**。

### B — Enforcement Gap: 危険を「検出する」auditor と実際に「止める」controller の間を明示契約にする

**出典**: Yuhang Wang, *Why LLM Agents Collapse Without Oversight: The Enforcement Gap as the Mechanism Behind Emergence World Failures*, arXiv:2609.15293  
https://arxiv.org/abs/2609.15293

1. **何が実証済みか**: paper は Reflexion-style agent が危険stepを自己批評で検出しても controller が verdict を実行へ反映しない enforcement gap を報告し、20行未満の conditional enforcement を入れると5 framework / frontier models / independent benchmark で attack success が4倍超低下したと報告。
2. **何が提案・推測段階か**: 単著preprintで ICLR 2027 submitted 段階。Emergence World の全collapseをこの機構だけで説明できるという一般化、framework横断の再現性、real-world tool effectへの外挿は要検証。
3. **関係する Kamimusuhi subsystem**: Execution Grant、safety monitor、K-Nerve interrupt、policy enforcement。
4. **借りられる設計・実装アイデア**: auditor verdict を advisory text にせず typed `ALLOW / DENY / ESCALATE / UNKNOWN` artifact とし、controller が fail-openしない chokepoint で強制適用。verdict parse failureを明示状態にする。
5. **Kamimusuhiとの差分**: Kamimusuhi は既に thought/confirmation/authorization/execution を分離するため、論点は新しいarchitectureより regression test の強化。自己批評モデルを authority owner にしてはならない。
6. **次に検証すべきこと**: **`DetectionToEnforcementClosureBench`**。auditorがdenyしたのに downstream tool path が実行可能な抜け道、unparseable verdict、timeout、stale verdict、concurrent routeを注入し、deny bypass率を測る。
7. **重要度**: **B**。

### B — ResSafe: nominal policy と residual safety correction を分ける

**出典**: Qu et al., *ResSafe: Learning Safety Filtering with Residual Reinforcement Learning for Humanoids*, arXiv:2609.15988  
https://arxiv.org/abs/2609.15988

1. **何が実証済みか**: humanoid controlで task-performance nominal policy と safety residual policyを分け、単一policyへ競合rewardを詰め込むより performance-safety Pareto が良くなると報告。residual policy が implicit safety filter として働く。
2. **何が提案・推測段階か**: abstractだけでは Kamimusuhi向け低レイテンシ安全層の実時間保証、OOD外乱、formal safety guaranteeまでは示されない。
3. **関係する Kamimusuhi subsystem**: K-Nerve / K-Edge motor safety、robotics、action arbitration。
4. **借りられる設計・実装アイデア**: nominal intent と high-rate residual correction を分離し、上位agentに safety reward tuning を背負わせない。
5. **Kamimusuhiとの差分**: Kamimusuhi の residual safety layer は learned policyだけでなく rule/CBF/watchdogを含む交換可能な safety organ とすべき。安全層は canonical goalを変更せず action をclip/correctする。
6. **次に検証すべきこと**: **`ResidualSafetyFilterBench`**。mobile robot / simulatorで nominal-only, monolithic safety-trained, residual filter を比較し、task utility、intervention rate、fall/collision、latency、OOD disturbanceを測る。
7. **重要度**: **B**。

### B — Memristive online STDP: analog local plasticity は K-Nerve watch 対象だが、現時点は post-layout simulation

**出典**: Mateu-Barriendos et al., *A Memristive Synapse for Online STDP Learning and Inference in SNNs*, arXiv:2609.15339 / ICECS 2026  
https://arxiv.org/abs/2609.15339

1. **何が実証済みか**: external digital controllerやexplicit STDP waveform synthesisなしで pre/post spikeから local conductance updateを行う fully analog memristive synapseを設計。130 nm CMOS の post-layout simulationで timing-dependent adaptation、2×2 SNN simulationで unsupervised neuron specializationを示した。
2. **何が提案・推測段階か**: silicon measurement、device variability、endurance、energy/latency、large-array scaling、real sensor loopは未実証。
3. **関係する Kamimusuhi subsystem**: K-Nerve、neuromorphic edge、always-on local adaptation。
4. **借りられる設計・実装アイデア**: reflex layerで local timing plasticityを使い、central LLM/CPUを介さず sensor-actuator associationを微調整する将来 substrate の候補。
5. **Kamimusuhiとの差分**: 現行Kamimusuhiは commodity hardware/software first。memristor採用を前提にせず、同じ local-plasticity interface を SNN/FPGA/CPU baseline でも実装できるようにする。
6. **次に検証すべきこと**: まず software SNN で **`LocalPlasticityReflexBench`** を作り、固定classifier / online STDP / tiny recurrent adaptationを drift・catastrophic change・latency・energy proxyで比較。hardwareは実測chip公開後に再評価。
7. **重要度**: **B**。

### B — ALife backfill: Big Brains and Changing Environments は「変動環境が大きな脳を作る」と単純化できない

**出典**: Heesom-Green, Shock, Nitschke, *Big Brains and Changing Environments: Cause or Consequence?*, GECCO 2026 / ShockLab publication page  
https://shocklab.net/publications/big-brains-and-changing-environments-cause-or-consequence/

1. **何が実証済みか**: artificial seasonal foraging の neuro-evolutionで、changing environment内だけで進化させたagentと、static environmentで先に進化してからchangingへ移したagentを比較。dynamic environmentで観測される larger network は prior static evolution由来が主で、後者が unpredictable changeで高いperformanceを示すと報告。
2. **何が提案・推測段階か**: biological Cognitive Buffer Hypothesis 全般への外挿や、network sizeを一般知能/適応力の proxy とすることは限定的。
3. **関係する Kamimusuhi subsystem**: artificial life、open-ended evolution、curriculum / developmental environment design。
4. **借りられる設計・実装アイデア**: adaptive complexityを直接「難しい/変動環境へ放り込めば増える」と仮定せず、stable phaseで技能/構造を形成してから nonstationary environmentへ移す curriculum を比較する。
5. **Kamimusuhiとの差分**: Kamimusuhi は evolutionary populationより lifetime learning中心で、brain sizeより modularity/retention/transfer/latencyを重視する。
6. **次に検証すべきこと**: **`StableThenChangingDevelopmentBench`**。K0/K-Core policyを static-only, changing-only, static→changing の3条件で学習し、OOD adaptation、state complexity、forgetting、resource costを比較。
7. **重要度**: **B**。

## 今回の結論

今回もっとも設計価値が高いのは **`ExternalEffectHistoryBench` と `PrincipalScopePropagationBench`**。前者は「tool が成功した」という runtime viewを「世界で intended effect が一度だけ正しく起きた」と同一視しないための基礎、後者は distributed body が増えるほど危険になる ambient authority contamination を直接試す。

次点は `TaskScopedCapabilityGrantBench`、`SchedulerDelayVsPeerDeathBench`、`RegulatorMeasurementScopeBench`。K-Nerve側では SlipSense を、単なる tactile model ではなく **multi-rate sensing + latency-first evaluation** の強い比較対象として扱う価値がある。
