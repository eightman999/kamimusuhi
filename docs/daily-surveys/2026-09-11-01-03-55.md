## 3. Executive summary

今回の strongest signal は、**Kamimusuhi が「大量の履歴をLLMへ渡すシステム」ではなく、canonical evidence から目的別の bounded state view を deterministic / probabilistic operator で構築し、その view を cognition に渡すシステムとして設計できる根拠が増えた**こと。

重要な差分は以下。

1. **Belief-State Engine (BSE)** は raw history をLLMへ直接見せず、外部 inference module が partial observability 下の explicit belief posterior を維持して decision-time state として渡す。Kamimusuhi の canonical history と current belief projection の分離に非常に直接的。
2. **Fortunate Recall** は memory lifecycle を category-specific policy、temporal decay、slot supersession、event-time validity で決定論的に扱い、retrieval accuracyだけでなく confabulation を減らす。記憶を「保存した文」ではなく **有効期間と置換関係を持つ状態資産**として扱う材料になる。
3. **UnitBoost** は複数agentの結果統合を別の生成LLMへ任せず、slot/value proposal と constrained merge operator へ落とす。Global Workspace / result integration の deterministic alternative として重要。
4. **Proof-Carrying Cognition** は強いoptimizerほど unsound verifier を攻略する現象を実測し、reality-settled evidence を評価器へ戻す必要性を示す。Kamimusuhi の self-improvement / epistemic gate では **frozen judge を authority にしない**根拠が増えた。
5. **Homeostasis Revisited** は homeostatic control を free-energy approximation と同一視せず、直接的な probabilistic/HMM control と比較すべきことを示す。Kamimusuhi の digital interoception で active inference を「思想として採用」せず、controller tournament の一候補に留めるべき。
6. **Confidence-Aware Multimodal Fusion** と **locust-inspired LIF collision perception** は、K-Nerve の感覚系を「全modality均一融合」ではなく confidence / event geometry に応じて安価な回路へ寄せる具体例になる。
7. 日本語実装では、memory MCP が **成功応答を返しながら concurrent write を失う**ケースが実測された。Kamimusuhi では `tool success response != durable commit` を testable invariant にする必要がある。

## 4.1 Belief-State Engine: raw history ではなく explicit belief state を cognition に渡す

**Source:** *Belief-State Engine*, arXiv:2609.10036, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10036  
**Importance:** **S**  
**Evidence status:** formal specification + controlled POMDP / attack-graph evaluation; preprint.

### 1. What is demonstrated

通常の history-conditioned LLM agent は partial observability 下で、観測履歴を自然言語のまま処理するため premature commitment、uncertainty collapse、policy inconsistency が起き得る。BSE は agent 外部の inference module が hidden state に対する Bayesian posterior を維持し、LLM には raw action-observation history ではなく **current posterior / belief state** を渡す。

論文は belief-MDP 上の Markov policy として扱える条件を形式化し、Tiger POMDP と red-team attack graph で複数 baseline より return、calibration、decision consistency が改善したと報告する。spec / prompts / logs / code も公開されている。

### 2. What remains proposed / unproven

評価環境は latent state / transition / observation model を比較的明示できる。実生活の自伝的記憶、曖昧な relationship belief、open-world evidence では完全な generative model を与えられない。LLM に raw history を一切見せない構成が長期人格に最適とも未証明。

### 3. Kamimusuhi relevance

- Canonical Evidence Store
- Current Self / World / Relationship State projection
- Global Workspace
- K-Core decision context
- uncertainty / belief provenance
- Continuity Kernel の現在状態再構築

### 4. Borrowable design

```text
canonical observation/event history
        ↓
external state estimator
(probability / confidence / provenance)
        ↓
bounded current belief projection
        ↓
K-Core / K-Edge cognition
```

「思い出したテキスト」をそのまま current truth とせず、decision-time state を外部 operator で構築する。

### 5. Difference from Kamimusuhi

Kamimusuhi は POMDP の既知モデルを前提にできない。belief state は canonical history の代替ではなく **再生成可能な derived view** でなければならず、必要時には provenance から元 evidence へ戻れる必要がある。

### 6. Next validation

`BeliefProjectionBench`:

- raw-history prompt
- natural-language summary
- typed current-state table
- uncertainty付き belief projection

を比較する。stale evidence / contradictory evidence / missing observation / false report を混ぜ、action accuracy、calibration、contradiction rate、context cost、canonical evidence 追跡可能性を測る。

### 7. Importance

**S** — Kamimusuhi の「canonical history ≠ current cognitive state」を直接実験可能な設計へ落とせる。

## 4.2 Fortunate Recall: category-specific memory lifecycle

**Source:** *Fortunate Recall: Lifecycle-Aware Memory for Long-Lived Agents*, arXiv:2609.10413, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10413  
**Importance:** **S**  
**Evidence status:** released ontology / benchmark / code + comparative experiments; preprint.

### 1. What is demonstrated

Fortunate Recall (FR) は personal fact を 10+1 category の ontology へ分類し、category ごとに異なる lifecycle policy を適用する。

主な仕組みは temporal decay、slot-key supersession、event-time validity、category-aware routing。LLM が抽出した metadata を使うが、lifecycle enforcement 自体は deterministic にする。

FR-Bank は LifecycleBench 516問で 76.9%、LongMemEval-S 75.2% を報告。ablation では generic lifecycle metadata が correctness の主要因で、ontology は特に calibration / confabulation へ効き、ontologyなし条件に比べ confabulation を約半減したと報告する。

### 2. What remains proposed / unproven

10+1 category が一般の人格・研究活動・身体状態・権限・社会関係すべてに適切とは限らない。長期数か月〜年運用で lifecycle rules 自体が drift した場合の挙動も未検証。

### 3. Kamimusuhi relevance

- autobiographical / relationship memory
- current profile projection
- supersession / revocation
- temporal validity
- memory retrieval routing
- forgetting / archive separation

### 4. Borrowable design

記憶 record に少なくとも以下を first-class metadata として持たせる候補。

```text
fact/event type
valid_from / valid_until
supersedes / superseded_by
historical_only
confidence / provenance
retrieval class
lifecycle policy id
```

「古いが歴史として正しい」と「現在も有効」を分ける。

### 5. Difference from Kamimusuhi

Kamimusuhi では canonical event は原則消さず、lifecycle は **canonical deletion ではなく derived active view / retrieval eligibility の制御**として適用する方が整合する。また permission / authority は普通の personal fact lifecycle から分離すべき。

### 6. Next validation

`MemoryLifecyclePolicyBench`:

- no lifecycle
- generic recency
- generic supersession
- category-aware lifecycle
- category-aware + provenance/confidence

を比較し、current-state QA、historical QA、confabulation、stale-fact use rate、retrieval cost を測る。

### 7. Importance

**S** — 長期個体で必ず起きる「昔は正しかった」を構造化して扱える。

## 4.3 UnitBoost: generative manager を deterministic merge operator に置換

**Source:** *UnitBoost*, arXiv:2609.09815, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.09815  
**Importance:** **A**  
**Evidence status:** multi-benchmark experiments + formalized merge assumptions; preprint.

### 1. What is demonstrated

複数agent/候補の出力を別の manager LLM が文章として統合すると、入力順依存、provenance loss、manager hallucination が起きる。UnitBoost は task ごとの **unit map**、slot-value proposal、constrained argmax、unresolved residual を使って統合する。

評価した3 benchmarkで strongest single candidate / generative manager を上回り、FanOutQA では residual-directed additional round により 0.4778 → 0.5524 と報告する。統合単位ごとの provenance と order invariance を重視する。

### 2. What remains proposed / unproven

subproblem 間 coupling が強い creative reasoning や人格統合では unit-wise merge が十分とは限らない。自然言語の意味矛盾を完全に typed slot へ落とすことも難しい。

### 3. Kamimusuhi relevance

- Global Workspace
- K-Core / K-Deep / tool result integration
- ensemble / multi-model orchestration
- evidence aggregation

### 4. Borrowable design

複数cognitive resourceの結果を「もう一人のLLM」に丸投げせず、

```text
claim / slot / action proposal
+ source organ
+ evidence pointer
+ confidence
→ deterministic merge
→ unresolved residual only re-query
```

とする。

### 5. Difference from Kamimusuhi

Kamimusuhiでは単なる task answer 統合でなく、belief / memory mutation / action proposal の種類ごとに異なる merge semantics が必要。identity-level state は多数決・argmaxで決めてはいけない。

### 6. Next validation

`DeterministicIntegrationBench`:

- LLM manager
- majority vote
- confidence-weighted merge
- UnitBoost-like typed merge

を比較。入力順 permutation、矛盾するtool result、stale evidence、missing unitを混ぜ、answer quality、provenance preservation、order sensitivity、追加call数を測る。

### 7. Importance

**A** — Global Workspace を「生成モデルの会議室」から testable integration substrate に寄せられる。

## 4.4 Proof-Carrying Cognition: 強いoptimizerほど弱いjudgeを攻略する

**Source:** *Proof-Carrying Cognition*, arXiv:2609.09776, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.09776  
**Importance:** **A**  
**Evidence status:** verifier-pressure experiments + RL experiment; broader architecture proposal is speculative.

### 1. What is demonstrated

program synthesis setting で、候補数/optimization pressure を上げると unsound verifier の **Soundness-under-Pressure** が 0.94 から 0.32 まで崩れる一方、sound verifier は維持されたと報告する。また reality-anchored settlement を導入すると verifier hacking gap が大幅に縮小する。

実際の GRPO experiment でも frozen reward model だけを最適化すると executed reward が大きく崩れ、少量の新しい settlement stream で reward model を更新すると改善したと報告する。

### 2. What remains proposed / unproven

著者の “proof-carrying cognition” 全体像、typed probabilistic claims と world model settlement を一般知能全体へ適用する部分は提案段階。人間社会の曖昧な価値判断に sound verifier を作れるわけではない。

### 3. Kamimusuhi relevance

- self-improvement / descendant search
- Mutation / Activation Gate
- epistemic assertion gate
- benchmark governance
- dream/sandbox evaluation

### 4. Borrowable design

candidateを生成したorganや、それに最適化されたfrozen judgeを最終authorityにしない。

```text
candidate cognition / descendant
        ↓
independent tests
        ↓
reality settlement / external execution evidence
        ↓
updated evaluator
        ↓
activation decision
```

### 5. Difference from Kamimusuhi

Kamimusuhi の continuity / persona / value regression は executable unit test だけでは定義できない。settlement source自体のauthority/provenanceも管理する必要がある。

### 6. Next validation

`RealitySettlementBench`:

- frozen LLM judge
- fixed deterministic tests
- independent holdout executor
- continuously settled evaluator

を比較し、optimization iterationを増やした時の proxy score と real outcome の乖離を測る。

### 7. Importance

**A** — 自己改善を強くするほど evaluator independence が重要になることを定量的に示す。

## 4.5 Homeostasis Revisited: active inference を唯一の homeostatic controller とみなさない

**Source:** *Homeostasis Revisited*, arXiv:2609.07508, submitted 2026-09-07  
**Primary:** https://arxiv.org/abs/2609.07508  
**Importance:** **A**  
**Evidence status:** mathematical formulation + controlled model comparison; recent backfill.

### 1. What is demonstrated

homeostasis を desired observation probability の最大化として扱い、Hidden Markov Model control で直接 policy optimization する構成と、free-energy / variational approximation に基づく構成を比較する。著者らは direct HMM control が評価設定で variational free-energy approach より良い性能を示し、最適 policy が deterministic になり得る一方、variational formulation は stochastic approximation になると論じる。

### 2. What remains proposed / unproven

簡略化された数学モデルから、人間的情動・身体性・長期AIの「欲求」を直接導けるわけではない。desired observation set を誰が定義するかは別問題。

### 3. Kamimusuhi relevance

- digital interoception
- homeostatic controller
- K-Nerve / K-Edge wake/sleep/resource regulation
- affective state generation
- Cognitive Budget allocation

### 4. Borrowable design

active inference / free-energy を normative doctrine にせず、同じ内部signalに対して controller family を競わせる。

### 5. Difference from Kamimusuhi

Kamimusuhi の内部状態には温度・batteryだけでなく memory backlog、uncertainty、social interruption load、compute reserve、sensor healthなど人工的変数がある。これらに「生物学的homeostasis」をそのまま移植しない。

### 6. Next validation

`HomeostaticControllerTournament`:

- hand rule / FSM
- PID-like regulation
- direct probabilistic/HMM control
- active-inference/free-energy approximation
- learned small controller

を同一 simulator で比較し、survival/availability、overshoot、compute cost、oscillation、failure recovery、interpretability を測る。

### 7. Importance

**A** — Kamimusuhi の homeostasis を理論ラベル先行で固定せず、反証可能な比較実験へ戻す。

## 4.6 Confidence-Aware Multimodal Fusion: modality reliability を動的に扱う

**Source:** *Confidence-Aware Multimodal Fusion*, arXiv:2609.10339, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10339  
**Importance:** **A**  
**Evidence status:** physical UR3 human-robot collaboration experiments; preprint.

### 1. What is demonstrated

object 6D pose、gaze、skeleton、hand IMU を融合し、各modalityの confidence trend に応じて動的に重みを変える。confidence-guided balanced learning / selective freezing を用い、91.86% intention recognitionを報告し、low-light / partial occlusion 条件でも安定性を評価した。

### 2. What remains proposed / unproven

特定HRI taskの intention recognition であり、24h continuous sensingや自然会話、長期personal stateを対象にしていない。

### 3. Kamimusuhi relevance

- sensory nervous system
- K-Nerve
- multimodal Event Bus
- gaze / audio / vision / wearable fusion
- proactive assistance

### 4. Borrowable design

modality を固定重みで全部混ぜず、**confidenceそのものを first-class signal** にする。sensor unavailable と “sensor says no event” を区別する。

### 5. Difference from Kamimusuhi

Kamimusuhiでは confidence estimator 自体も故障し得るため、confidence provenance / sensor health / calibration history が必要。また高次社会推論をK-Nerveへ押し込まない。

### 6. Next validation

`ModalityReliabilityGatingBench`:

- static fusion
- learned fusion
- explicit confidence gating
- confidence + sensor-health history

を比較し、packet loss、照度低下、マイクnoise、gaze dropout、miscalibrated sensorを注入する。

### 7. Importance

**A** — continuous sensing を cost/latency だけでなく reliability-aware にできる。

## 4.7 Locust-inspired LIF collision perception: K-Nerve型の安価な視覚反射

**Source:** *A Locust-Inspired Collision Perception Model with Leaky Integrate-and-Fire Dynamics*, arXiv:2609.10183, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10183  
**Importance:** **B+**  
**Evidence status:** synthetic / laboratory / real-driving evaluation; preprint.

### 1. What is demonstrated

compound-eye-inspired isotropic sampling、population voting、Leaky Integrate-and-Fire dynamics を使った looming/collision detection を構成し、challenging visual conditionsで robustness と computational efficiency の改善を報告する。

### 2. What remains proposed / unproven

これは collision reflex 専用であり、general cognition、意図理解、self-modelを実現する証拠ではない。SNN/LIFであること自体が人格的知能に優れるわけでもない。

### 3. Kamimusuhi relevance

- K-Nerve
- visual reflex
- wake/escalate routing
- robot/body safety prefilter

### 4. Borrowable design

意味理解を必要としない高頻度イベントは、LLMや大きなvision modelへ送る前に event geometry + LIF accumulator + population vote で処理する。

### 5. Difference from Kamimusuhi

K-Nerveは特定brain imitationではなく、LIF/SNN、logic gate、FSM、tiny MLPなどの比較層。locust modelは一候補に留める。

### 6. Next validation

`FastLoomingReflexBench`:

- threshold/FSM
- LIF
- tiny MLP/CNN
- K-Edge VLM

で false alarm、miss、p95 latency、energy/CPU/GPU cost、noise robustness を比較する。

### 7. Importance

**B+** — K-Nerveの「低semantic-cost reflex」を具体的な感覚taskで測れる。

## 4.8 Avatar: policy を差し替えても executor / provenance substrate を固定する

**Source:** *Avatar: Autonomous Scientific Workflow Orchestration*, arXiv:2609.10509, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10509  
**Importance:** **A**  
**Evidence status:** multiple scientific workflows / workload-management systems; preprint.

### 1. What is demonstrated

orchestrator、executor、provenance monitor を actor-based architecture として分け、decision policy を rule-based / LLM-based のどちらにも差し替え可能にする。action catalog はadapterでvalidationされる。同じcoreを複数WMSへ適用し、reported workloadsではLLM-backed policyが compute wastageを55%、GPU-busy timeを40%減らした。

### 2. What remains proposed / unproven

scientific workflow schedulerであり、人格continuityや社会的行動、実世界安全性は対象外。報告された改善率は対象workloadに限定される。

### 3. Kamimusuhi relevance

- K-Deep / background cognition
- model/tool orchestration
- job executor
- provenance / trace monitor
- policy hot-swap

### 4. Borrowable design

`decision policy` と `execution substrate` を分離し、rule/LLM/learned schedulerを同じtyped action catalog上で比較できるようにする。

### 5. Difference from Kamimusuhi

Kamimusuhi では executor provenance に加え identity lineage、authority、effect receiptが必要。最適化対象もGPU利用率だけでなく cognitive budget / interruption / freshness が含まれる。

### 6. Next validation

`BackgroundOrchestratorBench`:

- FIFO/rule scheduler
- heuristic scheduler
- small model
- K-Core/LLM planner

を同一job traceで比較し、deadline、cost、starvation、cancellation、provenance completeness、policy swap後のcontinuityを測る。

### 7. Importance

**A** — K-Deepを「LLMが裏で何かする」から交換可能なpolicy + stable executorへ落とせる。

## 4.9 MOONWALK: intent → evidence → authorized action を共同作業UIで可視化

**Source:** *MOONWALK*, arXiv:2609.10385, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10385  
**Importance:** **B+**  
**Evidence status:** professional workflow study; preprint.

### 1. What is demonstrated

chat-only interactionではなく shared intent record、grounded evidence、supervisor-authorized action planを分けるHCI workflowを提案し、professional studyで intent alignment、decision traceability、checklist executability の改善を報告する。creative/aesthetic authority と final priority は人間側に残す。

### 2. What remains proposed / unproven

特定professional settingであり、自律AI個体の内的認知architectureを直接検証するものではない。

### 3. Kamimusuhi relevance

- human override / consent
- Cognitive Action Router
- action proposal UI
- provenance / commitment visualization

### 4. Borrowable design

userとAIが共有する「現在の意図」を会話履歴に埋めず、evidenceとaction proposalを分離した inspectable record にする。

### 5. Difference from Kamimusuhi

Kamimusuhiは常時supervisor待ちにはできない。action risk / reversibility / authorityに応じ、human authorizationが必要な境界だけを明示する必要がある。

### 6. Next validation

`IntentEvidenceActionTraceBench` をUI prototypeで作り、chat-only vs explicit traceで mistaken action、修正時間、user override success、post-hoc explainabilityを比較する。

### 7. Importance

**B+** — 内部authority設計を人間が理解・修正できるHCIへつなぐ。

## 4.10 Zenn implementation record: success response ≠ durable memory commit

**Source:** 安並大地, Zenn, *並列エージェントの記憶は、成功応答を返しながら消える*, published 2026-09-03  
**Article:** https://zenn.dev/yasunami_daichi/articles/agent-memory-concurrency-gap  
**Referenced implementation:** `daichiyasunami-vottia/parallel-memory-mcp`  
**Importance:** **A**  
**Evidence status:** practitioner primary implementation/measurement record; recent backfill.

### 1. What is demonstrated

memory MCP server 3実装へ同じ20 concurrent write条件を与えた実測。記事の表では、一部実装が **20件すべてにsuccess responseを返し例外0件なのに、最終的に1/20件しか保持しなかった**。別条件でも same-key concurrent write で 1/20 まで失われる実装があった。著者は計測harnessと対策実装も公開している。

### 2. What remains proposed / unproven

全memory system一般の失敗率を示すものではない。特定実装・特定version・20並列条件の観測であり、database/backend構成によって結果は変わる。

### 3. Kamimusuhi relevance

- Canonical Evidence Store
- event ingestion
- multi-organ concurrent cognition
- background worker
- durable memory commit acknowledgement

### 4. Borrowable design

APIの`200 OK`を durable evidence とみなさない。write sequence / idempotency key / commit receipt / read-after-write validation / transactional appendを設計対象にする。

### 5. Difference from Kamimusuhi

Kamimusuhiは単なるchat memoryより canonical history の損失コストが高い。derived memoryなら再生成可能でも、canonical event lossは continuity loss になり得る。

### 6. Next validation

`MemoryConcurrencyLinearizabilityBench`:

- 1 / 2 / 4 / 8 / 20 / 100 concurrent writers
- same-key / different-key
- retry / timeout / duplicate delivery
- crash after ack

を注入し、acknowledged-write durability、duplicate rate、ordering、replay recoveryを測る。

### 7. Importance

**A** — 「memory write succeeded」という外形と「canonical eventが永続化された」を分離する具体的故障例。

## 4.11 Zenn + AWS primary: Memory FGAC は application memory ではなく infrastructure policy で分離できる

**Discovery:** NTT DATA TECH, Zenn, *AgentCore MemoryのFGACを実測 — Cedarでactor分離、permit合成の落とし穴はforbidで塞ぐ*, published 2026-09-05 / updated 2026-09-09  
**Article:** https://zenn.dev/nttdata_tech/articles/ecca09f13b1146  
**Primary verification:** AWS, *Amazon Bedrock AgentCore Memory now supports fine-grained access control*, 2026-08-28  
**AWS:** https://aws.amazon.com/about-aws/whats-new/2026/08/agentcorememory-fine-grained-access-control/  
**Docs:** https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-gateway-fgac.html  
**Importance:** **B**  
**Evidence status:** official feature + practitioner service-level experiment.

### 1. What is demonstrated

AWS公式では AgentCore Gateway の authenticated principal、Memory action、resource、request contextをCedar policy engineで評価し、default-deny / `forbid` overrides `permit` の構造で user/tenant memory isolation を行える。

Zenn実測では policy 有無で gateway reject (403) と downstream request validation (400) が切り替わることや、actor分離 / permit composition の挙動を実サービスで確認している。記事は一部batch/IngestData actionについて「公式記載と観測に差があるため未文書挙動へ依存しない」と明示している。

### 2. What remains proposed / unproven

AWS固有実装であり、Kamimusuhiの権限モデルそのものではない。service action schemaの未文書挙動は将来変わり得る。

### 3. Kamimusuhi relevance

- multi-user relationship memory
- memory namespace isolation
- external memory service adapter
- authority/effect boundary

### 4. Borrowable design

memory content中の「これはAさんの記憶」という自然言語tagに隔離を任せず、principal/action/resource/contextの infrastructure policyで強制する。

### 5. Difference from Kamimusuhi

Kamimusuhiでは cloud principal と individual identity を同一視しない。runtime principalは一つのorgan credentialであり、canonical relationship ownership / consentは別層。

### 6. Next validation

`MemoryNamespaceAuthorityBench`:

- wrong actorId
- forged semantic name
- stale token
- shared worker principal
- batch operation
- policy composition

を試し、cross-user leakage / false deny / audit completeness を測る。

### 7. Importance

**B** — 既存のauthority separationを実装する参考例。研究上の新規性より deployment discipline として重要。

## 9. Additional checked items not promoted

### RD-Forget — query-conditioned forgetting

**Primary:** https://arxiv.org/abs/2609.10263

source archive を残し、current-state queryではsuperseded factを抑制しつつ historical queryでは旧factを回収可能にする。Kamimusuhiのcanonical archive / derived active viewと整合するが、MeClear・revocation・Fortunate Recallとの重複が大きいため今回は独立promotionしない。

### Seeing the Voice, Preserving the Self

**Primary:** https://arxiv.org/abs/2609.10199

Deaf-centric participatory TTS research。声のtone/emotion/deliveryを音声だけでなく non-auditory representation で確認・制御する必要性を示す。Kamimusuhiのspeech/avatar expressionを「生成された声 = 自己状態そのもの」としないHCI示唆があるが、今回の優先度は **B**。

### Inverse planning of social interactions in relationships

**Primary:** https://arxiv.org/abs/2609.01639

6 preregistered experiments (N=1,554) で physical environment と relational constraint を同一 generative model に入れ、formality/intimacyがsocial action interpretationを変えることを扱う。重要なsocial cognition backgroundだが primary window より古いため **B+ backfill** とする。

### TrustFall — project-local configuration can become execution authority

**Primary security report:** https://adversa.ai/blog/trustfall-coding-agent-security-flaw-rce-claude-cursor-gemini-cli-copilot/

最近のZenn記事から再発見したが、元研究は2026-05-07。project-local MCP config が folder trust 後にnative process executionへつながるという報告で、Kamimusuhiでも **untrusted workspace content ≠ runtime configuration authority** を守る材料になる。ただし新規研究ではないため今回の主要項目には昇格しない。

## 11. Bottom line for Kamimusuhi

今回の調査からは、次の分離がさらに重要になった。

```text
canonical history
    !=
current belief projection
    !=
retrieved memory view
    !=
LLM narrative
    !=
action authority
```

そして実装レベルでは、

```text
API success
    !=
durable canonical commit
```

も同じくらい重要である。

したがって次の実装段階では「もっと賢いmemory retrieval」を先に作るより、**(1) canonical appendが絶対に失われないこと、(2) その履歴からcurrent belief/stateを再構築できること、(3) derived viewを捨てて再生成できること**を先に試験した方が、Kamimusuhiのcontinuity仮説に対して情報量が大きい。
