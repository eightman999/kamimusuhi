## 3. 要約

今回の中心テーマは、**局所的に成功・整合して見える状態を、システム全体の完了・正しさ・共同理解へ早すぎて昇格させないこと**だった。

特に重要な発見は以下。

1. **一部chunkの送信成功は、utterance全体のdelivery完了ではない。** Hermes #120073ではcontinuation送信が失敗してtailが見えていないのに、full payloadが`delivered=true`として記録され、fallbackまで抑止された。
2. **subagentの実行完了は、親の認知系へ結果がsettleされたことを意味しない。** OpenClaw #156416ではchildはsuccess・terminalReply保存済みでも、CLI requester経路だけparent completionが永久`pending`になった。
3. **world modelを信用するか否かは、抽象的なconfidenceではなく、decision marginとdecision-relevant model errorの比較としてgateできる。** Dual-Frontierは「予測優位が誤差上界を上回るときだけ使う」という定量境界を与える。
4. **協力行動の収束は社会規範の成立証拠ではない。** 同じ協力が期待共有・報酬構造・模倣など別機構から生じ得るため、behaviorとempirical/normative expectationを分ける必要がある。
5. **derived memoryはprovenanceを持つだけでは足りず、元sourceのauthorizationを推移的に継承し続ける必要がある。** AkasicMEMはsource→memory→memoryの派生でpolicyをcomposeし、retrieval時に再評価する。
6. **agentの失敗原因モデルにinfrastructure faultという変数がなければ、必ずagent自身を誤って責める。** CausalLoss-Finは545 planted episodesでこの構造的誤帰属を定量化した。

Kamimusuhiへの共通の含意は、`local success != global closure`、`behavior != mechanism`、`provenance != authorization continuity`、`agent failure != agent-caused failure` を明示的な状態・benchへ落とすこと。

## A — Hermes #120073: multipart deliveryの一部成功が「全文配信済み」に化ける

**Source**

- NousResearch/hermes-agent issue #120073, *Discord failed overflow continuations are marked fully delivered and the missing tail is suppressed*
- https://github.com/NousResearch/hermes-agent/issues/120073

### (1) 何が実証済みか

clean upstream上のcredential-free deterministic reproductionで、Discord向けfinal editが複数messageへ分割されたとき、最初のmessage editは成功するがcontinuation sendとretryを拒否させると、実際にはtailが一切見えていないにもかかわらず以下になる。

- `content_delivered=true`
- `final_matches=true`
- `normal_send_suppressed=true`
- `fallback_armed=false`

fixtureのraw textは606文字だが、Discord formatter後は4,061文字となりoverflow経路へ入る。failure branchではvisible messageは1件だけで`TAIL_MARKER`もない。

原因はadapterがpartial overflowでも`success=True`を返し、consumerの「失敗時partial recovery」経路へ入らず、requested full textを`_last_sent_text`として記録してしまうこと。

### (2) 何が提案・推測段階か

- issueはopenであり、修正がupstreamへmergeされたことはまだ実証されていない。
- 実Discordのnetwork timeout / ACK lossのようなacceptance ambiguityはfixtureのpermission refusalより難しく、同じretry規則をそのまま適用できない。

### (3) Kamimusuhi 関連 subsystem

- INV-012 thought / utterance / execution / delivery separation
- Gateway / utterance publication
- Continuity Kernelの未完了obligation
- external effect receipt
- multi-part streaming / voice / chat adapter

### (4) 借りられる設計・実装アイデア

`delivery`をbooleanにせず、canonical final payloadに対する**coverage ledger**にする。

例:

```text
utterance_id
canonical_payload_hash
rendered_chunks[]
  - chunk_id
  - canonical_range / semantic segment
  - transport_receipt
  - ack_state = confirmed | rejected | ambiguous
pending_ranges[]
```

一部送信が成功しても全rangeがconfirmedになるまで`DELIVERED`へ昇格しない。retryはconfirmed-undelivered rangeだけを送る。ACK ambiguityはreconcileへ回す。

### (5) Kamimusuhiとの差分

Kamimusuhiは概念上すでに`utterance != delivery`を分けているが、**multipart delivery内の部分完了**までcanonical truthとして表現する具体的ledgerはまだ十分ではない。

### (6) 次に検証すべきこと

`ChunkedDeliveryCommitmentLedgerBench-v0`

- 1/N〜N/N chunkの各位置でfailureを注入。
- formatterによるpayload expansionを含める。
- confirmed headを重複送信しない。
- confirmed-undelivered tailだけreplayできる。
- timeout / ACK lossは`ambiguous`として無条件replayしない。
- restart後もpending tail obligationを復元できる。
- Slack/Discord/Telegram/voice等で共通contractを通す。

### (7) 重要度

**A**

理由: Kamimusuhiの「発話した/届いた」を分ける不変条件を、さらにpartial deliveryの粒度まで降ろす直接的なfresh failure evidence。

## A — Dual-Frontier: world modelの予測を使う条件をdecision marginと誤差上界で切る

**Source**

- Zhu et al., *Dual-Frontier: When Can an Agent Trust Its World Model?*
- arXiv:2609.26293
- https://arxiv.org/abs/2609.26293

### (1) 何が実証済みか

論文は、world-model-guided decisionが失敗したとき、passive trajectoryだけでは「decision ruleが悪い」のか「world modelが悪い」のかを有限horizonでも一般に同定できないことをcounterfactual decompositionで形式化する。

Dual-Frontierは、world modelが予測するadvantageが**decision-relevant world-model errorのcertified bound**を上回るときだけそのdecisionをadmitし、そうでなければworld model verificationへevidence budgetを回す。action-conditioned value boundsとclosed-loop extensionで、admitted decisionについてnon-decreasing returnを保証する条件を示し、controlled learned-model experimentsとcross-backbone tool-use benchmarksでverify-then-promote ruleの改善を報告する。

### (2) 何が提案・推測段階か

- 実世界のKamimusuhiで誤差上界を常に計算可能とは限らない。
- social/person modelや高次意味推論のerror boundはrobot/world-stateより測りにくい。
- 理論保証は論文の仮定とcalibration条件に依存する。

### (3) Kamimusuhi 関連 subsystem

- K-Core / K-Deep planning
- world / body state prediction
- external model prediction
- Cognitive Budget / active sensing
- canonical evidence admission
- robotics / Semantic Commitment Closure

### (4) 借りられる設計・実装アイデア

`model confidence`をそのままauthorityにせず、**予測を使うことで得られるdecision margin**と、当該decisionに関係する予測誤差の上界を比較する。

```text
if predicted_advantage > decision_relevant_error_bound:
    allow model-guided action
else:
    acquire real evidence / probe world model
```

### (5) Kamimusuhiとの差分

Kamimusuhiの`generated cognition != fact`は質的な境界である。Dual-Frontierはそこへ、**いつderived predictionを実行判断へ使ってよいかの量的promotion gate**を追加できる。

### (6) 次に検証すべきこと

`WorldModelTrustFrontierBench-v0`

- simulatorでworld-model errorを既知化。
- action advantage marginを段階的に変える。
- prediction-only / always-verify / margin-vs-error gateを比較。
- tool-use、robot state、external API stateで別々に校正。
- false admission、verification cost、return、recovery costを測る。

### (7) 重要度

**A**

理由: canonical evidenceと予測の境界を「全面禁止/全面許可」でなく、decision relevanceに沿って定量化できる。

## A — Behavior is Not Enough: 協力行動の収束だけでは「規範」を同定できない

**Source**

- Muralidharan, Kwak, An, *Behavior is Not Enough: A Mechanism-Based Evaluation of Social Norm Emergence in LLM Societies*
- arXiv:2609.26481
- https://arxiv.org/abs/2609.26481

### (1) 何が実証済みか

同じcooperative outcomeでも、shared expectations、strategic incentives、imitationなど異なる機構から生じ得るという問題に対し、behaviorだけでなくagentsが報告する**empirical expectation / normative expectation**を測るframeworkを構築。

controlled ablationで expectation elicitation、interactionを通じたsocial learning、network-based group formationによるsocial selectionを分離し、4 LLM familiesでadversarial disruptionも評価。expectation elicitationはcontributionを増やし、social learningはbehaviorを安定させ、social selectionはcooperator識別には効くがbehavior reinforcementは限定的。disruption後にはnormative expectationとbehavioral coordinationが異なる回復を示した。

### (2) 何が提案・推測段階か

- LLMが「自分の期待」として報告する文章が、人間心理の内的状態と同じものだとは言えない。
- Kamimusuhiで持つPerson Model / Common Groundのbelief stateと、論文のelicited expectationが機構的に同一とは限らない。

### (3) Kamimusuhi 関連 subsystem

- Person Model / Relationship Memory
- Common Ground
- social cognition / ToM-like inference
- K-Deep multi-agent interaction
- social convention / long-horizon relationship state

### (4) 借りられる設計・実装アイデア

stable behaviorから直接`shared norm`を生成しない。少なくとも次を分ける。

- observed behavior
- predicted partner behavior
- empirical expectation: 他者は何をすると思うか
- normative expectation: 他者は何をすべきと思っていると推定するか
- incentive / enforcement condition

### (5) Kamimusuhiとの差分

KamimusuhiはPerson ModelとCommon Groundを持つが、反復された行動を「相手の価値観」「共有規範」へ昇格すると、**behavioral regularityとnormative stateを混同**する危険がある。

### (6) 次に検証すべきこと

`NormMechanismIdentifiabilityBench-v0`

- 表面上同じ協力率を、報酬・模倣・期待共有の3原因で生成。
- behaviorだけを見た条件とexpectation evidenceを見た条件を比較。
- disruption後にbehaviorとnormative expectationの回復を別測定。
- partner replacement時のnorm carry-overを監査する。

### (7) 重要度

**A**

理由: 長期social agentが「相手がいつもこうする」から「これは我々の規範だ」へ誤って飛躍するのを防ぐ直接的評価枠組み。

## A — AkasicMEM: derived memoryへsource authorizationを推移的に継承する

**Source**

- Bae et al., *AkasicMEM: Governed Enterprise Memory for Agents*
- arXiv:2609.25563
- https://arxiv.org/abs/2609.25563

### (1) 何が実証済みか

論文は、enterprise sourceの情報がmemoryへ入り、さらにmemory→memoryへ派生・再利用されると、principalやpolicyが変化する中で元sourceの制約が抜け落ち得る問題を定式化する。

AkasicMEMは以下でauthorization continuityを実装するarchitectureを提示する。

- transitive lineage
- memory formation時のpolicy composition
- retrieval時のpolicy re-evaluation

AkasicDBのvector–graph–relational substrate上でこれらを統合する設計を示す。

### (2) 何が提案・推測段階か

公開abstractからは、大規模adversarial leakage benchmarkや定量性能比較まで確認できない。したがって「authorization continuityを完全に解決した」とは扱わない。

### (3) Kamimusuhi 関連 subsystem

- canonical evidence / derived memory
- Relationship / Episodic / Library Memory
- provenance / authority
- Memory Router
- external-resource ingestion
- shared / distributed memory

### (4) 借りられる設計・実装アイデア

provenance linkに加えて、derived memoryが**source policy ceiling**を継承する。

```text

  policy P0
    -> summary M1 policy = compose(P0, local_rule)

```

retrieval時にはcurrent principal / purpose / contextに対し全lineageのpolicyを再評価する。source revoke後にderived summaryだけ残って漏れることを防ぐ。

### (5) Kamimusuhiとの差分

Kamimusuhiはcanonical evidenceとderived projectionを分け、provenanceを重視するが、**provenanceが残っていることと、そのsource policyが子孫へ実効的に継承されることは別**。この差分を明示的に埋められる。

- stale derived viewからのretrieval leakageを測る。
- policy compositionが過剰制限を作るfalse denialも測る。
- source deletionとderived projection invalidationを別々に検証。

### (7) 重要度

**A**

理由: 永続memoryを中心に据えるKamimusuhiで、長期派生によるauthority launderingを防ぐ根本原則になり得る。

## A — CausalLoss-Fin: infrastructureを原因変数に入れないfailure analysisは必ずagentを誤責任化する

**Source**

- Sharma, *CausalLoss-Fin: Attributing Financial-Agent Loss to Decisions and Infrastructure Faults*
- arXiv:2609.25960
- https://arxiv.org/abs/2609.25960

### (1) 何が実証済みか

explicit/replayableなinfrastructure fault processを持つbenchmarkで、agent decisionだけへinterventionするbaselineは、そもそもmodel内にinfrastructure fault変数が存在しないため、構造的にinfrastructure原因を名指しできない。

545 planted episodes × 3 deterministic policiesでは、agent-only baselineが**infrastructure episodesの100%を誤分類**し、$114,383.40をagentへ帰属。baselineが名指したagent側をrepairしてもrecoverable lossの0.0%しか回復せず、minimal sufficient infrastructure setをrepairすると100.0%回復。27.8%のepisodeはmessageごとの単純加算に分解できなかった。

### (2) 何が提案・推測段階か

- deterministic programmatic policiesとsynthetic generatorなので、field failure rateやstochastic LLM agentsへ prevalence を一般化できない。
- 金融損失そのものはKamimusuhiの主用途ではない。

### (3) Kamimusuhi 関連 subsystem

- self-improvement / failure learning
- Cognitive Action Router
- tool/network effects
- health / liveness / environment model
- Mutation candidate generation
- external effect receipts

### (4) 借りられる設計・実装アイデア

failure recordへ「agent action」だけでなく、**infrastructure/environment intervention variables**をfirst-classに残す。

例:

- request accepted?
- transport delivered?
- settlement message dropped?
- credential expired?
- provider route changed?
- actuator acknowledged?

自己改善系はcause attributionが閉じるまで「agent policyを直す」をdefaultにしない。

### (5) Kamimusuhiとの差分

Kamimusuhiはfailure provenanceやeffect receiptを重視するが、self-improvement loopがepisode traceだけを見ると、trace内に存在するagent decisionへ原因を吸い込む危険は残る。

### (6) 次に検証すべきこと

`DecisionVsInfrastructureFaultAttributionBench-v0`

- 同じvisible failureをpolicy bug / dropped tool result / stale credential / delayed actuator ackで生成。
- agent-only attributionとjoint causal attributionを比較。
- 誤ったself-mutation proposal率を測る。
- repair targetを実際に介入し、recovery rateでattributionを検証する。

### (7) 重要度

**A**

理由: 「失敗したから自己を修正する」長期AIにとって、誤った原因帰属は自己破壊的なmutationを生むため。

## B — FIRE: 「一度できる」と「繰り返し届けられる」を分けるruntime policy評価

**Source**: arXiv:2609.26048 — https://arxiv.org/abs/2609.26048

### (1) 実証済み

87-task Terminal-Bench 2.1で、failure直前stateへtargeted natural-language policy / action denialを差し込むruntime policyを評価。weights・user promptは固定。2 attempts/taskでrepeated success `pass^2`がLuna 50.6→54.0%、Terra 55.2→60.9%、Sol 64.4→73.6%。Solのbest-of-twoは+1.2ptだけで、主効果はreachabilityよりrepeatabilityに出た。randomized five-armでもreal policy 61%に対しno policy 39%、sham 36%。

### (2) 提案・推測

coding benchmark上のruntime policiesがKamimusuhiの全taskへ一般化するとは限らない。policy accumulationの長期干渉も別問題。

### (3) 関連 subsystem

K-Core harness / procedural memory / failure-derived guardrail / self-improvement evaluation。

### (4) 借りられる設計

能力評価を`best-of-N`だけにせず、**same condition repeated delivery**を別metric化する。

### (5) 差分

既収載Self-Healing Harness等はpolicy admission/regressionを扱う。FIREの新規性は「能力上限を変えず、既に可能なことの再現率だけを上げた」ことを測定上分離した点。

### (6) 次に検証

## B — MemoryAthena: generated memoryは直接retrievalを置換せず、bounded interventionとしてgateする

**Source**: arXiv:2609.25853 — https://arxiv.org/abs/2609.25853

### (1) 実証済み

Direct Engram retrieval `E`、retrieved cuesから生成する`GE`、backbone causal stateから生成する`GH`の3経路を比較し、generated memoryは入力ごとにhelp/harmが変わることを確認。frozen backbone/memory/generators/readers上で軽量routing headを学習し、accepted candidateだけE residualへbounded interpolation、reject時はE経路へexact fallback。QA平均37.65→39.28、general NLP 76.73→79.13を報告。

### (2) 提案・推測

これはLLM internal/learned-memory mechanismであり、Kamimusuhiのdurable autobiographical memory correctnessを直接証明しない。

### (3) 関連 subsystem

Memory Router / derived projection / K-Core inference / generated hypothesis。

### (4) 借りられる設計

生成memory/hypothesisをcanonical memoryへ書かず、direct evidence retrievalをanchorとして**bounded correction**だけ許す。reject時にexact evidence-only routeへ戻せる構造を持つ。

### (5) 差分

Kamimusuhiはdurable canonical evidenceをより強く分離するため、GE/GH相当はpersistent memoryではなくdisposable cognitive projectionとして扱うべき。

### (6) 次に検証

`GeneratedMemoryInterventionGateBench-v0`: evidence-only vs generated correction、hallucination injection、exact fallback、calibration、long-context retrievalで比較。

### (7) 重要度

## B — DexTacWAM: tactileを「追加特徴」ではなく予測world stateへ組み込む

**Source**

- arXiv:2609.24976 — https://arxiv.org/abs/2609.24976

### (1) 実証済み

22-DoF bimanual platformの6 contact-rich tasksで、各fingertipを別encoderし、finger/pose-aware compressorを通したtactile latentをvideo diffusion world modelへ入れる。平均70.6 vs strongest baseline 38.0。tactile world modelingを外し、同じtactile features/action expertを残すablationでは4-task mean 74.7→26.6。compressorはcontact recall 89.4%を保ちながらtraining 2.26×、inference 1.29×高速化。

### (2) 提案・推測

single platform・特定task群での結果。cross-sensor / cross-embodiment / long-term adaptationは未証明。

### (3) 関連 subsystem

K-Nerve / K-Edge / multimodal world state / tactile sensing / Physical AI。

### (4) 借りられる設計

touchをpolicyへの補助inputだけにせず、**contact evolution自体を予測対象**にし、そのpredictive stateをaction decisionへ渡す。

### (5) 差分

KamimusuhiのK-Nerveはfast sensor/event layer。DexTacWAMの重いworld modelはK-Nerveそのものではなく、K-Edge/Coreのpredictive body-state organとして位置付ける方が自然。

### (6) 次に検証

`PredictiveMultimodalContactStateBench-v0`: tactile-direct conditioning vs tactile predictive state、slip/regrasp failure、latency、VRAM、commitment detection精度を比較。

## B — TriWorldBench: 各viewがもっともらしくても「同じ世界」を描いているとは限らない

**Source**

- arXiv:2609.26314 — https://arxiv.org/abs/2609.26314
- official repo — https://github.com/TriWorldBench/TriWorldBench

### (1) 実証済み

### (4) 借りられる設計

sensorごとのaccuracyだけでなく、**同時刻の複数projectionが同一canonical world eventを説明しているか**をcross-view invariantとして検査する。

### (5) 差分

Kamimusuhiはevent vs interpretationを分けるが、複数sensor-derived interpretationの相互整合性を独立benchにする余地がある。

# 8. 既存docsへの追記候補

以下は**候補**であり、このsurveyから自動でnormative specへ昇格させない。

## `architecture.md` 候補

1. **Multipart Delivery Ledger**
   - utterance deliveryをbooleanでなくpayload coverage + chunk receiptで管理。
   - partial successをwhole successへ昇格しない。

2. **Delegated Completion Settlement Owner**
   - worker execution lifecycleとresult-to-owner settlement lifecycleを分離。
   - requester body/runtimeが消えてもcompletion obligationをdurableに保持。

3. **World-Model Trust Frontier**
   - model-derived predictionをactionへ使う前にdecision margin vs decision-relevant errorを比較。

4. **Derived-Memory Authorization Continuity**
   - provenance graphにsource policy ceilingを添付し、派生時compose・retrieval時re-evaluate。

5. **Failure Attribution Graph**
   - agent actionだけでなくnetwork/provider/credential/actuator等をintervenable causeとしてepisodeへ保存。

## `spec.md` 候補

既存invariantの強化候補:

- `transport success != complete delivery`; `DELIVERED`にはcanonical payload全体を覆うreceiptが必要。
- `subtask execution terminal != completion obligation terminal`。
- `provenance retained != source authorization retained`; derived artifactはsource policy ceilingを超えない。
- `behavioral convergence != shared norm`; norm beliefにはexpectation evidenceを要求する。
- `failure observed at agent boundary != agent-caused failure`; infrastructure causesを未観測のままself-mutationへ進まない。
