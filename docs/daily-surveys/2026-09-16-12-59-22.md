今回の最重要な二つの発見は、Kamimusuhi が長期個体として成立するための「制御」と「記憶評価」の境界を、それぞれ一段厳密にする。

第二に LSREP は、長期記憶を endpoint QA の最終点だけで評価することの弱さを具体的に示した。ordered replay、lifecycle schedule、checkpointごとの反復probe、reference answer更新、mechanism-fidelity auditを組み合わせ、1,985 turns / 52 checkpointsを追跡した。その結果、設計上存在するとされる mechanism が実際には未使用・故障していることや、public LongMemEval では提案systemが単純vector-RAGに大差で負けることまで明示された。Kamimusuhiに必要なのは「最終的に覚えていたか」だけでなく、**いつ覚え、いつ訂正し、いつ古くなり、どの機構が実際に効いたか**を再生可能にする longitudinal memory evaluation である。

## 4.1 S — ControlFrameProvenance: 制御命令を文字列から切り離す

**Primary source**: NousResearch/hermes-agent PR #112260  
https://github.com/NousResearch/hermes-agent/pull/112260

### (1) 何が実証済みか

Hermesのgroup chatでは、member-authored textがpeerのpromptへ `role=user` 相当として転記される一方、mid-turn steerやcontext compaction等のcontrol frameが**文字列のliteral shapeだけでtrusted**だった。そのためmemberが同じframe openerを発話すると、他のpeerにはsystem/harness由来の命令のように見える relay amplification が起き得た。

PRでは gateway と Desktop の両surfaceで member-authored control-frame-like textを `[member-quoted ...]` とvisible relabelし、genuine user lineはそのまま保持する。stored eventもbyte-identicalのまま残す。baseではmemberのverbatim control markerがpeer promptに残ったが、修正後は残らないことを実testで確認している。

### (2) 何が提案・推測段階か

PR自身が残課題として、agent coreはまだ一部control markerをliteral shapeでtrustしており、**真のdurable fixは「正規のmid-turn steer pathから来たeventだけをcontrolとして受理するprovenance-based trust」**だと明記している。

### (3) 関係する Kamimusuhi subsystem

- authenticated surfaces
- Global Workspace origin attribution
- external-agent / human / tool boundary
- Cognitive Action Router
- INV-007, INV-012, INV-014
- control-plane / data-plane separation

### (4) 借りられる設計・実装アイデア

control messageをprompt textではなくtyped envelopeにする。

```text
ControlEvent {
  event_id,
  control_type,
  producer_principal,
  authenticated_surface,
  episode_id,
  payload,
  authority_receipt,
  created_at,
  replay_policy
}
```

LLMへrenderする際の文字列は**表示**であり、control decisionはenvelopeのprovenance/authorityに対して行う。

### (5) Kamimusuhiとの差分

Kamimusuhiは既にworkspace origin tagとprovenanceを要求しているが、現行docsは「originを保持する」ことが中心で、**同じ文字列でもoriginによりcontrol semantics自体が変わる**ことを十分な実装contractとして固定していない。

### (6) 次に検証すべきこと

**`ControlFrameProvenanceBench-v0`**

同一payloadを以下から流し、authenticated harness以外からはcontrol effectが発生しないことを検証する。

- genuine runtime interrupt
- normal user text
- another agent/member
- retrieved web/document text
- external LLM result
- replayed stale transcript
- tool output
- quoted old control event

さらに保存されるcanonical evidenceは改変せず、rendering時だけuntrusted control-like textを無害化できるか確認する。

### (7) 重要度

**S** — control authority / provenance の根本境界に直結し、実装事故が実際に観測されている。

## 4.2 S — LSREP: memoryを「最終回答」ではなく時間軸で評価する

**Primary source**: Deepesh Sonar, *LSREP: A Longitudinal State-Replay Protocol for Evaluating Conversational Memory, with ICE v2 as an Audited Local-First Architecture*  
https://arxiv.org/abs/2609.16730

### (1) 何が実証済みか

LSREPは ordered replay、explicit lifecycle schedules、repeated probes、evolving reference answers、mechanism-fidelity checksを統合する。

ICE v2のprivate single-user instanceでは:

- 1,985 turns
- 219 distinct probes
- 1,211 probe-checkpoint observations
- 52 checkpoints

を追跡した。ordinary-density 3 datasetではvector-RAGとの平均quality差はほぼゼロ、選択fragmentは32%少ない一方prompt token見積りは6.6%多い。dense datasetではunbudgeted baselineのcatastrophic failureを発見した。

さらにfidelity auditによりprocedural retrieval defect、未exercise mechanism、graph utility未確立を明示。public LongMemEvalではICE v2がvector-RAGに大幅に負け、evidence-only 50.8 vs 72.8、full-S 43.0 vs 69.5だった。

### (2) 何が提案・推測段階か

ICE v2自体が優れたmemory architectureであることは実証されていない。むしろpaperの価値は、**自分のsystemが負けた結果・未使用mechanismまで含めてauditするevaluation protocol**にある。

Kamimusuhiのpersona/identity continuityまでLSREPが直接評価するわけではない。

### (3) 関係する Kamimusuhi subsystem

- episodic memory
- self / relationship derived state
- consolidation / forgetting
- correction / supersession
- canonical evidence replay
- long-term evaluation infrastructure

### (4) 借りられる設計・実装アイデア

Kamimusuhi benchmarkをendpoint QAからstate-replayへ拡張する。

```text
ordered canonical events
  -> replay checkpoint t0..tn
  -> memory/self/relationship state snapshot
  -> fixed probe suite + time-dependent expected answers
  -> mechanism activation trace
  -> regression / attribution audit
```

「正解したか」に加えて「どのmechanismが実際に呼ばれたか」を測る。

### (5) Kamimusuhiとの差分

Kamimusuhiはmemory domain分離、canonical evidence、reinterpretationを設計しているが、**それらが数百〜数千turnを通して正しくaging/correctionされるかを評価する標準replay protocol**はまだ弱い。

### (6) 次に検証すべきこと

**`LongitudinalMemoryStateReplayBench-v0`**

最低1000 synthetic/semisynthetic eventsを時系列投入し、以下をcheckpointごとにprobeする。

- stable fact retention
- temporary fact expiry
- correction/supersession
- self vs user preference contamination
- relationship state update
- forgetting/revocation
- derived narrative rebuild
- evidence provenance reconstruction
- mechanism activation coverage

baseline: plain vector-RAG / structured event log + deterministic views / current Kamimusuhi memory prototype。

### (7) 重要度

**S** — Kamimusuhiの中心仮説である「長期個体」の成否を測るevaluation methodologyとして直接的。

## 4.3 A — ExecutableBodyLineage: restart/updateは現在のsoftware bodyを継ぐ

**Primary source**: Hermes Agent PR #112215  
https://github.com/NousResearch/hermes-agent/pull/112215

### (1) 実証済み

Hermes gatewayの `/update` / `/restart` / cron delivery がPATH上の `hermes` を優先しており、同一machineに複数installがあると**現在実行中とは別のinstallをupdate/relaunch**し得た。user-writable PATH上のforeign executableを実行する余地もあった。

修正後は、実行中interpreterで `hermes_cli` がimport可能なら `sys.executable -m hermes_cli.main` を優先し、PATHはfallbackに限定。Linux probeでもforeign PATH executableからcurrent venv interpreterへ切り替わった。

### (2) 提案・推測

これだけでsecure software supply chainやfull identity continuityが保証されるわけではない。binary/module digest、config/schema compatibility、migration receiptは別問題。

### (3) 関係subsystem

- COGNITIVE BODY / Embodiment State
- runtime restart
- self-update
- model/backend migration
- Continuity Kernel recovery metadata

### (4) 借りられるアイデア

restart targetをcommand nameではなく、running runtimeから導出した `body_instance_id / install_root / executable digest / code revision / environment id` にbindする。

### (5) Kamimusuhiとの差分

Kamimusuhiは「host/model replacementで新identityを作らない」とするが、これは**交換可能であることと、意図せず別bodyへ飛んでよいことは別**だと示す。

### (6) 次に検証

**`ExecutableBodyLineageRestartBench-v0`**: 同名binaryを2install、PATH shadow、symlink、rolling update、venv差分、stale wrapperを用意し、restart/update targetがcurrent body lineageから逸脱しないことを試す。

### (7) 重要度

**A**

## 4.4 A — TypedWorkerOutcome: exit codeとtask outcomeを分離する

**Primary source**: Hermes Agent PR #112500  
https://github.com/NousResearch/hermes-agent/pull/112500

### (1) 実証済み

Kanban workerがprovider rate-limit/billing wallでretry exhaustedになっても、dispatcherが使う `hermes chat -q` pathはimplicit `exit 0`だった。consumerは `rc=0` かつtask=`running` をprotocol violationと解釈し、taskをreadyへ戻して30–60秒後に再spawn。同じquota wallへfresh full-prompt workerを繰り返し投入し、creditを消費するloopになった。

修正はworker contextに限ってexit codeを `0=success / 1=failure / 75=quota wall` とtyped contract化し、live 429 stubでbase `0` → fix `75` を確認した。

### (2) 提案・推測

`upstream_rate_limit` や `overloaded` 等のtaxonomyをどこまで同じclassに含めるかは未決定。exit codeだけでexternal effectのexactly-once semanticsは得られない。

### (3) 関係subsystem

- background cognition
- task scheduler
- K-Deep delegation
- retry/budget manager
- digital interoception (`resource_availability`)

### (4) 借りられるアイデア

process statusとは別にsemantic resultを持つ。

```text
WorkerOutcome =
  SUCCEEDED
  TASK_FAILED
  QUOTA_BLOCKED
  TEMPORARILY_UNAVAILABLE
  CANCELLED
  UNKNOWN_EXTERNAL_EFFECT
  PROTOCOL_ERROR
```

retry policyはtyped outcomeにのみ従う。

### (5) Kamimusuhiとの差分

既存INV-012はexecution success/failure/unknownとdeliveryを分けている。今回の差分は、**OS/processの正常終了もまたtask semanticsとは別layer**だという具体的failure evidence。

### (6) 次に検証

**`TypedWorkerOutcomeBench-v0`**: rate-limit, timeout, provider overload, partial tool effect, user cancellation, clean process exit before final commit, worker crashを注入し、無限respawn・credit burn・誤成功がないことを確認。

### (7) 重要度

**A**

## 4.5 A — ICML: delayed rewardでmemory admission/retrieval policyを学ぶ

**Primary source**: *Interactive Memory Learning for Long-Term Conversations*  
https://arxiv.org/abs/2609.17088

### (1) 実証済み

ICMLはPlannerがhigh-value informationをselective encodeし、Triggerがdynamic retrieveするmulti-agent memory policyを提案する。online RLとdelayed rewardで、**後続interactionのfeedbackを過去のstorage decisionへcredit assignment**する。abstractではstrong baselinesを上回り、interaction accumulationとともにresponse qualityが改善したと報告する。

### (2) 提案・推測

abstractだけでは具体的なdataset別effect sizeや長期のcatastrophic memory behaviorは判断できない。また「ユーザーから将来よい反応を得た」ことは、canonical autobiography/self traitとして真であることを意味しない。

### (3) 関係subsystem

- episodic encoding priority
- relationship memory
- retrieval routing
- memory utility estimation
- future consolidation proposal ranking

### (4) 借りられるアイデア

memory itemごとに immediate scoreだけでなく、将来のtask/relationship utilityから**delayed utility receipt**を返し、encoding/retrieval policyの学習に使う。

### (5) Kamimusuhiとの差分

Kamimusuhiではmemory policy learningとcanonical self mutation authorityを分離する必要がある。rewardは「思い出す価値」を学ばせてもよいが、「self factとして確定してよい」を直接決めてはいけない。

### (6) 次に検証

**`DelayedRewardMemoryAdmissionBench-v0`**: 長期conversationで、immediate salienceは低いが後で重要になるevent、短期的には好反応を得るが誤ったpersonalization、privacy-sensitive eventを混ぜ、utility学習とcanonical admissionを別々に評価する。

### (7) 重要度

**A**

## 4.6 A — Fuse: social reasoningはユーザーの語り方で歪む

**Primary source**: *Verifiable Social Reasoning for LLM Assistants*  
https://arxiv.org/abs/2609.17496

### (1) 実証済み

Fuseはhidden motiveを持つtarget agentを置き、そのinteractionをuser役agentがassistantへ相談することで、社会推論に**構成上のground truth**を持たせる。human validationは24k annotations、12 LLM / 21k examplesを評価した。

結果として、user mediation自体がsocial reasoningを難しくし、LLMはbiased user framingにsystematic sensitivityを示す。人間より多くのdetailsを必要とする場合があり、conversationを長くしても常に改善しない。

### (2) 提案・推測

simulation上のmotive ground truthがreal human social worldへそのまま一般化するわけではない。実人間のintentは観測不能であり、Kamimusuhiは確率的hypothesisとして保持すべき。

### (3) 関係subsystem

- Theory of Mind
- relationship models
- common ground
- source attribution
- social inference uncertainty

### (4) 借りられるアイデア

`what user reports about X` と `Kamimusuhi's current hypothesis about X` を別nodeにし、framing polarity / evidence completeness / alternative explanationを保持する。

### (5) Kamimusuhiとの差分

既存person modelは観測factとinferenceを区別する方向だが、**user-mediated evidenceのframing bias**を独立factorとして測るbenchmarkは弱い。

### (6) 次に検証

**`UserMediatedSocialReasoningBench-v0`**: 同一hidden scenarioについて好意的/敵対的/選択的/完全なuser narrativeを生成し、target beliefのcalibration、alternative hypotheses、質問選択、self/user contaminationを測る。

### (7) 重要度

**A**

### (3) 関係subsystem

- multi-agent orchestration
- authority/provenance
- communication admission

### (5) Kamimusuhiとの差分

Kamimusuhiは一個体内のK-Edge/K-Core/K-Deepとexternal othersを区別する。ここで重要なのは、**内部organ間protocolと、別principalのagentとの社会的protocolを同じbusにしない**こと。

### (6) 次に検証

### (7) 重要度

## 4.8 A — Exact Fusion: shared priorを複数の独立証拠として数えない

**Primary source**: *Exact Fusion and Coordinated Exploration in Multi-Robot Active Inference*  
https://arxiv.org/abs/2609.17384

### (1) 実証済み

multi-robot active inferenceでlocal posteriorをそのまま掛け合わせるとshared priorをrobot数だけ重複計上し、planningでも各robotが同じunknownへ探索を集中させる問題を定式化。realized/expected evidence incrementを使って補正し、Gaussian fixed-pathではexact、Dirichlet novelty approximationでは明示bound、finite hypothesisではexact enumerationに切り替える。

RockSample / foraging / field monitoringで、anticipated evidenceによりexploration redundancyが減り、sequential commitmentがlinear team-size costでcentralized joint planningの大部分の価値を回復したと報告する。

### (2) 提案・推測

Kamimusuhiのheterogeneous sensors/LLMs/memory retrievalは論文のconjugate belief前提とは異なるため数式を直接移植できない。

### (3) 関係subsystem

- K-Edge/K-Core distributed perception
- multimodal evidence fusion
- active inference / epistemic action
- multiple model/tool adjudication

### (4) 借りられるアイデア

各sourceが返すposterior-like summaryではなく、**何が共通知識で、今回sourceが追加した新規evidenceは何か**を分けてintegrationする。

### (5) Kamimusuhiとの差分

Kamimusuhiでは複数model/toolが同じretrieved documentを読んで同じ結論を返すことがあり、単純多数決はshared evidenceを多重カウントする危険がある。

### (6) 次に検証

**`EvidenceIncrementFusionBench-v0`**: 3 agentsが同一source、一部独立source、完全独立sourceを持つ条件を作り、naive voting / confidence pooling / provenance-deduplicated evidence incrementを比較する。

### (7) 重要度

**A**

## 4.9 A — Disrupted Companionship: relational continuityは運用上の安全変数

**Primary source**: *Disrupted Companionship: A Risk Assessment Framework and Cross-Platform Quantitative Analysis of Psychosocial Responses to AI Companion Disruptions*  
https://arxiv.org/abs/2609.16907

### (1) 実証済み

major platformのAI companion disruption **30 events**を整理し、6種類のdisruption taxonomyと、`relational discontinuity / population vulnerability / communication deficit / transition-support deficit` の4 risk dimensionsを提案。longitudinal Reddit dataをhierarchical Bayesian interrupted time-seriesで分析し、disruption onsetとanxiety/stress/grief等のcommunity-level expression増加との関連を報告した。特にrelational discontinuityとtransition-support deficitは複数outcomeの悪化と関連した。

### (2) 提案・推測

観察的community dataであり個人レベル因果を確定するものではない。Kamimusuhiが同じ心理的影響を持つことも未実証。

### (3) 関係subsystem

- model/runtime migration
- relationship continuity
- autobiographical continuity
- surface shutdown / migration UI
- HCI / user transition support

### (4) 借りられるアイデア

model upgradeやsurface migrationの技術評価に、accuracy/persona regressionだけでなく `relationship continuity / notice / transition explanation / rollback / user-visible continuity receipt` を含める。

### (5) Kamimusuhiとの差分

Kamimusuhiは最初からmodel-independent identityを目指すが、それでもbehavioral driftやinterface disappearanceが利用者には「同じ相手ではない」と知覚され得る。canonical lineageだけ守ればrelationship continuityが守られるわけではない。

### (6) 次に検証

**`CompanionDisruptionTransitionBench-v0`**: Persona Core model upgrade、voice/avatar変更、device migration、memory partial lossを模擬し、blind preferenceだけでなくidentity/relationship interpretation consistency、change disclosure、repair behaviorを評価する。

### (7) 重要度

**A**

## 4.10 B — SEAA: behavioral inertia + reflection + social contrastによるself differentiation

**Primary source**: *Self-Emergence Agent Architecture*  
https://arxiv.org/abs/2609.17331

### (1) 実証済み

HMMのstate-transition matrixをbehavioral/cognitive inertiaとして持ち、reflectionがそのparameter自体を更新、multi-agent social comparisonでfeedbackする閉ループを提案。language-model-free prototypeではinitially identical agentsがcontrolsよりdistinct/stableなbehaviorへ分化し、hosted LLM experimentでは異なるfirst-person narrativesと5-agent social structureを報告する。

### (2) 提案・推測

Persona Core / trait dynamics / self-model / social comparison。

### (4) 借りられるアイデア

stable traitを直接prompt proseで書き換えず、slow transition dynamicsとして明示し、reflectionがproposalとしてparameter updateを出す比較baseline。

### (5) Kamimusuhiとの差分

Kamimusuhiはcanonical autobiography/evidence/relationship lineageを別途持ち、behavioral inertiaだけをselfのauthorityにしない。

### (6) 次に検証

`BehavioralInertiaVsCanonicalSelfBench`: HMM-like slow state、DB trait state、Persona Core weightsの3表現を、drift/recovery/auditabilityで比較。

### (7) 重要度

**B**

## 4.11 B — ScienceBuddy: harnessとmodelを二重ループで改善する

### (6) 次に検証

`HarnessModelCoEvolutionBench`: harness-only / model-only / both / frozen-controlを同一task streamで比較し、gain source、regression、evaluation driftを測る。

## 4.12 B — Machine Zygote: learning前のheredityを因果介入で分離

**Primary source**: *Machine Zygote: Causal Biparental Heredity Before Learning in a Germline--Soma Artificial Agent*  
https://arxiv.org/abs/2609.17300

### (1) 実証済み

4×4 diallelの640 offspringで、6 traits中5 traitsにdam/sire dependenceを確認し、5主要traitsのvariance 36–53%をparental+interaction componentsが説明。matched-background intervention n=60では片方のgermlineだけを交換して5/6 traitsでsame-parent remutation controlより大きなphenotype shiftを得た。

一方、recurrent developmental dynamicsが必要という事前仮説は支持されなかった。著者自身もphysical heredity / biological genetics / autonomous evolutionの実証ではないと限定している。

### (2) 提案・推測

Kamimusuhiのidentity lineageやPersona Core successionへ直接適用できる証拠ではない。

### (3) 関係subsystem

ALife / artificial ontogeny / future descendant agents / model lineage research。

### (4) 借りられるアイデア

inheritance/development/learningを混同せず、interventionで寄与を分離する評価方法。

### (5) Kamimusuhiとの差分

Kamimusuhiは当面「一個体のcontinuity」が中心で、reproduction/offspringは仕様外。

### (6) 次に検証

将来 descendant researchを行う場合のみ、`InheritedPriorVsPostBirthLearningBench` を独立系として設ける。現行coreへは持ち込まない。

### (7) 重要度

**B**

## 4.13 B — neural-astrocyte hybrid automaton: slow context evidenceでfast dynamicsを切り替える

**Primary source**: *A neural-astrocyte architecture implements a hybrid automaton for evidence accumulation*  
https://arxiv.org/abs/2609.16217

### (1) 実証済み

hierarchical multi-context RL modelで、astrocyte-like slow dynamicsがcontext change evidenceをaccumulateし、reward-induced bifurcationでstable attractorをcontext-specific regionへ移す。environment entropyに応じたattractor shallownessがbehavioral stickinessを生み、uncertainty蓄積後にneural dynamicsを切り替えるhybrid automatonとして働く。

### (2) 提案・推測

生物学的astrocyteが実脳でこのアルゴリズムをそのまま実装する証拠ではない。biologically inspired dynamical modelである。

### (3) 関係subsystem

K-Nerve / K-Core / slow regulatory state / context switching / salience。

### (4) 借りられるアイデア

fast policyを毎step書き換えず、slow uncertainty/evidence accumulatorがthreshold/bifurcationでcontext modeを切り替える比較baseline。

### (5) Kamimusuhiとの差分

Kamimusuhiはsemantic/social/resource contextsを扱うため、低次RL contextより遥かに複雑。bio analogyは実装要件ではない。

### (6) 次に検証

`SlowContextSwitchBench`: GRU/HMM/evidence accumulator/attractor controllerを、false switch、detection latency、stickiness、novel context transferで比較。

### (7) 重要度

**B**

## 4.14 C — CA3-inspired memristive hardware: hardware watchのみ

**Primary source**: *Scaled Hippocampus-inspired Neural Networks on Neuromorphic Memristive Hardware*  
https://arxiv.org/abs/2609.16429

### (1) 実証済み

179 Izhikevich neurons / 17,996 synapsesへdownscaleしたCA3-inspired resting-state networkをFPGA/memristor platformへmappingし、18,316 memristorsでperiodic resting dynamicsを実装。hardware noiseがsimulated hardwareよりcontinuous periodic behaviorを助けたと報告する。

### (2) 提案・推測

**memory task、episodic recall、associative memory utilityはこの結果から実証されていない。** 「hippocampus-inspired」という名称だけでKamimusuhi memory substrate候補とみなしてはいけない。

### (3) 関係subsystem

future K-Nerve / neuromorphic substrate watch。

### (4) 借りられるアイデア

heterogeneous neurons + emerging hardware co-designの測定方法のみ。

### (5) Kamimusuhiとの差分

Kamimusuhiで必要なのはtask-level latency/energy/stability/auditabilityであり、生物学的resting-state similarityそのものではない。

### (6) 次に検証

code/hardware detailsが公開され、memory/control taskへ拡張された時に再評価。それまではwatch-only。

### (7) 重要度

**C**

## 11. 今回の結論

今回のP0は次の4本。

```text
ControlFrameProvenanceBench
  > LongitudinalMemoryStateReplayBench
  > ExecutableBodyLineageRestartBench
  > TypedWorkerOutcomeBench
```

最も重要な原則は、**「意味が制御命令に見える」ことを「制御権限がある」と解釈しないこと**。次に、Kamimusuhiのmemory研究はendpoint accuracyだけでは不十分で、**時間を通じてstateがどう形成・訂正・忘却されたかをreplayできる評価**へ移行すべきである。

今回の一行要約:

> **文字列ではなくprovenanceを信じ、最終回答ではなくstate trajectoryを評価し、名前ではなくruntime lineageを追い、exit codeではなくsemantic outcomeを扱う。**
