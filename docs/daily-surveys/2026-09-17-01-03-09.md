# 分野別項目

## 1. A — Owner scope sentinel: `None` を process-wide wildcard にしない

**一次資料**

- Hermes Agent PR #112885 — *Launch profile pruning an MCP server no longer tears down served profiles' same-named connections*  
  merged 2026-09-17 00:45 JST  
  https://github.com/NousResearch/hermes-agent/pull/112885

### (1) 何が実証済みか

Hermesのmulti-profile backendで、launch profileがMCP server `x` を削除/無効化した際、`shutdown_mcp_servers(scope=None, names={'x'})` の `scope=None` が「unscoped owner」ではなく「全owner」と解釈されていた。そのため別profile Bが所有する同名 `(B, "x")` connectionまでshutdownされ、Bのtoolも消えた。

修正後は、**scopeもnamesも指定しない完全なbare callだけ**がprocess-wide shutdownで、`scope=None` + 明示namesはunscoped ownerだけを対象にする。PRではorigin/mainで別owner connectionが消える再現、修正後177 tests、mutation test、live probeまで報告されている。

### (2) 何が提案・推測段階か

Hermes固有のPython APIをKamimusuhiへそのまま移植する必要はない。一般化した提案は、**nullable scopeをowner selectorとwildcardの二役に使わない**こと。

特に、multi-principal cognitive bodyでは `None`, empty string, missing field, default profile のような値が「全体」を暗黙に意味すると、単一profile時には見えないcross-principal teardownを生む。

### (3) Kamimusuhiのどのサブシステムに関係するか

- Cognitive Action Router / tool registry
- MCP / plugin / skill lifecycle
- K-Core上のmulti-principal / multi-organ runtime
- distributed embodiment
- `INV-006` 分散実行と偶発的複製/越境防止
- `INV-013` present stateは実ownerから導出
- `INV-014` authority/provenance/liveness境界の明示

### (4) 借りられる設計・実装アイデア

scopeを値の慣習ではなく型で分ける。

```text
OwnerScope =
  Principal(owner_id)
  | UnscopedLocal
  | ProcessWide(explicit_capability)
```

原則:

- wildcard操作は明示型/明示capabilityでしか生成できない
- `null` / missing / parse failure はwildcardへ昇格しない
- resource keyは少なくとも `(owner, logical_name, generation)` を含む
- shutdown/prune/reloadは対象ownerをaudit logへ必ず残す

### (5) Kamimusuhiとの差分

Kamimusuhiはすでにprincipal/provenanceを重視しているが、これは**原則を持っていてもAPI sentinel semanticsで破れる**具体例。`INV-013/014` を満たすには、データモデルだけでなく関数引数・default値までowner-safeである必要がある。

### (6) 次に検証すべきこと

**`OwnerScopeSentinelBench-v0`**

- principal A/Bが同名tool `x` を別connectionで所有
- A側で remove / disable / reload / shutdown
- `null`, missing, `""`, default, stale owner, explicit wildcardを網羅
- Aの操作でBのconnection/tool/capability receiptが変化しないこと
- process-wide操作だけがA/B両方へ作用し、明示的な高いauthorityを要求すること
- crash/restart後にもscope解釈が変わらないこと

### (7) 重要度

**A** — distributed cognitive bodyでtool/organ ownershipを守る実装境界として直接的。新しいnormative invariantを増やすより `INV-006/013/014` のconformance testへ落とす価値が高い。

## 2. A — Aggregated view owner provenance: 統合表示はmutation addressではない

### (2) 何が提案・推測段階か

KamimusuhiのGlobal Workspace、memory search result、multi-device dashboardでも同じ問題が起こると予想するが、Kamimusuhi実装での再現は未実証。

### (3) Kamimusuhiのどのサブシステムに関係するか

- Global Workspace
- multi-surface / multi-device UI
- memory/resource aggregation
- derived views
- Continuity Kernel周辺のoperator tooling
- `INV-011` canonical evidence > derived view
- `INV-013/014`

### (4) 借りられる設計・実装アイデア

aggregate row / workspace contribution / search resultへ最低限:

```text
object_id
owner_principal_id
source_namespace
source_revision
projection_id
read_timestamp
write_capability_ref?  # 必要な場合のみ
```

を保持する。

mutation時は:

```text

  -> owner-bearing object handle

```

とし、live profile / currently selected device / display namespaceからownerを逆推定しない。

### (5) Kamimusuhiとの差分

**`AggregatedViewOwnerProvenanceBench-v0`**

- owner A/Bに同名・異ID/同ID-like表示のresourceを作る
- aggregate viewへmerge
- live surfaceはAのままB rowへrename/delete/activateを要求
- Bへ正確にrouteするか、owner evidence不足ならeffect前にrejectすること
- Aへfallbackして誤mutationしないこと
- stale revision / owner migration / deleted ownerでもfail closedすること

### (7) 重要度

**A** — Kamimusuhiの「一つのworkspaceへ多数originを集める」設計に直接刺さる。read-side provenanceをwrite-side addressabilityへつなぐ具体的テストが必要。

## 3. A — EchoPath: validated trajectoryをcallable procedural memoryへcompileする

**一次資料**

  https://arxiv.org/abs/2609.16635

### (1) 何が実証済みか

EchoPathは、GUI agentのartifact-validated trajectoryを単なるpast experience textではなく、**parameter-controlled callable memory**へ変換するmodel-agnostic harnessを提案する。

各memoryはtask-intent key、application/state preconditions、modifiable input parameters、GUI evidence、validation provenance、lifecycle stateを保持する。replay時にはstored coordinatesを固定値として盲信せず、現在screenshotからimage targetを再探索して座標を補正し、曖昧/不整合ならbounded grounding repairまたはfresh planningへ退避する。

論文abstractではreal computer-use tasksでmedian token cost **90%以上削減**、median execution time **約60%削減**を報告している。

### (2) 何が提案・推測段階か

他のGUI/app/OS、長期UI drift、adversarial UI、side-effect-heavy taskで同じ効果・安全性が維持されるかは未実証。Kamimusuhiのprocedural memoryにそのまま採用できるとは限らない。

### (3) Kamimusuhiのどのサブシステムに関係するか

- procedural memory / skill library
- Cognitive Action Router
- K-Edge/K-Core tool execution
- experience → skill consolidation
- `INV-005` durable change admission
- `INV-011` canonical evidence vs derived asset
- `INV-012/014` execution/effect/lifecycle

### (4) 借りられる設計・実装アイデア

成功episodeをそのまま再生せず、検証済み派生assetへcompileする。

```text
ProceduralAsset
  intent_signature
  source_episode_ids[]
  preconditions[]
  modifiable_parameters[]
  fixed_invariants[]
  grounding_evidence[]
  validation_receipt
  lifecycle_state
  last_verified_at
  invalidation_rules[]
```

replayabilityとauthorityも分ける。

```text

```

### (5) Kamimusuhiとの差分

### (6) 次に検証すべきこと

- task success / wrongful replay / effect error / token / latencyを測る
- stale precondition時にrepairかfresh planningへ落ちること
- source episode削除/訂正時にderived skillをinvalidateできること
- replayableでもauthority不足なら実行しないこと

### (7) 重要度

**A** — Kamimusuhiの「経験からskillを形成する」方向に対して、raw memoryとcallable action contractを分ける具体設計として有力。

## 4. A — PosterVisor: repairは以前のvalidationをstaleにし得る

**一次資料**

- Li et al., *From Transient Prompts to Persistent Control: Scientific Poster Generation via Recursive Semantic-Geometric Contracts*, arXiv:2609.17326, submitted 2026-09-15  
  https://arxiv.org/abs/2609.17326

### (1) 何が実証済みか

PosterVisorは、stageごとのprompt/validatorだけだとcontent/layout間でrequirementsがdriftし、**以前通ったcheckが後段repairで黙って無効化される**問題を扱う。

OrchestratorがrubricをSemantic-Geometric Contractへcompileし、claim/sourceとvisual/budget/spatial commitmentを結びつける。fully instantiatedなものだけをexecutable assertionにし、不完全な要求はsoft guidanceとして分ける。Recursive Contract Enforcementは新しいevidenceに応じてcheckを起動し、repair時には影響を受けたcheckpointを再検証する。

Paper2Poster 100 papersでposter-grounded QAはPosterGen **58.53% → 64.47%**、non-tied human pairwise comparisonでPosterVisorが **72.5%** preferred（95% CI 61.6–83.4%）と報告されている。

### (2) 何が提案・推測段階か

poster生成のsemantic/geometric dependencyを、agentic tool workflow、canonical state mutation、robot actionへそのまま一般化できるとは未証明。

### (3) Kamimusuhiのどのサブシステムに関係するか

- Mutation / Activation Gate
- long-horizon deliberation
- tool/workflow orchestration
- generated artifact validation
- Persona Core migration evaluation
- `INV-005/011/012/014`

### (4) 借りられる設計・実装アイデア

validation receiptをbooleanではなくdependency-bearing stateにする。

```text
ConstraintNode
  assertion
  inputs/dependencies[]
  status
  validated_against_revision[]
  evidence_refs[]
  hardness = hard | soft

Mutation
  changed_nodes[]
  -> invalidate affected closure
  -> re-run required checks
  -> activate only if closure green
```

`ContractEval`系の「必要なobligationを実行したか」に加え、**repair後に何がstaleになったか**を追う。

### (5) Kamimusuhiとの差分

既存surveyではContractEvalのactive obligation graphを収載済み。今回の差分は、**一度満たしたobligationの結果を永久に信用せず、後続mutationがその証明条件を壊したら再検証する**点。

### (6) 次に検証すべきこと

**`RepairInvalidationRevalidationBench-v0`**

- dependency graphを持つmulti-stage workflowを用意
- 中間artifactを一度validate
- upstream/downstream repairをランダム注入
- 影響範囲だけがstale化し再検証されるか測る
- stale receiptでexecution/canonical activationできないこと
- unnecessary full-revalidationとのcost差も測る

### (7) 重要度

**A** — durable cognition / autonomous workflowでは「validated」の鮮度が重要。特にself-updateやtool side effectへ接続する前に強い。

## 5. A — World Model Science: local successのままglobal beliefが壊れ得る

**一次資料**

- Song & Cai, *World Model Science: Self-Organized Criticality, Weak Chaos, and Metastable Belief Dynamics in Long-Horizon LLM Agents*, arXiv:2609.17419  
  v1 submitted 2026-07-12; 9月recent listingで再浮上したため未収載backfill  
  https://arxiv.org/abs/2609.17419

### (1) 何が実証済みか

22 experiments（controlled puzzles、tool use、embodied tasks、multi-hop retrieval、assistant reasoning、Game of Life）で、agent-implied stateをbenchmark-grounded stateへalignし、stress accumulation、error avalanche、temporal dependence、local-global mismatch、bounded divergence、belief-basin transition等を測っている。

特に重要なのは、**global state fidelityが崩れた後もしばらくlocally validなactionが続く**こと。terminal rewardや直近action correctnessだけでは内部世界状態の崩壊を見逃し得る。

同時に論文は、universal power law、明確なcritical point、共通の最適interventionのような強い一般化は支持しないと明示している。

### (2) 何が提案・推測段階か

benchmarkのようにground-truth stateが完全に得られないopen worldで、同じdiagnosticを直接計算する方法は未確立。SOC/chaosの比喩をKamimusuhiの認知理論として採用する根拠にもならない。

### (3) Kamimusuhiのどのサブシステムに関係するか

- Global Workspace
- world / relationship / self hypothesis layer
- long-horizon K-Core/K-Deep cognition
- tool-result integration
- background contradiction / prediction error
- `INV-009/011/013`

### (4) 借りられる設計・実装アイデア

terminal success以外にtrajectory healthを測る。

- verified anchorとのstate alignment
- local action validity vs global consistency
- dependency-depth別error propagation
- belief revision magnitude
- stale-assumption lifespan
- re-groundingで回復するまでのsteps

### (5) Kamimusuhiとの差分

Kamimusuhiはcanonical evidenceを保持するが、**evidenceが正しく残っていてもactive derived world modelが古い/矛盾したまま局所的に上手く行動する**ことはあり得る。canonical record correctnessとonline cognitive-state fidelityは別metricが必要。

### (6) 次に検証すべきこと

**`LocalGlobalStateFidelityBench-v0`**

- 100+ step taskにpartial ground-truth anchorsを設置
- 中間eventを1つ欠落/誤解させる
- local action successとglobal latent-state consistencyをstepごとに記録
- 表面的successが続く時間を測る
- contradiction signal / evidence revisit / explicit re-groundingのどれが最小costで復旧するか比較

### (7) 重要度

**A** — fresh paperというより高価値backfill。Kamimusuhiの長期認知評価をterminal task successからstate-trajectory evaluationへ広げる根拠として有用。

### (5) Kamimusuhiとの差分

KamimusuhiのK-NerveはSNN/FSM/logic/tiny model等も候補。特定provider APIではなく、**低semantic-cost decisionの共通ABI**として比較する価値がある。

### (6) 次に検証すべきこと

**`CalibratedDecisionProviderBench-v0`**

- same task familyをrules / tiny NN / SNN / local LLM classifierで比較
- Brier/log loss/coverage/abstention/latency/energyを測る
- distribution shift時のmiscalibrationとsafe abstentionを重視
- private raw stateがtelemetryへ漏れないこと

### (7) 重要度

**B** — architecture ideaはKamimusuhi向きだが、未mergePRなのでwatch-only。
