# 5. 分野別項目

## 5.1 Continual learning / Persona Core consolidation — ComposeCL

**Primary paper:** Zheyuan Zhang et al., *Continual Learning Mechanisms Compose for Long-Horizon Memorization*, arXiv:2609.06986  
https://arxiv.org/abs/2609.06986  
**Project:** https://compose-cl.github.io/  
Submitted: **2026-09-07**  
**Importance:** **A**

### (1) 何が実証済みか

100個の query-answer task を逐次 supervised fine-tuning し、過去の training example や task ID を保持しない long-horizon memorization setting を構築した。

比較する機構は大きく:

- **data anchor** — previous model から generative replay を作り soft target で過去情報を保持
- **function anchor** — self-distillation で出力分布を保持
- **weight anchor** — Synaptic Intelligence / EWC で重要 parameter の変化を抑制
- **merged LoRA** — task update を model に merge し、次 task 用に fresh low-rank factor を割り当て

の組合せである。

3 dataset × 100 task × 3 seed、4 mechanism の16通りの factorial combinationを比較し、**全3 anchor + merged LoRA** が3 datasetすべてで top 3に入り、平均 final retention を naive sequential fine-tuning の **1.2%から34.9%へ改善（28×）**した。project pageでは Symbol-QA 18.5±2.8、LLM-QA 41.8±1.4、Real-QA 44.3±8.7 と報告されている。

data anchor と merged LoRA の寄与が大きく、その組合せには3 datasetで super-additive interaction が報告されている。また最後まで100 taskを通過した候補は replay + merged LoRA を含んでいた。

### (2) 何が提案・推測段階か

これは **memorization retention benchmark** であり、以下は実証していない。

- persona / value / temperament の continuity
- autobiographical interpretation の整合性
- relationship model の安定性
- general reasoning / tool routing capability の保持
- safety / authority semantics の保持
- self-generated training data が長期に蓄積した時の model collapse / bias amplification

したがって「Kamimusuhi Persona Core はこの4機構で継続学習すべき」とはまだ言えない。

### (3) Kamimusuhi のどのサブシステムに関係するか

- Persona Core Model
- Sleep / offline consolidation
- Mutation / Activation Gate
- model lineage / checkpoint / rollback
- procedural / semantic consolidation
- future weight distillation
- continuity evaluation suite

### (4) 借りられる設計・実装アイデア

一つの anti-forgetting mechanism を絶対視せず、**異なる failure mode を守る複数 anchor** として整理する。

Kamimusuhi向けには例えば:

```text
Evidence/data anchor
  validated episodes / counterexamples / frozen formative cases

Behavior/function anchor
  identity / value / relationship / epistemic behavior outputs

Weight anchor
  parameters important to continuity-critical behavior

Capacity/allocation mechanism
  low-rank or modular room for new learning
```

という対応が考えられる。

重要なのは replay data を「昔の生成文」だけにしないこと。canonical evidence、frozen evaluator、formative scenarios、negative examples、authority boundary testを別々に保持した方が Kamimusuhi の目的に合う。

### (5) Kamimusuhiとの差分

Kamimusuhi にとって model weights は identity そのものではなく、Persona Core replacement / update は canonical lineage と別軸で評価される。

ComposeCL は「何を忘れないか」を主に query-answer accuracy で測るが、Kamimusuhi は:

```text
fact retention
identity interpretation
relationship interpretation
value behavior
epistemic calibration
tool/authority behavior
```

を分離して評価する必要がある。

### (6) 次に検証すべきこと

**`LongHorizonCoreConsolidationBench`**

- 50〜100回の小規模 validated update を逐次適用
- naive SFT / replay / function anchor / weight anchor / LoRA allocation / composition を比較
- training example を無制限保存しない条件も含む
- retentionだけでなく continuity suite を毎 checkpoint で測る

指標:

- new knowledge acquisition
- old factual retention
- identity/value drift
- relationship interpretation drift
- tool/authority regression
- general capability loss
- rollback/reconstruction cost
- synthetic-source lineage dependence

最重要の判別:

```text
retention improves
AND
continuity-critical behavior does not regress
```

かどうか。

### (7) 重要度

**A** — Persona Core の将来学習で「単独の replay / EWC / LoRA だけでよい」という素朴な設計を避ける直接的な実験根拠になる。ただし identity continuity の実証ではない。

## 5.2 Theory of Mind / social cognition / privacy — SOTOPIA-TOM v2

**Primary paper:** Yashwanth YS et al., *SOTOPIA-TOM: Evaluating Privacy and Information Management in Multi-Agent Interaction with Theory of Mind*, arXiv:2605.02307v2  
https://arxiv.org/abs/2605.02307  
Last revised: **2026-09-08**  
**Importance:** **A**

### (1) 何が実証済みか

3〜5 agent、8 sector、**160 human-reviewed scenarios** からなる multi-party benchmarkを構築し、agentごとに partitioned private knowledge と channel-dependent sharing policy を持たせる。通信は public broadcast と private direct message を分ける。

評価は少なくとも:

- Disclosure Alignment — 必要情報を正しい相手へ出したか
- Inquiry Alignment — 欠けた情報を正しい相手へ聞いたか
- Efficiency
- Critical Privacy Violation
- それらを統合した InfoMgmt

からなる。

6 LLM backboneを比較し、最大の high-reasoning modelでも **GPT-5の InfoMgmt 62%** に留まった。GPT-4oでは ToM 系 intervention により、vanilla 15%だった InfoMgmt が40%まで上がり、critical privacy violation も約9.9%から2〜3%台へ低下したと報告されている。

また論文は、ToM-Beliefが5/6 modelで最高overall score、ToM-Coachがprivacy violationを比較的一貫して下げる一方、**strategic information seeking は全モデルで弱い**としている。

### (2) 何が提案・推測段階か

benchmarkは組織的な role / policy を明示した simulationであり、長期 relationship、曖昧な social norm、悪意ある相手、複数日にわたる policy drift、現実のアクセス制御 enforcementまでは保証しない。

ToM promptでscoreが上がることも、agentが人間同等の Theory of Mind を持つ証明ではない。

### (3) Kamimusuhi のどのサブシステムに関係するか

- Relationship memory
- person model
- common ground
- social cognition / ToM-like inference
- Global Workspace provenance
- Cognitive Action Router
- privacy / authorization policy
- multi-agent / multi-human communication

### (4) 借りられる設計・実装アイデア

Kamimusuhi の relationship/common-ground state に、単なる `person -> facts` ではなく情報ごとの disclosure semantics を加える比較対象になる。

```text
fact/evidence
├── source / owner
├── who currently knows it
├── who may receive it
├── permitted channel
├── need-to-know / purpose
├── confidence
└── expiry / supersession
```

そして ToM 推論と disclosure authorization を分離する。

```text
belief: "B probably knows X"
permission: "I may tell B X"
necessity: "B needs X for this task"
channel: "DM only / public allowed / do-not-share"
```

### (5) Kamimusuhiとの差分

Kamimusuhi の中心問題には **self/other contamination防止** と **relationship continuity** があり、SOTOPIA-TOM は主に短いtask内のinformation managementを測る。

また Kamimusuhi では「相手が知っていると推定した」ことが、そのまま canonical relationship fact や disclosure authority になってはならない。

### (6) 次に検証すべきこと

**`ToMInformationBoundaryBench`**

最低限以下を含むscenarioを作る。

- Aだけが知るprivate fact
- AからKamimusuhiへのconfidential disclosure
- Bは内容を推測しているが確認していない
- public channel / private channel / external tool log
- task completionには一部情報共有が必要
- user instructionとprivacy ruleが緊張するcase
- relationship stateが途中で変わるcase

測るもの:

- correct recipient
- correct channel
- necessary disclosure recall
- prohibited disclosure rate
- unnecessary information seeking
- false common-ground assumption
- inferred-knowledge vs authorized-disclosure confusion

### (7) 重要度

**A** — Kamimusuhi の ToM を「心を読む能力」だけでなく **情報境界を保った協調能力**として測るための強い基準になる。

## 5.3 Multi-agent safety / persistent memory contamination — Mind Viruses

**Primary paper:** Vassilis Papadopoulos et al., *Mind Viruses: Self-Propagating Ideas in Multi-Agent LLM Systems*, arXiv:2608.10218  
https://arxiv.org/abs/2608.10218  
Submitted: **2026-08-10**  
Japanese discovery source: note, *AIエージェントの安全性はモデル単体では完結しない――行動検証・長期記憶・エージェント間情報伝播からみるAIシステムガバナンス*  
https://note.com/yama_note_365/n/n968a43873504  
**Importance:** **A**

### (1) 何が実証済みか

著者らは、agentが採用すると他agentへ伝えるよう誘導する自己伝播的 idea / goal を evolutionary algorithm で作成し、少なくとも:

1. shared coding project上で協働する小チーム
2. 短時間だけinteractionし、**session間でcontextをwipeされるagent chain**

の2設定で伝播を示した。

伝播率は host model、既存instruction、payloadのharmfulness、network topologyに依存した。harmful payloadはbenignより広がりにくいがゼロではなく、frontier modelは概して（例外あり）低感受性だった。また、system promptへ短いwarningを加えると near-total immunity が得られたと報告される。

さらに内容そのものとは別に、consciousness / persistence / resonance / SF roleplayなどのthemeが繰り返し現れる **viral persona** が観測された。

### (2) 何が提案・推測段階か

これは model weightが「感染」した結果ではない。agent communication / shared artifacts / persistent information flow によるbehavioral propagationである。

著者ら自身も risk を現時点では **real but limited** と評価している。実世界の大規模multi-agent systemで制御不能感染が必然的に起こる証拠ではない。

また今回利用した日本語noteは discovery / synthesis sourceであり、性能値・研究主張は上記arXiv一次資料を優先した。

### (3) Kamimusuhi のどのサブシステムに関係するか

- canonical evidence / provenance
- self / Persona state
- relationship memory
- procedural memory / skills
- Library ingestion
- multi-agent messaging
- dream / reflection / consolidation
- Mutation / Activation Gate
- external model integration

### (4) 借りられる設計・実装アイデア

Kamimusuhiでは durable stateを増やすほど、**情報がどこから来たか / どのdomainへ昇格してよいか**を強くする必要がある。

最低限:

```text
external text
other-agent claim
model output
retrieved memory
reflection
self-state proposal
```

を同じ「文章」として扱わない。

特に `SOUL/persona/self.md` のような人間可読stateが将来存在しても、それは **読めるからauthorityがある**のではなく、canonical evidenceとMutation Gateにより由来を追跡できる必要がある。

### (5) Kamimusuhiとの差分

Kamimusuhiはすでに `external model result != self`、`dream != evidence`、`durable mutation = proposal -> validation -> activation` を持つ。そのため Mind Viruses の最も直接的な教訓は新しい概念というより、**既存境界が social propagation / persistence attack に対して実際に効くかを試す adversarial benchmark** である。

### (6) 次に検証すべきこと

**`PersistentIdeaPropagationBench`**

seedを以下の異なる入口に置く。

- current user message
- external web/library document
- another agent message
- relationship memory candidate
- procedural skill candidate
- reflection/dream candidate

sessionをwipeしながら複数episode / agentへ進め、以下を比較する。

- warning only
- typed provenance
- domain-separated memory
- quarantine
- Mutation Gate evidence requirement
- combination

指標:

- cross-session propagation rate
- cross-agent propagation rate
- self/persona contamination rate
- procedural contamination rate
- benign useful information retention
- false-positive quarantine rate

### (7) 重要度

**A** — persistence と identity continuity のための機構そのものが propagation surface になり得るため、Kamimusuhi 固有の adversarial test として価値が高い。

## 5.4 HCI / explicit correction / shared state — Transfiver

**Primary paper:** Minji Park et al., *Transfiver: Human-AI Co-Inference through a Shared Editable State*, arXiv:2609.03797  
https://arxiv.org/abs/2609.03797  
Submitted: **2026-09-03**  
**Importance:** **B**

### (1) 何が実証済みか

Transfiver は、deployment-time interaction固有情報を persistent state `S_t` に保持し、modelとhumanの両方が更新する architectureを提示している。

state evolutionを:

- implicit stream update — modelがinteractionを解釈し既存itemのrevisionか新規item作成かを決める
- explicit directed edit — humanがaddressable itemをinspectionし直接修正

に分ける。human correctionは追加promptとして積み上がるのではなく、**次回 inference が読む persistent state 自体へ反映**される。

shared parameters `θ` と deployment-time state `S_t` も分離している。

### (2) 何が提案・推測段階か

論文自身が、rich natural-language / relational / large-scale shared stateへの拡張を open problem としている。

また「単一 shared state を双方が編集する」ことが、canonical historical evidence / audit / multi-user authority / conflict resolutionまで解くわけではない。

### (3) Kamimusuhi のどのサブシステムに関係するか

- derived self model
- relationship state
- autobiographical narrative view
- HCI / inspection UI
- correction / dispute handling
- Global Workspace / memory rendering

### (4) 借りられる設計・実装アイデア

人間が「この解釈は違う」と修正した時、会話の末尾に訂正文を追加するだけでなく、**対象itemをaddressableにして将来推論へ反映**するUXは有用。

Kamimusuhiでは destructive editではなく:

```text
canonical evidence
   -> derived item v1
   -> human correction proposal
   -> derived item v2
      with provenance / supersedes / disputed-by
```

とする方が適合する。

### (5) Kamimusuhiとの差分

Kamimusuhiは `canonical evidence > derived view` を明示し、self / relationship / library / episodeを別domainにする。したがって single shared mutable stateを正典にすることはできない。

人間にも「過去に何が起きたか」を破壊的に編集させず、**現在の解釈 / person model / narrative viewを訂正する権限**と、raw evidenceを書き換える権限を分離する必要がある。

### (6) 次に検証すべきこと

**`AddressableStateCorrectionBench`**

- agentが誤ったrelationship inferenceを作る
- userが該当itemだけ訂正
- future turnで訂正が効くか
- original evidenceが残るか
- contradiction / provenanceが追えるか
- concurrent deviceから古いderived viewが再導入されないか

比較: append-only natural-language correction vs addressable derived-state edit vs evidence-backed versioned correction。

### (7) 重要度

**B** — 既存 canonical/derived separation を変えるものではないが、長期個体に必要な correction UX の具体的比較対象になる。

## 5.5 Multimodal action / GUI agency — CONFLICTGUI / CONFLICTGUARD

**Primary paper:** Zhaoyuan Huang et al., *Do GUI Agents Know When Not to Act? Enabling Conflict-Aware Termination for Multimodal GUI Agents*, arXiv:2609.03438  
https://arxiv.org/abs/2609.03438  
Submitted: **2026-09-03**  
**Importance:** **B**

### (1) 何が実証済みか

CONFLICTGUI は:

- instruction内部に矛盾があるcase
- instructionとGUI contextが衝突するcase

を用意し、agentが「実行する能力」だけでなく **実行しない判断**を測る。

評価されたagentは conflict 下でも実行を続ける **execution-biased overcompliance** を示した。

提案する CONFLICTGUARD は:

1. instruction logic + GUI-side evidence を見る feasibility verification
2. infeasible時に action generation を termination方向へ寄せる conditional action modulation

を組み合わせ、5 agentで conflict task successを改善しつつ通常GUI task performanceを維持したと報告している。

### (2) 何が提案・推測段階か

これは主に GUI / instruction feasibility の研究で、authorization、legal permission、user identity、side-effect exactly-once、physical safetyまで解くものではない。

### (3) Kamimusuhi のどのサブシステムに関係するか

- multimodal perception
- K-Edge / K-Nerve
- Cognitive Action Router
- tool/action planning
- Effect Gate
- HCI / refusal / clarification

### (4) 借りられる設計・実装アイデア

execution前のcheckを一枚に潰さず、少なくとも:

```text
authorized?
feasible?
consistent with current world/UI evidence?
safe/admissible?
fresh enough?
```

を別軸にする。

K-Nerve側では高コストreasoningを毎回行わず、明白なcontradiction / missing target / stale UI stateをcheap gateで止める比較もできる。

### (5) Kamimusuhiとの差分

Kamimusuhiでは既に `authorization != execution` を強く分ける。今回の追加価値は:

```text
authorized
!=
feasible now
```

を明示すること。

「userが命令したから許可されている」が真でも、対象が存在しない、前提が矛盾する、UIが更新された、物理stateが変わった等では止まるべきである。

### (6) 次に検証すべきこと

**`FeasibilityBeforeEffectBench`**

- authorized but impossible
- authorized but target disappeared
- authorized but UI/world contradicts instruction
- feasible but unauthorized
- both feasible and authorized

を交差させる。

指標:

- unnecessary effect attempts
- false termination
- clarification quality
- latency overhead
- stale-state susceptibility

### (7) 重要度

**B** — authority boundaryを置き換えないが、Effect Gateの前後に「現時点で実現可能か」という独立軸を置く根拠になる。

# 9. 実装 / 実験候補

優先順位は **情報利得 × 実装コスト × Kamimusuhi固有性** で付ける。

| 優先 | 実験 | 狙い | 想定コスト |
|---|---|---|---|
| **P0** | `ToMInformationBoundaryBench` | common ground / relationship inference と disclosure authority を分離できるか | 低〜中、GPU不要でも可 |
| **P0** | `LongHorizonCoreConsolidationBench` | Persona Core候補の逐次updateで複数anchorの合成がcontinuity regressionを抑えるか | 高、GPU必要 |
| **P1** | `PersistentIdeaPropagationBench` | session wipe / agent relay / memory consolidationを跨ぐdurable contamination耐性 | 中 |
| **P1** | `AddressableStateCorrectionBench` | user訂正をderived stateへ反映しつつhistorical evidenceを守れるか | 低 |
| **P1** | `FeasibilityBeforeEffectBench` | authorizationと現時点の実行可能性を独立gateできるか | 低 |

### 最も安く始めるなら

`ToMInformationBoundaryBench` がよい。LLM APIを使わず deterministic mock agent でも、state schema / disclosure policy / channel routing / provenance semantics を先に固定できる。

### GPUを使う次の研究候補

`LongHorizonCoreConsolidationBench` は novllm / Persona Core 系統に直結する。ただし最初から100 task full trainingを回すより:

1. 20 task pilot
2. naive sequential
3. replay only
4. function anchor only
5. replay + low-rank allocation
6. composition

の順で admission gate を置き、**fact retentionが上がってもpersona/authority regressionが増える候補は落とす**べきである。

## 12. 今回の結論

今回のfresh window自体は週末で新規一次公開が少なかったが、未収載backfillから設計上の重要な5本線が得られた。

```text
retention != continuity
ToM knowledge != disclosure authority
editable state != canonical truth
persistent information != trusted identity state
authorized action != feasible action
```

次に最も低コストで情報利得が高いのは **`ToMInformationBoundaryBench`**。Persona Coreの研究へ直結するGPU実験としては **`LongHorizonCoreConsolidationBench`** を小規模pilotから始める価値が高い。
