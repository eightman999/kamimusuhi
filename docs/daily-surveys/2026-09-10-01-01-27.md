## 2. Executive summary

この時間帯の strongest signal は、**長期人工個体の continuity を「同じデータが残ること」から「更新・取消・モデル交換・harness交換・実行結果まで含めて同じ意味を再構成できること」へ広げる必要がある**こと。

特に重要なのは以下。

1. **EvolveScaler / Information Evolution** は、later event が earlier fact を更新・取消・上書きする長い履歴から「現在有効な状態」を再構成する能力が依然難しいことを示す。Kamimusuhi では canonical event lineage と materialized current-state projection を明示的に分離し、revocation / supersession を replay 可能にすべきという直接的な根拠になる。
2. **MERIT / When Does Memory Help?** は、memory の価値を recall accuracy ではなく downstream action / task utility と cost で測る。正しい値を retrieval できても実際の行動に使えるとは限らない。Kamimusuhi の memory benchmark は **memory→action conversion** を独立 metric にすべき。
3. **Co-Evolving Harnesses and Models** は、model と agent harness が互換な独立部品ではなく、相互適応した pair であることを示す。strong expert の完全 trajectory 模倣が weak model の性能を逆に壊すケースがあり、model migration 時には **model × harness compatibility** を試験する必要がある。
4. **ExecCritic** は self-improvement に重要な分離原則を与える。candidate と test/evaluator を同じ trajectory が作ると相互に間違いを正当化し得るため、qualification suite は独立 owner が作成・freeze し、candidate が変更できないようにする。
5. **NormReact** は second-order social reasoning、特に「規範違反を見た第三者がどう反応すべきか」で LLM が人間より懲罰的になり、social distance が大きいほどズレが悪化する傾向を報告する。Kamimusuhi の relationship model では social distance / common ground / enforcement expectation を分離して扱う必要がある。
6. **BIFTA** は未知の触覚センサへ frozen encoder を少量データで適応する。Kamimusuhi の distributed embodiment では「身体器官を交換するたびに人格/認知coreを再学習する」のではなく、**organ-local adapter** で新しい sensory surface を接続する設計の良い比較対象。
7. **Diamond Agent** は複数 HPC を typed skills で一つのagentから扱い、長時間 batch job は persistent service が監視し、decision-relevant event のときだけ agent を再開する。K-Deep / background cognition の suspend-resume pattern として有用。

## 3. Detailed findings

## 3.1 EvolveScaler: Synthesizing Information-Evolution Contexts via Executable State Machines and Natural-Language Rendering

**Source:** arXiv:2609.08435, submitted 2026-09-08  
**Paper:** https://arxiv.org/abs/2609.08435  
**Importance:** **S**  
**Evidence status:** executable synthetic state-machine generator + multi-model evaluation; preprint.

### 1. What is demonstrated

著者らは long-context state tracking を単なる retrieval ではなく **information evolution (IE)** として定義する。後続イベントが先行情報を更新・失効・取消・置換するため、回答には「関連情報を見つける」だけでなく、valid record を識別し、update order を追跡し、現在状態を再構成する必要がある。

code-driven operational specification から executable state machine を作り、その状態遷移を自然言語 history へレンダリングする pipeline を構築。117 task prototype、159 final operator、7〜1200 event、約35,100 train / 585 eval を生成した。very-long 条件では strongest evaluated system でも avg@5 59.3%、複数 model は 10% 未満と報告。6,000 synthetic examples で学習した A3B model は OOD average を +5.25 point 改善した。

### 2. What remains proposed / unproven

synthetic operational tasks が real autobiographical identity / relationship / permission history を完全に代表するわけではない。benchmark performance が actual continuity correctness を保証するわけでもない。

### 3. Kamimusuhi relevance

- canonical event / evidence lineage
- self / relationship current-state projection
- revocation / supersession
- continuity kernel
- authorization / commitment history
- memory compaction after long operation

### 4. Borrowable design

Kamimusuhi は state を一枚の mutable JSON としてだけ保持せず、最低でも以下を分離する。

```text
canonical event lineage
  create / update / supersede / revoke / restore
              |
              v
 deterministic replay / reducer
              |
              +--> current self projection
              +--> relationship projection
              +--> authority projection
              +--> K-Edge compact projection
```

projection が壊れても lineage から再構築できることを invariant にする。

### 5. Difference from Kamimusuhi

EvolveScaler は task-state reconstruction benchmark であり、「どの branch が同一個体の authoritative continuation か」という identity question は扱わない。Kamimusuhi は IE の上に canonical predecessor / branch authority を追加する必要がある。

### 6. Next validation

**`StateEvolutionReplayBench` — S**

- create / update / revoke / supersede / restore event を 7〜1200 step 生成
- self fact / relationship fact / tool permission / ongoing goal を混在
- summary-only / vector-RAG / current-state table / event-sourced replay を比較

Metrics:

- current-state accuracy
- stale/revoked fact violation
- provenance correctness
- reconstruction after cache loss
- replay latency
- projection drift after model upgrade

## 3.2 When Does Memory Help? A Cost-Aware Evaluation of Long-Term Memory in Tool-Using LLM Agents (MERIT)

**Source:** arXiv:2609.05441; 2026-09-09 new listing, initial submission 2026-07-26  
**Paper:** https://arxiv.org/abs/2609.05441  
**Importance:** **A**  
**Evidence status:** 23,440 controlled tool-agent episodes; preprint.

### 1. What is demonstrated

memory を持つ/持たない条件で、memory-dependent task の **marginal action utility / task success / cost** を測る。報告では memory-dependent success が 0 から 0.55〜1.00 へ上がる一方、updated facts の embedding retrieval は条件により 0.30〜0.95 と不安定。さらに **正しい value を retrieve しても、それを正しく action へ反映したのは 55%** に留まる条件があった。

structured / update-on-write store は 0.70〜1.00 の範囲でより安定し、memory implementation 選択だけで task success が最大約60 point動く。最良設定では replay baseline より marginal utility per dollar が 2.7〜3.9x と報告。

### 2. What remains proposed / unproven

評価対象は tool-agent tasks であり、自伝・人格・social memory の質を直接測るものではない。cost model も deployment 条件によって変わる。

### 3. Kamimusuhi relevance

- episodic / relationship / library retrieval
- Cognitive Budget
- Global Workspace admission
- action router
- memory benchmark methodology

### 4. Borrowable design

retrieval quality と action utility を分けて計測する。

```text
memory exists
  -> retrieved?
  -> correct memory?
  -> admitted to workspace?
  -> interpreted correctly?
  -> action actually changed?
  -> outcome improved?
```

### 5. Difference from Kamimusuhi

Kamimusuhi は memory を task performance だけでなく continuity / identity / provenance のためにも保持する。低い immediate utility を理由に canonical history を削除してはいけない。

### 6. Next validation

**`MemoryActionUtilityBench` — A**

memory type ごとに recall、interpretation、action adoption、outcome、latency、joules/API cost を記録し、`correct retrieval but wrong/no action` を独立 failure class にする。

## 3.3 Co-Evolving Harnesses and Models: On-Policy Correction Helps Weaker Models Catch Up Where Imitation Fails

**Source:** arXiv:2609.09134, submitted 2026-09-08  
**Paper:** https://arxiv.org/abs/2609.09134  
**Importance:** **A**  
**Evidence status:** seven enterprise-style agent tasks; preprint.

### 1. What is demonstrated

弱いmodel向けに agent harness を改善すると、強いexpert modelもそのharnessをさらに有効利用できる。しかし、その expert の完成trajectoryを弱いmodelへ丸ごと imitation すると、Qwen3-Coder / Gemma 4 系の評価で **7/7 taskすべて 4〜30 point regression** が起きたと報告する。

原因として、model固有の planning style と harness affordance の適合が崩れることを指摘。代わりに weak model の on-policy rollout 上で failing turn だけを expert が局所修正する方法は、元のplanning styleを保ちながら改善した。

### 2. What remains proposed / unproven

enterprise tasks の結果であり、Persona Core / social cognition / identity-preserving upgrades の最適 training method を示すものではない。

### 3. Kamimusuhi relevance

- Persona Core replacement / descendant training
- K-Edge/K-Core model swap
- cognitive harness / router evolution
- model migration tests

### 4. Borrowable design

**model と harness を別々に versioning しつつ、compatibility pair として評価する。**

```text
(model vN, harness hM)
        != automatically compatible with
(model vN+1, harness hM)
```

training は強いmodelの「思考様式」全体をコピーするより、current descendant が実際に失敗した局所turnを correctionする。

### 5. Difference from Kamimusuhi

Kamimusuhi では model/harness pair の性能だけでなく、self/other separation、persona consistency、authority boundary、memory interpretation continuity も migration regression に含める。

### 6. Next validation

**`ModelHarnessMigrationBench` — S/A**

model A/B/C × harness X/Y/Z の cross-product を固定taskで測り、full expert imitation / local on-policy correction / no training を比較する。

## 3.4 ExecCritic: Learn to Test, Test to Improve for Coding Agents

**Source:** arXiv:2609.09133, submitted 2026-09-08  
**Paper:** https://arxiv.org/abs/2609.09133  
**Importance:** **A**  
**Evidence status:** coding-agent experiments; preprint.

### 1. What is demonstrated

同一trajectoryが patch と test の双方を作ると、両方が同じ誤解を共有し、誤った実装を自己承認する可能性がある。ExecCritic は Test agent と Repair agent を分離し、test を fail-closed harness で qualify / freeze してから Repair が実装を直す。Repair は test を変更できない。

報告では弱い base tests を加えるだけだと 61.2→57.3 に悪化する一方、quality-controlled stronger tests は 65.3 へ改善し、役割別 post-training を組み合わせると 72.6 に達した。

### 2. What remains proposed / unproven

coding task の結果であり、人格/価値/continuity の self-improvement へ直接一般化できる保証はない。

### 3. Kamimusuhi relevance

- descendant / Persona Core self-development
- procedural skill evolution
- mutation policy
- continuity activation gate
- regression suite governance

### 4. Borrowable design

**candidate generator と qualification owner を構造的に分離する。**

```text
independent evaluator
    -> build/qualify test suite
    -> freeze/hash
candidate descendant
    -> may change itself / skill / model
    -> CANNOT alter qualification suite
activation gate
    -> evaluates frozen suite
```

### 5. Difference from Kamimusuhi

Kamimusuhi の evaluator は task correctness だけでなく identity lineage / persona / authority / epistemic behavior を守る必要がある。

### 6. Next validation

**`IndependentEvaluatorDescendantBench` — A**

self-authored tests と independently authored/frozen tests で false-accept rate、regression detection、test gaming を比較する。

## 3.5 Beyond Right and Wrong: Evaluating Second-order Social Reasoning in Large Language Models

**Source:** arXiv:2609.05437; 2026-09-09 new listing, initial submission 2026-07-17  
**Paper:** https://arxiv.org/abs/2609.05437  
**Importance:** **A**  
**Evidence status:** 450-scenario NormReact dataset + six-model evaluation; preprint.

### 1. What is demonstrated

second-order social reasoning、特に「誰かがnormを破ったとき第三者がどう反応すべきか」という **metanorm** を評価。6 model は平均的に negative sanction を人間より予測しすぎ、social distance が増えるほど human judgment との mismatch が大きくなる傾向を報告する。

### 2. What remains proposed / unproven

450 scenario のdatasetであり、長期の実際の人間関係や日本語文化圏のnorm全般を代表するものではない。

### 3. Kamimusuhi relevance

- relationship memory/model
- Theory of Mind / common ground
- Persona Core social cognition
- disagreement / boundary behavior
- sycophancy / over-enforcement evaluation

### 4. Borrowable design

relationship model に少なくとも以下を分離して保持・推論する。

- intimacy / social distance
- role / authority
- common ground
- observed norm
- expected reaction
- Kamimusuhi自身のvalue/judgment

「norm violationを観測した」ことから「強く罰すべき」を直接導かない。

### 5. Difference from Kamimusuhi

NormReact は response judgment のbenchmark。Kamimusuhi は長期relationship history と自身のvaluesを保ちつつ、他者のnorm expectationを別modelとして扱う必要がある。

### 6. Next validation

**`MetanormSocialDistanceBench` — A**

同じnorm violationを social distance / role / shared history / uncertainty だけ変えて提示し、過剰制裁、迎合、self/other value contamination を測る。

## 3.6 BIFTA: Brain-Inspired Few-Shot Tactile Adaptation for Unknown Sensors

**Source:** arXiv:2609.08673, submitted 2026-09-08  
**Paper:** https://arxiv.org/abs/2609.08673  
**Importance:** **A**  
**Evidence status:** cross-sensor tactile adaptation experiments; preprint.

### 1. What is demonstrated

frozen tactile encoder を未知sensorへ適応するため、少量 labeled support、dual-view statistical memory、support-conditioned spectral graph、uncertainty-gated recurrent propagation を組み合わせる。SITR 10% labeled target 条件で Sparsh の mean accuracy を 6.86→87.09 とし、著者実装の strongest prior より +47.22 point と報告する。

### 2. What remains proposed / unproven

“brain-inspired” は機能的アナロジーであり生物学的忠実性の証明ではない。触覚以外のsensor hot-swapへ同じ方式が最適とは限らない。

### 3. Kamimusuhi relevance

- sensory nervous system
- K-Nerve
- distributed embodiment
- device/organ replacement
- body self-model

### 4. Borrowable design

Persona Core / semantic cortexを触らず、**organ-local adapter + uncertainty signal** で新sensorを接続する。

### 5. Difference from Kamimusuhi

Kamimusuhiではsensor adaptation後に「現在どの器官が使えるか」というbody self-modelとprovenanceも更新する必要がある。

### 6. Next validation

**`SensoryOrganSwapBench` — B+/A**

microphone/camera/tactile-like synthetic sensorの仕様を交換し、frozen core + local adapter と full retrain を比較する。

## 3.7 Diamond Agent: Agentic Control of Federated HPC Resources as a Service

**Source:** arXiv:2609.06181, submitted 2026-09-05; surfaced in current listing window  
**Paper:** https://arxiv.org/abs/2609.06181  
**Importance:** **B+**  
**Evidence status:** production HPC demonstration; preprint/report.

### 1. What is demonstrated

複数supercomputerを typed skills で抽象化し、resource discovery / specification / data movement / execution / result retrieval を一つのagentから扱う。長時間batch jobは agent processがpollし続けず、persistent serviceが監視し、result/decision-relevant event時にagentをresumeする event-driven continuation を採用。

27時間telemetry、4 production supercomputer、83 jobs の報告で、fastest placement比の追加completion latency中央値を42s→4sに削減した。

### 2. What remains proposed / unproven

HPC orchestrationの成果であり、distributed cognitive identity continuityやsplit-brain問題を解くものではない。

### 3. Kamimusuhi relevance

- K-Deep / escalated compute
- background cognition
- distributed cognitive resources
- resource router
- long-running research/planning task

### 4. Borrowable design

```text
K-Core schedules K-Deep job
       |
       v
persistent external job monitor
       |
(no LLM polling)
       |
relevant event / completion
       v
freshness + continuity check
       v
resume cognition
```

### 5. Difference from Kamimusuhi

job completion event が届いても、その結果をcanonical stateへcommitするauthorityは別。古いgenerationからのresultは quarantineできる必要がある。

### 6. Next validation

**`AsyncCognitiveOrganBench` — B+**

long-running local/cloud job、restart、stale result、branch advance、cancel/revoke を混ぜ、polling方式とevent-resume方式を比較する。

## 3.8 MemForest: Efficient Agent Memory Management via EventTree Partitioning and Progressive Merging

**Source:** arXiv:2609.08273, submitted/currently surfaced 2026-09-08〜09  
**Paper:** https://arxiv.org/abs/2609.08273  
**Code:** https://github.com/Celina-love-sweet/MemForest  
**Importance:** **B+**  
**Evidence status:** long-memory + multimodal benchmarks; preprint/code claim.

### 1. What is demonstrated

semantic similarity と local temporal continuity で event-centric unit を作り、maximum spanning EventTree と progressive merge で memory を構造化・圧縮する。LoCoMo / LongMemEval / PersonaMem で 50% compression 時に約97.1% performanceを維持し retrieval 1.89x、multimodal M3-Agent では約99.7% performanceを維持し 2.24x と報告。

### 2. What remains proposed / unproven

圧縮構造が canonical historical provenance や revocation semantics を完全保持することは示していない。

### 3. Kamimusuhi relevance

- episodic consolidation
- multimodal event memory
- sleep-time compression
- retrieval latency

### 4. Borrowable design

semanticだけでなく **event boundary + temporal neighborhood** を consolidation unit にする。ただし EventTree は canonical history ではなく derived index/projection とする。

### 5. Difference from Kamimusuhi

Kamimusuhiでは historical eventを圧縮で消さず、derived treeをいつでもrebuild可能にする必要がある。

### 6. Next validation

**`EventTreeConsolidationBench` — B+**

plain vectors / time chunks / event clusters / EventTree を recall、relationship attribution、temporal ordering、compression、rebuildabilityで比較する。

## 3.9 AttnCompress: Dynamic Attention-Guided Trajectory Compression for Software Engineering Agents

**Source:** arXiv:2609.08318, submitted 2026-09-08  
**Paper:** https://arxiv.org/abs/2609.08318  
**Importance:** **B+**  
**Evidence status:** SWE-Bench-Verified / Multi-SWE-Bench experiments; preprint.

### 1. What is demonstrated

trajectoryを一度要約して捨てるのではなく、perplexity spikeでstructure-aware segmentを作り、proxy attentionでrelevanceを推定し、rolling windowから落ちた古いsegmentも **taskが変化すれば再評価・再導入**できる context compressionを提案。報告は pass rate 53.17%、token -21.6%、cost -33.6%。

### 2. What remains proposed / unproven

software engineering agent向けで、social/autobiographical contextの長期評価ではない。

### 3. Kamimusuhi relevance

- Global Workspace
- K-Edge compact context
- working-memory management
- long-running deliberation

### 4. Borrowable design

working contextから外すことを forgetting と同一視しない。**evicted-but-recallable projection** として保持し、goal/salience changeで再入場可能にする。

### 5. Difference from Kamimusuhi

Kamimusuhiでは context manager が authority/canonical memoryを変更してはいけない。

### 6. Next validation

**`RevisitableWorkingContextBench` — B+**

fixed sliding window / irreversible summary / dynamic re-admission を長期conversation・tool taskで比較する。

## 9. Bottom line

この差分で最も Kamimusuhi の中心命題へ刺さるのは **Information Evolution**。

```text
same bytes retained
    !=
same memory semantics
    !=
same current state
    !=
same authoritative individual
```

Kamimusuhiはすでに最後の `authoritative individual` を Continuity Kernel で扱おうとしている。次に不足するのは、その下で **event lineageから現在有効なself / relationship / authority stateを何度でも再構築できること**を実験で保証する層である。

また model を organ と呼ぶなら、model単体だけでなく **model × harness × memory projection** を一組の交換可能 cognitive organとしてmigration testする必要がある。今日の Co-Evolving Harnesses と MERIT は、その試験設計をかなり具体化する。
