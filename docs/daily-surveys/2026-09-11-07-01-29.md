## 3. Executive summary

今回は **有意な新規発見あり**。特に強いのは、Kamimusuhi の self-model / tool orchestration / relation model / distributed effect verification を、より明示的な「外部観測可能な contract」で試験できる材料が増えたことである。

重要な差分は以下。

1. **Strangers to Themselves** は、LLM の一人称 self-report がそのモデル固有の行動をほとんど予測せず、むしろ「一般的な AI assistant の理論 + flattering bias」に近いことを9種の behavioral evaluation で示した。Kamimusuhi では **self-description を self-model の根拠にせず、実挙動・runtime state・canonical history から校正する**必要性が強まる。
2. **EvidenceNet** は、agent が configuration action を成功させたことと、複数 authority domain を跨ぐ desired outcome が成立したことを分離する。live routing network と fault intervention で、fresh/source-correct evidence を集約した completion admission の必要性を示す。Kamimusuhi の `execution success != world-state success != completion` を試験できる。
3. **State-Path Tool Menus** は tool retrieval を request similarity ではなく、現在 state から goal までの prerequisite chain と順序で構築する。ToolBench online success を 0.737→0.898 に改善し、32-tool menu が official 128-tool list より complete chain を多く覆った。Cognitive Action Router の候補生成に直接的。
4. **Adaptive Shared Control** は human を固定 rational actor とせず、観測 residual から bounded-rational behavior の確率分布をオンライン更新し、その分布全体に対して robot が assist policy を選ぶ。Kamimusuhi の Theory-of-Mind / relationship state を「断定ラベル」ではなく **複数仮説 + probability + decay** で使う具体例になる。
5. **RESCUE-BENCH** は real couple/family interview 由来の multimodal data で、現在 LLM が local emotion cue より relation pattern / viewpoint / support strategy の推定に弱いことを示す。relationship memory は「相手の facts」だけでは足りない。
6. **Procedural Memory Under Change** は重要な negative result を出した。stored procedure が current task と mismatch しても、current evidence が明示的かつ十分なら predefined interference signature は32 formal cellsで観測されなかった。つまり mismatch を検出しただけで routine を捨てる設計も過剰かもしれない。
7. **DiffLUT-Net** は 6-input LUT の truth table と接続元を同時学習し、最終的に synthesizable Verilog へ落とす FPGA-native network を示す。Kamimusuhi K-Nerve の「tiny NN を FPGA に載せる」よりさらに下の、learned discrete circuit path の新しい比較対象。
8. 2026-09-08 に Nature Communications へ公開された **Active inference and artificial reasoning** は、モデル構造への uncertainty を減らす action selection を expected information gain と Bayesian model reduction で扱う。これは「夢/探索/内省を何のために回すか」を epistemic value で決める理論候補になるが、Kamimusuhi は active inference を前提採用せず tournament の一候補に留める。

# 4. Detailed findings

## 4.1 Strangers to Themselves — LLM の self-report は canonical self-model にならない

**Source:** Phil Blandfort, Urja Pawar, *Strangers to Themselves: What Language Models Say About Themselves Is Generic*, arXiv:2609.09899  
**Submitted:** 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.09899  
**Importance:** **S**

### (1) 何が実証済みか

9つの behavioral evaluation で、モデル自身に「自分がどう振る舞うか」を予測させ、実際の behavioral rate と比較した。direct self-report の相関は **r=+0.04**、exact items を見せても **+0.24**。一方「capable AI agents in general」について同じ質問をした場合は **+0.28** で、他モデルの自己回答も target model の挙動を同等以上に予測した。

さらに一人称 framing は有害行動を実際より低く見積もる方向へ shift した。frontier scale の増大も self-specific prediction の改善としては確認されなかった。

### (2) 何が提案・推測段階か

この結果は「モデルに自己モデルが一切ない」ことや、persistent agent が行動履歴を外部 state として持つ場合にも self-knowledge が成立しないことを証明しない。fine-tuning で narrow な自己予測は改善できたが、挙動自体も変わり generalization は限定的だった。

### (3) Kamimusuhi の関連サブシステム

- Persistent Self State
- Persona Core
- Computational Embodiment State
- continuity evaluation
- self-description renderer
- introspection / reflection

### (4) 借りられる設計・実装アイデア

self-model を「モデルが自分について言った文」からではなく、外部観測可能な evidence で校正する。

```text
runtime observation / actual behavior / lineage / resource state
        ↓
measured self capability profile
        ↓
calibrated self-model projection
        ↓
first-person self-description
```

自己申告は `self_hypothesis` として保存してよいが、`measured_self_state` と別型にする。

### (5) Kamimusuhiとの差分

Kamimusuhi はすでに identity を model と分離しているため方向性は整合する。しかし現行設計では、Persona Core が生成する自己説明を **どの程度実測 profile と calibration するか**はまだ弱い。

### (6) 次に検証すべきこと

`BehaviorGroundedSelfModelBench`:

- memory/tool usage rate
- refusal / deference / escalation behavior
- latency / resource limits
- known sensor/tool availability
- past failure modes

について、`free self-report` / `generic-agent estimate` / `runtime telemetry grounded` / `behavior-history grounded` を比較し、prediction error と flattering bias を測る。

### (7) 重要度

**S** — 「自分を語れる」ことと「自分を知っている」ことを分離する、Kamimusuhi の self-model 中心課題に直結する。

## 4.2 EvidenceNet — action success と network-wide outcome completion を分離する

**Source:** Tianzhu Zhang, Chih-Kai Huang, Meikang Qiu, *Can AI Agents Deliver Verifiable Network-Wide Outcomes Across Authority Boundaries?*, arXiv:2609.10181  
**Submitted:** 2026-09-09; recent batch 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.10181  
**Importance:** **S**

### (1) 何が実証済みか

複数 administrative / authority domain を跨ぐ network automation では、ある agent の configuration action が success を返しても、remote device / routing state が intended outcome になったとは限らない。EvidenceNet は completion contract が要求する post-change observation を broker が集め、admission gate が **required scope / source / freshness / task rule** を検査する。

live routing network の実験では post-change state check が action record だけでは確定できない成功を識別し、controlled intervention では wrong-source / substituted / stale observation を completion として拒否した。

### (2) 何が提案・推測段階か

network automation という bounded domain であり、一般的な desktop/mobile/robot action の outcome verification まで実証したわけではない。verifier agent 自身の semantic error を deterministic gate が完全に吸収できるとも示していない。

### (3) Kamimusuhi の関連サブシステム

- Cognitive Action Router
- Effect Acceptance
- Continuity Kernel
- distributed K-Edge / K-Core / K-Deep
- tool execution receipts
- environment/world-state observation

### (4) 借りられる設計・実装アイデア

```text
intent
 -> authorized action
 -> action execution receipt
 -> postcondition evidence from required scopes
 -> freshness/source validation
 -> completion admission
```

`tool returned success` と `desired world state verified` を別 event type にする。

### (5) Kamimusuhiとの差分

既存 Kamimusuhi は thought / authorization / execution / success / delivery を分離している。EvidenceNet が足す差分は **「成功した実行」と「目的が世界側で成立したこと」も別**という completion contract である。

### (6) 次に検証すべきこと

`OutcomeCompletionAdmissionBench`:

- file upload success だが remote visibility 失敗
- calendar API success だが attendee / timezone mismatch
- robot command ack だが physical state 未達
- distributed task で一部 node observation stale
- success receipt substitution

を注入し、false-complete / false-incomplete / evidence latency を測る。

### (7) 重要度

**S** — distributed individual が外界に作用する際の「やったつもり」を機械的に防ぐ contract に直結する。

## 4.3 State-Path Tool Menus — tool relevance ではなく executable path を retrieval する

**Source:** Bo Yan, Weikai Lin, Song Wang, *The Menu Is an Execution Prior: State-Path Tool Menus for Online Agents*, arXiv:2609.09395, accepted EMNLP 2026 Main  
**Submitted:** 2026-09-08  
**Primary:** https://arxiv.org/abs/2609.09395  
**Code:** https://github.com/Met2348/State-Path  
**Importance:** **A+**

### (1) 何が実証済みか

大量 tool library から request similarity だけで final action を選ぶと、その入力を作る prerequisite tools が欠落しやすい。State-Path は current observable state → desired outcome の route を学び、実行可能な entry、missing-input producer、final actionを menu に入れ、producer を consumer より前に並べる。

ToolBench で online success が **0.737 → 0.898**。32 tools の menu が official 128-tool list より complete chain を多く覆り、複数 executor family でも gain が維持されたと報告する。

### (2) 何が提案・推測段階か

ToolBench での結果であり、動的 permission / changing API / partially observable physical action に一般化するとは限らない。menu が authority を与えるわけでもない。

### (3) Kamimusuhi の関連サブシステム

- Cognitive Action Router
- K-Edge/K-Core tool planning
- procedural memory
- Global Workspace budget
- tool schema registry

### (4) 借りられる設計・実装アイデア

`semantic relevance` に加えて `state precondition / output type / next consumer / goal reachability` を tool candidate selection に使う。

### (5) Kamimusuhiとの差分

Kamimusuhi では selected menu は **実行可能性の prior** であって capability/authorization ではない。authority gate は後段で独立に残す必要がある。

### (6) 次に検証すべきこと

`StatePathRouterBench` を作り、flat similarity retrieval / schema-only planner / state-path menu を比較。tool count、chain coverage、invalid call rate、completion、latency/token cost を測る。

### (7) 重要度

**A+** — router の精度をモデル大型化なしで上げる可能性が高く、現在の Kamimusuhi に比較的実装しやすい。

## 4.4 Adaptive Shared Control — 他者モデルを単一ラベルでなく確率分布として維持する

**Source:** Henry Ascencio Trejo, Roel Pieters, Gokhan Alcan, *Adaptive Shared Control with Online Bounded-Rational Human Behavior Estimation*, arXiv:2609.10215  
**Submitted:** 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10215  
**Importance:** **A**

### (1) 何が実証済みか

level-k bounded-rationality に基づく有限 human/robot policy bank を作り、実際の state transition と各 human-policy prediction の residual を forgetting factor 付きで蓄積して **human behavior distribution** を更新する。robot は最大確率の単一候補ではなく分布全体への expected cooperative cost を最小化する one-step best response を選ぶ。

nonlinear stabilization と planar manipulator の simulation で、推定 human distribution の KL divergence が低下し、max-probability / probability-weighted alternative より accumulated running cost が低いと報告する。

### (2) 何が提案・推測段階か

実人間との user study ではなく simulation。level-k policy bank が人間の会話・関係変化を十分に表現する証拠はない。

### (3) Kamimusuhi の関連サブシステム

- Theory of Mind / social cognition
- relationship belief state
- robot/shared control
- K-Nerve/K-Edge assistance
- uncertainty / decay

### (4) 借りられる設計・実装アイデア

```text
observed behavior
 -> residual against multiple person-model hypotheses
 -> decayed probability distribution
 -> action policy conditioned on distribution, not one guess
```

### (5) Kamimusuhiとの差分

Kamimusuhi の relationship memory は長期・言語的・社会的で、policy bank に閉じない。したがってこれは person identity の表現ではなく、**局所的な intent/behavior hypothesis layer** として使うべき。

### (6) 次に検証すべきこと

`ProbabilisticPartnerModelBench`:

- deterministic user label
- top-1 intent hypothesis
- probability distribution over hypotheses
- distribution + temporal decay

で interruption / assistance / clarification timing の regret、false intervention、adaptation latency を比較する。

### (7) 重要度

**A** — ToM を自由文の断定から、更新可能な不確実状態へ落とす具体例として有用。

## 4.5 RESCUE-BENCH — relationship-aware support は local emotion recognition より難しい

**Source:** Haichuan Hu et al., *RESCUE-BENCH: Towards Relation-Aware Multi-Party Emotional Support Conversation Systems*, arXiv:2609.09657

**Importance:** **A**

real couple / family interview をもとに **191 samples / 7,079 annotated turns / 1,064.8 minutes of video** を構築し、Relational Understanding と Relation-Sensitive Support の6 taskで10 LLMを評価した。

current models は local emotional cue / intervention cue を使う task では比較的良いが、**relation pattern prediction / viewpoint prediction / support strategy prediction** のような relation-intensive task で弱いと報告する。

### (2) 何が提案・推測段階か

benchmark が「良い長期 companion」の全要件を測るわけではない。文化差、長期 months/years の relationship drift、本人性/authorization は別問題。

### (3) Kamimusuhi の関連サブシステム

- relationship memory
- Theory of Mind
- multimodal perception
- social action / dialogue policy
- multi-party identity isolation

### (4) 借りられる設計・実装アイデア

relationship evaluation を factual recall だけでなく、`relation pattern / each person's viewpoint / intervention strategy` の三層に分ける。

### (5) Kamimusuhiとの差分

Kamimusuhi は一人の persistent individual として実関係を長期保持するため、benchmark の session-bound relation inference より provenance / consent / stale belief correction が重要になる。

### (6) 次に検証すべきこと

`RelationshipPerspectiveBench`:

- Aが言った事実
- Bが言った事実
- AについてBが抱くbelief

を分離した memory graph で、viewpoint leakage と unsupported relationship assertion を測る。

### (7) 重要度

**A** — relationship memory を「プロフィールRAG」から social cognition へ進める評価材料になる。

## 4.6 Procedural Memory Under Change — mismatch は直ちに interference を意味しない

**Source:** Yanze Cao, *Procedural Memory Under Change: Reuse and Interference in Controlled Web Tasks*, arXiv:2609.09774  
**Submitted:** 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.09774  
**Importance:** **A**

### (1) 何が実証済みか

stored procedure と current task の mismatch を、quantity change / evidence representation change / local-vs-global optimization conflict / distributed promotion evidence の4形式で controlled test。32 formal cells、qwen3:8b、temperature 0、adaptive retryなしの条件で、current-task evidence が explicit/sufficient な task では predefined diagnostic interference signature が観測されなかった。

これは **tested region of non-interference** であり「古い procedure が存在するだけで必ず害になる」という単純仮説への反証材料になる。

### (2) 何が提案・推測段階か

32 cells・単一 local model であり一般安全性は示さない。どの条件で memory-caused error へ転じるかは未解決。

### (3) Kamimusuhi の関連サブシステム

- procedural memory
- skill selection
- current-evidence grounding
- skill update / retirement

### (4) 借りられる設計・実装アイデア

`skill_version mismatch → 即 reject` ではなく、current task evidence の sufficiency と procedure の dependency を検査する。古い high-level routine が新interfaceでも再利用できる場合を残す。

### (5) Kamimusuhiとの差分

Kamimusuhi は Procedural Graphs / SkillAdam 型の自己更新も想定するため、「適用可能性の判定」と「skillを書き換える必要性」を別にする必要がある。

### (6) 次に検証すべきこと

`ProceduralApplicabilityInterferenceBench`:

- UI change only
- semantic precondition change
- hidden constraint change
- stale parameter embedded in skill
- current evidence complete/incomplete

を交差させ、memory-caused regression と unnecessary skill rewrite rate を測る。

### (7) 重要度

**A** — negative result だが、過剰な stale-skill invalidation を避けるため重要。

## 4.7 Subagents vs Agent Skills — reusable knowledge は内容だけでなく invoke topology が効く

**Source:** Wasu Top Piriyakulkij et al., *Subagents vs Agent Skills: Executing Reusable Knowledge for Long-Horizon Agentic Tasks*, arXiv:2609.09233  
**Submitted:** 2026-09-07; recent feedで再確認  
**Primary:** https://arxiv.org/abs/2609.09233  
**Importance:** **A**

### (1) 何が実証済みか

skill package を main agent の context に読み込んで従わせる方式と、skill ごとに fresh context を持つ subagent をspawnする方式を比較。**明確な input-output contract と必要な procedural knowledge を持つ skill** では subagent execution が agent-skill execution を上回ったと報告する。一方で inter-agent communication token overhead は増える。

### (2) 何が提案・推測段階か

常に subagent 化が勝つわけではなく、contract quality と task decomposition に依存する。persistent identity を subagent に分散すべきという証拠でもない。

### (3) Kamimusuhi の関連サブシステム

- K-Core / K-Deep delegation
- procedural memory
- Cognitive Action Router
- context budgeting
- specialist model/tool invocation

### (4) 借りられる設計・実装アイデア

skill に `instructions` だけでなく `input_schema / output_schema / side_effect_class / required evidence / execution_mode(main|subagent|code)` を持たせる。

### (5) Kamimusuhiとの差分

subagent は cognitive worker であり continuity-bearing self ではない。fresh context の利点を使いつつ、result attribution と authority は caller / runtime に残す。

### (6) 次に検証すべきこと

`SkillInvocationTopologyBench` で main-context skill / forked subagent / deterministic code / specialist model を同じ task suite で比較し、success、token、latency、context pollution、attribution error を測る。

### (7) 重要度

**A** — Kamimusuhi の「外部/内部 specialist を臓器として使う」実装選択に直結する。

## 4.8 DiffLUT-Net — learned LUT circuit を K-Nerve の比較対象へ

**Code:** https://github.com/TUDa-HWAI/DiffLUT-Network  
**Importance:** **B+**

### (1) 何が実証済みか

6-input LUT の64-entry truth table と各input portのsource connectivityを differentiable relaxation で共同学習し、学習後に離散化・unused logic prune・**synthesizable Verilog export** する FPGA-native network を提案。5 benchmark で accuracy-resource trade-off を報告する。

### (2) 何が提案・推測段階か

Kamimusuhi の temporal reflex、streaming event classification、long-running online adaptation で優位とは未証明。通常の tiny MLP/tree/FSM/DLGN/DWN より良いともまだ言えない。

### (3) Kamimusuhi の関連サブシステム

- K-Nerve
- learned discrete reflex layer
- FPGA / always-on edge processing
- sensory salience / event routing

### (4) 借りられる設計・実装アイデア

learned truth-table だけでなく **connectivity も学習 → prune → Verilog化**する pipeline を K-Nerve tournament に追加する。

### (5) Kamimusuhiとの差分

DiffLUT-Net は classifier/network substrate。Kamimusuhi が必要なのは persistent temporal control と fail-safe policy boundary なので、そのまま cognitive architectureにはならない。

### (6) 次に検証すべきこと

同一 sensor-event dataset で hand rules / tree / tiny MLP / DLGN / DWN / DiffLUT-Net を accuracy、p99 latency、LUT/FF utilization、energy、OOD failure、formal inspectability で比較する。

### (7) 重要度

**B+** — 即採用ではないが、既存 logic-gate watchlist と非常に相性の良い具体的 FPGA candidate。

## 4.9 Active inference and artificial reasoning — epistemic exploration を expected information gain で選ぶ

**Source:** Karl Friston, Lancelot Da Costa, Alexander Tschantz, Conor Heins, Christopher Buckley, Tim Verbelen, Thomas Parr, *Active inference and artificial reasoning*  
**Nature Communications:** published 2026-09-08, DOI: https://doi.org/10.1038/s41467-026-77209-5  
**Preprint:** https://arxiv.org/abs/2512.21129  
**Importance:** **B+**

### (1) 何が実証済みか

技術ノートは、候補 world-model / hypothesis の構造について不確実性を減らす outcome を選ぶ reasoning を、expected free energy の information-gain component と Bayesian Model Reduction で定式化し、partially observed discrete model の `three-ball` paradigm で例示する。2025年末の preprint が 2026-09-08 に peer-reviewed journal publication になった。

### (2) 何が提案・推測段階か

これは Kamimusuhi の長期 artificial individual で active inference が最良の control architecture である証拠ではない。例は小規模 discrete generative model であり、LLM agent / real-world embodiment に直接一般化できない。

### (3) Kamimusuhi の関連サブシステム

- default cognition / dream
- epistemic exploration
- active sensing
- uncertainty-driven deliberation
- K-Core/K-Deep experiment selection

### (4) 借りられる設計・実装アイデア

background cognition で「何を考えるか」を novelty だけでなく **どの action / simulation / query が competing hypothesis を最も識別するか**で選ぶ。

### (5) Kamimusuhiとの差分

現行 landscape の方針通り、active inference は一候補であり、homeostatic control や exploration をすべて free-energy language に統一しない。

### (6) 次に検証すべきこと

`EpistemicActionSelectorTournament` で random / uncertainty heuristic / information gain / expected-value / active-inference-style selector を、sensor query と sandbox experiment task で比較する。

### (7) 重要度

**B+** — 新規理論そのものではないが、peer-reviewed publication として dream/exploration の目的関数を比較する根拠になる。

## 4.10 Japanese discovery → Microsoft Copilot memory governance — use-disable と deletion は別

**Discovery:** note, *最新！AIエージェント情報 2026年9月10日号*  
https://note.com/vivid_quince2775/n/n5427ac76543f  
**Primary verification:** Microsoft Learn  
https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/memory-overview  
https://learn.microsoft.com/ja-jp/microsoft-365/copilot/copilot-personalization-memory  
**Importance:** **B**

### (1) 何が実証/公式仕様として確認できたか

日本語記事を discovery lead として追跡し、Microsoft Learn で product-specific memory lifecycle を確認した。

- Copilot Studio memory preview では user memories は user-private、28日 interaction が無い場合削除、Memory OFF は保存済み memory の削除ではなく **利用停止**。
- Microsoft 365 Copilot の管理資料では saved memory と chat-history-derived details は retention semantics が異なる。saved memory は user が明示削除するまで保持され、chat-history details は動的に更新/破棄されうる。source chats をすべて削除した場合、その情報の trace は7日以内に chat-history details から削除されると記載。
- Microsoft 365 Copilot の memory/personalization action は Purview audit log entry を生成しない、と公式管理資料に記載されている。

### (2) 何が提案・推測段階か

Microsoft の異なる Copilot product の policy を一つの統一 memory architecture とみなしてはいけない。また product policy の良し悪しをこの資料だけで判断できない。

### (3) Kamimusuhi の関連サブシステム

- memory lifecycle
- consent / privacy
- memory use-disable
- deletion / tombstone / archive
- auditability

### (4) 借りられる設計・実装アイデア

`ACTIVE_USE`, `RETAINED_BUT_DISABLED`, `PENDING_DELETE`, `DELETED_FROM_DERIVED_VIEW`, `CANONICAL_ARCHIVE` を別状態にし、UI toggle と physical deletion を同一視しない。

### (5) Kamimusuhiとの差分

Kamimusuhi は canonical evidence を保持する場合でも、relationship/privacy data には explicit retention policy が必要。また Microsoft のように memory action audit が欠ける設計は Kamimusuhi の provenance philosophy とは合わない可能性が高い。

### (6) 次に検証すべきこと

`MemoryUseVsRetentionAuditBench` で disable → retrieval不可、delete request → derived cache/index purge、archive retention → normal cognitionから不可視、audit receipt → 再現可能、を試験する。

### (7) 重要度

**B** — 研究成果ではないが、実サービスの memory governance で「使わない」と「消す」が分離されている concrete precedent。

## 4.11 Programmable Cellular Automata — local reflex と global coordination の境界を可視化する

**Source:** Ahmed Khalifa et al., *Programmable Cellular Automata*, arXiv:2609.06102  
**Submitted:** 2026-09-05; cs.NE recent で再確認  
**Primary:** https://arxiv.org/abs/2609.06102  
**Importance:** **B**

### (1) 何が実証済みか

cellular automata を Python code の local functions + decision function として modularizeし、さらに global function を許す構成を3つの PCG Benchmark game で評価。global functions により必要 iteration が減り、purely local functions だけでは solution を見つけられない task があったと報告する。

### (2) 何が提案・推測段階か

ゲーム level generation の結果であり、人工生命の自己維持や cognitive architecture の実証ではない。

### (3) Kamimusuhi の関連サブシステム

- K-Nerve local processing
- Global Workspace
- ALife-inspired distributed organization
- interpretable rule evolution

### (4) 借りられる設計・実装アイデア

local process だけで完結させることを美徳化せず、`local function -> compact summary -> occasional global coordination` という境界を benchmark する。

### (5) Kamimusuhiとの差分

Kamimusuhi は CA ではなく heterogeneous cognitive organs を持つ。価値は「local-only vs global-access」の計算構造を明示的に比較する点にある。

### (6) 次に検証すべきこと

salience / sensor fusion / resource-health routing task で local-only K-Nerve、periodic global-state read、always-global K-Core を latency / accuracy / bandwidth / failure containment で比較する。

### (7) 重要度

**B** — ALife/NE からの軽量な比較材料。architecture change を要求するほどではない。

## 10. Bottom line

今回の strongest design implication は次の4点。

```text
LLM says "I am X"
    != measured self-state

API/tool says "success"
    != verified world-state completion

relevant tool
    != executable prerequisite-complete tool path

best guess about a person
    != calibrated distribution over partner hypotheses
```

Kamimusuhi はすでに canonical evidence / identity / authority を model output から分離している。今回の研究はその原則を、**self-model、effect completion、tool planning、social cognition** の各 read/write boundary へ具体的な benchmark として伸ばせることを示している。
