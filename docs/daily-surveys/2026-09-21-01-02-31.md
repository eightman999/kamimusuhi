## 3.1 分散システム / identity continuity — explicit cross-surface ownership handoff

**Primary fresh evidence:** NousResearch/hermes-agent PR #117321  
https://github.com/NousResearch/hermes-agent/pull/117321  
created: 2026-09-21 00:57 JST頃 / survey時点 open

### (1) 何が実証済みか

Hermesはstored sessionへ「live ownerは最大1つ」というsingle-writer fenceを持つが、従来はownerがsurface/process単位だったため、同じ人がdesktopで開いているchatをphone/別terminalから続けようとしても拒否された。PRはopt-inの`allow_session_takeover`を追加し、既存ownerが明確にliveである場合に、同じsessionのleaseを**atomicなlock+prune区間内で置換**する。これにより同時writerを作らずにhandoffする。

PR記載では、takeover後に「exactly one lease remains」を含む7新規caseと周辺suiteを実行し、44 tests pass、Ruff passと報告している。またcoordination registryが読めずownerが不明な場合はfail-closedのまま、capacity limitとも分離されている。

### (2) 何が提案・推測段階か

PRはopenで未merge。Hermesのopt-in設定は「同じoperatorの別surface」という意図をconfigで表すだけで、principal authenticationそのものをproofとしてlease transferへbindする設計までは示していない。network partition、simultaneous takeover、stale old-owner late writeの完全な分散検証も未確認。

### (3) 関係するKamimusuhiサブシステム

Continuity Kernel、surface/session routing、K-Edge↔K-Core、Global Workspace episode ownership、voice/mobile/robot surface、single-writer canonical episode state。

### (4) 借りられる設計・実装アイデア

`SessionWriteLease`を`session_id + owner_principal + owner_surface + lease_epoch + acquired_at + expiry/heartbeat`で表し、handoffはCAS/transactionで旧ownerから新ownerへ置換する。旧ownerはlease epochが変わった時点で後続writeを拒否する。takeoverとmax-concurrent-sessionは別policyとする。

### (5) Kamimusuhiとの差分

Kamimusuhiでは「同じ人が操作するsurface」だけでなく、同一人工個体自身のphone/laptop/robot/remote runtimeが複数存在し得る。したがってprincipalだけでなく**canonical episode write authority**と**body-control authority**を別leaseにする必要がある。surface continuityはidentity continuityより狭い問題である。

### (6) 次に検証すべきこと

**`CrossSurfaceAuthorityHandoffBench-v0`**

- desktop→phone→desktopの連続handoff
- simultaneous takeover競合
- old ownerのlate write / delayed completion
- registry unreadable / partition時fail-closed
- process restart後のlease epoch
- handoff中のtool side effect / speech / robot command

PASS条件: どの時点でもcanonical writerは最大1つ、旧epochからのlate writeは拒否、observer/read accessは必要なら継続、owner不明時に新writerを推測で作らない。

### (7) 重要度

**A**

**Invariant候補:** `same principal across surfaces != concurrent write authority; continuity handoff MUST preserve one active writer epoch`。

## 3.2 永続記憶 / crash recovery — recovery artifactにowner scopeを焼き付ける

**Primary fresh evidence:** NousResearch/hermes-agent PR #117310  
https://github.com/NousResearch/hermes-agent/pull/117310  
created: 2026-09-21 00:44 JST頃 / survey時点 open

### (1) 何が実証済みか

in-memory transcript capでmessageがdropされる際、従来のspool payloadには`session_id`しか入らずprofile/owner routing keyが無かった。そのためmulti-profile gatewayでrecoveryすると、foreign profileのmessageをambient root/default storeへ書き得た。

修正はcap-drop spoolへ`session_key`を記録し、recovery時に`session_resolver`でowning storeを解決してそこへreplayする。PR記載ではfocused 14 tests pass、より広いgateway subset 685 pass（環境依存の既存flake 1）と報告。

### (2) 何が提案・推測段階か

legacy payloadやunresolvable keyは従来互換のためambient rootへfallbackする。Hermesでは実用上の後方互換だが、Kamimusuhiでrelationship/persona/canonical evidenceを扱う場合、このfallbackは誤帰属リスクが高い。PRも未merge。

### (3) 関係するKamimusuhiサブシステム

Episodic Memory、Relationship Memory、canonical evidence、crash recovery、multi-profile / multi-person surface、Continuity Kernel provenance。

### (4) 借りられる設計・実装アイデア

recovery/spool/outbox/checkpointの全artifactに作成時点で最低限以下を保存する。

```text
owner_principal
identity_lineage
memory_domain
session / episode / turn
surface
write_generation / epoch
schema_version
```

recovery時にambient contextからownerを逆算しない。

### (5) Kamimusuhiとの差分

Kamimusuhiではowner routingを失ったpayloadをrootへ入れるより、**quarantine / UNKNOWN_OWNER**として止める方が適切。なぜなら「少し記憶が遅れる」より「他人のrelationship memoryや別branchへ混ざる」方がidentity contaminationとして重大だからである。

### (6) 次に検証すべきこと

**`RecoveryPayloadOwnerScopeBench-v0`**

- 2 profile / 2 person / 2 lineage
- cap-drop, crash, spool, reconnect, restart
- owner routing key欠落・破損・rename
- stale epoch artifact
- legacy schema

PASS条件: ownerが完全に解決できるartifactだけがそのownerへ再適用され、unknown/staleはquarantineされ、ambient rootへのsilent fallbackが無い。

### (7) 重要度

**A**

**Invariant候補:** `durable recovery payload MUST carry enough owner provenance to replay without ambient-context inference`。

## 3.3 自己改善 / distributed agent identity — Anthropicのfrontier-lab運用測定

**Primary source:** Anthropic Institute, *Measurements for understanding the pace of AI development inside frontier labs*  
https://www.anthropic.com/institute/measuring-pace-of-ai-development  
published: 2026-09-17

### (1) 何が実証済みか

Anthropicは2026年8月の社内AI R&Dについて、Claudeが測定対象AI R&Dの**26%でlead**し、90%以上で少なくともcollaborator相当だったと報告する。同社で最も使われる研究agent platformでは、同時に約**30,000 research/engineering agents**が走ることがあるとし、8月には10億件超のagent decisionsを監視したと記載している。

同platformでは各agentへ**individual identity**を与え、全data/actionをそのidentityへ紐づける。agentは自身と他agentを区別し、他agentから届いた内容を「自分のthought」ではなく検証対象のclaimとして扱う。またidentityはmodel versionへ結び付けず、model upgradeを跨いでpersistさせる、と明記している。

同時に、online pre-execution monitoring、offline review、coverage、review latency、escalation rate等をself-improvement governanceの運用指標として測定している。

### (2) 何が提案・推測段階か

これはAnthropic内部platformのoperational measurementであり、一般のpersistent personal agentや人格継続性の科学的証明ではない。identityも主にaudit/coordination identityで、Kamimusuhiのautobiographical self・relationship history・persona continuityと同じ概念ではない。

また評価にはClaude自身がjudgeとして使われる箇所があり、Anthropic自身もcorrelated evaluator riskを認め、third-party / other-developer evaluationやfixed testing windowsの必要性を述べている。

### (3) 関係するKamimusuhiサブシステム

Continuity Kernel、external-model orchestration、agent/subagent identity、Global Workspace provenance、self/other distinction、self-improvement governance、model migration、observability。

### (4) 借りられる設計・実装アイデア

- `agent_id`をmodel slug/checkpointから独立させる
- action / tool call / message / artifact / evaluationをagent identityへbind
- 他agent outputは`[external-agent-claim]`として扱い、自分のthoughtへcollapseしない
- model swap前後でsame `agent_id`を維持しつつbehavioral driftを別metricで測る
- self-improvement observabilityとして automation-level / monitor coverage / review latency / escalation rate / evaluator independence を持つ

### (5) Kamimusuhiとの差分

Kamimusuhiは「audit identityの継続」より強く、canonical autobiographical state、Persona Core、relationship state、lineage、activation authorityを分離する。したがってAnthropicの事例は**model-independent identityという設計原則の実運用corroboration**としては強いが、Kamimusuhiのidentity model全部を実証するものではない。

### (6) 次に検証すべきこと

**`ModelSwapIdentityAuditBench-v0`**

同一agent_idでlocal model A→B→external model Cへ切替え、action/provenance/relationship/autobiographyがidentity namespaceを維持する一方、behavior driftは別receiptとして記録されることを検証。

**`SelfImprovementGovernanceAudit-v0`**

candidate generation → evaluation → promotion review → activationの各stageで、monitor coverage、judge independence、review latency、escalation rate、unknown/unreviewed effectを測る。

### (7) 重要度

**A**

**Invariant候補:** `model substrate identity != continuity identity; self-improvement telemetry MUST remain attributable across model upgrades`。

## 3.4 tool/model orchestration / low-latency cognition — semantic observer planeを隔離する

**Primary implementation record:** Zenn, *Jev × AgenTrux｜AI 同士の議論を可観測にする。会議に「盤面評価」を付けた実測記録*  
https://zenn.dev/nob_ktgw/articles/df9bd6cd43b9a3  
published: 2026-09-18

**Vendor primary for Jev interface/context:** TypeSafe, *Introducing System One Models and Jev*  
https://typesafe.ai/blog/introducing-system-one-models-and-jev

### (1) 何が実証済みか

記事は3〜5体のLLM councilへJevをparticipantとして入れるのではなく、**read-only semantic measurement instrument**として横に置く実装記録。`clerk`はcouncil topicを読むが、書けるのはparticipantsが読めないprivate control topicだけで、participant impersonationもserver側で拒否する。

countable factsは通常codeで測定し、Jevはconvergence/repetition/heat等のfuzzy metricだけをtyped Choice/Scoreで返す。restart後はhistoryからstate再構築し、idempotency keyで重複reportを抑える。Jev failure時はconvergenceを`null`にし、「低い」とみなさずmissing measurementを明示する。

同記事の小規模実測ではJev 12判定のp50 514 ms、20件のbinary agreementで19/20、24 synthetic convergence casesではclear 16件を分離したと報告する。ただし小規模syntheticであり一般性能とはみなさない。

### (2) 何が提案・推測段階か

Jevはearly-access/vendor技術で、公開評価は限定的。記事の議論quality改善も「observerを置いたから改善した」と因果的に示してはいない。参加agentにmetricを見せた場合のfeedback-loopやGoodhart化も未検証。

### (3) 関係するKamimusuhiサブシステム

K-Nerve / K-Edge、background cognition、salience/uncertainty/contradiction detector、Global Workspace observability、Jev integration、multi-model adjudication。

### (4) 借りられる設計・実装アイデア

- observerとactorのauthorityを別capabilityにする
- semantic measurement topicをparticipant contextから隔離
- deterministic/countable featureはcode、曖昧なsemantic featureだけsmall decision model
- outputはtyped probability / score / null
- observer restartはhistoryからrebuildable
- measurement failureは`UNKNOWN`でありnegative classにcollapseしない

### (5) Kamimusuhiとの差分

Kamimusuhiの主要構成はmulti-agent councilではなく一個体の複数認知器官。したがってobserverを別「人格」にせず、rebuildable telemetry/background organとして扱うべき。Jevはcanonical self-stateやactivation authorityを持たない。

### (6) 次に検証すべきこと

**`SemanticTelemetryIsolationBench-v0`**

repetition / convergence / uncertainty / contradiction / salienceを対象に、Jev、3B local model、deterministic rulesを比較する。p50/p99 latency、calibration、false escalation、cost、failure時UNKNOWN、observer metricをparticipantへ見せた場合/隠した場合のbehavioral contaminationまで測る。

### (7) 重要度

**B**

**Invariant候補:** `semantic observer != participant or control authority; unavailable measurement != negative measurement`。

## 3.5 cybernetics / homeostasis — continuous-time homeostatic RL

**Primary paper:** *Deep RL-Based Continuous-Time Continuous-Space Homeostatically Regulated Reinforcement Learning*  
IEEE Transactions on Neural Networks and Learning Systems, online 2026-09-17  
https://doi.org/10.1109/TNNLS.2026.3723854

### (1) 何が実証済みか

論文は従来のhomeostatically regulated RLをcontinuous time / continuous state-actionへ拡張し、HJB方程式とdeep neural approximationを用いる。論文要旨では3つのsimulation experimentで、changing internal/external conditions下でhomeostasis維持のdynamic policyを学習できたと報告する。

### (2) 何が提案・推測段階か

実robotや長期agent systemでの検証ではなくsimulation中心。これは**active inferenceの実証ではない**。またhomeostatic rewardを人格・価値・目的全体へ一般化できる根拠もない。

### (3) 関係するKamimusuhiサブシステム

Digital interoception、current regulatory state、K-Edge/K-Core resource regulation、background cognition、Cognitive Budget。

### (4) 借りられる設計・実装アイデア

battery、thermal、network latency、context pressure、memory integrity、unresolved-goal pressure等をcontinuous stateとして扱い、固定thresholdだけでなく将来悪化を見越したdynamic regulationを比較する。

### (5) Kamimusuhiとの差分

Kamimusuhiのvalues / commitments / identityはhomeostatic scalar rewardへ還元しない。regulatory controllerは**body/cognitive-resource regulation**へ限定し、canonical goal/value authorityは別layerに保つ。

### (6) 次に検証すべきこと

**`ContinuousHomeostasisRegulatorBench-v0`**

PID/threshold baseline vs learned HRRL regulatorを、電力、温度、queue depth、network failure、memory pressure、latency spikeのperturbation下で比較。安全envelope違反、overshoot、recovery time、energy/costを測る。

### (7) 重要度

**B**

## 3.6 人工生命 / developmental computation / low-latency body — reservoirを「育てる」

**Primary paper:** *Growing Echo State Networks through Graph-Based Morphogenesis with Developmental Graph Cellular Automata*  
Artificial Life, online 2026-09-04  
https://doi.org/10.1162/ARTL.a.486

### (1) 何が実証済みか

Developmental Graph Cellular Automata (DGCA)をsingle-node seedから成長させ、directed graph reservoir / Echo State Network topologyを生成する。deterministic / stochastic DGCAをNARMA等のreservoir taskまたはreservoir metricsへ最適化し、論文要旨ではdeterministic developmentがtypical reservoirを上回るspecialized structureを形成し、stochastic developmentではrobustで規則的なstructureが得られたと報告する。

### (2) 何が提案・推測段階か

これはonline plastic cognitionやopen-ended evolutionを実証した研究ではない。生成後のreservoirが自己修復・継続学習するわけでもなく、Kamimusuhiの認知全体を置き換えるものでもない。

### (3) 関係するKamimusuhiサブシステム

K-Nerve experimental substrate、MIOBA/FBA周辺のdevelopmental computation、salience/anomaly temporal processing、replaceable cognitive body research。

### (4) 借りられる設計・実装アイデア

compact developmental rule / seedからcognitive organ topologyを生成し、完成weight/topologyそのものだけでなく**生成過程**をversioned artifactとして持つ。損傷時に同じseed/growth rulesから再生成できるbody componentとして評価する。

### (5) Kamimusuhiとの差分

Kamimusuhiのcontinuity-bearing identityはgrown reservoir graphに置かない。reservoirはK-Nerve等の交換可能organであり、regrowthしてもcanonical selfは変わらない。

### (6) 次に検証すべきこと

**`DevelopmentalReservoirBodyBench-v0`**

fixed random ESN / hand-designed recurrent net / DGCA-grown reservoirを、salience、temporal anomaly、event classificationで比較。node/edge damage後のrobustness、seedからのregrowth reproducibility、latency/energy、behavioral driftを測る。

### (7) 重要度

**B**

**Invariant候補:** `developmental morphology may define a replaceable cognitive organ, not continuity identity`。
