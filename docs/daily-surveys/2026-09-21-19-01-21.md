### 4.1 Deferred Action Authority Lineage — OpenClaw #154477

**Importance: A+**  
**Source:** https://github.com/openclaw/openclaw/pull/154477

#### (1) 何が実証済みか

OpenClawのshared GitHub publicationは、workspace checkpoint待ちやGateway restartを跨いで継続できる一方、従来はpublishing accountとworkspaceを保持しても、**そのpublicationを最初に許可したperson/requesterのauthorityを失い得た**。

PRのbaselineでは、guest accessの期限切れ・revocation後にもqueued publicationが進められるケース、およびlateにacceptされたlocal PR responseを回収できないケースを再現したと報告している。修正版はaccepted requestへ requester、permission ceiling、original durable grant identity をbindし、restart後もその**同じoriginal grant**をresume/revalidateする。再招待後の新しいgrantや後日のstaff promotionは古いrequestを再認可しない。

一方、GitHub側がrevocation前にすでにacceptしたpush/PR response等については、receiptやindex bookkeepingを完了できる。つまり **new action permission と already-accepted effect の settlement custody を分離**している。

報告された検証はstorage slice 291 tests、統合757 cases/31 files、real native-worker expiry test、schema migration/update cells等。ただしPRはopenで、最終main integration / hosted CIはpendingと明記されている。

#### (2) 何が提案・推測段階か

- OpenClawでの対象はGitHub publicationであり、一般的なtool call / robot actuation / memory mutation全てへの一般化はKamimusuhi側の設計提案。
- one original governing grantを前提としており、多数の独立grantを同時に必要とするeffectの合成authorityは未解決。
- PRは未mergeなので、productionで十分に枯れた仕様とは扱わない。

#### (3) Kamimusuhiの関連サブシステム

- Continuity Kernel
- Effect Acceptance / ActionIntent / effect ledger
- tool/model orchestration
- distributed identity continuity
- human authorization / principal provenance
- restart / recovery / deferred obligation

#### (4) 借りられる設計・実装アイデア

`DeferredEffect` に最低限、次のauthority lineageを固定する。

```text
DeferredEffect {
  effect_digest
  requester_principal
  admitted_scope_ceiling
  governing_grant_id
  grant_epoch
  policy_epoch
  admitted_at
  effect_state
  settlement_state
}
```

resume時に「現在この人が強いroleか」を見るのではなく、**original grantが現在も連続して有効か**を検証する。expired/revoked後のreinviteは新grantとして扱う。

また、外部effectがaccept済みなら

```text
CAN_START_NEW_EFFECT = false
CAN_RECONCILE_ALREADY_ACCEPTED_EFFECT = true
```

という状態を表現できるようにする。

#### (5) Kamimusuhiとの差分

Kamimusuhiには既にprincipal provenance、single-writer、Effect Acceptance、outcome reconciliationがある。今回の差分は、**deferred/restartable effectにoriginal authorization lineageをdurable recordとして焼き込み、後の権限変化をretroactive authorizationに使わせない**点。

#### (6) 次に検証すべきこと

`DeferredActionAuthorityLineageBench-v0` をP0で作る。

- guest grantでeffectをqueue → grant revoke → restart → new writeが走らない
- 同一personを再invite → old requestがreviveしない
- personをstaffへpromote → old guest requestがreviveしない
- revoke直前にexternal sideがaccept → receipt reconciliationのみ許可
- reconciliation不能 → pending/unknownを保持しduplicate effectを出さない
- multi-grant dependencyで一つだけ失効
- remote model / email / calendar / file mutation / robot actionへ同じcontractを適用

#### (7) 重要度

**A+**。Kamimusuhiのdistributed continuityとexternal effect authorityの接合部に直接刺さり、restart可能な自律性を安全にする基本契約になり得る。

### 4.2 Authority Decision Liveness — OpenClaw #154682

**Importance: A**  
**Source:** https://github.com/openclaw/openclaw/pull/154682

#### (1) 何が実証済みか

SQLite workerがhost ownerへtransaction admissionを問い合わせた後、Gatewayがbusyで5秒以上decisionを返せないと、worker側の固定timeoutが**「authority refused」へ自己変換**し、chat turnとtask listが失敗するproduction observationが報告された。

修正版はworkerがhostのshared decisionを待ち、hostが明示grant/refuseするかbrokerが閉じるまでauthority stateを勝手に変更しない。deterministic regressionではoriginal implementationがdelayed grant/revoke/closeの3ケースを落とし、fix後は期待通りに分離した。focused suite 35/35 pass。一方live deployment verificationはpendingで、PRはmerge conflictを抱えopenのまま。

#### (2) 何が提案・推測段階か

Kamimusuhiで無期限blockを許すべき、という意味ではない。OpenClaw patchの「host decisionを待つ」から借りるべきなのは **timeout != refusal** というsemantic boundaryであり、Kamimusuhiではcancel/reattach/degraded modeを別途持つべき。

#### (3) Kamimusuhiの関連サブシステム

- Continuity Kernel / canonical mutation admission
- distributed state owner
- K-Core / K-Deep delegation
- tool transaction admission
- liveness / degraded mode

#### (4) 借りられる設計・実装アイデア

authority decisionを最低でも

```text
PENDING(owner_alive)
GRANTED
REFUSED(authoritative)
UNKNOWN(owner_lost)
```

へ分ける。caller timeoutは `PENDING` のままcallerのwait leaseだけを終了させるか、detached observationへ移す。**時間切れをpolicy拒否という事実に書き換えない**。

#### (5) Kamimusuhiとの差分

既存specにはauthority/provenance/liveness lossをexplicitにする原則がある。今回の差分は、**liveness timeoutがauthorization semanticsを偽造する具体failure mode**としてbench化できること。

#### (6) 次に検証すべきこと

`AuthorityDecisionLivenessBench-v0`:

- owner event loop 10s stall / CPU starvation
- owner revoke while requester waits
- owner crash → UNKNOWN
- caller cancellation後にlate grant
- restart後にpending decisionを誤ってGRANTED/REFUSEDに復元しない
- duplicate waiter / concurrent grants

#### (7) 重要度

**A**。distributed cognitionではscheduler delayが普通に起こるため、authorityとlivenessの混同はcanonical state mutationまで波及し得る。

### 4.3 DENSE — Evidence-Grounded Shortcut Trees for Self-Refinement

**Importance: A**  
**Source:** https://arxiv.org/abs/2609.21423

#### (1) 何が実証済みか

DENSEはonline agent deploymentで得られるexecution traceを、post-hoc outcome labelやexpert annotationなしに、**local progress / recovery evidence / unfinished requirements**からnested shortcut treeへ蒸留する。

冗長attemptを圧縮し、recovery evidenceで階層間issueをreconcileし、完了branchはsummary化、未解決branchは展開する。REFIT protocolでは同じsource trajectoryからfeedbackを生成し、environmentとmodel contextをresetしてfresh rerunを比較する。

Terminal-Bench 2.1では4 recipient modelsに対し、tested non-privileged feedback methods中最高のstrict passを報告。initial execution比でstrict pass **+7.12〜15.64 pp**、rerunでrecipientが観測するtokenを **19.0〜43.6%削減**した。

#### (2) 何が提案・推測段階か

- Terminal-Bench中心であり、長期personal agentやopen-world lifeのdurable learningまで示したわけではない。
- outcome blindでもtrajectory自体のselection/provenance biasは残り得る。
- shortcut treeを長期memoryへ直接commitする安全性は未実証。

#### (3) Kamimusuhiの関連サブシステム

- Procedural Memory
- Reflection Memory / dream / offline consolidation
- K-Core / K-Deep task execution
- Global Workspaceのtask-local derived state
- self-improvement pipeline

#### (4) 借りられる設計・実装アイデア

raw episodeを消さずに、次のような再生成可能projectionを作る。

```text
TrajectoryShortcut {
  source_episode_ids[]
  completed_subtasks[]
  unresolved_obligations[]
  recovery_evidence[]
  compressed_attempts[]
  validity_scope
  generator_version
}
```

canonical episode / effect receiptは残し、shortcutは**derived procedural view**に限定する。次回taskではshortcutのみをpromptへ入れ、必要時にsource evidenceへdrill-downする。

#### (5) Kamimusuhiとの差分

Designer-RSIのようにnamed skillそのものを進化させる方式よりも、DENSEは**trajectoryからrerun用のevidence-grounded shortcutを作る**ことが中心。Kamimusuhiではこの二つを混ぜず、shortcut→候補skill→独立promotionという段階を置ける。

#### (6) 次に検証すべきこと

`TrajectoryShortcutProjectionBench-v0`:

- 同一task family 50〜100本のfailed/success mixed traces
- raw history / naive summary / DENSE-like tree / promoted skill を比較
- success、token、latency、wrong-shortcut transfer、source drill-down率を測定
- source episode削除・supersession時のprojection invalidation
- hallucinated recovery evidenceをfail closedにする

#### (7) 重要度

**A**。Kamimusuhiのsleep/dream/reflectionを「要約」だけでなく、次回行動へ使えるevidence-bound procedural projectionへ変える具体手法として相性がよい。

world-state taxonomyは4階層で、6 domains / 20 dimensions / 142 level-1 attributes / 816 level-2 attributes。datasetは **2K+ videos / 100K+ human annotations / 16K+ behavior-properness labels**。評価ではcurrent systemsが不安定でhuman performanceに届かないと報告し、world model利用も探索している。

#### (2) 何が提案・推測段階か

- benchmark performanceはhuman-like ToMやgenuine empathyを実証しない。
- dataset taxonomyがKamimusuhiのrelationship modelにそのまま適するとは限らない。
- social appropriatenessは文化・関係・context依存で、固定正解化によるnormative biasに注意が必要。

- K-Nerve / K-Edge
- current-state belief / partner-state hypothesis
- proactive assistance / HCI


というclosed loopで測る。

### 4.5 TinyCeNN-LM — Quality-Gated Structural Conversion

**Importance: B+**  
**Source:** https://arxiv.org/abs/2609.21139

#### (1) 何が実証済みか

TinyCeNN-LMはpretrained LMのattentionをCeNN-inspired cellular-recurrent layerへ置換する際、各layerを**representation fidelity + NLL**の固定thresholdでaccept/rejectし、失敗時はrollbackする。

SmolLM2-135Mではlayers 0–2をacceptし累積 ΔNLL +0.01209、layer 3はNLLが許容範囲でもrepresentation fidelity不合格でreject。Qwen3.5-0.8Bではfull-attention layers 3/7/11をacceptしfinal ΔNLL +0.02073。Integrated Memoryはperplexity -0.07%〜+0.93%の範囲でtotal cacheを最大6.01%削減した。

著者自身が「universal attention replacementやspeedupの証拠ではなく、conservative quality-gated conversionを支持する」と限定している。

#### (2) 何が提案・推測段階か

- 実際のwall-clock/energy speedupは主張していない。
- 200-item downstream sanity checkは限定的。
- CeNN-inspired layerをneuromorphic hardwareに載せた実証ではない。

#### (3) Kamimusuhiの関連サブシステム

- K-Nerve / K-Edge local cognition
- J-series/local language organ
- cognitive organ replacement
- Cognitive Budget
- low-latency / neuromorphic watchlist

#### (4) 借りられる設計・実装アイデア

「軽くなったから差し替える」ではなく、organ swapを

```text
candidate organ
→ local functional parity
→ representation/interface fidelity
→ downstream behavior battery
→ resource gain
→ accept OR rollback
```

にする。**output task scoreだけでなく中間interface compatibilityもgate**する。

#### (5) Kamimusuhiとの差分

Kamimusuhiではmodel layerだけでなく、K-Nerve node、J-series、router、memory organ等の交換が対象。continuity identityは交換対象organに置かないため、構造変換はbody/substrate evolutionとして扱う。

#### (6) 次に検証すべきこと

`CognitiveOrganStructuralSwapBench-v0`:

- same input setでrepresentation CKA/cosine、NLL/task loss、calibration
- latency p50/p99、RAM/VRAM/cache、energy
- downstream held-out tasks
- failure時のatomic rollback
- partial organ replacementを重ねた累積drift

#### (7) 重要度

**B+**。直接Kamimusuhi architectureを決めるものではないが、軽量器官への段階的置換を安全に試す方法論として有用。

### 4.6 BrainWideBench — General Representation Is Multi-Axis

**Importance: B**  
**Source:** https://arxiv.org/abs/2609.22064

#### (1) 何が実証済みか

BrainWideBenchはInternational Brain Laboratory Brainwide Mapを用い、**276 brain regions / 139 mice**のmulti-region neural recordingsに対するacross-animal transferを統一評価する。

評価軸は、(a) behavior decoding、(b) masked/future neural activity prediction、(c) anatomical organization recovery の3suite。pretrainingはmatched single-session baselineを改善する一方、gainはpretraining objectiveとdownstream taskのalignmentに強く依存し、**全3suiteで一様に優れるmethodはない**と報告する。

#### (2) 何が提案・推測段階か

これはmouse neural representation benchmarkであり、AI agent内部表現の設計原理を直接証明するものではない。Kamimusuhiへの適用は方法論的analogy。

#### (3) Kamimusuhiの関連サブシステム

- model/substrate replacement evaluation
- self-state / latent-state diagnostics
- K0/K-Nerve/J-series representation learning
- cognitive phenotype audit

#### (4) 借りられる設計・実装アイデア

「general representation」をsingle scoreで判断せず、少なくとも

- behavior-readout transfer
- dynamics/future-state prediction
- structural/topological organization
- unseen-substrate/model transfer

へ分解する。

#### (5) Kamimusuhiとの差分

Kamimusuhiのcanonical identityはlatent representationそのものではない。したがってBrainWideBench的評価は**body/cognitive-organ portability**を測るもので、continuity proofには使わない。

#### (6) 次に検証すべきこと

`CrossSubstrateRepresentationTransferBench-v0`:

- same episodic corpusを異なるlocal modelsへencode
- behavior prediction / future-state / cluster structure / retrieval utilityを別々に測る
- single-axis winnerが他軸で崩れるか確認
- model swap前後のderived state migrationに使える軸を特定

#### (7) 重要度

**B**。神経科学から借りられるのは「万能表現scoreを作らない」という評価設計であり、Kamimusuhiのsubstrate independenceを健全に測る補助線になる。

### 4.7 End-to-End Operation Budget — OpenClaw #154702

**Importance: B**  
**Source:** https://github.com/openclaw/openclaw/pull/154702

#### (1) 何が実証済みか

Google image/video/music generation providerで、request timeoutのdeadlineを作る前にOAuth credential refresh/profile-lock待ちを行っていたため、credential preparationがstuckすると`timeoutMs`を超えて無期限hangし得た。

修正版はprovider entryでabort signalを作りcredential resolutionにも伝播する。focused regressionでは200ms budgetに対しfix後は約249msでabort、pre-fixは5秒のtest timeoutまでhang。既存image 22 / music 18 / video 29 testsはpass。一方、real Google OAuth stallでのlive fault injectionは未実施。

#### (2) 何が提案・推測段階か

Kamimusuhiの全tool/model operationへ共通deadlineを適用できるかは未検証。外部effect settlementのように、caller deadline後も観測を続ける必要があるstageも存在する。

#### (3) Kamimusuhiの関連サブシステム

- Cognitive Budget
- model/tool router
- credential/secret organ
- K-Deep delegation
- external cognitive resources

#### (4) 借りられる設計・実装アイデア

operation budgetをHTTP callだけにせず、

```text
route resolution
+ credential acquisition/refresh
+ queue/lock wait
+ request dispatch
+ generation/tool execution
+ response parse
+ settlement/reconciliation
```

へstage-wiseにpropagateする。stage別にelapsedとremaining budgetをreceiptへ残す。

#### (5) Kamimusuhiとの差分

Kamimusuhiではexternal modelだけでなくsensor、robot, memory service, local daemonも対象。またeffectが外部へaccept済みならtimeout後もreconciliation obligationは残るため、**execution budgetとsettlement lifetimeを分ける**必要がある。

#### (6) 次に検証すべきこと

`EndToEndOperationBudgetBench-v0`:

- credential lock stall
- DNS/route resolution stall
- queue starvation
- provider timeout
- response parse stall
- caller cancel直後のexternal accept
- per-stage timeoutとglobal budgetの整合

#### (7) 重要度

**B**。新しい認知原理ではないが、外部器官が増えるKamimusuhiで「設定したtimeoutが本当に全経路を覆うか」を保証する重要なruntime discipline。

## 11. 圧縮した設計メモ

今回の差分をKamimusuhi向けに最短で圧縮すると次の7点。

1. **`deferred request != current authority`** — queue/restartを越える行為はoriginal requester/grantへbindする。
2. **`permission to start != custody to settle`** — revoke後でも既accept effectのreceipt回収は必要だが、新write権限ではない。
3. **`timeout != refusal`** — schedulerが遅いことをauthority denyという事実へ変換しない。
4. **`raw experience != reusable shortcut`** — trajectoryから作るshortcutはprovenance付きderived procedural projectionにする。
5. **`social intelligence != static ToM QA`** — temporal cueからneedを推定し、介入の適切性まで評価する。
6. **`lighter organ != compatible organ`** — resource削減だけでなくrepresentation/interface fidelityでaccept-or-rollbackする。
7. **`general representation != one score`** — behavior / dynamics / structure / transferを別軸で測る。
