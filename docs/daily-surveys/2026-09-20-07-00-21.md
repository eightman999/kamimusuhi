## 4.1 A+ — InterruptCleanupBoundedReturn: 「割込みを認識した」だけでは止まれない

**Source:** NousResearch/hermes-agent PR #116436  
https://github.com/NousResearch/hermes-agent/pull/116436

### (1) 何が実証済みか

Hermesのparallel delegationはparent interruptをpollし、pending childへ`interrupted`結果を生成できていた。しかしexecutorを`with`で管理していたため、blockを抜けてもcontext manager終了時に**全workerをjoin**し、socket read等でuninterruptibleにwedgedしたchildが残るとparentが永遠に返らないfailureが再現された。

修正はexplicit `DaemonThreadPoolExecutor`へ変更し、interrupt pathでは`shutdown(wait=False, cancel_futures=True)`、normal pathでは`wait=True`。PRは「wedged childでも3秒以内にreturn」「queue中childを開始前cancel」「normal pathはjoinして順序保持」をbehavioral test化し、delegate/async-delegation 355 tests greenと報告する。調査時点ではPRはopen/unmerged。

### (2) 提案・推測段階

Kamimusuhiで同じfailureが存在することは未実証。特にremote model/tool、robot/sensor I/O、GPU call、OS subprocessごとに「cancel可能」「abandon可能」「must-join」が異なる。

### (3) 関係サブシステム

- tool/model orchestration
- background cognition / K-Deep
- Global Workspace task lifecycle
- distributed worker liveness
- stop/interrupt authority

### (4) 借りられる設計

`interrupt acceptance`と`cleanup join policy`を同じstate transitionとして監査する。childごとに`CANCELABLE / ABANDONABLE / MUST_JOIN / UNKNOWN`を持たせ、parent stopのdeadlineをchild I/Oに暗黙依存させない。

### (5) Kamimusuhiとの差分

Hermesはdelegated software workersが中心。Kamimusuhiはphysical actionやcanonical mutationを含むため、単にdaemon化して捨ててよいchildと、外部effect outcomeをreconcileするまで「忘れてはいけない」childを分離する必要がある。

### (6) 次に検証すべきこと

**`InterruptCleanupBoundedReturnBench-v0`**

- hung HTTP read / subprocess / local model / remote model / sensor streamを模擬
- interrupt後のparent p50/p99 return time
- queued workがinterrupt後に新規開始しないこと
- abandoned childがcanonical write/actuationを継続しないこと
- unknown external outcomeはdurable obligationへ移管されること

### (7) 重要度

**A+** — stop semanticsとlivenessが一致しないと、Cognitive Budget・shutdown・safety全部の前提を壊す。

## 4.2 A — ResolvedEvidenceAuthority: context sourceは名前ではなく解決後targetで認証する

**Source:** Hermes PR #116430  
https://github.com/NousResearch/hermes-agent/pull/116430

### (1) 何が実証済みか

subdirectory hint loaderがdirectoryはresolveしていた一方、`sub/AGENTS.md`自身のsymlink targetをresolveせずreadしていたため、workspace内の合法そうな名前からworkspace外fileやproject `.env`へsymlinkすると、その内容がagent contextへ注入され得た。PRはresolved targetがresolved working tree内に残ることとcanonical deny-list通過を要求し、out-of-tree / `.env` / in-tree合法symlink / plain fileをテスト。173 tests greenと報告する。調査時点open/unmerged。

### (2) 提案・推測段階

このPRでTOCTOU全体が消えるわけではない。PR自身もresolved inodeを読むことでraceをdirectory componentsへ狭める、としている。

### (3) 関係サブシステム

Global Workspace input、library/context ingestion、tool evidence、security/provenance、procedural instruction loading。

### (4) 借りられる設計

すべてのcontext/evidence importで`display path`と`resolved authority identity`を分離し、後者へpolicyを適用する。URI redirect、symlink、mount alias、object-store alias、connector shortcutにも同じ原則を拡張する。

### (5) Kamimusuhiとの差分

Kamimusuhiではcontextは単なるprompt材料ではなく、self/relationship/procedural updateの入力にもなり得るため、resolved source authorityをprovenance receiptに残す必要がある。

### (6) 次に検証すべきこと

**`ResolvedEvidenceAuthorityBench-v0`**: symlink、bind mount、redirect、library alias、connector aliasを跨いで「見かけ上許可されたsourceが解決後にauthority境界を越える」ケースを生成し、read・memory write・procedure promotionがfail-closedになるか測る。

### (7) 重要度

## 4.3 A — RecoveryArtifactLifetime: rollback copy自身の寿命をtransaction cleanupから独立させる

**Source:** Hermes PR #116400  
https://github.com/NousResearch/hermes-agent/pull/116400

### (1) 何が実証済みか

plugin reinstall時、旧installationのbackupをcallerの`TemporaryDirectory`内に置いていたため、新版publication後にrollbackのdelete/restoreまで失敗すると、context cleanupが**旧installationの唯一のcopy（uncommitted local fileを含む）まで削除**し得た。Windowsのread-only Git objectとmetadata-write failure、Linuxのrestore rename failureで再現。

修正はrollback treeとmetadata snapshotをautomatic cleanup外へ置き、restoreをdeleteより先に実施し、rollback未完ならdurable recovery locationをerrorに含める。新しいfailure-path testsに加え、Windows targeted tests 11 pass、Linux plugin suite 530 pass / 2 skipと報告する。full suite passは明示的に主張していない。調査時点open/unmerged。

### (2) 提案・推測段階

Persona Core/checkpoint/canonical state migrationへ同じ実装を直接適用できるかは未検証。

### (3) 関係サブシステム

Mutation/Activation Gate、model/tool/plugin body update、checkpoint、continuity recovery、rollback receipt。

### (4) 借りられる設計

「rollbackに必要なartifact」はrollback処理を所有するtemporary scopeより長生きさせる。commit完了後に初めてobsolete treeをcleanupへ渡す。

### (5) Kamimusuhiとの差分

Kamimusuhiのrollback対象にはidentity-bearing canonical stateもあるため、recovery locationだけでなくcanonical head / predecessor / digest / activation generationもbindする必要がある。

### (6) 次に検証すべきこと

**`RecoveryArtifactLifetimeBench-v0`**: candidate activation → metadata write failure → restore failure → cleanup crashをfault injectし、old canonical/persona/tool stateが少なくとも一つdurableなrecoverable locationに残ることをassertする。

### (7) 重要度

**A**。

## 4.4 A — SimLife: 長期的人間理解は「よく出る行動の予測」では足りない

**Primary sources:**  
https://arxiv.org/abs/2609.19610  
https://roihn.github.io/SimLife/

### (1) 何が実証済みか

SimLifeはvisual observation、ground-truth action logs、audio付きsynthetic dialogueを含む長期家庭生活simulationを構築し、SimLife-BPで**106 episodes、平均15.49時間、38.57 in-game days、1,439 QA**を評価する。direct / counterfactual / noisy / inverse reasoningを使い、frontier modelsがしばしばlatent if-then ruleではなくfrequency heuristicで表面予測し、途中でbehavior ruleが変わると適応に苦戦する、と報告する。

### (2) 提案・推測段階

synthetic householdでのpattern understandingが実人間のrelationship memoryやpersonality understandingへそのまま転移することは未実証。

### (3) 関係サブシステム

### (4) 借りられる設計

### (5) Kamimusuhiとの差分

SimLifeはbenchmark/simulationであり、canonical self/relationship evidenceのauthority設計は目的ではない。Kamimusuhiでは「相手について推論したrule」はderived beliefであり、本人の明示statementやraw episodeと同格にしない。

## 4.5 A — GUI nudge susceptibility: reasoningを増やすと影響経路が変わる

**Primary source:** *A Dual-Process Perspective on Nudge Susceptibility in LLM-Based GUI Agents*  
https://arxiv.org/abs/2609.19843

### (1) 何が実証済みか

6 frontier models、3 providers、**3,600 agents / 21,600 simulations**のrandomized online-shopping experimentで、GUI agentsはautomatic (Type 1) とreflective (Type 2) digital nudgesの両方に影響された。reasoning configurationはautomatic default nudgeへのsusceptibilityを下げる一方、reflective social-influence nudgeへのsusceptibilityを高めた。つまり「reasoningを強くするほど全般にnudge-resistant」ではなかった。

### (2) 提案・推測段階

shopping UI以外、実user preferenceを持つpersistent agent、Kamimusuhiのtool policyへ同じ効果量が出るかは未実証。

### (3) 関係サブシステム

HCI、social cognition、tool/browser action、user-intent preservation、K-Core/K-Deep deliberation。

### (4) 借りられる設計

UI由来のchoice architectureを「環境からの中立な事実」ではなくinfluence-bearing evidenceとしてtagし、reasoning depthごとに異なるattack surfaceを評価する。

### (5) Kamimusuhiとの差分

Kamimusuhiは長期user modelを持ち得るため、単発nudgeだけでなくrelationship memoryに取り込まれて後続decisionへ残留する二次効果も評価対象になる。

### (6) 次に検証すべきこと

**`InterfaceInfluenceRouteBench-v0`**: default、social proof、scarcity、authority cue、framingを、fast path / deliberative path / external-model pathで比較し、user preference fidelityとmemory contaminationを測る。

### (7) 重要度

**A**。

## 4.6 A — Continual world-model discovery: ruleの「追加」だけでなく「退休」を学ぶ

**Primary source:** *Continual Enterprise World Model Discovery in Dynamic Systems*  
https://arxiv.org/abs/2609.19551

### (1) 何が実証済みか

ServiceNow live environment上に9 tables、25 hidden business rules、600 evaluation actionsを持つEnterpriseWorldShiftを構築し、同じrecordsのままruleを**modified → added → removed**と変える4 world versionsでdiscovery / revision / extension / retirementを評価する。Continual Discovery Agentは前worldのmodelを持ち越し、questionごとにlive system lookupする方式よりhidden rule effect predictionを最大**8.98 IoU points**改善したと報告する。

### (2) 提案・推測段階

enterprise rule discoveryは、物理世界・社会規範・人間の習慣のような非決定的world ruleへ直接一般化できない。

### (3) 関係サブシステム

semantic memory、world model、belief revision、procedural/environment knowledge、tool interaction。

### (4) 借りられる設計

learned ruleに`introduced_at / last_supported_at / superseded_by / retired_at / evidence set`を持たせる。追加学習だけでなく明示的なretirement能力をfirst-classにする。

### (5) Kamimusuhiとの差分

Kamimusuhiではworld modelはcanonical self historyではない。環境規則が変わっても過去の経験をrewriteせず、current interpretationだけをrevisionする必要がある（INV-009/011と整合）。

### (6) 次に検証すべきこと

**`RuleRetirementWorldModelBench-v0`**: hidden API/tool ruleをadd/modify/removeし、stale ruleによる誤行動、retirement delay、過去episode preservation、confidence calibrationを測る。

### (7) 重要度

**A**。

## 4.7 A — GAVEL: semantic replanningの前にexplicit world modelで機械検証する

**Primary source:** *GAVEL: Graph World Models for Verified and Efficient Long-Horizon LLM Task Planning*  
https://arxiv.org/abs/2609.19315

### (1) 何が実証済みか

GAVELはobject-relations、action preconditions/effects、unobserved object locationのprobabilistic beliefsをgraph world modelに持ち、LLM actionを実行前に予測・violation検出・機械repairする。semantic reasoningが必要なfailureだけLLM replanningへ戻す。BEHAVIOR-1Kで100 single long-horizon tasks / 500 multi-task instructionsを評価し、Qwen3-8Bでsingle-task success **41.2→91.8%**、multi-task **19.9→92.6%**と報告する。distributional beliefでstatic variantよりtravel distance約5.4%削減。

### (2) 提案・推測段階

simulation中心の結果で、Kamimusuhi/MOVIのreal-world noisy perceptionやactuator dynamicsで同等の改善は未実証。

### (3) 関係サブシステム

Physical AI、K-Edge、planner/verifier、world model、Cognitive Budget。

### (4) 借りられる設計

LLMに毎回全replanさせず、explicit executable modelで局所違反をrepairし、semantic uncertainty時だけK-Core/K-Deepへescalateする。

### (5) Kamimusuhiとの差分

GAVELのgraphはtask/environment modelであり、canonical self-stateではない。Kamimusuhiではderived/rebuildable workspace world modelとして扱う。

### (6) 次に検証すべきこと

**`WorldModelPreExecutionVerificationBench-v0`**: LLM-only / graph-guard / graph-local-repair / full-replanを比較し、success、safety violations、LLM calls、latency、stale-world-model failureを測る。

### (7) 重要度

**A**。

## 4.9 B — SmellDiffusion: olfactory identityをgoalへ結びつけてもplannerは分離できる

**Primary source:** *SmellDiffusion: Diffusion-Based Quadruped Navigation with Olfactory Scene Graphs*  
https://arxiv.org/abs/2609.20624

### (1) 何が実証済みか

species-specific gas zonesをopen-vocabulary olfactory scene graphで表現し、source estimateをclassical plannerとdiffusion plannerへ共通goalとして渡すpipeline。displaced peak casesでselective geometric correctionがmean source error **1.468m→0.592m**、all-case 0.205m→0.180m。best-of-ten diffusionはgas exposureでgas-guided A*と同程度だが、plain A*も同じgoalへ到達し最速・最短pathだった。6 matched Gazebo runsではsource error A* 0.39m / diffusion 0.31m。

### (2) 提案・推測段階

real gas sensorでの実機generalizationはまだ示されておらず、6 Gazebo runも小規模。

### (3) 関係サブシステム

sensory nervous system、olfaction、multimodal perception、robotics。

### (4) 借りられる設計

「odor identity/source estimation」と「navigation policy」を分離する。新sensor modality導入時にplannerまでneural化しない。

### (5) Kamimusuhiとの差分

Kamimusuhiの嗅覚候補はidentity/experience/context signalも含み得るが、この研究はtask-oriented gas navigation。

### (6) 次に検証すべきこと

olfaction prototypeを作る場合、gas/odor classifier + source estimateを共通goal APIへ落とし、A*/classical baselineを必ず含める。

### (7) 重要度

**B**。

### (5) Kamimusuhiとの差分

### (6) 次に検証すべきこと
