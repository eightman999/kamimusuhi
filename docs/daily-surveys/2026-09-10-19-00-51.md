## 3. Executive summary

今回の strongest signal は、**生成モデルを「状態・制御・権限・身体」の owner にしないための interface / kernel / typed control plane が、異なる研究・実装領域で同時に具体化している**ことだった。

重要な差分は以下。

1. **Programmable World Model** は persistent world state と generative rendering を明示的に分離し、off-screen / non-visual state を軽量 state engine に保持する。Kamimusuhi の `canonical state != prompt/rendering` を別分野から強く支持する。
2. **Control-Data Flow Separation** は self-improving prompt / skill が routing・termination・format protocol を壊さないよう、execution-critical control を typed validated object に隔離する。Kamimusuhi の自己改善境界に直接使える。
3. **Show-Harness** は一つの semantic action interface と embodiment-specific deterministic interpreter で複数 robot embodiment を扱う。K-Edge/K-Core と身体の間に **Embodiment ABI** を置く具体例になる。
4. **Google Cloud Agent Identity / Agent principal** は runtime workload に監査可能な principal を与える実サービス例。Kamimusuhi では `individual identity != organ/runtime principal` を明文化する材料になる。
5. **Speaker Relationship Inference** は relationship inference を単発の一意推定ではなく、複数仮説の提案・反論・裁定として扱う。relationship memory の evidence-backed hypothesis layer に使える。
6. **AgentAudit** は agent の最終成否ではなく full execution trace のどの段階で信頼性が壊れたかを分類する。Kamimusuhi の trace / invariant test を拡張する比較対象。
7. 日本語実装側では **AgentCore Memory IngestData** と **MLflow Agent Skill trace evaluation** が有用だった。前者は raw history の source of truth と derived long-term memory を分離しやすくし、後者は手続きの正しさを judge ではなく trace order で検証する。

## 4.1 Programmable World Model — persistent state と generative rendering の分離

**Source:** Zheng-Hui Huang et al., *Programmable World Model*, arXiv:2609.10540, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10540  
**Importance:** **S**  
**Evidence status:** benchmarked research prototype; preprint.

### 1. What is demonstrated

著者らは video world model の「見えている映像」と「世界の真の状態」を分離する。agent が natural-language instruction から executable program を生成し、軽量 engine が entity state と state-transition rule を実行して **persistent global world state** を保持する。off-screen entity や non-visual attribute も state engine 側に残る。

生成映像は state-augmented 3D OBB から conditioning signal を決定論的に作り、pretrained video model が renderer として生成する。CombatStateBench では 94% Count Accuracy / 98% State Accuracy を報告している。

### 2. What remains proposed / unproven

game / video world の explicit state であり、自伝的 identity、曖昧な社会的信念、evidence provenance、distributed conflict は扱わない。明示 state が不完全・不確実な世界でどこまで成立するかも別問題。

### 3. Kamimusuhi relevance

- Canonical Self History / Evidence
- Persistent Self State
- relationship/body/current-state projection
- Persona Core / expression separation
- simulation / dream
- model replacement continuity

### 4. Borrowable design

Kamimusuhi でも次の separation を明示的に benchmark できる。

```text
canonical evidence / explicit state
        ↓
state transition / validation engine
        ↓
derived state views
        ↓
LLM / speech / avatar / UI rendering
```

**生成された表現が state owner ではない**。renderer/model を交換しても、off-screen な commitment、body capability、relationship fact、unfinished goal が保持される設計にする。

### 5. Difference from Kamimusuhi

Kamimusuhi では「状態」の多くが uncertain / evidence-dependent であり、world model の deterministic fact table だけでは足りない。`canonical event → belief proposal → confidence/provenance → current projection` が必要。

### 6. Next validation

`StateRenderSeparationBench`:

- 同一 canonical state を複数 Persona Core / renderer で表現する。
- UI に表示されない state を後の行動で正しく再利用できるか。
- renderer hallucination が canonical state を変更しないか。
- model upgrade 前後で derived view を再構築できるか。
- dream/simulation state が reality state に混入しないか。

## 4.2 Control-Data Flow Separation — 自己改善可能部分と runtime protocol の境界

**Source:** Wentao Zhang et al., *Control-Data Flow Separation: Stable Prompt Optimization in Multi-Agent LLMs*, arXiv:2609.00621, EMNLP 2026 Findings  
**Primary:** https://arxiv.org/abs/2609.00621  
**Code:** https://github.com/yuntian-group/cdsep  
**Importance:** **S**  
**Evidence status:** synthetic reasoning / collaborative review / insurance workflow experiments; paper reports 100% eventual protocol validity under its evaluated setting.

### 1. What is demonstrated

prompt optimizer が自然言語内容だけでなく routing、output format、termination signal まで書き換えると agent pipeline 自体が壊れる問題に対し、execution-critical control を **typed / validated program object** として分離し、task-relevant natural language のみを最適化対象にする。

### 2. What remains proposed / unproven

評価は multi-agent prompt optimization を中心とし、長期間の self-modifying artificial individual、canonical lineage、physical side effect を直接扱うものではない。100% は評価した workflow 内の値であり一般保証ではない。

### 3. Kamimusuhi relevance

- procedural memory evolution
- SkillAdam / descendant search
- Cognitive Action Router
- agent/tool protocol
- Mutation / Activation Gate
- K-Edge/Core/Deep handoff

### 4. Borrowable design

自己改善可能領域と、変更に formal review が必要な制御領域を分ける。

```text
optimizable / learnable
  skill text
  heuristics
  examples
  retrieval strategy

runtime-owned typed control
  message schema
  route target
  capability / authority
  termination
  commit protocol
  effect state machine
```

### 5. Difference from Kamimusuhi

Kamimusuhi は protocol validity に加え、**identity / evidence / authority semantics** まで守る必要がある。型が通るだけで正当な canonical transition とは限らない。

### 6. Next validation

`ControlProtocolDriftBench`:

- skill self-rewrite を数十〜数百 iteration 回す。
- optimizer に adversarial / contradictory feedback を混ぜる。
- typed control plane 有無で route corruption、termination failure、invalid commit、privilege drift を比較。
- content improvement と invariant violation を別 metric にする。

## 4.3 Show-Harness — semantic Embodiment ABI

**Source:** Yanzhe Chen et al., *Show-Harness: Just a VLM Agent Can Play Robots*, arXiv:2609.10522, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10522  
**Project:** linked from arXiv  
**Importance:** **A**  
**Evidence status:** multi-task / multi-embodiment robotics experiments; preprint.

### 1. What is demonstrated

Show-Harness は VLM が reasoning しやすい discrete semantic action unit を公開し、embodiment-specific interpreter がそれを local robot action に**決定論的に ground**する。同一 interface から closed frontier VLM の zero-shot robot control と、小型 open VLM の数 GPU-hour fine-tuning を示す。GUMI により GUI から複数 embodiment の demonstration collection も統一する。

### 2. What remains proposed / unproven

VLM が fine-grained physical decision を直接担う構造であり、長期 identity、side-effect authority、故障時 continuity、安全 envelope は研究対象外。

### 3. Kamimusuhi relevance

- distributed embodiment
- Cognitive Action Router
- K-Edge / K-Core → actuator boundary
- robotics / GUI surface
- body capability model

### 4. Borrowable design

身体ごとに cognitive policy を再学習するより、**semantic action ABI** を挟む。

```text
Kamimusuhi intention
  ↓
semantic action
  ↓
capability / safety gate
  ↓
embodiment interpreter
  ↓
local actuator command
```

### 5. Difference from Kamimusuhi

Kamimusuhi では semantic action を生成した component が effect authority を持つとは限らない。interpreter の前に capability / body-health / permission / freshness check が必要。

### 6. Next validation

`EmbodimentSemanticABIBench`:

- 同じ semantic action を desktop / simulated robot / physical robot adapter へ送る。
- body replacement 時の skill portability。
- unsupported capability の deterministic rejection。
- stale body state / actuator failure / delayed command。
- interpreter swap が Persona/continuity を変えないこと。

## 4.4 Google Cloud Agent Identity — individual identity と runtime principal を分ける実装例

**Discovery source:** Zenn, *Cloud Runでエージェントを作ると、プロジェクトのIAMに自分が書いていない行が増える*, 2026-09-09  
https://zenn.dev/acntechjp/articles/zenn-cloudrun-agent-identity  
**Primary:** Google Cloud, *Authenticate your AI agents*  
https://docs.cloud.google.com/run/docs/ai/authenticate-agents  
**Primary:** Google Cloud Agent Registry, *Key concepts*  
https://docs.cloud.google.com/agent-registry/concepts  
**Importance:** **A**  
**Evidence status:** Google Cloud Preview feature / official runtime identity semantics; Zenn article is implementation observation.

### 1. What is demonstrated

Cloud Run の `agent-identity` は agent workload に system-managed principal を与え、Google Cloud API / other agents / tools への認証と IAM audit に利用できる。Agent Registry 公式資料は **Agent identifier（inventory lookup）** と **Agent principal（secure runtime identity）** を明示的に区別している。

### 2. What remains proposed / unproven

Cloud provider の operational identity であり、人工個体の autobiographical identity / subjective continuity を表すものではない。Preview 機能で仕様変更の可能性がある。

### 3. Kamimusuhi relevance

- K-Edge/K-Core/K-Deep organ authentication
- distributed embodiment
- capability granting
- audit/provenance
- stale worker / migration

### 4. Borrowable design

Kamimusuhi では最低でも次を別 ID domain とする価値がある。

```text
IndividualIdentity / Lineage
  != OrganPrincipal
  != Activation / Session
  != Human/User identity
  != External cognitive resource identity
```

`OrganPrincipal` は短寿命・交換可能でよい。一方 `IndividualIdentity` は canonical lineage に属する。

### 5. Difference from Kamimusuhi

Google Agent Identity は workload security identity。Kamimusuhi は「その workload が今この個体の正当な organ か」「どの canonical head / epoch に属するか」も別途検査する必要がある。

### 6. Next validation

`OrganPrincipalContinuityBench`:

- K-Edge credential rotation。
- cloud → local node migration。
- stale organ token が残る状態で canonical epoch を進める。
- compromised organ principal の revoke。
- principal が有効でも lineage lease が古い場合は canonical write を拒否。

## 4.5 Who Are They to Each Other? — relationship belief を一発で確定しない

**Source:** Yaohan Guan et al., *Who Are They to Each Other? Multi-Agent Reasoning for Speaker Relationship Inference*, arXiv:2609.09628, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.09628  
**Importance:** **A**  
**Evidence status:** Seamless Interaction dataset; text/audio modalities; preprint.

### 1. What is demonstrated

training-free framework で、複数 agent が complementary role / social-theory-grounded perspective を持って relationship judgment を提案・反論・裁定する。別方式では候補を pairwise adjudication で競わせる。text を含む条件では zero-shot / existing multi-agent baseline を多くの条件で改善し、人間 annotator を上回る場合もある一方、audio-only/音響手掛かりでは弱さが残る。

### 2. What remains proposed / unproven

第三者話者間の relationship classification であり、長期的な関係発達・common ground・trust・commitment を更新するシステムではない。multi-agent debate のコストと calibration も課題。

### 3. Kamimusuhi relevance

- relationship memory
- Theory of Mind / social cognition
- speech perception
- uncertainty / epistemic behavior

### 4. Borrowable design

relationship inference を直接 durable fact にせず、競合仮説として保持する。

```text
observations
  ↓
H1 / H2 / H3 + evidence + confidence
  ↓
adjudication / later evidence
  ↓
relationship belief proposal
```

### 5. Difference from Kamimusuhi

Kamimusuhi は「私と相手の関係」だけでなく、`what I believe / what I think they believe / shared common ground` を分離する必要がある。relationship label より richer state が必要。

### 6. Next validation

`RelationshipHypothesisAdjudicationBench`:

- ambiguous conversation。
- acoustic cue と text cue の衝突。
- long-term evidence が short-term impression を覆すケース。
- unknown/abstain を許す。
- 誤った仮説が self/persona へ転写されないこと。

## 4.6 AgentAudit — final score ではなく failure stage を評価する

**Source:** Shrey Nag et al., *AgentAudit: An Open, Extensible Framework for Full-Lifecycle Trust Evaluation of AI Agents*, arXiv:2609.09875, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.09875  
**Importance:** **A**  
**Evidence status:** five models × nine capability/adversarial tasks; trace-based framework; preprint.

### 1. What is demonstrated

AgentAudit は agent 実装を置換せず execution trace を読み、instruction integrity、planner、memory、tool selection/invocation/correctness、alignment、tool faithfulness、security、execution integrity の 10 dimension と failure attribution を評価する。task completion が近くても unsafe compliance 等の振る舞いは大きく違うと報告する。

### 2. What remains proposed / unproven

全 trace を単一 fixed judge model が採点し、その judge 自身が評価対象 model の一つでもある点を著者が limitation としている。longitudinal identity / continuity / canonical mutation は含まない。

### 3. Kamimusuhi relevance

- traceability
- v0.1 continuity slice
- Cognitive Action Router
- memory/effect pipeline
- regression / descendant evaluation

### 4. Borrowable design

Kamimusuhi の trace を stage-wise に評価する。

```text
perception
→ evidence retrieval
→ belief/memory proposal
→ deliberation/delegation
→ capability check
→ effect execution
→ result observation
→ durable commit
```

最終回答正解でも途中で invariant violation があれば failure とする。

### 5. Difference from Kamimusuhi

Kamimusuhi では deterministic invariant を judge model に任せない。predecessor、authority、revocation、state machine、tool order 等は code check、semantic quality だけ judge を使う。

### 6. Next validation

`KamimusuhiLifecycleAudit`:

- stage-specific event schema。
- deterministic invariant scorers。
- semantic judge と code scorer の分離。
- model migration 前後の trace divergence。
- task success / identity integrity / effect integrity を別 metric にする。

## 4.7 AgentCore Memory IngestData — raw history を二重保存せず derived memory を作る

**Discovery source:** AWS Japan Zenn, *AgentCore Memory の IngestData API で既存の AI チャットアプリに長期記憶を後付けしてみた*, 2026-09-09  
https://zenn.dev/aws_japan/articles/agentcore-memory-ingestdata  
**Primary:** AWS, *Amazon Bedrock AgentCore Memory now supports direct ingestion to long-term memory*, 2026-09-08  
https://aws.amazon.com/about-aws/whats-new/2026/09/agentcore-memory-direct-ingest/  
**Importance:** **A**  
**Evidence status:** GA API + AWS Japan hands-on implementation record.

### 1. What is demonstrated

`IngestData` は content を short-term memory event として保存せず、configured long-term memory strategy に直接渡して抽出結果だけを作る。AWS Japan の実装記事では、既存 RDS history を履歴の正として維持しながら AgentCore Memory を derived memory backend として後付けする構成を試している。

### 2. What remains proposed / unproven

AgentCore Memory の extraction result が Kamimusuhi の canonical evidence / self-memory に適することを示すものではない。multi-tenant isolation / lineage / relationship authority は記事の検証対象外。

### 3. Kamimusuhi relevance

- canonical history vs derived long-term memory
- migration from existing logs
- memory backend replacement
- ingestion/replay pipeline

### 4. Borrowable design

`canonical evidence source` と `memory extraction service` を物理的にも論理的にも分離する実装パターン。

```text
canonical event log
  ├── normal application/history access
  └── extraction-only ingest
        ↓
      derived memory
```

### 5. Difference from Kamimusuhi

Kamimusuhi では derived memory の更新に evidence IDs、validity/supersession、subject domain、proposal policy が必要。外部 memory backend を authority にしない。

### 6. Next validation

`MemoryBackendReplayBench`:

- canonical log から複数 memory backend を再構築。
- backend を空にして full replay。
- same evidence から抽出結果の model/backend variance を計測。
- extraction failure / retry / duplicate ingestion の idempotency。

## 4.8 MLflow Agent Skill evaluation — 手続きの正しさを trace predicate にする

**Discovery source:** Qiita, *MLflowでAgent Skillを評価する - トレースのスパン順序で、LLM judgeなしに手順の正しさを測る*, 2026-09-10  
https://qiita.com/taka_yayoi/items/699a92dd93d63ed12e90  
**Primary:** MLflow, *Evaluating and Improving Agent Skills with MLflow*, 2026-08-02  
https://mlflow.org/blog/evaluating-improving-agent-skills/  
**Importance:** **A**  
**Evidence status:** official evaluation workflow + Japanese hands-on trace-scorer implementation.

### 1. What is demonstrated

MLflow 公式は agent skill を versioned software component のように dataset / trace / scorer で継続評価し、最終出力だけでなく tool choice / validation order / policy compliance を測る方式を示す。例では identity verification step の欠落を trace から見つけ、skill instruction 修正後に Correct Tool Selection が 43% → 98% に改善した。

Qiita の hands-on は `trace` の span と `start_time_ns` を使い、**「tool を呼んだか」だけでなく「正しい順序で呼んだか」**を LLM judge なしに判定できることを実装確認している。

### 2. What remains proposed / unproven

これは一般 agent skill の評価であり、Kamimusuhi の procedural memory self-evolution を長期間安定させる保証ではない。公式例の改善率は特定 demo workflow の値。

### 3. Kamimusuhi relevance

- procedural memory
- SkillAdam-like evolution
- descendant evaluation
- action/effect safety
- trace audit

### 4. Borrowable design

各 procedural skill に `behavioral contract` を付与する。

```text
skill
├── examples / natural-language guidance
├── regression dataset
└── deterministic trace predicates
    ├── must_call(X)
    ├── X_before_Y
    ├── never_call(Z_without_grant)
    └── effect_requires(receipt)
```

### 5. Difference from Kamimusuhi

Kamimusuhi では skill correctness に加え、identity/evidence/authority boundary を跨がないことも contract にする必要がある。

### 6. Next validation

`ProceduralTraceContractBench`:

- naive output-only judge vs trace predicate。
- skill update 前後 regression。
-「最終結果は正しいが禁止手順を踏んだ」case。
- judge model が変わっても invariant scorer は同じ結果になること。

## 4.10 Hindsight — structured memory と mental model の既存比較対象

**Discovery source:** Zenn, *Hindsight徹底解説：AI Agentに長期記憶を与えるMemory Engineの仕組みと、RAGとの違い・採用判断*, 2026-09-08  
https://zenn.dev/kimkiyong/articles/a27fee61dfac95  
**Primary:** ACL 2026 Demo, *Hindsight: Structured Agent Memory that Retains, Recalls, and Reflects*  
https://aclanthology.org/2026.acl-demo.27/  
**Repository:** https://github.com/vectorize-io/hindsight  
**Importance:** **B**  
**Evidence status:** ACL 2026 system demonstration + open-source implementation; not a new paper today but newly identified as useful comparison target.

### 1. What is demonstrated

Hindsight は retain / recall / reflect、memory types、observations、mental models / knowledge pages を持つ structured agent memory engine。ACL demo paper reports strong LongMemEval / LoCoMo performance under its evaluated setup and exposes memory graph inspection.

### 2. What remains proposed / unproven

benchmark memory accuracy は canonical autobiographical truth、relationship contamination resistance、identity lineage、model-independent continuity を保証しない。

### 3. Kamimusuhi relevance

- episodic / semantic / derived person model
- reflection
- memory engine baseline
- inspectability

### 4. Borrowable design

memory retrievalだけでなく、derived observation / mental model の形成過程を inspection surface として見せる点は参考になる。

### 5. Difference from Kamimusuhi

Kamimusuhi は canonical evidence を上位に置き、mental model を rebuildable / attributable derived state として扱う。memory engine 自体は identity owner ではない。

### 6. Next validation

Hindsight を `EvidencePreservingMemoryBench` / `MemoryBackendReplayBench` の比較 backend に加える。

## 11. Bottom line

19:00差分の中心は、新しい「巨大な認知モデル」ではなく**境界の設計**だった。

```text
state != rendering
control protocol != optimizable language
individual identity != runtime principal
intent != embodiment command
relationship hypothesis != relationship fact
successful answer != trustworthy execution trace
raw history != derived memory backend
skill output != procedurally valid execution
```

これは Kamimusuhi の既存方向を大きく反転させる発見ではない。むしろ、これまで設計してきた **canonical evidence / continuity kernel / proposal-only mutation / cognitive resource attribution / K-Edge/Core/Deep separation** を、world model・robotics・cloud identity・agent evaluation・日本語圏の実装知見から独立に補強する材料が増えた回である。
