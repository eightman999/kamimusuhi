最も fresh かつ実装上重要なのは Letta Code PR #4391。直前 survey で扱った #4379 は「別 sender の queued input を active continuation の acting principal にしてはいけない」という isolation 修正だった。しかし、その修正後に **sender を持たない background completion notification が queue 先頭に来ると、同じ user の follow-up まで異なる sender と誤判定されて end-turn まで停止する**という liveness regression が露呈した。#4391 は background job の launch 時点で `actingUserId` を `NotificationScope` に捕捉し、Bash / `exec_command` / Monitor の completion notification まで伝播させる。

これは Kamimusuhi に新しい境界を与える。

```text
principal isolation alone != correct principal semantics
async event provenance missing != harmless metadata loss
security isolation without provenance propagation -> liveness failure
originating principal provenance != fresh execution authorization
```

つまり非同期結果は「system event」へ匿名化せず、**どの principal / continuation / action から因果的に生まれたか**を保持する必要がある。一方、その provenance を side effect の再実行権限へ昇格させてはならない。

同じ数時間窓で merge された Letta Code PR #4389 も重要である。Cloud child agent を別の model/tool loop として起動するのではなく、**その computer / conversation を実際に所有する listener に work を submit**し、terminal event まで待つようにした。さらに timeout は「失敗」とみなして自動 resend せず、`execution may still be running` と扱う。Kamimusuhi では `logical child agent != execution owner`、`control/read timeout != execution failure` を runtime contract に落とせる。

自己モデル / neuroscience 寄りでは、*Perfect Aliasing* が重要な警告である。truth と task-prescribed action が training context 内で常に一致しているなら、そこで perfect な linear probe を作っても **何を probe しているかは同定できない**。751 cell-layer pair で rival-context AUROC の和が1になる関係を確認し、同じ in-distribution perfect probe が rival context で 0.080 と 0.986 に分かれる。Kamimusuhi が将来「内部 activation から自己状態・誠実性・belief を読む」場合、probe accuracy だけを canonical self-monitor にしてはいけない。

一方 *Legible Failures* は、出力が誤っていても hidden state には正しい in-context binding が残るケースを16 checkpointで示し、probe-output disagreement が model confidence より failure detection を改善し、probe-decoded direction への steering で8モデルすべての accuracy を平均 +0.168 改善した。したがって **output failure != internal state lacks useful binding** だが、上の Perfect Aliasing と組み合わせて「probe が何を測っているか」を先に検証する必要がある。

最後に *Routing by Reasoning Need* は diffusion VLM の限定結果だが、固定 decoding length ではなく、answer closure / commitment evidence / representation revision pressure という **進行中 trajectory の状態**を見て early / baseline / reasoning-supportive decoding を選ぶ。Kamimusuhi の Cognitive Budget に対し、pre-task difficulty prediction だけでなく `online trajectory → budget adjustment` を比較する B+ baseline になる。

今回の差分を圧縮すると以下である。

```text
principal isolation != principal provenance propagation
async completion != anonymous system event
logical child agent != execution owner
read/control timeout != known execution failure
high probe accuracy != semantically identified internal variable
wrong output != absence of correct internal binding
pre-task difficulty != sufficient signal for reasoning budget
```

## 5.3 Self-model / neuroscience / interpretability — Perfect Aliasing in truth probes

**Source:** Dylan Jayabahu, *The Truth Was Never Gone: Perfect Aliasing in Compliant-Context Truth Probes*, arXiv:2609.10739  
**Submitted:** 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10739  
**Importance:** **A**

### (1) 何が実証済みか

controlled binary reporting game で、truthful reporting と task-prescribed action が fitting context 内で一致すると、truth probe と prescribed-action probe は同じ optimization problem を解き、**training labels だけから semantic target を識別できない**ことを示した。

- rival context では truth と prescribed-action labels が補集合になり、**751 cell-layer pairs で AUROC の和が1**になる関係を floating-point precision で確認。
- reward-trained Gemma-2-9B が rival trials で全て false answer を出す条件で、conventional compliant-fit probe は **0.006 ± 0.005 AUROC**、mixed-fit probe は同じ held-out activations で **1.000**。
- compliant context ではどちらも perfect な2 probe が、同じ rival activations で **0.080 と 0.986** に分かれる。
- code / aggregate results を公開。

### (2) 何が提案・推測段階か

著者自身が限定している通り、これは「truth が機能的 belief として保存されている」「回収方向が causal に使われている」「deployable deception detector ができた」ことを示さない。

Kamimusuhi の self-model、uncertainty、intent、belief を activation probe で読めることも当然まだ示していない。

### (3) 関係する Kamimusuhi subsystem

- Persona Core self-model
- digital interoception
- uncertainty / confidence calibration
- observability without chain-of-thought
- behavior-grounded self-model
- future internal safety / truthfulness monitor
- model migration diagnostics

### (4) 借りられる設計・実装アイデア

**internal probe は「高accuracy」ではなく semantic identifiability を要求する。**

候補 rule:

```text
probe candidate
  -> identify plausible confounded target variables
  -> construct contexts where targets decorrelate
  -> counterfactual / rival-context evaluation
  -> intervention test where possible
  -> only then use as diagnostic signal
```

probe output は canonical self-state の source ではなく、telemetry / hypothesis として扱う。

### (5) Kamimusuhiとの差分

現行 Kamimusuhi は self-report を真の自己状態と同一視しない方向だが、将来 internal activation telemetry を導入した時に、**「内部だから外部 self-report より真実」へ短絡する危険**がある。本研究はその短絡を直接否定する。

### (6) 次に検証すべきこと

**`ProbeSemanticIdentifiabilityBench`**

- self/other belief、memory provenance、confidence、intended action など複数 target を用意。
- training split では一部 target を意図的に相関させる。
- rival/counterfactual split で decorrelate。
- ID accuracy、OOD semantic consistency、causal steering、behavioral prediction を別指標にする。
- semantic identity が崩れる probe は observability signal に昇格させない。

### (7) 重要度

**A** — Persona Core の機械的 self-monitor を設計する前に必要な epistemic hygiene。`self-report != measured state` の次に `probe score != identified state` を追加する。

## 5.4 Cognitive failure diagnosis — Legible Failures: hidden state can retain the right binding

**Source:** Ravulapalli, Chadha, Hari, *Legible Failures: Detecting and Repairing In-Context Binding Errors*, arXiv:2609.11216  
**Submitted:** 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11216  
**Importance:** **A**

### (1) 何が実証済みか

entity-obligation binding task で、model が prompt-supplied binding を誤答しても frozen hidden state から linear probe が正しい binding を回収できる条件を **16 public checkpoints × 3 seeds** で評価した。

- model が wrong な trial に限っても、probe accuracy は strict present-obligation baseline `1/K = 0.125` を平均 **+0.196** 上回る（95% CI `[+0.101, +0.296]`）。
- query-entity counterfactual で単なる token presence / recency を除外。
- probe-output disagreement の符号を使う score は model confidence より failure detection を **+0.079 AUROC** 改善。
- raw probe confidence 単独は model confidence に対する有意な改善なし。
- gold label を使わず probe-decoded binding 方向へ residual stream を steering すると、試した8モデルすべてで accuracy が上がり、平均 **+0.168**。

### (2) 何が提案・推測段階か

- in-context entity-obligation binding という限定 task であり、一般 reasoning、autobiographical memory、social belief、tool planning に一般化できない。
- probe の semantic validity は task設計に依存し、前項 Perfect Aliasing の問題を自動的に回避するわけではない。
- residual steering を long-running Persona Core に常用して安全・安定である証拠はない。

### (3) 関係する Kamimusuhi subsystem

- Persona Core / Global Workspace
- binding of person ↔ belief / obligation / commitment
- relationship state
- uncertainty / failure telemetry
- K-Core deliberation
- diagnostic / recovery path

### (4) 借りられる設計・実装アイデア

`wrong output` を一種類の失敗に潰さず、最低限以下を分ける。

```text
knowledge/binding absent
binding represented but not selected
binding selected but expression/action corrupted
probe semantics uncertain
```

behavioral confidence と独立した internal diagnostic が追加情報を持つかを評価する。

### (5) Kamimusuhiとの差分

Kamimusuhi は canonical memory / retrieved view / final action を分けているが、Persona Core 内部で **retrieved/bound state が正しいのに output selection だけ失敗する**ケースを独立診断する mechanism はまだ研究段階である。

### (6) 次に検証すべきこと

**`BindingLegibilityRepairBench`**

- `person A ↔ preference`、`request ↔ authority`、`episode ↔ source`、`tool result ↔ task` の typed binding task を用意。
- wrong output trial で hidden diagnostic が正しい binding を回収するか測る。
- Perfect Aliasing 型の confound を rival contexts で排除。
- recoverable trial のみ selective re-deliberation / steering を試す。
- 指標: recoverable-error rate、false repair、semantic probe robustness、final behavioral gain。

### (7) 重要度

**A** — 「失敗したから内部表現も壊れている」という単純仮定を崩し、低コスト recovery / self-diagnosis の可能性を与える。ただし probe semantics の検証が前提。

## 5.5 Multimodal / Cognitive Budget — Routing by Reasoning Need

**Source:** Liu et al., *Routing by Reasoning Need: Trajectory-Aware Decoding Control for Diffusion Vision-Language Models*, arXiv:2609.11315  
**Submitted:** 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11315  
**Importance:** **B+**

### (1) 何が実証済みか

LLaDA-V の iterative refinement trajectory を利用し、全questionへ同じ decoding length を与える代わりに、

- answer closure
- commitment evidence
- representation revision pressure

から各 example を **early commitment / baseline preservation / reasoning-supportive decoding** へ training-free で route した。著者らは answer-focused / mixed-reasoning / CoT-sensitive benchmarks で fixed long、pure short、single-rule interventions より routed control が robust と報告し、単なる output shortness では説明できないとしている。

### (2) 何が提案・推測段階か

- 長期agent task、tool use、memory retrieval、social cognitionでの budget optimality は未検証。
- trajectory signal 自体が hallucination / wrong early closure を検出できる保証はない。

### (3) 関係する Kamimusuhi subsystem

- Cognitive Budget

### (4) 借りられる設計・実装アイデア

budget allocation を二段階にする。

```text

  difficulty / modality / risk / latency
        +
online trajectory
  stability / revision / contradiction / uncertainty reduction
        -> continue / stop / escalate / change resource
```

### (5) Kamimusuhiとの差分

Kamimusuhi は variable-depth cognition を既に設計しているが、**開始前の routing だけでなく、思考途中の state transition を budget signal にする**具体的比較対象として新しい。

**`TrajectoryAdaptiveBudgetBench`**

指標: task success、premature-stop rate、unnecessary-compute rate、latency、energy/cost、escalation precision。

Async result SHOULD retain launch-time causal principal provenance.

### 最小の今夜実装案

最も安く、既存 architecture への情報利得が高いのは **1 → 2**。

#### `AsyncPrincipalProvenanceBench`

最低ケース:

1. A starts tool T.
2. T spawns async completion N(A).
3. A follow-up arrives behind N(A).
4. B follow-up arrives interleaved.
5. A is revoked before another N(A) arrives.

期待:

- N(A) は A-origin provenance を保持。
- A follow-up は不必要に end-turn まで block されない。
- B は current continuation へ混入しない。
- revoke 後 N(A) は provenance は保持するが、new effect authority は持たない。

#### `ExecutionOwnerRoutingBench`

最低ケース:

- child intent requests `surface=mac-camera` / `surface=linux-shell`。
- capability registry の owner だけが実行。
- client read timeout を注入。
- lookup/receipt なしの automatic retry は0件。

## 11. 今回の結論

今回の最も強い新規知見は、**principal provenance が security metadata ではなく runtime liveness の構成要素でもある**という点である。

```text
isolate principals
+ preserve causal principal provenance
+ revalidate current authority at effect time
```

の3点セットが必要になる。

また subagent については:

```text
who reasons / who owns the task
!=
which runtime owns and executes the capability
```

を分ける価値が高い。

Persona Core 内部観測については、今回の2論文を必ずセットで読むべきである。

```text
wrong output can coexist with useful hidden binding
but
high-accuracy hidden-state probe can still be semantically misidentified
```

したがって Kamimusuhi の internal self-monitor は **behavior / canonical evidence / runtime telemetry / semantically identified internal diagnostics** を組み合わせる方向が安全で、activation probe 単独を「内なる真実」と扱うべきではない。

次に回す価値が最も高いのは **`AsyncPrincipalProvenanceBench`**、次点で **`ExecutionOwnerRoutingBench`**。どちらも GPU 不要で、現在の Continuity / authority / distributed-body contracts を早く強化できる。
