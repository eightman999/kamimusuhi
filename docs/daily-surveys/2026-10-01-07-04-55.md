### A — Explicit delivery intent must not be silently rewritten across surfaces

Primary runtime evidence:
- https://github.com/openclaw/openclaw/issues/162058

1. **何が実証済みか**  
   scheduled job の `failureAlert` が明示的に `channel: "webchat"` を指定していても、そのchannelがdelivery-capableでない場合、OpenClawは要求channelを落として単一configured channel（報告環境ではSlack）へfallbackし、元の`to`文字列をそのまま持ち越す。報告環境では12件のfailure alertsが2日間deliverされず、監視機構の不調が約3か月気付かれなかった。現行code pathでは宛先名が偶然fallback channel上の実在targetと一致した場合、誤配送の可能性も構造上残る。
2. **何が提案・推測段階か**  
   偶然の名前衝突による実際の誤配送incidentは未観測。最新release全体での動作は一部source inspectionであり、全versionをruntime再現したものではない。
3. **Kamimusuhiのどのサブシステムに関係するか**  
   speech/action delivery、principal/surface identity、Cognitive Action Router、failure notification、effect state machine。
4. **借りられる設計・実装アイデア**  
   明示surface指定は**authority-bearing intent**として扱い、delivery不能ならfail-visibleにする。fallbackを許すのは「surface未指定」のpolicyだけに限定する。recipient addressは `surface_id × principal_id × address_version` にbindし、別surfaceへ文字列のまま持ち越さない。
5. **Kamimusuhiとの差分**  
   Kamimusuhiは既にspeech / delivery / acknowledgementを分離しているが、今回の差分は**surface substitution自体をauthorization eventとして扱う**点。とくにvoice/mobile/desktop/Discord等を跨ぐmulti-surface個体では、同じ表示名を同一principalと推定してはいけない。
6. **次に検証すべきこと**  
   **`ExplicitChannelFallbackRecipientScopeBench-v0`**。明示channelがunavailable / read-only / disconnectedな条件で、fallback禁止、operator-approved fallback、同名recipient collisionを注入し、wrong-recipient delivery、silent substitution、receipt truthを測る。
7. **重要度**: **A**

### A — Cacheable decision organs can lose rule sensitivity even when candidate scoring stays cheap

Primary:
- https://arxiv.org/abs/2609.37832

1. **何が実証済みか**  
   small non-generative decision model `Certo` を、state+rules+candidateをjointに読むscorerから、candidate側を事前cacheできるindependent encodingへ変えると、77 candidates規模で約5倍安くなる一方、synthetic rule-sensitivity recall@1が **1.00 → 0.24**へ崩れた。joint scorerは1.00を維持。targeted counterfactual supervisionでheld-out synthetic rule tasksは大幅に回復するが、matched cross-domain real prose mixtureは改善せず、contract accuracyを **-9.3 / -16.2 points**悪化させた条件もある。修正後benchmarkではjoint scorerがshort tier **0.861 vs 0.500**、hard tier **0.655 vs 0.483**と優位。
2. **何が提案・推測段階か**  
   synthetic rulesからreal safety policyへの転移、Jev等の既存typed-decision modelで同じfailureが生じるか、cacheable architectureの最適修正は未確定。
3. **Kamimusuhiのどのサブシステムに関係するか**  
   K-Nerve / K-Edge、typed microdecision organ、Cognitive Action Router、low-latency cognition、policy gating。
4. **借りられる設計・実装アイデア**  
   candidate cacheを導入する場合、**rule/stateとのinteractionを失っていないかをcounterfactual policy testsで独立検証**する。速さ・cache hitだけでK-Nerve organをpromotionしない。必要ならcandidate embeddingとpolicy-conditioned modulationを分離する。
5. **Kamimusuhiとの差分**  
   KamimusuhiのK-Nerveは意味・権限を所有しないが、routingやmicrodecisionがpolicy-sensitiveならrepresentation shortcutでも危険。typed outputであること自体はrule-followingの証拠ではない。
6. **次に検証すべきこと**  
   **`CacheableDecisionRuleSensitivityBench-v0`**。joint / cached-independent / policy-conditioned cached / code guardを比較し、candidate数、rule inversion、OOD wording、JP/EN、latency、energy、false-allow率を測る。
7. **重要度**: **A**

### B — Belief formation and decision policy should be evaluated as separate cognitive capabilities

Primary:
- https://arxiv.org/abs/2609.38005

1. **何が実証済みか**  
   probabilistic reasoningを、(a) evidenceからbeliefを形成する過程と、(b) beliefをutility-optimal actionへ変換する過程にdecision-theoretically分解し、ground truthが既知のsynthetic settingでそれぞれへのtargeted RLを比較。片方だけを最適化するとdecision lossの内訳は移動するが、他方への改善は保証されず、両方をjointに学習すると双方が改善する条件を報告。ただしtraining/evaluation formatが揃っていることへの依存も確認された。
2. **何が提案・推測段階か**  
   open-world belief、social inference、tool effects、longitudinal autobiographical beliefへ同じloss decompositionが直接適用できるかは未実証。
3. **Kamimusuhiのどのサブシステムに関係するか**  
   Persona Core、Global Workspace、Cognitive Action Router、belief/evidence representation、self-improvement evaluation。
4. **借りられる設計・実装アイデア**  
   `evidence → belief` と `belief → action` を同じaccuracyで採点せず、**belief calibration / inference quality / utility-policy quality**を別metricにする。行動が正しくてもbeliefが壊れている、またはbeliefが正しくてもpolicyが壊れているfailureを識別する。
5. **Kamimusuhiとの差分**  
   Kamimusuhiは概念上evidence / belief / actionを分離しているため相性がよい。今回の価値は、その分離をPersona Core training/evalで**独立loss・独立negative controls**として測ること。
6. **次に検証すべきこと**  
   **`BeliefFormationVsDecisionPolicyBench-v0`**。同じobservationからbelief reportとaction choiceを別評価し、miscalibrated belief / correct action、correct belief / wrong utility、format shiftを交差させる。
7. **重要度**: **B**

### B — One-pass correctness signals are useful routing evidence, not truth

Primary:
- https://arxiv.org/abs/2609.37700

1. **何が実証済みか**  
   frozen LLMの1 forward passから、hidden states、token probabilities、residual features、attention等を調べ、answer correctnessを予測する信号がanswer spanへ集中すること、closed-book / retrieval-context条件でも複数signal familyが相補的で、fusionがOOD discriminationを改善することを報告。downstream例ではretrieval controller gatingにも利用している。
2. **何が提案・推測段階か**  
   social reasoning、tool effects、memory proposals、long-horizon tasksで同じsignal locality/generalizationが成立する保証はない。probeはcorrectness oracleではない。
3. **Kamimusuhiのどのサブシステムに関係するか**  
   metacognition、K-Core/K-Edge、retrieval escalation、Cognitive Budget、verification routing。
4. **借りられる設計・実装アイデア**  
   model自己申告とは別にmechanical internal signalsを**escalation feature**として使う。複数signal fusionを試し、low-confidence時だけretrieval/verifier/K-Deepへ送る。
5. **Kamimusuhiとの差分**  
   correctness probeはPersona Coreの自己理解ではなくruntime competence telemetry。canonical beliefやaction authorityへ直接接続しない。
6. **次に検証すべきこと**  
   **`AnswerCorrectnessSignalFusionRoutingBench-v0`**。probability-only / hidden-state / residual / fusion / external verifierを比較し、selective accuracy、ECE、retrieval cost、OOD driftを測る。

### Hermes #129690 — persisted route locatorとcurrent organ incarnationを分ける

- https://github.com/NousResearch/hermes-agent/issues/129690

- 既存 provider/task readiness・organ incarnation freshnessへ、**dead loopback pinはrestart時にfresh routeへre-resolve**するfixtureを追加。
- remote URLは勝手にprobeせず、local managed endpointだけmechanical livenessで更新する。

### Hermes #129601 — malformed deferred receiptをqueue-wide failureにしない

- https://github.com/NousResearch/hermes-agent/issues/129601

- 既存 AuditPlaneSingleBadEventContainment / delivery-plane isolationへ、**bad receipt is evidence to quarantine, not a plane-wide poison pill** を追加。

### Hermes #129599 / #129609 — provenance欠落と「no output」placeholderを事実として捏造しない

- https://github.com/NousResearch/hermes-agent/issues/129599

- `recipient string != cross-surface identity`
- `cached candidate representation != preserved rule sensitivity`
