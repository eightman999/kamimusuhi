## 3. 要約

今回の中心テーマは、**「由来・近さ・一度正しかったこと」を、そのまま現在のauthority / completeness / truthへ昇格させないこと**だった。

- 同じhostのloopbackから来た新deviceでも、`local`であるだけで`operator.admin`を自己取得できる設計は、device identityによる権限分離を実質無効化する。
- build stampが正しいHEADを指していても、必要なruntime assetが欠落していれば、そのbodyは完全にactivation可能とは限らない。
- social agentは取得したrelationship evidenceをcontextへ置くだけでなく、現在の`goal / belief / relationship / norm / disclosure`仮説を更新し、その結果として`continue / switch / abandon / clarify`を切り替える必要がある。
- background heartbeatはemit時に正しくても、queue滞留中に世界が変わればdelivery時には偽になる。
- recovery/fallbackは「同じsemantic failureがexceptionで出たかHTTP-200 failed bodyで出たか」でpolicyが変わってはいけない。
- interrupted maintenanceの残骸は累積して将来のmaintenanceを遅くし、さらにinterruptしやすくするpositive feedbackを作り得る。

Kamimusuhiへの共通の含意は、`locality != authority`、`provenance != completeness`、`evidence retrieved != relational model revised`、`valid at emission != valid at consumption`、`same failure meaning != same transport representation`、`cleanup performed != substrate health restored` を別々に検証すること。

**Source**

- OpenClaw issue #156590, *Scope cap for silent local pairing (middle ground for gateway.nodes.pairing.autoApproveLocal)*
- https://github.com/openclaw/openclaw/issues/156590

### (1) 何が実証済みか

reporterはOpenClaw 2026.6.35で、loopback接続・`autoApproveLocal`有効時に**初回local device pairingがrequested scopeを見ずにsilent approve**され、fresh state dirから`operator.admin`を要求したdeviceがapproval promptなしでadmin identityを得ることをlive reproductionしている。

report自身も「host trust boundaryの突破」ではなく、**同一host内でagent用device identityとoperator用admin identityをscope分離したい場合のdefense-in-depth破綻**として位置付けている。

### (2) 何が提案・推測段階か

- `autoApproveLocalMaxScopes`のようなscope ceilingは提案段階。
- 2026.9.5で2026.6.35と完全に同じlive behaviorになることはcode inspection以上には未確認。
- host自体が完全に侵害された状況を防ぐmechanismではない。

### (3) Kamimusuhi 関連 subsystem

- device identity / K-Edge registration
- tool/action capability grants
- operator vs cognitive-body privilege separation

**bootstrap transport trustとcapability grantを分ける。**

```text

        !=
device identity accepted
        !=

```

- local read-only sensor registrationとadmin actuator registrationを分離する。

- device state dirを作り直してもauthorityをmintし直せない。

## A — ReAdapt: social evidenceを明示的なrelationship state更新へ変換する

**Source**

- Lin et al., *When LLM Agents Fail to Read the Room: ReAdapt for Relational Social Reasoning*
- arXiv:2609.25284
- https://arxiv.org/abs/2609.25284

### (1) 何が実証済みか

論文は500 synthetic social worldsから、friendship / follow / reaction history / feedを含む1,000 queriesを構成し、reaction selectionとwarm introductionを評価する。content上もっとも目立つcandidateとrelationship-grounded oracleが約53%で食い違うように設計されている。

ReAdaptはReActへ明示的social state `z=(G,B,R,N,D)`（goal, belief, relationship, norm, disclosure）を追加し、tool observationごとにtyped `Adapt` stepでstateを更新して`continue / switch / abandon / clarify`を選ぶ。

Gemini-3-Flash、各task n=150のstratified subsetで、warm-introduction accuracyは37%→51%、reaction-selectionは69%→77%。oracle regretも0.260→0.152、0.095→0.053へ低下したと報告している。

### (2) 何が提案・推測段階か

- synthetic social world上の結果で、長期の実人間関係への外挿は未実証。
- `G/B/R/N/D`がsocial cognitionの十分なstate decompositionである証拠はない。
- persistent relationship memoryやidentity continuityとの統合は論文の主眼ではない。

### (3) Kamimusuhi 関連 subsystem

- Relationship Memory / Person Model
- Common Ground
- Persona Core social cognition
- Global Workspace
- clarification / action routing

### (4) 借りられる設計・実装アイデア

retrieved social evidenceをpromptへ足すだけでなく、**現在の相手仮説をtyped state transitionとして更新し、その更新がpolicy switchを起こしたかを監査する**。

Kamimusuhi向けには例えば:

```text
relationship_state
  goal
  partner_belief_hypothesis
  tie / trust hypothesis
  empirical expectation
  normative expectation
  disclosure_scope
  uncertainty
  evidence_ids
```

### (5) Kamimusuhiとの差分

Kamimusuhiは長期Person Model / Relationship Memory / Common Groundを持つため、ReAdaptよりdurableかつauthority-sensitive。一方ReAdaptは、**新しいsocial evidenceがdecisionを実際に反転させるまでの中間state**を明示している点が具体的。

### (6) 次に検証すべきこと

`RelationalEvidenceAdaptationBench-v0`

- content salienceとrelationship evidenceを意図的に衝突させる。
- evidence取得前後でpartner hypothesisとaction policyが適切に変わるか。
- self preferenceを変えてもpartner stateが不当に追従しないか。
- 別personのrelationship evidenceがcross-contaminateしないか。
- disclosure scope / provenance / freshnessを保ったままstate更新できるか。

### (7) 重要度

**A**

理由: Kamimusuhiのsocial cognitionを「memory retrieval」から「evidence-driven relationship-state revision」へ具体化する、未収載の直接的な設計・評価材料。

## B — Hermes #120399: 同じsemantic failureがresponse shapeの違いで別policyへ流れる

**Source**

- Hermes Agent issue #120399, *Codex HTTP-200 `invalid_encrypted_content` soft failures bypass replay recovery and trigger fallback*
- https://github.com/NousResearch/hermes-agent/issues/120399

### (2) 何が提案・推測段階か

- suggested fixは未merge。
- `invalid_encrypted_content`以外のerror classについてrepresentation-invarianceが保たれるかは未調査。

## B — Hermes #120411: maintenance残骸が自己増幅するresource pathologyを作る

- https://github.com/NousResearch/hermes-agent/issues/120411

- `git gc --auto`をcleanup後に走らせるfixは提案段階。

# 10. 今回の圧縮結論

今回の一文は次。

> **「近い・同じ系譜・一度正しかった・一度検証した」を、現在のauthority / completeness / truthへ自動昇格させない。最終使用境界で、必要な性質をもう一度証明する。」**

具体的には、

```text
local transport             != admin authority
correct commit provenance   != complete cognitive body
social evidence retrieved   != relationship model revised
valid event at emission     != valid state at delivery
same semantic failure       != same wire representation
cleanup action executed     != substrate health restored
```

を別state / receipt / benchとして持つのが今回の主要な設計差分である。
