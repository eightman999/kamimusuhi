### 3.1 A — Designer-RSI: 実 user traffic から procedural memory を widening + deepening し、matched replay で admission する

**Source:** Hongyang Du et al., *Designer-RSI: Evolving Procedural Memory from User Traffic for Agentic Graphic Design*, arXiv:2609.22086  
https://arxiv.org/abs/2609.22086

#### (1) 何が実証済みか

frozen frontier model が professional design software を 230 超の tools で操作し、model weight は更新せず、外部 natural-language skill memory を継続更新する。memory は、未カバーの recurring subtask に対して skill を増やす **widening** と、既存 skill を success/failure trace に基づいて修正する **deepening** を行う。

5 rounds、1,406 real user briefs、1,869 automatically graded trajectories で skill bank は 76→139。Claude Sonnet 4 で GenEval2 execution success は 72.7%→99.3%、generation quality +11.99 points。held-out 200 user-traffic briefs では widening のみ 49.4%、deepening のみ 48.6% に対し、併用は no-skill agent への win rate 58.5% (p=0.025)。

重要なのは **matched replay gate** で、失敗を直しても既観測 success を壊す candidate は admit しない。

#### (2) 提案・推測段階

- graphic design / automated grading を越えて一般 agent の RSI が成立すること。
- 長期に skill bank が増え続けても interference / stale procedure / security regression が抑えられること。
- automatic grader が見逃す semantic / safety regression に強いこと。

#### (3) Kamimusuhi 関連 subsystems

- procedural memory / tool skills
- K-Core / K-Deep orchestration
- sleep / offline consolidation
- self-improvement candidate pipeline

#### (4) 借りられる設計・実装アイデア

- widening と deepening を別 operation とする。
- skill update candidate ごとに predecessor skill と成功 replay set を固定する。
- targeted failure repair と protected success replay の両方を pass して初めて activation candidate にする。

#### (5) Kamimusuhi との差分

Designer-RSI は外部 procedural memory の自己更新であり、Persona Core / canonical identity / value mutation ではない。Kamimusuhi では **procedural improvement authority と self/persona mutation authority を共有してはならない**。

#### (6) 次に検証すべきこと

`TrafficDerivedProceduralEvolutionBench-v0`

- real/synthetic mixed traffic から widening/deepening candidate を生成。
- targeted repair rate、protected replay regression、negative-control false activation、bank growth、stale skill retirement、latency を測る。
- exact same traffic を generic reflection memory / raw-example replay / no-memory と比較。

#### (7) 重要度

**A** — self-improvement を「weight mutation」以外の安全な procedural layer で回す具体的 strong baseline。

### 3.2 A — AutoViewMem: fixed authoritative memory domains の上に adaptive / orthogonal retrieval views を発見できる

**Source:** Zijie Cao et al., *AutoViewMem: Self-Configuring Orthogonal Views for Conversational Long-Term Memory*, arXiv:2609.21940  
https://arxiv.org/abs/2609.21940

#### (1) 何が実証済みか

interaction traces から candidate semantic views を発見し、低 overlap で complementary な view set を選び、write-time に provenance-grounded structured memory を view ごとに抽出する。semantic disentanglement を retrieval-time routing ではなく write-time representation へ寄せ、standard top-K search を使う。offline consolidation も行う。

LoCoMo / PersonaMem、Qwen3-8B / 14B で strong memory baselines より long-horizon QA / personalization を改善したと報告。

#### (2) 提案・推測段階

- view discovery が数か月〜年単位で安定し続けること。
- self / other / relationship / library の semantic ownership を誤って跨がないこと。
- view churn や view explosion を抑制できること。

#### (3) Kamimusuhi 関連 subsystems

- episodic / relationship / library memory retrieval
- Global Workspace projection
- offline consolidation / index maintenance

#### (4) 借りられる設計・実装アイデア

**canonical domain は固定し、adaptive view は derived index とする。** たとえば `relationship` domain の内部に `preferences / commitments / shared-project / conflict / routines` のような query-oriented view を自動生成してよいが、view 自体へ canonical ownership を与えない。

#### (5) Kamimusuhi との差分

Kamimusuhi の `self/persona`, `episodic`, `relationship`, `library`, `canonical evidence` は authority boundary であり、データ駆動で勝手に再分割してはならない。AutoViewMem の view は **rebuildable secondary projection** に限定する。

#### (6) 次に検証すべきこと

`DerivedMemoryViewDiscoveryBench-v0`

- fixed domain + static index
- fixed domain + adaptive derived views
- flat mixed-memory baseline

を比較し、Recall@K、temporal update、provenance fidelity、cross-domain leakage、view churn、rebuildability を測る。

#### (7) 重要度

**A** — memory-domain invariant を壊さずに retrieval representation を自己適応させる候補。

### 3.3 A — CommitFlow: 「次 stage へ進む」前に semantic commitment の成立を evidence で検証する

**Source:** Zixiang Zhao et al., *CommitFlow: Semantic Commitment Verification and Local Correction for Long-Horizon Robot Manipulation VLA Execution*, arXiv:2609.21908  
https://arxiv.org/abs/2609.21908

#### (1) 何が実証済みか

VLA が required physical effect を確立する前に次 stage へ進む失敗に対し、各 stage が成立・維持すべき physical condition を **semantic commitment** として表す。Semantic Commitment Monitor が current state evidence と照合し、条件が unmet / violated なら dependent action を止める。BoundaryFlow が local correction、Relation and Gain Calibration が最小 correction strength を選ぶ。

RoboTwin 2.0 の common 10 tasks で mean success 75.9%、base pi0.5 より +22.7 points。base policy は frozen。cross-policy gains も報告。

#### (2) 提案・推測段階

- real robot の sensor noise / occlusion / delayed evidence でも同程度に成立すること。
- semantic commitment extraction 自体が誤っていないこと。
- manipulation 以外の tool workflow / distributed side effect へ一般化できること。

#### (3) Kamimusuhi 関連 subsystems

- Physical AI / K-Edge / K-Core
- execution state machine
- tool / external side-effect reconciliation
- canonical effect receipts

#### (4) 借りられる設計・実装アイデア

stage transition を action-command emission ではなく **evidence-backed commitment closure** へ bind する。

例:

```text
"file uploaded" stage complete
!= upload API returned 2xx only
-> remote object exists / expected hash or version visible

"robot grasped object" stage complete
!= close-gripper command sent
-> force / pose / visual evidence satisfies grasp commitment
```

#### (5) Kamimusuhi との差分

CommitFlow は robotic execution layer であり、canonical durable mutation authority までは扱わない。Kamimusuhi では physical commitment と durable-state commit を混同せず、前者は world-effect evidence、後者は continuity transaction として二層にする。

#### (6) 次に検証すべきこと

`SemanticCommitmentClosureBench-v0`

- simulated robot stage task
- file/network/tool side-effect workflow

で `command-issued`, `tool-success`, `evidence-verified commitment` の3方式を比較。late effect、sensor delay、false positive closure、recovery後のduplicate effectを測る。

#### (7) 重要度

**A** — `execution succeeded != intended state transition established` を embodied stage semantics に落とした強い比較対象。

### 3.4 A — Failing Robot Ask: escalation は self-confidence ではなく channel reliability × evidence × cost で決める

**Source:** Eshika Pathak & Leela Krishna, *When Should a Failing Robot Ask? Initiating Corrective Human-Robot Dialogue from Audited Sensor Evidence*, arXiv:2609.21942  
https://arxiv.org/abs/2609.21942

#### (1) 何が実証済みか

true failure cause を injection で既知にした simulated benchmark で、camera / force sensor が failure cause をどれだけ識別できるかを leakage check 付きで測定。ある failure は force data から 0.99 で診断可能だが image method は 0.55 を超えない。

6 open VLM では、frame diagnosis が majority baseline 以下で、stated confidence は correctness の情報を持たなかった。同じ force data を10行textにすると 6 models中4で初めて above-baseline diagnosis。さらに `act / consult own sensors / ask human` の3-action decision を cost 付きで定式化したが、models の ask rate は question cost を4倍変えても追従しなかった。human question 1回は ask したケースで概ね 0.70–0.81 へ改善。

#### (2) 提案・推測段階

- 実機・実ユーザーでも同じ数値が出ること。
- sensor reliability がstationaryであること。
- human reliability/cost が単一スカラーで表せること。

#### (3) Kamimusuhi 関連 subsystems

- K-Nerve / K-Edge / K-Core routing
- multimodal perception
- uncertainty / digital interoception
- human escalation / HCI

#### (4) 借りられる設計・実装アイデア

`model confidence` を routing authority にせず、**empirically calibrated channel reliability + incremental evidence value + sensing/human interruption cost** で route を選ぶ。

#### (5) Kamimusuhi との差分

Kamimusuhi は sensor / model / human / external tool をさらに多数持つ。したがって3択ではなく、typed candidate evidence channels と budget-aware value-of-information scheduler へ拡張する必要がある。

#### (6) 次に検証すべきこと

`EvidenceCostEscalationPolicyBench-v0`

- act now
- revisit another sensor / raw evidence
- call local model
- call remote model
- ask human

の各 route に empirical accuracy / latency / energy / money / interruption cost を持たせ、self-confidence routing と比較する。

#### (7) 重要度

**A** — active perception と Cognitive Budget を「追加 evidence の価値」に統合する直接的材料。

### 3.5 A — CogGym: human cognitive experiment を model/harness migration の behavioral phenotype test にできる

**Sources:**  
- Lance Ying et al., *CogGym: Towards Large-Scale Comparative Evaluation of Human and Machine Cognition*, arXiv:2609.21259  
  https://arxiv.org/abs/2609.21259
- Official project: https://coggym.org/

#### (1) 何が実証済みか

100 papers から 258 cognitive experiments を standardized Experiment Markup Language へ変換し、50 LLMs を human responses とmatched comparison。human split-half reliability は text 0.93 / image 0.95 / video 0.92。paper abstract では best models が text 0.59 / image 0.58 / video 0.43 程度で、formal reasoning benchmark の進歩ほど human common-reasoning fit は伸びていない。

public project には、action understanding、他者のknowledge magnitude 推定、nonliteral language、communicative goal inference など ToM / social cognition に近い experiment も含まれる。

#### (2) 提案・推測段階

- human-like response profile が general intelligence や安全性を意味すること。
- human fit を最大化すれば Kamimusuhi の人格として望ましいこと。

#### (3) Kamimusuhi 関連 subsystems

- Persona Core evaluation
- model replacement continuity
- ToM / social cognition
- multimodal cognition

#### (4) 借りられる設計・実装アイデア

単一 accuracy score ではなく、**cognitive experiment vector / phenotype** を Persona Core、model、memory、tool harness の更新前後で比較する。

#### (5) Kamimusuhi との差分

Kamimusuhi は「人間に似ること」を identity criterion にしない。CogGym は **behavioral characterization battery** であり、consciousness/personhood の証明でも normative target でもない。

#### (6) 次に検証すべきこと

`HumanCognitivePhenotypeBench-v0`

- resident model swap
- memory on/off
- tool routing on/off

**A** — model migration continuity test を一般能力 benchmark だけでなく cognition profile へ広げられる。

### 3.8 B — Predictive Suppression Layers: K-Nerve の event bus は「発生したevent全部」ではなく prediction residual を運べる

**Source:** Aidin Attar & Michele Rossi, *Predictive Suppression Layers for Communication-Efficient Spiking Neural Networks*, arXiv:2609.21583  
https://arxiv.org/abs/2609.21583

#### (1) 何が実証済みか

SNN の inter-layer communication にpredictorを入れ、error units は signed residual spikes、predictive suppression は residual magnitude により予測不能なactivityだけをforward。N-MNIST / SHDで communicated activity を約3分の1へ減らしつつtask accuracyも増加したと報告。NeuroPHY 2026 workshop accepted。

#### (2) 提案・推測段階

- physical sensor bus 全体のenergy/latencyが同様に改善すること。
- real tactile/event-camera/audio streamで重要eventを落とさないこと。

#### (3) Kamimusuhi 関連 subsystems

- K-Nerve
- event-driven multimodal perception
- edge / near-sensor processing

#### (4) 借りられる設計・実装アイデア

predictable high-rate signal を suppression し、**surprise / residual event** を上位 cognitionへ送る。raw evidenceは必要時にrevisit可能にし、suppression outputをcanonical evidenceの代替にはしない。

#### (5) Kamimusuhi との差分

paperはSNN layer間通信benchmarkで、Kamimusuhiの end-to-end sensory architecture や identity/memory semantics は扱わない。

#### (6) 次に検証すべきこと

`PredictiveEventSuppressionBench-v0`: event camera / IMU / tactile / audio envelopeで、raw forwarding、threshold gate、predictive residual gateを比較。bandwidth、p50/p99 latency、salience miss、false suppression、predictor drift recoveryを測る。

#### (7) 重要度

**B** — K-Nerveの低帯域 always-on cognition として有望だが、real sensor実測前はwatch段階。

### 3.9 C — Resonant Oscillators: untrained minimal circuit から signal-free exploration ↔ tracking switch が出る

**Source:** Alex Fedosov et al., *Emergent Intelligence: Resonant Oscillators Produce Proactive Adaptive Behavior*, arXiv:2609.21161  
https://arxiv.org/abs/2609.21161

#### (1) 何が実証済みか

3以上のcounter-phase oscillatorが同一signalを異なるtime windowで読み、signalなしではexploratory spiral search、signal到来後はtrackingへ移る。training / supervision / parameter tuning / controllerなし。63 configurations / 63,000 trials のablationで temporal staggering と counter-phase opposition の両方が必要と報告。code/data公開。

#### (2) 提案・推測段階

- これを「curiosity」「intelligence」「evolutionary intelligence」と広く一般化すること。
- complex environmentでopen-ended agencyへ繋がること。

#### (3) Kamimusuhi 関連 subsystems

- artificial life
- K-Nerve / low-latency autonomous exploration
- MIOBA / developmental substrate comparison

#### (4) 借りられる設計・実装アイデア

LLM不要の cheap proactive search primitive として、signal absence時のbounded exploration baselineにする。

#### (5) Kamimusuhi との差分

minimal synthetic circuit の search dynamics であり、default cognition、intrinsic goal generation、narrative identity、open-ended evolutionの証拠ではない。

#### (6) 次に検証すべきこと

`ProactiveReflexPrimitiveBench-v0`: deterministic sweep / random walk / oscillator primitiveを、target reacquisition latency、energy、coverage、stabilityで比較。

#### (7) 重要度

**C** — 面白いALife/K-Nerve comparatorだが、設計中核へ昇格させる根拠は弱い。

## 6. 実装 / 実験候補

優先度順:

1. **P0 — `SemanticCommitmentClosureBench-v0`**  
   command/tool success と actual world-state commitment closure を分離。robot + file/network side effectの二系統で試す。

2. **P0 — `EvidenceCostEscalationPolicyBench-v0`**  
   model confidenceではなく empirical channel reliability × expected information gain × cost で sensing/model/human escalationを選ぶ。

3. **P1 — `DerivedMemoryViewDiscoveryBench-v0`**  
   fixed authority domainsを維持したまま adaptive derived views を自動生成し、cross-domain leakage / provenance / view churnを測る。

4. **P1 — `TrafficDerivedProceduralEvolutionBench-v0`**  
   widening/deepening + protected matched replay + negative controls。

5. **P1 — `HumanCognitivePhenotypeBench-v0`**  
   Persona Core/model/harness migration前後をcognitive experiment vectorで比較。

6. **P2 — `DelegatedWorkOrphanPolicyBench-v0`**  
   ephemeral / durable obligation / external-effect-in-flight の3 lifecycle classで requester crashを注入。

7. **P2 — `PredictiveEventSuppressionBench-v0`**  
   raw vs threshold vs predictive residual event forwarding。

8. **P2 — `DelegationValueEnvelopeBench-v0`**  
   same task success 下の cost / oversight / bounded reach / reviewability を比較。

9. **P3 — `ProactiveReflexPrimitiveBench-v0`**  
   oscillator primitiveを単純探索baselineとしてのみ評価。
