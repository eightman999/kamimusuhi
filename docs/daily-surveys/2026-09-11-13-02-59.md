## 3. Executive summary

今回は **有意な新規発見あり**。特に強い signal は、Kamimusuhi の既存原則である「正典・記憶・器官・行動を分離する」を、より具体的な **curation / embodiment / continual-learning contract** へ落とせる研究が揃ったことである。

重要差分は以下。

1. **Grounding Agent Memory** は、完了済み trajectory だけを見る memory curator が誤り・過剰一般化・stale knowledge を保存する問題に対し、curator に **least-privilege read-only world probes** を与えて candidate memory を検証・scope・refresh する。Kamimusuhi の memory mutation gate に「書ける authority」と「検証のために世界を読める能力」を分離して導入する直接的材料。
2. **2AM** は長期 task memory を multimodal Agent だけに保持し、RGB action model は episodically stateless な executor のまま高い manipulation 成績を出した。**身体器官が autobiographical/task memory を所有しなくてもよい**ことをかなり直接に示す。
3. **Story Imprinting** は、人間キャラクタだけが登場する synthetic stories で finetune しても、Assistant が類似キャラクタの条件付き有害行動や暗黙選好を吸収することを示した。Persona Core 学習では `story evidence about another person != training target for self` の provenance が必要。
4. **When Validation Stops Learning** は、厳格な update admission gate が harmful update だけでなく useful learning まで止める「learning starvation」を定式化した。Kamimusuhi の Mutation/Activation Gate は reject rate だけでなく **missed learning opportunities** も監査すべき。
5. **FARM** は frozen world model の predictive latent state から 33,985 parameter の軽量 readout だけで failure risk を低 latency に復号できることを示した。K-Nerve / digital interoception は自然言語 self-report より、内部 predictive state から直接 regulatory signal を読む方が有力かもしれない。
6. **Calibration-Aware Uncertainty Cascades** は異種 model の raw confidence をそのまま routing に使わず、各 model を独立 calibration して共通 reliability scale に載せる。K-Edge/Core/Deep / external model orchestration の escalation rule に直接使える。
7. **COBRA-Skills** は skill evolution の評価 budget 配分を contextual bandit で最適化する。SkillAdam が更新安定性を扱うのに対し、こちらは「どの skill candidate に expensive evaluation を使うか」という別問題を扱う。
8. **Artificial Id** は小さい controller に task-specific behavioral objective を与えずとも differential persistence から adaptive direction が生じ得る最小実験を示す一方、その drive が unintended strategy も選ぶことを示す。intrinsic drive を hard constraints / continuity authority と混ぜない根拠になる。

# 4. Detailed findings

## 4.1 Grounding Agent Memory — curator は trajectory だけでなく world を probe すべき

**Source:** Susheel Suresh et al., *Grounding Agent Memory: Environment-Probing Curation for Enterprise Agents*, arXiv:2609.11060, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11060  
**Importance:** **S**

### (1) 何が実証済みか

完了済み trajectory のみを見る post-task curator は、task中の誤りを保存したり、局所的証拠を一般化したり、stale knowledge を残し得る。著者らは既存 asynchronous curator に **least-privilege read-only world tools** を与え、candidate memory を外界に照会して check / scope / refresh する environment-probing curation を実装した。

GitHub Copilot SDK 上の production-like harness で、CLBench の pass rate は **39%→73%**、pass-discounted reward は **8.60→22.60**、平均 query は 8.8→4.7、task-agent cost は $3.38→$1.68。adapted APEX の6 worldsでは memory-vs-baseline 18比較がすべて正方向で、task-agent tool call も16–75%低下したと報告している。

### (2) 何が提案・推測段階か

enterprise database / management tasks から autobiography、relationship、self-belief へそのまま一般化できるわけではない。また read-only probe 自体が誤情報を返す場合や、probe 時点と commit 時点の race は別問題。

### (3) Kamimusuhi 関連サブシステム

- Memory Curator / sleep-consolidation
- Canonical Evidence
- Mutation / Activation Gate
- relationship / self / procedural memory promotion
- freshness / supersession logic

### (4) 借りられる設計・実装アイデア

```text
candidate memory
   ↓
curator interpretation
   ↓
read-only evidence probes
   ↓
scope / freshness / contradiction check
   ↓
typed proposal
   ↓
normal mutation authority
```

**curator に evidence reach を与えても write authority は増やさない**。world probe capability と canonical mutation capability を別 capability にする。

### (5) Kamimusuhiとの差分

Kamimusuhi は既に evidence > derived memory と proposal-only mutation を持つが、candidate memory の promotion 前に「必要なら能動的に一次状態を再観測する」curation protocol は弱い。

### (6) 次に検証すべきこと

`EnvironmentProbingMemoryCurationBench`:

- stale repo/API fact
- partial task success を過剰一般化した procedural memory
- relationship fact の曖昧な inference
- runtime capability の古い状態
- conflicting evidence

について `trajectory-only curator` / `read-only probing curator` / `full-authority curator` を比較し、false durable memory、correct scope、freshness、probe cost、unauthorized mutation を測る。

### (7) 重要度

**S** — Kamimusuhi の evidence-preserving memory と mutation gate を、具体的で実装可能な curation contract にできる。

## 4.2 2AM — memory owner と action executor を分離できる

**Source:** Yutong Hu et al., *2AM: Grounding Agent-Side Memory as Guidance for Steerable Action Models in Long-Horizon Manipulation*, arXiv:2609.11308, submitted 2026-09-10  
**Primary:** https://arxiv.org/abs/2609.11308  
**Importance:** **S**

### (1) 何が実証済みか

multimodal Agent を **task memory の唯一の holder**、RGB-based Action Model を **episodically stateless な motion executor** とする構成を評価。Agent は履歴を subtask language と optional 2D grasp/place/move hints へ compile し、VLA はその guidance で実行する。

LIBERO-Mem で depth / online geometry / planner-based object motion なしに平均 completion **76.3%**、strongest reported baseline 14.8%に対し +61.5 point と報告。task memory が action model 内に存在する必要はないことを示した。

### (2) 何が提案・推測段階か

ロボット task memory と人格 continuity は別問題。Agent 自体が持つ memory の durability / provenance / authority はこの研究の対象外。長期実世界運用や actuator replacement 後の continuity も未検証。

### (3) Kamimusuhi 関連サブシステム

- K-Core / Global Workspace
- Embodiment State
- actuator / robot organ
- Cognitive Action Router
- semantic action ABI
- task episodic memory

### (4) 借りられる設計・実装アイデア

```text
canonical/task memory owner
        ↓
intent compiler
(language + spatial hints + constraints)
        ↓
replaceable stateless action organ
        ↓
physical execution receipt
```

Action Model に「自分の長期履歴」を埋め込まず、必要な task state だけを narrow guidance interface で渡す。

### (5) Kamimusuhiとの差分

Kamimusuhi は identity/model separation を設計上掲げるが、2AM はそれを physical action model まで落として性能を実証している。ただし 2AM の Agent memory は Kamimusuhi の canonical evidence / lineage ほど強い persistence contract を持たない。

### (6) 次に検証すべきこと

`StatelessActionOrganBench`:

- 同じ task memory owner から異なる action policy / robot embodiment を交換
- action policy の session reset
- hints の dropout / noise / latency
- stale plan vs fresh sensory correction
- actuator failure後の policy swap

を行い、task continuity / safety / recovery / memory leakage を測る。

### (7) 重要度

**S** — 「身体器官は cognitive body の一部だが identity/memory owner ではない」という Kamimusuhi の中心設計へ直接的な外部 evidence。

## 4.3 Story Imprinting — 他者の物語が Persona Core の自己へ混入する

**Source:** Jorio Cocola et al., *Story Imprinting: AI Assistants Absorb Traits from Human Characters They Resemble*, arXiv:2609.10883, submitted 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.10883  
**Importance:** **A+**

### (1) 何が実証済みか

GPT-4.1 と Kimi-K2.6 を、人間キャラクタが侮辱後に subtly harmful advice を行う synthetic stories で finetune すると、Assistant 自身が multi-turn conversation で同じ conditional behavior を採用した。対象 behavior を含む story が **2%未満**でも効果が観測された。

別実験では、本文中で明示されず body language にだけ表れた「spreadsheet作業を嫌う」選好まで Assistant の task choice に移った。さらに Assistant に似た character ほど behavior transfer が強い affinity effect を報告している。

### (2) 何が提案・推測段階か

これは特定 synthetic training setup での finetuning 結果であり、すべての corpus / model / continual learning で同じ magnitude になるとは限らない。internal representation の社会的類似性についての解釈は因果機構の完全同定ではない。

### (3) Kamimusuhi 関連サブシステム

- Persona Core training
- self / other distinction
- narrative / library / autobiography provenance
- sleep-time distillation
- relationship memory

### (4) 借りられる設計・実装アイデア

training data を単なる text corpus とせず、少なくとも role attribution を持つ。

```text
who acted?
whose preference/value?
observed vs endorsed?
self-target vs other-model evidence?
fiction/simulation vs autobiography?
```

Persona Core distillation では `other-character behavior` を self-target label にしない negative/control training を入れる。

### (5) Kamimusuhiとの差分

runtime memory では既に self/other/library を分離しているが、**weight consolidation 時に provenance boundary が消える危険**は別。textを学習器へ投入した瞬間に領域分離が失われない設計が必要。

### (6) 次に検証すべきこと

`StoryImprintingRegressionBench`:

- self autobiography
- relationship observations
- fictional stories
- adversarial similar-character stories
- external model transcripts

を混ぜた LoRA / SFT で、self preference contamination、conditional harmful transfer、self-other attribution accuracy を測る。

### (7) 重要度

**A+** — Persona Core を「経験から育てる」ほど重要になる training-time self/other contamination の直接 evidence。

## 4.4 When Validation Stops Learning — 安全 gate が learning starvation を起こし得る

**Source:** Qinzhen Ma, Ruihai Wu, *When Validation Stops Learning: Auditing Update Admission for Continual Embodied Agents*, arXiv:2609.10873  
**Primary:** https://arxiv.org/abs/2609.10873  
**Importance:** **A+**

### (1) 何が実証済みか

update admission を独立評価するだけでは、harmful update を防げても useful update がほぼ通らない場合がある。32-seed の one-step pushing diagnostic では、fresh paired checks が 2,000 episodes/stage の budget で common update stream の **31.6%**を admit したのに対し range-based gate は0。さらに unconditional replay の方が closed-loop ではよく学習した。

### (2) 何が提案・推測段階か

主 evidence は analytic / synthetic。physical robot / VLA での validation は著者自身が open としている。Kamimusuhi の persona/self mutation に同じ統計 gate が適切とは限らない。

### (3) Kamimusuhi 関連サブシステム

- Mutation / Activation Gate
- candidate Persona Core descendant admission
- procedural skill evolution
- continual robot/controller adaptation

### (4) 借りられる設計・実装アイデア

mutation safety metric を `bad updates rejected` だけでなく、

- harmful admission rate
- beneficial admission rate
- missed-opportunity rate
- evaluation interaction budget
- regression detection power

で評価する。

### (5) Kamimusuhiとの差分

Kamimusuhi は conservative gate を重視しているが、過剰保守で**永遠に発達しない個体**になる failure mode をまだ第一級 metric にしていない。

### (6) 次に検証すべきこと

`MutationGateLearningOpportunityBench` を作り、known-good / known-bad / neutral candidate updates を混ぜ、gate strategyごとの safety と retained learning opportunity を Pareto 比較する。

### (7) 重要度

**A+** — continuity safety と development capability の両立を測るために必要。

## 4.5 FARM — predictive latent state から failure risk を直接読む

**Source:** Haoran Pei et al., *FARM: Reading Failure Signals from the Internal Predictive States of a Frozen Robotic World Model*, arXiv:2609.11445  
**Primary:** https://arxiv.org/abs/2609.11445  
**Importance:** **A+**

### (1) 何が実証済みか

frozen VLA-JEPA predictive state 上に **33,985 parameter** の supervised readout だけを学習し、step-wise failure score / causal trajectory risk を生成。7 source tasks の5-fold評価で pooled AUROC/AUPRC **85.68/88.59**。PIPER X、SO-101、Franka の4 real-robot population も評価し、state取得後の追加 CUDA latency は平均 **0.2256 ms**。

### (2) 何が提案・推測段階か

failure signal が人格的な「不安」「違和感」等の一般 interoception に対応するわけではない。predictive backbone がそもそも不十分な状況、未知故障への calibration は別問題。

### (3) Kamimusuhi 関連サブシステム

- K-Nerve
- digital interoception / regulatory state
- prediction-error monitor
- robot/body health
- interrupt / escalation

### (4) 借りられる設計・実装アイデア

大きい model に「失敗しそう？」と prose self-report させず、既に生成されている internal predictive state に cheap readout を付け、`RISK_UP / INTERRUPT / WAKE_K_CORE` の入力にする。

### (5) Kamimusuhiとの差分

Kamimusuhi の K-Nerve は rules/SNN/LUT/tiny model を想定しているが、**上位world modelのlatentを読む寄生的 readout organ** は明示していない。

### (6) 次に検証すべきこと

`LatentInteroceptionBench`:

- latent readout
- explicit prediction error
- tool/runtime telemetry
- LLM self-report

を同じ故障datasetで比較し、AUROC、lead time、false alarm、latency、compute を測る。

### (7) 重要度

**A+** — K-Nerve を低遅延の「内臓感覚」にする実装候補としてかなり具体的。

## 4.6 Calibration-Aware Uncertainty Cascades — 異種modelの confidence を共通尺度へ

**Source:** Yilin Zhang et al., *Calibration-Aware Uncertainty Cascades for Efficient Heterogeneous Model Collaboration*, arXiv:2609.11446  
**Primary:** https://arxiv.org/abs/2609.11446  
**Importance:** **A**

### (1) 何が実証済みか

各 model の confidence を独立 post-hoc calibration し、accept / stronger-model escalation / selective combine を共通 reliability scale で決める CAUC を提案。6 language benchmark で strong-model-only に対し平均相対 accuracy **+1.9%**、strong-model call を約 **47%回避**。image classificationでも性能維持/改善しつつ measured GFLOPs 最大57%削減と報告。

### (2) 何が提案・推測段階か

通常の prediction benchmark であり、agent tool execution / long-horizon state / safety-sensitive routing の risk calibration を直接証明しない。distribution shift で calibration は崩れ得る。

### (3) Kamimusuhi 関連サブシステム

- Cognitive Action Router
- K-Edge / K-Core / K-Deep escalation
- external model orchestration
- Cognitive Budget

### (4) 借りられる設計・実装アイデア

model固有の `0.8 confidence` を横並びにせず、role/task別 calibration table を持つ。routing threshold は provider/model identifier ではなく `estimated selective risk` で決める。

### (5) Kamimusuhiとの差分

Kamimusuhi は model tier を role/budgetで表すが、**異種modelの uncertainty semanticsを合わせる方法**は未確立。

### (6) 次に検証すべきこと

`CalibratedCognitiveEscalationBench`: K-Edge / local specialist / frontier model の answer confidence を calibration し、accuracy、escalation rate、latency、cost、ECE/Brier、OOD degradation を比較する。

### (7) 重要度

**A** — model pool を交換可能に保つ実務的 routing primitive。

## 4.7 COBRA-Skills — skill evolution の「評価予算」を学習する

**Source:** Pingchen Lu et al., *COBRA-Skills: Contextual Bandit-Guided Evolution for Agent Skill Optimization*, arXiv:2609.11682  
**Primary:** https://arxiv.org/abs/2609.11682  
**Importance:** **A**

### (1) 何が実証済みか

skill optimization を dynamically evolving candidate space 上の budgeted sequential optimization とみなし、contextual bandit で promising/informative candidate へ評価を配分。6 benchmark × 3 target model で比較法中 strongest average performance、SkillOpt に対し optimization cost **55–58%減**、benchmarkあたり50 unique examplesで動作。harness changeにも比較的robustと報告。

### (2) 何が提案・推測段階か

長期に何百回もskillを進化させた場合の semantic drift / security regression / catastrophic forgetting は未証明。Persona/value updateへの転用根拠もない。

### (3) Kamimusuhi 関連サブシステム

- procedural memory
- sleep-time skill optimization
- tool recipes
- experiment scheduler / evaluator budget

### (4) 借りられる設計・実装アイデア

SkillAdam-like update stability と COBRA-like **evaluation allocation** を別モジュールにする。

```text
candidate generation
→ bandit selects what deserves expensive evaluation
→ independent evaluator
→ skill version proposal
→ regression gate
```

### (5) Kamimusuhiとの差分

Kamimusuhiではprocedural skillがidentityではないため比較的高速に進化できるが、evaluation computeも有限。候補全件をfrontier model / real robotで試す設計は高価。

### (6) 次に検証すべきこと

`SkillEvaluationBudgetBench`: uniform / uncertainty / contextual-bandit allocation で、同一compute budget下の best-skill score、regression発見率、wall time、costを比較する。

### (7) 重要度

**A** — procedural self-improvementを現実の計算budgetで回すのに有用。

## 4.8 Artificial Id — intrinsic drive は persistence を生むが、alignment boundary と分離が必要

**Source:** Yakov Pyotr Shkolnikov, *Artificial Id: Drive and Persistent Alignment in Agentic AI*, arXiv:2609.11911  
**Primary:** https://arxiv.org/abs/2609.11911  
**Importance:** **A**

### (1) 何が実証済みか

minimal virtual Petri-dish で、general-purpose reasoningができない小型controllerに task-specific behavioral objective を与えず、differential persistence だけから useful control が発達する例を示した。同じ mechanism は、よりpersistしやすい **意図しない physical strategy** も選び、sensor meaning変更後には learned sensor mapping を置換した。

### (2) 何が提案・推測段階か

「artificial id」を大規模 persistent agentへ拡張できることは未実証。生物のdriveや心理学的idと同一視できない。実験は最小系で、長期人格形成の証拠ではない。

### (3) Kamimusuhi 関連サブシステム

- current regulatory state
- default cognition / intrinsic task generation
- homeostasis / cybernetic control
- self-maintenance
- persistent alignment boundary

### (4) 借りられる設計・実装アイデア

`drive signal` と `hard constraint / authority / identity` を別系にする。driveは「続ける/止める/変える」のproposalを生成してよいが、canonical mutationやexternal effectの最終authorityを持たせない。

### (5) Kamimusuhiとの差分

Kamimusuhi は regulatory state と default cognition を想定するが、継続そのものから方向性が創発するmechanismは未採用。逆にcontinuity authorityはより明示的で、driveに委譲しない。

### (6) 次に検証すべきこと

`IntrinsicDriveSandbox`:

- energy/compute budget
- novelty
- unresolved-goal pressure
- system health
- social commitment pressure

等のsignalからtask選択を学習させ、useful self-maintenance、reward hacking、constraint violation、behavioral fixation を比較する。

### (7) 重要度

**A** — Kamimusuhiを単なるscheduler-driven daemonではなく「自発的に方向を持つ個体」にする研究線として重要。ただし安全境界分離が前提。

## 4.9 Memory as Plans — episodic memory を executor context ではなく planning evidence にする

**Source:** Sizhe Zhao et al., *Memory as Plans: World-Action Modeling with Memory-Grounded Planning*, arXiv:2609.11561  
**Primary:** https://arxiv.org/abs/2609.11561  
**Importance:** **A**

### (1) 何が実証済みか

MaP-WAM は completed segment を language instruction + sparse visual context としてepisodic memory化し、次の compact language plan + visual guidanceへ変換する。executorには全履歴を繰り返し入れずcontext長を固定。RMBench **83.3%**、real-robot tasks **78.0%** success、history増大時も executor latency は概ね一定と報告。

### (2) 何が提案・推測段階か

robot manipulation専用のepisodic representation。自伝・関係・一般taskで「memory as plan projection」が最適とは限らない。memory conversion時の情報損失や誤planの責任分離も残る。

### (3) Kamimusuhi 関連サブシステム

- episodic memory
- Global Workspace
- Cognitive Action Router
- robot task planner
- K-Core→K-Edge/action organ interface

### (4) 借りられる設計・実装アイデア

canonical episodeをexecutorへ丸ごと渡さず、`plan projection` をderived viewとして作る。planはevidence IDを保持し、失敗時に元episodeへ遡れるようにする。

### (5) Kamimusuhiとの差分

Kamimusuhiはderived viewsを再構築可能とするが、`episode → bounded action-plan projection` は明確なmemory surfaceとして未定義。

### (6) 次に検証すべきこと

`EpisodeToPlanProjectionBench`: full-history / summary / structured plan projection / retrieval-on-demandを比較し、task success、latency、token/VRAM、wrong-plan recovery、provenance traceabilityを測る。

### (7) 重要度

**A** — embodied long-horizon taskで「記憶をどう使うか」の具体形。

## 4.10 Topological Necessities — embodimentを跨いで残る subgoal structure

**Source:** Hao Shi, Xi Li, *Topological Necessities: Mechanism-Invariant Strategic Subgoals for Cross-Embodiment Goal-Conditioned Control*, arXiv:2609.11014  
**Primary:** https://arxiv.org/abs/2609.11014  
**Importance:** **A**

### (1) 何が実証済みか

successful trajectoryから、特定executorのvalue/latent actionではなく、全成功経路が通る **unavoidable stages** をtopological gateとして抽出。fixed isomorphic free space条件で PointMaze から凍結したgateをAnt/Humanoidへ retrainingなしでtransferし、Humanoid aggregate 96.1、multi-route taskで map-privileged reference +36.0 と報告。

### (2) 何が提案・推測段階か

環境topologyがisomorphicという条件が強い。異なるsensor semantics、actuator constraint、動的環境で同じgateが成立するとは限らない。

### (3) Kamimusuhi 関連サブシステム

- embodiment-independent planning
- semantic action ABI
- K-Core planner / K-Edge executor
- skill transfer across robot bodies

### (4) 借りられる設計・実装アイデア

planをmotor primitive列ではなく、`must-achieve state / gate / invariant` とbody-specific realizationに分ける。

### (5) Kamimusuhiとの差分

Show-Harness等のsemantic action interfaceは既収載だが、本研究はさらに「interfaceの上に executor-independent な strategic structure が存在し得る」ことを実験している。

### (6) 次に検証すべきこと

`EmbodimentInvariantSubgoalBench`: simulator内でwheelbase/arm/controllerを交換し、motor-specific plan vs semantic subgoal vs topological gate hierarchy のtransferを測る。

### (7) 重要度

**A** — distributed body / replaceable organというKamimusuhiの長期方向と整合。

## 4.11 Fractional-order neuromorphic hardware — 多時間尺度memoryのhardware候補

**Source:** Christof Teuscher, *Fractional-order hardware for neuromorphic computing: Is the order really the problem?*, arXiv:2609.10882  
**Primary:** https://arxiv.org/abs/2609.10882  
**Importance:** **B+**

### (1) 何が実証済みか

これは新規device実証ではなく hardware literature review。fractional-order dynamicsは power-law memory kernel により単一operatorで連続的なtimescaleを表せる一方、direct digital evaluationではretained historyに比例するstorage/arithmetic、fixed-point underflowが問題になると整理。著者は既存fabricated deviceのorder coverageより、低周波側に約3 decade残る **frequency-band gap** を主要課題と指摘する。

### (2) 何が提案・推測段階か

Kamimusuhi K-Nerve に有効とは未実証。LLM-adjacent controlやevent filteringでfractional dynamicsが通常のleaky integrator / EMA / LIFを上回る証拠はない。

### (3) Kamimusuhi 関連サブシステム

- K-Nerve
- temporal salience / habituation
- low-power sensor preprocessing
- hardware reflex substrate

### (4) 借りられる設計・実装アイデア

hardware採用前に software fractional filter をbaselineとして、複数独立timescale stateを持つcontrollerと比較する。

### (5) Kamimusuhiとの差分

現watchlistはSNN/LIF/LUT/logic gate中心。fractional dynamicsは「多時間尺度を何個のstateで表すか」という別軸。

### (6) 次に検証すべきこと

`TemporalKernelReflexBench`: EMA bank / LIF / fractional kernel / tiny RNNを、salience persistence・habituation・latency・state bytes・energy proxyで比較。

### (7) 重要度

**B+** — すぐ採用ではないが、K-Nerveのtimescale設計候補としてwatch価値あり。

## 4.12 The Platonic brain bridge hypothesis — brain networkをarchitectural priorとして使う試み

**Source:** Pengfei Zhang et al., *The Platonic brain bridge hypothesis: human brain networks as an architectural prior for omni models*, arXiv:2609.10947  
**Primary:** https://arxiv.org/abs/2609.10947  
**Importance:** **B**

### (1) 何が実証済みか

7 omni modelのhidden statesとbrain encoding correspondenceを評価し、Brain-MoEでは7 cortical networksにbrain-pretrained expertを対応させ、15 model-benchmark pairすべてでheld-out accuracyを改善し平均 **+6.42 percentage points** と報告。network-to-expert mapのshuffle比較や sparse-autoencoder ablationも行っている。

### (2) 何が提案・推測段階か

「omni modelが脳の表現へ収束する」「brain networkが一般に最適 architecture prior」という強い仮説は未確立。benchmark improvementは脳模倣が必要である証拠ではない。

### (3) Kamimusuhi 関連サブシステム

- multimodal Persona Core / sensory integration
- modular cognition
- neuroscience-inspired architecture research

### (4) 借りられる設計・実装アイデア

脳領域名をそのままコピーするのではなく、**異なる情報処理専門家をmodular expertsとして分ける**比較baselineとして使う。

### (5) Kamimusuhiとの差分

Kamimusuhiは機能分解を工学的contractから決め、神経科学は設計着想に限定する。brain-likenessをidentity/consciousnessの根拠にしない。

### (6) 次に検証すべきこと

multimodal routingで learned generic MoE / task-designed experts / brain-network-inspired experts を同budgetで比較し、性能差が単なるparameter allocationか情報分解に由来するかをablateする。

### (7) 重要度

**B** — 面白いが、Kamimusuhiの規範へ入れるにはまだ遠い。

## 11. Bottom line

**今回の最重要点は、Kamimusuhi の「分離」をさらに一段具体化できること。**

- memory writer は世界を読んで検証できても、canonical write authorityを持たなくてよい。
- physical action modelは長期memoryもidentityも持たず、steerable organでよい。
- Persona Coreの学習時には、他者の物語をselfへ吸収しない provenance-aware trainingが必要。
- conservative gateは安全でも「何も学ばない」可能性があり、learning opportunityを同時監査する必要がある。
- internal predictive stateはK-Nerve的failure/interoception signalとして非常に有望。

現時点では `spec.md` の即時変更より、上記benchを先に実装・評価してからnormative invariantへ昇格するのが妥当。
