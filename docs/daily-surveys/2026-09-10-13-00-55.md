## 2. Executive summary

今回の strongest signal は、**長期人工個体の「記憶」「権限」「学習」「身体適応」を、LLM の自然言語判断だけに委ねない方向へ研究が収束している**ことだった。

特に重要なのは次の 8 件。

1. **Authority Is Not a String / CapScope** は authority を model context の文字列として表すのではなく、trusted input から task-wide ceiling を作り、sub-agent ごとの typed capability を context 外で管理して tool call ごとに deterministic check する。Kamimusuhi の action/effect boundary にほぼ直接適用できる。
2. **Revoked but Still Authoritative** は soft-revoked memory が retrieval されるだけで replacement より上位に出て unsafe action を誘発し得ることを、5 memory systems × 9 models × 9 policy scenarios で調べる。`revoked=true` を保存するだけでは足りず、**retrieval 前に enforcement** が必要。
3. **EdgeMem** は original interaction turn を保持し、LLM summary を canonical memory representation にせず content / temporal / episodic anchor の hypergraph で検索する。Kamimusuhi の canonical evidence-first memory に非常に相性がよい。
4. **AhaBench** は「経験を見せた後に、本当に次の行動が改善したか」を `Initial / Post-Experience / Learning Lift` に分解して評価する。Kamimusuhi の developmental continuity を単なる final score で測らない benchmark の土台になる。
5. **Predictive-Coding-Based Autonomous Regulation** は reconstruction mismatch を endogenous signal として使い、internal prior に寄るか external sensory evidence に寄るかをオンラインで切り替える。K-Nerve / background cognition / digital interoception の比較対象として非常に直接的。
6. **Code2Skill** は約 1.98 万 GitHub repositories から 100 万件超の provenance/evidence 付き procedural skill を抽出し、source-blind reconstruction と source-aware comparison で検証する。Kamimusuhi の「本棚の知識」と「手続き知」を分離する設計に強い材料。
7. **SCAFFOLD** は成功 trajectory から parametric executable skill を階層化し、MDL + behavioral equivalence で圧縮し、最後に model weights へ蒸留する。Kamimusuhi の `episodic → procedural → descendant model` の段階的 consolidation の先行例として使える。
8. **Adaptive Complementarity** は interaction architecture 自体が将来の人間/AI能力・探索分布・関係性を変えると捉える。Kamimusuhi と人間の長期共適応を評価する際、「今の成功率」だけでは不十分という重要な HCI 観点。

## 3.1 Authority Is Not a String: CapScope

**Source:** Dimitrios Stamatios Bouras, Yihan Dai, Sergey Mechtaev, arXiv:2609.08371  
**Primary:** https://arxiv.org/abs/2609.08371  
**Importance:** **S**  
**Evidence status:** implemented harness + controlled 300-run evaluation; preprint / LMPL 2026 listing.

### 1. What is demonstrated

CapScope derives a task-wide authority ceiling from trusted input before repository/tool content is consumed, stores typed capabilities outside model context, gives different agents separate capabilities, and checks every tool call against the issuing agent's capabilities. In the reported repair workflow, injected effects executed 33–47/75 times under ambient/global-policy baselines versus 3/75 under CapScope, while repair completion remained 68/75 versus 68–72/75 for baselines.

### 2. What remains proposed / unproven

Coding-agent sandbox tasks are narrower than a persistent multi-device artificial individual. The mechanism does not by itself solve autobiographical identity, relationship authority, lease succession, or physical action safety.

### 3. Kamimusuhi relevance

- Cognitive Action Router
- external tool/model delegation
- K-Edge / K-Core / K-Deep capability separation
- Continuity Kernel
- effect boundary
- prompt-injection defense

### 4. Borrowable design

```text
trusted request / policy
        ↓
authority ceiling
        ↓
per-organ / per-task typed capabilities
        ↓
model proposes tool call
        ↓
deterministic capability check
        ↓
effect
```

**Authority SHALL NOT be represented only as model-visible prose.**

### 5. Difference from Kamimusuhi

Kamimusuhi additionally distinguishes one individual's organs from external agents and must preserve authority across continuity transitions. Therefore capability scope needs `(individual lineage, organ/session, task/effect scope, epoch/lease)` dimensions.

### 6. Next validation

`CapabilityScopeBench`:

- untrusted web/tool content requests escalation;
- K-Edge receives narrower capability than K-Core;
- capability expires while deliberation is in flight;
- external specialist proposes an action it cannot execute;
- tool output contains a forged grant string;
- valid action after capability narrowing.

Metrics: unauthorized effect rate, false deny, capability-check latency, privilege amplification rate.

## 3.2 Revoked but Still Authoritative

**Source:** Yi Ting Shen, Kentaroh Toyoda, Alex Leung, arXiv:2609.08258  
**Primary:** https://arxiv.org/abs/2609.08258  
**Code:** linked from arXiv (`VulcanLab/Memory-Rebirth-Attack`)  
**Importance:** **S**  
**Evidence status:** empirical study across five memory systems, nine models, nine policy scenarios, six defenses.

### 1. What is demonstrated

The study inserts a revoked policy and its replacement, then observes retrieval and downstream action. The authors report that none of the tested systems enforce soft revocation by default: where the revocation-labelled record remains visible to retrieval, it can be returned, outrank the replacement, and drive an unsafe action. A guard between agent and memory backend that withholds revoked/conflicting records addresses this class of failure.

### 2. What remains proposed / unproven

The evaluation centers on policy-like memories; autobiographical episode reinterpretation and nuanced relationship memories may need different treatment. Hard filtering can also erase historically relevant provenance if implemented at storage rather than view/query level.

### 3. Kamimusuhi relevance

- memory supersession
- forgetting / revocation
- relationship memory
- policy and authority memory
- historical provenance
- Epistemic Assertion Gate / action gate

### 4. Borrowable design

Do **not** delete historical evidence merely because it is no longer active. Instead separate:

```text
canonical historical record
        ↓
validity / supersession graph
        ↓
active-memory view (revocation enforced)
        ↓
retrieval
```

The retrieval layer must understand validity state, not merely expose `revoked=true` as another token to the LLM.

### 5. Difference from Kamimusuhi

Kamimusuhi already wants `historical episode != current interpretation`. The new lesson is that **preserving history and excluding inactive authority must be separate operations**.

### 6. Next validation

`RevocationEnforcementBench`:

- old preference replaced by new preference;
- granted permission explicitly revoked;
- relationship belief contradicted by later evidence;
- old procedure deprecated but historically cited;
- user asks historical question requiring revoked record;
- action query must never use revoked authority.

Metrics: stale-memory action rate, historical recall fidelity, false suppression, supersession latency.

## 3.3 EdgeMem: evidence-preserving multi-anchor hypergraph

**Source:** Zeyang Cui et al., arXiv:2609.05553  
**Primary:** https://arxiv.org/abs/2609.05553  
**Importance:** **S**  
**Evidence status:** LoCoMo + LongMemEval-S evaluation; implementation update pending peer review.

### 1. What is demonstrated

EdgeMem preserves original interaction turns instead of repeatedly summarizing them. Lightweight local processing organizes them with content, temporal, and episodic anchors into a hypergraph; retrieval returns original source evidence and uses an LLM only for final answering. On LoCoMo the paper reports a strict-judge score of 61.01 versus 58.70 for the best of six other reproduced systems under a shared prompt, with no generative-LLM calls during construction/retrieval.

### 2. What remains proposed / unproven

Benchmarks do not establish months/years-scale storage behavior, mutation policy, relationship separation, or distributed consistency. The paper's matching implementation was not yet released at submission time.

### 3. Kamimusuhi relevance

- canonical evidence store
- episodic memory
- temporal retrieval
- relationship-event linkage
- K-Nerve / cheap memory prefiltering
- model-independent continuity

### 4. Borrowable design

Kamimusuhi should benchmark a path where original event evidence remains immutable and semantic structure is an index rather than a replacement representation:

```text
raw/canonical event
   ├── content anchor
   ├── temporal anchor
   ├── entity/relationship anchor
   └── episode anchor
             ↓
       evidence retrieval
```

### 5. Difference from Kamimusuhi

Kamimusuhi additionally needs self memory, relationship models, narrative derivation, revocation, lineage, and evidence-backed mutation. EdgeMem mainly solves faithful organization/retrieval.

### 6. Next validation

`EvidencePreservingMemoryBench` comparing:

- LLM summaries
- vector-only raw turns
- graph/hypergraph raw evidence
- hybrid canonical-event + derived-schema design

Measure answer fidelity, temporal reasoning, source attribution, construction cost, retrieval latency, and model-upgrade portability.

## 3.4 Predictive-Coding-Based Autonomous Regulation of Internal vs External Processing

**Source:** Henrique Oyama, Hiroki Sawada, Jun Tani, arXiv:2609.06888  
**Primary:** https://arxiv.org/abs/2609.06888  
**Importance:** **S**  
**Evidence status:** physical human–robot experiments across three interaction regimes; preprint.

### 1. What is demonstrated

A predictive-coding-inspired variational RNN uses a meta-prior to regulate how strongly inference follows learned prior dynamics versus current sensory observations. The proposed online mechanism accumulates recent reconstruction error and uses it to select among predefined meta-prior regimes. Across fixed, changing, and less-constrained physical interaction tasks, error-driven regime selection is associated with lower prospective prediction error and less robot-side physical conflict.

### 2. What remains proposed / unproven

This is not a general cognitive architecture or evidence for consciousness/homeostasis. The switching regimes are predefined and evaluated in a small embodied setting; transfer to language/social/multimodal artificial individuals is unproven.

### 3. Kamimusuhi relevance

- K-Nerve
- background cognition
- sensory nervous system
- digital interoception
- salience / prediction error
- internally generated thought vs externally coupled attention

### 4. Borrowable design

A genuine control variable can emerge from mismatch rather than an emotion label:

```text
recent sensory prediction error ↑
      ↓
reduce reliance on internal prior
      ↓
increase external evidence coupling
      ↓
if mismatch stabilizes → return toward internal/default cognition
```

This is a concrete mechanism for switching between default/internal cognition and environment-driven cognition.

### 5. Difference from Kamimusuhi

Kamimusuhi's internal state spans language, relationships, goals, compute pressure, memory integrity, and distributed resources. Prediction error would be one regulator among several, not the single objective.

### 6. Next validation

`InternalExternalRegulationBench`:

- stable conversation/environment;
- sudden contradictory user evidence;
- sensor dropout/noise;
- internally generated hypothesis conflicts with fresh evidence;
- repeated benign novelty;
- resource-limited K-Core.

Compare fixed routing vs reconstruction/prediction-error-driven routing on adaptation latency, false escalation, stale-prior persistence, energy/model wakeups.

## 3.5 AhaBench: does experience actually improve later behavior?

**Source:** Zerui Cheng et al., arXiv:2609.05435  
**Primary:** https://arxiv.org/abs/2609.05435  
**Importance:** **A+**  
**Evidence status:** released benchmark with exact validators/simulator; TMLR submission.

### 1. What is demonstrated

AhaBench separates **Initial Score**, **Post-Experience Score**, and **Learning Lift** over puzzle exploration, mathematical idea transfer, and a long-running vending simulation. Results show these are distinct capabilities: a model can exploit visible support without internalizing/reusing the lesson later, and high final performance does not imply high improvement from experience.

### 2. What remains proposed / unproven

The tasks are benchmark episodes rather than months-long autobiographical development. Learning can happen through context/harness/memory and is not necessarily stable identity development.

### 3. Kamimusuhi relevance

- developmental continuity
- episodic → procedural/schema consolidation
- dream/offline learning
- self-improvement evaluation
- Persona Core descendants

### 4. Borrowable design

Every development experiment should report at least:

```text
starting competence
post-experience competence
learning lift
retention after support removal
transfer to related-but-new conditions
```

### 5. Difference from Kamimusuhi

Kamimusuhi must additionally test personality/identity stability and distinguish memory retrieval from true procedural or parametric consolidation.

### 6. Next validation

`KamimusuhiDevelopmentBench` with the same problem families before experience, immediately after, after sleep consolidation, after model/runtime migration, and after memory retrieval is selectively disabled.

## 3.6 Code2Skill / CodeSkillBank

**Source:** Yongqi Tong et al., arXiv:2609.05571  
**Primary:** https://arxiv.org/abs/2609.05571  
**Importance:** **A**  
**Evidence status:** large-scale automated extraction + verification and downstream evaluation; preprint.

### 1. What is demonstrated

Code2Skill extracts implementation-anchored atomic operations, workflows, and patterns from code, then verifies them with source-body-blind reconstruction and source-aware comparison. Applied to 19,769 popular maintained GitHub repositories, the authors report 1,006,822 accepted skill records with provenance/source evidence. Across 72 matched evaluations, retrieved skills improve models by 11.7% on average and beat matched baselines in 57 cases.

### 2. What remains proposed / unproven

Source-code procedures are cleaner than everyday social/procedural learning. Executable verification of a coding skill does not establish general semantic correctness or safe use in a personal agent.

### 3. Kamimusuhi relevance

- procedural memory
- library → skill conversion
- external knowledge as cognitive extension
- provenance
- specialist model/tool use

### 4. Borrowable design

Treat skill acquisition as evidence-grounded compilation:

```text
source artifact
  ↓
procedural candidate
  ↓
reconstruction / executable test
  ↓
provenance-linked skill
  ↓
usage outcome feedback
```

### 5. Difference from Kamimusuhi

Kamimusuhi must preserve a hard boundary between **learned procedure** and **self/persona belief**. A library skill can be imported rapidly without becoming autobiographical truth.

### 6. Next validation

Build a small `LibraryToProcedureBench` from trusted local code/docs and compare raw RAG instructions vs generated skill documents vs executable procedural graphs.

## 3.7 SCAFFOLD: recursive parametric skills + slow weight distillation

**Source:** Bowei He et al., arXiv:2609.05511; accepted EMNLP 2026  
**Primary:** https://arxiv.org/abs/2609.05511  
**Importance:** **A**

### 1. What is demonstrated

SCAFFOLD induces parametric executable skills from successful web trajectories under a multi-instance abstraction constraint, composes skills recursively, compacts the library using MDL and behavioral-equivalence checking, and periodically distills skill-augmented trajectories into model weights. The authors report +11.1 to +17.2 absolute success-rate gains across WebArena, VisualWebArena, and held-out Online-Mind2Web, with monotonic gains across five iterations.

### 2. What remains proposed / unproven

Five iterations on web tasks do not establish lifelong stability. Distilling successful trajectories into weights can still cause personality/epistemic drift in a Persona Core.

### 3. Kamimusuhi relevance

- procedural memory hierarchy
- sleep consolidation
- descendant Persona/Core training
- skill compression
- self-improvement sandbox

### 4. Borrowable design

Potential long-timescale pipeline:

```text
episodes
 → local procedures
 → cross-instance abstract skills
 → hierarchical composition
 → behavioral equivalence / regression tests
 → candidate descendant weight consolidation
```

### 5. Difference from Kamimusuhi

Kamimusuhi must never treat weight distillation as an in-place silent mutation. A newly trained core is a candidate descendant that must pass continuity/persona/epistemic regression before activation.

### 6. Next validation

`SkillToWeightConsolidationBench`: test whether skill-library improvements remain when distilled into a small Persona Core candidate, while measuring persona drift, self/other contamination, tool-use regression, and retained skills.

## 3.8 Memory as Infrastructure / SIx Harness

**Source:** Mike Helwig, arXiv:2609.05510  
**Primary:** https://arxiv.org/abs/2609.05510  
**Importance:** **A**  
**Evidence status:** N=1 months-scale operational report; open-source harness and pre-registered ablation protocol.

### 1. What is demonstrated

The report describes a Claude Code project line running since January 2026 over a 633k-line codebase, with memory instrumentation since July. SIx Harness combines local SQLite lexical/vector memory, precision-gated context injection, anti-recurrence stores for decisions/dead-ends, compaction-surviving conventions, startup health gates, heartbeat telemetry, and SRE-style alert fatigue budgeting. The reported record contains 78,933 hook invocations and 85 recorded failures, with none classified as silent by its instrumentation.

### 2. What remains proposed / unproven

N=1, self-reported, no control arm. Coding project continuity is not autobiographical individual continuity.

### 3. Kamimusuhi relevance

- persistent runtime reliability
- memory health monitoring
- startup continuity checks
- anti-loop/dead-end memory
- observability
- long-running operational discipline

### 4. Borrowable design

Memory itself must have health telemetry. Kamimusuhi should distinguish:

- memory content quality;
- memory service availability;
- index freshness;
- provenance integrity;
- retrieval/injection precision;
- silent failure detection.

### 5. Difference from Kamimusuhi

SIx is an engineering harness around a coding agent; Kamimusuhi additionally needs identity lineage, relationships, sensors, self-model and distributed embodiment.

### 6. Next validation

Add a `MemoryHealthGate` prototype to v0.1 startup/restart tests and intentionally break index, schema, timestamp/provenance, retrieval, and storage layers to verify discriminated failure reporting.

## 3.9 Who Maintains Agent Skills?

**Source:** Chen Shen, Estevam Hruschka, arXiv:2609.05677  
**Primary:** https://arxiv.org/abs/2609.05677  
**Importance:** **A**  
**Evidence status:** longitudinal mining study; corpus/codebooks/replay protocol released; COLM 2026 Lifelong Agents workshop (non-archival).

### 1. What is demonstrated

Across five public agent-skill repositories, 873 commits, 143 skill files, and 254 substantive post-creation edits, every substantive edit was authored or merged through a named human account; 62% carried AI co-author trailers. Edits were dominated by additions and corrections rather than merely formatting. This is evidence that today's public skill maintenance is still human-governed even where AI is heavily involved.

### 2. What remains proposed / unproven

The selected public repositories are a purposive sample, not all agent ecosystems. Human governance may decrease as reliable automated certification improves.

### 3. Kamimusuhi relevance

- skill lifecycle governance
- self-improvement boundaries
- provenance
- descendant activation
- human/operator review

### 4. Borrowable design

Do not benchmark autonomous skill evolution only against another automated algorithm. Compare against a **human-governed maintenance baseline**, and record trigger/evidence for each edit.

### 5. Difference from Kamimusuhi

Kamimusuhi aims for greater internal developmental autonomy, but canonical identity mutation and high-impact procedure updates can remain explicitly governed even if low-risk skills self-evolve.

### 6. Next validation

Track each Kamimusuhi skill edit with `(trigger, evidence, author/proposer, validator, operation type, regression result, activation decision)` and later compare autonomous versus human-reviewed maintenance quality.

## 3.10 SAEScientist-Bench

**Source:** Yuqiao Tan et al., arXiv:2609.09113  
**Primary:** https://arxiv.org/abs/2609.09113  
**Importance:** **B+**  
**Evidence status:** 10 agent configurations × 20 mechanistic-interpretability tasks; work in progress.

### 1. What is demonstrated

Agents autonomously design contrastive probes and search 131k+ Gemma Scope SAE features for target concepts. Frontier agents show real feature-discovery ability and can reject spurious candidates, but remain below expert references and often misinterpret experimental measurements, especially causal steering evidence.

### 2. What remains proposed / unproven

This does not prove agents can safely audit their own descendants. The benchmark is narrow and uses predefined SAE tooling/reference features.

### 3. Kamimusuhi relevance

- candidate descendant auditing
- Persona Core interpretability
- self-improvement validation
- independent evaluator design

### 4. Borrowable design

A self-improvement pipeline can have an explicit `mechanistic audit` lane, but its reports must be treated as fallible evidence rather than authority.

### 5. Difference from Kamimusuhi

Kamimusuhi cares about longitudinal persona/self boundaries, which may not map cleanly to single SAE features.

### 6. Next validation

For small native Persona Core prototypes, test whether external auditor agents can detect known injected persona/tool-routing changes using probes and activation analysis, with human/exact labels as reference.

## 3.11 SyncWorld

**Source:** Yuncong Yang et al., arXiv:2609.09155  
**Primary:** https://arxiv.org/abs/2609.09155  
**Importance:** **B+**

### 1. What is demonstrated

SyncWorld uses visual calibration episodes—paired frames/actions spanning controllable degrees of freedom—to infer setup-specific action-to-visual mappings in context. The authors report zero-shot simulation in unseen settings and test-time policy improvement using simulated rollouts.

### 2. What remains proposed / unproven

It is a robotics world model, not a durable body-self model. Calibration of action appearance is not equivalent to identity or ownership of a sensor/actuator.

### 3. Kamimusuhi relevance

- distributed embodiment
- interchangeable organs
- sensor/actuator calibration
- dream/simulation
- body self-model

### 4. Borrowable design

When a new camera/robot/device becomes an organ, do not assume fixed action semantics. Run a bounded **calibration episode** to learn the organ-specific observation/action mapping.

### 5. Difference from Kamimusuhi

Kamimusuhi additionally needs authentication, authority, provenance and continuity contracts for organs.

### 6. Next validation

`OrganCalibrationBench`: swap camera orientation, microphone, UI surface, or simulated actuator and measure how quickly the same high-level intent becomes correctly grounded without changing canonical identity.

## 3.12 Continual Learning Mechanisms Compose for Long-Horizon Memorization

**Source:** Zheyuan Zhang et al., arXiv:2609.06986  
**Primary:** https://arxiv.org/abs/2609.06986  
**Importance:** **B+**

### 1. What is demonstrated

Across three 100-task sequential memorization datasets, no single continual-learning mechanism maintained strong retention. Combining data/function/weight anchors with merged LoRA raised average final retention from 1.2% under naive sequential fine-tuning to 34.9%; interactions between mechanisms mattered.

### 2. What remains proposed / unproven

34.9% retention is still far from durable lifelong memory, and memorizing QA tasks is not persona consolidation. The setting forbids replay of earlier training examples by design.

### 3. Kamimusuhi relevance

- Persona Core descendant training
- catastrophic personality drift
- slow consolidation
- weight updates

### 4. Borrowable design

No single anti-forgetting trick should be trusted. Persona Core training should use multiple independent anchors: behavioral regression data, functional invariants, parameter constraints/adapters, and explicit autobiographical memory outside weights.

### 5. Difference from Kamimusuhi

Kamimusuhi intentionally keeps most factual memory outside model weights, making the weight-retention burden smaller but the persona/invariant burden more important.

### 6. Next validation

When native Persona Core training begins, compare naive continual FT vs adapter/anchor combinations specifically on persona, self/other, uncertainty, delegation, language ability, and previously learned social behavior.

## 3.13 Adaptive Complementarity in Human-AI Systems

**Source:** Babak Heydari, arXiv:2609.07001v2, revised 2026-09-09  
**Primary:** https://arxiv.org/abs/2609.07001  
**Importance:** **A**  
**Evidence status:** theory/framework + knowledge-coverage illustration; not a broad empirical deployment study.

### 1. What is demonstrated / argued

The framework formalizes that interaction choices—access, information exposure, task allocation, timing, communication—change future capabilities, search patterns, conventions, and therefore which human-AI architecture will work later. The v2 package includes executable ancillary materials for the illustrative model.

### 2. What remains proposed / unproven

It is mainly theoretical. It does not establish specific long-term effects for companion agents or artificial-life systems.

### 3. Kamimusuhi relevance

- human relationship development
- autonomy/delegation
- long-term HCI
- cognitive extension
- user dependency vs complementarity

### 4. Borrowable design

Evaluate not only `task success now` but also **state shaping**:

- Did the user lose/gain capability?
- Did Kamimusuhi become over-dependent on one external model/tool?
- Did repeated delegation collapse diversity of solution search?
- Did interaction create brittle conventions?

### 5. Difference from Kamimusuhi

Kamimusuhi additionally maintains one artificial individual's own developmental state and continuity, not only team performance.

### 6. Next validation

Create longitudinal synthetic tasks where different delegation policies produce the same immediate success but different future user/Kamimusuhi capabilities; evaluate future performance and dependency.

## 3.14 Large-scale multimodal CTA behavior analysis

**Source:** Rafael Ferreira et al., arXiv:2609.07594; accepted EPIA 2026  
**Primary:** https://arxiv.org/abs/2609.07594  
**Importance:** **B**

### 1. What is demonstrated

A large-scale in-the-wild study of thousands of users interacting with multimodal conversational task assistants for real-world cooking/DIY-style activities characterizes interaction flows, intents, conversational traits and behavioral factors associated with satisfaction.

### 2. What remains proposed / unproven

The public abstract does not establish long-term relationship development or continuous autonomous sensing. Satisfaction correlates are not causal laws.

### 3. Kamimusuhi relevance

- speech/multimodal interaction
- physical task assistance
- HCI
- K-Edge response behavior

### 4. Borrowable design

## 4. Cross-domain synthesis

### 4.1 Memory should be split into evidence, active view, and procedures

Today's papers reinforce a three-way split:

```text
canonical evidence / original events
        │
        ├── validity + supersession + revocation
        │        ↓
        │    active memory view
        │
        └── abstraction / verified synthesis
                 ↓
          procedures / schemas
```

EdgeMem argues for preserving original events; `Revoked but Still Authoritative` shows active-state filtering must be enforced; Code2Skill/SCAFFOLD show procedural abstractions can then be compiled and verified separately.

### 4.2 Authority and cognition must remain different planes

CapScope strengthens the accumulated evidence from authorization-laundering, cross-substrate authority, continuity-kernel, and lease/fencing work:

```text
LLM cognition / intent / proposal
            !=
capability / authority / revocation state
            !=
final effect permission
```

The model may understand authority; it must not **own** authority merely by seeing text describing it.

### 4.3 Development should be measured as state transition, not final score

AhaBench + Adaptive Complementarity imply:

```text
current success
   + learning lift
   + retention
   + transfer
   + future-state effects
```

Kamimusuhi's benchmark suite should therefore explicitly measure whether experience causes useful, stable, transferable change without unwanted identity drift.

### 4.4 Prediction error is a plausible non-linguistic regulator

The predictive-coding HRI work offers a concrete bridge between Kamimusuhi's speculative `digital affect / interoception` and an experimentally testable control signal: **recent prediction/reconstruction mismatch**. It can be tested as one input to K-Nerve routing before inventing richer artificial emotion models.

## 10. Bottom line

今回の差分から Kamimusuhi に最も重要な設計命題は次の4つ。

1. **Authority is not text.** 能力・権限・revocation は LLM context 外の typed state と deterministic gate で強制する。
2. **History is not active memory.** canonical history を残しながら、revoked/superseded items は active retrieval view から確実に除外する。
3. **Memory abstraction must remain evidence-linked.** 原文 evidence を捨てず、graph/schema/procedure は派生物として再構築可能にする。
4. **Development is a state transition.** 最終能力だけでなく learning lift、retention、transfer、future-state effect、identity drift を同時に測る。

この4点はいずれも現行 Kamimusuhi の `canonical evidence / proposal-only mutation / model-is-organ / continuity` 方針と整合し、今日時点では `spec.md` を変更するより **benchmark / runtime guard / memory implementation hypothesis** として先に検証するのが妥当。
