## 3. 要約

今回の中心は **「再起動・委譲・記憶・物理計算で、何を引き継いでよく、何を引き継いではならないか」** である。

新規差分を圧縮すると次の通り。

```text
process restart
  != authorization replay

stale pending effect
  != permission to re-execute the effect

fail-closed effect recovery
  != cognition must wait for another human message

unset destination override
  != permission to reroute to an arbitrary/default cloud body

offline saved organ
  != consent to cross-substrate fallback

persistent memory exists
  != memory causally changes behavior in every domain

queue accepted
  != delivered / replied / completed

physical reservoir demonstrated
  != practical solid-state neuromorphic advantage demonstrated
```

特に Letta Code #4404 は、Kamimusuhi の crash recovery に重要な境界を具体化している。**外部 effect は fail-closed にしつつ、認知 episode 自体は人間の追加入力なしに自動再開できる**。これは安全性と liveness を同じ retry policy に押し込まない設計である。

また *Readable Minds* は、直前に収載した「長期 agent society で memory ablation が行動を変えなかった」負結果と対照的である。繰り返し相手を読むことが本質の partially observable social task では persistent memory が ToM-like behavior の出現に強く効いた。したがって Kamimusuhi で測るべきなのは「memory があるか」ではなく、**その task で cross-episode state が因果的に必要か、その memory が実際に partner-model 更新へ使われたか**である。

## 5.1 Distributed runtime / continuity — Letta Code #4404: restart-safe interrupted-turn recovery

**Primary implementation record:** Letta Code PR #4404, `fix(listener): resume an interrupted turn on the first sync after a restart [LET-12476]`  
https://github.com/letta-ai/letta-code/pull/4404  
Merged: **2026-09-13 14:15:49 JST**  
**Importance:** **A**

### (1) 何が実証済みか

問題は、client-side tool が `EXECUTING_CLIENT_SIDE_TOOL` 中に sandbox/listener が kill/restart された場合に発生した。server 側では `stop_reason: requires_approval` が残っている一方、新 listener は `WAITING_ON_INPUT` / `active_run_ids=[]` となり、Slack/cron のように次の human message が来ない turn は永久停止し得た。

修正は二段階。

1. **各 process/scope の first sync では approval recovery を必ず実行**する。軽量 sync が `recover_approvals=false` を送っていても、fresh process は一度だけ backend state を回収する。失敗時は recovery-completed flag を立てず、次 sync で retry する。
2. restart 前から残った **non-interactive stale approvals は再実行せず deny** する。しかし deny result を「次の user message まで駐車」せず、その場で continuation turn を開始する。モデルは stale-denial を観測し、必要なら fresh な tool call を再発行できる。

Interactive tool（例: `AskUserQuestion`）は従来どおり control request として再提示され、人間を待つ。

テストでは recovered stale approval を approval/re-execution しない source guard と、first-sync recovery、retry、lease 下での immediate continuation を検証している。

### (2) 何が提案・推測段階か

このPR単体では **実 sandbox kill を含む製品E2E** はまだ実行していない。full product path は paired cloud-side E2E に委ねられている。

また「すべての stale effect を deny → model に再計画させる」が普遍的に最適とは限らない。外部 effect がすでに成功したか不明な `unknown outcome` では、fresh call の再発行自体が二重実行になる可能性がある。

### (3) Kamimusuhi のどのサブシステムに関係するか

- Continuity Kernel / recovery metadata
- Effect Acceptance / Execution Grant
- K-Core runtime / turn lease
- background / scheduled task
- distributed K-Edge / K-Core handoff
- crash recovery / replay safety
- canonical execution evidence

### (4) 借りられる設計・実装アイデア

recovery state を少なくとも次に分ける。

```text
cognition_resume_state
pending_interactive_control_request
pending_external_effect
pending_effect_outcome: NOT_STARTED | CONFIRMED | FAILED | UNKNOWN
restored_authorization_state: FRESH | STALE | REVOKED
resume_trigger: AUTO | HUMAN_REQUIRED | QUARANTINE
```

特に原則候補は:

```text
resume cognition automatically when safe
BUT
never infer effect replay permission from process recovery alone
```

restored approval は **fresh Execution Grant ではない**。

### (5) Kamimusuhiとの差分

現行 spec は thought / authorization / execution / unknown outcome を分離し、Continuity Kernel に recovery metadata を置く。しかし、**process restart 後に non-interactive cognition の liveness を自動回復しつつ、stale effect authorization は fail-closed にする**という復旧 policy はまだ明文化されていない。

### (6) 次に検証すべきこと

**`CrashRestartContinuationBench`**

シナリオ:

- tool call 発行前 crash
- local tool 実行中 crash
- external effect request 送信直後 crash（outcome unknown）
- effect success receipt 後、canonical finalization 前 crash
- human approval 待ち中 crash
- background/cron turn 中 crash

比較:

- blind replay
- wait-for-user
- fail-closed + auto-reasoning-resume
- outcome-aware recovery

指標:

- duplicate effect rate
- false deny / unnecessary recomputation
- human nudge requirement
- recovery latency
- lost-task rate
- provenance / lease correctness

### (7) 重要度

**A** — Continuity Kernel の「生き残る」能力と Effect Gate の「勝手に再実行しない」能力を同時に試せる。

## 5.2 Theory of Mind / relationship memory — Readable Minds

**Source:** Hsieh-Ting Lin, Tsung-Yu Hou, *Readable Minds: Emergent Theory-of-Mind-Like Behavior in LLM Poker Agents*, arXiv:2604.04157  
https://arxiv.org/abs/2604.04157  
Published: 2026-04-05  
**Importance:** **A**

### (1) 何が実証済みか

Texas Hold'em の長期 interaction で、**persistent memory 有/無 × poker domain knowledge 有/無**の 2×2 factorial、各5 replication（N=20、約6,000 agent-hand observations）を実施。

報告では:

- persistent memory ありで ToM-like behavior が出現し、なしでは Level 0 に留まった。
- memory effect: Cliff's δ=1.0, p=0.008。
- opponent model に根ざした strategic deception は memory 条件でのみ観測（Fisher exact p<0.001）。
- poker knowledge は ToM-like level の出現自体には必須でないが、deception precision を改善（p=0.004）。
- mental-model annotation の cross-model validation は weighted Cohen's κ=0.81。

### (2) 何が提案・推測段階か

これは **poker という反復・部分観測・対人推論が本質のdomain**での functional ToM-like behavior であり、人間の Theory of Mind と同等な内部機構を示したわけではない。

自然言語で書かれた opponent model が「読める」ことも、その prose が内部計算の完全な faithful report であることを保証しない。

また、直前 daily で収載した long-run town-economy experiment では memory ablation の detectable effect がなかった。したがって `memory -> social intelligence` を一般則にしてはいけない。

### (3) Kamimusuhi 関連

- relationship/person model
- Theory-of-Mind-like inference
- episodic memory
- common ground
- social strategy / trust / uncertainty
- Persona Core の self/other distinction

### (4) 借りられる設計・実装アイデア

memory の品質を retrieval hit-rate だけでなく **counterparty prediction の因果改善**で測る。

```text
partner observation
  -> episodic evidence
  -> partner hypothesis
  -> confidence / alternatives
  -> next-action prediction
  -> observed outcome
  -> hypothesis update
```

特に「相手について記憶した情報」が **自分のpersonaへ混入せず**、partner-specific prediction を改善するかを見る。

### (5) Kamimusuhiとの差分

Kamimusuhi は relation / self / episode を構造上分けるが、現在の研究 agenda では memory causal contribution を一般的 long-horizon taskで測る比重が大きい。

本研究は、**memory が必要となる task structure 自体を操作**する比較が必要と示唆する。

### (6) 次に検証すべきこと

**`RelationshipMemoryCausalBench`**

- repeated hidden-information game / negotiation / collaborative task
- partner behavior を途中で drift させる
- 条件: no memory / raw transcript / episodic memory / structured partner model
- partner identity swap と adversarial false memory を入れる
- 指標: next-action prediction、calibration、adaptation speed、self/other contamination、task utility
- 同じmemory条件を、cross-episode state が不要な task でも回し、因果効果が task-dependent か確認

### (7) 重要度

**A** — Relationship Memory が本当に「人間関係を形成する器官」になっているかを falsifiable にできる。

## 5.3 Neuromorphic / robotics — wave-based physical reservoir computing

**Source:** Jacob Zohar et al., *Autonomous robotic operation controlled by wave-based neuromorphic hardware*, Nature Communications, 2026-09-10  
https://doi.org/10.1038/s41467-026-77661-3  
https://www.nature.com/articles/s41467-026-77661-3  
**Importance:** **A**

### (1) 何が実証済みか

論文は、水面波の物理干渉を **physical reservoir computing** として使い、robotic vehicle の obstacle recognition を行い、その出力で **real-time autonomous obstacle avoidance** を閉ループ制御した。

つまり、単なる off-line waveform classification ではなく、物理計算 substrate が実 robot action へ接続されている。

### (2) 何が提案・推測段階か

実験で使ったのは water-based system である。論文はさらに、electrically excited spin wave を使う magnetic nanodevice を **micromagnetic simulation** で検討し GHz operation への道筋を示すが、solid-state robot chip を実機で実証したわけではない。

したがって以下は未確立:

- Kamimusuhi の実用 K-Nerve に載るサイズ・安定性
- MCU/FPGA/SNN/LUT に対する end-to-end energy advantage
- 長期 drift / temperature / manufacturing variation 耐性
- arbitrary control task への汎化

### (3) Kamimusuhi 関連

- K-Nerve
- artificial nervous system
- sensor-near processing
- reflex / salience / obstacle response
- robotics / embodied perception-action loop
- low-latency non-LLM cognition

### (4) 借りられる設計・実装アイデア

K-Nerve candidate を `digital neural` だけに限定せず、**physical dynamics + lightweight readout** という substrate class も比較対象にする。

評価 interface は substrate independent にする。

```text
sensory event
  -> substrate state evolution
  -> bounded readout
  -> reflex proposal
  -> hard safety / effect gate
```

### (5) Kamimusuhiとの差分

現行 K-Nerve 候補は LIF/SNN、logic gate、LUT、FSM、tiny model、rules が中心。**physical reservoir** は明示候補ではない。

ただし Kamimusuhi の採否原則は biological analogy ではなく latency / energy / accuracy / stability / auditability の比較なので、その枠組み自体は既存設計と整合する。

### (6) 次に検証すべきこと

- tiny MLP
- SNN/LIF
- LUT/logic network

- 将来 physical reservoir

で比較。

指標:

- sensor-to-action latency
- joules / decision
- accuracy / false emergency rate
- calibration drift
- online adaptation cost
- cold-start / recovery behavior
- component footprint
- explainability / reproducibility

### (7) 重要度

**A** — 「非LLMの高頻度制御」を実際の物理 substrate まで広げる強い比較対象。ただし solid-state 実用性は未実証なので spec 採用ではなく watchlist + bench 候補。

## 5.6 Narrative identity / multi-agent coordination — JSAI controlled simulation

**Source:** Chao Li, Tianxiang Yang, Masayuki Goto, *Narrative Identity in LLM-Based Multi-Agent Research Collaboration: Simulation Modeling and Numerical Study*, JSAI 2026 proceedings  
https://doi.org/10.11517/pjsai.JSAI2026.0_3O2IS302  
Released on J-STAGE: 2026-07-17  
**Importance:** **B**

### (1) 何が実証済みか

二つのagentが limited resources と stochastic external shocks の下で共同研究する minimal simulation を作り、**shared, mutable narrative state**を prompt-level conditioning で policy に入れ、narrative bias の強さを scalar parameter で操作した controlled numerical study。

abstract では narrative-conditioned agent が narrative-agnostic baseline より、shock 後の research quality と social trust を速く回復したと報告する。

### (2) 何が提案・推測段階か

これは minimal simulation / prompt conditioning であり、長期実サービスや人間関係での narrative identity の必要性を実証したものではない。

また `shared collaboration narrative` は、Kamimusuhi が守りたい **一個体の autobiographical/narrative identity** と同じものではない。

### (3) Kamimusuhi 関連

- autobiographical narrative
- relationship/common-ground state
- joint project memory
- long-horizon recovery
- social trust

### (4) 借りられる設計・実装アイデア

個体 narrative と shared project narrative を別objectにして、shock後の recovery signal として比較する。

```text
self narrative
relationship narrative
shared project narrative
canonical evidence
```

を混ぜない。

### (5) Kamimusuhiとの差分

Kamimusuhi は narrative を canonical evidence 上の derived view とする。論文の shared mutable narrative を identity authority に置く設計は採らない。

# 12. 今回の結論

今回もっとも重要なのは、**restart recovery を「全部再実行」か「全部停止」かの二択にしない**ことである。

```text
recover identity / episode / reasoning continuity
        !=
recover permission to repeat external effects
```

Kamimusuhi では process が死んでも個体・task・思考 episode は続いてよい。一方、pre-crash の effect authorization は自動復活させてはいけない。安全側にeffectを止めても、human messageを待つ理由がないなら認知自体は再開できる。この **safety × liveness の直交化**は Continuity Kernel にかなり直接的な課題である。

次点は、distributed body における:

```text
unset destination != anywhere is allowed
offline organ != cloud fallback consent
```

である。

研究側では、persistent memory の価値を一般論で語らず、**cross-episode partner state が本当に必要なtaskで causal ablation する**こと、K-Nerveについては SNN/logic/LUTだけでなく **physical reservoir** まで同一contractで比較可能にしておくことが、今回の主要な持ち帰りとなる。
