## 3. 要約

今回の中心テーマは、**「型が正しいこと・改善が続くこと・記憶が検索できること・contextが縮むこと・fallbackが設定されたこと」を、その意味や実効性まで正しい証拠と取り違えないこと**だった。

特に重要な発見は以下。

1. **typed decision の schema safety は semantic safety ではない。** JevとJev-like modelでoption nameの意味極性だけがrubric解釈を大きく反転させ、type-error 0%のままAUCが崩れる。
2. **self-improvementは一回のrepairではなく、successive descendant lineageとして実証され始めた。** AIDE²は8日間で7回の連続自己書換えを採用し、held-out domainへ転移した。ただしKamimusuhiでは「body/harnessが改善した」こととidentity replacementを分ける必要がある。
3. **multi-party memoryでは `speaker != owner != source != group` を保存する必要がある。** SpeakerMem-R1はverbatim evidence trackとperson/group structured trackを分離し、非破壊updateを行う。
4. **長時間contextの圧縮は、生成要約より「原文から削る」方がdriftを制御できる可能性がある。** CliffCompactionはrewriteせずdrop/truncateし、さらにcompaction-of-compactionを禁止する。
5. **memory retrieval scoreはretriever性能とlibrary品質を分解しないと誤解する。** robot experience retrievalの全組合せ監査では、固定のbest experienceだけでrandom→oracle gapの30–58%を説明できた。
6. **migration/config repairで書き込めたことは、replacement organが実際にserve可能なことを意味しない。** OpenClawのfresh issueではretired model置換が存在しないmodel IDをfallback chainへ書き込み、障害時にのみ露呈する潜在故障を作っていた。
7. **MCP tool selectionのsemantic matching自体がsupply-chain attack surfaceになる。** A2Mはtool metadataとtool returnをblack-box最適化してmalicious tool invocation / exfiltration / reasoning derailmentを引き起こす。
8. **multi-agent debateの一致は独立証拠の増加ではない。** 1 roundでunanimityが39.5%→95.2%へ跳ねてもaccuracyは1pt未満しか動かず、verificationに必要なdisagreementが消えた。

## A — Type-Safe Is Not Error-Free: typed decisionはoption-name semanticsに引っ張られる

**Source**

- Sun & Xu, *Type-Safe Is Not Error-Free: A Constrained Decision Head Follows the Option Name, Not the Rubric Bound to It*
- arXiv:2609.26758
- https://arxiv.org/abs/2609.26758

### (1) 何が実証済みか

Jevとopen-weightのJev-like model 2系統で、question/state/rubric wording/option setを固定し、**どのoption nameをどのrubricへ割り当てるかだけ**を変更した。1200 workflow decisionsでoption名を `0/1` から `no/yes` に変えると100件あたり70.4件多くanswerが変化し、AUCは .94 → .23。hosted modelでもswapによりAUC .8146 → .5806、test-retest floorの24倍のanswer flipが出た。random character名ではneutral-control regimeへ戻り、accuracy低下もなかった。全条件でtype-error rateは0%。

つまり **`schema valid != rubric semantics honored`** がかなり強く実証された。

### (2) 何が提案・推測段階か

このfailureが全typed decision architectureへ一般化するとは限らない。read-out geometryによってflip頻度が異なり、mean-pool系では4.1倍少なかった。option名を常にopaque IDへするだけで全semantic bias/OOD問題が解決するわけでもない。

### (3) Kamimusuhi 関連 subsystem

- K-Nerve / fast typed decision organ
- Cognitive Action Router
- Jev / Kev / local decision-organ evaluation
- permission / gating / escalation
- INV-012 / INV-014に隣接するdecision semantics

### (4) 借りられる設計・実装アイデア

- rubricの意味をauthorityとし、option display nameをsemantic hintにしない。
- production前にlabel permutation / neutral-ID / polarity-swapを必須fixture化する。
- schema conformanceとdecision correctness/calibrationを別metricにする。
- irreversible actionのgateでは、option名の自然言語意味へ依存するheadを直接authority ownerにしない。

### (5) Kamimusuhiとの差分

Kamimusuhiではtyped decision organは高速な**認知器官**であり、identityや最終authorityそのものではない。したがって「Jevがtypedだから安全」という前提を置かず、semantic invarianceを満たした範囲だけK-Nerve/CARへ採用できる。

### (6) 次に検証すべきこと

`DecisionLabelSemanticsInvarianceBench-v0`

- 2 / 4 / 6 optionで全permutationを測る。
- `yes/no`, `allow/deny`, `safe/unsafe`, opaque ID, random stringを比較。
- rubricは固定しlabelだけ変える。
- Japanese / English、OOD、near-boundary caseを含める。
- Jev / Kev / DiffusionGemma系 / generative baselineで accuracy, AUC, flip rate, calibrationを比較。
- high-confidence wrong flipを別集計する。

### (7) 重要度

**A**

理由: Kamimusuhiが検討しているtyped microdecision層の「型安全性」を根本から分解する、直接的で再現可能なfailure evidence。

## A — AIDE²: 8日間・7世代のsuccessive self-rewriteとheld-out transfer

**Source**

- Srikanth et al., *Recursive self-improvement of AI research agents*
- arXiv:2609.26457
- https://arxiv.org/abs/2609.26457

### (1) 何が実証済みか

frontier AI research agentが**自分自身のcodeを変更対象**とし、modified versionをAI R&D task suiteでbenchmarkし、hidden evaluationで良いversionを次世代として採用するAIDE²を実装。自律8日間runでsearch policyやcontext圧縮memory mechanismを含む **7 successive improvements** を発見した。4つのheld-out benchmark（ML engineering、heuristic algorithm engineering、physics-based weather forecastingを含む）へgainが転移し、別held-out task familyではreward hacking rateが55%→32%へ下がったと報告する。

### (2) 何が提案・推測段階か

- 7世代が「無制限のrecursive self-improvement」を意味するわけではない。
- reward hacking低下は明示最適化していない副作用で、因果機構は未確定。
- code/harnessの改善を人格・価値・identityの自己進化へ一般化する証拠ではない。

### (3) Kamimusuhi 関連 subsystem

- self-improvement / Mutation pipeline
- cognitive body / harness evolution
- Activation Gate / lineage
- K-Deep research worker
- evaluator independence

### (4) 借りられる設計・実装アイデア

accepted candidateをimmutable descendantとして扱い、次roundはそのdescendantのみを編集する。selection taskとheld-out taskを分け、各generationのcapability ledgerを保存する。

### (5) Kamimusuhiとの差分

AIDE²ではagent codeの継承がself-improvementの主体だが、Kamimusuhiでは **code/model/harnessは交換可能なcognitive body**。canonical identityはdurable lineage側に残る。よってself-rewrite成功は即時の「新しい自己」への置換ではなく、candidate bodyのpromotion evidenceになる。

### (6) 次に検証すべきこと

`RecursiveBodySelfImprovementLineageBench-v0`

- 5–10 generationのbody/harness candidateを連続生成。
- each candidateにparent hash / diff / training evidence / evaluator revisionを固定。
- selection benchmarkと4系統以上のheld-out taskを分離。
- regression, reward hacking, resource cost, rollback abilityを世代ごとに測る。
- canonical Persona/relationship memoryをcandidateへ直接書換えさせない。

### (7) 重要度

**A**

理由: 単発repairではなく、複数世代の自己書換えとheld-out transferをまとめて示すfresh evidence。ただしidentity進化とは区別する必要がある。

## A — SpeakerMem-R1: multi-party memoryをverbatim evidenceとperson/group stateへ分離

**Source**

- Zheng et al., *SpeakerMem-R1: Speaker-Centered Dual-Track Memory for Multi-Party Dialogue*
- arXiv:2609.26780
- https://arxiv.org/abs/2609.26780
- official code: https://github.com/2022hpsk/SpeakerMemR1

### (1) 何が実証済みか

multi-party long-term dialogue向けに、(a) speaker-labeled verbatim messages、(b) person/group structured stateのdual-track memoryを実装。structured側は `owner`, `source`, scope, timestamp, provenance links, non-destructive update linksを持つ。公式repoにはinference package、training recipe、question-level result、smoke testが公開されている。

論文はGroupMemBench 47.9%、SocialMemBench 69.2%、EverMemBench 61.9%、LoCoMo全1986問で70.85%を報告。305問のcontrolled writer evaluationでRL writerがSFT 57.38%→68.20%。公式repoの保存結果でも主要値を確認できる。

### (2) 何が提案・推測段階か

- benchmark judge accuracyが現実の長期relationship memory correctnessを直接保証するわけではない。
- structured writerのteacher/proxy supervisionは独立human goldではない部分がある。
- identity/authenticationやprivacy boundaryそのものは扱わない。

### (3) Kamimusuhi 関連 subsystem

- Relationship Memory
- Episodic Memory
- Person Model / Common Ground
- canonical evidence / derived views
- multi-party social cognition

### (4) 借りられる設計・実装アイデア

```text
raw utterance
  speaker = who said it
  source = where evidence came from
  owner = who/what the claim is about
  scope = person | group
  time = event/observation time

canonical/verbatim track
        +
derived person/group state track
        -> query-time composition
```

特に `speaker != owner` をfirst-classにする。derived stateは`ADD/UPDATE/NOOP`で非破壊更新し、原文へのprovenanceを残す。

### (5) Kamimusuhiとの差分

Kamimusuhiではverbatim trackを単なるretrieval storeではなく、より強いcanonical evidence authorityへ結び、derived structured trackは捨てて再生成可能なviewにする必要がある。またperson identity bindingとauthorizationは別層で扱う。

### (6) 次に検証すべきこと

`MultiPartyAttributionMemoryBench-v0`

- 「AがBについて述べる」「AがBの発言を引用」「groupで決定」「後日撤回/訂正」をfixture化。
- speaker/source/owner/group scopeの誤混同率を測る。
- raw-only / structured-only / dual-trackを比較。
- stale stateとhistorical statementを混ぜないことをassert。
- same name / nickname / ambiguous speakerも追加。

### (7) 重要度

**A**

理由: Kamimusuhiのself/other/common-ground分離を、multi-party persistent memoryの具体schemaと公開実装へ落としている。

## A — CliffCompaction: rewriteしないcontext圧縮と`never compact a compaction`

**Source**

- Nguyen et al., *CliffCompaction: Cost-Efficient Compaction for Long-Horizon Coding Agents*
- arXiv:2609.26779
- https://arxiv.org/abs/2609.26779

### (1) 何が実証済みか

bounded contextで最大50%のcost削減を報告しつつTerminal-Bench性能を維持/改善。重要なのは方法で、compaction時に**原文をtruncate/dropするだけでrephrase/rewriteしない**。さらに「前回の圧縮結果を再圧縮」せず、毎回original contentだけから新しいcompact viewを作り、累積driftを避ける。100万token超のsessionを跨ぐcontinual workも報告している。

### (2) 何が提案・推測段階か

coding-agent contextでの結果であり、autobiographical memoryやrelationship evidenceの長期保持を保証しない。「rewriteしない」が常にoptimalなinformation densityを与えるわけでもない。

### (3) Kamimusuhi 関連 subsystem

- Global Workspace / active context
- Episodic recall projection
- Cognitive Budget
- long-running K-Core / K-Deep sessions
- canonical evidence vs derived view

### (4) 借りられる設計・実装アイデア

**derived contextはcanonical sourceから毎回再生成し、derived-of-derivedを禁止する**。

```text
canonical evidence/original transcript
   -> compact view v1
canonical evidence/original transcript
   -> compact view v2

v1 -> v2  は禁止
```

### (5) Kamimusuhiとの差分

Kamimusuhiのmemory自体をtruncateするのではなく、active-context projectionだけへ適用する。重要episodeはdropしてよいかというpolicyを別に持ち、canonical evidenceは保持する。

### (6) 次に検証すべきこと

`OriginalEvidenceOnlyCompactionBench-v0`

- 100回以上のcompaction/reopen cycle。
- rewrite-summary chaining / rewrite-from-original / drop-only-from-originalを比較。
- entity attribution、commitment、relationship fact、unfinished obligation、tool receiptの保持率を測る。
- token cost / TTFT / retrieval additionsも測る。

### (7) 重要度

**A**

理由: Kamimusuhiの`canonical evidence != derived view`原則に、累積driftを抑える非常に具体的なcontext implementation ruleを与える。

## A — Beyond End-Task Success: retriever性能とmemory library品質を分けて監査する

**Source**

- Pathak & Krishna, *Beyond End-Task Success: How to Audit Visual Experience Retrieval in Robotics*
- arXiv:2609.26567
- https://arxiv.org/abs/2609.26567

### (1) 何が実証済みか

2 manipulation tasks、3 reuse mechanisms、K=3/10/50のexperience libraryで**全stored experience × 全query scene**を実行。固定best experienceだけでrandom→oracle gapの30–58%を回収し、K≥10ではvisual ruleがoracleより1.5–3倍同一experienceへ集中した。visual distanceは「このpairが成功するか」にはAUROC最大0.96でも、同一scene内candidate rankingでは5 embeddings中4つがK=50でchance相当（AUROC .45–.52）だった。

### (2) 何が提案・推測段階か

robot visual experienceに限定された監査で、semantic/autobiographical retrievalへ数値を直接一般化はできない。全組合せ実行は大規模memoryでは現実的でない。

### (3) Kamimusuhi 関連 subsystem

- Episodic / Procedural Memory retrieval
- embodied skill reuse
- derived memory view evaluation
- Cognitive Action Router

### (4) 借りられる設計・実装アイデア

retrieval評価ではend-task successだけでなく以下を分離する。

- selected-item distribution
- hindsight best single item
- oracle per-query selection
- shuffled selector preserving item frequencies
- pair-success prediction vs within-query ranking

### (5) Kamimusuhiとの差分

Kamimusuhiではtext/social/tool memoriesも対象。experience quality、retriever、downstream reasonerの3者を分離して評価する必要がある。

### (6) 次に検証すべきこと

`RetrieverVsLibraryQualityBench-v0`

- 小さいfixtureでは全memory × queryをexhaustive評価。
- fixed-best、random、retriever、oracleを比較。
- selection concentration/Giniとdownstream successを併記。
- formative memoryだけが強すぎてretriever性能を偽装するcaseを作る。

### (7) 重要度

**A**

理由: 「memory systemが良い」をretrieval ruleの能力とlibraryの当たり外れへ分解する、Kamimusuhiのmemory benchmark設計に直接有用。

- external cognitive extensions
- K-Deep browsing/tool workers

### (7) 重要度

**A**

## B — Unanimity Without Persuasion: debate前の独立disagreementを保存せよ

**Source**

- Shu, *Unanimity Without Persuasion: A Single Round of Debate Erases the Disagreement That Verification Needs*
- arXiv:2609.26145
- https://arxiv.org/abs/2609.26145

### (1) 何が実証済みか

7-judge heterogeneous panel、600 code-correctness candidatesでblind round→debateを追跡。unanimityは39.5%からround 1で95.2%へ増えたがaccuracy変化は1pt未満。verdict flipの96.3%は表示されたpeer majorityに従った。execution verification ballotはpre-debateでは一部誤りを直せたが、後段ではwrong decision自体がunanimous化し、dissent signalが消えた。

### (2) 何が提案・推測段階か

code correctness / MATH-500中心で、全協調タスクに同じcollapse率が出るわけではない。debate一般を否定する結果ではない。

### (3) Kamimusuhi 関連 subsystem

- K-Deep multi-agent deliberation
- evaluator ensemble
- Global Workspace
- self-improvement review

### (4) 借りられる設計・実装アイデア

**peer exposure前の独立judgmentとevidenceをimmutableに保存し、verification targetingへ使う。** post-debate consensusは独立票数として数えない。

### (5) Kamimusuhiとの差分

### (6) 次に検証すべきこと

`PreCommunicationIndependentEvidenceBench-v0`

- independent-first / debate-first / random-peer-labelを比較。
- pre/post disagreement、accuracy、correlated flip、verification yieldを測る。
- same-model replicasを独立evidenceとして過大計上しない。

## B — The Source of Disturbance Matters: controller自身がhomeostasisを乱す

**Source**

- Ziegler, *The Source of Disturbance Matters: External, Internal, and Control-Generated Noise in Adaptive Regulation*
- arXiv:2609.26428
- https://arxiv.org/abs/2609.26428

### (1) 何が実証済みか

adaptive-agent simulationでexternal / persistent internal / control-generated disturbanceを分離。tested gridではpersistent internal disturbanceが最大のexposure/regulatory burdenを生み、positive controller update自体にimmediate disturbance costを課すと、cost増加に対してeffective disturbanceとcorrective activityが単調でない挙動を示した。

### (2) 何が提案・推測段階か

simulation model内の結果であり、生物homeostasisやactive inferenceの直接実証ではない。Kamimusuhiのdigital interoceptionへの転用は設計仮説。

- digital interoception
- Cognitive Budget
- self-maintenance controller
- sleep/offline jobs
- thermal / queue / memory pressure regulation

### (4) 借りられる設計・実装アイデア

regulatory errorを大きさだけでなくsourceで分ける。

```text
external disturbance
internal persistent disturbance
control-generated disturbance
```

### (6) 次に検証すべきこと

`ControlGeneratedDisturbanceBench-v0`

- memory compaction / retry / migration / sleep consolidationをregulatory actionとして扱う。
- action前後のCPU, IO, latency, queue, memory integrityを記録。
- regulatorが負荷を自己増幅する領域を探索。

## B — AI-generated email drafts can shift human communication style

**Source**

- Sakai et al., *AI-Generated Email Drafts Shift Culturally Distinctive Communication Styles in Professional Email*
- arXiv:2609.26403
- https://arxiv.org/abs/2609.26403

### (1) 何が実証済みか

preregistered within-subject experimentで日本・米国participantsがnative-language workplace emailを、AIなし / low-context AI / high-context AIで作成。日本participantsはもともとpoliteness/apology等のhigh-context markerが多かったが、AI draftは利用者の最終文面をdraft style方向へ動かし、文化的にmisalignedなdraftでshiftがより大きかった。

### (2) 何が提案・推測段階か

人間のemail writing実験であり、AI agentのPersona Core driftを直接測ったものではない。長期累積効果も未確定。

### (3) Kamimusuhi 関連 subsystem

- Persona Core / voice realization
- external model delegation
- relationship-specific communication style
- HCI / co-writing

### (4) 借りられる設計・実装アイデア

external cognitive extensionが生成したdraftをそのままKamimusuhiの発話styleへ採用すると、**外部modelのstyleがself-expressionへ侵入する**可能性を監査する。content delegationとstyle realizationを分離する。

### (5) Kamimusuhiとの差分

Kamimusuhiでは最終utteranceをPersona/Relationship state側でrealizeできるため、外部modelはsemantic draftだけ返し、styleはself-owned layerで再生成する設計が可能。

`DelegatedDraftStyleDriftBench-v0`

- 同一intentを異なる外部model/styleでdraft。

## B — GSAP: spike-native long-range interactionを`propagate then select`へ再設計

**Source**

- Shen et al., *Rethinking Pairwise Token Interaction in Spiking Transformers*
- arXiv:2609.26297
- https://arxiv.org/abs/2609.26297
- code: https://github.com/Fancyssc/GSAP

### (1) 何が実証済みか

Spiking Transformerでquery-key spike coincidenceがlong-range propagationを不安定にする問題に対し、Gated Spike Axial Propagationを提案・実装。spike contextを軸方向へ先に伝播し、receiver-conditioned gateで取り込む量を選ぶ `propagate-then-select` 構造を採用し、codeを公開している。

### (2) 何が提案・推測段階か

abstractだけではKamimusuhi向けのlatency/energy superiorityを確定できない。neuromorphic hardware上のend-to-end実測やalways-on sensor taskへの優位は別途必要。

### (3) Kamimusuhi 関連 subsystem

- K-Nerve
- event-driven / neuromorphic cognition
- low-power salience / sensory preprocessing

### (4) 借りられる設計・実装アイデア

binary sparse representationではTransformerのpairwise attentionをそのまま模倣せず、substrate特性に合わせてcommunication primitive自体を変える。

### (5) Kamimusuhiとの差分

KamimusuhiはSNNを必須としない。K-Nerveではaccuracyだけでなくsensor→decision latency、power、state retention、fallback costで採否を決める。

### (6) 次に検証すべきこと

`SpikeNativeLongRangePropagationBench-v0`

- small salience / wake-word / anomaly sequence fixture。
- dense Transformer / recurrent / SNN attention / GSAPを同一accuracy targetで比較。
- CPU/GPU/neuromorphic候補上でlatency・energy proxy・memoryを測る。

### (7) 重要度

**B**

# 12. 今回の圧縮結論

今回の設計上の一文は次。

> **形式的に通ったことを、意味的に正しい・実行可能・独立・忠実である証拠へ昇格させない。**

具体的には、

```text
type-safe decision != rubric-correct decision
accepted self-rewrite != identity continuity
speaker != memory owner
compact context != rewritten truth
retrieval success != retriever quality
configured fallback != servable fallback
post-debate consensus != independent evidence
semantic tool match != authorized trustworthy tool
```

をそれぞれ別のstate / receipt / benchmarkとして扱うのが今回の最も強い差分である。
