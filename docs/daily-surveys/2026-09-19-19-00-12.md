# 3. A — Memory domain separation を「write owner exclusivity」まで強める

**Primary source**

- NousResearch/hermes-agent PR #115985, *fix(review): background review routes facts to USER.md vs MEMORY.md and never writes one fact to two stores*  
  https://github.com/NousResearch/hermes-agent/pull/115985

### (1) 何が実証済みか

Hermes の background self-improvement review では、memory tool に `USER.md`（ユーザー自身のプロフィール）と `MEMORY.md`（環境・一般的な実用事実）の二つの保存先があるにもかかわらず、review prompt がこの違いを十分に伝えていなかった。さらに combined review prompt が user-preference lesson を skill と memory の双方へ持たせるよう読める記述を含んでいた。

PR が引用する field data では、一つの production instance で **MEMORY.md 8件中5件（63%）が既存 SKILL.md の内容を再記述**し、両 store が char limit の99%に達して、その後の write が失敗していた。修正案は「一つの fact は一つの store」「skill が所有する lesson は skill のみ」「cross-cutting user preference だけ USER.md」を prompt contract に明記する。targeted background-review tests は43件 pass と報告される。

### (2) 何が提案・推測段階か

修正は主に prompt text であり、runtime schema / mutation gate が二重所有を機械的に拒否するわけではない。したがって、この PR が長期 memory drift や semantic duplication を一般に解決したとは言えない。また field count は一つの instance の観測であり、発生頻度の一般化はできない。

### (3) 関係する Kamimusuhi サブシステム

- episodic / self / relationship / semantic / procedural memory
- sleep / reflection / consolidation
- Mutation / Activation Gate
- Persona Core training-data generation
- `INV-002` domain separation
- `INV-005` durable mutation boundary

### (4) 借りられる設計・実装アイデア

Kamimusuhi では domain separation を schema だけでなく、**semantic owner contract** として mutation proposal に持たせる。

```text
learned item
  ├─ canonical evidence refs
  ├─ proposed semantic owner: relationship | self | procedural | semantic | ...
  ├─ optional projections/indexes
  └─ duplicate-owner justification: normally forbidden
```

同じ内容を複数 domain に物理コピーする代わりに、canonical evidence / one authoritative derived record を参照する rebuildable projection を各 view に作る。重複が必要なら「cache/index copy」であり authority copy ではないことを型で示す。

### (5) Kamimusuhiとの差分

Kamimusuhi はすでに `INV-002` で memory domain を概念的に分離している。ただし現仕様は「同じ抽象 lesson を複数 durable domain が同時に owner として保持する」ケースを明示的に禁止していない。今回の evidence は、**read/retrieval の分離だけでなく write ownership の排他性**が必要になり得ることを示す。

### (6) 次に検証すべきこと

**`MemoryDomainWriteExclusivityBench-v0` — P0 candidate**

- 同一 session から user preference / environment fact / procedural lesson / relationship fact を生成
- sleep-review を複数回走らせる
- prompt-only routing vs typed owner validation vs shared canonical fact + projections を比較
- metric:
  - semantic duplicate rate
  - false-owner rate
  - store growth
  - later contradiction/update cost
  - retrieval accuracy
  - cross-domain contamination
- adversarial case: 一つの statement が複数 domain に見える曖昧例

成功条件は「物理的な重複ゼロ」ではなく、**authoritative owner が一意で、projection/cache を owner と誤認しないこと**。

### (7) 重要度

**A** — Kamimusuhi の memory taxonomy 直下にある fresh implementation failure。概念設計を runtime invariant へ進める根拠になる。

# 4. A — HIL-UMI: learning signal と live actuation authority を分離する

**Primary source**

- Han et al., *HIL-UMI: Bringing Human-in-the-Loop Post-Training of Vision-Language-Action Models to Universal Manipulation Interface*, arXiv:2609.20659, submitted 2026-09-17  
  https://arxiv.org/abs/2609.20659

### (1) 何が実証済みか

HIL-UMI は handheld UMI demonstration の同じ observation stream に現在の VLA policy を **shadow query** するが、その prediction を robot では実行しない。human trajectory と policy prediction の Energy Score の disagreement を使って OOD 領域の追加収集を起動し、別ループで low online advantage の区間を progress estimator 改善に使う。

4つの real-world manipulation task で SFT より一貫した改善を報告し、Clean Up Table では HG-DAgger を上回りつつ per-frame collection time を下げたとする。重要なのは、policy-aware iterative data collection を robot deployment から切り離した点である。

### (2) 何が提案・推測段階か

4 task の結果から、未知の embodiment、失敗コストの高い実世界、長期 online self-improvement 全般に安全・有効とは言えない。shadow prediction が human trajectory と違うことは、policy が誤っている証拠とは限らず、human 側の suboptimality や複数正解もある。

### (3) 関係する Kamimusuhi サブシステム

- K-Edge / Physical AI
- procedural self-improvement
- sleep/offline training-data generation
- Cognitive Action Router
- human demonstration / correction channel
- future Persona Core / body-controller descendant training

### (4) 借りられる設計・実装アイデア

**shadow cognition lane** を設け、現行 policy/model が「自分ならどう動くか」を観測に対して出すが、live actuator authority は持たせない。operator/human action と disagreement が大きい区間だけを、学習候補 episode として high-resolution に保存する。

```text
observation ──> human/operator action ──> real world
      └──────> shadow policy proposal ──X actuator
                    │
                    ▼
            disagreement / uncertainty
                    │
                    ▼
             training-data candidate
```

### (5) Kamimusuhiとの差分

HIL-UMI は VLA post-training の方法であり identity continuity を扱わない。Kamimusuhi では shadow lane の出力を canonical action history と混同せず、**counterfactual/generated cognition** として保存しなければならない。また学習済み descendant の activation は continuity/evaluation gate を別途通す。

### (6) 次に検証すべきこと

**`ShadowPolicyDisagreementLearningBench-v0` — P1 candidate**

- human teleoperation / scripted safe expert / current controller を実行 owner にする
- candidate controller は shadow-only
- disagreement、uncertainty、failure-near state を収集
- uniform logging と targeted logging を同 budget で比較
- descendant を offline train し、held-out task / safety / latency / continuity regressions を評価
- shadow output が誤って canonical executed action と記録されないことも検証

### (7) 重要度

**A** — high-authority embodied self-improvement を「まず観測・比較で学ぶ」方向へ寄せる、直接借用可能な安全なデータ収集パターン。

# 5. A — SkipVLA: cognitive resource は task 全体ではなく phase ごとに切り替える

**Primary source**

- Agrawal et al., *SkipVLA: Skipping VLA Steps with Classical Planning for Fast Robot Manipulation*, arXiv:2609.20648, submitted 2026-09-17  
  https://arxiv.org/abs/2609.20648

### (1) 何が実証済みか

SkipVLA は pretrained VLA を全 control step で呼ばず、**free-space motion は classical motion planner、grasp/place など contact-rich skill だけ VLA**を使う hybrid policy。frozen VLA の vision-language backbone を target-pose prediction に再利用し、追加 demonstration なしで構成する。

3 VLA、LIBERO 13 tasks、physical 6-DoF YAM arm の3 pick-and-place tasks で評価し、**最大2.5× faster task completion** と energy reduction を、同じ task success rate で報告する。

### (2) 何が提案・推測段階か

free-space / contact-rich の分割が明瞭な manipulation task から、open-world mobility・social interaction・uncertain navigation 全般への一般化は未実証。target pose 自体は VLA由来なので、VLAを「完全に安全境界の外」へ追い出したわけではない。

### (3) 関係する Kamimusuhi サブシステム

- K-Nerve / K-Edge
- Cognitive Action Router
- Cognitive Budget
- Physical AI / mobility
- local vs expensive model routing

### (4) 借りられる設計・実装アイデア

routing unit を「一つの task」ではなく **control phase / semantic boundary** にする。

```text
low-semantic-cost, geometrically specified phase
    -> deterministic / classical planner / FSM

contact / ambiguity / semantic choice boundary
    -> learned local model or VLA / deeper cognition
```

低コスト controller には bounded authority を与え、goal / target / envelope が変わったら再度 higher cognition へ戻す。

### (5) Kamimusuhiとの差分

直前に収載した VLA-ULAP は remote VLA の間を learned local action predictor で埋める方式だった。SkipVLA は **古典的 planner へ仕事を戻す**点が異なる。Kamimusuhi では「小さいAIに全部置換」だけでなく、structure が明示可能な区間は非LLM・非neural controlへ落とせる。

### (6) 次に検証すべきこと

**`SemanticPhaseRoutingBench-v0` — P1 candidate**

- VLA-only
- local learned predictor
- classical planner/FSM + VLA boundary calls
- K-Nerve-like event controller + K-Edge

を同じ manipulation/mobility task で比較。

metric: success、collision/near-miss、p50/p99 control latency、energy、VLA calls、semantic-boundary miss、recovery cost。

### (7) 重要度

**A** — K-Nerve/K-Edge の「意味コストの低い制御を重い cognition から逃がす」という設計を、実機を含む独立研究がかなり直接支持する。

# 6. B — INSPECT: active perception を「どの claim を検証したいか」から駆動する

**Primary source**

- Wen et al., *INSPECT: Learning Robot View Selection from Assistant Use*, arXiv:2609.20615, submitted 2026-09-17  
  https://arxiv.org/abs/2609.20615

### (1) 何が実証済みか

smart-glasses assistant の利用記録から、assembly inspection に有用な robot viewpoint preference を学習する。physical gearbox image 評価では、keep-current-view 比で human-rated full verifiability を **34.8% → 41.7%**へ改善。IMPACT angle-grinder recordings への transfer では frozen perception head の correct decision rate を **50.6% → 54.3%**へ改善した。

### (2) 何が提案・推測段階か

評価の一部は annotated assistant-video replay による state feedback simulation であり、完全な online closed-loop robot exploration の実証ではない。改善幅も task により modest で、一般の epistemic action policy とはまだ距離がある。

### (3) 関係する Kamimusuhi サブシステム

- multimodal perception
- K-Edge active sensing
- Global Workspace / evidence requests
- Physical AI
- self-modeled uncertainty

### (4) 借りられる設計・実装アイデア

workspace に「何が不明か」だけでなく **which claim lacks verifiable evidence** を持たせ、camera/viewpoint/sensor selection をその claim へ結び付ける。

```text
claim / belief proposal
  -> evidence gap
  -> candidate sensor/view action
  -> new observation + provenance
  -> claim update
```

### (5) Kamimusuhiとの差分

Kamimusuhi は visual inspection 専用ではなく分散感覚系を持つ。したがって view selection を camera pose に限定せず、screen capture、mic、LiDAR、robot viewpoint、fresh API read などを同じ `EvidenceAcquisitionAction` として扱う方が一般的。

### (6) 次に検証すべきこと

**`EvidenceSeekingViewControlBench-v0` — P1 candidate**

同じ claim set について passive sensing / uncertainty-only active sensing / claim-indexed active sensing を比較し、evidence coverage、action cost、latency、誤belief activation、不要なprivacy exposureを測る。

### (7) 重要度

**B** — active perception の良い具体例。ただし Kamimusuhi へ一般化するには sensor/action cost と authority を含む追加実験が必要。

# 7. B — Value Faces: stable value と relationship-specific demonstrated value を分ける

**Primary source**

- Koo, Rashed, Jahanbakhsh, *Value Faces: Surfacing How Self-Presentation Shifts Across Relationships*, arXiv:2609.19581, submitted 2026-09-17  
  https://arxiv.org/abs/2609.19581

### (1) 何が実証済みか

Value Faces は everyday messaging history から Schwartz の10 basic values を用い、**relationship ごとの demonstrated-value profile**を作る。mixed-methods study は N=18。生成 profile は relational context を chance guessing の約2倍の odds で区別し、participant が認識していた relationship 間差と system inference が整合したと報告する。参加者は profile を、役割・時間変化・自己評価を言語化する補助として使った。

### (2) 何が提案・推測段階か

N=18 と小規模で、推定された value profile が本人の「真の価値」を測るとは言えない。chat platform / culture / relationship type への一般化も未確立。

### (3) 関係する Kamimusuhi サブシステム

- self-model / values
- relationship model
- narrative identity
- social cognition
- longitudinal HCI

### (4) 借りられる設計・実装アイデア

Kamimusuhi 自身についても、

```text
stable value prior
!=
relationship-specific expression / demonstrated policy
```

を分けて記録する。相手ごとに tone・foregrounded concern・interaction norm が違っても、それを即座に stable Persona value drift と解釈しない。

### (5) Kamimusuhiとの差分

Value Faces は人間の self-reflection system。Kamimusuhi では relationship-specific 表現が **自己の core value を上書きする経路**にならないよう、derived relational profile と canonical self value proposal を分離する必要がある。

### (6) 次に検証すべきこと

**`RelationshipDemonstratedValueSeparationBench-v0` — P2 candidate**

同じ underlying value policy を持つ agent に複数 relationship context を与え、relationship-specific expression の適応性と core-value drift を別指標で測る。user preference の self-contamination、sycophancy、cross-person leakage を含める。

### (7) 重要度

**B** — Kamimusuhi の「一つの人格だが相手ごとに関係が違う」を評価する conceptual/HCI evidence として有用。

# 8. B — Hermes #115983: dead organ の liveness probe が cognition 全体を starvation させる

**Primary source**

- NousResearch/hermes-agent PR #115983, *fix(mcp): a dead stdio child no longer spins the lifecycle loop after the proof deadline*  
  https://github.com/NousResearch/hermes-agent/pull/115983

### (1) 何が実証済みか

stdio MCP child が session proof 前に死亡すると、deadline 後の timeout が0のままになり、dead-child check を tight loop する failure が再現された。報告では約 **82k liveness checks/s**、短い live probe では main が0.11秒で3,652 checksし return せず、修正版は1回で `reconnect` へ遷移した。Telegram/Discord/cron 等が starvation し得た。18 targeted tests pass と報告される。

### (2) 何が提案・推測段階か

MCP stdio lifecycle 固有の修正であり、すべての distributed organ failure に同じ threshold/retry budget が適切とは限らない。PR は open/unmerged。

### (3) 関係する Kamimusuhi サブシステム

- tool/model orchestration
- resource health / digital interoception
- K-Core scheduler
- external cognitive extension lifecycle
- background cognition fairness

### (4) 借りられる設計・実装アイデア

organ state を `PROBING -> PROVEN -> DEAD/RECONNECTING -> PARKED` の explicit state にし、deadline 後の liveness probe は bounded retry budget を消費する。失敗した extension が control-plane compute を無限消費できないようにする。

### (5) Kamimusuhiとの差分

Kamimusuhi では external tool だけでなく local model、sensor node、K-Edge、memory service も「organ-like resource」になり得る。したがって failure budget は process単位ではなく Cognitive Budget と scheduler fairness に統合する必要がある。

### (6) 次に検証すべきこと

**`DeadOrganRetryBudgetBench-v0` — P1 candidate**

複数 organ を同時実行し、一つを crash/hang/flap させる。interactive latency、background progress、CPU burn、retry count、inflight outcome closure、recovery time を測り、死んだ organ が他 cognition を starvation しないことを要求する。

### (7) 重要度

**B** — identityそのものではないが、長期常駐個体の self-maintenance / liveness に実装上重要な failure class。

# 9. B — Hermes #115951: agent の自己申告とは別に execution receipt を持つ

**Primary source**

- NousResearch/hermes-agent PR #115951, *feat(plugins): run-receipts — hash-chained per-run evidence records*  
  https://github.com/NousResearch/hermes-agent/pull/115951

### (1) 何が実証済みか

open PR は turn ごとに NDJSON receipt を書く plugin を実装し、run/session/task/turn ID、model/provider、time、outcome、tool/API calls の digest、previous hash を記録する。raw args/results は保存せず SHA-256 digest のみ。lockfile で concurrent append を serialize し、edit/delete/reorder を `verify` が検出する。16 tests と OpenAI-compatible endpoint を使った live e2e を報告する。

### (2) 何が提案・推測段階か

hash chain は **記録内容が真実であること**を証明しない。また chain writer 自体を完全に支配できる attacker は全履歴を再生成できる。外部 anchor / signature / canonical head binding は別問題。低entropyな sensitive argument の unsalted hash は equality/dictionary information を漏らす可能性もある。

### (3) 関係する Kamimusuhi サブシステム

- observability / provenance
- Continuity Kernel receipts
- tool/model orchestration
- self-improvement evaluator evidence
- distributed execution debugging

### (4) 借りられる設計・実装アイデア

canonical transcript とは別に compact execution receipt を持ち、private payloadを直接保存しなくても「どの実行があったか」を後から突合できるようにする。Kamimusuhi では receipt を current canonical head / principal / software-body epoch に bind する。

### (5) Kamimusuhiとの差分

Kamimusuhi の lineage receipt は identity/state activation authority を扱う。一方 run receipt は **observed execution envelope**。両者を統合しすぎず、`execution evidence != canonical identity commit` を維持すべき。

### (6) 次に検証すべきこと

**`RunReceiptIntegrityBench-v0` — P2 candidate**

- concurrent K-Edge/K-Core/background turns
- crash between tool effect and finalize
- receipt deletion/reordering/replay
- keyed digest / signature / external periodic anchor の比較
- canonical event と receipt の cross-link coverage

### (7) 重要度

**B** — 既存 provenance 設計を実装へ落とす参考。ただし新しい identity principle ではなく observability pattern。

# 10. B — Sequential Contextual Fit を cheap salience feature として検証する

**Primary source**

- Sun & Wang, *Sequential Contextual Fit Predicts Human Behavioural and Neural Dynamics Across Domains*, arXiv:2609.20179, v1 submitted 2026-07-24, Sep 18 recent-list cross-list/backfill  
  https://arxiv.org/abs/2609.20179

### (1) 何が実証済みか

SCF は current information state と recent context の embedding similarity を recency-weighted kernel で測る単純な指標。language、music emotion、audiovisual EEG subset、gambling、human activity recognition、decision-related EEG で、**低い contextual fit が長い processing、より大きな affect/behavior transition、強い neural-state change を予測**した。surprisal、RL prediction error、acoustic/visual/sensor change を control しても効果が残ったと報告する。

### (2) 何が提案・推測段階か

これは人間データ上の predictive association であり、SCF が脳の salience mechanism であることや、AI agent にそのまま移植すれば有効なことを示していない。v1 は7月のため fresh paper ではなく今回の未収載 backfill。

### (3) 関係する Kamimusuhi サブシステム

- background cognition / salience
- novelty / prediction-error processors
- K-Nerve candidate feature
- sensory event triage
- cognitive budget allocation

### (4) 借りられる設計・実装アイデア

semantic/event embedding がすでに得られる modality では、`recent-state fit` を一つの cheap feature として使い、低fit時に K-Edge/K-Core を wake する。ただし単独 decision authority にはしない。

### (5) Kamimusuhiとの差分

Kamimusuhi の novelty/salience は人間神経機序の再現ではなく工程上の resource allocation。SCF は biological justification ではなく **候補 heuristic** としてのみ評価する。

### (6) 次に検証すべきこと

**`ContextualFitSalienceBench-v0` — P2 candidate**

raw change / embedding distance / surprisal / task-specific anomaly score / SCF を、sensor stream と dialogue event で比較。重要event recall、false wake、latency、compute、modality transfer を測る。

### (7) 重要度

**B** — cross-domain human evidence は興味深いが、Kamimusuhi での因果的 utility は未検証。
