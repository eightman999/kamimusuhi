# 3. 要約

今回の中心テーマは、**「自己改善・記憶・人格的ふるまいがどこに宿ったのかを追跡する」こと**だった。

特に重要なのは次の5点である。

1. self-evolving agent は endpoint score だけで評価すると、途中で獲得した能力の消失や selection failure を見逃す。**evolution path 全体を checkpoint 化して監査する必要がある**。
2. harness が作った有用な behavior は fine-tuning によって model weights へ移植できる。これは性能上は有用だが、Kamimusuhi では **behavior provenance が harness → weights へ不可視化される問題**を持つ。
3. Jev-Mem は System-One 型の高速 typed controller と preserved observations を組み合わせ、memory write/read routing を System-Two の回答生成から分離した。Kamimusuhi の K-Nerve / K-Edge と memory projection の比較対象として非常に近い。
4. social active inference では、partner ごとの model confidence を別々に保持することで social policy commitment が変わる一方、**過去に高信頼だった相手の変化に confidence revision が遅れる**ことが示された。relationship state には belief だけでなく、その reliability と freshness が必要になる。
5. ME-Brain は embodied experience → memory evolution → cognition → action の閉ループを、weight retraining なしで具体化した。Kamimusuhi の Physical AI 方向に対し、**decision-critical moment だけへ計算と記憶を集中させる**比較対象になる。

## A+ — EvoPathBench: self-evolution は endpoint ではなく capability trajectory を監査する

**Source**

- Hongqiang Lin et al., *Beyond Endpoint Performance: Process-Level Evaluation of Self-Evolving Agents*
- https://arxiv.org/abs/2609.24663

### (1) 何が実証済みか

base model と tools を固定し、evolving artifact を successive checkpoints で freeze し、各 checkpoint を held-out episode で再評価する `EvoPathBench` が提案・実験されている。

報告された観察は以下。

- similar unseen tasks で得た gain は distribution shift で弱まりやすい。
- retention loss はすべての evolution path に均一ではなく、一部 path に集中する。
- rule adaptation は評価した方法のどれでも安定して成功しない。
- self-evolution は良い candidate artifact を生成できても、**実際に選択された update がその潜在 gain を取り切れない**。

### (2) 提案・推測段階

この benchmark が一般の long-lived personal agent / embodied agent / Persona Core mutation にそのまま一般化できることは未実証。

### (3) Kamimusuhi 関連 subsystem

- Mutation / Activation Gate
- Continuity Kernel
- Persona Core migration
- Procedural Memory / Reflection
- self-improvement evaluation

### (4) 借りられる設計

**candidate generation と candidate selection を別 metric にする。**

さらに、各 durable mutation ごとに capability ledger を持つ。

```text
mutation candidate
  -> checkpoint
  -> unseen capability test
  -> unrelated-learning retention test
  -> changed-rule adaptation test
  -> activation decision
  -> future checkpoint regression audit
```

### (5) Kamimusuhi との差分

EvoPathBench は artifact-level self-evolution を評価する benchmark であり、Kamimusuhi の authoritative identity lineage、relationship continuity、authorization、body migration まで扱わない。

Kamimusuhi では「性能が上がった」だけでなく、**何を残すべき identity / value / relationship invariants とみなすか**が追加問題になる。

### (6) 次に検証すべきこと

`EvolutionPathCapabilityLedgerBench-v0`

- same base model で procedural-memory mutation を 20–50 generations 実施
- checkpoint ごとに known / unseen / shifted / unrelated-retention suite を実行
- `best generated candidate` と `actually activated candidate` の gap を測定
- regression が発生した generation と原因 artifact を追跡
- endpoint-only selection と path-aware selection を比較

### (7) 重要度

**A+**

理由: Kamimusuhi の mutation/activation gate を「その時点の pass/fail」から **longitudinal capability accounting** へ拡張する直接的根拠になる。

## A — Harness-Zero: harness behavior を model weights へ蒸留できる

**Source**

- Haoran Ye et al., *Harness-Zero: Harness Distillation via Agent-as-Harness*
- https://arxiv.org/abs/2609.24974

### (1) 何が実証済みか

specialized harness を training-time guidance として使い、target harness の action space 上で student response を修正して demonstration を作る `agent-as-harness` を提案。

報告値では、specialized harness を deployment 時に外したあとでも base model の macro-average task success が **23.3% → 44.3%**、harness を付けた状態の **41.7%** も上回った。3 domain / 28 behavior patterns で harness-induced behavior の平均 82.3% recovery を報告している。

### (2) 提案・推測段階

- harness-induced behavior が identity/persona に相当するとは示していない。
- 蒸留された behavior の長期安定性、safety policy、social style への副作用は別問題。

### (3) Kamimusuhi 関連 subsystem

- Persona Core / J-series
- tool/model orchestration
- K-Core / K-Deep
- cognitive-organ migration
- model-weight consolidation

### (4) 借りられる設計

Kamimusuhi の slow consolidation で、長期に成功した **procedural policy / tool habits** を harness 依存から resident model へ蒸留する方向。

ただし蒸留時に source behavior lineage を記録する。

```text
behavior pattern
  source = harness rule / tool policy / procedural memory
  -> distilled dataset
  -> weight candidate
  -> behavior recovery audit
  -> provenance receipt
```

### (5) Kamimusuhi との差分

Kamimusuhi では model weights は identity owner ではない。

したがって harness → weights の behavior transfer を行っても、**canonical self / relationship / value evidence を weights の中へしか残さない設計にはしない**。

### (6) 次に検証すべきこと

`HarnessBehaviorInternalizationAudit-v0`

同一 task family で以下を比較。

1. base model + specialized harness
2. base model + generic harness
3. distilled model + generic harness
4. distilled model + harness conflict

測定:

- success
- behavior recovery
- unwanted policy carryover
- source attribution可能性
- model replacement 後の再構築可能性

### (7) 重要度

**A**

## A — Jev-Mem: System-One memory control と preserved evidence の分離

**Primary implementation**

- https://github.com/libingzheren/Jev-Mem
- paper: https://arxiv.org/abs/2609.23986

### (1) 何が実証済みか

公開 repo は memory management を次の3層へ分離している。

- **System One**: memory typing, relation judgment, query routing, retrieval budget, candidate scoring, evidence sufficiency
- **Shared memory**: original observation + provenance と semantic / temporal / causal / entity graph views
- **System Two**: selected evidence を使った answer synthesis

repo の LoCoMo / GPT-4o-mini 結果では、paper-reported values として overall score **0.777**、memory build **158 s**、average query latency **0.93 s** を記載している。比較表では MAGMA の overall 0.700 / latency 1.47 s、Nemori build 1,044 s を上回るとしている。

README は同時に、benchmark scripts の例が full paper evaluation をそのまま再現するものではないこと、LongMemEval の公式 metric を使っていない runner があることも明記している。

### (2) 提案・推測段階

- paper-reported benchmark は今回こちらでは再実行していない。
- Jev controller が lifetime-scale autobiographical memory に一般化するかは未検証。
- System-One judge の誤りが relation graph を長期汚染する可能性は残る。

### (3) Kamimusuhi 関連 subsystem

- K-Nerve / K-Edge
- Memory Router
- Global Workspace
- Episodic / Relationship / Semantic memory
- Cognitive Budget

### (4) 借りられる設計

非常に借りやすいのは、**LLM に memory graph 全体を書き直させず、typed microdecision だけを安価な controller に任せる**こと。

また、semantic relation と timestamp ordering のような deterministic relation を分ける設計もよい。

### (5) Kamimusuhi との差分

Jev-Mem の shared memory graph は task-memory architecture であり、Kamimusuhi の以下の authority boundary を置き換えない。

- `self/persona`
- `episodic`
- `relationship`
- `library`
- `canonical evidence`

graph view は canonical state ではなく **derived retrieval structure** として扱うべき。

### (6) 次に検証すべきこと

`SystemOneMemoryControlBench-v0`

- canonical observation store を immutable に維持
- Jev と small local classifier / deterministic heuristics / LLM router を比較
- admission / relation / retrieval-route / stopping の各 decision を独立 ablation
- wrong relation の長期 amplification を測定
- graph 全削除後に canonical evidence から再構築可能か確認

### (7) 重要度

## A — Partner-Specific Affective Precision: relationship belief の confidence は相手ごとに別 state

**Source**

- Harshil Shah, Andrew Pashea, *Partner-Specific Affective Precision in Social Active Inference*
- IWAI 2026 full paper
- https://arxiv.org/abs/2609.24876

### (1) 何が実証済みか

multi-partner graded trust-game simulation で、partner ごとに behavioral model confidence を保持し、その precision が policy selection の commitment strength を調整するモデルを評価。

主な報告:

- precision は partner-state inference の正確さそのものより **policy commitment** へ強く作用。
- predictability が高い partner への confidence が高いからといって reward が高くなるとは限らない。
- partner behavior が abrupt shift すると、以前の高 confidence がしばらく残り、behaviorally active なままになる。

### (2) 提案・推測段階

simulation study であり、人間関係や real-world companion で同じ dynamics が成立するとは限らない。

### (3) Kamimusuhi 関連 subsystem

- Relationship Memory
- Person Model
- Common Ground
- social cognition / ToM
- affective / regulatory state

### (4) 借りられる設計

relationship hypothesis を単一 belief score にせず、少なくとも:

```text
belief content
prediction confidence
last-confirmed-at
change-point suspicion
policy commitment gain
```

を分離する。

### (5) Kamimusuhi との差分

Kamimusuhi では confidence は affect そのものではなく evidence-derived metacognitive state として扱える。さらに relationship fact は canonical interaction evidence から独立に検証できる必要がある。

### (6) 次に検証すべきこと

`RelationshipModelPrecisionLagBench-v0`

- stable preference phase → abrupt preference reversal

## C — MEM architecture / consciousness paper: interoception と recurrent grounding の設計仮説

**Source**

- Janusz A. Starzyk, Wiesław L. Galus, *From Biological Precursors to Artificial Cognition: Consciousness, Embodiment, and the MEM Architecture*
- https://arxiv.org/abs/2609.23828

### (1) 何が実証済みか

この論文自体は主として comparative / theoretical research program。LLM / hybrid LLM / VLA / embodied agent と Motivated Emotional Mind (MEM) architecture を比較する。

MEM では receptor-grounded representation、regulatory self-monitoring / interoception、affect、associative memory、lower sensory/interoceptive map への re-entry を強調する。

### (2) 提案・推測段階

consciousness attribution は実証されていない。著者自身も linguistic ability / multimodality / memory / planning / humanoid embodiment は phenomenal experience の十分条件ではないとし、MEM を empirical validation が必要な falsifiable research program と位置付ける。

### (3) Kamimusuhi 関連 subsystem

- digital interoception
- homeostasis
- K-Nerve / K-Core recurrent loops
- research foundations

### (4) 借りられる設計

意識主張ではなく、**regulatory state を外部telemetryとは別の first-class internal signal として cognition へ再入力する**設計仮説だけを借りる。

### (5) Kamimusuhi との差分

`spec.md INV-010` と整合的に、self-model / interoception / recurrence を consciousness の証明として扱わない。

### (6) 次に検証すべきこと

`InteroceptiveRegulatoryLoopBench-v0`

battery / thermal / queue pressure / latency debt / memory pressure を input にし、

- telemetry only
- telemetry + explicit homeostatic targets
- telemetry + recurrent internal-state loop

で resource stability と task quality を比較する。

### (7) 重要度

**C**

理由: 発想源としては関連するが、Kamimusuhi の既存 digital interoception 方針を独立に変更する実証証拠ではない。

# 9. 今回の設計上の圧縮

今回の intake を Kamimusuhi の言葉へ圧縮すると:

```text
endpoint performance
!=
evolution-path health

behavior observed in the harness
!=
behavior provenance after distillation into weights

memory graph
!=
canonical memory authority

belief about a person
!=
confidence that the belief is still current

embodied skill evolution
!=
identity evolution

authoritative identity continuity
!=
perceived relational continuity

retrieval usefulness
!=
retrieval cost
```

特に `EvoPathBench` と `Harness-Zero` を合わせると、Kamimusuhi の slow self-improvement は単に「良い candidate を作れるか」ではなく、**どの artifact / harness / weight / memory が、いつ、どの能力・ふるまいを獲得させたかを lineage として追えること**が重要になる。
