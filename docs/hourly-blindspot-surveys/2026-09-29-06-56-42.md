## 候補1 — Restore-Time Non-Execution & Confinement

Sources: OpenClaw #160732 / #160733.

1. **実証済み**: restore処理のaccept前にeffectが生じ得る経路と、staging境界の不整合がsource-levelで報告された。
2. **提案段階**: Kamimusuhiで同じ実装を採るとは限らない。
3. **関係**: Continuity Kernel、backup/restore、death/rebirth、migration。
4. **借用案**: untrusted source → bounded staging → parse → semantic validation → restore receipt → explicit activation。
5. **差分**: 既出Application-Semantic Backup Attestationはbackup内容の正しさ。今回はrestore evaluator自身のeffect boundary。
6. **次の検証**: `RestorePreActivationSafetyBench-v0`。accept前effect=0、verified artifactとactivated artifactの一致を確認。
7. **拾いにくい理由**: backup、supply-chain、identity continuityの境界。
8. **重要度**: **A**

## 候補2 — Audit-Ledger Per-Event Fault Isolation

Source: OpenClaw #160734.

1. **実証済み**: 1件の形式不整合audit payloadが、その後のaudit availability全体へ波及し得るsource-level finding。
2. **提案段階**: audit health低下時のfail-open/fail-stopはeffect class依存。
3. **関係**: observability、Canonical Evidence、incident recovery、execution receipts。
4. **借用案**: per-event quarantine、typed audit health、bounded breaker、recovery probe。
5. **差分**: observer back-actionではなく、audit内部のfault containment。
6. **次の検証**: `AuditLedgerFaultIsolationBench-v0`。valid→malformed→validで後続valid記録が継続するか確認。
7. **拾いにくい理由**: serialization detailに見えるがprovenanceへ直結。
8. **重要度**: **A update**

## 候補3 — Passive Presentation Non-Interference

Source: Hermes Agent #126885.

1. **実証済み**: 表示補助処理がuser actionなしに外部アクセスを伴う経路が報告された。
2. **提案段階**: preview全廃ではなく、安全なenrichment設計が必要。
3. **関係**: perception/presentation、HCI、privacy、tool-result rendering。
4. **借用案**: `PURE_RENDER` と `EFFECTFUL_ENRICHMENT` を分離し、後者のみpolicy gateを通す。
5. **差分**: Passive Materialization Safetyより手前の「表示だけでeffectが出る」問題。
6. **次の検証**: `PassivePresentationEffectBench-v0`。
7. **拾いにくい理由**: HCI、privacy、network、agencyが分断される。
8. **重要度**: **A update**

## 候補4 — Capability-Ledger Continuity After Failed Migration

Source: Hermes Agent #126886.

1. **実証済み**: runtime migration失敗後のretryで、従来capability setが無警告で縮小し、その縮小setが新しいledgerとして残る実運用報告。
2. **提案段階**: capability削減自体は禁止しない。明示retireは正当。
3. **関係**: computational embodiment、software-body evolution、Cognitive Resource Registry、degraded mode。
4. **借用案**: desired/pre/target capability manifest、added/dropped diff、drop reason、operator authorizationをmigration receiptへ持つ。
5. **差分**: version continuityから capability continuityへの拡張。
6. **次の検証**: `SoftwareBodyCapabilityContinuityBench-v0`。
7. **拾いにくい理由**: package managerとagent capabilityが別レイヤーで評価される。
8. **重要度**: **A update**

## 候補5 — Background Egress Policy Closure

Source: Hermes Agent #126888.

1. **実証済み**: background refresh/checkで、documented policyと実際のpathの差異が複数報告された。
2. **提案段階**: 全background egress禁止ではない。
3. **関係**: autonomous maintenance、privacy、zero trust、Infrastructure Preference。
4. **借用案**: `EgressIntent{purpose,destination_class,credential_class,user_triggered,principal}` を共通gateへ通す。
5. **差分**: Policy Interposition Coverageをbackground actorへ拡張。
6. **次の検証**: `BackgroundEgressPolicyCoverageBench-v0`。
7. **拾いにくい理由**: refresh UX、security、privacy settingへ分散。
8. **重要度**: **B update**

## 候補6 — Semantic Middleware Parity Across Submit / Steer / Queue

Source: Hermes Agent #126917.

1. **実証済み**: idle sendでは通るsemantic middlewareがbusy steer pathでは迂回され、reply contextが失われるreproduction。
2. **提案段階**: system-internal messageまで同一middlewareへ通す必要はない。
3. **関係**: DialogueSession、common ground、busy steering、multi-surface interaction。
4. **借用案**: transport選択前にsemantic normalizationをexactly once実行。
5. **差分**: busy stateによるhuman utterance semanticsのpath divergence。
6. **次の検証**: `SemanticSendPathParityBench-v0`。
7. **拾いにくい理由**: UI bugに見えるがsocial common groundへ影響。
8. **重要度**: **B update**
