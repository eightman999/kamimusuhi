## 1. A — Recursive External Data Needs Structural-Complexity & Cycle Budgets

Sources:
- https://github.com/NousResearch/hermes-agent/issues/132006
- https://github.com/NousResearch/hermes-agent/issues/132005
- https://github.com/NousResearch/hermes-agent/issues/132023

1. 実証済み: 小さなYAMLでもaliasによりcycleを持つobject graphになり、cycle-awareでないwalkerがRecursionErrorになるcontrolled reproductionが報告された。別issueでは外部MCP/tool schemaの深いnestingで複数normalizerがstack limitへ達し、Slack Block Kitでもsender-authored nestingが複数walkerのfailureやsilent degradationを起こす。
2. 提案段階: すべての入力に同一depth上限を置く必要はない。schema、message tree、AST、ontology、memory graphは別budgetでよい。
3. 関係: Sensory Event Bus、platform adapter、MCP/tool registry、schema normalization、Library ingestion、K-Nerve、runtime assurance。
4. 借用案: StructuralComplexityBudgetとしてmax_depth / max_nodes / max_edges / max_refs / max_expansion / cycle_policyをinput classごとに持つ。cycle-aware traversalを使い、budget超過はtypedなrejection/degradationとして扱う。
5. 差分: 既存Cognitive Budgetはtoken/latency/energy中心で、入力のshape complexityはfirst-classではない。
6. 次: RecursiveStructureAdmissionBench-v0 (P0)。cycle、deep nesting、schema composition、message treeをfuzzし、process survival、bounded resource use、typed failureを確認。
7. dailyで拾いにくい理由: parser security、serialization、MCP schema、messaging UIが別分野に分かれる。
8. 重要度: A。

## 2. A update — Request-Scoped Authority Must Not Be Cached Across Principals

Source: https://github.com/openclaw/openclaw/issues/164132

1. 実証済み: reusable MCP bridgeがgateway restart後の最初のcaller scopesを保持し、その後の別principalのturnにも再利用するfield/source report。後続のowner/admin turnがfirst callerの低いscopeで評価され、restart後の到着順によって結果が変わる。
2. 提案段階: principal-independentなmetadataまで毎request再構築する必要はない。
3. 関係: Effect Acceptance、Execution Grant、DialogueSession、external runtime、principal propagation。
4. 借用案: authority-bearing contextはcurrent-turn admissionから毎request解決し、cache keyはprincipal/grant epochを含める。transport/bridge object lifetimeをauthority lifetimeにしない。
5. 差分: causal principal propagationは既出だが、今回はshared long-lived bridgeがfirst caller authorityをambient stateへ変える具体例。
6. 次: CrossPrincipalBridgeAuthorityBench-v1 (P0)。principal順序、restart、parallel turnsを交差し、decisionがarrival orderへ依存しないことを確認。
7. dailyで拾いにくい理由: IAM、MCP transport、runtime reuseが別レイヤー。
8. 重要度: A update。

## 3. A update — Semantic Backup Attestation Must Preserve Supported Authority Policies

Source: https://github.com/openclaw/openclaw/issues/164146

1. 実証済み: migration可能なolder approval policyを含むDBについてbackup verificationとrestoreは成功する一方、restore側でpolicyのallowlist意味が失われるcontrolled reproductionが報告された。backup warningもない。
2. 提案段階: backup時に必ず最新schemaへrewriteする必要はなく、原representationを保持してrestore後migrateしてもよい。
3. 関係: Continuity Kernel、backup/restore、Execution Grant、approval policy、software-body migration。
4. 借用案: BackupAttestationへpolicy_schema_version、supported_legacy_parser、effective_policy_digest、semantic decision witnessesを追加。pre/post restoreの代表decisionを比較する。
5. 差分: 9/27のApplication-Semantic Backup Attestationはwrong/incomplete storeを扱った。今回はarchive自体はvalidでもauthority semanticsだけがtransformで変わる。
6. 次: SemanticBackupPolicyRoundTripBench-v1 (P0/P1)。
7. dailyで拾いにくい理由: backup integrity、security evaluator、schema migrationが別々に評価される。
8. 重要度: A update。

## 4. A update — Layered Policy Wrappers Must Preserve Inner Scope & Failure Semantics

Source: https://github.com/NousResearch/hermes-agent/issues/132096

1. 実証済み: narrow matcherとfail-open semanticsを持つtool hookでも、外側dispatcherのtimeout/suppression policyが先に働くと、inner hookが対象にしていないtoolまで一時的に利用不能になるfield report。2つのbackground runsで複数tool callが影響を受けた。
2. 提案段階: explicit global policyによる広域fail-closeまで禁止するものではない。
3. 関係: Effect Acceptance、tool hooks、runtime assurance、degraded mode、policy composition。
4. 借用案: ApplicabilityScope / FailureMode / TimeoutOwner / SuppressionScopeをtyped metadata化し、outer wrapperによるscope拡大やfailure-mode変更はexplicit policy originを要求する。
5. 差分: Configuration Satisfiabilityは設定値同士の矛盾。今回はruntime compositionが宣言済みsemanticsを変える。
6. 次: PolicyWrapperSemanticCompositionBench-v0 (P0/P1)。
7. dailyで拾いにくい理由: guard policyとtimeout supervisorが別moduleとして実装される。
8. 重要度: A update。

## 5. B update — Tool-Result Truncation Must Be an Explicit Omission Event

Source: https://github.com/openclaw/openclaw/issues/164227

1. 実証済み: exec/readのagent-facing payloadが上限で短縮されてもstable markerがなく、visible prefixをcomplete dataとして集計したproduction report。
2. 提案段階: exact withheld量を常に計算する必要はない。最低限PARTIALとcontinuation/full referenceを持てばよい場合もある。
3. 関係: Observation Omission Provenance、tool result envelope、epistemic calibration、K-Deep。
4. 借用案: ResultCompleteness = COMPLETE/PARTIAL/UNKNOWN、truncated、observed size、full_output_ref、digest等をpayload本文とは別に持つ。
5. 差分: 10/2 findingは添付なし vs 取得失敗。今回は一部だけ観測できたpartial observationがcompleteに見える。
6. 次: ToolResultCompletenessEnvelopeBench-v1 (P1)。
7. dailyで拾いにくい理由: truncationはtransport optimizationに見えるがagentにはepistemic state。
8. 重要度: B update。

## 6. B update — Protocol Annotation Projection Must Be SDK/Wire-Version Aware

Source: https://github.com/NousResearch/hermes-agent/issues/132042

1. 実証済み: MCP ToolAnnotationsのPython objectがPythonic attribute名を持つのに、adapterがwire-style field名だけをobject属性として探索した結果、read-only metadataを認識できず、untrusted server上のread-only toolまでwrite-capable相当として扱われるreproductionが報告された。
2. 提案段階: annotationはsecurity proofではなく、trusted metadataとしてどこまでpolicy利用するかは別問題。
3. 関係: MCP adapter、Cognitive Resource Registry、tool capability metadata、Effect Acceptance。
4. 借用案: SDK-native object → canonical capability model → wire projectionの3層に分け、official SDK versionsをadapter conformance testへ含める。unknownをfalseへ潰さない。
5. 差分: 既出MCP annotation研究はannotationをauthority sourceにしないこと。今回はlanguage/SDK naming差でmetadataが消えるprojection failure。
6. 次: ProtocolAnnotationProjectionBench-v1 (P1)。
7. dailyで拾いにくい理由: wire spec、SDK API、policyが別々に見られる。
8. 重要度: B update。

## 結論

今回の中心は、byte length、transport lifetime、archive integrity、設定値の見た目をsemantic safetyのproxyにしないこと。

とくにrecursive structureでは bytes / tokens / depth / nodes / edges / references / cycles / expansion は別々のbudgetである。小さな入力でもcycleならwalkerを止められず、正当なschemaのexpressivenessでもruntime boundを越え得る。

authority側も同型で、shared bridge、cache、wrapper、backup sanitizerは性能・保守のため長生きするが、principal、policy meaning、failure semanticsまで同じlifetimeへ固定してはいけない。

Long-lived cognition needs semantic state to be scoped by the thing that gives it meaning: structure budgets by input class, authority by admitted principal, policy by explicit composition, backup validity by recoverable semantics, and calibration by the body generation actually measured.
