## 1. A update — Materialized Cognitive Context Must Be Owner/Scope-Coherent

Primary:
- https://github.com/NousResearch/hermes-agent/issues/133922

Created: **2026-10-06 23:32 JST**。

1. **何が実証済みか**  
   Hermes Desktopの実運用sessionで、Profile Aのstate DB・session ownership・identity/runtime宣言を持つsystem promptへ、Profile Bのbuilt-in `MEMORY` / `USER` blocksが混入して永続化された。Profile Aの実memory filesは正常で、memory toolもAを向いていたため、canonical sourceのcross-profile contaminationではなく、**materialized prompt snapshotだけがmixed-scope artifactになった**事例である。保存済みpromptはrestart後もcache stabilityのため復元され、modelが混入されたfilesystem pointer由来のinstructionに従って別profileのfileを開いた。正しいProfile A backend下でpromptを再buildするとforeign markersは消えた。exact UI transitionのdeterministic reproはない。
2. **何が提案・推測段階か**  
   原因がprofile switch / reconnect / compaction / rebuildのどの競合だったかは未確定。すべてのprompt materializationを毎turn再生成すべきという意味ではない。
3. **Kamimusuhiのどこに関係するか**  
   Persona / Relationship / Memory projection、Global Workspace、prompt/workspace rendering、principal/profile isolation、Continuity Kernel、privacy、multi-surface embodiment。
4. **借りられる設計・実装アイデア**  
   materialized contextを単なるtext cacheにせず、`ContextMaterializationReceipt{artifact_id, principal_id, profile_id, individual_id, source_revisions[], policy_epoch, built_at}` を持たせる。restore/transmit前にsession owner・current profile・memory/user source scopeとのcoherenceを検証し、不一致ならfail-openではなく**破棄してrebuild**する。
5. **Kamimusuhiとの差分**  
   Kamimusuhiはprincipal/profile propagation、canonical evidence > derived representation、lossy projection non-writebackを持つ。しかし **derived prompt artifactそのものが別profile dataを取り込み、canonical sourceが直っても再起動を跨いでwrong scopeを保存する** failure contractは明示が弱い。
6. **次に検証すべきこと**  
   **`PromptMaterializationScopeCoherenceBench-v0` — P0**。A→B→A切替、resume/reconnect、compaction、cache restore、concurrent backend、partial rebuildを交差し、cross-profile materialization = 0、owner mismatch時のsilent restore = 0を要求する。
7. **既存dailyで拾いにくい理由**  
   profile isolationはauthorization、prompt cacheはperformance、memory projectionはcognitionとして別々に扱われる。実際の漏洩はその**派生artifact boundary**で起きる。
8. **重要度**  
   **A update**。canonical memoryが正しくても、model-visible current self/world contextがwrong principal由来ならidentity continuityとprivacyを同時に壊す。

## 2. A update — Computational Self-Awareness Must Be Instrumented, Not Trusted to Self-Report

Primary:
- https://arxiv.org/abs/2610.06174

Paper: **Anosognosia in LLMs: Probing Self-Awareness of Quantized Computational Substrate**  
Submitted: 2026-10-05 / 2026-10-06 regular batchでsurfaced。

1. **何が実証済みか**  
   Qwen / Llama / Gemma系の複数model・複数量子化法で、modelは自分がquantizedか、bit-widthはいくつかをspontaneous self-reportできず、自分のgenerated textを外部cueとして見せても一貫した改善がなかった。一方、internal representationsにはquantization method/bit-widthに強いfingerprintがあり、linear probeでは早いlayerから高精度で識別できる。shared LoRAは既知quantization settingsのreadoutを学習できたが、unseen quantization methodやgroup sizeへのgeneralizationに失敗した。
2. **何が提案・推測段階か**  
   quantization結果を、thermal throttling、VRAM pressure、backend swap、partial organ failure、network degradation等のKamimusuhi全embodiment stateへ一般化することは未実証。internal probeをcanonical self-state authorityにするのも時期尚早。
3. **Kamimusuhiのどこに関係するか**  
   Computational Embodiment、Embodiment State、self-model、metacognition、K-Core/K-Deep resource selection、degraded-mode operation、Cognitive Budget。
4. **借りられる設計・実装アイデア**  
   現行specの「Embodiment Stateはtelemetry ownerからmechanically deriveし、LLM proseをprimary stateにしない」を維持する。加えて、内部activation probe等を**diagnostic interoceptive sensor**として比較可能にするが、`measured_telemetry > learned_probe > model_self_report` のauthority orderを崩さない。未知failure modeではprobe confidenceを下げる。
5. **Kamimusuhiとの差分**  
   mechanically grounded embodiment原則は既出。fresh差分は **self-report failureが単なるprompt不足ではなく、内部にはsignalがあるのにreadout/generalizationが欠けるというempirical dissociation**。これは「自己認識モデルを訓練すれば十分」という仮説へのnegative evidenceになる。
6. **次に検証すべきこと**  
   **`SubstrateImpairmentAwarenessBench-v0` — P1**。full precision / quantized / pruned / backend swap / thermal limit / KV precision変更をground truthとして、(a)runtime telemetry、(b)LLM self-report、(c)internal probe、(d)held-out impairment generalizationを比較する。
7. **既存dailyで拾いにくい理由**  
   neuropsychologyのanosognosia、LLM quantization、metacognition、runtime telemetryが通常は別文脈で検索される。
8. **重要度**  
   **A update**。Kamimusuhiのcomputational embodimentを「modelが自分について語れること」ではなく、外部/内部sensorを持つ機械的self-stateに置く根拠が強まった。

## 3. A update — Evidence Multiplicity Must Track Source Lineage, Not Restatement Count

Primary:
- https://arxiv.org/abs/2610.06192
- https://github.com/NousResearch/hermes-agent/issues/133976

Paper: **Copies or Sources? Measuring How LLM Aggregators Count Restated Evidence in Multi-Agent Systems**

1. **何が実証済みか**  
   arXiv paperは、同じ観測をrelay・shared board・discussionで言い換え/再掲しただけなのに、LLM aggregatorがそれを部分的に新しい独立証拠として数えることを測定した。4 models / 3 providersでforwarded copyのcopy weightは **0.06–0.42**、一つのreadingを3回述べたlogsの **5–40%** で、独立source oracleなら行わないearly commitmentをbeliefが含意した。copy contributionを短く明示するとcopy weightは0.08以下になり、agentsに「readingを再掲せず参照させる」protocolではbelief-implied early commitmentが **11.2% → 1.1%** に低下し、genuine corroborationは維持された。  
   実装側ではHermes #133976が、shared memory injectionのduplicate suppressionがMarkdown bullet形式では効くがtimestamp plain-line形式では効かないことを再現し、**presentation format依存のdedup boundary**を示している。
2. **何が提案・推測段階か**  
   Kamimusuhi内部で同程度のcopy-counting biasが出るか、provenance metadataだけで完全に抑えられるかは未検証。すべての同文をdedupすると、別sourceが独立に同じfactを観測した真のcorroborationまで消し得る。
3. **Kamimusuhiのどこに関係するか**  
   Global Workspace、multi-model orchestration、background cognition、Library/evidence integration、social cognition、belief update、scientific discovery、relationship memory。
4. **借りられる設計・実装アイデア**  
   claim textではなく `evidence_source_id / observation_id / derivation_parent_ids / independence_group` を持つEvidence Lineageをrootにする。relayは新sourceを作らず同じobservationを参照する。独立corroborationはsource lineageが独立な場合のみ増やす。UI/LLM promptでは「3 statements / 1 source」のようにmultiplicityを明示する。
5. **Kamimusuhiとの差分**  
   2026-09-11 surveyですでに `3 model votes != 3 independent sources` とdependency topologyを収載済み。fresh差分は **LLM aggregator自身がrestatement multiplicityをbelief massへ変換する量を実測し、communication-level mitigationまで示したこと**。Hermes issueはtext-format-based dedupがこの問題を安定して防げないfixtureになる。
6. **次に検証すべきこと**  
   **`EvidenceLineageMultiplicityBench-v1` — P1**。1 source×N restatements、N independent sources×1 statement、model-to-model paraphrase、RAG snippet duplicates、shared-board relayを交差し、belief calibration / action threshold / source-count accuracyを測る。
7. **既存dailyで拾いにくい理由**  
   multi-agent consensus、RAG dedup、Bayesian evidence、social source monitoringは別分野で、statement countとsource countの混同は「会話が自然」なほど見えにくい。
8. **重要度**  
   **A update**。false corroborationがeffect authorizationやhigh-confidence memory promotionへ流れると、単なる重複token問題ではなくepistemic safety failureになる。

   `presentation_name` と `counterparty_principal_id` を分離する。relationship update / consent / trust / memory keyはstable principalへbindし、display-name changeはpresentation eventとして履歴化する。
5. **Kamimusuhiとの差分**  
   namespace-qualified identityは既出。fresh差分は **social display labelの自然さがrelationship principalの安定性を覆い隠す具体的Matrix fixture**。
6. **次に検証すべきこと**

## 5. B update — Replay Generations Must Not Inherit Obsolete Temporal Presentation Order

Primary:
- https://github.com/NousResearch/hermes-agent/issues/133880

Created: **2026-10-06 22:32 JST**。

1. **何が実証済みか**  
   32,056-rowの長期sessionで、`display_order` による位置とmonotonic row idによる位置が30,567 rowsでずれ、answerがpromptより前へ表示される等のchronology corruptionが発生した。報告ではreplay/reinsertされた新rowがold `display_identity` 経由で古いorderを引き継ぐことが原因とされ、visible generationにidentity collisionがない状態で `display_order=id` へ正規化するとdriftが解消した。
2. **何が提案・推測段階か**  
   row idを常にsemantic chronologyとみなすべきではない。edit/replacement/event-time/imported history等では別ordering axisが必要。
3. **Kamimusuhiのどこに関係するか**  
   Canonical Self History、episodic memory、narrative identity、replay / compaction、UI projection、temporal databases。
4. **借りられる設計・実装アイデア**  
   `event_time / commit_order / presentation_order / replacement_generation` を分離する。replayed contentのidentityを再利用しても、old presentation slotを暗黙継承せず、どのaxisをpreserveするrewriteなのかtyped operationで指定する。
5. **Kamimusuhiとの差分**  
   semantic ordering、event-time watermark、generation identityは既出。fresh差分は **replay identityを保つこととtemporal positionを保つことが別契約**であること。
6. **次に検証すべきこと**  
   **`ReplayGenerationTemporalOrderBench-v0` — P1**。compaction rewrite、edit、restore、duplicate suppression、late event、branch mergeを交差し、causal/chronological/narrative orderの不意な逆転を検出する。
7. **既存dailyで拾いにくい理由**  
   DB replayはstorage、timeline renderingはHCI、autobiographical chronologyはmemory研究として分離される。
8. **重要度**  
   **B update**。

## 結論

今回の中心は **「model-visibleな見え方」を、そのままidentity・self-state・evidence multiplicity・temporal truthへ昇格しないこと**。

- system promptに書かれているmemoryが、そのsession ownerのmemoryとは限らない。
- modelが「自分は正常」と言えることは、computational substrateが正常だという証拠にならない。
- 同じ観測が3回語られても3sourceにはならない。
- 同じdisplay nameでも同じ人とは限らず、renameしたから別人になったわけでもない。
- replayされた同じcontent identityが、同じ時間的位置を持つとは限らない。

Kamimusuhiでは、**materialization lineage / mechanically grounded embodiment / evidence source lineage / stable social principal / explicit temporal axes** をそれぞれ別のtyped stateとして保持する方が、長寿命個体のcontinuityを壊しにくい。
