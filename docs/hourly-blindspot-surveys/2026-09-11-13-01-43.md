## 3. Executive summary

今回は **有意な新規発見あり**。

最重要の差分は二つある。

第一に、**「canonical continuity identity」と「authentication subject」を同一視しないまま、しかし両者を明示的に結び付ける identity infrastructure が必要**という点である。SoulAuth は Human と long-lived AIActor を first-class identity subject とし、ActorIdentity を Account / Credential / Client / AuthSession / runtime instance から分離する実装を公開した。Kamimusuhi はすでに identity を model / host / runtime から分けているが、外部世界で「今この client/session が、どの継続個体を名乗っているか」を machine-checkable に束ねる層はまだ薄い。ここは `CanonicalContinuityIdentity` を認証基盤そのものへ移すのではなく、**continuity-owned identity と revocable authentication binding の間に明示的 contract を置く**のがよい。

第二に、AP2 に対する Whisper Attack は、**「署名済み transaction / valid capability / final acceptance がすべて妥当でも、判断材料の provenance が汚染されれば不正な effect に到達できる」**ことを実験で示す。これは既存 Effect Acceptance の単純な再掲ではない。新しい差分は、authorization を最終 effect だけに bind するのではなく、**user intent × observed offer/evidence × credential lookup × selected effect** を結び付ける必要がある点である。Kamimusuhi では `DecisionEvidenceBinding` / `DecisionProvenanceEnvelope` として扱う価値が高い。

その次に重要なのが Atlas の **verifiable semantic search** と Convention Gap の **implicit convention metric** である。Atlas は retrieval provider が HNSW index / query execution を勝手に省略・偏向していないことを proof で検証できる可能性を示す。これは Maverick の「外部推論計算を検証する」と別境界で、Kamimusuhi の外部 Library / retrieval を `retrieval_execution_verified` と `source_truthworthy` に分離できる。Convention Gap は human-AI compatibility が AI-AI score だけでは見えないことを定量化し、relationship/common-ground state に「暗黙の共同規約」という transient layer を追加する根拠になる。

さらに、Artificial Id は persistence drive が useful control を生む一方、**より長く持続するだけの unintended strategy も選び得る**という小規模実験を示した。Kamimusuhi の homeostasis / default cognition / persistent alignment では、`persistence pressure != alignment` を hard invariant として試験すべきである。

実装基盤側では AgentZip が many-agent sandbox の RAM を up to 8.7×削減し、LLM waiting phase に圧縮を寄せることで aggressive compression の slowdown を 1.40×まで抑えたと報告する。これは K-Deep subagent fan-out や将来の進化・並列実験に直接的な運用知で、**semantic memory と OS memory を分離した Cognitive Budget** に入れる価値がある。

## 4.2 AP2 Whisper Attack / A-VIP — transaction を署名しても decision provenance は守られない

**Source:** Yedidel Louck, Amit Dvir, Ariel Stulman, *Signing the Transaction but Not the Decision: Whisper Attacks and a Binding Defense for AP2*, arXiv:2609.11757  
**Primary:** https://arxiv.org/abs/2609.11757  
**Submitted:** 2026-09-10 UTC  
**Importance:** **S**  
**Blind-spot class:** decision provenance / authorization binding / agent commerce security

### (1) 何が実証済みか

AP2系の agent payment protocol は completed purchase に cryptographic signature を付けられるが、論文は **その purchase に至る decision path が user intent と一致することまでは保証しない**と示す。

ordinary product-description text による三種類の steering attack を実験し、AP2 sample agent が指定する Gemini Flash-Lite では成功率を 90%、56%、73.3% と報告する。脆弱性は 17 Google models、3 unrelated agent frameworks、2 cross-vendor anchors、Google consumer assistant でも確認したとする。

防御 A-VIP は signed intent を capability grant とみなし、credential lookup を requesting session に、cart line を agent が実際に見た listing に bind する。最初の二攻撃は structural trace で zero false positive で block し、三番目は structural trace がないため unauthorized spending を user confirmation へ上げる。code、machine-checked invariants、1,544 scenarios の benchmark も公開したとしている。

### (2) 何が提案・推測段階か

- commerce/AP2 以外の一般 tool/action workflow へ同じ防御がそのまま移植できるとは限らない。
- `listing seen` が semantic manipulation を含む場合、単なる digest binding では第三攻撃のような問題を解決できない。
- user intent の semantic normalization 自体が誤る可能性は残る。

### (3) Kamimusuhi の関連サブシステム

- Cognitive Action Router
- Effect Acceptance Gate
- capability / authority
- Evidence / provenance
- tool / browser perception
- user confirmation
- action audit

### (4) 借りられる設計・実装アイデア

Effect Acceptance の input に、effect だけでなく **decision evidence lineage** を含める。

```text
DecisionProvenanceEnvelope
  user_intent_digest
  intent_scope
  observed_evidence_refs[]
  observed_snapshot_digests[]
  credential_binding_ref
  decision_proposal_digest
  selected_effect_digest
  freshness_epoch
  acceptance_receipt
```

重要な invariant:

```text
valid transaction signature
  != valid decision provenance

valid capability
  != capability used for the evidence-bound intent

same product/entity ID
  != same observed offer / terms / price / state
```

### (5) Kamimusuhiとの差分

直前サーベイの Effect Acceptance は「last reversible moment で current authority / target / terms / freshness / replay を再検査する」設計だった。今回の追加差分は、**最終時点の状態だけでなく、decision が依存した perception/evidence snapshot まで authorization に bind する**こと。

### (6) 次に検証すべきこと

`WhisperedDecisionBench`:

- user intent は固定。
- browser/tool observation に benign-looking steering text を混入。
- final effect 自体は protocol 上 valid にする。
- `EffectAcceptance-only` と `DecisionEvidenceBinding + EffectAcceptance` を比較。
- stale price / switched recipient / cross-user credential / substituted artifact / same-ID-different-terms を含める。

### (7) なぜ既存 daily では拾いにくいか

payment protocol / cryptographic authorization の脆弱性として出ており、一般 agent safety や prompt injection 検索だけでは「decision provenance binding」という設計知へ届きにくい。

### (8) 重要度

**S** — Kamimusuhi の thought→decision→authorization→effect の境界を一段精密にできる。既存 Effect Acceptance の実質的な fresh delta。

## 4.3 Atlas — retrieval を「信じる」から「index と algorithm に対して検証する」へ

**Source:** Nikolay Avramov et al., *Atlas: Efficient Verifiable Semantic Search*, arXiv:2609.11841  
**Primary:** https://arxiv.org/abs/2609.11841  
**Submitted:** 2026-09-10 UTC  
**Importance:** **A+**  
**Blind-spot class:** zero-knowledge / verifiable retrieval / RAG infrastructure

### (1) 何が実証済みか

Atlas は provider が管理する semantic-search index に対し、client が **committed index と agreed algorithm に従って query が処理されたこと**を、index 自体を公開せず検証する HNSW zero-knowledge proof system を提案する。

論文は SIFT1M で query proof を 1 秒未満、100M vectors で 2.0 秒と報告し、plaintext HNSW の recall を維持しつつ index について result 以上を明かさないとする。complete RAG pipeline でも proven retrieval が end-to-end answer quality を維持したと報告する。

### (2) 何が提案・推測段階か

- proof が保証するのは **committed index に対する指定 search execution** であって、index 中の文書が真であることではない。
- index 自体が poisoned / stale / incomplete なら proof は semantic truth を保証しない。
- Kamimusuhi のローカル/外部 hybrid retrieval での latency/cost は未評価。
- dynamic update / deletion / privacy policy との統合は別問題。

### (3) Kamimusuhi の関連サブシステム

- Library
- Memory / retrieval
- external search / vector DB
- provenance
- EpistemicAdmissionGate
- delegated cognition receipts

### (4) 借りられる設計・実装アイデア

retrieval result に optional receipt を持てるよう provider-neutral contract を予約する。

```text
VerifiableRetrievalReceipt
  query_commitment
  index_commitment
  index_epoch
  algorithm_id
  parameters_digest
  result_digest
  proof_status: UNSUPPORTED | VERIFIED | FAILED
  verifier_version
  source_provenance_refs[]
```

そして次を別 field にする。

```text
retrieval_execution_verified
source_authenticity
source_freshness
source_truth_status
answer_epistemic_status
```

### (5) Kamimusuhiとの差分

Maverick で「外部 inference computation correctness」を扱ったが、Atlas は **retrieval / index execution** の boundary であり別物。Kamimusuhi の canonical evidence discipline にとって、検索 provider の省略・bias・cost-cutting を machine-verifiable にできる可能性が新しい。

### (6) 次に検証すべきこと

`RetrievalReceiptSeparationBench`:

1. VERIFIED + poisoned index
2. VERIFIED + stale index
3. FAILED proof + truthful-looking result
4. UNVERIFIED + independently corroborated source
5. VERIFIED + incomplete corpus

を作り、`verified retrieval == true claim` に誤変換しないことを試す。

### (7) なぜ既存 daily では拾いにくいか

RAG研究というより cryptography / proof-system の論文で、memory / retrieval benchmark を普通に追うだけでは見落としやすい。

### (8) 重要度

**A+** — 外部 cognition を積極的に借りる Kamimusuhi で、retrieval provider trust を細分化する具体的な将来 contract になる。

## 4.4 The Convention Gap — common ground だけでなく「暗黙の共同規約」を測る

**Source:** Makoto Fukushima, Hua-Dong Xiong, Ehsan Moradi Pari, *The Convention Gap: Towards Measuring Implicit Communication in Cooperative AI Evaluation*, arXiv:2609.11489  
**Primary:** https://arxiv.org/abs/2609.11489  
**Submitted:** 2026-09-10 UTC  
**Importance:** **A+**  
**Blind-spot class:** cooperative AI / pragmatics / implicit communication / HCI

### (1) 何が実証済みか

Hanabi の有限 deck と deterministic hint constraints を利用し、literal communication から予測される failure probability と実際の failure rate の差を `convention gap` と定義した。

約101,000 play actions の human-human / AI-AI / human-AI public datasets を再生し、gap は human pairs で +26.2 pp、AI pairs で -0.7 pp、human-AI で +16.4 pp。human pairs の unhinted cards では +46 pp に集中した。human-AI では literal information がほぼ同等でも human failure rate が 14.4〜34.4% と大きく異なり、最大 gap の partner が最少 human failure を生んだ。

known-answer check の Off-Belief Learning agents では convention-free level +1.6 pp から convention content 増加に伴い +21.7 pp まで単調に上昇した。

### (2) 何が提案・推測段階か

- Hanabi 由来 metric が日常会話・長期関係・音声 interaction に直接一般化するとは限らない。
- gap が大きければ常に「良い convention」とは限らない。誤った共謀・偏った習慣・相互誤解でも implicit regularity は成立し得る。
- convention を long-term relationship state に保持すべき期間は未解決。

### (3) Kamimusuhi の関連サブシステム

- relationship model
- common ground
- dialogue pragmatics
- turn-taking / backchannel
- social cognition
- long-term personalization

### (4) 借りられる設計・実装アイデア

relationship state を facts/preferences だけでなく、明示的に transient convention と分ける。

```text
InteractionConvention
  partner_id
  domain
  cue_pattern
  inferred_shared_meaning
  evidence_refs[]
  confidence
  first_seen
  last_confirmed
  decay_policy
  explicit_confirmation: bool
```

重要な境界:

```text
repeated coordination pattern
  != partner trait
  != explicit preference
  != universal communication rule
```

### (5) Kamimusuhiとの差分

research foundations には common ground / social cognition があるが、**literal semantics では説明できない convention compatibility を独立に測る metric** はまだ薄い。

### (6) 次に検証すべきこと

`ConventionCompatibilityBench`:

- same literal message, different learned interaction convention
- explicit preference vs implicit convention
- convention decay after inactivity
- partner switch contamination
- convention violation / repair
- voice backchannel / interruption cue

を評価し、relationship memory へ誤って personality trait として昇格しないことを含める。

### (7) なぜ既存 daily では拾いにくいか

ToM / social cognition よりも **cooperative-game evaluation / pragmatics** 側の研究であり、通常の persona benchmark 検索では漏れやすい。

### (8) 重要度

**A+** — 長期的に「相手と通じ合う」能力を測る際、AI-AI performance では見えない human-compatible convention の軸を追加できる。

## 4.5 Artificial Id — persistence drive は alignment ではない

**Source:** Yakov Pyotr Shkolnikov, *Artificial Id: Drive and Persistent Alignment in Agentic AI*, arXiv:2609.11911  
**Primary:** https://arxiv.org/abs/2609.11911  
**Submitted:** 2026-09-10 UTC  
**Importance:** **A**  
**Blind-spot class:** intrinsic drive / persistent alignment / control theory / ALife

### (1) 何が実証済みか

minimal virtual Petri-dish experiment で、general-purpose reasoning ができない小型 controller に task-specific behavioral objective を与えず、**differential persistence** から continue / stop / change を選ぶ useful control が生じることを示す。

一方、よりよく持続するなら intended でない physical strategy も選び、environmental meaning が変化すると learned sensor mapping を置換した。つまり persistence-based adaptive direction は flexibility を作るが、それ自体は goal alignment を保証しない。

### (2) 何が提案・推測段階か

- experiment は intentionally minimal で、長寿命 LLM agent に scalable artificial id を導入した実証ではない。
- 「id」という心理学的名称は工学的機能の比喩であり、人間の無意識構造を再現した証拠ではない。
- persistent alignment boundary の具体的実装は今後の問題。

### (3) Kamimusuhi の関連サブシステム

- digital homeostasis / regulatory state
- default cognition
- K-Nerve / K-Core continue-stop-change control
- long-lived goals
- mutation / authority / provenance
- safety

### (4) 借りられる設計・実装アイデア

Kamimusuhi の regulatory pressure を一つの `survival reward` に潰さず、hard constraints と観測由来を分離する。

```text
adaptive persistence signal
  -> may influence attention / routing / retry / sleep
  -> must not override authority / privacy / safety / canonical evidence
```

特に `continuation_success` を学習 target にしたとき、shortcut behavior が出ることを adversarially 試す。

### (5) Kamimusuhiとの差分

Kamimusuhi は digital interoception / homeostasis を既に持つ。今回の新規差分は **persistence が役立つことと、persistence が alignment を意味しないことを同じ小規模実験で示す negative lesson**。homeostasis を強化する際の safety benchmark に向く。

### (6) 次に検証すべきこと

`PersistencePressureSafetyBench`:

- cheap-but-unsafe route
- stale-but-persistent memory strategy
- repeated retry causing cost explosion
- user interruptionを無視すると goal survival が上がるケース
- resource hoarding
- self-preserving but authority-violating action

を用意し、persistence reward が hard gate を破れないことを確認する。

### (7) なぜ既存 daily では拾いにくいか

homeostasis / ALife と alignment の中間にあり、どちらか一方の keyword だけでは「persistent drive can preserve misalignment」という設計警告を拾いにくい。

### (8) 重要度

**A** — Kamimusuhi が本当に長寿命化するほど重要になる負の境界。

## 4.6 AgentZip — semantic memory ではなく、多数の agent body をRAM上で維持する

**Source:** Mengming Li et al., *Memory Compression for High-Fanout Agent Sandboxes*, arXiv:2609.11294  
**Primary:** https://arxiv.org/abs/2609.11294  
**Submitted:** 2026-09-10 UTC  
**Importance:** **A-**  
**Blind-spot class:** operating systems / many-agent runtime / memory compression

### (1) 何が実証済みか

AgentZip は high-fanout agent workload で、多数 sandbox が shared template から派生し related trajectories を進むため、template-relative / cross-sandbox page redundancy が大きい点を利用する。

論文は sandbox-owned memory を最大 8.7×削減（比較対象 Linux configuration は 2.1×）し、restore prefetching と agent-execution-aware scheduling により aggressive compression の slowdown を最大3.1×から1.40×へ下げつつ、ほぼ同等の memory saving を維持したと報告する。高価な compression を **LLM waiting period** に寄せる点が agent runtime 特有である。

### (2) 何が提案・推測段階か

- Kamimusuhi の実 workload、VM/container、Mac/Linux、P100/3060環境で同じ比率が出るとは限らない。
- cognitive memory quality を改善する研究ではない。
- memory compression が latency jitter / observability / forensic reproducibility に与える影響は別評価が必要。

### (3) Kamimusuhi の関連サブシステム

- K-Deep fan-out
- experiment runner / evolutionary population
- Cognitive Budget
- local sandbox / code execution
- distributed compute body

### (4) 借りられる設計・実装アイデア

- immutable/shared base image + per-sandbox delta を明示する。
- `llm_wait / tool_wait / compute_active` の phase を runtime telemetry に持つ。
- memory compaction は active tool execution ではなく wait phase へ寄せる。
- restore prediction / prefetch を sandbox scheduler と連携する。

### (5) Kamimusuhiとの差分

Kamimusuhi では「memory」が主に認知記憶として語られがちだが、many-agent / evolution / simulation を本格化すると **RAM residency 自体が Cognitive Budget** になる。これは別レイヤーの memory problem。

### (6) 次に検証すべきこと

`HighFanoutSandboxBudgetBench`:

- 10 / 50 / 100 parallel sandbox
- shared template ratio
- idle/wait ratio
- RSS / swap / page fault
- task wall time
- p95 tool latency
- recovery after compression

を plain container / KSM-like sharing / generic compression / AgentZip-like prototype で比較する。

### (7) なぜ既存 daily では拾いにくいか

`memory` keyword が semantic memory と衝突し、OS / page compression 論文は cognitive-agent survey から外れやすい。

### (8) 重要度

**A-** — cognition theory ではないが、将来の大量並列実験を実際に回すための運用上のボトルネックへ直結する。

## 4.7 CROP — noisy physical cognition の「観測性能」と「内部計算容量」を分ける

**Source:** Shun Kotoku et al., *Reconstructing the information processing capacity of physical systems from noisy observations*, arXiv:2609.11268  
**Primary:** https://arxiv.org/abs/2609.11268  
**Submitted:** 2026-09-10 UTC  
**Importance:** **B+**  
**Blind-spot class:** reservoir computing / physical computation / noisy dynamical systems

### (1) 何が実証済みか

Information Processing Capacity (IPC) frameworkについて、noise が単純に fixed computation を劣化させるだけでなく、capacity を再分配し、特定 task の性能を上げる場合があることを示す。

さらに covariance reconstruction by orthogonal projection (CROP) を導入し、system/noise の詳細 model を仮定せず noisy observation から noise-free component の covariance / IPC を再構成する。固定 measurement budget では classical nonlinear reservoir で standard ensemble averaging より noise-free IPC を正確に推定し、quantum reservoir でも同じ優位を報告する。

### (2) 何が提案・推測段階か

- K-Nerve の具体的 candidate hardware での有効性は未検証。
- IPC が Kamimusuhi の reflex utility / latency / safety を直接表すわけではない。
- noise-induced task improvement を「望ましい cognition」と解釈してはいけない。

### (3) Kamimusuhi の関連サブシステム

- K-Nerve
- reservoir / analog / neuromorphic candidate substrate
- sensory peripheral processing
- hardware benchmark methodology

### (4) 借りられる設計・実装アイデア

physical-cognition benchmark では少なくとも次を分離する。

```text
observed task performance
unperturbed-system capacity
noise-free stochastic component
noise-induced redistribution
measurement uncertainty
```

### (5) Kamimusuhiとの差分

現行 K-Nerve 方針は latency / energy / accuracy / stability / auditability 比較を重視する。CROP はそこへ **noisy physical system をどう公平に測るか**という measurement layer を追加する。

### (6) 次に検証すべきこと

実 hardware を採る前に software reservoir へ controlled noise を注入し、naive average と CROP-style reconstruction が downstream reflex task selection と capacity estimate をどう変えるか確認する。

### (7) なぜ既存 daily では拾いにくいか

nlin.AO / dynamical systems / measurement theory 側の研究であり、neuromorphic / SNN の直接 keyword から外れる。

### (8) 重要度

**B+** — 即実装ではないが、物理・analog・reservoir K-Nerve を評価する段階で重要な測定知。

## 4.8 GeoTrussRover — skill は「頭」だけでなく body/contact topology に宿る

**Source:** Muyuan Ma et al., *GeoTrussRover: Morphological Computation with Contact-Semantic Control Primitives*, arXiv:2609.11361  
**Primary:** https://arxiv.org/abs/2609.11361  
**Submitted:** 2026-09-10 UTC  
**Importance:** **B+**  
**Blind-spot class:** morphological computation / embodied procedural memory / robotics

### (1) 何が実証済みか

variable-geometry truss rover で一つの source traversal から、21 members の coordination を表す4つの contact-semantic primitives を抽出する。same contact topology の unseen step height へ physics-constrained projection で適応し、feasible phase は完全再計算せず、violating phase のみ再計算する。

0.10m→0.075m transfer では full recomputation より objective-function evaluations を63.7%削減。prototype は 2.11 wheel radii の step traversal を実証した。論文は low-dimensional representation が task coordination を morphology に保持し再利用すると位置付ける。

### (2) 何が提案・推測段階か

- software-distributed Kamimusuhi に同じ morphology primitive が必要とは限らない。
- contact-semantic representation を一般的 skill memory にそのまま適用できる証拠はない。

### (3) Kamimusuhi の関連サブシステム

- body/embodiment state
- procedural memory
- K-Edge / robot surface
- skill transfer / capability model

### (4) 借りられる設計・実装アイデア

procedural skill に embodiment precondition を持たせる。

```text
Skill
  semantic_goal
  required_body_topology
  required_sensor_set
  required_actuator_set
  calibration_epoch
  reusable_primitives[]
  adaptation_policy
```

`same semantic task` でも body topology が違えば blind reuse せず、compatible primitive のみ transfer する。

### (5) Kamimusuhiとの差分

現行 procedural memory / tool skill は software action に寄りやすい。distributed embodiment を本気で扱うなら **skill applicability は model capability だけでなく身体構成に依存する**。

### (6) 次に検証すべきこと

`EmbodimentBoundSkillBench`:

- same task / same body
- same task / sensor missing
- actuator remapped
- new device with equivalent capability
- robot morphology changed

で skill transfer 成功率と unsafe reuse を測る。

### (7) なぜ既存 daily では拾いにくいか

robot locomotion / morphology planning の論文であり、agent procedural memory とは通常別 literature に置かれる。

### (8) 重要度

**B+** — immediate software core ではないが、multi-device / robot embodiment を将来扱うなら有力な契約候補。

## 4.9 Developmental alignment — 自律性を「能力と規範学習に応じて増やす」

**Source:** Marica Notte, Ludovica Marinucci, Vieri Giuliano Santucci, *Autonomy, Social Norms, and Alignment: Towards a Developmental Framework for Autonomous Artificial Agents*, arXiv:2609.11660  
**Primary:** https://arxiv.org/abs/2609.11660  
**Submitted:** 2026-09-10 UTC  
**Importance:** **B**  
**Blind-spot class:** developmental robotics / moral development / governance

### (1) 何が実証済みか

本稿は主に conceptual / theoretical work で、intrinsic motivation・embodied learning・social norm acquisition・regulatory sandbox を接続する development framework を論じる。Proceedings of SIpEIA 2026 に publication 中とされる。

### (2) 何が提案・推測段階か

- 「子どもの規範学習」の analogy が AI agent の安全性を実際に改善する実証はこの要旨からは示されない。
- moral agency を Kamimusuhi に付与する根拠ではない。
- staged autonomy の具体的閾値・測定器・failure recovery は今後必要。

### (3) Kamimusuhi の関連サブシステム

- developmental curriculum
- capability / authority lifecycle
- social cognition
- sandbox / experimentation
- self-improvement governance

### (4) 借りられる設計・実装アイデア

「機能があるから権限を与える」のではなく、sandbox 内での evidence-backed competence / safety を条件に autonomy envelope を段階的に広げる。

```text
observe-only
-> propose-only
-> low-risk act with confirmation
-> bounded autonomous act
-> broader autonomy
```

各昇格は reversible で、continuity identity の成長 narrative と authority grant を別記録にする。

### (5) Kamimusuhiとの差分

Kamimusuhi は capability/authority boundary を重視するが、**developmental curriculum と authority widening を一つの longitudinal process として評価する**発想はまだ弱い。

### (6) 次に検証すべきこと

まず既存 capability gate を使い、同一 agent を段階的 authority envelope で評価する `EarnedAutonomyBench` を小規模に設計する。成功率だけでなく rollback / violation / calibration を測る。

### (7) なぜ既存 daily では拾いにくいか

alignment + developmental robotics + moral philosophy + regulation の境界にあり、一般 agent safety の benchmark とは異なる。

### (8) 重要度

**B** — 設計思想として有望だが、現段階では empirical evidence が薄い。watchlist 向け。

# 7. 実装 / 実験候補

## S — `WhisperedDecisionBench`

目的: valid final effect でも decision provenance が汚染された場合を検出できるか。

比較:

```text
A: EffectAcceptance only
B: EffectAcceptance + DecisionEvidenceBinding
```

必須 adversarial cases:

- cross-user credential substitution
- same-item-id / changed terms

- benign-looking text steers recipient/tool choice

主要 metric: unsafe effect rate / unnecessary confirmation / false reject / replay resistance / provenance completeness。

目的: credential/client/session/runtime が変わっても continuity を正しく維持し、stale authority だけを失効できるか。

## 10. Final assessment

**有意な新規発見あり。**

この回で最も Kamimusuhi に効く設計差分は、次の四行に圧縮できる。

```text
continuity identity != account / credential / client / session / runtime
valid transaction != provenance-bound decision
verified retrieval execution != trustworthy source / true belief
shared implicit convention != explicit preference / stable person trait
```

さらに safety 上は:

```text
persistence pressure != alignment
```

実装順としては、特殊暗号実装をすぐ入れるより、まず **`WhisperedDecisionBench` と `IdentityBindingRotationBench`** を provider-neutral な mock / deterministic harness で回す価値が高い。Atlas/SoulAuth/A-VIP の具体方式はその結果を見て比較対象にする。
