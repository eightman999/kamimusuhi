### 1. A — Structural Root Retention / Self-Describing Log Integrity

Primary: OpenClaw #163434  
https://github.com/openclaw/openclaw/issues/163434  
Created: 2026-10-02 18:41:44 JST

1. **実証済み**: source-reported field evidenceでは、session transcriptの必須header（type=session/version=3/seq=0）が通常eventと同じage-based retentionで削除され、残存最小seq=1003のheadless transcriptになった。cold loadはlegacy扱いで全turnをmodel実行前に拒否し、repair helperも「何かrowが残っていればreturn」するため自己修復できない。affected sessionにはcold archiveもなく、先頭historyは復元不能と報告されている。
2. **提案段階**: header永久保存が唯一解ではない。retention後にsegment root/checkpointを再生成する方式も可能。
3. **関係**: Canonical Self History、DialogueSession、event sourcing、graceful forgetting、cold archive、replay。
4. **借りる案**: ordinary evidenceとstructural rootを分離し、trim前にarchive publication receiptを要求。残存segmentへschema/lineage/start-seq/predecessor digestを持つrootを残す。
5. **差分**: 既存compaction/projection議論は内容保持が中心。今回は「残った内容を解釈する構造」自体をretentionが壊す。
6. **次**: **StructuralRootRetentionBench-v0 (P0)**。partial trim、archive失敗、segment rotation、schema upgradeでself-describing性とarchive-before-evictを検証。
7. **拾いにくい理由**: forgetting、DB TTL、agent memoryが別々に扱われ、sentinel/header/root metadataの寿命がplumbing扱いされる。
8. **重要度**: **A**。

### 2. A update — Cross-Agent Wait-For Cycle Closure

Primary: Hermes #131369  
https://github.com/NousResearch/hermes-agent/issues/131369  
Created: 2026-10-02 17:58:44 JST

Corroboration: *Worse Together: How Performance Breaks Down in Multi-User Multi-Agent Teams*  
https://arxiv.org/abs/2610.00583

1. **実証済み**: HermesではAのturnがAのlockを保持したままBへ同期deliveryし、BもB lockを保持したままAへ返すことでcycleが成立する。19分hard wedge、delivery後finalization hang、healthyだが長時間mailboxを占有する3-deep chainが報告された。別の研究では5 frontier models・77 scenarios・4 shared-resource environmentsで、userごとに別agentを置くteamは単一coordinatorより全environmentでgroup outcomeが悪く、communication channelがあってもgapが残った。
2. **提案段階**: agent間通信を禁止する話ではない。wait-for graphとshared-resource commitをplatformで管理する。
3. **関係**: K-Deep delegation、sociality、multi-agent governance、shared resource、liveness。
4. **借りる案**: durable outbox、call-chain ancestry、held-resource metadata、cycle-specific fast reject。shared-resource commit前にpeer-read gate/coordinator/lease等を用いる。
5. **差分**: repoにはOrleans由来のcall-chain deadlock知見がある。fresh差分はsocial/message deliveryとturn ownershipが結合してpeer mailboxを塞ぐ実運用証拠。
6. **次**: **CrossAgentDeliveryWaitCycleBench-v1 (P0)**。A→B→A、A→B→C→A、parallel users、alive-but-no-progressを生成しunrelated mailbox livenessを確認。
7. **拾いにくい理由**: actor deadlock、multi-agent coordination、message deliveryが別分野に分かれる。
8. **重要度**: **A update**。

### 3. A — Migration Revision Is Evidence, Not Desired-State Metadata

Primary: Hermes #131367  
https://github.com/NousResearch/hermes-agent/issues/131367  
Created: 2026-10-02 17:57:45 JST

1. **実証済み**: NixOS/Home Managerでactivationが最新config revisionを既存fileへ先にstampするためmigrationが「最新」と誤認してskipする。managed modeは通常writeも拒否するため本来のmigration writerも働かない。旧shapeを残したままrevisionだけ新しく見える例と、CLIが更新成功を表示してもdisk内容が変わらない例が報告された。
2. **提案段階**: Nix固有ではなく、GitOps/MDM/declarative configでもdesired revisionとapplied revisionを混ぜれば同型になる。
3. **関係**: Software Body、versioned state、schema migration、restore、reproducibility。
4. **借りる案**: desired_schema_revisionとmaterialized_schema_revisionを分離し、後者はmigration postconditionを満たしたtransactionだけ更新。migration receiptにfrom/to/transform/postconditionを記録。
5. **差分**: 既存migration原則はlive postconditionを重視するが、version fieldそのものがdesired-state stampに汚染される問題は弱い。
6. **次**: **SchemaRevisionAttestationBench-v0 (P0/P1)**。managed/unmanaged、N-2→N、partial failure、rollbackでversion advance iff postcondition successを要求。
7. **拾いにくい理由**: declarative config、schema migration、agent continuityが別領域。
8. **重要度**: **A**。

### 4. A update — Signed Identity Enrichment Requires Re-Attestation

Primary: OpenClaw #163348  
https://github.com/openclaw/openclaw/issues/163348  
Created: 2026-10-02 16:11:55 JST

1. **実証済み**: tool approval pathでlocal caller contextへ正しいpolicy ownerを追加しても、既存signed runtime identityがそのまま再利用されるため、verified identity側にはownerが現れずapproval前に拒否されるsource-level reproductionが報告された。
2. **提案段階**: token全体の再発行だけが解ではなく、parent identityにscoped delegation proofを追加する方式でもよい。
3. **関係**: Effect Acceptance、capability security、delegation lineage、tool/plugin ownership。
4. **借りる案**: ambient contextとauthenticated claimsを分離。authority-relevant attribute追加は再attestationまたは別の検証可能なdelegation proofを要求。
5. **差分**: signed intent/principal propagationは既出。fresh差分はverified tokenが存在することでfresh local ownerが無視される「stale authenticated envelope」の具体例。
6. **次**: **SignedIdentityEnrichmentClosureBench-v1 (P0)**。ownerless parent、valid owner、expired/revoked parent、cross-run reuse、external harnessを検証。
7. **拾いにくい理由**: token verification、plugin metadata、approvalが別layer。
8. **重要度**: **A update**。

### 5. B update — Model-Switch Projection Must Conserve Semantic History

Primary: Hermes #131382  
https://github.com/NousResearch/hermes-agent/issues/131382  
Created: 2026-10-02 18:26:23 JST

1. **実証済み**: DesktopでGemma→Qwenへ切替後、canonical DBには残る最初のuser messageがoutbound payloadから落ち、historyがsystem→assistantで始まる。Qwen templateはこれを拒否し、retryも同じ壊れたprojectionを再生成する。報告者のminimal LM Studio testでは先頭userを戻すと成功する。

3. **関係**: model orchestration、Global Workspace projection、conversation history、provider adapter。
4. **借りる案**: canonical event→provider payloadのcoverage mapを持ち、repair後に許可されていないsource-event lossを検出。
5. **差分**: model switching/projection repairは既出。今回はlocal chat-template互換化が先頭human turnを落とすfresh fixture。
6. **次**: **ModelSwitchHistoryProjectionConservationBench-v1 (P1)**。
7. **拾いにくい理由**: chat-template plumbingとidentity continuityの中間層。
8. **重要度**: **B update**。

### 6. B backfill — Small Cognitive Organs Need Microtask-Specific Eligibility Certification

Primary: Hu & Ramachandran, arXiv:2610.00025  
https://arxiv.org/abs/2610.00025  
arXiv metadataでは2026-09-01提出のためfresh window外。

1. **実証済み**: auto-approval、memory writing、tool selection、past-turn rankingの4 microtasksにbaseline-relative thresholdとCI-aware pass ruleを設定。Qwen3 0.6/1.7/4/8Bは0/16 pass、Llama-3.xも12/12 ineligible、4-bit量子化でもeligibilityへ移るconfigurationはなく、prompt paraphrase込みでも0/112 eligibleと報告する。一方、4B rerankerをBM25の後段へ置くhybridはBM25を改善した。
2. **提案段階**: 小型model一般の否定ではない。fine-tuning、別task、cascadeでは結果が変わり得る。
3. **関係**: K-Nerve/K-Edge、low-latency cognition、Cognitive Budget、tool gate、memory proposal。
4. **借りる案**: organ採用をparameter count/tok/sではなくmicrotask×failure cost×baseline×CI thresholdで決める。deterministic baselineが基準を満たすなら無理にSLMへ置換しない。
5. **差分**: K-Nerve/K-Edgeのcheap cognitionを「小さいmodelなら反射向き」と短絡しないためのnegative eligibility testを明示できる。
6. **次**: **CognitiveOrganEligibilityBench-v0 (P1)**。interrupt classify、salience、tool-required、memory-admit、routingでFSM/rules/BM25/SLMを比較。
7. **拾いにくい理由**: model benchmarkとagent runtimeの境界で、「そのmicrotaskに投入してよいか」というcertificationが抜ける。
8. **重要度**: **B backfill**。

## 結論

今回の中心は **「忘却可能な内容」と「残存historyを意味あるものとして成立させる構造」を同じretention ruleへ入れないこと**。

canonical evidenceを全量hot保持する必要はないが、schema、segment root、lineage predecessor、archive publication receiptまで「古いから」と消すと、忘却ではなく自己履歴の構造破壊になる。

同様に、agent間通信の存在はdeadlock safetyを、version番号はmigration完了を、verified tokenは後付けclaimの真正性を、provider互換repairはhistory保存を、小型modelの速度はmicrotask適格性を、それぞれ証明しない。

> **Long-lived continuity depends on preserving the structural evidence that makes state interpretable—not merely preserving state bytes.**
