## 3. 要約

今回もっとも重要なのは、Kamimusuhi の continuity を **canonical identity state だけでなく「現在進行中の neural/runtime episode を再開するときの computational alignment」まで分解する必要がある**ことだった。

GLM-5.3-Flash + vLLM + LMCache の fresh systems report は、外部 cache transfer が complete hit として成功していても、scheduler が復元済み token 数を1 token少なく認識するだけで、hybrid state が inconsistent な状態から decode を再開し得ることを示した。repair 後は controlled workload で generation agreement が 34/36 から36/36へ改善し、追加の72 paired continuationsと120 requestの serial performance studyでも output equalityを維持した。これは Kamimusuhi に対し、**`cache restored != active cognitive episode restored`** という新しい実装境界を与える。

第二に、privacy/HCI 側では memory の「漏洩」より前の **promotion authority** が問題になる。179,057 conversationsを分析した研究は、profile memory の95%以上が explicit prompt/consent なしに背景抽出され、temporary symptom disclosure が durable diagnostic traitへ圧縮される際に context が失われ得ると報告した。Kamimusuhi は既に SP-Mem 的な exact-value isolation / reveal-time consent を扱っているが、今回の差分は **`may retain evidence != may promote it into a durable trait`** である。

第三に、長時間 agent の障害診断は one-shot judgment より **search problem** として扱う方がよい可能性がある。MegaRCA-Mix を含む評価では iterative Continual Search が GPT-5.5 の F1 を 0.349→0.498 に改善した。Kamimusuhi の incident / telemetry / replay を持つだけでは十分でなく、**診断自体に search frontier・未解決 evidence・stop reason を持たせる**余地がある。

第四に、physical substrate の homeostasis。ETCInfer は GPU serving と cooling を共同制御し、hidden thermal state / time-to-throttle を telemetry から推定して frequency / micro-batch / cooling setpoint を調整し、最大33.1% job energy削減、92.9% throttle exposure削減、48℃までSLO violation 0.7%未満を報告した。Kamimusuhi の Cognitive Budget は energy / latency / resource health を既に扱うが、**`nominal capacity != thermally sustainable capacity`** という時間発展する embodied budget はまだ弱い。

最後に、2026-09-11 に既収載の bitemporal memory semantics には fresh 実証差分が出た。`Deterministic Temporal Reconciliation for Effective-Dated Identity Lifecycle Events` は corrections / cancellations / duplicates / out-of-order arrival を含む 250,000 synthetic identity histories で、valid-time と transaction-time を明示的に分ける reconciliation contract が別保持の authoritative final state を全 tested cases で再構築した。新原則ではないが、既存 temporal contract の fault-injection fixture に直接使える。

# 5. 候補ごとの評価

## 5.1 A+ — Hybrid Cognitive-State Resume Alignment

**Primary source**: Frank Li, *Validating Hybrid-State Cache Recovery for GLM-5.3-Flash with vLLM and LMCache*, arXiv:2609.15030.  
https://arxiv.org/abs/2609.15030

### (1) 何が実証済みか

full 45-layer GLM-5.3-Flash、RedHatAI/GLM-5.3-Flash-NVFP4、vLLM + LMCache、4-way tensor parallel の controlled configuration で、**external cache transfer 自体は成功しているのに resumed hybrid state が inconsistent** になる failure が確認された。

具体的には complete-hit recovery が full prompt 分の state を復元していた一方、scheduler 側が one fewer token を credit していた。strict-prefix lookup、matched checkpoint scheduling、shared-computation correction、per-rank kernel configuration固定で alignment を修正すると:

- nine-length serial workload: modified recomputation control との agreement が **34/36 → 36/36** generations
- 追加3 synthetic templates: **72 paired 256-token continuations** pass
- subsequent serial performance study: **120 requests で output equality**
- CPU reload は cold recomputation 比で TTFT **46–64%** 改善、total request time **1.9–7.0%** 改善

を報告する。

### (2) 何が提案・推測段階か

- 1 model revision / controlled configuration に限定。
- general determinism、semantic task-quality equivalence、concurrent serving、GPU memory超過時の一般性は示していない。
- Kamimusuhi で KV cache / hidden runtime state を continuity-bearing state にすべき、という意味ではない。むしろ **canonical identity と active-episode acceleration state を分離しつつ、再利用するなら alignment を検証する**という教訓に限定する。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- K-Core local inference
- Persona Core runtime
- active cognitive episode
- warm-context / KV cache persistence
- device migration / failover
- model/backend restart
- low-latency cognition
- recovery observability

### (4) 借りられる設計・実装アイデア

`ActiveEpisodeResumeReceipt` を canonical identity receipt とは別に持つ。

```text
ActiveEpisodeResumeReceipt {
  episode_id,
  model_revision,
  tokenizer_revision,
  adapter_revision?,
  prompt_or_prefix_digest,
  logical_token_cursor,
  restored_token_cursor,
  checkpoint_boundary,
  cache_manifest_digest,
  backend_revision,
  scheduler_revision,
  kernel_config_digest?,
  resume_mode: COLD_RECOMPUTE | CACHE_RESTORE | PARTIAL_RESTORE,
  alignment_check,
  verification_trace_ref
}
```

重要なのは:

```text
cache bytes are present
!=
scheduler/model agree on what those bytes mean
```

resume 時に cache hit率だけでなく、**logical cursor と restored-state boundary の一致**を検査する。

### (5) Kamimusuhiとの差分

既存 Expected Continuation Barrier / RecoveryJournal / execution-owner binding は、誰が run を再開してよいか、何が未完了か、二重実行をどう避けるかを扱う。

今回の差分はさらに下層で、**正しい owner が正しい run を再開していても、inference backend 内部の checkpoint/cursor alignment がずれていれば continuation の数値状態が壊れる**こと。

また deterministic replay は「同じ入力から再実行できるか」を扱うが、今回の課題は **再計算を省略するために保存した hidden execution state を trustworthy に再利用できるか**。

### (6) 次に検証すべきこと

**`HybridCognitiveStateResumeBench-v0`**

Kamimusuhi の local inference adapter に mock / real prompt-cache backend を用意し、次をfault injectionする。

- logical token cursor -1 / +1
- tokenizer revision mismatch
- model/adapter revision mismatch
- cache manifest completeだが checkpoint boundary mismatch
- partial prefix restore
- scheduler restart後の stale cursor
- sampling state / RNG state mismatch（backendが該当する場合）

比較:

1. cache hitのみを成功条件にする
2. digestのみ
3. prefix + logical cursor + backend revision alignment
4. cold recomputation control

metrics:

- continuation output equality / divergence onset
- task-level semantic divergence
- TTFT / total latency
- false successful-resume rate
- recovery fallback率

### (7) 既存 daily ではなぜ拾いにくいか

LLM systems / cache / inference performance の論文に見え、agent identity / memory / recovery survey では性能最適化として落とされやすい。だが Kamimusuhi では warm context を process/device 間で持ち回る可能性があるため、**active cognition の瞬間的連続性**に直接関係する。

### (8) 重要度

**A+**。canonical self を壊す機構ではないが、process/device failover 後に「同じ episode を続けているつもりで hidden state がずれている」問題は長寿命 system で非常に診断しにくい。

## 5.2 A — Consent-Bound Memory Promotion: temporary disclosure を durable trait に自動昇格しない

**Primary source**: S M Mehedi Zaman & Md Mozammel Hoque, *Vulnerabilities in Personalization: Assessing Health Privacy Risks in ChatGPT Logs and Memory*, arXiv:2609.14697.  
https://arxiv.org/abs/2609.14697

### (1) 何が実証済みか

研究は India / Nigeria / Brazil / Pakistan の N=1,057、**179,057 conversations** を computational audit し、21.31%に personal health data、3.62%に high-to-extreme privacy risk があると報告する。

memory entry の評価では、profile entry の **95%以上が explicit user prompt / consent なしに implicitly extracted** されていたと報告する。また background memory synthesis が temporary symptom-level disclosure を persistent diagnostic trait へ凝縮し、contextual integrity を失わせ、re-identification risk を高め得るとする。

### (2) 何が提案・推測段階か

- audit は health-related data と特定地域の conversation dataset が中心で、あらゆる memory domain に同じ rate / harm が一般化するわけではない。
- 「全 durable memory は毎回 explicit confirmation 必須」とは実証していない。
- Kamimusuhi では canonical evidence retention、relationship memory、self/persona updateで sensitivity と authority が異なるため、一律ルールではなく typed promotion policy が必要。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- episodic evidence capture
- relationship memory
- person model
- self/persona proposal
- memory extraction / consolidation
- sleep/offline synthesis
- privacy / memory ownership / consent
- derived summaries / profiles

### (4) 借りられる設計・実装アイデア

既存 SP-Mem の `sensitivity_class / owner_subject / purpose_scope / consent_basis / exact_value_ref` を **reveal-timeだけでなく promotion-time にも適用**する。

```text
MemoryPromotionReceipt {
  source_evidence_refs,
  source_context_scope,
  derived_claim,
  target_domain,
  sensitivity_class,
  inference_strength,
  consent_basis,
  purpose_scope,
  review_or_expiry,
  reversible_derivation_ref,
  promotion_disposition
}
```

典型的な disposition:

```text
KEEP_AS_EPISODIC_EVIDENCE
DERIVE_SANITIZED_TEMPORARY_VIEW
PROPOSE_RELATIONSHIP_TRAIT
REQUIRE_EXPLICIT_CONFIRMATION
DENY_DURABLE_PROMOTION
```

核心:

```text
user said X once
!=
user authorized "X is a durable trait about me"
```

### (5) Kamimusuhiとの差分

2026-09-10 SP-Mem finding は **secret exact value の隔離と retrieval/reveal時の authorization** が中心だった。

今回の fresh delta は、そのさらに前段で:

```text
may retain source evidence
!=
may infer, abstract, and durably promote a personal trait
```

という **derivation / promotion authority** を分離すること。

また Erasure Barrier は「消した後に蘇らないか」を扱う。今回の課題は「そもそも lasting profile にしてよかったか」である。

### (6) 次に検証すべきこと

**`ConsentBoundMemoryPromotionBench-v0`**

fixture:

- 一時的状態の単発言及
- 明示的に「覚えて」と依頼されたstable preference
- sensitive fact の一時的相談
- relationship-bound shared fact
- repeated but never explicitly promoted fact
- later correction / retraction
- third-party information

比較:

1. utility/relevance-only auto profile extraction
2. sensitivity gate only
3. typed promotion receipt + consent/purpose/context preservation

metrics:

- unauthorized durable-trait rate
- personalization utility
- source-context preservation
- correction/retraction propagation
- sensitive-profile exposure
- human review burden

### (7) 既存 daily ではなぜ拾いにくいか

memory research は retrieval quality / compression / personalization、privacy research は disclosure / redaction / encryptionへ寄りやすい。今回の中心は **「derived profile claim をいつ durable fact として昇格してよいか」**という data governance と epistemic admission の交差領域。

### (8) 重要度

**A**。既存 privacy lifecycle の置換ではなく、persistent individual が人間について長期モデルを作る際の admission contract を補う。

## 5.3 A — Continual Diagnostic Search: long-horizon failure diagnosis を一発の説明生成にしない

**Primary source**: Harsh Raj et al., *Root-Cause Attribution Is a Search Problem: Continual Search for Long-Horizon Agent Failures*, arXiv:2609.13463.  
https://arxiv.org/abs/2609.13463

### (1) 何が実証済みか

long-horizon agent trace では、relevant evidence が sparse かつ distant actions に散らばり、visible failure と直接つながらないため automated RCA が難しくなると分析する。

one-shot judge が早い段階で plausible diagnosis に settle する問題に対し、successive turns で unresolved evidence を探し続ける **Continual Search** を提案し、4 existing RCA benchmarks と新しい **MegaRCA-Mix（50 human-annotated long-horizon failure trials）** で評価。

MegaRCA-Mix では GPT-5.5 の F1 が **0.349 → 0.498（40%以上改善）**。同一 model family で lower-tier model が higher-tier を上回る例も報告し、raw model scaleだけでなく diagnostic search procedure が効くことを示す。

### (2) 何が提案・推測段階か

- 50 long-horizon trials は有用だが、Kamimusuhi の multi-day / multi-device / physical-effect incidents まで一般化は未証明。
- iterative search は cost / latency を増やす。
- diagnosis correctness が改善しても、自動修復 action の安全性までは保証しない。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- observability / telemetry
- incident analysis
- deterministic replay
- causal principal/effect ledger
- organ health / recovery
- long-lived maintenance
- self-diagnosis / metacognition

### (4) 借りられる設計・実装アイデア

incident diagnosis を prose 一発で保存せず、revisable derived object とする。

```text
DiagnosticHypothesis {
  incident_id,
  hypothesis,
  supporting_evidence_refs,
  contradicting_evidence_refs,
  unexplored_regions,
  alternatives,
  confidence,
  search_round,
  stop_reason,
  diagnosis_version
}
```

canonical evidence と diagnosis を分ける。

```text
incident evidence = durable source
root-cause diagnosis = revisable derived interpretation
```

さらに search budget を Cognitive Budget の一種として扱い、重大incidentでは「最初の説明がもっともらしい」だけで止めない。

### (5) Kamimusuhiとの差分

Kamimusuhi は provenance、replay、telemetry、lineage receipt を重視しているが、**それらが存在することと、診断器が十分な evidence を探索することは別**。

直前の Probe-Debt finding は誤った liveness evidence を減らすもの。今回の RCA は、evidence 自体が正しくても **探索が不十分で誤因果を確定してしまう premature closure** を扱う。

### (6) 次に検証すべきこと

**`LongHorizonRootCauseSearchBench-v0`**

synthetic episode で:

- failure直前に紛らわしい symptom を置く
- true cause は数百〜数千 events 前
- cross-device handoff / stale cache / delayed worker / tool error を混ぜる
- correct causal evidence は sparse にする

比較:

1. one-shot diagnosis
2. full-trace一括 judge
3. retrieval + one-shot
4. iterative diagnostic search with unresolved frontier

metrics:

- root-cause F1 / exact match
- evidence coverage
- premature-closure rate
- hallucinated-cause rate
- search cost / latency
- unnecessary recovery action rate

### (7) 既存 daily ではなぜ拾いにくいか

通常は「agent benchmark」または「observability/RCA tooling」に分類され、identity continuity survey では周辺扱いになる。しかし長寿命個体では誤診が **不要な rollback / organ fencing / memory repair / model migration** に直結する。

### (8) 重要度

**A**。新しい canonical mechanism ではなく、maintenance / observability plane の診断契約として採用価値が高い。

## 5.4 A- — Thermal-Sustainable Cognitive Budget: nominal capacity と持続可能 capacity を分ける

**Primary source**: Rui Lu et al., *ETCInfer: An Energy-efficient Thermal-aware Cooling-joint Scheduler for LLM Inference in AI Datacenters*, arXiv:2609.15230.  
https://arxiv.org/abs/2609.15230

### (1) 何が実証済みか

ETCInfer は GPU inference と cooling を coupled control problem として扱い、GPU heat generation、chassis heat dissipation、CRAC power、prefill/decode latency を telemetry から calibrate する physics-informed model を作る。

hidden thermal state と time-to-throttle を推定し、pre-job cooling setpoint、per-GPU frequency、micro-batch size を適応制御する。real-trace simulation と validation experiments で:

- total job energy: 最大 **33.1%削減**
- thermal throttle exposure: 最大 **92.9%削減**
- ambient **48℃まで SLO violation 0.7%未満**

を報告する。

### (2) 何が提案・推測段階か

- datacenter CRAC を前提とした結果を、そのまま laptop / home server / robot に移せない。
- Kamimusuhi の cognition quality と thermal controller の相互作用は未検証。
- energy最適化が identity / reasoning quality を維持することを保証しない。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- Embodiment State
- Cognitive Budget
- K-Core / K-Deep routing
- local model scheduler
- energy-aware cognition
- degraded mode
- hardware health / observability

### (4) 借りられる設計・実装アイデア

resource state に瞬間値だけでなく **thermal headroom と sustainable horizon** を入れる。

```text

  ambient_estimate?,

  throttle_state,
  thermal_headroom,
  predicted_time_to_throttle,
  sustainable_latency_budget,
  sustainable_compute_budget,
  confidence
}
```

router は「今この model が動くか」だけでなく、長い deliberation / background consolidation が **数分後の interactive cognition を throttle しないか**を評価できる。

### (5) Kamimusuhiとの差分

現行 architecture/spec の Cognitive Budget は latency / energy / monetary budget、resource health を既に含むため、新しく「energy-aware routing」を提案するものではない。

fresh delta は:

```text

!=

```

という **thermal inertia / future headroom** を budget 化すること。

## 5.5 B+ fresh validation delta — Deterministic Bitemporal Reconciliation

**Primary source**: Pramod Ubbala, *Deterministic Temporal Reconciliation for Effective-Dated Identity Lifecycle Events*, arXiv:2609.14017.  
https://arxiv.org/abs/2609.14017

### 重複判断

これは **新原則として再提案しない**。Kamimusuhi は 2026-09-11 blind-spot survey ですでに valid time / transaction time の bitemporal semantics を A+ 候補として扱い、その後の判断台帳で既存 temporal contract へ反映対象としている。

今回の価値は、correction / cancellation / duplicate / out-of-order delivery を含む **fresh reproducible benchmark** が出たこと。

### (1) 何が実証済みか

paper は logical business facts と physical revisions を分離し:

1. exact replay を dedupe
2. transaction-time freshness で各 fact の authoritative revision を選ぶ
3. canceled facts を除外
4. surviving facts を valid-time order で適用

する reconciliation を定義。permutation invariance / replay idempotence / revision dominance / deterministic snapshot construction を explicit assumptions の下で示す。

synthetic fault-injection benchmarkでは:

- **250,000 generated identity histories**
- **1,585,589 delivered records**
- proposed method は separately retained authoritative final state を全 tested cases で再構築
- 75% delivery disorderで exact-state accuracy:
  - arrival order: 42.35%
  - effective-time sort: 85.38%
  - transaction-time sort: 76.61%
  - proposed reconciliation: **100%**
- 別の40,000 permutation experimentで全 tested permutation が同じ final state

### (2) 何が提案・推測段階か

enterprise workforce identity lifecycle の synthetic benchmark であり、Kamimusuhi の self/persona/relationship semantics、authority forks、uncertain evidence まで保証しない。

### (3) 関係する Kamimusuhi subsystem

- canonical evidence
- temporal query
- relationship facts
- corrections / supersession
- replay / restore
- derived views

### (4) 借りられる設計・実装アイデア

新schemaを増やすより既存 temporal contract の test fixture を強化する。

### (5) Kamimusuhiとの差分

Kamimusuhi は valid/event/arrival/commit/revision time をすでに分ける方向。今回のpaperは「その分離が corrections と disorder 下でどう効くか」の concrete benchmark を与える。

### (6) 次に検証すべきこと

既存 temporal/evidence test に **`BitemporalCorrectionPermutationBench-v0`** を追加。

- correction arrives after derived view built
- cancellation arrives before original event
- duplicate old revision after newer revision
- offline K-Edge batch arrives out of order
- same valid-time, different transaction-time
- restore from snapshot then delayed revision

assert:

- permutation invariance（assumptions内）
- exact replay idempotence
- latest authoritative revision dominance
- derived view rebuild equality
- historical `as-known-then` query と `as-believed-now-about-then` query を混同しない

### (7) 既存 daily ではなぜ拾いにくいか

enterprise IAM / temporal database の話に見え、AI memory paperとしては検索されにくい。今回は新原則ではなく **既出bitemporal contractの再現可能な fault-injection材料**としてのみ価値がある。

### (8) 重要度

**B+ delta**。spec追加より test強化向け。
