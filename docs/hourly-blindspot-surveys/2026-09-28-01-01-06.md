## 3. 重要発見

### 3.1 A — Delegate Epistemic Access Manifest / Capability-Scoped Input Projection

Source: Hermes Agent #125319  
https://github.com/NousResearch/hermes-agent/issues/125319

1. **実証済み**  
   MoA の virtual provider が vision capability を持たないため、画像付き turn が text fallback へ落ち、reference models には画像そのものではなく同一の text-only representation が配られる。vision 対応 reference でも primary image を見られず、tool schema も無いため回収できない。一方 aggregator だけが画像解析できる。
2. **提案・推測**  
   全 delegate へ raw image を配る必要はない。privacy / cost / capability に応じて OCR、caption、crop、structured observation に変換してよい。
3. **関連 subsystem**  
   Cognitive Action Router、K-Core/K-Deep、Global Workspace、multimodal perception、distributed cognition、external model trust。
4. **借りる案**  
   delegate result に、delegate identity、capability revision、source evidence IDs、実際に渡した representation、変換種別、tool access、privacy scope を記録する Epistemic Access Manifest を添付する。
5. **Kamimusuhiとの差分**  
   現行は evidence provenance と model/tool result provenance を分けるが、その中間の「この delegate が何を見られたか」は中心契約ではない。
6. **次に検証**  
   **DelegateEpistemicAccessBench-v0**。vision/text-only/tool-capable などを混在させ、raw/OCR/caption/no-evidence を配り、aggregator が evidence access の差を正しく扱えるか測る。
7. **dailyで拾いにくい理由**  
   multimodal と multi-agent を別分野として見ると、orchestration layer で evidence が失われる問題が落ちる。
8. **重要度**: **A**

Invariant候補: **delegate claim の epistemic weight は、その delegate が実際に受け取った evidence projection を越えない。**

### 3.2 A — Semantic Compatibility Fingerprint for Rebuildable Cognitive Artifacts

Source: OpenClaw #159769  
https://github.com/openclaw/openclaw/issues/159769

1. **実証済み**  
   同一 memory-search config、同一 model、同一 768 dimensions、同一 endpoint のまま、release 間で persisted provider label が ollama → openai-compatible → ollama と変化し、その nominal label 差だけで vector memory search が pause する field report。23 agents 中11がこの理由で pause、2が metadata_missing と報告。
2. **提案・推測**  
   provider alias を無視すればよいわけではない。同名 model でも backend revision や normalization が変わる可能性がある。
3. **関連 subsystem**  
   derived memory index、semantic retrieval、software-body upgrade、provider adapter migration、health attribution。
4. **借りる案**  
   「どこで作ったか」の provenance と「再利用できるか」の compatibility fingerprint を分ける。fingerprint は model semantics、dimension、normalization、preprocess/chunking version、source schema 等から作る。
5. **Kamimusuhiとの差分**  
   schema compatibility は既出だが、nominal implementation identity の揺れが memory recall continuity を切る具体例は未収載。
6. **次に検証**  
   **DerivedArtifactCompatibilityFingerprintBench-v0**。alias-only、model revision、dimension、chunking、provenance-only、unknown を比較し、誤 pause / 誤 reuse / rebuild cost を測る。
7. **dailyで拾いにくい理由**  
   memory quality と software migration の中間にある「derived cognitive artifact の互換性」だから。
8. **重要度**: **A**

Invariant候補: **nominal identity の変更だけで、semantic compatibility が保たれた derived cognition artifact を無効化しない。**

### 3.3 A update — Deadline-Expired Work Loses Mutation Authority

Sources:
- Hermes #125353  
  https://github.com/NousResearch/hermes-agent/issues/125353
- PR #125354  
  https://github.com/NousResearch/hermes-agent/pull/125354

1. **実証済み**  
   deterministic regression で、古い upload が client deadline を超えて失敗扱いになった後、新しい retry が成功して state を更新しても、古い async continuation が後から再開して旧内容で remote state を上書きし、さらに sync-back で host 側まで巻き戻せる。PR は timeout 時に submitted Future を cancel し、対象 regression を red→green にしたと報告。
2. **提案・推測**  
   cancellation は cooperative なので、remote が effect を受理済みならそれだけでは十分でない。
3. **関連 subsystem**  
   Deadline Closure、Continuity Kernel、remote tool、migration/sync、cancellation/reconciliation、distributed embodiment。
4. **借りる案**  
   attempt_id / generation / deadline / mutation lease を持ち、expired または superseded attempt は newer generation commit 後の mutation authority を失う。可能なら predecessor / generation check を effect 側へ渡す。
5. **Kamimusuhiとの差分**  
   既出 Deadline Closure は caller release と child quiescence、既出 stale-writer は canonical writer が中心。今回はその接点として「deadline超過した detached work が stale writer 化する」。
6. **次に検証**  
   **ExpiredWriterGenerationFenceBench-v0**。attempt N を timeout、N+1 を commit、N を late resume させ、旧 effect が reject / quarantine / reconciliation に落ちるか測る。
7. **dailyで拾いにくい理由**  
   timeout、consistency、file sync が別分野に分かれるため。
8. **重要度**: **A update**

更新原則: **expired/superseded attempt は newer generation を上書きする authority を持たない。**

### 3.4 A update — Action-Specific Consent Projection Closure

Source: OpenClaw #159762  
https://github.com/openclaw/openclaw/issues/159762

1. **実証済み**  
   voice-originated consult で confirmation required になると、agent が作った「何を実行したいか」の説明が generic yes/no prompt に置換され、ユーザーが対象 action を識別できない。backend challenge 自体には tool identity と parameter fingerprint がある。
2. **提案・推測**  
   agent の自然言語説明をそのまま読むだけでは誤説明や過剰情報の問題があるため、effect identity から mechanically/policy-controlled に human summary を作る方がよい場合がある。
3. **関連 subsystem**  
   Effect Acceptance、voice surface、HCI、authorization receipt、multi-device embodiment。
4. **借りる案**  
   ApprovalChallenge と ApprovalPresentationReceipt を分け、challenge ID、effect fingerprint、surface、redacted action summary、presentation digest を bind する。
5. **Kamimusuhiとの差分**  
   approval artifact identity は既出。fresh 差分は backend correctness を human-facing surface まで end-to-end に閉じること。
6. **次に検証**  
   **ApprovalPresentationClosureBench-v0**。text/voice/mobile、複数pending action、stale challenge、redactionを試し、action summary 欠落時の bare yes/no を拒否する。
7. **dailyで拾いにくい理由**  
   security は backend binding、HCI は wording を見るため、その間の projection loss が落ちる。
8. **重要度**: **A update**

更新原則: **approval surface が action identity を保持しなければ informed consent とは扱わない。**

### 3.5 B — Access-Control Representation Non-Interference

Sources:
- OpenClaw #159734  
  https://github.com/openclaw/openclaw/issues/159734
- Linux acl(5)  
  https://man7.org/linux/man-pages/man5/acl.5.html

1. **実証済み**  
   private-dir hardening の raw chmod により named POSIX ACL entry は残っても ACL mask が変化し、named user/group の effective permission が消える source-level reproduction。POSIX ACL では mask が named entries の effective rights を制約する。
2. **提案・推測**  
   named ACL grant を保持すべきかは policy 次第。「完全revocation」が意図なら permission loss は正しい。問題は base-mode hardening と explicit grant revocation を同じ操作として扱うこと。
3. **関連 subsystem**  
   memory ownership/consent、canonical storage、capability security、multi-user deployment、backup/migration。
4. **借りる案**  
   filesystem policy を mode bits だけでなく owner、named ACL、mask、default ACL、security labels を含む effective principal graph として評価する。
5. **Kamimusuhiとの差分**  
   高位 authority が typed でも、storage layerで単純 mode bits に潰すと richer policy との semantic gap が生じる。
6. **次に検証**  
   **FilesystemPolicyRepresentationBench-v0**。hardening / migration / restore 前後で effective access graph を比較し、explicit revocation 以外の silent grant loss/gain を検出する。
7. **dailyで拾いにくい理由**  
   capability security と OS ACL が別領域だから。
8. **重要度**: **B**

### 3.6 B backfill — Skill-to-EFSM Compilation with Replay-Gated Evolution

Source: Li et al., **HEXIS: Compiling Skills into Extended Finite State Machines**  
https://arxiv.org/abs/2609.30123

1. **実証済み**  
   agent skill を Extended Finite State Machine に compileし、local reasoning と control flow を分離。development traces から missing operation/dependency を補い、更新は static checks と current + previously accepted traces の replay 後だけ accept。4 benchmarks / 4 executorsで Skill+ReAct より平均16.1 percentage points改善、Qwen3.8-27Bで execution tokens 38.4–88.9%削減と報告。
2. **提案・推測**  
   open-ended / social / perception-heavy task は state explosion や brittle guard があり得る。
3. **関連 subsystem**  
   procedural memory、K-Nerve/K-Edge、formal methods、skill evolution、tool orchestration、offline consolidation。
4. **借りる案**  
   ProceduralSkill に natural-language source、compiled graph、state schema、transition guards、tool bindings、accepted trace suite、compiler revision を持たせる。
5. **Kamimusuhiとの差分**  
   EFSM は task-control artifact であり identity/canonical memory authority にはしない。external effect は既存 gate を必ず通す。
6. **次に検証**  
   **SkillEFSMCompilationBench-v0**。raw skill+ReAct / EFSM / small typed controller を比較し、step omission、wrong order、tokens、latency、fault recovery、regression replay を測る。
7. **dailyで拾いにくい理由**  
   skill prompt、formal methods、low-latency controller を別々に探索しがちだから。
8. **重要度**: **B backfill**

## 10. 結論

今回もっともKamimusuhi固有に効くのは **Delegate Epistemic Access**。複数model・複数device・raw/derived sensory evidence・privacy scopeを組み合わせるほど、同じturnの各delegateは同じ世界を見なくなる。result integrationでは claim + claimant identity + actual evidence-access set + representation transform + capability revision + authority/privacy scope を一組として扱うべき。

次に、software updateでadapter名が変わっただけでmemory recallが停止するのも、本当に意味が変わったartifactをalias一致だけでreuseするのも避けたい。**semantic compatibilityとnominal identityを分ける**必要がある。

最後に、deadlineは単なるlatency budgetではなく **mutation authorityの寿命** として扱う。timeout後のworkがlate writerとして復活しnewer stateを巻き戻す経路は、Continuity Kernel / distributed embodimentへ直接接続する。
