## 1. A — Retention Budget Must Be Composed With Recovery Materialization Budget

Source: https://github.com/openclaw/openclaw/issues/165253 （2026-10-05 10:45 JST）

1. **実証済み**: long-lived agent DBが1.15 GBへ成長し、startup queryの一括materializationで約1 GB heapを使い切ってreadiness前のrestart loopになった。古いtrajectory削除後は起動した。保存量はtrajectory側の既定retention上限内だった。
2. **提案段階**: DBをheapより小さくする必要はなく、page read、lazy hydration、reduced recovery mode等が候補。
3. **関係**: Canonical Evidence、Continuity Kernel再起動、Cognitive Budget、Software Body maintenance。
4. **借用案**: durable retentionとrecovery materializationを別budget化し、boot-critical readへpage/peak-memory上限を持たせる。
5. **差分**: 既出resource admissionは実行時pressure中心。本件は保存policy内でも復旧readerだけで個体が起動不能になるcross-layer failure。
6. **次**: **RetentionMaterializationRecoveryBench-v0 (P0)** — DB量、row幅、page size、heap上限をsweepしboot成功、peak heap、degraded recoveryを測る。
7. **拾いにくい理由**: retention/storage、runtime OOM、recoveryが別分野。
8. **重要度**: **A**。

## 2. A update — Successful Memory Mutation Must Report Displaced State

Source: https://github.com/openclaw/openclaw/issues/165245 （2026-10-05 10:23 JST）

1. **実証済み**: memory promotion前のquota compactionが古いpromotion blocksをdropする一方、journalは新規promotionのsuccessだけを記録する。報告workspaceでは371 historical promoted keysが6 live markersへ減ったが、66 promotion eventsは成功扱いだった。
2. **提案段階**: eviction自体はgraceful forgettingとして正当な場合がある。
3. **関係**: MemoryProposal、Mutation Policy、forgetting、memory ownership/consent、sleep/dream。
4. **借用案**: mutation receiptに added / updated / superseded / evicted / retained / budget-before-after を含める。
5. **差分**: Kamimusuhiはforgetting種別を分けるが、成功した追加が何を押し出したかの負のdeltaは弱い。
6. **次**: **MemoryMutationDisplacementReceiptBench-v0 (P0)** — promotion/compression/quota/supersessionでbefore-after集合とreceipt一致、silent displacement=0を確認。
7. **拾いにくい理由**: memory評価は追加成功を見がちで、同transactionのlossはstorage側へ隠れる。
8. **重要度**: **A update**。

## 3. B — Preference State Needs Articulability & Verifiability Qualification

Source: https://arxiv.org/abs/2610.03025  
v1は10月2日提出、10月5日のcs.AI recent batchでsurfaced。

1. **実証済み**: 2.8M texts、317M human preference judgments、7 domains、42 tasksで、articulated rubricやverifiable metricだけでは説明できないpreference gapを報告。math/software engineeringにもgapがあり、articulated criteriaへの最適化がtacit preferenceからずれる場合を示す。
2. **提案段階**: human preferenceの構造をKamimusuhi内部personaへ直接一般化することは未実証。
3. **関係**: Persona Core、values、temperament、versioned personality、metacognition、aesthetics。
4. **借用案**: preference stateを ARTICULATED / VERIFIABLE / TACIT-LATENT / CONTESTED のように資格付けし、明示commitmentと行動から推定したstyle preferenceを同じauthorityで扱わない。
5. **差分**: values/temperamentは分離済みだが、articulability自体はfirst-classではない。
6. **次**: **PreferenceArticulabilityStateBench-v0 (P1)** — rubric、pairwise example、長期behavior traceからの推定を比較し、latent preferenceがexplicit commitmentを上書きしないことを検証。
7. **拾いにくい理由**: alignment、persona、reward modeling、人文学的tacit knowledgeが別々に扱われる。
8. **重要度**: **B**。
