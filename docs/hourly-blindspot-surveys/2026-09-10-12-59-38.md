## 4. Executive summary

今回の strongest design delta は、Kamimusuhi の memory と deliberation に **「保持しているもの」「今使ってよいもの」「今は使うべきでないもの」「歴史照会なら復活させるもの」**を分離する明示的 view layer を置くことだった。

```text
Canonical / retained evidence
        │
        ├── replacement / supersession edges
        ├── temporal validity
        ├── privacy / relationship scope
        ├── current-vs-historical intent
        └── lifecycle metadata
        │
        ▼
Query-conditioned Eligible Memory View
        │
        ▼
Workspace / prompt / reasoning
```

これは Kamimusuhi がすでに持つ `canonical evidence != derived memory` を具体化する。**forgetting は必ずしも evidence deletion ではない**。current-state answer では旧値を抑制しながら、historical / forensic / autobiographical query では古い evidence を再び eligible にできるべきである。ただし privacy/legal/user-requested erasure は別契約であり、単なる retrieval suppression で済ませてはいけない。

第二の差分は、memory retrieval / privacy / injection policy を「各 agent/model が賢く守ること」に委ねないこと。Kernel-Managed Shared Memory の結果は、system-level owner が shared memory の access path を管理する設計に実証的根拠を与える。ただし Kamimusuhi では **Continuity Kernel と Memory Access Kernel を同一巨大 kernel に融合しない**方がよい。前者は「誰が続くか」、後者は「この cognition episode に何を見せるか」を所有する。

第三の差分は stopping semantics である。Safe to Stop? では強制的に情報取得を続けた場合に誤りが悪化する非単調性が観測されている。Kamimusuhi の `THINK_MORE` は善ではなく **resource-consuming action with possible regression** とみなし、`STOP_AND_ACT / THINK_MORE / DEFER` を校正・評価する必要がある。

# 5. Detailed findings

## 5.1 RD-Forget: 「何を保存するか」と「今何を使うか」を分ける

**Source**

- Yuhang Li, Yuchen Li, *What Should an Agent Forget? Separating What Is Stored from What Is Used*, arXiv:2609.10263, submitted 2026-09-09 UTC  
  https://arxiv.org/abs/2609.10263

**Importance: S**  
**Blind-spot class:** forgetting / archival semantics / query-time evidence eligibility。通常の memory benchmark では retention score や compression rate に吸収されやすい。

### 1. What is demonstrated

RD-Forget は training-free framework として、**retained source archive** と **query-conditioned memory view** を分離する。curator が evidence を抽出して semantic slot にまとめ、同一 slot の replacement link により current-state query では superseded value を抑制しつつ、historical intent では古い evidence を再び検索対象にできる。

論文は conversational memory、knowledge updating、fact consolidation、long-context reasoning、personalization を同一 answering pipeline で評価し、forgetting をしない構成、または query conditioning を外した構成の deficit が大きいと報告する。slot grouping、historical access、relation preservation は相補的に寄与したとされる。

### 2. What remains proposed / speculative

- preprint であり、長年運用される autobiographical agent での再現は未確認。
- privacy / consent / legal deletion の意味論を解く研究ではない。
- self-belief、relationship belief、canonical action receipts のような異種 memory class 全体に同じ slot logic が適用可能かは未実証。
- query intent classifier が誤った場合の failure mode は Kamimusuhi 向けに別途評価が必要。

### 3. Kamimusuhi subsystem relevance

- canonical evidence / historical self history
- episodic memory
- self / relationship memory
- Global Workspace retrieval
- sleep / consolidation / graceful forgetting
- dispute / forensic replay
- autobiographical narrative regeneration

### 4. Borrowable design / implementation idea

`MemoryEligibilityView` を canonical storage と Workspace の間に置く。

```text
MemoryRecord
  evidence_id
  domain
  semantic_slot?
  valid_from
  valid_to?
  supersedes[]
  superseded_by[]
  source_time
  observed_time
  privacy_scope
  retention_state

MemoryQueryIntent
  CURRENT
  HISTORICAL
  AUTOBIOGRAPHICAL
  FORENSIC
  RELATIONSHIP
  RECONSOLIDATION

EligibilityDecision
  ELIGIBLE
  SUPPRESSED_SUPERSEDED
  SUPPRESSED_SCOPE
  SUPPRESSED_ERASURE
  ELIGIBLE_HISTORICAL
  NEEDS_REVIEW
```

重要なのは、`SUPPRESSED_SUPERSEDED` と `DELETED/ERASED` を同じ flag にしないこと。

### 5. Difference from current Kamimusuhi

Kamimusuhi はすでに historical truth と current interpretation を分離し、canonical evidence を派生要約より上位に置く。今回の差分は、それを **retrieval eligibility の明示的 runtime contract** に落とす点。

```text
stored
!= currently eligible
!= historically eligible
!= legally/operationally retained
```

### 6. Next validation

**`CurrentHistoricalMemoryBench` — priority S**

ケース:

- 住所・所属・好みが時間とともに変更される。
- current query では旧値を混ぜない。
- 「2025年当時は？」では旧値を復元する。
- 同一人物について contradictory evidence がある。
- user-requested erasure 後は historical query でも復活させないケースを別扱いする。
- relationship-specific fact と global semantic fact を混同しない。
- supersession chain が 10〜100 update まで伸びる。

metrics:

- obsolete-fact contamination
- historical recall accuracy
- scope leakage
- provenance completeness
- query-intent misclassification damage
- deletion/erasure compliance

### 7. Why daily survey may miss it

「長期 memory の精度改善」として読むと既存 memory 系研究の一つに見える。しかし Kamimusuhi では **forgetting を storage mutation ではなく evidence eligibility の問題として切り出せる**ことが本質で、canonical evidence / continuity と接続して初めて大きな差分になる。

## 5.2 Fortunate Recall: lifecycle metadata は correctness と calibration を別々に支える

**Source**

- Ansuman Mullick, Eray Tüzün, *Fortunate Recall: Ontology-Driven Memory Lifecycle Management for Persistent Coherence in LLMs*, arXiv:2609.10413, submitted 2026-09-09 UTC  
  https://arxiv.org/abs/2609.10413

**Importance: A+**  
**Blind-spot class:** database lifecycle / temporal validity / ontology-driven policy。単純な vector retrieval 改良ではない。

### 1. What is demonstrated

Fortunate Recall (FR) は personal facts を 10+1 の behavioral ontology に分類し、category ごとに temporal decay、slot-key supersession、event-time validity、category-aware retrieval routing を適用する policy layer を提案する。

著者らの FR-Bank は新規 LifecycleBench 516問で **76.9%**、比較対象 Mem0 / A-MEM / Memory-R1 / MemoryOS の **61〜70.5%** を上回り、LongMemEval-S では **75.2%** を報告する。

特に興味深い ablation は、typed ontology を3つの generic lifecycle primitives に置換しても correctness の差が統計的に明確でなかった一方、ontology は calibration に寄与し、downstream confabulation を **24.2% → 12.0%** に半減したと報告している点である。つまり **正しく更新するための最低限 metadata** と **「答えるべきか」を校正する taxonomy** は役割が違う可能性がある。

### 2. What remains proposed / speculative

- preprint / under review。
- ontology の category 数や分類が Kamimusuhi にそのまま最適とは限らない。
- personal fact memory が中心で、canonical action evidence、procedural skill、dream/reflection、relationship inference まで検証していない。
- LLM-extracted metadata が誤る場合の long-run drift は要検証。

### 3. Kamimusuhi subsystem relevance

- episodic / relationship / self memory lifecycle
- temporal validity
- sleep / consolidation
- graceful forgetting
- uncertainty / confidence calibration
- retrieval routing
- derived view regeneration

### 4. Borrowable design / implementation idea

まず「人間らしい memory category」を大量に作るのではなく、correctness に効く最小 generic lifecycle metadata を先に固定する。

```text
LifecycleMetadata
  slot_key?
  event_time?
  valid_from?
  valid_to?
  supersession_relation?
  decay_policy?
  retrieval_scope
  confidence / evidence_quality
```

その上に domain-specific ontology を derived policy として重ねる。

```text
canonical evidence
   ↓
generic lifecycle metadata      <- correctness boundary
   ↓
optional behavioral ontology    <- calibration/routing hypothesis
   ↓
query-conditioned view
```

### 5. Difference from current Kamimusuhi

現行 Kamimusuhi は memory domain を分離しているが、**各 memory record の lifecycle behavior を機械可読な共通契約としてどこまで持つか**はまだ薄い。FR は `self/relationship/episodic` という storage domain と、`supersedes/expires/decays/valid-at` という lifecycle semantics を直交軸にする材料になる。

### 6. Next validation

**`LifecyclePrimitiveAblation` — priority A+**

比較:

1. timestamp only
2. timestamp + supersession
3. + validity interval
4. + domain-specific decay
5. + behavioral ontology

Kamimusuhi synthetic autobiography で current/historical/relationship query を混在させ、correctness、confabulation、abstention、metadata extraction error、storage overhead を測る。

### 7. Why daily survey may miss it

memory paper としては ontology が目立つが、Kamimusuhi に重要なのは「ontology 自体」より、**generic lifecycle primitives と calibration taxonomy の効果を分解した ablation**。DB/schema design の示唆として読む必要がある。

## 5.3 Kernel-Managed Shared Memory: memory policy owner を agent/model の外へ出す

**Source**

- Ryan Lum, Yongfeng Zhang, *Kernel-Managed Shared Memory for System-Wide Personalization*, arXiv:2609.10144, submitted 2026-09-09 UTC  
  https://arxiv.org/abs/2609.10144

**Importance: A+**  
**Blind-spot class:** agent operating system / memory access control / prompt assembly ownership。

### 1. What is demonstrated

この研究は specialized agents が structured/tagged memories を書き、**individual agent ではなく agent-system kernel が retrieval、privacy enforcement、prompt injection を管理する**構造を AIOS 上に実装した。

GPT-4o、Llama-3.1:8B、Qwen2.5:7B、計1,800 trials で評価し、同じ underlying storage を使う unmanaged Mem0 と比較して personalization score を 5-point scale 上で **+2.4〜4.0 points** 改善したと報告する。full unfiltered context と比べて 3モデル中2モデルで統計的に同等、残り1モデルで小さな deficit がある一方、end-to-end latency は **15〜61%低下**したとされる。

### 2. What remains proposed / speculative

- benchmark は personalization が中心で、years-long autobiographical continuity は未評価。
- system kernel が central owner になることの可用性・障害・侵害時 blast radius は別問題。
- user identity resolution と memory authorization が完全に正しいことは実証していない。
- Kamimusuhi の canonical evidence / continuity authority をこの kernel に移す根拠にはならない。

### 3. Kamimusuhi subsystem relevance

- memory retrieval / workspace assembly
- relationship-memory privacy
- K-Edge / K-Core shared context
- local/remote model prompt construction
- memory access observability
- per-surface privacy policy

### 4. Borrowable design / implementation idea

**Continuity Kernel と別物として `MemoryAccessKernel` を試す。**

```text
memory producers
  K-Edge / Persona Core / extractor / tool
           │ typed records/proposals
           ▼
      durable memory stores
           │
           ▼
      MemoryAccessKernel
  scope / freshness / lifecycle / budget
  provenance / privacy / retrieval policy
           │
           ▼
   attributed Workspace View
           │
           ▼
     whichever model runs now
```

model/provider を替えても access policy が変わらないことが重要。

### 5. Difference from current Kamimusuhi

Kamimusuhi の Continuity Kernel は canonical head / lineage / activation authority の owner である。memory retrieval policy まで抱え込ませると kernel が巨大化する。

今回の差分は、**identity-authority kernel と memory-view kernel を責務分離しつつ、どちらも model-independent にする**こと。

```text
Continuity Kernel: who/which state continues?
MemoryAccessKernel: which evidence may this cognition see/use now?
```

### 6. Next validation

**`MemoryConsistencyVisibilityBench` — priority A+**

ケース:

- K-Edge が書いた relationship memory を K-Core が直後に読む。
- concurrent write/read。
- user/person scope の取り違え。
- malformed sharing metadata は private-safe default にする。
- stale local cache。
- network timeout 中に sensitive memory が必要になる。
- local model と frontier model で可視範囲を変える。

metrics:

- cross-person leakage
- stale-read rate
- read-your-writes consistency
- policy bypass rate
- latency/token overhead
- availability under partition

### 7. Why daily survey may miss it

表面上は personalization memory の論文だが、重要なのは retrieval algorithm より **policy ownership を model/agent から OS-level component へ移したこと**。Kamimusuhi の provider-independent identity philosophyと同型の boundary が memory access に現れている。

## 5.4 Safe to Stop?: `THINK_MORE` は単調改善ではない

**Source**

- Yuexin Wu, Vasile Rus, *Safe to Stop? Risk-Constrained Stopping for Sequential Clinical Diagnosis Agents*, arXiv:2609.09678, submitted 2026-09-09 03:46:53 UTC  
  https://arxiv.org/abs/2609.09678

**Importance: A+**  
**Freshness note:** survey primary window から約13分だけ外れるため near-window backfill。  
**Blind-spot class:** clinical sequential decision / selective prediction / stopping theory。

### 1. What is demonstrated

Cros は sequential diagnosis agent に対し、state-wise error ranking と development/calibration split を用いて、診断する・追加検査する・defer する stopping decision を扱う。

1,834-episode の MIMIC-derived abdominal-pain benchmark で full ranker の state-error AUROC は **0.853**、max class probability は **0.715**、backbone native stop score は **0.552**。既に閲覧済みの 367-episode evaluation split では、frozen Cros weights の解析平均として **16.9% selective error / 78.8% coverage**、native stopping は **30.8% error / 100% coverage** と報告される。

Kamimusuhi に最も重要なのは、**forced continuation が non-monotone** だった点で、HPI-only の error 28.3% に対し full workup 後は 34.3% へ悪化した。つまり「情報・推論stepを増やせば必ず良くなる」は成り立たない。

### 2. What remains proposed / speculative

著者ら自身が、evaluation labels が earlier development で inspected されたため、結果を confirmatory safety certificate ではなく exploratory feasibility / audit evidence と位置付けている。また joint criterion を満たしたのは development resplit 20回中6回に留まる。

臨床診断の stopping calibration が general-purpose cognitive agent にそのまま移るわけではない。

### 3. Kamimusuhi subsystem relevance

- variable-depth deliberation
- `THINK_MORE / RESPOND / DEFER`
- Cognitive Budget
- K-Core → K-Deep escalation
- uncertainty / confidence calibration
- background task stopping
- external model delegation stopping

### 4. Borrowable design / implementation idea

`EffectAcceptanceGate` とは別に **`CognitiveStoppingGate`** を置く。

```text
current workspace/state
      │
      ▼
estimated error / uncertainty / value-of-more-compute
      │
 ┌────┼───────────┐
 │    │           │
STOP  THINK_MORE  DEFER/HANDOFF
 │    │           │
act   spend       human/safer tier
```

停止は cognition の終了ではなく、**risk / coverage / cost を持つ action selection** として観測する。

### 5. Difference from current Kamimusuhi

architecture は variable-depth reasoning と `THINK_MORE` / `DEFER` を持つが、現在は「いつ止めるべきか」を独立した reliability problem として規定していない。

また前回の Effect Acceptance は「最終外部効果を今発生させてよいか」であり、今回の stopping は「さらに認知 compute を費やすか」。二つは分ける。

### 6. Next validation

**`DeliberationStoppingBench` — priority A+**

タスク群:

- 1step で十分な問題。
- additional reasoning が hallucinated premises を増やす問題。
- stale Web/tool result を重ねるほど悪化する問題。
- extra model delegation による disagreement。
- high-cost K-Deep escalation が不要な問題。
- 不確実なので人/operatorへ defer すべき問題。

比較:

1. fixed depth
2. model self-stop
3. confidence threshold
4. learned/calibrated stopping gate
5. stopping gate + explicit handoff

metrics:

- task error
- overthinking regression rate
- token/time/energy cost
- unnecessary K-Deep escalation
- defer coverage
- error among autonomous completions

### 7. Why daily survey may miss it

agent benchmark は「最終精度」や「何step考えたか」を評価しがちで、**stopping policy 自体の校正**は医療・selective prediction 側に分散している。Kamimusuhi の Cognitive Budget に直結するが、一般的な agent orchestration キーワードでは拾いにくい。

## 5.5 Affective Resonance: emotion state ではなく interaction field を持つ

**Source**

- Cy Gorman, Yihang Yao, *Shifting Relational Paradigms for Affective Computing: Affective Resonance, Vitality Affects, and Vocal Interaction Fields*, arXiv:2609.09864; Interspeech 2026 poster accepted  
  https://arxiv.org/abs/2609.09864

**Importance: A**  
**Blind-spot class:** speech dynamics / relational affect / interaction process。通常の affective computing の emotion label taxonomy とは異なる。

### 1. What is demonstrated

著者らは individual speaker の discrete emotion / arousal-valence を主単位とする枠組みでは interaction を十分に表せないとし、**interactional field** を単位とする relational framework を提案する。

proof-of-concept では self-supervised speech representation を用い、multi-party conversation で **directional expressive coupling** を検出した。coupling は interaction regime ごとに異なり、sub-second timescale に集中し、exclusive-speech negative control では崩れると報告される。

### 2. What remains proposed / speculative

- preliminary study であり、Artificial Affective Resonance Intelligence という broader framework の有効性は未実証。
- observed coupling が長期的な trust / intimacy / relationship quality を直接意味するわけではない。
- Kamimusuhi の behavior を改善することも未検証。

### 3. Kamimusuhi subsystem relevance

- K-Nerve / K-Edge audio processing
- turn-taking / backchannel / interruption
- speech motor control / prosody
- social signal background processor
- current relationship interaction state
- joint attention / interpersonal timing

### 4. Borrowable design / implementation idea

individual-state tags の横に、短寿命の **`InteractionFieldState`** を置く。

```text
InteractionFieldState
  participants[]
  time_window_ms
  directional_coupling
  synchrony / divergence
  turn-transition dynamics
  prosodic energy trend
  confidence
  source_audio_refs
  expires_at
```

これは durable `person/<id>/trust` に直接書かず、まず session / workspace / social-signal layer に置く。

```text
sub-second coupling
!= emotion label
!= relationship trait
!= trust evidence by itself
```

### 5. Difference from current Kamimusuhi

Kamimusuhi は digital interoception / regulatory state と person model を持つが、**二者・多者の間に一時的に成立する relational dynamical state** は明示的でない。self emotion / other emotion の二つを並べるだけでは表現しにくい層を追加する候補になる。

### 6. Next validation

**`RelationalProsodyBench` — priority A**

- natural dyadic / multi-party audio と exclusive-speech shuffled control を比較。
- individual emotion classifier と interaction-coupling features を比較。
- turn transition / backchannel timing を予測。
- coupling signal を使った時に interruption latency / inappropriate backchannel が改善するか。
- noisy mic / packet loss / speaker diarization error での頑健性。
- relational signal を durable memory に誤昇格させない policy test。

### 7. Why daily survey may miss it

「emotion recognition」と検索すると individual label prediction が大量に出る。今回の示唆は、Kamimusuhi が emotion tag を増やすことではなく、**social affect を agent内部属性ではなく interaction process の一時状態として表現すること**にある。

## 5.6 Partial-TEE BFT: secure organ を少数足せば単調に安全になるとは限らない

**Source**

- Xiaoqing Wen et al., *Breaking Fault Lines: Unifying TEE-Assisted BFT Consensus in Partially Trusted Worlds*, arXiv:2609.09742; accepted to EuroSys 2027  
  https://arxiv.org/abs/2609.09742

**Importance: A-**  
**Blind-spot class:** distributed systems / secure hardware / mixed-trust quorum theory。

### 1. What is demonstrated

論文は任意 subset の replica だけが TEE 内で実行される partial-TEE model を解析し、heterogeneous trust が quorum formation と fault tolerance を変えることを示す。tight resilience bound として

`f < max{n/3, m/2}`

を導き、TEE が fault tolerance を改善するのは **deployment の 2/3 を超えてから**という threshold phenomenon を示す。

さらに dual-quorum construction と TEE-leader fast path を提案し、Intel SGX 上の Raftel / chained-Raftel を LAN/WAN で実装評価。WAN で最大 625 TPS、sub-670ms latency、HotStuff より throughput 最大 +308 TPS と報告する。

### 2. What remains proposed / speculative

- BFT replica federation と Kamimusuhi の one-individual/multi-organ continuity は同一問題ではない。
- SGX の trust model は malicious model output、bad memory extraction、operator error、social engineering 等を解決しない。
- enclave rollback / key management / attestation lifecycle を Kamimusuhi 用にどう扱うかは別問題。

### 3. Kamimusuhi subsystem relevance

- distributed Continuity Kernel
- K-Core failover
- K-Edge/K-Core trusted organ classification
- secure enclave deployment
- activation authority / canonical commit
- mixed local/cloud hardware trust

### 4. Borrowable design / implementation idea

将来 TEE を continuity/security に使うなら、単純な `trusted=true` node count ではなく **`TrustTopology`** と quorum assumptions を明示する。

```text
TrustTopology
  nodes[]
  trust_class: TEE_ATTESTED | OWNED_HOST | REMOTE_UNTRUSTED
  attestation_epoch
  lease/fencing_epoch
  quorum_role
  rollback_protection?
  key_scope
```

そして「TEE node を1台追加したので安全性が上がった」とは仮定せず、mixed-trust topology ごとに safety/liveness を検証する。

### 5. Difference from current Kamimusuhi

直近 daily survey の PRIMUS から lease + fencing はすでに候補化されている。今回の差分は **authority ownership ではなく、heterogeneous hardware trust 下の quorum threshold が非線形になり得る**という警告。

したがって TEE-BFT を Continuity Kernel の正解として採用するのではなく、将来の distributed trusted-compute experiment の falsification target とする。

### 6. Next validation

**`MixedTrustContinuityBench` — priority A-**

- 3/5/7 node topology。
- TEE-equipped node 比率を変更。
- stale/fenced node、Byzantine proposal、network partition、rollback/replay を注入。
- TEE attestation は valid だが application state は stale、というケース。
- TEE node failure による liveness loss。

metrics:

- conflicting canonical commit rate
- stale activation acceptance
- failover latency
- liveness under partial trust
- recovery complexity
- TEE operational overhead

### 7. Why daily survey may miss it

AI-agent survey では secure enclave を「より trusted な compute」と単純化しがちだが、distributed-systems 側では **一部だけ trust assumption を強くすると quorum geometry 自体が変わる**。multi-device embodiment を持つ Kamimusuhi では、将来 secure hardware を使うほどこの境界が重要になる。

# 6. Cross-cutting synthesis

## 6.1 Memory には少なくとも4種類の「消える」がある

今回の RD-Forget と Fortunate Recall を Kamimusuhi 用に蒸留すると、`forget()` 一個では危険である。

```text
1. RETRIEVAL_SUPPRESSION
   今の query では使わない

2. SUPERSESSION
   current truth としては後継値を優先する

3. DECAY / DEPRIORITIZATION
   salience / retrieval weight を落とす

4. ERASURE / RETENTION_END
   policy/consent/legal/security reasons で保持自体を終了する
```

1〜3 は historical evidence を保持できる。4 は別物。Kamimusuhi の canonical evidence discipline と privacy/consent semantics を両立させるには、この区別を schema と API に出した方がよい。

## 6.2 Kernel は一個の巨大 root process ではなく、責務境界として考える

今回の memory-kernel 研究は「kernel」という語を使うが、Kamimusuhi の Continuity Kernel に全機能を詰め込む必要はない。

推奨分離:

```text
Continuity Kernel
  canonical lineage / predecessor / activation authority

Memory Access Kernel
  visibility / lifecycle / retrieval eligibility / prompt-view assembly

Effect Acceptance Gate
  last reversible moment before consequential effect

Cognitive Stopping Gate
  stop / think more / defer under risk and cost
```

これらは互いに evidence / version / authority reference を渡すが、owner を分離した方がテストしやすい。

## 6.3 「もっと賢く考える」と「もっと長く考える」を分ける

Safe to Stop? と Proof-Carrying Cognition は別問題を扱うが、共通して **optimization pressure / additional compute が verifier や final quality を単調に改善するとは限らない**ことを示す。

Kamimusuhi では Cognitive Budget を単なる上限ではなく、追加 compute の期待価値と regression risk を評価する対象にした方がよい。

この intake から直ちに normative spec を変更しない。レビュー後の候補は以下。

### Candidate A — memory architecture note / `spec.md`

候補 invariant:

> Durable retention, current retrieval eligibility, historical retrieval eligibility, supersession, and erasure MUST NOT be represented as one undifferentiated memory state.

日本語案:

> **保持されていること、現在の認知に利用可能であること、歴史照会で利用可能であること、後継値に置換済みであること、消去済みであることを同一状態として扱ってはならない。**

まず benchmark で有効性を確認してから昇格する。

### Candidate B — architecture: MemoryAccessKernel

Continuity Kernel の責務を増やさず、memory view policy の model-independent owner を architecture note として追加する候補。

### Candidate C — deliberation architecture

`THINK_MORE` / `RESPOND` / `DEFER` に `CognitiveStoppingDecision` を明示し、Cognitive Budget の評価指標に **overthinking regression** と **selective autonomous error** を追加する候補。

### Candidate D — speech/social state

`InteractionFieldState` を session-scoped derived state として検討。relationship durable state への direct mutation authority は与えない。

### Candidate E — distributed security note

TEE / attestation を導入する場合の `TrustTopology`、attestation epoch、quorum assumption、rollback protection を明示し、「一部TEE化 = 単調な安全性向上」を禁止する design note 候補。

## 12. Bottom line

今回の blind spot は「新しい巨大 cognitive architecture」ではなく、**既存 Kamimusuhi の境界を機械的に強くする semantics** に集中した。

最も重要な3点:

```text
A. forgetting != deletion
   retained evidence と query-time eligibility を分ける

B. memory producer != memory-policy owner
   retrieval/privacy/view assembly を model-independent にする

C. think more != always better
   stopping/defer を独立した校正対象にする
```

この3点は、Kamimusuhi の「モデルや計算資源が変わっても同じ個体として続く」という中心命題と矛盾せず、むしろ canonical history、Cognitive Budget、provider-neutral runtime を具体化する。
