## 3. Executive summary

今回は **有意な新規発見あり**。

最も重要な設計差分は、Kamimusuhi の「外部の知能・計算を借りてよい」という方針を、**単なる provenance から “borrowed computation can sometimes be independently verified” へ一段進められる**ことだった。

Maverick は open-weight LLM inference の主要演算を第三者へ委譲しつつ、入力 privacy と計算の検証を両立する prototype を示す。Kamimusuhi にその protocol を即採用する必要はないが、`external model result` の provenance に加えて `compute_verified / model_digest / verifier_receipt` を持つ余地を contract として残す価値が高い。ただし重要な負の境界として、**正しいモデルを正しく計算したこと != その回答が真・安全・妥当であること**は維持しなければならない。

第二に、`Do Agents Know When They Succeed?` は local model の residual representation から agentic task の成功を予測する probe を示した。これは Persona Core / local K-Core が「私はできると思う」と自然言語で言う confidence とは別の **CompetenceTelemetry** を持ち、routing / escalation / handoff に使う可能性を示す。ただし probe は model-version-specific な operational telemetry であり、canonical self belief に直接昇格させない。

第三に、HCI の trust 研究は Kamimusuhi の `relationships/trust` を単一 scalar として扱う危険を補強する。ability、integrity、benevolence は同じものではなく、UI 上の多機能さや anthropomorphism がそれらを一様に保証しない。将来の person model / relationship state では **domain-scoped multidimensional trust** を検討すべきである。

第四に、金融 systemic-risk の異分野研究から、認知資源の「台数」ではなく **shared failure domain** を追うべき設計知が得られた。frontier model A/B/C を三つ呼んでも、同じ provider、同じ identity provider、同じ network egress、同じ underlying model family、同じ compromised MCP registry に依存していれば、独立した三票とは限らない。Cognitive Budget に `dependency topology / independence group / correlated-failure risk` を加える価値がある。

第五に、temporal database の valid time / transaction time は、Kamimusuhi がすでに考えている event / arrival / commit time を **「世界の時間」と「知識状態の時間」**に整理する古典的な語彙を与える。これにより「2026-01-01時点で何が真だったと今は考えるか」と「2026-01-01当時、Kamimusuhi は何を真だと記録していたか」を別 query にできる。

# 4. Detailed findings

## 4.1 Maverick — 「外部推論を借りる」と「外部推論を信じる」を分離する

**Source:** Ben Merbaum et al., *Maverick: Private and Verifiable LLM Inference Made Practical via Matrix-Vector Multiplication Delegation*, arXiv:2609.10264  
**Primary:** https://arxiv.org/abs/2609.10264  
**Submitted:** 2026-09-09 UTC  
**Importance:** **A+**  
**Blind-spot class:** cryptography / verifiable computation / private outsourcing

### (1) 何が実証済みか

Maverick は、LLM の主要演算である matrix-vector multiplication を第三者へ委譲し、client 側でその計算を検証する protocol を提案・実装している。論文は transparent preprocessing、batch verification、server overhead をほぼ増やさない verification primitive と、LPN-based pseudorandom masking による input privacy を組み合わせる。

Qwen3-4B を用いた end-to-end prototype で throughput を測定し、1 client thread + CPU server 最大128 threads の条件では local inference 比で、privacy mask online 生成時最大17x、precomputed mask で最大45x、verification-only で最大44x の throughput gain を報告する。4 client threads 条件でも対応する改善を報告している。

ここで重要なのは、**「外部計算資源を使う」ことと「外部計算結果を無条件に信用する」ことを protocol 上分離できる**実例が出たこと。

### (2) 何が提案・推測段階か

- end-to-end 評価は Qwen3-4B を中心とした prototype であり、巨大 MoE、multimodal、speculative decode、closed frontier API にそのまま適用できるとは限らない。
- verification が保証するのは指定された計算の correctness であり、model の知識、推論、alignment、factuality、tool selection の正しさではない。
- privacy と verification の cost は network / hardware / batch size に依存する。
- Kamimusuhi がこの protocol 自体を採るべきかは未検証。

### (3) Kamimusuhi の関連サブシステム

- Cognitive Action Router
- K-Deep / remote compute
- external local-model server / borrowed compute organ
- Evidence / provenance
- privacy policy
- resource capability model
- distributed embodiment

### (4) 借りられる設計・実装アイデア

外部推論結果を少なくとも次の二軸で扱う。

```text
DelegatedInferenceReceipt
  provider / endpoint
  model_id
  model_digest_or_manifest
  request_commitment
  response_commitment
  privacy_mode
  compute_verification:
    UNVERIFIED | VERIFIED | FAILED | UNSUPPORTED
  verification_scheme
  verifier_version
  timestamp
  trace_ref

Epistemic status
  UNKNOWN | CORROBORATED | CONTESTED | REJECTED
```

**compute verification と epistemic admission を同じ field にしない。**

将来の backend interface では `supports_verifiable_inference` の capability bit を持てるようにする。実装初期は常に `UNSUPPORTED` でもよい。

### (5) Kamimusuhiとの差分

現行 Kamimusuhi は external model/tool result の provenance と self-belief の分離を重視しているが、外部推論の **execution correctness を cryptographically attest / verify できる backend** は中心契約にまだ現れていない。

### (6) 次に検証すべきこと

`DelegatedInferenceVerificationBench`:

- mock verifier を含む provider-neutral adapter を作る。
- 同じ inference request について `UNVERIFIED / VERIFIED / FAILED` を注入。
- `VERIFIED` でも factual error を含むケースを用意し、EpistemicAdmissionGate が誤って `verified == true` を `belief == true` に変換しないことを確認。
- receipt の model digest / request commitment が食い違う replay を拒否する。

Maverick 自体の導入実験はその後でよい。

### (7) 既存デイリーサーベイではなぜ拾いにくいか

agent / persistent memory ではなく cryptography / matrix-vector delegation の論文として出てくるため、通常の LLM agent survey では「privacy-preserving inference」の性能論だけで流れやすい。Kamimusuhi では **external cognition の trust boundary** として読む価値がある。

### (8) 重要度

**A+** — protocol の即採用より、「外部知能の計算正当性」と「外部知能の認識論的正当性」を別軸にする contract が重要。

## 4.2 Do Agents Know When They Succeed? — self-report とは別の competence telemetry

**Source:** Priyanka Mary Mammen et al., *Do Agents Know When They Succeed? Calibrating Agent Confidence from Internal Representations*, arXiv:2609.09448  
**Primary:** https://arxiv.org/abs/2609.09448  
**Submitted:** 2026-09-08 UTC  
**Importance:** **A**  
**Blind-spot class:** mechanistic/representation monitoring / runtime confidence calibration

### (1) 何が実証済みか

論文は multi-turn agent interaction の内部表現から eventual task success を予測できるかを調べ、二つの手法を提案する。

- **Latent Trajectory Dynamics (LTD):** interaction trajectory 中の residual-stream representation の変化を要約。
- **Action Representation Probe (ARP):** action decision 時の representation から成功を予測。

Bash / SQL / Python の3 interactive benchmark、Qwen14B / Qwen7B / DeepSeek6.7B の3 model family で、surface generation や sequence-based calibration baseline より一貫して良い confidence signal を報告している。prompt modification や multi-sample rollout を必要としない monitor として評価されている。

### (2) 何が提案・推測段階か

- closed API model では residual stream を取得できない。
- model update / quantization / finetune / context distribution が変わると probe calibration が崩れる可能性がある。
- coding/interactive benchmark の成功予測が、社会対話、自己解釈、長期 relationship、physical action の confidence にそのまま一般化するとは限らない。
- probe が高 confidence でも canonical truth や moral correctness を保証しない。

### (3) Kamimusuhi の関連サブシステム

- Persona Core / local resident model
- K-Core / K-Edge local models
- capability model
- Cognitive Action Router
- uncertainty / calibration
- observability
- escalation to K-Deep

### (4) 借りられる設計・実装アイデア

`self_confidence` を一個の自然言語値にせず、由来を分ける。

```text
ConfidenceBundle
  verbal_self_report
  task_calibration_prior
  latent_competence_probe?   # local models only
  tool/evidence coverage
  historical_success_rate
  distribution_shift_score

CompetenceTelemetry
  model_manifest
  probe_manifest
  task_domain
  success_probability
  calibration_epoch
  ood_score
  trace_ref
```

`CompetenceTelemetry` は **operational telemetry** であり canonical self-model ではない。繰り返し evidence が溜まれば、別 proposal を通じて capability model 更新の根拠になり得る。

### (5) Kamimusuhiとの差分

Kamimusuhi は uncertainty behavior と capability model を重視するが、runtime の内部表現を使った non-verbal competence monitor はまだ明示的でない。現在の provider-neutral architecture を壊さず、local model だけが optional telemetry として提供する形が合う。

### (6) 次に検証すべきこと

`LatentCompetenceCalibrationBench`:

- local Qwen 系等で action-step representation を取得可能な backend を1つ選ぶ。
- `verbal confidence`、token/logit proxy、historical task prior、latent probe を比較。
- quantization変更、context長変更、model checkpoint変更で calibration drift を測る。
- OOD task で high-confidence false success が増えるか確認。
- probe signal による `stay local / escalate / ask evidence / defer` routing の cost-quality 改善を測る。

### (7) 既存デイリーサーベイではなぜ拾いにくいか

self-model / metacognition に見えるが、実体は agent framework ではなく **internal representation probing**。また「agent confidence」を自然言語自己評価だけで探すと見落としやすい。

### (8) 重要度

**A** — local Persona/K-Core を育てる段階で有望。ただし optional sensor として扱い、identity や truth authority にしないことが重要。

## 4.3 How Far Do Capability Cues Travel? — trust を一つの scalar に潰さない

**Source:** Chenchen Mao et al., *How Far Do Capability Cues Travel? Anthropomorphism and Differentiated Trust in a Platform-Embedded AI Assistant*, arXiv:2609.09713  
**Primary:** https://arxiv.org/abs/2609.09713  
**Submitted:** 2026-09-09 UTC  
**Importance:** **A-**  
**Blind-spot class:** HCI / social psychology / trust calibration

### (1) 何が実証済みか

270名の米国 Reddit user を対象とした randomized 2x2 experiment で、embedded AI assistant に1機能または3機能を表示し、短い rationale の有無も操作した。

3機能表示は perceived multifunctionality を増やしたが、6 outcomes に対するその他の randomized main effect は correction 後に残らなかった。rationale availability も perceived intelligence を安定して高めなかった。

同時測定された知覚の探索分析では、perceived intelligence は anthropomorphism と ability / integrity / benevolence の trust dimensions に関連した一方、perceived intelligence を統制した anthropomorphism は benevolence とは正に関連したが、integrity / ability とは安定した関連を示さなかった。

### (2) 何が提案・推測段階か

- これは **human → AI trust perception** の研究であり、Kamimusuhi が人間をどう信頼すべきかを直接実証していない。
- Reddit user / platform-embedded assistant という条件から、長期 companion 関係へ数値を一般化できない。
- association 部分は randomized causal effect ではない。

### (3) Kamimusuhi の関連サブシステム

- `relationships/person_models`
- `relationships/trust`
- social cognition
- capability self-presentation
- HCI / UI
- external-agent relationship modeling

### (4) 借りられる設計・実装アイデア

現在の `relationship.trust` 候補を一個の浮動小数へ潰さない。

```text
TrustAssessment
  subject_id
  domain
  ability
  integrity
  benevolence
  predictability?
  confidentiality?
  evidence_refs[]
  uncertainty
  valid_time
  last_recomputed_at
```

さらに、UI で Kamimusuhi 自身の capability を多く見せることを、user trust の根拠と混同しない。`capability disclosure` と `trust evidence` を別にする。

### (5) Kamimusuhiとの差分

`architecture.md` の relationship state には `trust` が候補としてあるが、現状は dimension / domain / evidence semantics が薄い。個別人モデルを持つ設計なら、**「この人はコードレビュー能力は高いが、秘密保持の evidence は不足」**のように scope を分けた方が自然。

### (6) 次に検証すべきこと

`TrustDimensionBench`:

- 同一人物について ability / integrity / benevolence が意図的に異なる履歴を作る。
- scalar trust と dimensioned trust で decision を比較。
- 一領域の高能力が別領域の権限・秘密開示へ誤って波及する `trust halo` を測る。
- user-facing capability UI の増加が authority grant を暗黙に誘発しないか HCI test を将来実施。

### (7) 既存デイリーサーベイではなぜ拾いにくいか

Theory of Mind / social cognition survey では mental-state inference に寄りやすく、**trust measurement の心理測定構造**は漏れやすい。また AI assistant の UI experiment として読むと、relationship-state schema への接続を見落とす。

### (8) 重要度

**A-** — 数値を直接輸入してはいけないが、scalar trust を避ける設計根拠として有用。

## 4.4 Cyber-Financial Contagion — 「三つの外部知能」でも fault domain が一つなら冗長ではない

**Source:** Alex Leytes, *Cyber-Financial Contagion: Modeling the Propagation of an AI Vendor Compromise Through the Banking System*, arXiv:2609.10350  
**Primary:** https://arxiv.org/abs/2609.10350  
**Submitted:** 2026-09-09 UTC  
**Importance:** **A**  
**Blind-spot class:** systemic risk / network science / correlated dependency / economics

### (1) 何が実証済みか

論文は AI vendor、financial institutions、interbank exposure、customer accounts を結ぶ4-layer heterogeneous network と、vendor compromise の伝播を扱う stochastic epidemic-and-clearing model `CFC-Prop` を提案する。

評価は **synthetic dataset** で、60 vendors、220 banks、約2,500 vendor-bank service edges、1,400 interbank exposures を用いる。heavy-tailed losses と patch latency への感度を報告し、vendor-side telemetry と graph structure を使う early-warning GNN も評価している。

実銀行システムで cascade がこの通り起きることを実証した研究ではない。しかし「一見独立した組織が共通 vendor を経由して correlated failure を持つ」という network model 自体は、Kamimusuhi の external cognitive organs に強い類推がある。

### (2) 何が提案・推測段階か

- 金融 cascade の結果は synthetic network/model に基づく。
- Kamimusuhi の external model/tool dependency に同じ epidemic dynamics が成立するとは限らない。
- CFC-GNN を Kamimusuhi に導入する根拠はない。

借りるのは **vendor concentration を topology として明示する考え方**であり、論文の金融 risk score ではない。

### (3) Kamimusuhi の関連サブシステム

- Cognitive Budget
- resource capability model
- K-Deep / external model routing
- distributed embodiment
- provider failover
- security / incident response
- source-independence / evidence corroboration

### (4) 借りられる設計・実装アイデア

`ResourceRegistry` に capability だけでなく dependency/fault-domain metadata を持つ。

```text
CognitiveResource
  resource_id
  provider
  model_family
  auth_domain
  network_egress_domain
  runtime_host_domain
  registry_or_marketplace_origin
  dependency_ids[]
  failure_domain_ids[]
  compromise_epoch?
  health
```

さらに evidence corroboration で「別モデルが同意した」を independence と同一視しない。

```text
3 responses
  model-A@provider-X
  model-B@provider-X
  model-C@provider-X

!= 3 independent sources
```

credential、provider control plane、egress、base-model ancestry、retrieval source が共通なら `source_independence_group` を共有させる。

### (5) Kamimusuhiとの差分

現行 Cognitive Budget は model capacity、compute、retrieval、tool、latency、energy、money、network/privacy constraints を列挙しているが、**correlated dependency topology / common-mode failure** は第一級の budget/resource property になっていない。

### (6) 次に検証すべきこと

`CommonModeCognitionBench`:

- 3つの logical external resources を作る。
- 条件A: 独立 fault domain。
- 条件B: provider / auth / network / retrieval corpus の一部を共有。
- shared compromise / outage / stale model rollout を注入。
- naive majority / independence-weighted corroboration / topology-aware failover を比較。
- availability、false corroboration、recovery time、cost を測る。

### (7) 既存デイリーサーベイではなぜ拾いにくいか

finance / systemic-risk の論文であり、agent architecture の keyword をほとんど持たない。だが Kamimusuhi の「外部知能を認知資源として束ねる」方針では、**認知 supply chain の共通故障点**が長寿命性に直結する。

### (8) 重要度

## 4.5 TrajMark — final artifact ではなく operational trajectory の局所整合性を見る

**Source:** Bokang Zeng et al., *TrajMark: Ownership Attribution and Segment-Level Tamper Localization for Coding-Agent Trajectories*, arXiv:2609.10416  
**Primary:** https://arxiv.org/abs/2609.10416  
**Submitted:** 2026-09-09 UTC  
**Importance:** **B+**  
**Blind-spot class:** trajectory watermarking / forensic integrity

### (1) 何が実証済みか

TrajMark は training-free / symmetric-key / visible-only な trajectory watermarking を提案し、**ownership attribution** と **local integrity verification** を分離する。

owner layer は自然に存在する READ action の一部を keyed に書き換えて deployment identifier を埋め、localization layer は critical-action segment の周辺へ linked seals を入れる。

3 coding-agent framework × 3 LLM の評価で clean full-watermark batch から exact owner を全て回復し、eligible single-site attack で95.5〜100%の edit detection、random single-action corruption で95.8%の modified site を accepted protocol region へ局所化したと報告する。matched Pass@1 は watermark 有26.9% / 無26.3%。

### (2) 何が提案・推測段階か

- coding-agent の visible action trajectory 向けであり、Kamimusuhi の canonical event log に直接最適化された方式ではない。
- symmetric-key watermark が canonical integrity の最良方式とは限らない。append-only hash chain / Merkle commitment / signed receipt 等の方が素直な領域も多い。
- ownership watermark の `owner` を Kamimusuhi の canonical identity と同一視してはいけない。

### (3) Kamimusuhi の関連サブシステム

- operational trace
- forensic export
- audit / dispute replay
- K-Edge/K-Core/K-Deep handoff trace
- delegated tool execution

### (4) 借りられる設計・実装アイデア

TrajMark の具体 watermark より、**global provenance と local integrity を別レイヤにする**発想を借りる。

```text
TraceProjection
  global provenance / signer / run id
  segment commitments[]
    segment_id
    critical_action_range
    local_integrity_receipt
```

canonical evidence store 自体は通常の cryptographic commitment を優先し、第三者へ渡す visible/exported trajectory に segment-local seal を付ける設計を検討する。

### (5) Kamimusuhiとの差分

直近 survey で TRACE / OpenTelemetry / derived trajectory projection は扱ったが、**長い trace のどこが後から編集されたかを局所化する**観点は薄かった。

### (6) 次に検証すべきこと

`TrajectoryTamperLocalizationBench`:

- canonical trace から signed/exported projection を作る。
- critical segment 単位の hash/seal を付ける単純 baseline を先に実装。
- insertion / deletion / reorder / local edit / redaction を注入。
- tamper detection、localization granularity、redaction compatibility、storage overhead を測る。
- watermark は baseline が足りない場合のみ比較する。

### (7) 既存デイリーサーベイではなぜ拾いにくいか

coding-agent watermarking として検索されるため、provenance survey でも final patch attribution の話に見えやすい。Kamimusuhi には **forensic trace の局所破損検知**という別用途がある。

### (8) 重要度

**B+** — contract の発想は有用だが、TrajMark 自体を採る必要性はまだ低い。まず通常の segment commitment を baseline にする。

## 4.6 Backfill: bitemporal database — 「いつ真だったか」と「いつ知っていたか」を二軸にする

**Sources:**  
- Richard T. Snodgrass / Christian S. Jensen 系 temporal database research  
- Jensen & Snodgrass, *Temporal Data Management*, IEEE TKDE 1999（temporal DB の valid time / transaction time の古典的整理）  
- Jensen & Snodgrass, *Valid Time*, Encyclopedia of Database Systems: https://doi.org/10.1007/978-1-4614-8265-9_1066  
- XTDB, *Time in XTDB*: https://docs.xtdb.com/about/time-in-xtdb.html  
**Importance:** **A+**  
**Blind-spot class:** database theory / temporal semantics / auditability

### (1) 何が実証済みか

temporal database では古くから、少なくとも次を分離する。

- **valid time** — その fact が modeled reality で真である時間。
- **transaction time** — その fact が database に記録され、database state の一部だった時間。

bitemporal relation はこの二つを同時に保持する。これにより現在の知識で過去を再構成する query と、**当時の database が何を知っていたか**を再現する query を区別できる。

現代の bitemporal database 実装でも、概念的には次の問いを分ける。

1. 今の current state は何か。
2. 今わかっている情報で、過去はどうだったか。
3. 過去のある時点で、当時はどう記録されていたか。

これは Kamimusuhi の canonical evidence / reinterpretation / correction / late-arriving observation に極めて直接的。

### (2) 何が提案・推測段階か

- 人間的 autobiographical memory の semantics が relational bitemporal DB と同じとは限らない。
- sensor event time、speaker-claimed time、world-valid time、arrival time、commit time、interpretation time をすべて二軸だけで表せるわけではない。
- Kamimusuhi の全 table を bitemporal 化すべきという結論ではない。storage / query complexity が増える。

### (3) Kamimusuhi の関連サブシステム

- Canonical Evidence / Self History
- episodic / relationship memory
- current-state projection
- supersession / correction / revocation
- incident replay
- Continuity Kernel audit
- ADR-C02 `event time / causality / episode ID / view version`

### (4) 借りられる設計・実装アイデア

少なくとも fact-like derived records で、次を分ける。

```text
TemporalFact
  proposition
  world_valid_from
  world_valid_to
  recorded_from       # transaction/knowledge time
  recorded_to
  evidence_refs[]
  confidence
  derivation_version
```

そして API/query mode を明示する。

```text
CURRENT
  今の最新知識で現在を答える

VALID_AS_OF(t)
  今の知識で「t時点の世界」を答える

KNOWN_AS_OF(k)
  k時点までに Kamimusuhi が持っていた記録だけで答える

KNOWN_AS_OF(k) + VALID_AS_OF(t)
  k時点の知識状態で、t時点の世界をどう捉えていたか
```

例:

```text
実際の引越し: 5/01
Kamimusuhi が聞いた: 5/20
訂正を知った: 6/03

world valid time != first observed/recorded time != correction commit time
```

これにより「5/10の住所は今わかっている限り何だった？」と「5/10当時、私は住所を何だと思っていた？」を分けられる。

### (5) Kamimusuhiとの差分

Kamimusuhi はすでに event time、arrival、commit、validity、supersession、historical interpretation を個別に意識しており、ADR-C02 も `clock/arrival/commit` 分離を候補化している。一方で **valid time × transaction/knowledge time の query semantics** はまだ明示的 contract になっていない。

したがってこれは新思想というより、散在している時間概念を database theory の既知の軸で整理する backfill である。

### (6) 次に検証すべきこと

`BitemporalMemoryBench`:

- late-arriving fact
- retroactive correction
- future-valid commitment
- wrong belief later corrected
- revoked relationship fact
- offline Edge が古い observation を後送

を用意し、`CURRENT / VALID_AS_OF / KNOWN_AS_OF / combined` query が期待通り分離されるか確認する。

特に、現在の正しい値を過去の self-state に retroactively 注入して「当時から知っていた」ことにしないことを検査する。

### (7) 既存デイリーサーベイではなぜ拾いにくいか

memory survey は retrieval / forgetting / embedding / consolidation に寄りやすく、database theory の **transaction-time semantics** はほぼ検索語に入らない。だが長寿命個体の autobiographical audit では重要。

### (8) 重要度

**A+** — 既存 ADR-C02 の設計をかなり明確にできる。全DBへの強制導入ではなく、canonical/derived fact contract と benchmark から始めるべき。
