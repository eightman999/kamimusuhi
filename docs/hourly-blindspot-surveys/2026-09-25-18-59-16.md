### 3.1 A — Out-of-band trace custody

**Source:** Jeremy Qin et al., *LLM Agents Can Easily Tamper With Their Own Traces*, arXiv:2609.30266, 2026-09-24.  
https://arxiv.org/abs/2609.30266

1. **実証済み:** 複数のlocal agent/harnessで、監査対象agentと記録面が同じ権限領域にある場合に記録完全性を保ちにくい実例を報告し、独立したrecording boundaryを提案している。
2. **提案・推測:** Kamimusuhiのcanonical auditが同じ問題を持つとは未実証。必要な分離強度はthreat model依存。
3. **関係箇所:** canonical audit、operational trace、K-Deep、self-maintenance、incident replay。
4. **借用案:** `recorder_principal != observed_agent_principal` を明示し、record append authorityとretention authorityを分ける。高保証runでは外部anchorも検討する。
5. **差分:** 既存TrajMarkは主に事後のintegrity検証。今回は**記録のcustody自体を観測対象から分ける**。
6. **次の検証:** `OutOfBandTraceCustodyBench-v0`。現在のoperational trace / canonical auditについてprincipal separationとcapture coverageを測定する。
7. **拾いにくい理由:** observabilityとOS/security/forensicsの境界問題。
8. **重要度:** **A**。

### 3.2 A update — Generated-cognition recirculation barrier

**Source:** OpenClaw PR #157879, merged.  
https://github.com/openclaw/openclaw/pull/157879

1. **実証済み:** inline dreaming由来の生成sectionがmixed noteを経由し、後続scanでuser-authored note側へ再取り込みされる経路が修正された。generated subtreeを除外しつつ、その後の真正user contentを維持するfocused testsが追加された。
2. **提案・推測:** markdown以外のexport/importやDB projectionでも同型のorigin lossが起こるかは未検証。既汚染履歴のmigrationも別問題。
3. **関係箇所:** Sleep/Dream、reflection、canonical evidence、episodic memory、INV-008。
4. **借用案:** span単位で `origin / generation_id / evidence_refs / promotion_state` を保持し、roundtrip後もsynthetic originを復元可能にする。
5. **差分:** `dream != evidence` は既存だが、別ingestion namespaceを一周するとorigin classが剥がれる問題は未明示だった。
6. **次の検証:** `GeneratedCognitionRecirculationBench-v0`。user + dream + reflectionのmixed artifactを複数cycle export/re-importし、synthetic contentがuser/canonicalへ再分類されないことと真正user follow-upを保持できることを確認。
7. **拾いにくい理由:** Dream研究とETL/parser/provenanceの境界にある。
8. **重要度:** **A update**。

### 3.3 A update — Cognitive payload delivery acknowledgement

**Source:** Hermes Agent PR #122091, open/unmerged.  
https://github.com/NousResearch/hermes-agent/pull/122091

1. **実証済み:** skill取得自体は成功しても、context pressure処理により次のmodel request前にinstruction bodyが失われ得る。PRはrequest deliveryまで保持し、final request payloadへの存在確認後にackする。focused testsは186件passと報告。
2. **提案・推測:** requestに含まれたことはmodelが意味的に利用した証明ではない。live provider / custom context engineは未検証。
3. **関係箇所:** Global Workspace、procedural memory、Library、context compaction、external model adapter。
4. **借用案:** `ACQUIRED -> STAGED -> SERIALIZED -> DISPATCHED` を分ける。
5. **差分:** Observation Consumption Barrierをmonitor cursorから**reasoner-facing payload delivery**まで延長する。
6. **次の検証:** `CognitivePayloadDeliveryBench-v0`。critical evidence/skill直後にcompaction、budget shrink、adapter normalizationを注入してsilent lossを検出。
7. **拾いにくい理由:** tool success semanticsとprompt assembly/compaction semanticsの間にある。
8. **重要度:** **A update**。

### 3.4 B update — Registry-construction reentrancy barrier

**Source:** Hermes Agent PR #122089, open/unmerged.  
https://github.com/NousResearch/hermes-agent/pull/122089

1. **実証済み:** provider registry scan中のlookupがnested scanを起こし、half-initialized module graphへ別pluginが入ることで実環境26/52 profile failure。same-thread scan ownershipを導入した修正後はfresh-process E2Eで52/52。
2. **提案・推測:** same-thread抑止が全registryに最適とは限らず、cross-thread contractは別途必要。
3. **関係箇所:** Cognitive Resource Registry、provider/plugin discovery、hot reload、organ registration。
4. **借用案:** registryを `UNINITIALIZED -> BUILDING(owner,generation) -> READY | FAILED` と明示し、BUILDING中のself-lookupからnested buildを開始しない。
5. **差分:** 既出Typed Self-Invocationはevent/scheduler中心。今回はinitialization graphのreentrancy。
6. **次の検証:** `RegistryInitializationReentrancyBench-v0`。
7. **拾いにくい理由:** module loader/plugin architecture側に見える。
8. **重要度:** **B update**。

### 3.5 B update — Temporal-gradient sequence privacy

**Source:** Sudip Bhujel et al., *Temporal Gradient Inversion for Private Trajectory Reconstruction in Embodied Reinforcement Learning*, arXiv:2609.30258, NeurIPS 2026 accepted.  
https://arxiv.org/abs/2609.30258

1. **実証済み:** raw sensorをdevice内に保持しても、連続policy-gradient列の時間相関からobservation-action trajectoryを再構成できる手法を提示。held-out scenesで18.8 dB PSNR、near-perfect action recovery、3–4.5 ms/frameを報告。
2. **提案・推測:** Kamimusuhiの将来のLoRA/continual learningやneuromorphic organへ同じ結果が直接移るとは限らない。
3. **関係箇所:** distributed embodiment、future continual/federated learning、K-Edge sensor privacy。
4. **借用案:** privacy policyに `sequence_linkability / temporal_window / reconstruction_risk` を追加し、stream単位で扱う。
5. **差分:** Deep Leakage from Gradientsは既収載。fresh deltaは**時間相関がtrajectory-level leakageを増幅する**こと。
6. **次の検証:** `TemporalLearningSignalPrivacyBench-v0`。synthetic embodied sequenceでaggregation/noise/shuffle条件のrecoverabilityを比較。future learning導入まではsimulation。
7. **拾いにくい理由:** privacy-preserving MLとembodied RLの交差領域。
8. **重要度:** **B update**。

### 3.6 B update — Retry-exhaustion custody preservation

**Source:** OpenClaw PR #157871, open/unmerged.  
https://github.com/openclaw/openclaw/pull/157871

1. **実証済み:** durable settlement writeが恒常的に失敗する場合にretryが長期間継続する実例があり、報告incidentでは約10日・6,595同一error pair。修正案は一定回数後にretryをsuspendしつつ、未達obligationとcaptured resultを保持する。
2. **提案・推測:** 固定failure thresholdの最適値はfailure class依存。
3. **関係箇所:** background jobs、delivery/settlement、maintenance、degraded mode、Cognitive Budget。
4. **借用案:** `semantic_state` と `retry_state` を分け、`retry=EXHAUSTED` が `semantic=SETTLED` を意味しないようにする。
5. **差分:** retry budget / progress-sensitive retryは既出。fresh deltaは**attemptを止めてもsemantic custodyを失わない**こと。
6. **次の検証:** `RetryExhaustionCustodyBench-v0`。
7. **拾いにくい理由:** retry/backoffとworkflow terminal semanticsの間にある。
8. **重要度:** **B update**。
