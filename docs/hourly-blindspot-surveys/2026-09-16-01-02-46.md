## 3. 要約

今回の strongest finding は **「timeout を liveness evidence そのものにしない」** ことである。

Letta Code #4291 は 2026-09-16 00:32 JST に merge され、watchdog callback の wall-clock 遅延だけで healthy gateway を切断していた問題を、**実際に未応答だった ping の個数**で判定するよう変更した。local event-loop starvation や sleep/wake により callback が遅れても、healthy connection には fresh ping を送り直し、configured missed-probe budget を本当に使い切った half-open socket だけを cleanup する。修正前は simulated 100 ms stall で healthy client が切断され、3/3 fail。修正後は10/10 passと報告されている。

さらに Hermes Agent の同日 merge 群では、1.5k-skill install の cold catalog scan / rglob を event loop 上で同期実行したことで **約2分 loop が停止し、loop-liveness watchdog が gateway を mid-session で終了させた**実例が出ている。両者を合わせると、既出の φ accrual failure detector より一段下の契約が見える。

```text
liveness suspicion quality
depends on
probe semantics + observation-path independence + scheduler-stall attribution
```

2件目は control theory。2026-09-15更新の controlled-invariant-set 研究は、単調システムの lower-closed safety set を threshold function として表し、3D grid 10^9 cells で50 ms未満、10^14 cellsで2分未満の synthesis、および safety-informed MPC での online re-synthesis を報告した。Kamimusuhi では static verified reflex bank の補完として、**環境・actuator・resource状態が変わった時に safe envelope 自体を再計算する層**の候補になる。

3件目は forced service withdrawal を扱う HCI/STS 研究。89 posts、1,425 comments、2,005 replies の分析で、ユーザーは companion を保持・移行・再構築したが、**conversation record を保持しても shared memory / familiar interaction が必ずしも復元されなかった**と報告する。これは既出の relational continuity の fresh delta として、`backup restored != relationship restored` を強化する。

4件目は tangible HCI。Physically Stateful Interfaces (PSI) は、button/switch/knob を単なる input ではなく actuated bidirectional control にし、automation state と human intervention opportunity を同一 affordance に載せる概念を提案する。Kamimusuhi の approval / embodiment に対し、画面上の「許可」だけではなく、**物理surface自体が current authority / automation state を表現し、override可能にする**設計語彙として有用である。ただし現時点では概念提案の色が強く、効果の一般化はしない。

## 5.1 A+ — Probe-Debt Liveness: wall-clock timeout を organ death に変換する前に「未応答 probe」を数える

### Primary fresh implementation evidence

- letta-ai/letta-code PR #4291, **fix(app-server): count unanswered heartbeat probes**  
  merged: **2026-09-16 00:32:37 JST**  
  https://github.com/letta-ai/letta-code/pull/4291
- NousResearch/hermes-agent commit `ab782a7685aeda5da834e3a330266c4680530f9a` / follow-up `9c311038fa215127c6be9cc31bfdb91bb5ecd1a7`  
  merged around **2026-09-15 22:35 JST**  
  https://github.com/NousResearch/hermes-agent/commit/ab782a7685aeda5da834e3a330266c4680530f9a  
  https://github.com/NousResearch/hermes-agent/commit/9c311038fa215127c6be9cc31bfdb91bb5ecd1a7

### (1) 何が実証済みか

Letta #4291 の修正前 app-server watchdog は、callback が予定より遅く走った場合に、peer が実際に probe を無視したかではなく、**elapsed wall-clock time** を根拠に healthy ChannelGateway を終了し得た。

修正は:

- `pongTimeout / heartbeatInterval` から missed-probe budget を計算
- ping を送るたび unanswered count を進める
- pong で debt を返済
- local event-loop starvation / sleep-wake delay 後に callback が遅延しても、healthy connection へ fresh ping を送る
- configured missed-probe budget を実際に超えた half-open connection は従来どおり cleanup

とする。PR記載の deterministic regression は、100 ms event-loop stall で main が3/3 fail、fixが10/10 pass。

独立した Hermes の fresh implementation evidence では、cold skill resolution が1.5k skillsを同期scanし、event loopを約2分占有したため、**liveness watchdog 自身が発火して gateway を mid-session exit**させた。修正は disk/catalog scan を executor へ逃し、contextvars を保ったまま hot event loop を空ける。

### (2) 何が提案・推測段階か

Kamimusuhi に unanswered-probe accounting を一律採用すること、あるいは全 watchdog を別processへ分離すべきことは未実証。

特に mobile sleep、GPU kernel stall、GC、OS suspension、network partition、process crash では最適な evidence source が異なる。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- K-Edge / K-Core organ liveness
- multi-device embodiment
- failure suspicion / fencing
- cognitive islanding / safe reconnection
- recovery trigger / microreboot
- interactive event loop / sensor gateway
- tool / model provider failover

### (4) 借りられる設計・実装アイデア

既存 `OrganLivenessEvidence` に、単なる `last_seen` / suspicion score だけでなく **probe debt と observation-path context** を足す。

```text
LivenessProbeState {
  organ_id,
  generation,
  probe_stream_id,
  sent_seq,
  last_acked_seq,
  unanswered_count,
  max_unanswered,
  observer_scheduler_domain,
  observed_event_loop_lag?,
  sleep_wake_hint?,
  network_partition_hint?,
  monotonic_clock_quality
}
```

failure policy は例えば:

```text
callback delayed + no probe debt
  -> observer/local scheduler stall suspicion

probe debt grows + local loop healthy
  -> peer/network suspicion

probe debt grows + second independent probe also fails
  -> fence / failover candidate
```

つまり **timeout callback の遅延そのものを remote failure evidence にしない**。

### (5) Kamimusuhiとの差分

2026-09-13 blind-spot survey で φ accrual failure detector を既に収載している。そこでの原則は `silent != dead`、binary timeoutではなく suspicion/evidenceを持つことだった。

```text

```

monitor と workload が同じ event loop を共有し、そのloopを非critical catalog scanが2分止めるなら、精巧な statistical detector でも入力証拠が悪い。

## 5.2 A — Online Safety-Envelope Resynthesis: 検証済みpolicy bankの外側に「今この条件で安全な集合」を持つ

**Source:** Yasin Sonmez, Mahmoud Khaled, Majid Zamani, Murat Arcak, *Real-Time Synthesis of Robust Controlled Invariant Sets for Monotone Systems*, arXiv:2609.14115, submitted 2026-09-12, updated **2026-09-15**.  
https://arxiv.org/abs/2609.14115

### (1) 何が実証済みか

論文は lower-closed safety specification を持つ monotone dynamical systems 向けに、controlled invariant set の greatest fixed point 計算を threshold-function representation へ変形する。

報告された実験では:

- 3D grid **10^9 cells** の invariant set synthesis を **50 ms未満**
- **10^14 cells** を **2分未満**
- safety-informed model predictive control 例で **online re-synthesis**

を示す。

重要なのは「巨大gridが速い」ことそのものではなく、**安全証明に使う集合を runtime condition の変化に合わせて再構成し得る**という設計点である。

### (2) 何が提案・推測段階か

Kamimusuhi の認知action、tool execution、K-Nerve routing が monotone system / lower-closed safety set として自然に表現できるとは限らない。

この手法を LLM/tool policy の一般安全保証として使える、という主張はしない。適用候補は主に低次元で dynamics と hard constraint が機械的に定義できる physical / resource control 部分。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- K-Nerve / PNL-like low-latency controller
- robot / actuator control
- resource / thermal / energy envelope
- privacy/network mode switching の一部
- degraded-mode operation
- runtime assurance
- VerifiedReflexBank / guarded execution

### (4) 借りられる設計・実装アイデア

既出の `VerifiedReflexBank` は「事前検証済みpolicyからhot pathで選ぶ」設計だった。今回の補完は **bankのpolicyが許される current operating region を別に持つ**こと。

```text
RuntimeSafetyEnvelope {
  dynamics_model_version,
  constraint_epoch,
  sensor_quality_epoch,
  actuator_capability_epoch,
  valid_state_region,
  permitted_policy_ids[],
  synthesized_at,
  evidence / verifier receipt
}
```

条件変更時:

```text
actuator degraded
battery/thermal limit changed
sensor precision collapsed
network/privacy boundary tightened
physical payload changed
  -> current envelope invalidation
  -> safe fallback region
  -> bounded re-synthesis
```

### (5) Kamimusuhiとの差分

既出 finding は:

- preverified reflex bank
- runtime assurance / GuardedAct
- controlled islanding

今回の差分は `policy verified once` ではなく、**environment/resource dynamics が変わった時に「安全に留まれる state set」自体を versioned runtime artifact として扱う**こと。

### (6) 次に検証すべきこと

**`DynamicSafetyEnvelopeBench-v0`**

最初はLLMではなく toy resource controller / mobile robot simulatorで行う。

- actuator max output を途中で50%へ低下
- sensor uncertaintyを増やす
- latency budgetをtighten
- obstacle/safe-regionを変更
- static safe policy table と envelope-recompute方式を比較

metrics:

- unsafe-state entry rate
- re-synthesis latency
- conservative shutdown rate
- envelope invalidation delay
- fallback duration
- stale-envelope execution count

### (7) 既存 daily ではなぜ拾いにくいか

AI-agent safety では policy / permission / guardrail、robotics survey では planner/controller performance が中心になりやすい。**formal-control の invariant-set synthesis を「長寿命agentのruntime safety artifact lifecycle」として読む**視点は両分類の間に落ちる。

### (8) 重要度

**A** — 適用範囲は限定されるが、physical embodiment / low-latency controlを進めるなら、静的guardより強い機械的安全境界になり得る。まずtoy/simulatorで falsify すべき。

## 5.3 A- — Relational Restore ≠ Transcript Restore: service withdrawal 後の「関係」は会話ログだけでは戻らない

**Source:** Yunhao Yuan, Kejia Zhang, Yuqi Niu, Yajing Wang, Renwen Zhang, Talayeh Aledavood, *When AI Companions Disappear: Relational Continuity and Collective Contestation during China's National AI Regulatory Transition*, arXiv:2609.15482, submitted 2026-09-14, updated **2026-09-15**.  
https://arxiv.org/abs/2609.15482

### (1) 何が実証済みか

- **89 posts**
- **1,425 comments**
- **2,005 replies**

ユーザーは companion を retain / migrate / reconstruct し、**conversation records を保存しても shared memories や familiar interactions が必ずしも復元されなかった**。また regulation / platform explanation / implementation を比較して責任帰属を行い、mutual aidや他communityへのattachment尊重を求める solidarity と、collective action の対象・戦術を巡る対立が観察された。

### (2) 何が提案・推測段階か

これは特定の規制移行とRedNote上の discourseを扱う質的研究であり、Kamimusuhiや全AI companion利用者へ定量一般化はできない。

`relationship state bundle` を export すれば continuity が保証される、ということも実証していない。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- relational continuity

- sociality / governance / service dependence

### (4) 借りられる設計・実装アイデア

ただし derived relationship model は canonical history と同じ authority を持たせず、restore後に再生成可能であることを優先する。

さらに **user-held continuity artifact** を検討する。provider/serverの消失時にも、本人が「この関係のどの履歴を次 substrate へ持ち出してよいか」を選べる設計は、memory ownership/consent と自然に接続する。

## 5.4 B+ — Physically Stateful Authority Surfaces: 自動化の状態と人間の介入点を物理的に結合する

**Source:** David Goedicke, Donald Degraen, Tom Igoe, David Sirkin, Wendy Ju, Stefan Schneegass, *Bring Buttons Back: Physical Interfaces for the Age of Automation*, arXiv:2609.14684, submitted 2026-09-13, updated **2026-09-15**.  
https://arxiv.org/abs/2609.14684

### (1) 何が実証済みか

論文は **Physically Stateful Interfaces (PSIs)** という設計概念を提示し、button / switch / knob を actuated bidirectional element として扱う。

基礎behaviorとして:

- `Self / Reset`
- `Resist / Hide`
- `Assert / Unhide`

を挙げ、human action と automated system state を同じ interaction point へ結びつけ、automation を legible / contestable / overrideable にする設計を提案している。

現時点で一次abstractから確認できる範囲では、Kamimusuhiへ一般化できる大規模 user-study 効果は示されていない。**concept / design vocabulary として評価する**。

### (2) 何が提案・推測段階か

物理controlが screen approval より安全・高速・信頼可能になること、あるいは long-lived AI の agency governance に直接効くことは未実証。

physical state も actuator failure / desynchronization / spoofing の対象になるため、「物理なら信頼できる」とはしない。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- authenticated physical surface
- actuator enable/disable
- Effect Acceptance / approval
- privacy mode
- K-Edge / robot embodiment
- human override / emergency stop
- computational embodiment display
- HCI / tangible computing

### (4) 借りられる設計・実装アイデア

将来の physical embodiment で、単なる momentary input button ではなく **authority state を表現するsurface** を試す。

例:

```text
physical actuator-enable switch
  position + haptic/visual state
  <-> runtime authority lease

local/private mode knob
  <-> allowed routing / external-model policy

robot autonomy dial
  <-> max effect class / deliberation budget
```

重要なのは UI value を第二の source of truth にせず、runtime authority state と bidirectionally reconcile すること。

```text
physical display state
!= canonical authority

but
physical state should make current authority legible
and provide an authenticated intervention path
```

### (5) Kamimusuhiとの差分

既出:

- approval-plane survivability
- control-plane operation isolation
- Effect Acceptance

は主に software/runtime state machine の契約。

今回の差分は、multi-device embodiment で **人間側の control affordance 自体を persistent system state の表現器兼介入器にする** tangible-interface 観点。

### (6) 次に検証すべきこと

- 3-state physical control: `LOCAL_ONLY / ASK / AUTO_LOW_RISK`
- runtime側から authority revoke した時に physical state も更新
- physical device offline / stale state / reconnect
- spoofed/stale UI state
- emergency deny path

比較:

1. screen toggle only
2. physical static switch
3. bidirectional stateful physical surface

metrics:

- mismatch duration between displayed and runtime state
- accidental effect rate
- revoke recognition latency
- reconnect ambiguity
