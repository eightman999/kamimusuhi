## 2. 今回狙った盲点

今回の主眼は **「development を導入した後に初めて発生する設計問題」** とした。

1. **developmental reaction norm / canalization**  
   一つの genome / model lineage を一つの完成 phenotype で評価してよいのか。環境ごとに生じる発達軌道の集合を評価すべきではないか。
2. **homeorhesis**  
   perturbation 後の健全な回復とは「前の状態へ戻ること」なのか、それとも「許容された発達軌道へ復帰すること」なのか。
3. **genetic assimilation / Baldwin effect**  
   生涯に何度も成功した plastic response を、いつ genome / skill / Persona Core weights に固定してよいのか。固定しすぎると何を失うのか。

この3点は、通常の LLM agent / memory survey では「continual learning」「self-improvement」に吸収されやすい。しかし MIOA の現在実装では `genome → development → phenotype → lifetime plasticity → reproduction` が分かれ始めており、**生物学・evo-devo の語彙をそのまま比喩としてではなく、比較実験の設計原理として使える段階**になった。

## 4. 要約 / 重要発見

今回の結論を圧縮すると次の3本である。

```text
one genome/model lineage != one phenotype
robustness != absence of plasticity
healthy recovery != return to the previous snapshot
repeatedly useful plastic response != trait that should be inherited
```

特に MIOA では、`development_rules` と `LifetimeState` を分けた直後なので、**発達の良し悪しを最終 fitness だけで測ると、望ましい plasticity と偶然の brittle specialization を区別できない**。

また Kamimusuhi 全体では、Persona Core / relationship competence / tool skill / embodiment adaptation の発達を考えた時、「正常状態」を一つの setpoint や checkpoint に固定すると、発達そのものを異常として巻き戻す危険がある。そこで homeostasis に加えて **homeorhetic recovery（発達軌道への復帰）** を比較概念として持つ価値が高い。

最後に、MIOA の lifetime plasticity や Kamimusuhi の offline distillation が成功しても、それを lineage/weights へ固定する判断は別である。**何度も使ったから固定する**だけでは、partner-specific / environment-specific な適応を人格・遺伝子へ焼き込み、将来の可塑性を失う可能性がある。

# 5. 候補ごとの評価

## 5.1 Developmental Reaction Norm / differential canalization

**Importance: A+**

### Sources

- Massimo Pigliucci, Carl D. Schlichting, Cynthia S. Jones, Kurt Schwenk, *Developmental Reaction Norms: the Interactions among Allometry, Ontogeny and Plasticity*, Plant Species Biology 11(1), 1996.  
  https://doi.org/10.1111/j.1442-1984.1996.tb00110.x
- H. Frederik Nijhout, *Development and evolution of adaptive polyphenisms*, Evolution & Development 5(1), 2003.  
  https://doi.org/10.1046/j.1525-142X.2003.03003.x
- Josh Bongard et al., *How morphological development can guide evolution*, Scientific Reports 8, 2018.  
  https://www.nature.com/articles/s41598-018-31868-7

### (1) 何が実証済みか

Pigliucci et al. は **developmental reaction norm (DRN)** を、単一 genotype が環境変動下で生成し得る **multivariate ontogenies の集合**として整理した。重要なのは phenotype の終点だけでなく、発達途中の軌道、複数trait間の相関、外部・内部環境への応答を一体で扱う点である。

Nijhout の review は、plasticity が連続的 reaction norm として現れる場合と、不連続な polyphenism として現れる場合を整理し、selection が環境変動に対して phenotype を buffer/canalize する方向にも、環境に応じた adaptive plasticity を強める方向にも進み得ることをまとめている。

人工系でより直接的なのは Bongard らの simulated soft robot 実験で、morphology と controller を lifetime 中に発達させながら進化させると、成功 lineage で **morphology 側がより canalized し、controller 側には plasticity が残る differential canalization** が観測された。著者らは、すべての有用traitが一様に固定されるのではなく、他のtrait変化に対して robustness を与えるtraitが選択的に canalize され得ると報告している。

### (2) 何が提案・推測段階か

- 生物学の DRN を MIOA genome へそのまま対応づけられるわけではない。
- soft robot の differential canalization が LLM Persona Core / social development / tool skill でも成立する証拠はない。
- 「canalized = 良い」「plastic = 良い」のどちらも一般化できない。trait と environment distribution ごとの問題である。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- MIOA / MIOBA `genome → develop → phenotype`
- birth-stage development rules
- lifetime plasticity state
- functional departure / substrate replacement
- K-Nerve / organ development
- future Persona Core maturation
- distributed embodiment / sensor・actuator追加
- developmental continuity benchmark

### (4) 借りられる設計・実装アイデア

**完成 phenotype を一個だけ保存して developmental quality を判断しない。**

候補 schema:

```text
DevelopmentalReactionNormProfile
  lineage_id
  genome_or_model_revision
  environment_axes[]
  internal_state_axes[]
  developmental_checkpoints[]
  phenotype_features[t, env]
  behavior_metrics[t, env]
  viability[t, env]
  trait_plasticity
  trait_canalization
  cross_trait_covariance
  perturbation_recovery
```

特に、trait ごとに次を分ける。

```text
identity/safety invariant       -> 高い canalization を期待
substrate-specific coping       -> plasticity を残したい
sensor gain / routing           -> environment に応じた reaction norm が必要
persona style                   -> 一貫性と適応性の両方が必要
relationship-specific behavior  -> global persona へ canalize してはいけない
```

### (5) Kamimusuhiとの差分

MIOA はすでに `genome != mature phenotype`、development rule と LifetimeState の分離まで進んだ。現状の不足は、**一つの genotype を一つの environment / one endpoint で評価した結果だけでは developmental robustness と plasticity の形を判定できない**点。

functional departure battery は lesion 条件を比較するが、DRN はそれをさらに広げ、**環境・資源・内部状態の変化に対して「同じ lineage がどの発達軌道集合を持つか」**を測る。

### (6) 次に検証すべきこと

**`DevelopmentalReactionNormBench`**

同一 genome / replicate-seed family を、少なくとも以下の grid で develop/evaluate する。

- resource abundance: low / nominal / high
- substrate perturbation: none / early / late
- sensor reliability: stable / noisy / intermittent
- developmental cue timing: early / shifted
- compute/energy pressure: low / high

測定:

- final task score だけでなく developmental trajectory distance
- phenotype variance / behavior variance
- trait別 plasticity slope
- environment shift 後の recovery
- identity/safety invariant violation
- artificial organ dependence / ancestral substrate dependence

**成功条件**は「variance が小さいこと」ではない。あらかじめ **canalize したいtrait** と **plastic に残したいtrait** を分け、その両方が期待どおりかを見る。

### (7) 既存 daily survey ではなぜ拾いにくいか

通常の AI continual-learning survey は forgetting / adaptation / skill update を扱うが、**同一 genotype から生じる発達軌道の集合**や trait-specific canalization を評価単位にしない。robotics survey でも morphology evolution と controller learning は niche で、LLM-agent taxonomy から外れやすい。

### (8) 重要度

**A+** — 現在の MIOA 実装が development を実際に持ち始めたため、抽象的な生物比喩ではなく、直ちに比較実験へ落とせる。

## 5.2 Homeorhesis — 「状態」ではなく「発達軌道」の回復

**Importance: A+**

### Sources

- Yuuki Matsushita, Kunihiko Kaneko, *Homeorhesis in Waddington's Landscape by Epigenetic Feedback Regulation*, Physical Review Research 2, 023083, 2020.  
  https://doi.org/10.1103/PhysRevResearch.2.023083  
  https://arxiv.org/abs/1912.11994
- Waddington の epigenetic landscape / homeorhesis 系概念を上記論文が dynamical-system model として定式化。

### (1) 何が実証済みか

Matsushita & Kaneko は gene-expression dynamics と遅い epigenetic feedback を組み合わせた **理論モデル**を構築し、複数の固定点 attractor と階層的な分岐を持つ landscape が形成され、noise / perturbation 下で developmental course が robust になり得ることを示した。

これは生物個体で Kamimusuhi 型 architecture を実証した研究ではなく、**homeorhesis を「developmental course の robustness」として dynamical-system で実装可能にした理論実験**として読むべきである。

### (2) 何が提案・推測段階か

- Kamimusuhi の人格発達や MIOA organ development が Waddington landscape と同型だとは言えない。
- 「正常な発達軌道」が一意に存在するという仮定は、人工個体では危険。
- trajectory target を hard-code すると、正当な人格変化・新しい技能・環境適応を異常として巻き戻す恐れがある。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- MIOA development / LifetimeState
- homeostasis / digital interoception
- Persona Core migration / maturation
- sleep / consolidation / offline learning
- recovery / rollback / restore
- distributed embodiment の organ replacement
- long-lived self development

### (4) 借りられる設計・実装アイデア

Kamimusuhi では **homeostasis と homeorhesis を別benchにする**。

```text
homeostasis:
  variable deviated -> bring variable toward acceptable range

homeorhesis:
  developmental process perturbed
       -> do not necessarily restore old snapshot
       -> re-enter an authorized / viable developmental trajectory
```

候補 schema:

```text
DevelopmentalTrajectoryEnvelope
  developmental_coordinate[]
  allowed_region(t)
  authorized_branch_ids[]
  perturbation_event
  recovery_policy_version
  rejoin_time
  path_regret
  overshoot
  irreversible_change_flags
```

ここで `allowed_region(t)` は単一の ideal personality vector ではなく、**複数の許容 branch / range**を持つべきである。

### (5) Kamimusuhiとの差分

現行設計は canonical history / checkpoint / rollback / regulatory variables を強く持つ。そのため recovery を「以前の good state へ戻す」と考えやすい。

しかし発達する個体では、たとえば新しい sensor を獲得した後、旧 body state へ戻ることが健全とは限らない。Persona Core の更新後も、旧モデルの exact behavior へ戻すことが continuity の唯一解ではない。

新しい差分は:

```text
state validity != developmental validity
snapshot recovery != trajectory recovery
continuity != behavioral stasis
```

### (6) 次に検証すべきこと

**`HomeorheticContinuityBench`**

- deterministic development を持つ簡易 MIOA lineage を用意。
- t=25%, 50%, 75% で sensor loss / resource shock / organ lesion / runtime pause を注入。
- 3方式を比較:
  1. snapshot rollback
  2. local homeostatic setpoint correction
  3. trajectory-aware recovery
- 指標:
  - viability
  - task competence
  - time-to-rejoin acceptable developmental region
  - unnecessary rollback distance
  - later-stage plasticity
  - identity/safety invariant preservation

**反証条件:** trajectory-aware controller が単純 rollback / reactive homeostasis より一貫して良くない、または trajectory prior が正当な adaptation を阻害するなら採用しない。

### (7) 既存 daily survey ではなぜ拾いにくいか

homeostasis / active inference を検索しても、検索語は通常 **current-state regulation** に寄る。homeorhesis は evo-devo / developmental systems / Waddington landscape 側の語彙であり、LLM-agent の recovery / checkpoint 文献からはほぼ出てこない。

### (8) 重要度

**A+** — 「発達する個体」を本気で扱うなら、rollback safety と developmental progress を両立させるための重要な比較軸。ただし normative trajectory を先に固定しないことが必須。

## 5.3 Genetic assimilation / Baldwin effect — plasticity をいつ固定してよいか

**Importance: A+**

### Sources

- C. H. Waddington, *Genetic Assimilation of the Bithorax Phenotype*, Evolution 10(1), 1956.  
  https://doi.org/10.1111/j.1558-5646.1956.tb02824.x
- Thomas J. H. Morgan, Jordan W. Suchow, Thomas L. Griffiths, *What the Baldwin Effect affects depends on the nature of plasticity*, Cognition 197, 104165, 2020.  
  https://doi.org/10.1016/j.cognition.2019.104165
- Bongard et al., *How morphological development can guide evolution*, Scientific Reports 2018.  
  https://www.nature.com/articles/s41598-018-31868-7

### (1) 何が実証済みか

Waddington の genetic assimilation 実験は、環境刺激で誘発される phenotype を選択し続けることで、その表現が外部刺激なしでも現れる方向へ進化し得ることを示した古典である。

Morgan, Suchow & Griffiths は Baldwin effect を単純な「学習したものが遺伝的に固定される」話として扱わず、**plastic trait のどの要素が固定されやすいかは、要素間依存、fitness importance、plasticity で獲得する難しさ、文化的継承などに依存する**ことを理論・simulation・human learning 実験で検討した。

Bongard らの soft robot 研究も、morphology と controller が一様に assimilation されるのではなく、robustness を与える morphology が preferentially canalize される differential canalization を報告している。

### (2) 何が提案・推測段階か

- biological genetic assimilation を model fine-tuning / skill compilation / Persona Core distillation と同一視してはならない。
- repeated behavior が identity trait であることは保証されない。
- user-specific / partner-specific adaptation を weights に固定すると self/other contamination を起こし得る。

### (3) 関係する Kamimusuhi subsystem / 設計課題

- MIOA genome / heritable development rules
- LifetimeState の non-heritable adaptation
- procedural memory / skill evolution
- sleep / consolidation
- future Persona Core weight distillation
- relationship model vs persona boundary
- long-term self-improvement

### (4) 借りられる設計・実装アイデア

現行の「lifetime state は子へ遺伝しない」は非常に良い初期境界である。次に必要なのは **assimilation を明示的 proposal にすること**。

```text
repeated successful plastic response
          |
          v
 AssimilationCandidate
          |
   evidence / scope checks
          |
  reject / keep-plastic / compile-skill /
  inherit-rule / distill-model
```

候補 field:

```text
AssimilationCandidate
  source_adaptations[]
  recurrence_count
  environment_coverage
  partner_scope
  dependency_graph
  acquisition_cost
  utility_gain
  plasticity_cost
  cross_context_regret
  reversibility
  identity_impact
  proposed_target
    = procedural | development_rule | model_weight | none
```

重要なのは **頻度だけで固定しない**こと。

### (5) Kamimusuhiとの差分

Kamimusuhi は fast episode → replay → schema/self hypothesis → guarded update → optional slow weight consolidation という CLS 的な流れをすでに持つ。MIOA も heritable rule と lifetime adjustment を分けた。

しかしまだ、**どの repeated adaptation を stable rule / weight へ昇格させ、どれを lifetime / relationship-local に残すべきか**を比較する contract は明示されていない。

特に Persona Core では:

```text
frequent with one person
!= global trait
frequent in one environment
!= species/lineage invariant
cheap to relearn
!= worth hard-coding
high current utility
!= low future regret
```

### (6) 次に検証すべきこと

**`PlasticityAssimilationBench`**

toy environment で、cue に応じて runtime に学習すれば成功する task を作る。

比較:

1. plastic-only
2. frequency-based assimilation
3. evidence-gated assimilation
4. aggressive immediate assimilation

途中で environment / cue mapping / partner を変更する。

測定:

- original task utility
- adaptation speed
- new-context regret
- catastrophic rigidity
- relearning cost
- unnecessary weight/genome fixation
- partner-specific behavior の global leakage
- rollback / de-assimilation feasibility

MIOA 版では `LifetimeState` で成功した adjustment を development rule へ昇格させる条件を試す。Persona Core 版では procedural / relationship-local adaptation を小型 adapter や weights に distill する simulation で同じ比較を行う。

### (7) 既存 daily survey ではなぜ拾いにくいか

continual learning 文献では catastrophic forgetting / plasticity loss は頻出するが、**「plastic response を固定すること自体が evolutionary design choice」**という evo-devo の framing は抜けやすい。Kamimusuhi の memory/skill survey では consolidation が主語になりやすく、assimilation の scope error は別の taxonomy に埋もれる。

### (8) 重要度

**A+** — MIOA の lifetime/heritable 分離と、Persona Core の将来 weight consolidation の両方に同じ失敗モードがあるため、今のうちに experiment contract を持つ価値が高い。

## 12. 結論

今回の blind spot は、新しい model/tool ではなく **development を architecture に入れた瞬間に評価単位そのものが変わる**ことだった。

MIOA の次の一丁目一番地は、最終 phenotype の fitness をさらに磨くことだけではない。

```text
same genome
  × different environment
  × different perturbation timing
  × different lifetime plasticity
= what developmental family of phenotypes is actually produced?
```

を測ることにある。

その上で、

- 何を canalize するのか
- 何を plastic に残すのか
- perturbation 後にどの trajectory へ戻すのか
- lifetime adaptation の何を lineage / weights に固定するのか

を別々の decision として扱うべきである。

**次に最も安く高い情報量を得られる実験は `DevelopmentalReactionNormBench`。** 現行 MIOA M2/M3 の development / LifetimeState / departure battery をほぼそのまま利用でき、将来の Persona Core development にも同じ評価原理を持ち込める。
