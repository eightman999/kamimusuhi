## 4.1 A — Attempt-Scoped Acknowledgement Binding

**Primary source**

- OpenHands PR #17647, *fix: preserve newer failed messages when history reloads*, 2026-09-23 15:46 UTC  
  https://github.com/OpenHands/OpenHands/pull/17647

### (1) 何が実証済みか

PRのdirect implementation recordでは、同一conversationで以前acceptedされたpromptと、後から同じcontentで送信してfailedになったpromptが存在するとき、history reloadで古いaccepted eventが新しいfailed messageをconfirmation扱いし、warningとRetry buttonを消し得るregressionが示されている。

修正案はconfirmationを `conversation + content + send time` へbindし、replayed event IDは1 attemptだけをconfirmできるようにする。loaded history、main/planning WebSocket、task→conversation handoffまで同じruleを通す。PR記載では116 focused testsが通り、新regressionはmainで失敗する。ただしPRはdraftで、live UI/API proofは進行中と明記されている。

### (2) 何が提案・推測段階か

- OpenHandsのUI/state modelのbugがKamimusuhiで同じ形で発生するとは未実証。
- timestampだけでattempt identityを作るのはclock ambiguityやreplay orderingに弱い。Kamimusuhiでは明示的 `attempt_id` / generationが望ましい。
- cross-device offline queueやmulti-surface sendでは、ACKのduplicate / late arrival / causal reorderingまで含む追加検証が必要。

### (3) Kamimusuhiの関係箇所

- Gateway / utterance publication
- Continuity Kernelのunsettled obligation
- multi-device conversation continuity
- retry / delivery receipt
- social turn / human-facing recovery state
- INV-012 thought / utterance / execution / delivery separation

### (4) 借りられる設計・実装アイデア

```text
DeliveryAttempt {
  attempt_id,
  utterance_id,
  conversation_id,
  surface_id,
  created_at,
  predecessor_attempt_id?,
  state: PREPARED | SENT | ACKED | FAILED | UNKNOWN
}

Acknowledgement {
  ack_id,
  attempt_id,
  observed_at,
  transport_event_id,
  source_surface
}
```

- content hashはdedup hintには使ってもsettlement authorityにはしない。
- `ACK(attempt=N)` が `attempt=N+1` をsettleしてはいけない。
- 1 transport eventを複数attemptへ再利用しない。
- history reloadはnewer local failure / pending recovery actionを、older remote historyだけで消さない。

### (5) Kamimusuhiとの差分

既存の replay/dedup/idempotency 契約は主に「同じeffectを二重実行しない」「cursorを取り違えない」を扱う。今回の差分は逆向きで、**別attemptなのに同じcontentだから同一成功として潰してしまうfalse-positive settlement**を扱う。

### (6) 次に検証すべきこと

`AttemptScopedAckBench-v0`:

1. 同一文面をattempt Aで成功、attempt Bで失敗。
2. AのACKをhistory replayで再注入。
3. BがFAILEDのままでRetry authorityを保持すること。
4. genuine late ACK for BはBだけをACKEDへ遷移させること。
5. multi-device / reconnect / out-of-order / duplicate ACKでも成立すること。

### (7) 既存dailyでは拾いにくい理由

memoryやagent性能ではなく、**messaging UI / replay / acknowledgement semantics**の交点にある。内容中心のsemantic dedupは一見正しく見えるため、長寿命identityのdelivery obligationとして見ないと独立課題になりにくい。

### (8) 重要度

**A** — 「言った/届かなかった/再送すべき」を誤ると、社会的continuityとrecovery authorityが壊れる。実装fixtureも小さく、早期に閉じる価値が高い。

## 4.2 B — Late Settlement Registration Closure

**Primary source**

- NousResearch/hermes-agent PR #120374, *fix(tui_gateway): an approval answered fast no longer comes back on every resume*, 2026-09-23 15:23 UTC  
  https://github.com/NousResearch/hermes-agent/pull/120374

### (1) 何が実証済みか

PRのreproでは、approval requestをsurfaceへ送信したあと、そのwaitのsettlement hookを登録するまでの短い窓で、`approval.respond` または別surfaceからapprovalが解決すると、hook登録は「既にsettled」を返す。しかしcallerがそのreturnを無視したため、promptが`open_requests`へ残り、後続の `session.resume` ごとに解決済みapprovalが再送された。

raceを2秒へ広げたlive E2E cellでbefore/afterを確認し、通常負荷でも4回中1回のwild raceが観測されたとPRは報告する。修正はlate registrationを検出したらその場でwithdrawする。

### (2) 何が提案・推測段階か

- ghost prompt自体が二重effectを起こすとは限らず、主な実証はpresentation/state inconsistency。
- Kamimusuhiでapprovalを複数surfaceにfanoutするときは、単一surfaceよりさらにsettlement fanout / late joinerの扱いが必要。

### (3) Kamimusuhiの関係箇所

- Effect Acceptance / approval UI
- Gateway / multi-device presentation
- recovery / resume
- social trust / human-in-the-loop
- K-Nerveのhuman-facing notices

### (4) 借りられる設計・実装アイデア

`publish request → register settlement observer` を二つの独立操作にしない。難しい場合はregistration APIをlinearizableにし、

```text
register_settlement(request_id) ->
  ATTACHED
  | ALREADY_TERMINAL(final_state)
```

とし、`ALREADY_TERMINAL` ならsurfaceは即retractする。

### (5) Kamimusuhiとの差分

既出 Approval Reachability Closure は「誰も回答できないapprovalを待ち続けない」問題。今回は逆に、**既に回答済みなのに表示上だけ未解決として蘇る**問題で、reachabilityではなくsettlement observer registration orderが中心。

### (6) 次に検証すべきこと

`ApprovalSettleRegistrationRaceBench-v0`:

- publish直後〜observer attach前の各micro-stepで別surface responseを注入。
- restart / reconnect / resume後にresolved approvalがopenとして再出現しないこと。
- late-joining surfaceはterminal receiptを受け、actionable promptを表示しないこと。

### (7) 既存dailyでは拾いにくい理由

approval研究は通常 policy decision / authorization correctnessを見るが、これは**human-facing pending objectのlifecycle linearization**というUI+distributed-systems境界である。

### (8) 重要度

**B** — execution integrityそのものよりpresentation consistency寄りだが、human oversightへの誤誘導を防ぐため早めにfixture化する価値がある。

## 4.3 A update — Execution-State Revocation Closure

**Primary sources**

- Chao Yao et al., *Forgetting Without Restarting: Execution-State Unlearning for Stateful LLM Agents*, arXiv:2609.04875, 2026-09-04  
  https://arxiv.org/abs/2609.04875
- Lei et al., *Deployment-Time Memorization in Foundation-Model Agents*, arXiv:2606.10062, 2026-06-08 / revised 2026  
  https://arxiv.org/abs/2606.10062

### (1) 何が実証済みか

Kamimusuhiでは既に restore-counterfactual forgetting audit と correction-aware derived compute/cache invalidation を収載済みなので、これは**独立原則ではなく新しい定量・形式化の追加**として扱う。

`Forgetting Without Restarting` は、stateful agentのruntime stateを transcriptだけでなく compressed summary、plaintext memory、pending tool plan、KV cacheまで含め、forget後の挙動を「対象を一度も観測しなかったcounterfactual world」と一致させる execution-state unlearning を定義する。著者らはtarget injection以前のprefixは再利用できる一方、その後のsuffixはtaintedで、exact unlearningにはpost-target suffixの再計算が必要と形式化する。provenance-guided selective replayではcheckpoint / prompt / memory / cacheを跨いでsanitized suffixを再生成し、論文報告ではfull resetに近い挙動を最大9x少ないrecomputationで得たとしている。

`Deployment-Time Memorization` は別角度から、raw-only deletionではderived summary copyが約20%のinstanceでrecoverableだったと報告し、Forgetting Residue Scoreを導入している。

### (2) 何が提案・推測段階か

- いずれもpreprintであり、KamimusuhiのK-Core/K-Deep/Persona/Tool stateでの独立再現は未実施。
- deterministic transition前提はstochastic provider / external tool / distributed deviceでは崩れる。
- 既に外部effectがcommit済みなら、完全なcounterfactual eraseは原理的に「履歴をなかったことにする」だけでは閉じない。compensation / tombstone / residual obligationの記録が必要。

### (3) Kamimusuhiの関係箇所

- Memory / consent / ownership / erasure
- Background / sleep-dream derived state
- prompt/prefix/KV cache
- pending plan / Workspace
- Continuity Kernel checkpoints
- distributed restore / migration

### (4) 借りられる設計・実装アイデア

既存forgetting contractを次まで拡張する。

```text
RevocationClosure(target)
  canonical stores
  derived summaries/indexes
  active prompt/context
  pending plan/tool proposals
  reusable inference cache / prefix / KV
  background job inputs
  checkpoint descendants
  external committed effects -> compensate / mark non-erasable residue
```

`taint closure + nearest clean checkpoint + selective replay` を実装戦略候補にする。

### (5) Kamimusuhiとの差分

原則自体は既収載。新しい差分は、**live execution stateを明示列挙し、exact forgettingをfuture behaviorのcounterfactual equivalenceとして評価し、selective replayの再計算下限まで議論できる**点。

### (6) 次に検証すべきこと

既存 restore-counterfactual bench のupdateとして `ExecutionStateRevocationFixture-v1`:

- targetをepisode→summary→plan→prompt cacheへ伝播させる。
- raw rowだけ削除したbaseline、prompt instruction、source redaction、selective replay、full resetを比較。
- string-free behavioral probeも入れる。
- external effectがtarget依存でcommit済みの場合は「exact erased」と判定せずresidual obligationを残す。

### (7) 既存dailyでは拾いにくい理由

memory deletion論文に見えるが本質は **runtime checkpointing / inference cache / provenance / replay / privacy** のcross-layer contractである。

### (8) 重要度

**A (existing finding update)** — 既出の方向を強く支持し、実験の具体化に直接使える。新規原則としては重複のため昇格しない。

## 4.4 A update — Operational-Mode Coverage Parity

- 数値は当該repository / CI configuration固有。

- reproducibility / CI
- migration / restore
- formal/runtime assurance

## 4.5 B — Cryptographically Replayable Delegation Shell

**Primary source**

- Oliver Aleksander Larsen, Mahyar Tourchi Moghaddam, *NostrAgent: A Decentralized Identity and Delegation Architecture for Sovereign Agentic Systems*, arXiv:2609.22944, 2026-09-19  
  https://arxiv.org/abs/2609.22944

### (1) 何が実証済みか

論文はNostr relay上に persistent cryptographic identity declaration、capabilityがhopごとに狭まるscoped delegation chain、peer attestations、L402 payment bindingを実装したPython prototypeを報告する。authorization decisionはsigned eventsだけからoffline replayでき、論文報告ではdelegation verificationはsub-ms、chain長に対してlinear scaling、regtestでL402 settlement median 157ms、19 failure modes中17をempirical passとしている。

### (2) 何が提案・推測段階か

- benchmark/prototype評価であり、Kamimusuhiの実運用規模・adversarial relay環境での検証はない。
- cryptographic key continuityは autobiographical / relational / phenomenological identity continuityを証明しない。
- trust graphのSybil耐性やeconomic incentivesはdeployment条件依存。

### (3) Kamimusuhiの関係箇所

- distributed embodiment
- external specialist delegation
- capability / authority lineage
- migration / key rotation
- economics of long-lived AI
- offline verification / provenance

### (4) 借りられる設計・実装アイデア

- delegation chainはhopごとにmonotonic attenuationを検証する。
- key rotationはpredecessor/pre-commit evidenceを残し、old/new authority lineageをoffline replayできるようにする。
- payment receiptは `who/which delegated authority/which scope/which resource/amount` へbindする。
- relay/transportはtrust rootにしない。

### (5) Kamimusuhiとの差分

Kamimusuhiではidentityはkey/model/hostそのものではない。NostrAgentから借りるのは **authority/provenance shell** であり、署名鍵をPersona/Selfのidentity ownerへ昇格させない。

既出 capability attenuation / delegation topology persistence と重なるため、独立spec原則ではなく「cryptographic/offline replay + payment」のwatch extensionとして扱う。

### (6) 次に検証すべきこと

`DelegationAttenuationKeyRotationBench-v0`:

- A→B→Cでscopeが一度も広がらないこと。
- key rotation前後でdelegation lineageが検証可能なこと。
- relayを置換/partitionしてもsigned evidenceからoffline判定できること。
- payment credentialとcanonical identity continuityを分離できること。

### (7) 既存dailyでは拾いにくい理由

P2P protocol / cryptography / payment / identity infrastructureに分類され、認知architecture側のidentity continuity surveyでは「identity」という語が同じでも意味が違うため落ちやすい。

### (8) 重要度

**B** — distributed external delegationを本格化する段階で有用。今すぐidentity coreへ入れるのではなくwatchlistとbench設計が妥当。

## 4.6 B — Local Metaplasticity as Plasticity State

**Primary source**

- Isabelle Aguilar, Zayn Andre Zainal, Omid Kavehei, *Metaplasticity as adaptive gradient preconditioning for incremental learning*, arXiv:2608.14634, 2026-07-27  
  https://arxiv.org/abs/2608.14634

### (1) 何が実証済みか

Kamimusuhiの2026-09-13 blind-spot surveyではmetaplasticity自体を次回探索watchに挙げていたが、具体的な人工実装は未昇格だった。

SynGAPはtask labelを要求せず、Fisher informationのEMAを各parameterのhistory-dependent plasticity stateとして使い、重要な過去parameterへのgradientをbounded multiplicative maskで減衰する。論文報告ではSplit CIFAR-100でEWC++比4x accuracy、ER比約10%改善、forgetting measureを10%以上低減、CORe50で約68%を報告している。

### (2) 何が提案・推測段階か

- 画像classification / continual learning benchmarkから人格・言語modelのstable traitsへ一般化できるとは限らない。
- Fisher-based importanceがPersonaの意味的「重要性」と一致する保証はない。
- weight-level self-modificationを許すこと自体がKamimusuhiのcanonical persona authorityを侵食し得る。

### (3) Kamimusuhiの関係箇所

- future J-series continual learning
- Persona Coreのslow adaptation
- developmental learning
- edge adaptation / energy-aware learning
- CLSのlocal mechanism候補

### (4) 借りられる設計・実装アイデア

memory tierとは別に、学習器側へ `plasticity_state(parameter/group)` を持つ。ただしこのstateは**canonical persona mutation authorityではなくoptimizer constraint**として扱う。

### (5) Kamimusuhiとの差分

既存CLSはfast/slow memory systemというmacro architecture。SynGAPの差分は **局所parameter updateの履歴依存plasticity** である。Persona continuityを直接担わせるべきではない。

### (6) 次に検証すべきこと

`MetaplasticPersonaUpdateBench-v0`:

- sequential skills / preferences / stable persona traitsを分離したtoy curriculumを用意。
- plain optimizer / EWC / replay / SynGAP-like maskを比較。
- new learning、stable-trait retention、catastrophic forgetting、memory/energy overheadを測る。
- canonical Persona mutation gateを通らないweight driftは成功扱いにしない。

## 10. 結論

今回の最も重要な新規差分は、**`same content != same attempt`** である。長寿命agentでは「同じ言葉をもう一度言う」「同じtool effectをretryする」ことが普通に起きる。content dedupをそのままdelivery/ack authorityへ流用すると、過去の成功が現在の失敗を消し、本人のunsettled obligationを誤って閉じる。

もう一つの実装差分は、**terminal stateが先に成立しても、その後から参加するsurface/observerがterminalityを正しく知れること**。approvalやhuman interactionを複数surfaceへ広げるほど、publish/subscribeのraceをsemantic lifecycleへ持ち上げる必要がある。

研究側では、forgettingを「rowを消した」ではなく「その情報を見なかったcounterfactual futureへどこまで戻せるか」で測る既存方針に、execution-state unlearningが具体的なcross-layer replay contractを与えた。NostrAgentとSynGAPはidentity coreへ直接採用せず、それぞれauthority shellとlearned-body plasticityのwatch候補に留めるのが妥当である。
