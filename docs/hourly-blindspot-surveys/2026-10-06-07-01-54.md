## 1. A — Interaction Constituency Must Be Explicit Across Multi-Event Surfaces

Primary: https://github.com/openclaw/openclaw/issues/165823  
Created: 2026-10-06 07:00:13 JST

1. **実証済み**: Matrixだけdocumented inbound debounceが実ingressへ接続されず、rapid text burstが1 event=1 agent turnになる。Element Webでは画像と後続質問が別eventなので画像だけ先に処理される。shared debouncerを挟んだlive testでは5-line burstが1 turnへまとまった。
2. **提案/推測**: 固定時間windowで何でも結合すればよいわけではない。surface/sender/thread/event-kind別bindingが必要。
3. **関係**: sensory ingress、K-Nerve/K-Edge、multimodal perception、turn-taking、Global Workspace、Cognitive Budget。
4. **借用案**: raw event IDsからsemantic interaction IDを作るInteractionAssemblyを置き、surface、sender、thread、reply/edit relation、attachment-caption relation、event time、binding confidenceを保持する。
5. **差分**: 10/05 07:03のdebounce findingはordering domain中心。本件は前段の「複数transport eventが一つのhuman communicative actか」というconstituency問題。
6. **次**: **SemanticInteractionAssemblyBench-v0 (P0/P1)**。rapid text、image→caption、same/different sender/thread、edit/reply、network reorder、複数intervalで過剰結合/分割率とgrounding accuracyを測る。
7. **dailyで拾いにくい理由**: HCIのmessage composition、stream batching、agent debounce、multimodal fusionの境界。
8. **重要度**: **A**。

## 2. A update — Failure-Derived Holds Must Be Bound to the Failing Route Generation

Primary: https://github.com/NousResearch/hermes-agent/issues/133454  
Created: 2026-10-06 03:49:54 JST

1. **実証済み**: 15分jobがmonthly quotaの約29.9日retry-afterで1か月parkされ、健康な別providerへrepoint後もholdが残った。schedule再計算後は即実行できた。
2. **提案/推測**: 最適なhold ceilingは未確定。長期reset windowを完全無視する必要はない。
3. **関係**: Resource Registry、Cognitive Budget、K-Deep/background、fallback、degraded mode、standing duties。
4. **借用案**: hold/backoffへroute_id、route_generation、provider/account-pool/model、failure class、bounded_reprobe_atをbind。route変更時は旧holdを再評価。
5. **差分**: recovery-persistent retry budgetの逆側。restartで保持すべきretry stateでも、resource routeが変われば失効すべきfailure evidenceがある。
6. **次**: **RouteGenerationQualifiedBackoffBench-v0 (P0)**。provider/model/account-pool/endpoint変更と短期・長期429等を交差。
7. **dailyで拾いにくい理由**: retry、routing、quota/economicsが別領域。
8. **重要度**: **A update**。

## 3. A update — Provider-Local IDs Need Explicit Uniqueness Domains Before Idempotency Reuse

Primary: https://github.com/openclaw/openclaw/issues/165786  
Created: 2026-10-06 05:49:03 JST

1. **実証済み**: Crabbox createのidempotency keyがsessionId+toolCallIdのみ。responseごとにcall IDを再利用するproviderでは、過去callが/newやcompactionでcontextから消えた後の新規createが古いstopped operationへ衝突する。fixtureではrepeated IDだけ失敗しfresh IDはgeneration 2を作成。
2. **提案/推測**: providerごとにID保証scopeは異なる。
3. **関係**: Action Router、tool execution、sandbox lifecycle、compaction、provider adapters、action receipts。
4. **借用案**: provider IDへ unique_within=response/attempt/turn/session/global のscopeを付与し、durable idempotency identityはcanonical operation/attempt IDをrootにする。
5. **差分**: idempotency/dedup/UNKNOWN outcomeは既出だが、key素材identifierのuniqueness scopeは弱い。
6. **次**: **ScopedExternalIdentifierIdempotencyBench-v0 (P0/P1)**。ID scope、compaction、context reset、retry/fallback、create-stop-create、concurrencyを交差。
7. **dailyで拾いにくい理由**: API側はIDをopaque stringとして扱い、distributed systems側は一意性を前提にしがち。
8. **重要度**: **A update**。

## 4. B update — Fallback Success Must Preserve Configured-Resource Failure

Primary: https://github.com/NousResearch/hermes-agent/issues/133473  
Created: 2026-10-06 04:15:48 JST

1. **実証済み**: configured search backendが失敗してもrescue backendが成功するとtop-level success=trueとなり、primary failureはnested metadataだけに残る。報告環境ではconfigured backend障害が13日間見逃され、empty resultも「該当なし」と読まれた。
2. **提案/推測**: fallback時にsuccess=falseへ落とすと既存consumerを壊す場合がある。
3. **関係**: Resource Registry、search/retrieval、health、epistemic confidence、fallback routing。
4. **借用案**: request_outcome と configured_route_outcome を分離し、served_by、fallback_used、evidence completenessをfirst-classにする。fallback成功でもhealthへfailure evidenceを送る。
5. **差分**: factorized outcomes等は既出。fresh差分はavailability successがconfigured cognitive organの長期障害とempty evidenceの意味を同時に隠すproduction evidence。
6. **次**: **FallbackOutcomeHealthFactorizationBench-v1 (P1)**。primary/fallback success、partial、empty、all-failを交差。
7. **dailyで拾いにくい理由**: resilienceはavailability、epistemic systemはevidence semanticsを見るため境界が落ちる。
8. **重要度**: **B update**。

## 5. B update — Execution Origin Must Not Override Live Participation Context

Primary: https://github.com/openclaw/openclaw/issues/165811  
Created: 2026-10-06 06:25:03 JST

1. **実証済み**: live interactive conversationをtargetにしたscheduled agent turnにも固定の「unattended run」preambleが付与され、人がpresentな会話で「Nobody is present」というfalse contextがmodel-visible transcriptへ入る。
2. **提案/推測**: scheduled originを隠す必要はない。provenanceとして残しつつparticipation stateとは分離すべき。
3. **関係**: sociality、pragmatics、common ground、scheduled follow-up、Expected Continuation、surface state。
4. **借用案**: execution_origin=SCHEDULED と participation_context=LIVE/UNATTENDED/UNKNOWN を別fieldにし、preambleは両者から構成する。surface presenceはfresh evidenceで決める。
5. **差分**: per-message participation-role separation / operational-mode parityへのfresh implementation delta。scheduler provenanceがsocial participation truthを上書きする具体例。
6. **次**: **ScheduledLiveParticipationContextBench-v1 (P1)**。live/idle/disconnected conversation、reminder、quota-reset continuation、operator-present/absentを交差。
7. **dailyで拾いにくい理由**: schedulerはexecution semantics、conversation analysisはparticipation/common groundとして分断される。
8. **重要度**: **B update**。

## 結論

今回の中心は **局所的なevent境界・failure hold・provider ID・success boolean・scheduler originを、長寿命個体のsemantic truthへそのまま昇格しないこと**。

platformが2 eventに分けたから人間が2 turnを意図したとは限らない。old routeの長期quota failureはrepoint後resourceの未来を決めない。provider-local call IDの再利用は同じoperationを意味しない。fallbackが応答してもconfigured organが健康だったとは限らない。scheduled originも「人がいない」というsocial factではない。
