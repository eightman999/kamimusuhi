# 3. 要約

今回の中心は、**「残っているデータ」と「継続可能な構造」は別物**という点だった。

Kimi Code の fresh PR は、server restart 後も child conversation 自体は disk に残っているのに、spawn / completion association が transient だったため swarm member graph を cold replay できない実例を示した。つまり、**child state persistence != delegation relation persistence** である。Kamimusuhi の branching / collective cognition では、member 関係や ownership を derived guess にせず、relation event 自体を durable evidence として持つ価値が高い。

OpenClaw の update-drain 修正は別の境界を示す。irreversible shutdown drain に入ると新規 root work は拒否すべきだが、既に選択済み update run の progress を観測する read-only path まで同時に殺す必要はない。重要なのは単純な allowlist ではなく、**read path が hidden reconciliation write をしないことを証明したうえで、lifecycle phase ごとに authority を縮退させる**ことである。

異分野 backfill では、learning-based perception の誤りを「risk scoreで検知して停止」するだけでなく、offline に perception contract の preimage から uncertainty を構成し、runtime で controller に渡す state を補正する研究を確認した。Kamimusuhi の人工感覚系でも、raw observation / learned estimate / control projection を分離すれば、K-Edge で低遅延に安全側へ補正しつつ、canonical evidence は改変しない設計が可能になる。

最後に OpenClaw の reply settlement 修正は、observer callback の障害が「相手には届いた」という semantic fact を覆してはいけないことを具体化した。ただしこれは既出の observer back-action / extension containment と強く接続するため、独立原則ではなく **A級の fresh delta** として扱う。

## 4.1 A — Causal Delegation Topology Persistence: child が残るだけでは collective state は復元できない

**Primary source**

- MoonshotAI/kimi-code PR #3970 — `fix: restore swarm members from persisted lifecycle events`  
  created: 2026-09-21 22:46 JST 頃  
  https://github.com/MoonshotAI/kimi-code/pull/3970

### (1) 何が実証済みか

PR の問題設定では、foreground Swarm が進行中のまま server を restart すると、reopen した conversation から member 一覧が消えた。

重要なのは、**child conversation 自体は disk に残っていた**ことである。失われていたのは、parent requesting conversation と child member を結び付ける spawn / completion 等の lifecycle association だった。これらが transient event だったため、cold transcript から member task や parent tool call を再構成できなかった。

修正では、requesting conversation の wire journal に以下を永続化する。

- spawn
- start
- completion
- failure
- cancellation

さらに parent-conversation ownership と swarm index を保持し、fork から継承した child history を無関係な current member と誤認しないようにする。restart 後、requesting turn も child runtime も生きていない unfinished member は `lost` と表示し、**history を読むだけで勝手に session / work を再起動しない**。

PR は transcript folding / cold read / event replay / scope lifecycle を含む targeted 274 tests を報告している。また修正以前の historical conversations は association fact 自体が存在しないため、child name や creation order から推測して復元しない、と明示している。

### (2) 何が提案・推測段階か

Kamimusuhi で delegation / branch / collective identity の relation event を canonical evidence と同等の durability classへ置くことは本 survey の提案である。

Kimi Code の Swarm UI 問題だけから、すべての multi-agent topology を永久保存すべきことまでは証明されない。retention / privacy / branch retirement との整合は別途必要。

### (3) Kamimusuhi の関連 subsystem / 設計課題

- K-Core / K-Deep delegation
- auxiliary / specialist agents
- collective / branching identities
- Continuity Kernel
- execution lineage / causal provenance
- session restore / cold replay
- observability / task ledger

### (4) 借りられる設計・実装アイデア

`child_id` の存在だけでなく、**relation を event として保存する**。

```text
DelegationRelationEvent
  relation_id
  parent_execution_id
  child_execution_id
  parent_identity_lineage
  delegated_role
  spawn_reason / obligation_id
  member_index
  authority_receipt
  context-envelope digest
```


`relational restore vs transcript restore` は主に human–companion relationship / common ground の復元問題であり、今回の差分は **agent execution graph の因果的 association** である。

## 4.2 A — Phase-Qualified Observability Authority: drain 中は mutation を閉じても selected progress read を残せる

**Primary source**

- openclaw/openclaw PR #155499 — `fix(update): preserve run progress during committed shutdown drain`  
  created: 2026-09-22 14:55 JST 頃 / merged: 2026-09-22 18:10 JST 頃  
  https://github.com/openclaw/openclaw/pull/155499

### (1) 何が実証済みか

OpenClaw は update / stop 時、active work を drain した後に process を止める。従来は committed shutdown drain に入ると通常 request admission が閉じるため、すでに接続済み administrator でも selected update run の進捗を読めなくなった。

修正では `update.runs.get` だけを irreversible drain phase に通す。ただし通常 getter は expired record 等の reconciliation を行い得るため、そのまま allowlist せず、**existing read-only database-worker path** を使う。

報告された proof では:

- `update.runs.get` は committed drain 中も成功
- broader `update.runs.list` は拒否
- update start / hold / status 等も新たに許可しない
- reversible restart-signal phaseでは従来どおり拒否
- teardown / resource-close が進んだ後は read も拒否
- read のために新しい lifecycle owner を作らない

つまり **shutdown 中も何でも読める**のではなく、phase と operation semantics を組み合わせた狭い authority projection である。

### (2) 何が提案・推測段階か

Kamimusuhi の sleep / migration / K-Core replacement / failover / graceful shutdown に、この pattern を一般化するのは提案。

すべての shutdown で progress surface を維持すべきとは限らない。privacy wipe / emergency containment では read plane も即閉鎖すべき場合がある。

### (3) Kamimusuhi の関連 subsystem / 設計課題

- Continuity Kernel
- maintenance / migration / update
- K-Nerve / K-Core health
- long-running K-Deep jobs
- operator UI / observability
- degraded-mode operation
- graceful stop / body replacement

### (4) 借りられる設計・実装アイデア

lifecycle を binary `RUNNING / STOPPED` ではなく、operation-class と組み合わせて admission する。

```text
LifecyclePhase
  ACTIVE
  QUIESCING
  COMMITTED_DRAIN
  TEARDOWN
  OFFLINE

OperationClass
  START_NEW_WORK
  MUTATE
  RECONCILE
  OBSERVE_EXISTING
  ACKNOWLEDGE
  EMERGENCY_STOP
```

例:

```text
COMMITTED_DRAIN:
  START_NEW_WORK   = DENY
  MUTATE           = DENY
  RECONCILE        = DENY
  OBSERVE_EXISTING = ALLOW only for already-authorized selected run
```

重要なのは、`GET` / `read` というHTTP名ではなく、**hidden write / reconciliation / owner acquisition がない semantic read** であること。

### (5) Kamimusuhi との差分

既出の `completion-publication barrier / global quiescence` は、in-flight work の完了・公開・停止境界を中心にしている。`approval-plane survivability` は human approval 経路の可用性が中心だった。

今回の差分は、**new work admission を閉じた後も、既存workの観測authorityを限られた期間だけ残し、それをmutation-free pathへ束縛する**こと。

### (6) 次に検証すべきこと

**`QuiescentReadAuthorityBench-v0`**

1. K-Deep research / model migration / backup のいずれかを進行させる。
2. authenticated observer が selected run を購読した状態で `COMMITTED_DRAIN` へ移行。
3. drain 中に progress / current phase / immutable receipts が読めることを確認。
4. 同じ principal でも new task、general listing、reconciliation、retry、mutation は拒否。
5. getter 内部から durable mutation / lease acquisition が0件であることを trace で確認。
6. `TEARDOWN` へ入ったら read handle も閉じる。
7. emergency privacy containment 条件では drain read exception自体を無効化する。

### (7) 既存 daily ではなぜ拾いにくいか

graceful shutdown は「仕事を受ける / 受けない」「待つ / killする」という liveness 問題として扱われやすい。ここで重要なのは、**停止過程の中にも authority の段階があり、observability と mutation を同時に閉じる必要はない**という capability-security / operations の交差点である。

## 4.3 A — Perception-Contract Runtime Correction: learned estimate を canonical observation と分離したまま control 用に補正する

**Backfill source — 新着ではないが未収載の異分野補完**

- Yan Miao, Hussein Darir, Sayan Mitra, *Correcting Learning-based Perception for Safety*  
  submitted: **2026-08-16**  
  https://arxiv.org/abs/2609.22108

### (1) 何が実証済みか

論文は learning-enabled perception の state estimate に対して2段階の runtime correction を提案している。

1. offline に **perception contract の preimage** を用いて、ML perception の state-estimation uncertainty を特徴付ける。
2. runtime に risk heuristic を用い、uncertain estimate の中から control decision に使う particular state を選ぶ。

vision-based adaptive cruise control を YOLO / LaneNet と組み合わせ、weather / road conditions を変えた simulation で評価している。

原 perception-based controller が safety violation を起こした45 scenariosのうち、**73%で runtime correction が safety を維持**した。残り **27%は perception-contract preimage 構築が完全に conformant でない条件で回復できなかった**。corrected scenarios の completion time 増加は平均 **2.8%** と報告されている。

これは「学習知覚は危険」という一般論ではなく、**知覚誤差の集合を contract として扱い、制御へ渡す estimate を runtime で修正できる**ことの具体的 proof-of-concept である。

### (2) 何が提案・推測段階か

- 実証は simulation-based ACC が中心であり、Kamimusuhi の一般 multimodal sensing / social action / robot manipulation への一般化は未実証。
- preimage が不完全なら回復できないという明示的限界がある。
- perception correction 自体が新しい false confidence source にならない保証は別途必要。

### (3) Kamimusuhi の関連 subsystem / 設計課題

## 4.4 A級更新 — Observer Outcome Non-Interference: observer が壊れても semantic settlement を壊さない

**Primary source**

- openclaw/openclaw PR #155522 — `fix(replies): observer errors leave reply settlement stuck`  
  created: 2026-09-22 15:21 JST 頃 / merged: 2026-09-22 17:28 JST 頃  
  https://github.com/openclaw/openclaw/pull/155522

**Cross-domain specification**

- OpenTelemetry — Error handling in OpenTelemetry  
  https://opentelemetry.io/docs/specs/otel/error-handling/

### (1) 何が実証済みか

OpenClawでは、reply delivery自体は recipient に成功していても、plugin の settlement observer とその error reporter が同期的に throw すると settlement wait が reject し、idle notification も発火せず、later settlement まで詰まるケースがあった。

修正後は observer / error-reporter の同期throwとrejected promiseを best-effort boundary 内に封じる。報告された real local HTTP recipient proof では、3 replies の delivered receipts と settlement notification が保持され、後続replyもsettleし、idleも発火する。cancellationはdelivery failureへ誤分類されず cancellation outcomeを保つ。

OpenTelemetry specification も一般原則として、SDK内部のerrorでruntime applicationをfailさせないこと、external callbacksのerrorsをhandleすること、background task内部例外をend-user applicationへ波及させないことを要求している。

### (2) 何が提案・推測段階か

Kamimusuhi の全observerをbest-effortにすることは提案しない。security monitor / Continuity Kernel validatorのように、observerではなく**authority-bearing guard**として明示されたcomponentはfail-closedでよい。

重要なのは role typing である。

```text
OBSERVER / TELEMETRY / UI NOTIFIER
!=
VALIDATOR / AUTHORITY / SAFETY INTERLOCK
```

### (3) 関係subsystem

- K-Nerve / observability
- delivery / social activity state
- plugins / extension runtime
- telemetry
- task settlement / receipts
- operator notifications

### (4) 借りられる設計

semantic outcomeを先に決め、observer結果を別軸にする。

```text
SemanticSettlement
  DELIVERED | CANCELLED | FAILED | UNKNOWN

ObserverSettlement
  OK | DROPPED | CALLBACK_FAILED | REPORTER_FAILED
```

observer failureはdiagnostic eventを生成してよいが、既に確定したdelivery/cancellation outcomeを書き換えない。

### (5) Kamimusuhiとの差分

2026-09-16の `observer back-action / quiescent observability` はpoll/log/monitor自体のlock・I/O・scheduler負荷がcognitionへback-pressureを入れる問題だった。2026-09-21の `extension termination-class containment` はpluginがhost terminationへ抜ける問題だった。

今回のdeltaは、**observerの論理的失敗が authoritative semantic settlement を支配しない**こと。したがって独立findingを増やさず、既存observer/extension contractへ追加する。

### (6) 次に検証すべきこと

**`ObserverOutcomeNonInterferenceBench-v0`**

- delivery成功後に observer sync throw / async reject
- observer error reporterもthrow
- cancellation path
- delivery failure path
- observer callback timeout
- 連続10件の後続settlement

を試し、semantic receiptが変化せず、queue/idle lifecycleも閉じることを確認する。

### (7) 既存 daily ではなぜ拾いにくいか

observability研究はlogging/metricsの取得精度、agent研究はreply deliveryを別々に見るため、**observer callback failureがbusiness/semantic outcomeの状態機械へ逆流する**問題はplugin runtimeの細部に埋もれやすい。

# 10. 今回の結論

今回の3つの独立findingを一行で表すと:

```text
nodeが残る != relationが残る
停止を始めた != 観測まで即座に禁止すべき
知覚が不確か != 警告するだけが選択肢
```

Kamimusuhiに最も直接効くのは **Causal Delegation Topology Persistence** だと判断する。今後branch / specialist / swarm / collective identityを増やすほど、child stateだけを永続化しても「誰が誰のcontinuation / delegateだったか」が失われれば、cold restore時に社会構造を捏造することになる。

次点は **Phase-Qualified Observability Authority**。長寿命agentはupdate・migration・sleep・backup・K-Core交換のような「止まりつつある時間」が長くなるため、RUNNING/OFFLINEの二値ではなく、mutation authority と observation authority を段階的に縮退させる方が自然である。

Perception-contract correctionはすぐにidentity kernelへ入れる話ではないが、Physical AI / sensory nervous systemが進んだ段階で、**raw evidenceを保持したままaction用projectionだけを安全補正する**設計として試験価値が高い。
