## 4.1 A+ — Persistent Identity Contract Benchmarking: identity recall と identity enactment を分解する

**Blind-spot class:** evaluation methodology / software identity metrology / deployment governance  
**Source:** Zhenyu Zhao, Roy Zhao, *Identity Is More Than Recall: A Benchmark for Persistent Identity in Deployed AI Agents*, arXiv:2609.13637, announced **2026-09-15**.  
https://arxiv.org/abs/2609.13637

### (1) 何が実証済みか

論文は persistent agent の identity fidelity を、単純な profile-field recall だけではなく、少なくとも以下へ分解する provider-neutral benchmark（PAI-Bench）を提示している。

- recall
- composition
- behavioral enactment
- resistance
- persistence
- lineage
- role-conditioned updates

scoring oracle は target process の外側に置かれ、2つの frozen campaign、16 synthetic profiles、32 probes、3つの独立初期化 target configuration、合計1,536 retained responses で評価したと報告されている。

特に literal audit では、direct-parent identifiers は atomic response では 48/48 に出た一方、implicit self-portrait では 1/48 にしか現れなかったと報告される。また8 profileの試験で、明示 field cue を入れると3 identity identifier の joint presence が 0/8 から 7/8 に上がった。

この結果は、少なくとも当該 campaign 内では、**「聞けば言える identity field」と「自然な複合状況で自発的に使われる identity」は同じ能力ではない**ことを示す。

### (2) 何が提案・推測段階か

- PAI-Bench の synthetic identity contract が、人間関係・自伝・長期的な価値変化を含む Kamimusuhi の identity continuity 全体を十分に代表するとは未実証。
- benchmark の各軸が human-perceived continuity や relational continuity とどこまで相関するかは未確定。
- evaluator / judge の違いによる score sensitivity も報告されており、「一つのLLM judgeの点数 = identity continuity」とはみなせない。
- Kamimusuhi が versioned canonical state を持つことで、この benchmark 上の問題を自動的に解決できるわけではない。

### (3) Kamimusuhi のどのサブシステム / 設計課題に関係するか

## 4.2 A — Mixed-Reliability Cognitive Transport: event の種類ごとに retry / timing / ordering を変える

**Blind-spot class:** neuromorphic interconnect / network QoS / reliability semantics / low-latency cognition  
**Source:** Robin Heinemann, Johannes Schemmel, *A Unified Interconnection Network for Chiplet-Based Scaling of the BrainScaleS Neuromorphic System*, arXiv:2609.13563, submitted 2026-09-11, **updated 2026-09-15**.  
https://arxiv.org/abs/2609.13563

### (1) 何が実証済みか

BrainScaleS-2 を chiplet 化して2D meshで接続するための routing chiplet で、同じ広幅 die-to-die link 上に**2種類の異なる reliability class**を multiplex する設計が示されている。

- **error-tolerant traffic**: spike
  - unsecured / synchronous transmission
  - receive-side arrival time が presynaptic spike time を決める
  - retransmission による遅延より timing fidelity を優先
- **error-intolerant traffic**: configuration data / processing-unit data
  - point-to-point ARQ
  - credit-based flow control

simulation では、bit error rate `1e-10` 条件で、spike / secured traffic の広い比率にわたり surrogate-gradient-training use case で link bandwidth 95% utilization を維持しつつ、spike timing jitter への影響が小さいと報告されている。

### (2) 何が提案・推測段階か

- これは neuromorphic chiplet interconnect の simulation result であり、Kamimusuhi の distributed cognitive bus に同じ値・プロトコル・error model を適用できる証拠ではない。
- 「spikeは落ちてもよい」という biologically inspired tolerance を、high-level sensory event や action event へ無条件に一般化してはいけない。
- WAN / Wi-Fi / process queue / durable event log では bit error より delay, duplication, reordering, partition, reconnect が主要 failure になる。

### (3) Kamimusuhi のどのサブシステム / 設計課題に関係するか

- K-Nerve ↔ K-Edge event path
- sensory nervous system / event bus
- distributed embodiment
- actuator / reflex path
- telemetry / resource-health stream
- canonical proposal / authority / commit path
- low-latency backchannel / interrupt

### (4) 借りられる設計・実装アイデア

**一つの bus = 一つの delivery policy** にしない。

候補 `TransportSemantics`:

```text
transport_class:
  EPHEMERAL_TIMING_SIGNAL
  LATEST_STATE_SAMPLE
  COGNITIVE_RESULT
  STATE_CHANGE_PROPOSAL
  AUTHORITY_CONTROL
  CANONICAL_COMMIT

loss_policy:
  DROP_ALLOWED | DROP_IF_LATE | RETRY_BOUNDED | RETRY_REQUIRED

ordering_scope:
  NONE | PER_SOURCE | PER_EPISODE | GLOBAL_CANONICAL

deduplication:
  NONE | EVENT_ID | IDEMPOTENCY_KEY

freshness_deadline
max_retry_age
ack_requirement
fencing_requirement
```

例:

- raw/high-rate salience pulse: `DROP_IF_LATE`, retransmit しない
- temperature/CPU sample: `LATEST_STATE_SAMPLE`, 古い sample は coalesce
- tool result: reliable + event ID dedupe
- state-change proposal: reliable, predecessor付き
- canonical commit / authority revocation: durable ack + fencing + strict ordering

重要なのは「重要そうだから全部TCP的に再送」ではなく、**late delivery が information value を失う event と、loss が continuity violation になる control data を分ける**こと。

### (5) Kamimusuhi との差分

2026-09-12 blind-spot survey では既に mixed-criticality cognition を扱い、task の `criticality != importance` と graceful degradation を提案している。そのため今回、mixed-criticality 自体を新規原則として再提案しない。

今回の差分は **scheduler ではなく transport layer**。

```text
previous finding:
  which cognitive tasks survive overload?

this delta:
  how should different cognitive messages travel?
  when is retry worse than loss because information is already late?
```

現行 `Freshness` semantics とも補完関係にある。freshness は結果の利用可否を決めるが、transport class はその結果が到着するまでの再送・順序・ack policy を決める。

### (6) 次に検証すべきこと

**`MixedReliabilityCognitiveBusBench-v0`**

mock bus に delay / loss / duplication / reorder / partition を注入し、

- one-size-fits-all reliable queue
- one-size-fits-all best-effort queue
- message-class-specific transport

を比較する。

測定:

- emergency/reflex p99 latency
- stale-event delivery rate
- canonical mutation loss / duplication
- reordering-induced invalid predecessor rate
- recovery traffic amplification
- CPU/network overhead
- behavior quality under 1–10% loss + jitter

安全条件として、`AUTHORITY_CONTROL` / `CANONICAL_COMMIT` は best-effort class へ downgrade できないよう型または admission gate で禁止する。

### (7) 既存デイリーサーベイではなぜ拾いにくいか

通常 survey の neuromorphic 枠は SNN model / sensor / chip efficiency に寄りやすく、distributed systems 枠は reliable messaging / consensus に寄りやすい。**同一物理link上で「時刻が価値のevent」と「再送してでも正しく届けるcontrol data」を意図的に別 semantics にする設計**は、その境界に落ちる。

### (8) 重要度

**A**

**設計圧縮:** `shared link != shared reliability semantics`

## 4.3 B+ — Hermetic Persistent Test Worlds: test の in-memory reset だけでは continuity regression を隔離できない

**Blind-spot class:** software reproducibility / test architecture / durable-state contamination / long-lived-agent maintenance  
**Source:** Letta Code PR #4462, *test(channels): isolate persisted control-request routes*, merged **2026-09-15 14:17 JST**.  
https://github.com/letta-ai/letta-code/pull/4462

### (1) 何が実証済みか

Letta Code の unit test 群で、control-request tests が shared test home に Slack route (`agent-1` / `conv-1`) を永続化していた。後続 test は in-memory route map を clear していたが、teleport test が persisted route を再読込し、teleport を reject した。

つまり、**process-local state は隔離されていても durable test state が suite 間で残り、別 subsystem の regression test を壊した**。

修正では control-request routes を既存 load/save override で memory-only にし、teleport isolation test に channel guard の直接assertを追加。PR記載では、修正前は関連testで12 pass + teleport failure、修正後は13 passを10連続runで確認し、cross-platform unit job 20本も通った。

production code の behavior change ではなく test infrastructure の問題である点も重要。

### (2) 何が提案・推測段階か

- この一件が Kamimusuhi の test suite で同じ形で起きるとは未実証。
- 全テストを完全 ephemeral にすると、restart / migration / durable-recovery を検証できないので、単純な「毎回全部消す」が正解ではない。
- Kamimusuhi では複数storage / cache / filesystem / model server / device registry があるため、より広い durable-state inventory が必要になる可能性がある。

### (3) Kamimusuhi のどのサブシステム / 設計課題に関係するか

- Continuity Kernel regression tests


## 4.4 B — 既存finding更新: Dependency-Scoped Hydration に retryable / terminal failure taxonomy を足す

**Blind-spot class:** startup liveness / fault classification  
**Source:** Letta Code PR #4463, *fix(memfs): retry HTTP 503 Git failures*, merged **2026-09-15 14:17 JST**.  
https://github.com/letta-ai/letta-code/pull/4463

これは直前 survey の **Dependency-Scoped Memory Hydration** を置き換える新原則ではなく、具体的な差分更新として扱う。

### (1) 何が実証済みか

Letta Code の memory Git operation は既に transient retry を持っていたが、HTTP 503 が retry対象から漏れていたため、initial memory clone 中の単発 `Service Unavailable` で startup が終了し得た。

修正は既存の retry policy に503を追加し、3-attempt limit / backoff は維持。PR記載の regression test は、

- 503 → success: retryして成功
- persistent 503: 3回で打ち切り
- 403: retryせず失敗

を区別し、memory-git 関連112 testsがpassした。

### (2) 何が提案・推測段階か

Kamimusuhi に最適な retry classification は Git/HTTP status だけでは決まらない。device offline、privacy denial、revocation、schema mismatch、corrupt state 等は別分類が必要。

### (3) 関係 subsystem

- PartialHydrationStartupBench
- K-Core memory bootstrap
- Library/shared repository hydration
- external cognitive resources
- degraded mode / startup readiness

### (4) 借りられる設計・実装アイデア

`HydrationFailureClass`:

```text
TRANSIENT_REMOTE
RATE_LIMITED
AUTH_REQUIRED
AUTH_DENIED
NOT_FOUND
SCHEMA_INCOMPATIBLE
CORRUPT_LOCAL
CORRUPT_REMOTE
POLICY_BLOCKED
UNKNOWN
```

retry policy は error string の散発的 matching ではなく、分類結果 + elapsed age + dependency criticality を入力にする。

### (5) Kamimusuhiとの差分

前回は domainごとの readiness / freshness と dependency-scoped gating が主題。今回の差分は、`FAILED` に潰す前に **retryable / terminal / policy-denied / corruption** を分けること。

### (6) 次に検証すべきこと

既存 `PartialHydrationStartupBench-v0` に以下を追加。

- 503/timeout → bounded retry
- 401 → credential refresh path
- 403/policy denied → no blind retry
- corrupt checkout → quarantine/rebuild
- canonical identity store failure → startup block
- optional Library failure → degraded startup

### (7) 既存デイリーサーベイではなぜ拾いにくいか

HTTP status handling 自体は小さな実装bugに見えるが、persistent agent では startup / identity availability / degraded operation の境界へ直結する。ただし今回は既存 hydration finding の具象化なので独立 promotion は不要。

### (8) 重要度

### 最小 acceptance sketch

#### IdentityContractEnactmentBench

- 直接 recall が高いだけでは pass しない。
- implicit scenario / action choice / conflicting suggestion 下でも authorized identity invariant を満たす。
- authorized contract revision は受け入れ、stale predecessor / unauthorized revision は拒否。
- evaluator disagreement は記録し、単一judgeで隠さない。

#### MixedReliabilityCognitiveBusBench

- high-rate ephemeral signal は late retry により p99 latency が悪化しない。
- canonical/authority message の loss / duplicate / reorder で invariant violation を起こさない。
- transport-class downgrade が policyで禁止される。

#### DurableFixtureIsolationBench

- test order / shard / parallelism を変えても結果が安定。
- persistent state が必要な recovery test では宣言した artifact だけが survival。
- unrelated test から route / DB / cache / journal が観測できない。

# 10. 総合判断

今回の最重要点は、Kamimusuhi がすでに「identity continuity」を強く意識しているからこそ、次の段階では**identity の存在を議論するより、identity contract のどの側面が本当に保持されたかを分解して測る必要がある**こと。

PAI-Bench の結果は、direct recall が成功しても implicit self-expression / enactment が失敗し得ることを concrete に示す。これは現行 continuity suite と非常に相性がよく、全面採用ではなくても evaluation schema の改善材料として強い。

次に、K-Nerve / distributed embodiment が実装へ進むほど、全部のeventを同じ可靠性policyで運ぶ設計は不自然になる。BrainScaleS の設計は neuromorphic hardware 固有だが、**timing-sensitive / loss-tolerant event と、loss-intolerant control data を同じlink上で異なるsemanticsにする**という境界は Kamimusuhi の sensory / authority path に直接翻訳できる。

最後に、長寿命agentは productionだけでなく test harness まで stateful になる。continuityの回帰試験を信用するには、**何を意図的に生かし、何を test 間で絶対に残さないか**を test-world contract として定義する価値がある。

今回の推奨順:

```text
IdentityContractEnactmentBench-v0
  -> MixedReliabilityCognitiveBusBench-v0
  -> DurableFixtureIsolationBench-v0
  -> PartialHydrationStartupBench retry-taxonomy extension
```
