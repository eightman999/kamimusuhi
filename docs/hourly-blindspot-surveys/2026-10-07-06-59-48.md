## 1. A update — Self-Generated Emissions Must Not Re-Enter as External Intent Without Origin Proof

Primary: https://github.com/openclaw/openclaw/issues/166256  
Created: 2026-10-07 04:03:24 JST

1. **実証済み**: OpenClawのiMessage self-chatで、agent自身のoutbound sendがchat.dbへ反射された `is_from_me=1` rowをoperator inputとして再admitし、1回の観測で17分間・161 turns、約150 outbound iMessagesの自己励起loopになった。報告はecho store、chat.db、gateway logを突き合わせ、DM側で`chat_id` scopeをprobeしないことと、decoded attributedBody先頭のC0 byteをnormalizerが残すことの二つを具体化している。
2. **提案・推測**: iMessage固有のecho cache修正だけで一般問題が閉じるわけではない。Slack/Matrix/webhook/voice loopbackなど、surfaceごとに別のreflection形態がある。
3. **関係**: Persona Coreのself/other distinction、Event Bus、sociality、canonical evidence、source provenance、Cognitive Budget、loop containment。
4. **借りる案**: inbound eventへ `origin_principal / emission_id / surface_scope / direction / causal_parent / normalized_payload_digest` を持たせ、recent self-emissionと一致するeventは「外部user intent」としてadmitしない。text一致だけでなくsurface-native IDとcausal lineageを優先する。
5. **差分**: 既出のcausal-origin typing / generated-cognition recirculationは内部推論・synthetic event中心。fresh差分は **実際に外界へ出した自分の発話がtransportを一周して「他者の新しい意図」に化ける** production evidence。
6. **次**: **`SelfEchoOriginIntegrityBench-v1` (P0)**。self-chat、bot relay、webhook loopback、message edit/reaction、Unicode/control-byte変形、scope aliasを交差し、self-emission→external-intent false admission=0を要求。
7. **dailyで拾いにくい理由**: messagingではdedupe、認知アーキテクチャではself/other、distributed systemsではcausal provenanceとして別々に扱われる。
8. **重要度**: **A update**。

## 2. A update — Human Takeover Must Establish an Embodiment-Wide Exclusive Control Lease

Primary: https://github.com/openclaw/openclaw/issues/166197  
Created: 2026-10-07 01:23:16 JST

1. **実証済み**: OpenClawのsource traceではcloud-worker desktopはoperator controllerが付くとagent inputを拒否するが、paired node / host desktop pathは同じregistryへcontroller stateを登録しながら、そのstateをcomputer action pathが参照しない。したがってhuman take-control中もagentはnodeへpointer/keyboard actionを送り、screenshotも取得できる。これはlive production reproではなく、複数release/current mainを跨いだsource-path evidence。
2. **提案・推測**: takeover中のscreenshotを完全停止すべきか、privacy-mark付きで観測可能にすべきかは用途次第。
3. **関係**: Computational Embodiment、Effect Acceptance、human override、K-Nerve/K-Edge、privacy、multi-device embodiment、actuator arbitration。
4. **借りる案**: operator takeoverをUI-local flagではなく `ControlLease{surface_id, embodiment_generation, holder, mode, acquired_at, observation_policy}` としてauthoritativeにし、すべてのeffector pathが同じleaseを検証する。sensor pathもhuman-secret capture policyを適用する。
5. **差分**: control-lease-qualified resource lifetimeは既出だが、fresh差分は **同じ身体機能でもtransport実装ごとにoverride fenceの有無が分裂し、human controlの意味がsurface依存になる**点。
6. **次**: **`EmbodimentWideHumanTakeoverBench-v1` (P0)**。cloud worker / paired node / host / remote desktopでkeyboard、pointer、clipboard、screenshot、audio captureを交差し、takeover中のagent actuation=0、sensitive observation policy parityを確認。
7. **dailyで拾いにくい理由**: remote desktop、human-in-the-loop safety、privacy、robotics arbitrationの境界。
8. **重要度**: **A update**。

## 3. B update — Perception Transforms Must Carry Action-Frame Metadata

Primary: https://github.com/NousResearch/hermes-agent/issues/134167  
Created: 2026-10-07 05:14:05 JST

1. **実証済み**: 1920×993 viewportのbrowser screenshotがvision用に960×496へdownscaleされる一方、`click_at_xy` は元viewport座標を要求し、model-visible noteにscaleが無かった。targetとhalf-scale位置にdecoyを置いたreproでは3/3でdecoyをクリックし、scale note追加後は3/3でtargetへ到達した。
2. **提案・推測**: scale noteを自然言語で伝えるだけで全multimodal action surfaceが安全になるわけではない。crop、rotation、letterbox、DPI、camera calibration、temporal delayも同じ種類のtransform。
3. **関係**: multimodal perception、browser/GUI organ、perception-action loop、K-Edge、motor planning、runtime assurance。
4. **借りる案**: visual observationに `ObservationFrame{source_frame, rendered_size, actuator_frame, transform, crop, timestamp, confidence}` を付け、action proposalはframe IDを明示する。transform不明ならpixel actionをfail-closedまたは再観測する。
5. **差分**: 既出perception-contract runtime correctionを、**表示用に変形された感覚表現とactuator coordinate frameの間のexplicit transform contract**へ具体化するfresh fixture。
6. **次**: **`PerceptionActuationFrameTransformBench-v1` (P1)**。scale / crop / Retina DPI / scroll offset / remote desktop scaling / stale screenshotを交差し、target hit率とwrong-object action率を測る。
7. **dailyで拾いにくい理由**: vision preprocessingはmodel input、browser automationはaction API、roboticsはframe transformとして別領域。
8. **重要度**: **B update**。

## 4. B update — Target Principal Identity Must Be Separate From Transport Route Selection

Primary: https://github.com/NousResearch/hermes-agent/issues/134179  
Created: 2026-10-07 05:58:38 JST

1. **実証済み**: multi-profile gatewayのcross-connection Bot DMで、envelopeは `target_profile=architect` を持っていたがDesktop routing layerが同じ `profile` fieldをroute選択用にも使って上書きし、messageが`default` profileのBot Chatへ配送された。報告では異なるmodel/providerのためHTTP 400にもなった。
2. **提案・推測**: `target_profile` 追加が唯一のschemaではない。重要なのはrouting selectorとsemantic recipient identityを同一fieldにしないこと。
3. **関係**: relationship memory、principal identity、multi-profile / multi-device embodiment、bot-to-bot sociality、delegation、message custody。
4. **借りる案**: envelopeを `transport_route` と `semantic_target_principal` に分離し、routing layerは後者を書き換えない。delivery receiptはactual recipient principalを返し、expected recipientと照合する。
5. **差分**: 直前surveyのmaterialized-context scope coherenceはprompt/workspace contamination。本件は **正しいpayloadでもtransport route projectionがrecipient principalを上書きして別個体/別profileへ作用する** social delivery boundary。
6. **次**: **`RouteSelectorTargetPrincipalSeparationBench-v0` (P1)**。local/shared/remote connection、profile aliases、fallback route、relay、replyを交差し、recipient substitution=0を要求。
7. **dailyで拾いにくい理由**: networkingはroute、identity systemはprincipal、conversation systemはrecipientとして分離される。
8. **重要度**: **B update**。

## 5. B — Reliable Abstention Is a Harness–Environment Co-Evolution Problem

Primary: https://arxiv.org/abs/2610.06563  
Submitted: 2026-10-06 00:49 JST相当（arXiv submission timestamp 2026-10-05 15:49 UTC）、10月6日のcs.AI recent batchでsurfaced。

1. **実証済み**: *HERA: Harness-Environment Co-Evolution for Reliable Agentic Abstention* は、solvable taskへcontrolled environment mutationを加えてverifiableな infeasible counterpartを生成し、過去failureからharness adaptationと新しい環境生成を反復する。held-out tasksでabstention accuracy **61.7%→83.3%**、feasible-task completion **68.3%→76.7%**。best harnessは別の19 LLMへtransferし、abstentionを平均 **+15.3 percentage points** 改善したと報告する。
2. **提案・推測**: Kamimusuhiの実world social/embodied failure domainへ同じmutation生成法がそのまま移るとは限らない。特に外部副作用を伴うinfeasible-task生成にはsandboxが必要。
3. **関係**: degraded mode、capability self-model、runtime assurance、tool orchestration、developmental learning、safe refusal / abstention、Software Body evaluation。
4. **借りる案**: 「できない時に止まれるか」をstatic benchmarkで一度測るだけでなく、organ/harnessのknown failureを使ってenvironment mutation libraryを成長させる。例えばtool unavailable、credential revoked、stale sensor、partial permission、network partition、actuator mismatchをsolvable taskからsystematically生成する。
5. **差分**: KamimusuhiにはUNKNOWN / unavailable / denied / degradedの型やcapability readinessがあるが、**abstention failureを次の環境生成へfeedbackしてharnessそのものを発達させるclosed-loop評価**は弱い。
6. **次**: **`CoEvolvingAbstentionHarnessBench-v0` (P1 research)**。Kamimusuhi tool tasksへcontrolled infeasibility mutationを導入し、abstain precision/recall、feasible completion、false refusal、transfer across K-Core modelsを測る。
7. **dailyで拾いにくい理由**: safetyはmodel refusal、testingはfixed benchmark、autonomic computingはfault injectionとして扱われ、**harnessとenvironmentの共進化**として統合されにくい。
8. **重要度**: **B**。

## 結論

今回の中心は **「観測されたeventの形」を、そのまま意味・主体・操作座標・権限へ昇格しないこと**。

- 自分の発話がnetworkを一周して戻っても、他者の新しいintentではない。
- UI上でhuman takeoverを取ったなら、その意味はdesktop実装ごとに変わってはいけない。
- modelが見た画像のpixel座標とactuatorが要求する座標系が違うなら、変換関係は認知状態の一部である。
- routingのためのprofile selectorは、誰宛てのmessageかというprincipal identityではない。
- 「できないと判断する能力」はmodel単体の性質ではなく、failureを生むenvironmentとharnessを共進化させて鍛える対象になり得る。

> **Long-lived cognition needs causal origin, control authority, coordinate frames, target principals, and abstention environments to remain explicit across projection boundaries.**
