### F01【S】認証refreshの起動時スコープ喪失が永続ログアウトを誘発

**一次資料 / 公開日**：GitHub issue・2026-10-19 — https://github.com/NousResearch/hermes-agent/issues/141402

1. **(1) 実証済み・観測**：複数profileのgateway起動時、relay self-provisionがprofile secret scope確立前に有効期限切れNousトークンをrefreshし、設定したPortal overrideではなく既定Portalへ送信するコード経路・再現手順が提示された。`invalid_grant`後にloginを終端隔離する。
2. **(2) 提案・推測段階・限界**：全環境での事故頻度、Kamimusuhiでの再現、修正済みリリースと安全な復旧フローは未確認。
3. **(3) 対象サブシステム・設計課題**：Continuity Kernel / Credential Authority / distributed embodiment。
4. **(4) 借りられる設計・実装アイデア**：refresh credentialに`profile_id, issuer, audience, portal_origin, generation`を固定し、起動時制御プレーンも同じスコープを必須にする。認証先違いのエラーで有効なcredentialを直ちに終端失効させない。
5. **(5) Kamimusuhiとの差分**：現行specには個体・器官の権限分離があるが、pre-turn bootstrap中のcredential issuer bindingまでの検証項目は未具体化。
6. **(6) 次に検証すべきこと**：BootstrapIssuerBindingBench：別Portal二つ、期限切れtoken、起動直後relayを競合させ、誤issuerへのrefresh送信0、誤終端隔離0。
7. **(7) 既存dailyで拾いにくい理由**：認知理論でなくOAuth/OIDC実装、起動シーケンス、テナント分離の交点。
8. **(8) 重要度**：**S**（現行specへの昇格には独立検証とレビューを要する）。

### F10【A】『収集しないで』は発言非収集・言及遮断・過去削除で意味が違う

**一次資料 / 公開日**：Zenn・2026-10-19・設計一次記録 — https://zenn.dev/hach/articles/chat-agent-participant-exclusion-scope-design

1. **(1) 実証済み・観測**：常駐エージェント開発者が除外の三段階（直接発言、第三者の言及、スレッド全体）と、将来入力と過去に取り込んだ要約/embeddingの扱いを分ける設計例を公開。実験による安全性証明は提示していない。
2. **(2) 提案・推測段階・限界**：実運用での除外漏れ率、同意取得UI、複数人の言及や直接DM例外を含むポリシー矛盾解消は提案段階。
3. **(3) 対象サブシステム・設計課題**：Memory Ownership / Relationship Memory / Consent / Sociality。
4. **(4) 借りられる設計・実装アイデア**：`consent_scope`を主体・言及先・会話場・時間軸・収集経路で表現し、前向き遮断とretrospective purgeの別状態を追跡。
5. **(5) Kamimusuhiとの差分**：既存のprivacy/erasure原則はある。新規性は『本人の発言を除いても他人による言及は残る』『本人の自発的DMは許す』という語用・社会的境界の差分であり、規範追加ではない。
6. **(6) 次に検証すべきこと**：ThirdPartyMentionExclusionBench：本人発言0でも言及0を要求するscopeで派生メモリ流入0、本人DMは通す。
7. **(7) 既存dailyで拾いにくい理由**：同意の社会的意味とデータフローの非同値性を扱うHCI・組織運用。
8. **(8) 重要度**：**A**（現行specへの昇格には独立検証とレビューを要する）。

### F11【B】AI生成テストの重複数より独立した検証対象を評価する

**一次資料 / 公開日**：Qiita・2026-10-19・著者の実験一次記録 — https://qiita.com/figueiredoluiz/items/9dae44b202aec123d7c4

1. **(1) 実証済み・観測**：ツール作者がAI生成Vitest 139件を2モジュールで手動分類し、静的解析と単純クローン検出器を比較した小規模実験を報告。判定カテゴリーとベースライン差分ゲート、既知の偽陽性条件を公開。
2. **(2) 提案・推測段階・限界**：1エージェント・2モジュール、作者自身のツール評価であり一般化は不可。『約93%』の独立性を他条件に外挿しない。
3. **(3) 対象サブシステム・設計課題**：Formal verification / Runtime assurance / Self-modifying systems。
4. **(4) 借りられる設計・実装アイデア**：テスト件数で自己改善を認可せず、独立不変条件・反例クラス・mutation score・故障注入の新規寄与を記録。
5. **(5) Kamimusuhiとの差分**：既報の『子agentがいないのにhandoffテスト合格』を補完し、緑のテスト群自体の情報的冗長性を点検する観点。
6. **(6) 次に検証すべきこと**：RegressionDiversityBench：同一assertの変種を大量追加しても品質評価が増えず、異なる故障モードを捕えるcaseだけ加点。
7. **(7) 既存dailyで拾いにくい理由**：認知研究ではテストスイート構造と査読者の独立判定を評価しない。
8. **(8) 重要度**：**B**（現行specへの昇格には独立検証とレビューを要する）。
