# 主推論による直接ツール実行

Mioの主推論は、回答文を作るだけでなく、residentのツールを呼び、結果を読んで
次の操作を決める既存のtool loopを使います。外部executorへの委譲とは別経路です。

ファイル・repo・Webの短い調査は、まず本人が提供ツールを使います。
登録済みrepoは`git list`で選び、`git files`で未追跡を含むファイル一覧を取得し、
`git read_file`で本文を読みます。汎用filesystem MCPへrepo全体を追加する必要はありません。
指定された絶対pathが存在するとは仮定せず、利用できる登録先との違いを報告します。
詳しい呼び出しと読取制限は[Gitツール](git-tool.md)を参照してください。

MCPは`tool_catalog`で発見し、`tool_enable`でそのターンに有効化します。
独立した操作はまとめ、前の結果が必要な操作は次roundで実行します。
回数上限は既存の`tools.max_rounds`（1〜16）に従い、使い切った場合は
取得済み結果と未確認事項を区別して回答します。既存のallowlist・承認・judgeを維持します。

## 委譲失敗と認証切れ

- 外部executorは、利用者が指定した場合か、直接ツールで完了できない長時間作業に使います。
- `task_delegate`/`task_continue`の失敗、または`task_status`が`failed`を返したあと、
  主推論が調査せず終了しようとした場合、hostが直接ツールへの復帰を促します。
  同じ認証切れexecutorの再実行、未承認の課金・権限変更を促すことはありません。
- 回復の促しは既存の有限回repair枠を使います。実行できない場合は具体的な制約を報告します。
- 実タスクの明確な認証エラーは、executor名と時刻だけを保存して15分間選択対象から除外します。
  モデル一覧取得の成功では解除せず、resident再起動後も維持します。
  待機中に先行タスクの認証失敗が判明した場合も、実行直前で止めて予約・slotを解放します。
- `agent_health`/`agent_models`は`auth_retry_after`を表示します。
  鍵を自動更新せず、通常のテスト名に含まれる`login`を認証失敗として扱いません。

非同期の`task_review`は外部結果の採否を記録する仕組みです。
今回の変更は、レビュー通知だけを契機に元依頼を無条件で自動再実行するものではありません。
失敗したタスクを引き継ぐ対話では、状態を確認して直接ツールから続行できます。
外部タスクの失敗履歴を成功扱いへ書き換えず、本人の実行結果は別の対話・tool evidenceとして残します。
