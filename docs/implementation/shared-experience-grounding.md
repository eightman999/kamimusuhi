# 共有体験の出典と会話の継続性

2026-11-09。対象はPersona HTTPの会話生成と、実APIのtyped Jev応答評定・再生成である。

## 問題と変更

過去のassistantが生成した「一区切りついた」などの文が、共有した出来事の独立した証拠として再利用され、さらに期間・予想・疲労の原因を補う応答が実モデル評定に残っていた。

- 会話中のassistant発言は、元の文とevidence IDを保持したJSON引用として渡す。`prior_generated_assistant_utterance` / `not_independent_evidence`を付ける。user発言と現在入力は元のbytesを保持する。
- ホストで今回提示された会話履歴の件数と保持項目の件数を分けて渡す。これは全記憶の一覧ではなく、未提示の範囲はunknownである。評定・修復にも同じ件数情報を渡す。欠落・配列でない履歴を0件へ変換しない。
- 共有体験の時間、予想との差、原因、感情を節ごとに評定する。先行生成は出来事の証拠ではなく、不確かなユーザー報告は不確かさを維持する。明示された数量・訂正・約束・承認待ちは残す。
- GROUNDING修復では根拠と現在入力から返答を組み立て直す。棄却した文のdigestを保持し、文そのものは`previous_response`へ再投入しない。他の修復理由では既存動作を維持する。

記憶DB、個体ID、継続head、writer epoch、既存失敗markerは書換えない。出典ラベルはLLMへの入力構造であり、完全な真偽判定器ではない。typed判定が根拠不足・矛盾を返す場合に、既存のホスト側制約でACCEPTを認めない。

## 評価の読み方

固定8ケースを各条件2回生成し、旧版と最終版の同じ評定・修復経路を比較する。生成文そのもの、最大1回の修復後、gate通過可否、別コンテキストの意味評定を分けて記録する。`baseline` / `candidate`はcaptureの第1・第2反復名で、実装の旧新ではない。

[固定suite](../../evaluation/continuity/shared-experience-20261109.json)と[rubric](../../evaluation/continuity/shared-experience-20261109.rubric.json)は新規出力より先に固定した。旧4ケースの期待条件（`バックアップ`を含む）を変更していない。[再現用probe](../../evaluation/continuity/grounding-probe/README.md)は単一候補の評定と最大1回の修復を再現するもので、runtime全体・DB書戻し・実際の送達は再現しない。

親しさを保つため、現在の訴えへの受容や休息の提案に不要な出典説明を要求しない。明示された「二時間」を抑制して不明と答えることも回帰として扱う。評定はモデルによるもので、人間の評定や異なる重みのモデルによる独立検証ではない。

## 確認された限界

生の生成にはassistant由来の「一区切り」が残る。typed gateと修復を含む最終比較で通過可能候補は旧13/16から15/16となったが、新版でも1件は修復後に通過不可だった。提示履歴2発言があるのに「過去の記録は見えていない」とする誤った否定を1件gateが受理し、「この口」という不自然な表現も残った。これらをPASSへ読み替えず、全出力と失敗を保存する。有限の合成ケースから共有体験の補完を完全防止したとは結論しない。
