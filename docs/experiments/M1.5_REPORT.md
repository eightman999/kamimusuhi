# M1.5 — Functional Validation / Selection Pressure

> 日期： 2026-09-16 ｜ 上游实验： `M1-20260915-152426-54b69e`（已冻结于
> `.runs/M1-20260915-152426-54b69e.BASELINE-FROZEN`，sha256 manifest 齐全，
> M1 原始数据未做任何修改）

## 0. Executive summary — 结构是增了，但功能呢？

**先说结论：M1 里增殖的器官，在受控 ablation 下基本没有可测的功能贡献。**

M1 overnight run（139,000 神经元 / 13,994,854 边 FBA0 基質，21 世代，1008 次
評価、0 失敗）證明了「進化會讓結構增長」：平均器官数 0.4 → 7.6（上限 8 饱和）、
attachment 1.0 → 21.9（上限 24 趋近）。但 M1.5 的 paired ablation（同一 genome、
同一 seed 集合、N=64 replicates）给出的因果证据是：

- 全部 8 个 enabled organ 的逐一 ablation，Δfitness = −0.0001 ~ −0.0003，
  全部 neutral；器官的平均 firing rate **精确为 0.000 Hz**——它们在整个
  评估里一次都没发过火；
- `all_artificial_disabled`（器官 + attachment 全禁）的 Δfitness 也只有
  −0.0015（neutral 级）——**整套人工结构对这个 task 的贡献 ≈ 0**；
- 真正值得注意的反倒是负号方向：移除静默器官使 fitness *微升*
  （64/64 replicate 方向一致）。机理是 mean rate 在全体神经元上取平均，
  313 个静默人工神经元摊薄了分母——结构不但没贡献，还在轻微拖累指标。

换句话说：M1 的器官增殖是**结构漂移**——器官便宜（`resource_efficiency`
惩罚小）、变异算子偏向 structural（权重 0.55）、而任务 target 5Hz 对
~0.6Hz 的种群来说遥不可及，没有任何结构能通过提升 task 得分来"回本"。
这正是 M1.5 要修的 selection landscape 问题，而不是要隐藏的失败。

本文其余部分：§2 ablation 全表、§3 整系统 ablation、§4 hyperactive 表型
机理、§5 fitness landscape 诊断、§6 M2 落地配置。

## 1. 方法（可复现）

- **Baseline 冻结**：M1 run dir 整体复制为 `*.BASELINE-FROZEN/`（先 WAL
  checkpoint 再拷贝），`MANIFEST.sha256` 覆盖 83 个文件。以下所有分析均
  对 sqlite 以 `mode=ro` 只读打开。
- **Ablation runner**：`experiments/mioba/scripts/m15_ablation.py`。
  对 best genome（`b2b:81cb36f0…`，M1 overall best fitness -4.3654，
  gen 20，8 enabled organs / 24 enabled attachments / 16 parameter
  mutations）生成 12 个变体：`full` + 8×`disable_organ:<id>` +
  `all_organs_disabled` + `attachments_disabled` + `all_artificial_disabled`。
  变体只把 `ArtificialOrgan.enabled` / `Attachment.enabled` 置 false，
  **不改写原 genome**（`develop()` 自然跳过 disabled 器官，dangling
  attachment 被剔除——禁用是非破坏性的）。
- **Paired seeds**：全部 12 个条件共用同一 `evaluation.seed`
  （20260916），`replicate_seeds(seed, i)` 由 BLAKE2b 派生且前缀稳定，
  N=64 的前 32 个 seed 与 N=32 完全一致 → 条件间为完全配对比较。
- **判定阈值**（`m15_ablation.yaml`，非硬编码）：functional Δ≥0.05 且方向
  一致率 ≥ 阈值；weak 0.01≤Δ<0.05；neutral |Δ|<0.01；harmful Δ<0 且一致。
  Δ 的显著性用 paired bootstrap（2000 次重采样，95% CI）+ effect size
  `dz = mean/std` 衡量——看效应量，不只看 p 值。
- **统计口径**：paired Δfitness 基于 per-replicate 的
  `-|rate − target|`（即 placeholder fitness 按 replicate 分解）；
  同时记录每条件的 `selection_score`（elite 排序实际使用的量）及其差值。

|---|---|---|---|
| all_organs_disabled | −0.0015 | +0.036 | neutral |

**Activity ≠ Function**：8 个器官的 activity 全部为 0.000 Hz，Δ 全部为
负且 |Δ|≪0.01——连"silent 但重要"的悬念都不存在，它们是**纯静默死重**。
N=64 下 CI 极窄（±1e-6 量级），效应量 dz ≈ −28，结论非常硬。

**真正的发现藏在 selection_score 一列**：禁掉全部 attachment 让 task
得分纹丝不动（Δfitness=+0.0000），却让 selection_score 掉了 0.069。
分解成分可见根因——本 genome 的 `structural_functionality = 1.0000`
（24 条 attachment 把所有人工神经元都编进了 FBA0→器官→FBA0 环路），
这一项以权重 0.2 贡献了 **+0.2 分，占其 selection_score 0.5102 的 ~40%**。
也就是说：M1 的选择函数为"接线接得像回事"本身发放了占总分四成的补贴，
而 ablation 证明这些线路对任务毫无因果作用。器官个数增长的主体是
中立 drift（structural 变异权重 0.55 + 免费持有），structural_functionality
则负责奖励"把器官全部接上线"这一姿势——这正是 §9 maintenance cost
要抵消的对象。

## 3. Hyperactive phenotype 分析（§7）

从 1008 次评估中筛出 fitness ≤ −100 的 runaway 个体（gen3–4 集中出现），
按 wall 时间排序：

| gen | fitness | wall | propagated edges | 其中 artificial | organ max rate |
|---|---|---|---|---|---|
| 3 | −395.3 | 2428s | 10.89B | 30.5M | 400.3 Hz |
| 3 | −396.4 | 2324s | 11.16B | 22.1M | 401.4 Hz |
| 4 | −396.0 | 2301s | 14.36B | **3166.7M** | 401.2 Hz |
| 3 | −395.4 | 2297s | 10.77B | 19.5M | 400.5 Hz |
| 3 | −395.2 | 2250s | 10.26B | 13.0M | 400.2 Hz |

（正常评估对照：edges p50 = 15.8M、p99 = 17.0M、max = 48.8M；
wall p50 = 95s、max = 228s。runaway 的 edge 事件是正常的 **200~900 倍**。）

wall-time 相关性（全部 1008 次评估，Pearson）：

| 指标 | r |
|---|---|
| propagated edge events（总量） | 0.69 |
| spikes total | 0.74 |
| mean rate | 0.74 |
| **artificial edges only** | 0.25 |
| organ count | −0.15 |

**机理结论**：runaway 不是"器官内部算得慢"——artificial 边只占总量的一小
部分。真正的链条是 **器官过活跃（~400Hz）→ 经 attachment 向 14M 边基質
注入电流 → 基質全网 event 爆炸**。event 驱动后端的成本 ∝ propagated
edge events，所以 wall 时间与总 edge 数强相关、与器官个数无关。
这直接决定了 guard 的第一选择：`max_propagated_edge_events`。

## 4. Fitness landscape 诊断（§11）

利用 summary 里持久化的 per-slice `rate_hz` trace 做离线重打分
（`scripts/m15_diagnostics.py`，零重跑仿真）：

- **可达速率分布**：全 1008 次评估 mean rate p50 = 0.588、p90 = 0.605 Hz；
  p99+ 的 436~456Hz 全部是 runaway 个体。**正常种群被压在 ~0.6Hz 天花板
  附近**，5Hz 目标是 p90 的 8 倍以上，实际 unreachable。
- **target sweep（task_quality = max(0, 1−|rate−T|/T)，跨全部评估的种群
  散布）**：

| target | mean | std | spread [min..max] |
|---|---|---|---|
| 0.5 Hz | 0.754 | 0.196 | 0.000 .. 0.850 |
| 1.0 Hz | 0.539 | 0.142 | 0.000 .. 0.637 |
| 2.0 Hz | 0.269 | 0.071 | 0.000 .. 0.319 |
| 5.0 Hz | 0.108 | 0.028 | 0.000 .. 0.127 |

**判读**：target=5Hz 时 task_quality 被压扁在 0..0.127、std 只有 0.028——
mutation 把 rate 从 0.57 推到 0.60 只换来 +0.006 的质量分，选择几乎看不
见梯度，这解释了 M1"结构猛涨、fitness 躺平"。target=1.0Hz 是拐点：方向
仍是"越快越好"（种群均值 0.59 < 1.0），std 放大 5 倍，且 ~400Hz 的
runaway 自动拿到 quality 0（|400−1|/1 直接封顶截 0），不需要特判。
target=0.5Hz 梯度更大但方向反转（种群在目标上方，"少动"反而得分），
会奖励降活——不符合 M2 目标。

## 5. M1.5 落地的机制改动（全部默认关闭，M1 行为 byte-identical）

1. **Deterministic runaway guard**（`fba/torch_backend.py` 内
   `set_run_limits`/`_check_run_limits`，`workers/worker.py` 接线
   `evaluation.guard`）：
   - `max_propagated_edge_events`（首选，纯函数）、`max_spike_events`、
     `max_mean_rate_hz`、`max_wall_seconds`（ops 兜底，
     `deterministic:false` 明示）。
   - 触发即 break step 循环 → summary 携带 `guard{tripped,reason,
     at_t_ms,propagated_edge_events,spike_events,deterministic}`，
     `simulated_ms` 记录真实推进时间。**非静默截断、非基础设施失败**。
   - 计数器是 job 级（backend 每 job 新建），跨 chunk/跨 slice 累计——
     同 genome 同 seed 在任何机器上于同一 step 触发。
2. **Fitness 两个新成分**（`evolution/fitness.py`，权重默认 0 → M1
   打分完全不变）：
   - `runaway_guard`：正常 1.0、trip 时 0.0——可复现的确定性惩罚；
   - `structural_maintenance`：成分 = −(per_organ×器官 +
     per_neuron×人工神经元 + per_attachment×attachment)，按 develop 后
     的实际表型计费（disabled 器官不计）。
3. **Observatory**：organism 页新增可选 ablation 面板
   （`/static/ablation.json` 存在才渲染；DERIVED 标注），以及此前已交付
   的实连接层（蓝=基質実辺標本、橙=该个体実 attachment）。

## 6. Recommendation for M2 — 已落地为 `configs/mac_m2.yaml`

| 项 | M1 | M2 | 依据 |
|---|---|---|---|
| target_rate_hz | 5.0 | **1.0** | §4：5Hz unreachable、梯度 std 0.028→0.142 |
| evaluation.guard | 无 | `max_propagated_edge_events=100M` + `max_wall_seconds=900` | 100M ≈ 2×正常 max 48.8M、1/100 runaway；900s ≈ 4×正常 max |
| w(runaway_guard) | 0 | **0.5** | trip ⇒ −0.5 score，确定性致死但不无限惩罚 |
| w(structural_maintenance) | 0 | **1.0** | 成分即负成本，weight 1.0 原样生效 |
| maintenance (low) | 全 0 | organ 0.005 / neuron 0.00005 / attachment 0.001 | 饱和基因型总成本 ≈0.09 ≈ 20% 典型分差；medium=4×low，0=M1 |
| 其余（基質/种子/种群48/变异算子/环境/40代） | 相同 | 相同 | 保持可比，diff 仅限上述 |

**注意（来自 §2 分解）**：`structural_functionality`（权重 0.2）为"接进
FBA0 环路"的拓扑姿势一次性发放至多 +0.2 分，与是否真有用无关。M2 保留
它——它的 share 语义仍会惩罚*未接线*的死组织，而 maintenance 使每个新增
结构净成本 ≈ −0.01，drift 方向反转为温和负值。若 M2 仍观测到结构继续
饱和，下一步候选是把该权重 0.2→0.05，或对 struct_func 加 ablation 校验
后再计分。

M2 观察指标（§13）除 `functional organ fraction` 外全部可从 summary
离线提取：fitness/task_score（evaluations+summary）、器官/神经元/
attachment 数（`circuit`）、active organ fraction（`activity."organ:*"`
>0.01Hz 占比）、maintenance 成本（structure 重算）、edge events
（`resource`）、wall p95（`wall_s`）、runaway 次数（`summary.guard`）。
`functional organ fraction` 需要按代跑 ablation——runner 支持任意
genome_id，建议对每代 elite 抽样执行。

## 7. 验证与限制

- `test_runaway_guard.py` 7 件：trip 阈值、trip 后 `simulated_ms` 如实、
  正常路径不触发、M1 兼容默认、fitness 罚分、无 N² dense 分配。
- 相关套件 76 件（torch/fitness/worker/evaluate/sparse）+ GUI 63 件全过。
- 限制：ablation 只在 quiet 环境 + 单一 best genome 上做，"neutral" 结论
  限定于该任务；maintenance/guard 参数是启发式起点，M2 需按 §9 sweep
  校准；`functional organ fraction` 指标需代际 ablation，开销未摊入
  M2 单代评估。
