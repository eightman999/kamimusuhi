# M1.5 — Functional Validation / Selection Pressure

> 日付: 2026-09-16 ｜ 上位実験: `M1-20260915-152426-54b69e`
> （`.runs/M1-20260915-152426-54b69e.BASELINE-FROZEN` に凍結済み。
> sha256 manifest 完備、M1 の元データには一切手を付けていない）

## 0. Executive summary — 構造は増えた。では、機能していたのか?

**結論を先に言う: M1 で増殖した器官には、統制された ablation の下で
測定可能な機能的寄与がほぼ存在しなかった。**

M1 overnight run（139,000 ニューロン / 13,994,854 エッジの FBA0 基質、
21 世代、1,008 回評価・失敗ゼロ）は「進化すると構造が増える」ことを
証明した: 平均器官数 0.4 → 7.6（上限 8 に飽和）、attachment
1.0 → 21.9（上限 24 に接近）。しかし M1.5 の paired ablation
（同一 genome・同一 seed 集合・N=64 replicates）が示した因果的証拠は:

- enabled な全 8 器官を 1 つずつ ablation した Δfitness は
  −0.0001 〜 −0.0003 で**すべて neutral**。器官の平均 firing rate は
  **正確に 0.000 Hz** —— 評価の全期間を通じて一度も発火していない;
- `all_artificial_disabled`（器官 + attachment を全無効）でも
  Δfitness は −0.0015 止まり（neutral 級）——
  **人工構造全体のこのタスクへの寄与は ≈ 0**;
- むしろ注目すべきは負号の方向: 沈黙した器官を取り除くと fitness が
  *わずかに上がる*（64/64 replicate で方向一致）。機序は mean rate が
  全ニューロン平均で取られるため、313 個の沈黙した人工ニューロンが
  分母を薄めていたこと。構造は寄与しないどころか、指標をわずかに
  引き下げていた。

つまり M1 の器官増殖は**構造ドリフト**だった——器官は安い
（`resource_efficiency` のペナルティが小さい）、変異演算子は
structural に偏っている（重み 0.55）、そしてタスク目標 5Hz は
~0.6Hz の個体群にとって事実上到達不能で、どんな構造も task スコアの
向上で「元を取る」ことができなかった。これは隠すべき失敗ではなく、
M1.5 が修正すべき selection landscape の問題である。

以降の構成: §2 ablation 全表、§3 人工システム全体の ablation、
§4 hyperactive 表現型の機序、§5 fitness landscape 診断、
§6 M2 への反映済み設定。

## 1. 方法（再現可能）

- **Baseline 凍結**: M1 の run dir を `*.BASELINE-FROZEN/` へ丸ごと
  複製（WAL checkpoint 後にコピー）。`MANIFEST.sha256` が 83 ファイルを
  カバー。以下の全分析は sqlite を `mode=ro` で読み取り専用オープン。
- **Ablation runner**: `experiments/mioba/scripts/m15_ablation.py`。
  best genome（`b2b:81cb36f0…`、M1 overall best fitness −4.3654、
  gen 20、8 enabled organs / 24 enabled attachments / 16 parameter
  mutations）から 12 個のバリアントを生成: `full` +
  8×`disable_organ:<id>` + `all_organs_disabled` +
  `attachments_disabled` + `all_artificial_disabled`。
  バリアントは `ArtificialOrgan.enabled` / `Attachment.enabled` を
  false にするだけで**元 genome を書き換えない**（`develop()` が
  disabled 器官を自然にスキップし、dangling な attachment は
  除去される——無効化は非破壊的）。
- **Paired seeds**: 全 12 条件で同一 `evaluation.seed`（20260916）を
  共有。`replicate_seeds(seed, i)` は BLAKE2b 派生で prefix 安定のため、
  N=64 の先頭 32 seed は N=32 と完全一致 → 条件間は完全なペア比較。
- **判定しきい値**（`m15_ablation.yaml`、ハードコードなし）:
  functional は Δ≥0.05 かつ方向一致率がしきい値以上;
  weak は 0.01≤Δ<0.05; neutral は |Δ|<0.01; harmful は Δ<0 かつ一致。
  Δ の有意性は paired bootstrap（2,000 回リサンプリング、95% CI）と
  効果量 `dz = mean/std` で評価——p 値単独ではなく効果量を見る。
- **統計口径**: paired Δfitness は per-replicate の
  `-|rate − target|`（placeholder fitness を replicate 分解したもの）に
  基づく。各条件の `selection_score`（elite 順位付けに実際使われる量）
  とその差分も併記する。

| 条件 | Δfitness | Δselection_score | class |
|---|---|---|---|
| all_organs_disabled | −0.0015 | +0.036 | neutral |

**Activity ≠ Function**: 8 器官の activity はすべて 0.000 Hz、Δ はすべて
負で |Δ|≪0.01——「沈黙しているが重要」という余地すらない。これらは
**純粋な沈黙の死重**である。N=64 では CI が極めて狭く（±1e-6 オーダー）、
効果量 dz ≈ −28 と結論は堅い。

**本当の発見は selection_score の列にある**: attachment を全無効化しても
task スコアは微動だにしない（Δfitness=+0.0000）のに、selection_score は
0.069 も下がる。成分分解で原因が見える——この genome は
`structural_functionality = 1.0000`（24 本の attachment が全人工
ニューロンを FBA0→器官→FBA0 のループに編み込んでいる）で、この成分が
重み 0.2 を通じて **+0.2 点、selection_score 0.5102 の約 4 割** を
稼いでいた。つまり M1 の選択関数は「配線がそれらしく見える」こと自体に
総得点の 4 割に及ぶ補助金を出しており、ablation はその配線がタスクに
何の因果的作用も持たないことを証明した。器官の個数増加の主体は中立
ドリフト（structural 変異重み 0.55 + 保有コストゼロ）であり、
structural_functionality は「器官をすべて配線済みにする」という姿勢への
報酬を担っていた——これこそ §9 の maintenance cost が相殺すべき対象である。

## 3. Hyperactive phenotype 分析（指示書 §7）

1,008 回の評価から fitness ≤ −100 の runaway 個体を抽出
（gen3–4 に集中）、wall 時間順:

| gen | fitness | wall | propagated edges | うち artificial | organ max rate |
|---|---|---|---|---|---|
| 3 | −395.3 | 2428s | 10.89B | 30.5M | 400.3 Hz |
| 3 | −396.4 | 2324s | 11.16B | 22.1M | 401.4 Hz |
| 4 | −396.0 | 2301s | 14.36B | **3166.7M** | 401.2 Hz |
| 3 | −395.4 | 2297s | 10.77B | 19.5M | 400.5 Hz |
| 3 | −395.2 | 2250s | 10.26B | 13.0M | 400.2 Hz |

（正常評価との対照: edges p50 = 15.8M、p99 = 17.0M、max = 48.8M;
wall p50 = 95s、max = 228s。runaway の edge イベント数は正常の
**200〜900 倍**。）

wall-time との相関（全 1,008 評価、Pearson）:

| 指標 | r |
|---|---|
| propagated edge events（総量） | 0.69 |
| spikes total | 0.74 |
| mean rate | 0.74 |
| **artificial edges のみ** | 0.25 |
| organ count | −0.15 |

**機序の結論**: runaway は「器官内部の計算が遅い」のでない——artificial
辺は総量のごく一部にすぎない。真の連鎖は **器官の過活動（~400Hz）→
attachment 経由で 14M 辺の基質へ電流注入 → 基質全体のイベント爆発**。
イベント駆動バックエンドのコストは propagated edge events に比例するため、
wall 時間は総 edge 数と強く相関し、器官数とは無関係。この結果が
guard の第一選択を `max_propagated_edge_events` と直接決定づけた。

## 4. Fitness landscape 診断（指示書 §11）

summary に永続化済みの per-slice `rate_hz` trace を使いオフラインで
再スコア（`scripts/m15_diagnostics.py`、シミュレーションの再実行ゼロ）:

- **到達可能なレート分布**: 全 1,008 評価の mean rate は p50 = 0.588、
  p90 = 0.605 Hz。p99 以上の 436〜456Hz はすべて runaway 個体。
  **正常な個体群は ~0.6Hz の天井付近に押し込まれている**——5Hz の
  目標は p90 の 8 倍以上で、事実上到達不能。
- **target sweep（task_quality = max(0, 1−|rate−T|/T)、全評価にわたる
  個体群のばらつき）**:

| target | mean | std | spread [min..max] |
|---|---|---|---|
| 0.5 Hz | 0.754 | 0.196 | 0.000 .. 0.850 |
| 1.0 Hz | 0.539 | 0.142 | 0.000 .. 0.637 |
| 2.0 Hz | 0.269 | 0.071 | 0.000 .. 0.319 |
| 5.0 Hz | 0.108 | 0.028 | 0.000 .. 0.127 |

**解釈**: target=5Hz では task_quality が 0..0.127 に潰れ、std は
0.028 に過ぎない——mutation が rate を 0.57 から 0.60 へ押し上げても
品質点は +0.006 しか増えず、選択は勾配をほとんど認識できない。
これが M1 の「構造は急増、fitness は横ばい」を説明する。
target=1.0Hz が転換点: 方向は依然「速いほど良い」（個体群平均
0.59 < 1.0）を保ちつつ std は 5 倍に拡大し、~400Hz の runaway は
quality 0 を自動的に受ける（|400−1|/1 で頭打ち→0）。特別扱いは不要。
target=0.5Hz は勾配こそ最大だが方向が反転する（個体群が目標の上側に
位置し「活動を減らす」方が得点になる）——活動低下を報酬するのは
M2 の目的に反する。

## 5. M1.5 で導入した機構変更（すべてデフォルト無効、M1 と byte-identical）

1. **Deterministic runaway guard**（`fba/torch_backend.py` の
   `set_run_limits`/`_check_run_limits`、`workers/worker.py` が
   `evaluation.guard` を配線）:
   - `max_propagated_edge_events`（第一選択、シミュレーションの
     純関数）、`max_spike_events`、`max_mean_rate_hz`、
     `max_wall_seconds`（運用上のバックストップ。
     `deterministic:false` と明記）。
   - 発動すると step ループを break → summary に
     `guard{tripped,reason,at_t_ms,propagated_edge_events,
     spike_events,deterministic}` を記録し、`simulated_ms` には
     実際に進んだ時間を入れる。**暗黙の打ち切りでも、インフラ
     失敗でもない**。
   - カウンタは job スコープ（backend は job ごとに新規生成）、
     chunk/slice を跨いで累積——同じ genome・同じ seed なら
     どのマシンでも同じ step で発動する。
2. **Fitness の新成分 2 つ**（`evolution/fitness.py`、重みの
   デフォルトは 0 → M1 の採点と完全一致）:
   - `runaway_guard`: 通常 1.0、trip 時 0.0——再現可能な決定的
     ペナルティ;
   - `structural_maintenance`: 成分 = −(per_organ×器官数 +
     per_neuron×人工ニューロン数 + per_attachment×attachment数)。
     develop 後の実際の表現型に課金（disabled 器官は対象外）。
3. **Observatory**: organism ページにオプションの ablation パネルを追加
   （`/static/ablation.json` が存在する時のみ描画、DERIVED 表記）。
   加えて既に納入済みの実接続レイヤー（青=基質の実辺標本、
   橙=当該個体の実 attachment）。

## 6. Recommendation for M2 — `configs/mac_m2.yaml` として反映済み

| 項目 | M1 | M2 | 根拠 |
|---|---|---|---|
| target_rate_hz | 5.0 | **1.0** | §4: 5Hz は到達不能、勾配 std が 0.028→0.142 |
| evaluation.guard | なし | `max_propagated_edge_events=100M` + `max_wall_seconds=900` | 100M ≈ 正常 max 48.8M の 2 倍・runaway の 1/100; 900s ≈ 正常 max の 4 倍 |
| w(runaway_guard) | 0 | **0.5** | trip ⇒ −0.5 score。決定的に致命だが無限の罰ではない |
| w(structural_maintenance) | 0 | **1.0** | 成分がそのまま負のコストなので weight 1.0 で素通し |
| maintenance (low) | 全 0 | organ 0.005 / neuron 0.00005 / attachment 0.001 | 飽和 genome で総コスト ≈0.09 ≈ 典型分差の 20%; medium=4×low、0=M1 |
| その他（基質/seed/個体数 48/変異演算子/環境/40 世代） | 同一 | 同一 | 比較可能性を保持、diff は上記のみ |

**注意（§2 の分解より）**: `structural_functionality`（重み 0.2）は
「FBA0 ループに接線されている」というトポロジー上の姿勢に対し、
有用性と無関係に最大 +0.2 点を一度だけ支給する。M2 ではこれを残す——
share セマンティクスは*未接線*の死組織を依然として罰するし、
maintenance が新規構造 1 つあたり ≈ −0.01 の正味コストを課すため
ドリフトの方向は穏やかな負へ反転する。もし M2 でも構造の飽和が
観測されたら、次の候補は当該重みを 0.2→0.05 に下げるか、
struct_func の得点計上に ablation 検証を要求すること。

M2 で見るべき指標（指示書 §13）は `functional organ fraction` を除き
すべて summary からオフライン抽出可能: fitness/task_score
（evaluations+summary）、器官数/人工ニューロン数/attachment 数
（`circuit`）、active organ fraction（`activity."organ:*"` の
>0.01Hz 割合）、maintenance コスト（structure から再計算）、
edge events（`resource`）、wall p95（`wall_s`）、runaway 件数
（`summary.guard`）。`functional organ fraction` は世代ごとの
ablation が必要——runner は任意の genome_id に対応するので、
各世代の elite をサンプリング実行するのが妥当。

## 7. 検証と限界

- `test_runaway_guard.py` 7 件: trip しきい値、trip 後の
  `simulated_ms` が実時間を反映、通常経路は未発動、M1 互換
  デフォルト、fitness への罰則適用、N² dense 確保なし。
- MIOBA テストスイート全 609 件パス（GUI 63 件含む）。
- 限界: ablation は quiet 環境・単一 best genome に限定され、
  「neutral」の結論はこのタスクに限られる。maintenance/guard の
  パラメータは経験則による初期値であり、M2 では指示書 §9 の
  sweep（0 / low / medium）で校正する。`functional organ fraction`
  指標は世代別 ablation を要し、そのコストは M2 の単位世代評価に
  織り込んでいない。
